# ⚠️ 选型记录 — 历史归档文档

> 本目录记录项目开发过程中的技术选型、方案对比和决策依据。所有文档均为历史快照，记录了特定时间点的分析与决策状态。当前代码状态以对应源文件为准，本文档内容可能已过时，仅供参考。

## 📝 文档编写规范

### 归档声明要求
**⚠️ 强制要求**：本目录下的所有文档必须在文件头部添加归档声明，格式如下：

```markdown
> ⚠️ **归档声明**：本文档为历史快照，记录了特定时间点的决策与实施状态。
> 当前代码状态以对应源文件为准，本文档内容可能已过时，仅供参考。
```

## 阅读须知

1. **时间敏感性**：选型记录反映的是特定时间点的技术判断，随着项目演进，某些决策可能已被更新或推翻。
2. **上下文依赖**：许多选型文档需要结合当时的代码版本、性能测试结果和业务需求来理解。
3. **决策依据**：每个选型文档都应包含明确的决策依据、对比分析和最终结论。
4. **实施记录**：部分选型文档包含实施记录，用于追溯具体修改的时间和文件。

---

## 何时查阅本文档

- **理解设计决策**：想知道为什么选择某种算法或方案时
- **方案对比参考**：遇到类似问题时，查阅历史选型分析作为参考
- **技术债务追溯**：了解某些技术选择的背景和权衡
- **新成员培训**：帮助新团队成员理解系统的设计演进过程

## 文档分类

建议按文档内容性质分类维护，常见分类示例：

- **🔬 算法/技术选型**：记录核心算法或技术方案的选型过程和对比分析
- **🛠️ 方案对比**：记录针对特定问题的多种解决方案对比
- **📋 问题清单**：记录系统中发现的问题和待解决的清单
- **🔍 审计报告**：记录参数和配置的审计结果
- **📊 根因诊断**：记录特定问题的根因分析
