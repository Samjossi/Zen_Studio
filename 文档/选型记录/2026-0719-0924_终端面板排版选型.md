# 终端面板排版选型

## 1. 背景与约束

Zen Studio 的终端面板位于中栏下部（垂直 `QSplitter` 的下段，默认高约 250px），当前实现为**真 PTY 单会话**（ptyprocess + pyte + 自绘 `TerminalWidget`），排版为"标题行 + 终端区"两段式：

- 标题行：shell 名 + 状态文本 + 「重开」按钮
- 终端区：`TerminalWidget` 自绘字符网格，占剩余空间

近期走查暴露的排版缺陷（标题行未设 stretch 约束而膨胀抢空间、首屏内容沉底）已临时修复，但标题行的**信息架构本身**（按钮位、扩展性）缺乏参照系。本文对比三个参考项目的终端面板排版，为重构选型。

**约束**：

- PySide6 自绘控件体系，样式走 `config/themes/*.qss` 主题；
- 面板默认高度有限（250px），垂直空间珍贵，每一行装饰都要有代价意识；
- 产品定位 AI-first IDE：终端为**用户终端**，后续规划含多会话、agent 命令镜像（ACP terminal RPC，备案）；
- 会话生命周期操作（重开/清屏/隐藏）需要明确的视觉入口。

## 2. 候选方案

### 方案 A：现状 · 极简标题行两段式（Zen Studio 当前）

```
┌────────────────────────────────────────────┐
│ bash                    [状态] [重开]       │ ← 标题行（约 26px）
├────────────────────────────────────────────┤
│ $ █                                        │
│                                            │ ← 终端视口（占满剩余）
│                                            │
└────────────────────────────────────────────┘
```

结构：[`gui/panels/terminal/panel.py`](gui/panels/terminal/panel.py)，`QVBoxLayout[标题行, 终端区(stretch=1)]`。

### 方案 B：底部 Dock · 头部行承载一切（Multi_Cli_Studio）

来源：[`参考代码/Multi_Cli_Studio/src/components/chat/TerminalDock.tsx`](参考代码/Multi_Cli_Studio/src/components/chat/TerminalDock.tsx)、[`参考代码/Multi_Cli_Studio/src/styles/terminal-dock.css`](参考代码/Multi_Cli_Studio/src/styles/terminal-dock.css)

```
┌────────────────────────────────────────────┐
│ ⇕⇕⇕ 拖拽把手（6px，拖高面板 160–520px）      │
│ [bash ×] [zsh ×] [+]                 [×]   │ ← header：tab 列表(可滚动) + 新建 + 隐藏面板
├────────────────────────────────────────────┤
│ $ █                                        │
│                                            │ ← xterm 视口（深色背景，占满剩余）
│                                            │
└────────────────────────────────────────────┘
```

要点：

- 面板顶部一条 6px **拖拽把手**调整面板高度（持久化到 localStorage）；
- header 一行集中全部操作：左侧**横向可滚动 tab 列表**（tab = 标题 + 行内 × 关闭，激活态为 2px 下划线指示），tab 末尾跟 `+` 新建按钮；最右端一枚圆形 `×` 隐藏整个面板；
- 单终端内部**无任何工具行/状态栏**，激活后整片就是 xterm 视口；
- 与运行日志面板互斥渲染（底部 dock 位二选一）。

### 方案 C：tabbar 同行工具栏式（Theia）

来源：[`参考代码/theia-zen/packages/terminal/src/browser/terminal-widget-impl.ts`](参考代码/theia-zen/packages/terminal/src/browser/terminal-widget-impl.ts)、[`参考代码/theia-zen/packages/core/src/browser/shell/tab-bars.ts`](参考代码/theia-zen/packages/core/src/browser/shell/tab-bars.ts)

```
┌────────────────────────────────────────────┐
│ [🖵 bash ×] [🖵 zsh ×]      [▾] [＋] [⿻]   │ ← tabbar 行：tab(可滚动) + 下拉 + 工具栏
├────────────────────────────────────────────┤
│ $ █                        ┌───────────┐   │
│                            │ 查找浮层   │   │ ← 搜索为右上角浮层，不占布局
│                            └───────────┘   │
└────────────────────────────────────────────┘
```

要点：

- bottom panel 的 **tabbar 横向排列于面板顶部**，同一行内三段：可滚动 tab 区（tab = codicon 图标 + 标题 + ×关闭）→「打开的 tab」下拉按钮 → **面板级工具栏**（独立于滚动区，右对齐）；
- 工具栏只放高频两颗：**＋新建终端、拆分**；**清屏/终止不进工具栏**，收进终端内容右键菜单与 tab 上下文菜单；
- 单终端无标题行/状态行，xterm 视口占满 widget（100%×100% + 内边距）；
- **查找框做成终端右上角浮层**（绝对定位，默认隐藏，`find` 命令调出），完全不占布局空间；
- tab 标题动态跟随 shell `onTitleChange`，图标可随主题变色。

### 方案 D：REPL 上下分割式（PyGPT，"VS_Code_Python" 实际身份）

来源：[`参考代码/VS_Code_Python/src/pygpt_net/tools/code_interpreter/ui/widgets.py`](参考代码/VS_Code_Python/src/pygpt_net/tools/code_interpreter/ui/widgets.py)

⚠️ 该项目实为 **PyGPT**，无真 PTY 终端；对应物是"代码解释器面板"（REPL 体验）：

```
┌────────────────────────────────────────────┐
│ 输出                                        │
│  stdout/stderr（QWebEngineView）│ 历史      │ ← 水平分割（85:15，历史列可选）
├────────────────────────────────────────────┤
│ 代码输入区                                  │ ← 垂直分割下部（输出:输入 = 9:1）
├────────────────────────────────────────────┤
│ [清空] [☑IPython] [☑自动清空]        [发送] │ ← 底部按钮栏
└────────────────────────────────────────────┘
```

要点：主 `QTabWidget` 挂工具 tab → 内部 `QVBoxLayout[QSplitter垂直(QSplitter水平(输出|历史) / 输入), 底部按钮栏]`；无多会话、无状态栏。

## 3. 各方案优缺点

### 方案 A（现状）

| | |
|:---|:---|
| ✅ | 结构最简、实现已完成；真 PTY 交互完整（ANSI/光标/交互程序） |
| ❌ | 标题行信息架构无章法：shell 名仅是静态文本，无多会话承载力；「重开」独占按钮位，新操作无处安放 |
| ❌ | 无"隐藏面板"入口（只能靠拖 splitter，且 `setCollapsible(1, False)` 已禁止折叠） |
| ❌ | 排版缺陷刚修复（标题行膨胀），说明该行布局缺乏正式设计 |

### 方案 B（Multi_Cli_Studio）

| | |
|:---|:---|
| ✅ | 一行 header 承载全部操作（tab/新建/关闭/隐藏），信息密度高、视线路径短 |
| ✅ | tab 行内 × 关闭 + 下划线激活态，形态轻；`+` 跟在 tab 尾符合直觉 |
| ✅ | 拖拽把手独立于 header，面板高度调节有专属热区 |
| ✅ | 单终端内部零装饰，终端区利用率 100% |
| ❌ | 无查找、无清屏/终止入口（功能极简，需自行补充） |
| ❌ | 把手 + header 两行装饰，对 250px 默认高度的面板偏奢侈（可把把手并入 splitter handle） |

### 方案 C（Theia）

| | |
|:---|:---|
| ✅ | tabbar 同行工具栏：tab 区与工具栏**同一行**，垂直开销只有一行；工具栏独立于滚动区，tab 再多按钮也不被挤走 |
| ✅ | 功能分层成熟：工具栏只放高频（新建/拆分），低频进右键菜单，查找做成浮层不占布局——垂直空间利用率最高 |
| ✅ | tab 带图标 + 动态标题（跟随 shell 标题），多会话辨识度最好 |
| ✅ | 有"打开的 tab"下拉，溢出兜底完善 |
| ❌ | 架构最重（ToolbarAwareTabBar + 命令注册体系），完整照搬成本高 |
| ❌ | Theia 的 tabbar 是全局 shell 设施（编辑器/面板共用），Zen Studio 只需终端局部实现 |

### 方案 D（PyGPT）

| | |
|:---|:---|
| ✅ | 底部按钮栏语义直白；上下分割对"输出长、输入短"的 REPL 合理 |
| ❌ | 非真终端范式：无 PTY、无光标控制，输入/输出分区与 shell 行编辑模型冲突，**不适合真终端** |
| ❌ | 底部按钮栏 + 双分割，装饰行数最多，250px 高度下终端区被压缩最严重 |

## 5. 推荐结论与后续实施要点

**推荐：以 C（Theia）的信息架构为目标形态，按 B（Multi_Cli_Studio）的元素量级裁剪落地**——即"单行头部栏 + 浮层化低频功能"，分两个阶段演进：

### 阶段一（单会话，近期）

保持单 PTY 会话，把现有标题行重构为**正式的单行头部栏**：

```
┌────────────────────────────────────────────┐
│ 🖵 bash        [状态]  [清屏] [重开] [−]   │ ← 单行：左标识，右操作组
├────────────────────────────────────────────┤
│ $ █                                        │ ← 终端视口占满剩余
└────────────────────────────────────────────┘
```

实施要点：

1. 头部行高度锁定（`setFixedHeight` 或布局 stretch 约束，吸收本次"标题行膨胀"教训，DEBUG 边框在重构时移除）；
2. 右侧操作组按 B/C 惯例收敛为图标按钮：清屏（重置 pyte 屏幕 + 光标归位）、重开（已有）、**新增"隐藏面板"**（折叠 `QSplitter` 下段，需与 `setCollapsible(1, False)` 的现有防折叠策略协调）；
3. 按钮样式接入主题 qss（沿用 `QPushButton` 实体化描边体系），不再硬编码。

### 阶段二（多会话，中期）

头部栏左侧进化为 **tab 区**（`QTabBar` 或自绘 tab 条），右侧操作组前移到同行固定位置（Theia 的"工具栏独立于滚动区"原则）：

```
┌────────────────────────────────────────────┐
│ [🖵 bash ×] [🖵 zsh ×] [＋]     [清屏][−]  │
├────────────────────────────────────────────┤
│ $ █                                        │
└────────────────────────────────────────────┘
```

实施要点：

1. 每会话一套 `PtySession + TerminalScreen`，`TerminalWidget` 切换绑定（现有五层单向依赖结构天然支持）；
2. tab = 图标 + shell 名 + 行内 ×；`＋` 新建固定在 tab 尾或工具栏（二选一，建议工具栏，对齐 C）；
3. 查找等低频功能按 C 的做法做成**终端右上角浮层**，不占布局；
4. 终端内容右键菜单承接清屏/终止（对齐 C 的功能分层）。

### 明确不采纳

- **方案 D**（REPL 分割式）：与真终端行编辑模型冲突，且垂直开销最大；
- 方案 B 的独立拖拽把手行：面板高度调节由现有 `QSplitter` handle 承担，不额外增加一行装饰。
