## 1. 背景与需求

中栏（上）目前为占位面板（[`gui/main_window.py:39`](../../gui/main_window.py) `make_panel("中栏")`）；右栏文件树的 `file_opened(str)` 信号已就绪，暂以 `print` 兜底（[`gui/main_window.py:52`](../../gui/main_window.py)）。需求：

1. **点选文件 → 中栏显示内容**：单击选中/双击打开文件树中的文件，中栏（上）展示其文本内容
2. **语法高亮**：代码文件按语言着色；文档（Markdown 等）至少有等宽源码视图
3. **与主题一致**：高亮配色需适配现有明暗双主题（`config/themes/*.qss`）
4. **AI 改动即时可见**：文件被 agent 外部修改（AI 写盘）时自动重载并提示

边界（**AI-first 定位**，2026-07-19 用户决策）：本 IDE 的生产关系为"**AI 写、人审**"——中栏职责是**阅读 / 审查 / 喂上下文**（选段、行号引用），代码修改一律经 AI agent 落盘。**编辑、保存、代码补全永久剔除**（产品决策；技术上 `setReadOnly` 为可逆开关，不锁死）。依据三份借用分析报告的"代码浏览与高亮"章节（[`work charter/`](../../work%20charter/) 0757 / 0937 两份）做选型。

## 2. 参考实现调研结论

| 项目 | 高亮相关资产 | 结论与教训 |
|:---|:---|:---|
| VS_Code_Python（PyGPT） | `data/js/highlight/`（highlight.js 全套 ~190 语言，资产实测存在）+ `core/render/web/syntax_highlight.py`（58 行，QWebEngineView 前端高亮）；`MarkerHighlighter(QSyntaxHighlighter)` 65 行 | 🔴 **没有真正的代码编辑器**：highlight.js 方案仅覆盖"只读展示"；`QSyntaxHighlighter` 路线在其仓内仅用于查找标记 |
| Multi_Cli_Studio | `ChatFilePreviewPanel.tsx`（1268 行，CodeMirror 6）：只读/编辑切换、外部修改冲突检测（2s mtime 轮询）、Markdown/图片预览 | 🔴 **声明了 CodeMirror 却未加载任何语言包，无语法高亮**；Monaco 为死依赖。教训：选型必须一步到位带语言包，勿重蹈"有编辑器无高亮"；其预览面板的类型分派（代码/MD/图片）与冲突检测状态机值得借鉴（PySide6 用 `QFileSystemWatcher` 更优雅） |
| theia-zen | Monaco + TextMate grammar + LSP（工业级） | 🔴 深度绑定 Web 技术栈不可移植；官方建议路线：`QPlainTextEdit + QSyntaxHighlighter`（Pygments）或 QScintilla |

**关键启示**：

- 三家殊途同归指向 **`QPlainTextEdit + QSyntaxHighlighter`** 为 PySide6 原生正解；本项目的差异点在于一步到位接入语言级高亮（Pygments 500+ lexers），避开两个前人的坑。
- highlight.js 资产虽现成，但只解决只读场景且引入 WebEngine 重量；未来中栏必然走向可编辑，Web 路线届时需整体返工。
- **依赖底牌实测**（2026-07-19）：`pygments` 未装（纯 Python，`uv add` 零风险）；`PySide6.QtWebEngineWidgets` 已随 PySide6 就绪；`qscintilla`/`tree_sitter` 未装（新增二进制依赖）。

## 3. 候选方案对比（四个维度）

### 3.1 维度一：渲染引擎路线

| | A. QPlainTextEdit + Pygments 高亮器 | B. QWebEngineView + highlight.js | C. QScintilla | D. Monaco / tree-sitter |
|:---|:---|:---|:---|:---|
| 做法 | 自研 `PygmentsHighlighter(QSyntaxHighlighter)`：token → `QTextCharFormat`，lexer 按文件名探测 | 复制 PyGPT 资产：HTML 模板 + `highlight.min.js` + languages，Web 视图加载 | `QsciScintilla` 控件 + 内建 lexer | Web 内核 / 增量解析库 |
| ✅ 优点 | 原生 Qt 零重型依赖；**只读→可编辑无缝演进**（同一控件）；Pygments 500+ 语言、纯 Python 单依赖；与 qss 主题同进程配色，明暗主题易对齐 | 资产现成（58 行装配代码 + 全套语言包）；~190 语言开箱即用；天然支持 HTML 渲染（Markdown 预览同源） | 成熟编辑器内核：行号/折叠/缩进参考线内建，编辑能力一步到位 | 工业级体验 |
| ❌ 缺点 | 需自研适配层（~150 行：token 映射 + 增量区间高亮）；超大文件需性能守卫（3.4） | QtWebEngine 进程级重量（百 MB 内存级）；**可编辑演进死路**（届时整体返工）；复制/查找/字体等交互与原生控件不一致 | 新增二进制依赖（轮子含 PySide6 绑定）；主题配色需逐 lexer 手工对齐，与 qss 双主题打通成本高 | Monaco 绑定 Web 栈不可移植（theia-zen 结论）；tree-sitter 需逐语言管理 grammar，本期过度设计 |

### 3.2 维度二：内容类型覆盖策略

| | A. 纯源码视图（统一路径） | B. 代码视图 + Markdown 预览双模式 | C. 全类型预览（+图片/二进制） |
|:---|:---|:---|:---|
| 做法 | 所有文本文件走高亮源码视图（.md 按 markdown lexer 着色） | 代码走源码视图；.md 额外提供渲染预览（切换或并列） | 再扩图片 pixmap、二进制占位 |
| ✅ 优点 | 单一渲染路径，控件结构最简单；.md 源码高亮已可读性良好 | Multi_Cli 预览面板同款体验；文档阅读友好 | 文件树任意文件都有反馈 |
| ❌ 缺点 | .md 无渲染预览 | 需第二渲染通道（QTextBrowser markdown() 或 WebEngine），模式切换增加状态 | 本期范围膨胀，图片/二进制价值低 |

### 3.3 维度三：只读 vs 可编辑（AI-first 定位裁决）

| | A. 永久只读（`setReadOnly`，AI-first） | B. 可编辑 |
|:---|:---|:---|
| ✅ 优点 | 与"AI 写、人审"定位闭环：阅读/审查/喂上下文均无需键盘输入；彻底免除保存/冲突检测/撤销栈/补全一整层复杂度；`setReadOnly` 可逆开关保留后悔权，产品决策不锁死 | 传统 IDE 习惯；改 typo 等微调不经 AI 时更直接 |
| ❌ 缺点 | 微调摩擦：改 typo 也需使唤 AI（定位哲学使然，可接受） | **与 AI-first 定位冲突**：手动修改绕过 agent 上下文（AI 不知道人改了什么），破坏审查闭环；引入编辑全栈复杂度 |

🟢 **选 A（用户决策，2026-07-19）**：永久只读，永不引入代码补全。引擎选型（3.1-A）的意义随之从"为编辑铺路"变为"给产品决策保留可逆性"。

### 3.4 维度四：大文件与外部修改策略

| | A. 全量加载 + 大小守卫 | B. 分段/懒加载 |
|:---|:---|:---|
| 做法 | 一次性读入；超过阈值（如 1 MB）截断显示并提示"文件过大已截断" | 按滚动位置分块加载 |
| ✅ 优点 | 实现直白；`QPlainTextEdit` 对 1 MB 级文本渲染无压力（高亮为一次性全文档 pass，可控） | 理论上无上限 |
| ❌ 缺点 | 超大文件体验降级（但有明确提示，可接受） | 高亮上下文跨块维护复杂，本期过度设计 |

> 外部修改：**AI-first 下为主频场景，非低频**——agent 直接写盘是主修改路径，用户正在阅读的文件被 AI 改动时必须即时刷新，否则即审查事故。`QFileSystemWatcher` 自动重载 + 变更提示**纳入本期**（Multi_Cli 的 mtime 轮询方案为备选参考）。

## 4. 综合对比与推荐结论

🟢 **推荐组合：A + A + A + A**——`QPlainTextEdit`（只读）+ Pygments `QSyntaxHighlighter`，纯源码统一视图，全量加载加大小守卫：

| 维度 | 决策 | 理由 |
|:---|:---|:---|
| 渲染引擎 | **A. QPlainTextEdit + Pygments** | 原生正解、只读→可编辑零返工、单依赖纯 Python；避开 PyGPT（Web 只读死路）与 Multi_Cli（有编辑器无高亮）两个前车之鉴 |
| 类型覆盖 | **A. 纯源码统一视图** | 单一渲染通道最简；.md 走 markdown lexer 源码高亮已够用；Markdown 预览/图片预览备案 |
| 编辑性 | **A. 永久只读（AI-first）** | "AI 写、人审"闭环；`setReadOnly` 可逆保留后悔权；编辑/保存/补全永久剔除 |
| 大文件 | **A. 全量 + 1 MB 守卫** | 实现最简，阈值内体验完整；截断提示保底 |

**B/C 路线否决记录**：B（WebEngine + highlight.js）资产虽现成，但可编辑演进必然返工且交互不一致，否决；C（QScintilla）编辑能力超前于本期需求，引入二进制依赖与主题对齐成本，待编辑期再评估；D 为明确否决项（Web 绑定/过度设计）。

## 5. 实施要点（供后续计划引用）

1. **新增面板子包** `gui/panels/viewer/`：`CodeViewer(QPlainTextEdit)`（**只读**、等宽字体、行号栏 lineNumberArea + 当前行高亮——行号为人与 AI 的对话坐标系）+ `PygmentsHighlighter(QSyntaxHighlighter)`（token→`QTextCharFormat` 映射，`get_lexer_for_filename` 探测、失败回退纯文本）+ `ViewerPanel`（容器：路径标题行 + CodeViewer）。
2. **接线**：`main_window.py` 以 `ViewerPanel` 替换 `make_panel("中栏")`；`file_explorer.file_opened` 从 `print` 改接 `viewer_panel.open_file(path)`（读文件 → 按扩展名设 lexer → 全文高亮 → 标题行显路径）。
3. **外部修改自动重载（AI-first 主频场景）**：`QFileSystemWatcher` 监视当前打开文件，内容变化（AI 写盘）→ 自动重载并重新高亮，标题行提示"已重新加载"。
4. **主题对齐**：高亮配色表按明暗双主题各一份（`config/themes/` 同源色板；或 Pygments `default`/`monokai` 风格取色后微调），`apply_theme` 时同步重建高亮器。
5. **依赖**：`uv add pygments`（纯 Python）。
6. **守卫**：>1 MB 截断提示；二进制文件（读取解码失败）显示占位提示而非乱码。
7. **剔除**：代码折叠（本期）；Markdown 预览、图片预览（备案）；**编辑/保存/代码补全（永久剔除，AI-first 定位）**；`setReadOnly` 保留可逆开关。
