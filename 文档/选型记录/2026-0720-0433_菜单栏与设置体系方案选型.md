## 1. 背景与约束

### 1.1 现状盘点

当前菜单栏为骨架状态，全部硬编码在 `gui/main_window.py` 的 `_build_menus` 中：

| 菜单 | 现状 |
|:---|:---|
| 文件(&F) | 仅「退出」，无快捷键 |
| 编辑(&E) | 占位禁用「（待实现）」 |
| 视图(&V) | 终端面板显隐 ✓ / 过滤噪音目录 ✓ / 变更面板显隐 ✓ / 刷新 Git 状态 / 主题互斥组（5 主题动态生成） |

**已有持久化能力但无 UI 入口**（`gui/settings.py` 的 `update_settings` 合并写回机制已就绪）：

| 配置键 | 状态 |
|:---|:---|
| `font_size` | `apply_theme` 每次读取，但无修改入口 |
| `font_family` | settings.json 中已存在，但 `DEFAULT_SETTINGS` 未登记 |
| `model_backend` / `model_version` | 仅聊天面板 ModelBar 下拉可选，无全局入口 |
| 窗口几何 / 四组分隔栏 | 自动持久化，无「恢复默认布局」入口 |

**可接菜单的现有面板能力**：终端新建 tab / 清屏 / 重开 / 终止（右键菜单已有）、终端查找浮层、查看器打开文件、文件树噪音过滤、Git 手动刷新。

**需新增的能力（本次菜单驱动）**：

| 新功能 | 说明 |
|:---|:---|
| 打开文件夹（工作区根切换） | 程序项目多以文件夹形式存在，须支持切换工作区根。联动面：FileExplorer 换根目录、ChatPanel `workspace_root`（@相对路径计算基准）、GitStatusService 重建（新根下重新探测 git）、新终端会话 cwd（已存在的会话保持原 cwd 不动）、`workspace_root` 持久化供启动恢复 |
| 查看器查找浮层 | 查看器目前无查找能力（终端已有自己的浮层，可参照复用） |

### 1.2 项目约束

1. **AI-first 定位**：查看器永久只读，代码修改一律经 AI agent 落盘 → 编辑菜单不放写入类操作；「打开原始配置文件」反而符合项目哲学（配置修改可由 AI 落盘）。
2. **技术栈**：PySide6 原生 `QMenuBar`/`QMenu`/`QAction`，无自绘窗口 chrome 的计划。
3. **规模**：单主窗口、四面板，设置项目前 ≤ 8 个 → 拒绝过度设计，但需为增长留口。
4. **既有先例**：文件树 `FileExplorer` 移植自 PyGPT，已验证 PyGPT 风格代码与本项目兼容。
5. **既有模式**：面板显隐采用「单一入口」法（`_set_terminal_visible` 同步勾选态与可见性，`setChecked` 不触发 `triggered`），新项须照搬；主题互斥组用 `QActionGroup` + 闭包，已有实现。

## 2. 候选方案

分两个正交维度选型：**A. 菜单架构**（代码怎么组织）、**B. 设置组织**（设置项以什么形态呈现给用户）。

### 2.1 菜单架构

#### 方案 A1：极简直连式（现状顺延）

在 `_build_menus` 基础上继续补全，每个 `QAction` 当场创建、当场 `connect`，全部逻辑留在 `main_window.py`；文件过长时最多把 `_build_menus` 原样抽到新模块。

- 🟢 零抽象成本，所见即所得；与现有代码风格一致
- 🟢 工期最短
- 🔴 action 无法跨模块引用（如「AI 模型」菜单项想同步 ModelBar 勾选态，只能挂属性互相找）
- 🔴 菜单、快捷键、右键菜单三处同一功能各写一遍，状态易不同步（终端「新建会话」将在文件菜单与终端右键菜单重复）
- 🔴 `main_window.py` 已 265 行，补全后预计 400+ 行，主窗口类继续膨胀

#### 方案 A2：模块化菜单 + 全局 Action 注册表（PyGPT 风格）

新建 `gui/menus/` 包，每菜单一文件一类（`file.py` / `edit.py` / `view.py` / `settings.py` / `help.py`），由 `MenuBar` 装配器统一 `setup()`；所有 action 存入**全局注册表字典**（如 `actions["view.terminal"]`），任何模块可按名取 action 改勾选态/文本；单选组沿用 `QActionGroup(exclusive)`，改用 `setData()` 载荷共用单一回调（替代现在的 N 个闭包）。

- 🟢 与项目同栈同源（文件树已移植自 PyGPT，模式已验证）
- 🟢 action 全局可寻址，解决「菜单勾选态 ↔ 面板内按钮」双向同步（现有 `_set_terminal_visible` 模式正式化）
- 🟢 每菜单一文件，主窗口减重；新增条目不触碰其他菜单
- 🟡 无命令层抽象，快捷键仍挂在 action 上，未来做命令面板需二次改造
- 🟡 比 A1 多一层字典约定，需文档化键名规范

#### 方案 A3：命令注册表 + 三层分离（Theia 轻量版）

自建 `CommandRegistry`：命令 = `(id, label, callback, is_enabled)` 纯数据；菜单只登记 `(menu_path, command_id, order)`，路径排序前缀决定位置与分组；快捷键表只登记 `(command_id, QKeySequence)`。QAction 由注册表统一生成，菜单/快捷键/右键菜单/未来命令面板共享同一启用态。

- 🟢 一处定义四处复用，状态天然同步；命令面板（Ctrl+Shift+P）是注册表的免费副产品
- 🟢 扩展性最好，新功能（调试、Git 操作组）只挂点不改骨架
- 🔴 对当前规模（~25 个菜单项、无命令面板计划）明显过度设计
- 🔴 需自研路径排序、`when` 上下文求值等基础设施，工期最长、测试面最大
- 🔴 与项目「拒绝过度设计」的既有风格冲突

### 2.2 设置组织

#### 方案 S1：菜单直挂

不设设置对话框，设置项全部作为菜单条目：字体大小（增大 / 减小 / 重置默认）、主题子菜单（已有）、AI 模型子菜单（后端 + 版本互斥组）、开关类直挂勾选项。

- 🟢 零新窗口代码；设置项 ≤ 8 个时体验直接
- 🔴 项数增长后菜单臃肿；无法展示描述/分组；数值类（font_size 精确值）表达力差

#### 方案 S2：声明式设置对话框（PyGPT 风格）

设置项用 JSON/字典元数据声明（`type / section / label / description / min / max`），对话框左分区列表 + 右分页控件由元数据自动生成；保存走现有 `update_settings`。

- 🟢 新增设置项零 UI 代码；天然支持分区与描述
- 🔴 当前设置项太少，对话框基建（控件工厂、分区列表、校验）成本远超收益
- 🔴 与 settings.json 手写/AI 改并存时需注意读写时机

#### 方案 S3：混合双通道（菜单直挂 + 打开原始配置文件）

高频项（字体大小、主题、AI 模型、开关类）菜单直挂；同时在设置菜单提供「打开配置文件」——在查看器中打开 `config/settings.json`（只读展示，修改由 AI 落盘，契合 AI-first）。声明式对话框列为远期演进项，设置项超过 ~10 个再启动 S2。

- 🟢 当下成本最低，且向 S2 演进无返工（元数据声明可后补）
- 🟢 双通道兼顾普通用户与高级/AI 用户（PyGPT 已验证该模式）
- 🟡 「打开配置文件」只读，用户手改需经外部编辑器或 AI，需在状态栏/文档说明

## 4. 推荐结论

**采用 A2（模块化菜单 + 全局 Action 注册表）× S3（混合双通道）组合**，并做两点裁剪吸收：

1. **借 Theia 的命名纪律，不借其机制**：action 注册表键名采用 `菜单路径.动作` 规范（如 `view.terminal`、`settings.model`），即 Theia 菜单路径思想的扁平化。未来若上 A3 命令注册表或命令面板，键名可直接升格为 commandId，迁移零改名成本。
2. **借 PyGPT 的三件兵器**：① 每菜单一文件一类 + 装配器；② 单选组 `QActionGroup(exclusive)` + `setData()` 载荷共用回调（收敛现有主题组的 N 闭包写法）；③ 「图形设置 + 打开原始配置文件」双通道。

### 4.2 关键机制要点（实施时遵循）

| 机制 | 约定 |
|:---|:---|
| action 注册表 | 键名 = `菜单.动作`（如 `view.terminal`），集中在 `gui/menus/` 装配器登记；任何模块按名取 action |
| 快捷键 | **菜单一律不绑定快捷键**（保持简单）；文本控件 Qt 内建的 Ctrl+C/V/A 属控件级行为，不受影响、无需处理 |
| 面板显隐 | 沿用「单一入口」法：`_set_xxx_visible(v)` 同步 `setChecked` + `setVisible`，菜单勾选与面板头部「−」按钮汇入 |
| 单选组 | `QActionGroup(exclusive)` + `setData()` 载荷，单一回调读 `action.data()`；主题组顺手重构 |
| 工作区根切换 | 「打开文件夹」换根后四处联动：文件树换根 / ChatPanel `workspace_root` / GitStatusService 重建 / 新终端会话 cwd；`workspace_root` 持久化，启动时恢复（缺省 = 项目根） |
| 持久化 | 一律走 `update_settings` 合并写回；`font_family` 补登 `DEFAULT_SETTINGS` |
| 字体联动 | 字号变更 → `apply_theme(app)` 重设全局字体 + 通知查看器/终端等宽字号同步 |
| 不可折叠约束 | 右栏/中栏显隐后恢复显示时验证 splitter 尺寸恢复；closeEvent 已有「隐藏先恢复再保存」先例照搬 |
| 跨平台 | 「退出/设置/关于」类 action `setMenuRole(NoRole)` 防 macOS 系统菜单抢走（PyGPT 经验） |

### 4.3 实施分期建议

| 期 | 内容 | 性质 |
|:---|:---|:---|
| 一期 | `gui/menus/` 包落地 + 注册表；文件/视图/终端/设置（字体三件套 + 打开配置文件 + AI 模型子菜单）；**打开文件夹（工作区根切换 + 四处联动 + 持久化）**；现有视图项迁移 | 接线 + 重构 + 一项新功能 |
| 二期 | 查看器查找浮层（编辑菜单查找项按焦点分发）；恢复默认设置；帮助/关于 | 含新功能 |
| 远期 | 设置项 > 10 个时启动 S2 声明式对话框；需要命令面板时 A2 → A3 平滑升格（键名已按 commandId 规范） | 演进预留 |

### 4.4 明确排除项（本期不做）

- ❌ **菜单快捷键绑定** —— 保持简单，菜单一律不绑快捷键；文本控件 Qt 内建的 Ctrl+C/V/A 等控件级行为不在此列
- ❌ 命令面板 —— A3 副产品，随远期演进再议
- ❌ 自绘无边框窗口 chrome —— 与原生 QMenuBar 路线冲突
- ❌ 快捷键用户自定义（dict 配置 + 全局 eventFilter）—— 已无菜单快捷键，更无改键需求
- ❌ 声明式设置对话框（S2）—— 设置项不足，列为远期
- ❌ 多 Profile 配置方案 —— 单用户单工作区，无场景
