## 1. 背景与需求

当前聊天面板（[`gui/panels/chat/`](../../gui/panels/chat/)）直连 DeepSeek，模型在 [`llm/providers/deepseek.py`](../../llm/providers/deepseek.py) 中硬编码为 `deepseek-chat`，存在三个待补能力：

1. **模型名与版本可见**：用户需在与 AI 聊天时看到当前模型（如 "DeepSeek · V3.2 通用"），前者为模型名、后者为版本。
2. **版本下拉切换**：通过下拉框切换模型版本。本期只有 DeepSeek 一家 API key，仅实现版本级切换，模型级（多 provider）切换留作后续。
3. **思考块显示**：切换到推理版本（`deepseek-reasoner`）时，思维链需区别渲染上屏。

DeepSeek 官方 API 实际仅有两个版本（模型 ID）：

| 模型 ID | 定位 | 思维链字段 |
|:---|:---|:---|
| `deepseek-chat` | 通用对话（当前指向 DeepSeek-V3.2 非思考模式） | 无 |
| `deepseek-reasoner` | 推理（当前指向 DeepSeek-V3.2 思考模式） | 流式 `delta.reasoning_content` |

> 显示名/版本别名由本地定义（如 "V3.2 通用" / "V3.2 思考"），API 本身不返回友好名称。

## 2. 参考实现调研结论

| 项目 | 模型切换实现 | 思考块实现 |
|:---|:---|:---|
| PyGPT（VS_Code_Python） | `models.json` 配置文件为数据源（含 `deepseek-reasoner` 条目）；toolbox 区 `ModelCombo` 下拉框按 provider 分组；切换即写 config、下次请求生效；生成中锁定；per-mode 记忆上次选择（[`controller/model/model.py`](../../参考代码/VS_Code_Python/src/pygpt_net/controller/model/model.py)、[`data/config/models.json`](../../参考代码/VS_Code_Python/src/pygpt_net/data/config/models.json)） | **无 `reasoning_content` 解析**；仅支持模型把 `<think>...</think>` 内联进 content 的场景，经自定义 HTML 标签 + CSS 渲染为灰字左竖条（[`web-chatgpt.css:82-89`](../../参考代码/VS_Code_Python/src/pygpt_net/data/css/web-chatgpt.css)） |
| Multi_Cli_Studio | —（编排外部 CLI，非本形态） | **最完整链路**：Rust 后端解析 `delta.reasoning_content`（兼容 `reasoning` 别名）与 `content` 双通道累积（[`main.rs:3093-3115`](../../参考代码/Multi_Cli_Studio/src-tauri/src/main.rs)）→ 存储时合成 `<think>` 包装 → 前端解析为 `{kind:"reasoning"}` 独立 block → 渲染为可折叠紫罗兰卡片（默认摘要 2 行/220 字符 + 展开按钮） |
| theia-zen | `LanguageModel` 注册表（已吸收进本项目 `llm/`） | 独立内容类型 `ThinkingChatResponseContent` + 渲染器用原生 `<details>/<summary>` 折叠（[`thinking-part-renderer.tsx`](../../参考代码/theia-zen/packages/ai-chat-ui/src/browser/chat-response-renderer/thinking-part-renderer.tsx)） |

**关键启示**：

- 思考块必须**双通道分离**：`reasoning_content` 与 `content` 在流式中交错到达，需分别累积、区别渲染（Multi_Cli_Studio 的 Rust 层做法可直接翻译为 Python）。
- DeepSeek 官方约束：**多轮请求不得回传 `reasoning_content`**，历史中只存 `content`；思考内容仅用于当次显示。
- PyGPT 的模型选择器细节值得吸收：生成中锁定下拉、切换写配置下次请求生效。

## 3. 候选方案对比（四个维度）

### 3.1 维度一：版本清单数据源

| | A. provider 内常量 | B. 配置文件 | C. 运行时 API 拉取 |
|:---|:---|:---|:---|
| 做法 | `deepseek.py` 内 `MODELS = {"deepseek-chat": "V3.2 通用", ...}` | 新建 `config/llm_models.json`，仿 PyGPT `models.json` 简化版 | 启动时 `client.models.list()`（PyGPT 导入器同款） |
| ✅ 优点 | 零依赖、离线可用、实现 <20 行；2 个版本场景下最经济 | 增删版本/显示名不改代码；为多 provider 时代铺路 | 永远与账号实际可用版本一致 |
| ❌ 缺点 | DeepSeek 升级指向版本时需改代码发版 | 第一期仅 2 个版本，多一层文件 IO 与校验，过度设计 | 启动即依赖网络，失败需兜底；API 只返回裸 ID，友好显示名仍需本地映射表，实际收益低 |

### 3.2 维度二：显示与切换的 UI 位置

| | A. 面板顶部工具条 | B. 输入区底部内嵌行 | C. 主窗口状态栏 |
|:---|:---|:---|:---|
| 做法 | splitter 上方加一行：`QLabel("模型")` + `QComboBox`（选中项即当前版本显示） | 输入框底部嵌一行模型选择（PyGPT toolbox 语义：模型是发送参数） | `QStatusBar` 常驻显示 + 弹起菜单切换 |
| ✅ 优点 | 显眼，"看到当前模型"需求天然满足；实现直白（`QVBoxLayout` 顶部 insert） | 语义贴近发送动作，主流聊天工具常见 | 不占面板空间 |
| ❌ 缺点 | 左栏 320px 宽内再占一行垂直空间 | 输入区已 150px 高，再挤一行压缩输入体验；`ChatInput` 需改构造 | 离聊天面板远，状态栏语义是瞬态提示，放置持久控件不合适 |

### 3.3 维度三：llm 层接口扩展（思考块传输通道）

| | A. `Chunk` 数据类（改协议） | B. 双接口并存 | C. 内联 `<think>` 包装 |
|:---|:---|:---|:---|
| 做法 | `chat()` 返回 `Iterator[Chunk]`，`Chunk(kind: Literal["text","reasoning"], text: str)` | `chat()` 保留返回 str，另加 `chat_events()` 返回带类型流 | 接口零改动，provider 把思考包成 `<think>...</think>` 内联进文本流（Multi_Cli_Studio 存储层同款思路），UI 端解析 |
| ✅ 优点 | 类型明确、UI 零解析；可扩展未来 `tool_call` 等块类型；与 theia-zen `ThinkingChatResponseContent` 独立类型理念一致 | 向后兼容，旧调用方不动 | 接口与 worker 完全不改 |
| ❌ 缺点 | 改 Protocol 签名，`worker.py`/`panel.py` 同步改（均在项目内，可控） | 两个接口语义重叠，长期是腐化点 | UI 需流式解析标签且防半截标签（PyGPT `stream.js:381-392` 有专门的防拆保护，可见坑之实）；文本协议脆弱，模型若原样输出 `<think>` 会误判 |

### 3.4 维度四：思考块渲染方式

| | A. 输出区内联灰字竖条 | B. 可折叠块 | C. 纯文本前缀 |
|:---|:---|:---|:---|
| 做法 | `ChatOutput` 收到 reasoning 块时 `insertHtml` 灰字 + 左竖条样式片段（PyGPT `think` CSS 思路移植到 QTextBrowser） | 思考内容进独立可折叠控件（theia-zen `<details>` / Multi_Cli_Studio 卡片同款），默认折叠 | 输出 `[思考] ... [/思考]` 纯文本 |
| ✅ 优点 | 不新增控件，输出区保持单一滚动体；视觉贴近主流 IDE；与现有 `append_stream_chunk` 流式上屏机制兼容 | 长思维链不占屏，可展开查阅；体验最佳 | 零成本 |
| ❌ 缺点 | 不可折叠，长思维链占输出区高度 | QTextBrowser 内嵌交互控件需改输出区为 widget 列表结构，第一阶段成本高 | 视觉噪音大，无样式区分 |

## 4. 综合对比与推荐结论

🟢 **推荐组合：A + A + A + A**（各维度第一方案），折叠块渲染（维度四-B）与配置文件数据源（维度一-B）列为第二期演进：

| 维度 | 决策 | 理由 |
|:---|:---|:---|
| 版本清单 | provider 内常量 `MODELS`（dict：模型 ID → 显示版本名） | 2 个版本场景下最经济；后续接入多 provider 时再升级配置文件 |
| UI 位置 | 面板顶部工具条（`QLabel` + `QComboBox`） | 直接满足"可见当前模型名+版本"；不挤占输入区 |
| 接口扩展 | `Chunk` 数据类（`kind: "text" \| "reasoning"`） | 类型安全、UI 零解析、可向未来块类型演进 |
| 思考块渲染 | QTextBrowser 内联灰字左竖条 | 与现有流式上屏机制兼容，成本最低；折叠块列入第二期 |

下拉项与顶部显示格式建议：`DeepSeek · V3.2 通用（deepseek-chat）` / `DeepSeek · V3.2 思考（deepseek-reasoner）`——模型名 + 版本别名 + API ID 三者齐显。

## 5. 实施要点（供后续计划引用）

1. **llm 层**：`base.py` 新增 `Chunk` 数据类，`LanguageModel.chat()` 签名改为 `Iterator[Chunk]`；`deepseek.py` 增加 `MODELS` 常量与 `set_model(model_id)`（或构造传参），流式解析增加 `delta.reasoning_content` 分支（`getattr` 容错，chat 版本无此字段）。
2. **面板层**：`panel.py` 顶部加工具条（`QLabel` + `QComboBox`），切换写实例变量、**下次请求生效**；发送中锁定下拉（仿 PyGPT `change_locked`）。
3. **历史管理**：`_history` 与 `_stream_buffer` 只累积 `kind=="text"` 的块；`reasoning` 块仅当次上屏，**不回传 API**（DeepSeek 官方约束）。
4. **渲染**：`ChatOutput` 增加 `append_reasoning_chunk()`，灰字 + 左竖条 HTML 片段；流式结束在思考区与正式回复间插入分隔。
5. **版本显示**：工具条下拉选中项即当前版本显示；首期无持久化（重启回默认 `deepseek-chat`），持久化入 `config/settings.json` 列为可选增强。

## 6. 后续阶段（备案）
