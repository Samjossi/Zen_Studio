# 图片文件预览功能选型

## 1. 背景与目标

Zen Studio 中栏文件查看器当前**只能显示文本**：双击 `.svg` / `.png` 等图片文件时，标题行提示"（二进制文件，共 N 字节，不支持预览）"。这与一个 IDE 的基本期望（能就地浏览工作区内的图片资产、Logo、截图、图标）不符。

**目标**：在中栏查看器中支持图片文件的就地预览，提供符合 IDE 习惯的交互（缩放/平移/适应窗口/实际像素/同目录翻页），并对 SVG 做矢量无损渲染。形态上尽量复用现有查看面板的基建（标题行、外部修改自动重载、Git 差异徽标、查找浮层框架），不引入重型依赖。

本选型基于对三个参考项目图片浏览实现的调研，提炼可借鉴点并提出 Zen Studio 的实现方案候选，供审阅定夺。

---

## 2. Zen Studio 现状与接入点

### 2.1 现有架构

中栏文件查看器由两个文件构成：

- `gui/panels/viewer/panel.py` — `ViewerPanel`：标题行（路径 + Git 差异徽标 + 状态提示）+ 查看器 + `QFileSystemWatcher` 外部修改自动重载 + 右上角查找浮层。对外接口 `open_file(path)` 是打开文件的唯一入口。
- `gui/panels/viewer/code_viewer.py` — `CodeViewer`：`QPlainTextEdit` 派生，只读、行号栏、当前行高亮、软换行，专司**文本**。

### 2.2 不能预览图片的根因

`ViewerPanel.open_file` 的处理链是"读字节 → UTF-8 解码 → 上屏"：

```python
# gui/panels/viewer/panel.py（open_file 核心分支）
raw = p.read_bytes()
...
try:
    text = raw.decode("utf-8")
except UnicodeDecodeError:
    return self._show_placeholder(f"（二进制文件，共 {len(raw)} 字节，不支持预览）", path=str(p))
```

图片是二进制，必然落入 `UnicodeDecodeError` 分支，被当作"不支持预览"的占位文本处理。这是功能缺失的根因，也是接入点所在。

### 2.3 接入点

最小侵入的接入方式：在 `open_file` 开头**按文件类型分流**——文本走现有 `CodeViewer`，图片走新增的图片预览控件，两者用 `QStackedLayout` 在同一面板内切换（复用标题行/watcher/Git 徽标等面板壳）。详见 §4.3 形态 1。

依赖底牌：`pyside6>=6.11.1`（见 `pyproject.toml`），`QImageReader` / `QPixmap` / `QGraphicsView` / `QSvgRenderer` / `QSvgWidget` 均随 PySide6 就绪，**零新增第三方依赖**即可实现。

## 3. 参考项目调研

三个项目分属三种技术栈，控件层只有 VS_Code_Python 可直接移植，但三者在**架构思路与交互设计**上各有可借鉴之处。

> ⚠️ **协议合规边界（theia-zen）**：theia-zen 为 EPL-2.0（文件级弱传染）。依据 `../审计报告/2026-0729-1028_theia实质代码审计与协议补全建议.md` 的审计结论，对 theia-zen **仅限思想/架构/交互范式级借鉴**——禁止翻译式移植其 TypeScript 代码、禁止复制其资产（图标/样式/文案）。本文标注的所有 theia"可借鉴点"（OpenHandler 竞标、source/preview 双模式、预览器即主区 widget、watcher 刷新）均为**设计概念**，实施时须以 PySide6 独立实现。项目整体采用 MIT 协议，根目录将补 `NOTICE` 致谢 Eclipse Theia 并注明"仅设计参考、未复制代码"。另两项目（VS_Code_Python/PyGPT、Multi_Cli_Studio）为 MIT，移植其代码片段时须保留对应版权声明（见审计报告 §4.3 预防性条款）。

### 3.1 theia-zen（Theia / TypeScript / Electron）

**实现概要**：图片预览由 `@theia/mini-browser` 包承担——前端是一个嵌在主编辑区的 `<iframe>` Widget，后端是一个 Express 静态端点，按扩展名分派 `ImageHandler`（jpg/jpeg/png/bmp/gif）/`SvgHandler`（svg）回传原始字节，渲染与缩放全部交给 Chromium 内核。

**关键架构（最值得借鉴）**：
- **OpenHandler 优先级竞标**：打开文件时，各 `OpenHandler` 用 `canHandle(uri)` 返回优先级整数，最高者赢得打开权。文本编辑器恒返回 100，图片预览对图片扩展名返回 101（胜出），SVG 返回 1（默认进文本编辑器，可显式以"预览"模式 200 分打开）。
- **`openFor: 'source' | 'preview'` 双模式**：同一 URI 可被不同 opener 以不同意图打开，对 SVG/Markdown 这类"既是文本又是图形"的格式尤其好用（源码视图 ↔ 渲染视图互跳）。
- **预览器即主区普通 Widget**：图片预览不特殊，实现统一 `NavigatableWidget` 接口，与编辑器共用分栏/拖拽/tab 外壳。
- **文件 watcher + 去抖自动刷新**。

**交互**：❌ 几乎没有——无缩放/平移/适应窗口/翻页，完全依赖浏览器对裸图片的原生查看。

**可借鉴度**：控件层 ❌ 不可移植（Web+iframe+HTTP 端点，PySide6 下属本末倒置）；架构思路 ✅ 高（优先级分派、source/preview 双模式、预览器即主区 widget）。

### 3.2 VS_Code_Python / PyGPT（🟢 PySide6 6.9.1，与 Zen Studio 同源）

> **关键发现**：该项目虽被普遍称作"PyQt 应用"，但 `pyproject.toml` 实际声明 `PySide6==6.9.1`，全部源码为 `from PySide6.Qt...`。**与 Zen Studio API 层面零差异，可直接移植。**

**实现概要**：独立的"微型看图程序"，核心两个文件（约 1350 行）：
- `src/pygpt_net/tools/image_viewer/tool.py` — 打开/关闭/保存/删除/目录导航/剪贴板/全屏
- `src/pygpt_net/tools/image_viewer/ui/dialogs.py` — UI：对话框、工具栏、状态栏、缩放/平移事件

**技术控件**：`QLabel + QPixmap + QScrollArea`，"双 QLabel"模式（一个隐藏存原始尺寸 pixmap，一个可见显示缩放副本）。**无 QGraphicsView，无 SVG 支持**（SVG 被排除在预览列表外，GIF 仅静态首帧）。

**交互（实现扎实，代码可抄）**：
- ✅ 滚轮缩放：步进 1.25×，范围 5%–1600%，**以鼠标位置为锚点**保持指向点不动
- ✅ 适应窗口（fit）/ 手动（manual）双模式，`resizeEvent` 自动重算
- ✅ 拖拽平移（仅图大于视口时，抓手光标）
- ✅ 同目录上一张/下一张（循环，复用窗口原地重载）
- ✅ 状态栏：目录序号 i/N、显示尺寸、缩放百分比、原始分辨率+文件大小
- ✅ 另存为 / 复制到剪贴板 / 伪全屏（`setGeometry` 规避 QDialog 全屏平台坑）
- ✅ 超大图防护：单边钳制 32768px、总像素钳制 80MP

**可借鉴度**：🟢 **S 级**。核心缩放/平移/目录导航/状态栏/大图防护代码可直接复制，主要工作是架构形态从"独立 `QDialog`"改造为"内嵌 `QWidget`"，并自补 SVG（`QSvgRenderer`）、GIF 动画（`QMovie`）、键盘快捷键。

### 3.3 Multi_Cli_Studio（Tauri / Rust + TypeScript）

**实现概要**：多 CLI AI 代理编排工作台（非图片工具），但在"工作区文件预览面板"场景实现了图片预览。前端 React + 原生 `<img>`（`object-contain` 适应窗口），Rust 后端统一定性文件 `kind`（text/image/pdf/binary-unsupported）回传 base64 给前端。

**关键架构（值得借鉴）**：
- **后端统一 `kind` 分类驱动前端路由**：一个 `classify_file(path) -> FileKind` 决定渲染器（文本/图片/PDF/不支持），路由清晰、易扩展新类型。
- **文件树双击 → 内嵌分割预览面板（多 tab）**：形态与 IDE 场景契合。
- **棋盘格透明底**（纯 CSS 渐变实现）：透明 PNG 预览的细节体验。
- **全屏遮罩**：ESC/点击关闭、深色半透明底、顶栏文件名+MIME、"在文件夹中显示"。
- 大图阈值（4MB）+ `truncated` 标志 + asset 协议 onError 多候选回退链（这是 Web 沙箱逼出来的复杂度，PySide6 不需要）。

**交互**：❌ 无缩放/平移/翻页（仅 `object-contain` + `overflow-auto`）。

**可借鉴度**：控件层 ❌ 不可移植（Web 栈）；架构思路 ✅ 高（kind 分类路由、棋盘格底、全屏遮罩交互细节）。其缺失的缩放/平移恰是 Zen Studio 用 `QGraphicsView` 低成本超越的空间。

### 3.4 三项目交互能力横向对比

| 能力 | theia-zen | VS_Code_Python | Multi_Cli_Studio |
|:---|:---:|:---:|:---:|
| 适应窗口 | 浏览器原生 | ✅ fit 模式 | ✅ object-contain |
| 滚轮缩放（锚点） | ❌ | ✅ 扎实 | ❌ |
| 拖拽平移 | ❌ | ✅ | ❌ |
| 同目录翻页 | ❌ | ✅ | ❌（多 tab 切换） |
| 状态栏元信息 | ❌ | ✅（i/N/尺寸/百分比） | △（截断提示） |
| SVG 矢量渲染 | △（浏览器渲染） | ❌（不支持 SVG） | ❌（当位图） |
| 棋盘格透明底 | ❌ | ❌ | ✅ |
| 全屏预览 | ❌ | ✅（伪全屏） | ✅（遮罩 overlay） |

| **可移植到 PySide6** | ❌ | 🟢 S 级（同栈） | ❌ |

**小结**：三个参考项目无一"完美"。VS_Code_Python 代码最可移植但形态（独立窗口）与 IDE 不符、且缺 SVG；另两个交互贫瘠。Zen Studio 的最优解是**博采众长**：以 Qt 原生控件重写，借鉴三者各自的架构亮点。

## 4. 候选方案

图片预览的实现可沿四个**正交维度**分别选型。各维度独立给出候选，最终推荐为各维度选择的组合。

### 4.1 维度一：位图渲染控件

| | 方案 A：`QLabel + QPixmap + QScrollArea` | 方案 B：`QGraphicsView + QGraphicsScene` | 方案 C：`QWebEngineView` |
|:---|:---|:---|:---|
| 来源 | 借鉴 VS_Code_Python（有现成代码） | Qt 原生自绘 | 借鉴 theia-zen 思路（PySide6 侧落地） |
| 缩放 | 手写 `eventFilter`，重建 pixmap 或 `setScaledContents` | 内建 `scale()`/`setTransform`，滚轮事件十几行 | Chromium 原生（点击放大） |
| 平移 | `QScrollArea` 滚动条 / 手写拖拽 | 内建 `DragMode.ScrollHandDrag`（一行） | 浏览器原生滚动 |
| 适应窗口 | 手算 `scaled(KeepAspectRatio)` | 内建 `fitInView()`（一行） | CSS `object-contain` |
| 性能（大图） | 中（每次缩放重建/拉伸整图） | 高（仅渲染视口可见区域） | 高（Chromium） |
| SVG 支持 | 需另接 `QSvgRenderer` | `QGraphicsSvgItem` 矢量原生 | 浏览器原生矢量 |
| 可抄代码 | 🟢 VS_Code_Python 现成 | 需自写（但逻辑短） | ❌ |
| 新增依赖 | 无 | 无 | ⚠️ 与项目路线冲突（见下） |

**方案 C 否决依据**：项目在 viewer / 终端 / 聊天面板选型中**一致否决 WebEngine**（见 `文档/选型记录/2026-0719-0205_中栏代码显示与语法高亮选型报告.md`："QtWebEngine 进程级重量（百 MB 内存级）"；`2026-0719-0405_中栏下终端面板选型报告.md`："原生 Qt 优先，WebEngine 否决"）。仅为图片预览引入 WebEngine 违背既定的轻量哲学，🔴 **否决**。

### 4.2 维度二：SVG 处理

| | 子方案①：矢量渲染 | 子方案②：栅格化为 QPixmap |
|:---|:---|:---|
| 控件 | `QSvgRenderer` → `QGraphicsSvgItem`（方案 B）/ `QSvgWidget` | `QSvgRenderer` 渲染到 `QPixmap` 后按位图处理 |
| 放大质量 | 无损（矢量） | 模糊（像素化） |
| 与位图统一性 | 需在 scene 里区分 item 类型 | 完全统一（都是 pixmap） |
| 推荐 | 🟢 推荐（SVG 是 Zen Studio 核心资产，见 logo 工作流） | △ 简单但牺牲质量 |

### 4.3 维度三：架构形态

| | 形态 1：内嵌 ViewerPanel（`QStackedLayout`） | 形态 2：独立 tab / 窗口 | 形态 3：OpenHandler 注册 |
|:---|:---|:---|:---|
| 描述 | 在 `ViewerPanel` 内用 `QStackedLayout` 在 `CodeViewer` 与图片控件间切换 | 仿 VS_Code_Python 独立 `QDialog`，或单独图片 tab | 仿 theia-zen 抽象 `OpenHandler` 优先级竞标机制 |
| 复用面板基建 | 🟢 标题行/watcher/Git 徽标/查找浮层全复用 | ❌ 需另起一套 | 取决于实现 |
| 侵入度 | 低（`open_file` 加分流） | 中（新窗口/新 tab 体系） | 高（重构打开机制） |
| 与现状契合 | 🟢 最高 | △（Zen Studio 当前是单查看面板，非多 tab 编辑器区） | △ 当前无多 opener 需求，属过度设计 |
| 推荐 | 🟢 推荐 | △ | 🔴 当前过度设计，留待多 tab 编辑器期再评估 |

### 4.4 维度四：文件路由

| | 路由①：`open_file` 内按扩展名分流 | 路由②：OpenHandler 优先级竞标 |
|:---|:---|:---|
| 描述 | `open_file` 开头判定扩展名，文本→CodeViewer，图片→图片控件 | 仿 theia-zen，各 opener 返回优先级，最高者打开 |
| 复杂度 | 极低（一个 `if` 分支 + 扩展名表） | 中（需定义 opener 协议、注册表、竞标） |
| 扩展性 | 加新类型改一处 | 加新类型加一个 opener（开闭原则） |
| 当前必要性 | 🟢 足够（仅文本/图片两类） | 🔴 当前类型少，过度设计 |
| 推荐 | 🟢 推荐 | 留待未来类型增多（PDF/Markdown 预览等）再演进 |

## 5. 综合对比与推荐结论

### 5.1 推荐方案组合

| 维度 | 推荐 | 理由 |
|:---|:---|:---|
| 位图控件 | **方案 B：`QGraphicsView`** | 缩放/平移/适应窗口均为内建（vs 方案 A 全手写），大图性能好，SVG 可用 `QGraphicsSvgItem` 矢量原生。代价是无可抄代码，但需自写的逻辑量很小 |
| SVG | **矢量渲染** | SVG 是 Zen Studio 核心资产（logo 母版即 SVG），矢量无损放大有实际价值 |
| 形态 | **形态 1：内嵌 ViewerPanel + `QStackedLayout`** | 最低侵入，复用现有面板基建，与单查看面板现状契合 |
| 路由 | **`open_file` 按扩展名分流** | 当前类型少，简单直接；未来类型增多时可平滑演进到 OpenHandler |

> 说明：方案 A（`QLabel`）因有 VS_Code_Python 现成代码、上手更快，是"求快"时的合理替代；但中长期看 `QGraphicsView` 的内建交互与性能优势更值得一次性投入。**二者可由实施者按偏好二选一**，本选型倾向 B。

### 5.2 各参考项目的借鉴落点（博采众长）

| 借鉴来源 | 落到 Zen Studio 的具体点 |
|:---|:---|
| VS_Code_Python | 目录导航（上一张/下一张）、状态栏元信息（i/N、分辨率、缩放%）、大图防护（32768px/80MP 钳制）、锚点缩放算法、伪全屏——**这些与控件无关，可直接移植到 `QGraphicsView` 方案** |
| Multi_Cli_Studio | 后端统一 `kind` 分类驱动路由、棋盘格透明底（`QPainter` 16px 棋盘刷）、全屏遮罩（ESC/点击关闭/reveal in folder） |
| theia-zen | `source`/`preview` 双模式（对 SVG 提供"源码视图 ↔ 渲染视图"切换）、文件 watcher 自动刷新（Zen Studio 已有，直接复用） |

### 5.3 交互目标清单（综合三者 + 超越）

实施时应达到的交互能力（参考项目无一全部具备，Zen Studio 可全部实现）：

- ✅ 超大图防护
- ✅ 全屏预览（ESC/点击关闭）
