# 主题体系架构方案选型

## 1. 背景与约束

### 1.1 现状盘点

- 五套主题为 `config/themes/` 下**五个完整 qss 副本**（各 ~320 行），2026-07-20 五主题一致性复查（0734 计划清理项 2）逐文件比对证实：**结构 100% 同构，仅色值不同**。
- 加载机制（[`gui/theme.py`](gui/theme.py) `apply_theme()`）：读 settings.json 的 `theme` 字段 → 原样加载对应 qss → `setStyleSheet`，无任何加工。
- 主题注册表 `THEME_META`（label + family 两字段）；qss 管不到的颜色已有集中管理先例——`GIT_STATUS_COLORS` 按明暗两族集中在 theme.py。

### 1.2 痛点（本次选型的直接动因）

1. **跨规则耦合色值漂移**（已实际发生）：菜单（`QMenu`）与下拉弹出层（`QComboBox QAbstractItemView`）是 Qt 里两个不同控件栈，必须是两条 qss 规则；QSS 无变量机制，同语义色只能重复写字面值。当年菜单取微染灰、下拉取纯白，各自演进产生色差（2026-07-20 用户发现，已手工对齐修复）。
2. **五副本维护成本**：任何样式调整须同步改 5 个文件（本次配色统一即手工改 5 处），漏改即产生主题间不一致。
3. **耦合关系隐性化**：`QMenu.background-color` 与 `QComboBox QAbstractItemView.background-color` 必须相等这类约束，目前在代码里无任何显式表达，只能靠人记忆。

### 1.3 项目约束

1. **技术栈**：PySide6 Qt Style Sheets——无 `var()`/自定义属性，任何"色值复用"必须在 qss 文本之外解决。
2. **验证基础设施已就绪**：离屏截图 + 像素断言 + 多模态视觉复核流程（`.tmp/round2_verify.py`，17 项断言）可直接扩展为架构改造的等价性验收工具。
3. **规模**：五主题、单模板渲染在启动路径上，渲染耗时须可忽略（字符串替换级）。
4. **拒绝过度设计**：令牌提炼范围与主题实际差异点对齐，不为"可能的未来需求"过度抽象。

## 2. 候选方案

### 方案 A：维持五副本 + 交叉注释规约（最轻治理）

架构不动。在五套 qss 的 `QMenu` 与 `QComboBox QAbstractItemView` 段注释中互相点名耦合关系（"改底色/圆角须同步对方"），并将耦合点清单写入规约文档。

- 🟢 零架构风险，不改任何运行逻辑，立即可做
- 🟢 耦合关系从隐性变为显式（读 qss 的人当场可见）
- 🔴 防呆不防忘：依赖人自觉遵守，五副本同步修改的体力活依旧
- 🔴 注释本身也会腐化（改色忘改注释）

### 方案 B：方案 A + 一致性校验脚本（机器防回归）

在 A 基础上新增校验脚本：解析五套 qss，断言每套内 `QMenu.background-color == QComboBox QAbstractItemView.background-color`、圆角相等、五套结构同构（规则集合一致）。纳入验证流程（与 `round2_verify.py` 同级）。

- 🟢 漂移可被机器捕获，不靠人记忆；一次编写长期有效
- 🟢 仍不动运行架构，风险低
- 🔴 只"发现"问题不"消除"问题：耦合点越多，校验清单越长；五副本维护成本未降
- 🔴 校验覆盖范围需要随样式演进人工维护（新型浮层加入时须记得补断言）

### 方案 C：单模板 + 调色板字典（模板渲染架构）

五副本合并为唯一模板 `config/themes/base.qss`（色值写 `{{占位符}}`），每主题一个色值字典集中在 `theme.py`（如 `THEME_PALETTES["cloud"]["popup_bg"]`）；`apply_theme()` 加载模板 → 字典渲染 → `setStyleSheet`。耦合色（菜单/下拉同底色）在字典里是**同一个令牌**，模板两处引用 `{{popup_bg}}`——物理上不可能漂移。

两个子档：

| 子档 | 提炼范围 | 说明 |
|:---|:---|:---|
| C1 最小模板化 | 仅提炼已发生/可预见的耦合令牌（浮层底色/描边/圆角、选中色） | 模板仍含大量字面值，五主题差异点之外的重复未消除 |
| C2 全量令牌化 | 五副本全部差异点提炼为令牌，模板纯结构化 | 一份模板管全部主题；新增主题 = 加一行字典 |

- 🟢 单一事实源：耦合令牌改一处即全局生效；五副本同步体力活彻底消除
- 🟢 新增主题成本骤降（当前 = 复制 320 行再逐处改色，易漏；C2 = 加一字典）
- 🟢 与 `GIT_STATUS_COLORS`/`THEME_META` 集中管色先例同构，架构心智统一
- 🟢 验收可严格自动化：渲染结果与现行五文件逐字节等价 + 截图像素回归
- 🔴 手术面大：五 qss 文件退役、theme.py 加载链路改造（虽仅 `apply_theme` 一处）
- 🔴 模板含占位符，不再是合法 qss——编辑器语法高亮/直接预览失效
- 🔴 令牌清单设计是一次性决策，漏提炼的差异点后续发现时须补令牌（有校验兜底则可控）

### 方案 D：叠加补丁层（五副本保留 + 代码生成耦合规则覆盖）

五套 qss 保留不动，仅把**耦合规则**（`QComboBox QAbstractItemView` 的底色/圆角）从 qss 中删除，改由 `theme.py` 按各主题 QMenu 色值动态生成一小段 qss，追加在 `setStyleSheet(原qss + 补丁)`。

- 🟢 手术面最小：只动 `apply_theme` 与五文件的耦合规则段
- 🟢 耦合色单一事实源（字典），漂移消除
- 🔴 治标不治本：五副本其余 95% 重复依旧，新增第二类浮层又得扩补丁逻辑
- 🔴 样式来源分裂（qss 文件 + 代码补丁两处），排查样式问题需看两个地方
- 🔴 补丁规则依赖 qss 选择器优先级覆盖语义，脆弱

## 4. 推荐结论

**推荐方案 C2（单模板 + 全量调色板字典），以 B 的校验脚本作为迁移期与迁移后的双保险。**

理由：

1. 五副本结构 100% 同构已被实证——C2 的前提成立，合并无信息损失；
2. 项目正处于主题数量增长期（0704 多亮色主题体系刚扩到 4 亮 1 暗），C2 的"新增主题 = 一行字典"收益会持续放大；
3. 验证基础设施（截图 + 像素断言 + 多模态复核）成熟，等价性验收可做到逐字节 + 逐像素双重级别，手术风险可控；
4. A/B 作为独立方案不及格（不消除体力活），但 B 的校验脚本在 C2 落地后转型为"模板令牌完整性校验"仍有价值（防漏占位符/错令牌名）。

**不选 D**：样式来源分裂为 qss+补丁两处，违背"样式单点排查"原则，且五副本重复未解。

### 实施要点（另立计划文档展开）

1. 令牌清单设计：对五副本做全量 diff，每个差异点命名令牌（族分组：窗口底/侧栏底/浮层底/描边/文字/选中色/状态色……）
2. `theme.py`：`THEME_PALETTES` 字典 + 渲染函数（`string.Template` 或 `str.replace` 链，启动耗时 < 1ms 级）；`apply_theme` 改走渲染路径
3. 等价性验证：渲染输出与现行五 qss **逐字节 diff == 空**（第一验收门）；`round2_verify.py` 扩展五主题全控件截图 + 像素断言（第二验收门）
4. 旧五文件退役：`config/themes/{cloud,wheat,sky,mint,dark}.qss` → `base.qss` + 调色板；`THEMES_DIR`/`is_valid`/`available_themes` 同步调整（主题存在性改查字典）
5. 校验脚本转型：检查模板占位符集合 == 调色板键集合（双向无遗漏）
6. 回滚预案：单提交完成迁移，`git revert` 恢复五副本
