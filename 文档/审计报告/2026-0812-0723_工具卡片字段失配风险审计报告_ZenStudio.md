## 1. 审计动因与方法

TodoList 事件（kimi 用 `title`、提取只认 `content`，全体静默跳过、无声降级 4 天）暴露的失效范式有三要素：**字段名失配 → 静默降级 → mock 假绿掩盖**。本审计以此为模板，对全部工具卡片做同类隐患排查：

1. 盘点每张卡的分派路径与其依赖的**后端私有字段**（rawInput/rawOutput 键名——ACP 标准字段之外的失配面）；
2. 核对每个字段依赖的**实证状态**（真机帧存档 / 计划文档记载实证 / 仅 mock / 无实证）；
3. 核对 **mock 场景覆盖矩阵**，找出与 TodoList"假绿"同构的盲区。

**结论先行**：未发现第二例"TodoList 式"已确定失效；现存风险集中在**验证与证据制度**（mock 覆盖盲区、帧证据欠账与丢失、第三后端零实证），而非现存代码 bug。逐项见 §4/§5。

## 2. 卡片总览与共享提取层

五个 provider（kimi / kilocode / opencode / reasonix / dream）**全部**经 `llm/providers/acp.py` 的 `map_session_update` 公共映射出 Chunk（各 provider 私有 `_map_update` 已删，1602 计划 D4 上收）——即字段提取**单点**，本审计一处覆盖全部后端；反过来说，任何字段判据失配也**一处波及全部后端**。

卡片分派两级（`gui/panels/chat/cards.py:1278` `make_tool_card`）：工具名分派表 `_TOOL_NAME_CARDS` 优先，未命中按 `tool_kind` 分派，兜底 McpCard。

| 卡片 | 分派路径 | 后端私有字段依赖（失配面） | 失配时降级方向 |
|:---|:---|:---|:---|
| BashCard | kind=execute | `rawInput.command` | `$ ` 命令头静默缺失，输出仍显示 |
| DiffCard | kind=edit | `content[].oldText/newText`（ACP 标准项）；write 合成读 `rawInput.content`、排除键 `old_string/new_string/oldString/newString` | 无 diff 退化为纯标题行（设计内） |
| TextOutputCard | kind=read/search/fetch | 副标题：`locations[0].path` / `rawInput.path/filePath/pattern/query/url` | 副标题静默缺失，正文不受影响 |
| SubagentCard | kind=think 或名 agent/task | 成果摘要 `<task_result>` 包裹标记；无标记取全文兜底 | 全文兜底，方向安全 |

| McpCard | 兜底 | `_INPUT_DETAIL_KEYS` 白名单（按 kind）；未命中 JSON pretty 全文兜底 | **兜底保证不丢信息**（设计亮点） |
| ThinkingCard | reasoning chunk | `content.text`（ACP 标准） | 无正文懒建，风险极低 |
| TodoCard | plan 通道 | `entries[].content/title`（与 TodoListCard 同一提取函数，0812 修复同批受益） | 同 TodoList 归一后口径 |

另有两处载荷级机制参与失配面：`_format_input_detail` 入参区（白名单 + JSON 兜底，**任何键名失配都不丢信息**）与 `_allow_progress_frame` 迟到帧放行白名单（`panel.py:943`，见 F5）。

## 4. 发现项（按风险分级）

### F1（高，结构性）：kind 分派四卡 mock 零覆盖——与 TodoList 假绿同构的盲区

TodoList 假绿的本质是"提取判据改动无对应形态 mock 兜底"。BashCard / DiffCard / TextOutputCard / SubagentCard(think 路径） 目前处于**完全相同**的暴露状态：它们的提取判据（`rawInput.command`、diff 项、`rawInput.content` 合成、`<task_result>` 提取、locations/path 摘要）今后任何改动或后端形态差异，mock 都无法发现，只能靠真机碰运气。这不是现存 bug，是**防回归网破洞**。

### F2（高，欠账）：0812 修复的真机验收 T3 未闭环

`2026-0812-0336` 计划的 T3（kimi TodoList 真机 A1/A2 + 帧存档 B6）尚未执行（git 记录 `95c7a00` 明示"真机验收A1/A2留待T3"；`.temp/frame_archive/` 无 TodoList 帧）。即本次修复目前**只有 mock 证据**——与当初 0808 计划"已落地"假象的中间态同构，差别只在本次有文档明示欠账。

### F3（中，证据制度）：真机帧证据脆弱且已有丢失

- `.temp/` 整体在 `.gitignore` 内——帧存档不入库、不可复核、随手可清；
- `acp.py:449` docstring 引用的取证文件 `.temp/write_frames_kimi.json`（kimi write 无 diff 项的实证基准）**已不存在**；
- 现存存档仅 AskUserQuestion 7 帧（0807），是全部卡片中**唯一**有库内可复核真机证据的字段形态；
- 其余字段（kimi 的 `command`/`content`/edit diff 项/`.tmp` 相对路径等）实证仅存于各计划文档的文字记载，原始帧不可得。

### F4（中，覆盖面）：第三形态未知——reasonix 零实证，新后端必踩同坑

- 实证仅覆盖 kimi 与 kilocode/opencode 两系（0812 计划风险表已自认此点）；
- reasonix 已接入且共享同一提取层，但其各工具 rawInput 字段形态**零帧存档、零 mock**；
- opencode 系 ACP 适配层 `rawInput` 为工具原生 input 透传（参考代码 `kilocode-main/packages/opencode/src/acp/tool.ts:275` 实证）——rawInput 键名 = 各工具自家 schema，无跨后端归一承诺；
- `_TOOL_NAME_CARDS` 名分派表外的 todo/问答/读图工具名（如第三后端另有其名）会静默退化 McpCard——信息仍在（JSON 兜底），但结构化渲染无声丢失，与 TodoList 事件同形态。

### F5（低，维护陷阱）：迟到帧放行白名单需手工同步

`_allow_progress_frame`（`panel.py:943`）按 `diff_hunks / summary / input_detail / images / todos` 白名单放行 in_progress 帧。历史上 todos、images、input_detail 都是"回填不到卡"之后逐一补进白名单的——**今后新增任何迟到回填载荷字段，忘记同步此白名单即静默丢帧**，与字段失配同效。

### F6（低，边界）：`_input_detail_seen` 账本跨会话不隔离

模块级 `set` 以 toolCallId 为键，不按 sessionId 键控（对照：todo 快照 `_last_todo_snapshots` 是 sessionId 键控的）。终态帧惰性清理；会话异常结束（无 completed/failed 帧）时条目泄漏，若后续会话复用同 toolCallId，入参回填与 media_path 回填会被静默跳过。触发条件苛刻（后端 tid 跨会话复用 + 前会话异常无终态帧），列观察项。

### F7（低，防御面）：`_extract_write_diff` 排除键仅四形态

edit/write 区分靠排除 `old_string/new_string/oldString/newString` 四键（`acp.py:473`）。若某后端 edit 用其他键名且 rawInput 恰有 `content` 键，write 合成路径会误判（方向是**多显示**合成 diff，非静默丢失，降级方向安全）。无实证样本，列观察项。

## 5. 逐项排查结论（无失配确认项）

以下逐字段核对过提取判据与现有实证，**未发现失配**：

- **QuestionCard 全系字段**（`questions[].question/options[].label/description/header/multi_select`、completed `answers`/`note`）：与 7 份真机帧存档逐键一致，实证最足；
- **TodoListCard `title/content` 两系归一**（0812 修复后）：判据放宽方向安全（更宽不更窄），两键均缺维持静默跳过、plan 通道零行为变化，mock 16/18/20（title 形）与 04/17（content 形）双系覆盖；
- **MediaReadCard `path/filePath`**：kimi 真机实证形态（含 `.tmp` 相对路径下发与首帧空壳迟到时序），mock 01/12-15 覆盖；
- **出参通道**（`rawOutput` dict/str 三态分流、content 块 text/image/image_url/resource 识别矩阵、`<image path>` 标签、JSON try-parse pretty 化）：0806 计划重构时有真机取证，kimi 中止降级形态（rawOutput 纯字符串）有实证记载；
- **入参区**：白名单未命中即 JSON pretty 全文兜底——**设计上免疫字段失配**（顶多格式不美观，信息不丢），这是与 todos 提取（无兜底、静默跳过）的本质区别，也是本次审计确认的最重要正面结论；
- **usage_update / thinking / plan**：ACP 标准字段或同一已归一提取函数，无新增失配面。

## 6. 结论与建议（供审阅决策，未动任何代码）

**结论**：TodoList 是孤例，不是冰山一角——逐卡排查未发现第二例已确定失效。但"假绿"的结构性土壤仍在：mock 网有破洞（F1）、修复证据链未闭环（F2）、真机证据不入库且已丢失（F3）、第三后端零实证（F4）。下次同型事故更可能从这四个口子进来，而不是从现存代码 bug 进来。

**建议**（按优先级，均为独立小任务，可分别立项）：

1. **闭环 F2**：执行 0812 计划 T3（kimi 真机 TodoList A1/A2 + 帧存档）——欠账最小、收益最直接；
2. **补 F1**：`shot_tool_cards.py` 为 kind=execute/edit/read/search/fetch/think 各补至少一场景（kimi 迟到帧时序 + kilocode 首帧齐备时序各一为佳），把四卡纳入防回归网；
3. **治 F3**：帧存档移出 `.temp/`（或在 `.gitignore` 对 `.temp/frame_archive/` 设豁免），让真机证据入库可复核；已引用的 `write_frames_kimi.json` 能找回则找回，找不回改 docstring 标注证据已失；
4. **备 F4**：有条件时为 reasonix 留一轮全工具帧存档（同 askuser 取证范式），消除第三形态盲区；
5. F5/F6/F7 为观察项，不建议现在改代码——记入本报告备案，未来触及相关代码时对照自查。
