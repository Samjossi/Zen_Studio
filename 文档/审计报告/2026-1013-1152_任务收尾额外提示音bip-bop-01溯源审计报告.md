# 任务收尾额外提示音（bip-bop-01）溯源审计报告

> **日期**：2026-10-13（UTC+8）
> **结论**：额外声音**不是运行时 bug，也不是配置问题**，而是测试套件里一条「真实播放」用例在每次跑门禁 `bash scripts/check.sh` 时真实出声。门禁按纪律在任务收尾（提交前）执行，所以用户总在任务快结束时听到它。

---

## 1. 现象

- 任务快结束时总会额外响一声 `bip-bop-01.wav`；
- 但设置中心「通知」页三项配置为：任务成功 `yup-03.wav`、任务失败 `error.wav`、交互提问 `bip-bop-09.wav`，均不含 `bip-bop-01.wav`。

## 2. 根因

**`tests/test_notification.py:235-240` 的 `test_sound_real_file_no_crash` 用例真实播放了 `done.wav`**：

```python
def test_sound_real_file_no_crash(qapp, isolated_settings, monkeypatch):
    """真实 wav 路径：offscreen/无声卡环境下 QSoundEffect→兜底链全程不抛异常。"""
    monkeypatch.setattr(sound_player_mod, "_last_play_at", 0.0)
    sound_player_mod.play_completion_sound(True)   # ← _play 未打桩，真实播放
    QTest.qWait(600)  # 覆盖 _STATUS_CHECK_MS 复查分支
    qapp.processEvents()
```

机制链：

1. `isolated_settings` 把配置重定向到 `.temp/` 隔离文件并清空残留 → 读取落到默认值 `notify_sound_done = "done.wav"`（`src/gui/settings.py:184`）；
2. `play_completion_sound(True)` 只 monkeypatch 了防抖时间戳，**`_play` 未打桩** → 真实加载并播放 `assets/sounds/正在使用/done.wav`；
3. 门禁 `scripts/check.sh` 以 `QT_QPA_PLATFORM=offscreen` 跑 pytest——**offscreen 只关 GUI 显示，不关音频后端**，Qt Multimedia 照常向真实声卡输出；`QTest.qWait(600)` 泵事件循环，播放完整发生；
4. `done.wav` 与 `bip-bop-01.wav` **内容完全相同**（md5 均为 `747ca9d9786ded6f744a8ade6b640880`， kilocode 语义映射 `done → bip-bop-01` 的改名拷贝）——所以听到的就是 bip-bop-01 这个音色；
5. AGENTS.md 规定提交前必跑 `bash scripts/check.sh`，AI 在每轮开发任务收尾都会执行 → 用户「每次任务快结束时」必响一声。

用例 docstring 假设「offscreen/无声卡环境」所以静默——该假设在无声卡 CI 上成立，但在日常开发机（有音频输出）上不成立，属测试编写时遗留的隐性硬编码播放。

已实证：本报告调查期间单独运行该用例一次（`pytest tests/test_notification.py::test_sound_real_file_no_crash`），通过且真实出声一次。

## 3. 排查过程（排除项）

| 嫌疑 | 结论 |
|:---|:---|
| `src/` 运行时代码硬编码 `bip-bop-01.wav` | 排除。全库 grep 无命中；git 历史 `-S 'bip-bop-01'` 在 `src/` 也无命中。声音选择完全由设置驱动（`src/gui/sound_player.py:44-57`，`src/gui/main_window.py:835-849`） |
| 打包态配置错误 | 排除。`~/.config/zen-studio/settings.json` 三项为 `yup-03/error/bip-bop-09`，与设置中心截图一致；`load_settings()` 每次现读现用，无缓存 |
| 开发态配置（项目内 `config/settings.json`） | 有嫌疑但非本次主因。其 `notify_sound_done = "done.wav"`（= bip-bop-01 音色）——开发实例（`python src/main.py`）完成任务时会响 bip-bop-01，与 AppImage 设置互不影响（双配置：`src/core/paths.py:55-63`）。当前无开发实例常驻运行 |
| 设置默认值回退 | 仅在配置缺失/损坏/「恢复默认设置」时回退 `done.wav`（`src/gui/settings.py:184,241-244`），当前配置有效，不触发 |
| AppImage 资产缺失 | 排除。运行中实例挂载点内 `正在使用/yup-03.wav` 存在，资产收编完整 |
| 其他测试真实出声 | 排除。`test_media_viewer.py` 全部用 `_FakePlayer` 或 monkeypatch `shutil.which`/`play_system`；全 tests/ 仅此一条未打桩的真实播放 |

## 4. 修复建议（待审阅，暂未改动代码）

**建议方案 A（推荐）**：给 `test_sound_real_file_no_crash` 的 `_play`/`play_system` 打桩，只断言「真实 wav 路径全程不抛异常」，不真出声——保留原测试意图（异常路径覆盖），消除噪音。该用例本意是「不抛异常」，并非「真的放出声」，打桩不损失覆盖。

**建议方案 B（可选加固）**：在 `src/gui/sound_player.py` 增加环境变量静音开关（如 `ZEN_STUDIO_MUTE=1` 时 `_play` 直接返回），门禁 `scripts/check.sh` 导出该变量——防未来再新增「真实播放」用例复发。

另可顺手治理（与本问题同源但独立）：`config/settings.json` 开发态 `notify_sound_done` 仍为 `done.wav`，若希望开发实例与打包实例听感一致，可改为 `yup-03.wav`。

## 5. 影响面

- 仅听觉噪音，无功能损害；防抖（1 秒）保证每次门禁最多响一声；
- 修复不涉及运行时代码（方案 A 只动测试），门禁其余环节不受影响。
