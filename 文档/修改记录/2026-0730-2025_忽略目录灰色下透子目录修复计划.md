# 忽略目录灰色下透子目录修复计划

## 1. 问题现象

被 `.gitignore` 命中的目录（如 `.tmp/`、`.venv/`）**自身名称不灰**，
其内**文件灰色，但子目录名称不着色**——三层全错位。

用户语义（对齐 VS Code）：被 gitignore **整体命中**的目录，自身与
**全部子孙**（文件与子目录，任意深度）都应暗显；仅个别文件被忽略
（如 `*.pyc` 散文件）时父目录**不**暗显。

## 2. 诊断结论（实施实证后的正确版本）

### 2.1 根因一：1940 切上冒后，目录着色查询无下透兜底

文件树着色入口（`gui/panels/file_explorer/model.py`
`_git_status_color_of`）：目录查 `status_of_dir()`，文件查
`status_of()`。1940 计划切断 ignored 向上冒泡（子孙状态 → 祖先
聚合）后，`status_of_dir()` 只查 `_dir_status` 聚合缓存，无任何
下透兜底——ignored 目录子孙三条着色路径全部落空：

1. git 对 ignored 内容不给子孙目录状态条目，`status_of_dir` 直查
   落空；
2. 祖先 ignored 不再向上冒泡，`_dir_status` 无其子孙键；
3. `status_of_dir` 无前缀匹配兜底。

文件因 `status_of()` 直查/前缀匹配仍为灰——构成"文件灰、子目录
不灰"的不对称。

### 2.2 根因二（初版计划漏判，首次实施验收时实证）：
`--untracked-files=all` 使 ignored 目录逐条展开

> ⚠️ 本节是后来者最容易走错的点：初版计划假设"git status 对
> ignored 目录折叠输出 `!! dir/`"，据此把 `_collapsed_keys` 设计为
> "从 `_status` 筛 `dir/` 结尾键"。**该假设不成立。**

实证（Zen_Studio 仓库，2026-07-30 20:36）：

```
git status --porcelain=v1 -z --ignored --untracked-files=all
  !! 条目总数: 38898（逐条 ignored 文件）
  其中折叠键（`dir/` 结尾）: 仅 2 个——
    .temp/git_bubble_probe/repo/、参考代码/theia-zen/（均为嵌套 git 仓库）
```

`--untracked-files=all` 会连带把 ignored 目录**逐条展开**，`.venv/`、
`.temp/`、`__pycache__/` 等均**不以折叠键存在**——它们的 ignored 文件
被逐条列出（这就是文件仍灰、目录无据可查的原因）。折叠键仅剩嵌套
git 仓库（git 不进入子仓库）。

**正确数据源**：`git ls-files --others --ignored --exclude-standard
--directory -z`（status.py `fetch_ignored_dirs()`）按 gitignore 命中
单元折叠输出：

- 整目录被忽略 → 仅输出 `dir/` 自身（不进入），实证 24 条覆盖
  `.venv/`、`.temp/`、`.tmp/`、`参考代码/`、各层 `__pycache__/` 等；
- 目录内仅个别文件被忽略（`*.pyc` 散文件）→ 逐条列文件路径——
  按尾斜杠过滤掉，父目录不暗显（对齐 VS Code 语义）。

### 2.3 概念界定：下透 ≠ 冒泡

- **冒泡**（向上聚合）：子孙状态 → 祖先目录着色。ignored 不冒泡
  （1940 已修复，保持）；
- **下透**（向下传递）：被整体忽略目录的状态 → 自身与子孙条目
  **显示**继承。ignored 目录内容整体暗显（VS Code 语义），正是本
  计划所补。

两者方向相反、互不冲突：1940 切上冒，本计划补下透。

### 2.4 修复后实证（Zen_Studio 仓库，2026-07-30 20:45）

```
折叠键数: 23（ls-files 22 + status 嵌套仓库键去重合并）
status_of_dir('.venv')            = ignored  ← 自身（rel == key[:-1] 命中）
status_of_dir('.venv/lib')        = ignored  ← 子孙前缀命中
status_of_dir('core/__pycache__') = ignored
status_of_dir('.temp')            = ignored
status_of_dir('参考代码')          = ignored
status_of_dir('.git')             = None     ← git 永不报告 .git，不着色
status_of('.venv/pyvenv.cfg')     = ignored  ← 文件直查表
```

## 4. 关键实现要点

### 4.1 `_collapsed_keys` 构建（service.py `refresh()`）

```python
# 折叠目录键 = 整体被忽略的目录（ls-files --directory 折叠）
# ∪ _status 中的折叠条目（嵌套 git 仓库，`!! dir/`）；
# ls-files 失败 → 仅保留 status 折叠键（下透降级，其余正常）
ignored_dirs = status.fetch_ignored_dirs(self._repo_root) or ()
self._collapsed_keys = tuple(
    dict.fromkeys(
        (*ignored_dirs, *(k for k in self._status if k.endswith("/")))
    )
)
```

降级分支（无 git / 非仓库）同步置空 `_collapsed_keys = ()`。

### 4.2 `status_of_dir()` 下透兜底（service.py）

```python
direct = self._dir_status.get(rel)
if direct is not None:
    return direct
# 下透：自身为 ignored 目录（`rel + '/'` 即键）或位于其下
# （前缀匹配）→ 继承暗显；嵌套仓库折叠键亦然
for key in self._collapsed_keys:
    if rel.startswith(key) or rel == key[:-1]:
        return self._status.get(key, status.IGNORED)
return None
```

两个要点，均为首次实施漏掉、验收实证后补上：

1. **自身命中** `rel == key[:-1]`：ls-files 键带尾斜杠，
   `"​.venv".startswith(".venv/")` 恒 False，必须补等值判定，否则
   ignored 目录**自身**不灰（只灰子孙）；
2. **`self._status.get(key, status.IGNORED)`**：ls-files 来源键不在
   `_status` 中，回退 `IGNORED`；status 折叠键仍直取原值。

## 7. 风险与回归点

- **前缀误伤**：键以 `/` 结尾，`"build2".startswith("build/")` 恒
  False，兄弟前缀天然免疫（单测 6c/6d 双覆盖）；
- **仓库根**：`_rel(仓库根)` 为 `"."`，不以任何 `dir/` 键开头，
  根不着色语义不变；
- **空键集**：非 ignored 仓库 `_collapsed_keys` 为空，兜底循环零
  开销返回 None；
- **ls-files 失败**：降级为仅 status 折叠键（嵌套仓库仍下透），
  其余链路不受影响；
- **变更面板**：`collect_changes()` 不经查色链路，不受影响；
- **主题色**：不改 `gui/theme.py` 任何色值。
