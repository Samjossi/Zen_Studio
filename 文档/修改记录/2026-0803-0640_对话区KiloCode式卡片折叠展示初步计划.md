## 1. 背景与问题

### 1.1 用户诉求重定位（2026-08-03）

用户明确表示喜爱 kilocode VS Code 插件对话区的**排版、折叠、代码展示、
TODO LIST 展示**，并判断 0619 计划「应该有更好的计划」。

对照 kilocode 调研实证（见 §1.3），0619 的局限一目了然：它把 diff、
成果摘要、尾窗等更多信息塞进 QTextBrowser 的行文本——信息密度确实
提升，但形态仍是「**更密的行**」。kilocode 体验的内核不是信息量，
而是**结构**：统一工具卡外壳 + 可折叠 body + 默认开合约定，让长活动流
「默认清爽、点开有细节」。行文本路线无论加多少内容都到不了这个形态。

### 1.2 1836 的 L3 判定与本文的立项性质

1836 计划 §3 警告框原文：

> L3 是被架构决策（D2 坚守 QTextBrowser）排除的另一条路线……若要 L3，
> 必须单独做载体迁移的立项评估，**严禁顺着增量惯性滑入载体重构**。

**本文即该立项评估**。1836 当时判 L3「收益不抵重构风险」，是在
「观感层级微调」的语境下；本次用户以 kilocode 整体体验为明确目标，
收益端已经改变，载体迁移值得正式摆上桌面评估（§3）。

## 2. 目标形态（对标规格）

对话区由「行文本流」变为「**块序列**」，每块一个 QWidget：

```
┌─ 用户气泡块（直角灰底卡，L2-1 形态平移）
┌─ 思维链卡：▾ Thinking — <自动提取标题>（流式展开，完成自动折叠）
├─ 工具卡：▸ ☐ ✔ Read — gui/panels/chat/output.py        ← 折叠态一行
├─ 工具卡：▾ $ Bash — npm test                            ← 展开态
│   ┌──────────────────────────────────────┐
│   │ $ npm test                           │  等宽底卡，运行中尾滚 5 行，
│   │ ...（尾部输出，限高内滚）             │  完成后定格末 20 行
│   └──────────────────────────────────────┘
├─ 工具卡：▸ ✎ Edit — output.py  +12 −3                   ← diff 默认折叠，
│   （点开：@@ 灰 / + 绿 / − 红 hunk 卡，超 200 行截断）      徽标常驻标题行
├─ TODO 卡：▾ ☑ 任务清单 — 3/5 项完成（强制展开）
│   ☑ 已完成项（灰+删除线）  ☐ 进行中 ▶  ☐ 待办
├─ 子代理卡：▾ ⧉ Agent — Explore codebase（运行中展开，完成折叠）
│   └ 成果摘要（<task_result> 提取，截 10 行，弱化灰）
└─ 正文块：assistant 流式文本（形态同现状）
```

要点：折叠是**真显隐**（QWidget.setVisible），不是文本增删；工具行
状态流转（◐→✔/✖）是**属性更新**（label.setText），锚点簿记与
`_shift_anchors` 偏移维护整套机制随 QTextBrowser 旧轨一并淘汰。

## 3. 载体选型评估（D1）

| 候选 | 折叠/卡片 | 代价与风险 | 判定 |
|------|-----------|-----------|------|
| A. 坚守 QTextBrowser + 锚点伪折叠 | 点击锚点删插文本模拟 | 体验粗糙（滚动/选区跳动）；锚点脆弱性被折叠交互放大；到不了目标形态 | ❌ |
| B. **QScrollArea + 块级 QWidget** | 真折叠、真按钮、真 hover | 跨块文本选择丢失（硬伤，§7 对策）；长会话 widget 数量性能；流式布局开销 | ✅ **建议** |
| C. QListView/QTreeView + Delegate | model 行级折叠原生 | 块形态高度异构（气泡/卡片/图片/流式文本），delegate 自绘或 setIndexWidget 均别扭；流式增量更新绕路 | ❌ |
| D. QWebEngineView | 全可达 | 项目四次否决的既定立场 | ❌ 不复议 |

**建议选定 B**。理由：① 块形态异构度高，widget 组合布局是唯一自然的
表达；② 折叠/按钮/hover 全部原生可达，一次迁移到位，无伪折叠的
体验欠账；③ 文本块内部仍用只读 QTextBrowser 小块，**已落地的
L1/L2 渲染资产（气泡卡 HTML、输出卡、链接化、思维链标题）可近乎
原样搬入块内**，不是推倒重来；④ 交互自由，后续复制按钮、
「在编辑器打开」等挂点自然。

## 4. 总体架构

```
panel.py（路由层，接口不变）
   │  append_tool_call / update_tool / upsert_todo / stream / reasoning …
   ▼
ChatTranscriptView (QScrollArea + QVBoxLayout + 底部 stretch)   ← 新增
   ├─ UserBubbleBlock      用户气泡（现状 HTML 平移）
   ├─ TextStreamBlock      正文流式（只读 QTextBrowser 小块，30ms 节流平移）
   ├─ ThinkingCard         思维链卡（CollapsibleCard 子类，自动折叠逻辑）
   ├─ ToolCard             工具卡外壳基类：图标+标题+副标题+chevron+body
   │    ├─ BashCard        body = 命令+输出等宽卡（运行中尾滚/完成定格）
   │    ├─ DiffCard        body = hunk 三色卡，标题行 +N −M 徽标
   │    ├─ ReadCard 等     body 缺省，标题行尾注「—— N 行」
   │    └─ SubagentCard    body = 成果摘要灰块
   ├─ TodoCard             checkbox 列表（setEntries 整刷，弃锚点）
   └─ SystemBlock          系统消息
```

- **CollapsibleCard 基类**：标题栏（QToolButton chevron + 图标 + 标题 +
  副标题）+ body 容器；`set_open(bool)`；开合状态存模块级
  `_open_state: dict[str, bool]`（键 `{tool}:{toolCallId}`，LRU 2000，
  直译 kilocode `tool-open-state.ts`）。
- **双轨并存**：旧 `ChatOutput` 冻结保留，设置项「对话区渲染：卡片
  （新）/ 经典（旧）」切换（D2）；新轨稳定一个版本后再议旧轨下线。
- **协议层载荷扩展**（期一，载体无关）：0619-T3 原样——`diff_stat`/
  `diff_hunks`/`result_summary`/in_progress 尾窗数据，新旧两轨
  共同受益（旧轨降级为尾注文本）。
