## 2. 各文件改动摘要

### `llm/registry.py`（新增）

- `BackendSpec`（frozen dataclass）：`name/label/vendor/vendor_label/available/list_models/factory` 七字段，
  发现-探测-枚举-工厂单点收敛；import 无副作用（探测均为惰性可调用）。
- 模块级 `REGISTRY`（插入序 = kimi-cli → kimi-acp → reasonix-acp）。
- 查询 API：`spec_of()`（未知名返回 None——后端名来自持久化 settings，可能指向已移除实现）、
  `vendor_of()`、`vendor_groups()`；派生 `BACKEND_LABELS` / `VENDOR_LABELS`。

### `llm/providers/acp.py`（新增）

- `_AcpConnection` → `AcpConnection(bin_path, cwd, agent_name)`：ndjson JSON-RPC 帧收发、id 配对、
  反向请求分发（审批回环）、死讯注入全部协议无关化；错误文案经 `agent_name` 参数化。
- `PermissionOption/ToolCallInfo/PermissionParams/PermissionHandler` 协议定型类型一并迁入。
- kimi 专有的 `-32000 authRequired` 文案映射**不搬**（D5：各 provider `_ensure_session` 自行翻译）。

### `llm/providers/kimi_acp.py`

- 仅 import 改引 `acp.py` + 类名替换，`KimiAcpLLM` 逻辑零差异（diff 逐行核对）。

### `llm/providers/reasonix_acp.py`（新增）

- `_find_bin()` 三级解析（PATH → `$REASONIX_HOME/bin` → `~/.reasonix/bin`）、`reasonix_available()`。
- `list_reasonix_models()`：`tomllib` 解析 `~/.reasonix/config.toml`（`$REASONIX_HOME` 可覆盖），
  `[[providers]]` 段产出 `provider/model` 全名（兼容字符串列表与表数组、段级/条目级 default 两形态，
  default 提首）；文件缺失/解析失败全 try 兜底空列表（R2）。
- `ReasonixAcpLLM`：与 `KimiAcpLLM` 逐行同构；差异三处（均写 docstring）：
  ① initialize 响应含非空 `authMethods` → 抛「reasonix 尚未配置，请先在终端运行 reasonix setup」
  （宽松判定：声明即拦截，不耦合 authMethods 内部结构）；
  ② 认证类错误宽松映射（auth/unauthorized/login/setup 关键词 → setup 引导文案）；
  ③ 模型目录来源为自身 config.toml（D6 红线 1）。

### `llm/__init__.py`

- `BACKEND_LABELS` 改由 REGISTRY 派生 re-export；新增导出 `REGISTRY/BackendSpec/spec_of/vendor_of/
  vendor_groups/VENDOR_LABELS/ReasonixAcpLLM/reasonix_available/list_reasonix_models`；
  旧符号全部保留（外部 import 不破）。

### `gui/panels/chat/panel.py`

- `_build_providers` 删除 → **懒实例化**（D4）：`_get_provider(name)` 首轮使用前经
  `spec.factory(workspace_root=...)` 创建，鸭子类型注入 `set_permission_handler` 与 `set_model`
  （替代 `isinstance(provider, (KimiCliLLM, KimiAcpLLM))` 硬编码）。
- 切换接口时旧实例 `close()` 后丢弃，防多标签×多后台长驻进程膨胀。
- `_close_providers` 改鸭子类型 `close()`。

### `gui/panels/chat/model_bar.py`（全量重写）

- 双按钮 → 三按钮：**后台（CLI 产品）→ 接口（接入实现）→ 模型（模型别名）**（D1 定稿）；
  原「模型」改名「接口」、原「版本」改名「模型」。

## 5. 实测修正清单（2026-07-30 二轮，R1 差异对齐）

用户完成 `reasonix setup` 后的全链路实测推翻/补强了四处实现假设，
均已在 `llm/providers/reasonix_acp.py` 修正并写 docstring：

| # | 原假设 | 实测真相 | 修正 |
|:--|:---|:---|:---|
| 1 | initialize 响应含非空 `authMethods` 即未 setup（宽松拦截） | `authMethods` 是**静态能力声明**（恒为 terminal 型 `reasonix-setup`），已/未 setup 完全相同，拦截误伤已配置态 | 移除 initialize 拦截（改留 agent 版本日志）；未配置信号归 `session/new` 错误映射 |
| 2 | 未 setup 错误含 auth 类关键词 | 实为 `-32603 model "..." is not configured`，无 auth 字样 | `_raise_setup_hint_if_auth` 补 `not configured` 关键词 |
| 3 | cwd 透传即可 | `session/new` 硬校验绝对路径（-32602） | 构造与 `set_workspace_root` 统一 `os.path.abspath`（幂等） |
| 4 | 模型表仅 `models` 列表/表数组两形态 | setup 向导单模型 provider 写单值 `model = "..."`，枚举漏项 | `list_reasonix_models()` 补单值形态（真实 config 对齐）；另补强：顶层 `default_model` 命中别名时**全局提首**（setup 选定的默认 = 菜单回退落点） |
| 5 | 轮次失败走 error 帧 | reasonix 轮次失败为**正常响应 `stopReason="error"` 且零 update**，不拦截则用户见空回复 | `_raise_on_turn_error` 补 stopReason=error 识别，报错文案引导查 provider 配置（kimi_acp 不动：kimi 正常为 end_turn，零回归） |

实测中另发现**用户配置错误**（非代码缺陷）：`deepseek-pro` 的 `base_url`
被误填为 API key 致该模型轮次 error，用户修正后 pro 复测通过。
该案例验证了修正 #5 的报错引导价值。
