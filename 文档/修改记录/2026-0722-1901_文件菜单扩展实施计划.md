## 1. 现状与差距

现有 `file_menu.py` 仅 4 项（打开文件 / 在新窗口打开文件夹 / 打开配置目录 /
退出），缺两块能力：

1. **同根多开无入口**：多开改造（work plans/2026-0722-0756）后进程模型
   已支持同工作区多窗口并存（状态文件按根哈希隔离、settings flock
   串行化），但菜单只有「在新窗口打开**文件夹**」（必须换根），
   想再开一个同根窗口只能手动起进程。
2. **无历史回访**：查看器打开过的文件无任何记录，回访只能靠文件树
   重新定位或再弹一次 QFileDialog——IDE 标配的 Recent Files 缺位。

### 1.1 关键既有事实（方案约束来源）

| 事实 | 位置 | 对本计划的约束 |
|:--|:--|:--|
| 起新进程逻辑已存在：`subprocess.Popen([sys.executable, main.py, folder])` | `main_window.py:336-341` | 「新建窗口」复用同一调用，仅目录来源改为当前根、不弹对话框 |
| 查看器打开入口共 4 处：文件树双击 / 变更面板 / 打开文件对话框 / 设置菜单「打开配置文件」 | `main_window.py:148,328,464` + `controllers.py:83` | 记录点必须收口在 `ViewerPanel.open_file` 成功路径，4 处调用零改动 |
| `_reload()` 也走 `open_file(self._current_path)` | `panel.py:256` | 外部修改自动重载会重复记录——去重后语义为「提升到最新」，无害 |
| `window_state_<hash8>.json` 键空间定型 5 键，值校验仅放行 `None / ASCII str` | `window_state.py:55-106` | `recent_files` 为 `list[str]`（含非 ASCII 路径），需扩键空间**并扩值级校验**（见 §2.3） |
| 菜单构建走 `build(menubar, ctx, actions)` 模块范式 + Action 注册表 | `menus/assembler.py` `menus/registry.py` | 新 action 照常登记；子菜单为动态内容，登记父 action 即可 |
| `update_window_state` 为读-合并-写原子操作 | `window_state.py:109-113` | 高频记录与关闭时布局回写互不覆盖，无需额外并发处理 |

## 2. 方案

### P1 新建窗口（同根多开入口）

- `main_window.py`：新增 `new_window()` 槽——取 `self.file_explorer.root_dir`
  走与 `open_folder_in_new_window` 相同的 `Popen` 调用；两槽共用的进程
  启动行提为私助手 `_spawn_window(folder: str)`，消除复制粘贴
- `file_menu.py`：插第二位「新建窗口（&N)」→ `ctx.new_window`，
  登记 `file.new_window`
- 状态栏反馈与现有一致：`已在新窗口打开：<根>`

### P2 最近打开的文件（动态子菜单）

**记录链（信号收口，面板不碰持久化）**：

- `ViewerPanel` 新增 `file_opened = Signal(str)`，在 `open_file` 成功路径
  末尾（`_current_path` 赋值后）发射；守卫/占位分支（不存在/读取失败/
  二进制）不发射——只记"真的看到了内容"的文件
- `MainWindow` 接线 `viewer_panel.file_opened → RecentFilesStore.add`
- 「打开配置文件」入查看器同样会被记录：**接受**（它是合法查看历史，
  且绝对路径回放无障碍），不为它开特例

**存取层（新增 `gui/recent_files.py`）**：

```python
MAX_RECENT_FILES = 10

class RecentFilesStore:
    """最近查看文件列表（按工作区隔离，存 window_state_<hash8>.json）。

    add(path)：去重 + 置顶 + 截断 10 条，即时原子写；
    list()：读回（缺失/损坏回退空表）；
    remove(path)：回放发现文件已消失时剔除；
    clear()：清空（子菜单「清除列表」项）。
    """
```

- 构造接 `state_file: Path`（由 `window_state_file_for(workspace_root)` 推导，
  与 `WindowStateStore` 同源，**多开天然按工作区隔离**）
- 复用 `load_window_state / update_window_state` 的读-合并-写原子链，
  不自造 IO

**键空间扩展（`window_state.py`）**：

- 新增 `KEY_RECENT_FILES = "recent_files"`，`WindowState` /
  `WindowStatePatch` / `DEFAULT_WINDOW_STATE`（默认 `[]`）同步扩
- 值级校验按键分流：5 个布局键维持 `None | ASCII str`；
  `recent_files` 校验为 `list` 且元素全 `str`（否则丢弃回 `[]`）——
  分流逻辑集中 `load_window_state` 一处，注释说明两类的损坏判据差异
  （布局值恒 ASCII base64；路径值允许多字节 UTF-8）

**子菜单（`file_menu.py`）**：

- `addMenu("最近打开的文件(&R)")`，登记 `file.recent_files`（父 action）
- `aboutToShow` 动态重建：读 store → 每条一个 action（显示名
  `文件名  —  所在目录`，toolTip 全路径）→ `triggered` 调
  `ctx.open_recent_file(path)`
- 列表为空：一个禁用占位项「（空）」，防菜单消失导致的位置跳动
- 末尾分隔 + 「清除列表（&L)」（空列表时禁用）
- `MainWindow.open_recent_file(path)`：`Path.is_file()` 探活——存在则
  `viewer_panel.open_file(path)`（成功会经信号自动置顶）；不存在则
  `store.remove(path)` + 状态栏提示「文件已不存在，已从列表移除」，
  与变更面板「文件已删除，待提交」提示风格一致

### P3 菜单重排 + 模块文档更新

- `file_menu.py` 按目标布局重排（含助记符 &O/&N/&W/&C/&R/&Q 核对无冲突）
- 文件头 docstring 更新为新清单；`main_window.py` 文件菜单槽小节同步
