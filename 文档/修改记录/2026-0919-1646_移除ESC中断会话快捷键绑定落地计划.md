# 移除 ESC 中断会话快捷键绑定落地计划

> **状态**：已实施（2026-09-19，修改清单 8 项全部完成，门禁全绿）
> **范围**：`src/gui/panels/chat/panel.py`
> **时间**：2026-09-19 16:46（设计）(UTC+8) / 2026-09-19（实施）
> **优先级**：中

---

## 1. 背景与动机

用户反馈：AI 执行任务期间，按 ESC 键会停止当前任务，等价于点击「■ 停止」按钮。用户按 ESC 的本意常是退出其他软件的弹窗/操作，误触发导致 AI 任务被中断，体验受损。拍板结论：**ESC 不再绑定任何停止任务的行为**，停止任务只保留「■ 停止」按钮一条路。

## 2. 排查结论（已确认）

### 2.1 唯一绑定点

`src/gui/panels/chat/panel.py` 的 `_connect_signals()` 内，每个会话标签的 ChatPanel 注册了一个 QShortcut：

```python
# src/gui/panels/chat/panel.py
esc = QShortcut(QKeySequence(Qt.Key.Key_Escape), self)
esc.setContext(Qt.ShortcutContext.WidgetWithChildrenShortcut)
esc.activated.connect(self._on_esc_stop)
```

- 机制：`QShortcut`，context 为 `WidgetWithChildrenShortcut`——焦点落在会话面板**任意子控件**（输入框、输出区、按钮、附件行）时 ESC 均触发。
- 处理链：`_on_esc_stop()` → busy 时 `request_stop()`（幂等，空闲静默忽略），与停止按钮 `_on_stop_button()` 殊途同归。

### 2.2 关于"其他软件按 ESC 也触发"的澄清

全仓搜索 `registerHotKey`、`grabKeyboard`、`QAbstractNativeEventFilter`、`nativeEvent`、pynput/keyboard 监听库均无命中；唯一的应用级 eventFilter（`src/gui/window_resize.py`）只处理鼠标事件，不碰键盘。**代码层面不存在全局热键**，Qt shortcut 在窗口无键盘焦点时收不到按键。用户感知的"跨应用触发"实为 Zen Studio 窗口仍持有焦点（focus-follows-mouse 或切回瞬间焦点停在聊天面板）。本计划移除绑定后该问题随之消失。

### 2.3 不受影响的其他 ESC 处理（明确不动）

| 位置 | 行为 |
|:---|:---|
| `src/gui/panels/find_bar.py` | 查找栏 Esc 关闭（eventFilter 装在查找栏输入框） |
| `src/gui/panels/file_explorer/explorer.py` | 文件树搜索栏 Esc 收起（eventFilter 装在搜索栏） |
| `src/gui/panels/terminal/widget.py` | Esc 映射为 `\x1b` 发给终端 |
