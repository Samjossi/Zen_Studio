# Git 树内嵌页拓扑与提交主题双列布局落地计划

> **状态**：草稿（待审阅）
> **范围**：右栏上内嵌提交图的图列/主题列布局、低噪声提交摘要、整行悬停与 tooltip、宽窄面板和超宽拓扑、测试与视觉验收
> **时间**：2026-11-06 06:14（设计，UTC+8）
> **优先级**：中

## 1. 背景与目标

Theia 泳道算法和 Qt 原生绘制落地后，真实走查确认拓扑效果不错，但 graph-only 单列在常见仓库中只占据左侧少量空间，其余区域长期空白，信息密度偏低。

本期采纳“**左侧固定拓扑 + 右侧提交主题**”的纠偏方向：

- 不把拓扑单独居中，避免泳道数量变化或刷新时整张图左右漂移。
- 不恢复完整四列表格，不在内嵌页常驻短 hash、作者、时间或 refs 徽标。
- 每个提交行由左侧节点/边和右侧提交主题组成；HEAD 行主题加粗，与 HEAD 双圆共同提供当前位置提示。
- 被省略的主题及完整提交元数据继续通过整行 tooltip 查看，完整弹窗维持现有详细阅读职责。

本计划只调整展示层，不改变已验证的 parents → lanes 算法、结构化取数、三类边几何、加载和降级路径。

## 2. 当前代码与根因

- `GitGraphView.set_graph_only()` 当前隐藏 `COL_COMMIT`、`COL_AUTHOR`、`COL_DATE` 和表头，只显示 `COL_GRAPH`。
- `GitGraphView._resize_columns()` 在 graph-only 下把图列宽设为 `max(实际拓扑宽, viewport 宽)`；这正是少量泳道时右侧空白无法承载内容、也不能简单再启用主题列的直接原因。
- `CommitColumnDelegate` 已具备完整模式的 hash + refs + 主题绘制，可以复用其主题色、省略和 HEAD 加粗机制，但必须增加只画主题的内嵌摘要分支。
- 当前 tooltip 和鼠标跟踪只服务于 graph-only；恢复主题列后，两列必须共享同一行的悬停与完整元数据，不能出现图列有反馈、文字列没有反馈的分裂状态。
- `GitGraphContent`、`GitGraphPanel` 和测试仍以 `graph_only` 命名；新布局已不是“只有图”，需要同步改成语义明确的摘要模式。

## 3. 需求

1. 内嵌页显示两列：左侧固定拓扑，右侧提交主题；隐藏表头、作者列和时间列。
2. 图列左对齐，宽度只由实际最大泳道数和统一 lane 宽决定；viewport 变宽时剩余空间分配给主题列，不把图列拉满。
3. 内嵌主题列不显示短 hash、refs 徽标、作者或时间；HEAD 提交主题加粗，普通主题使用现有正文色。
4. 长主题在可用宽度内右侧省略，不换行、不增加行高、不挤压图列；完整主题保留在 tooltip。
5. 鼠标位于节点、曲线、主题或该行空白区域时，均有统一的整行悬停背景和完整提交 tooltip。
6. 超宽拓扑保持 lane 宽和几何不变，继续横向滚动；不得为同时显示主题而压缩泳道或节点。
7. 保留按完整 commit id 恢复选中、横纵滚动恢复、字号与主题重绘、进入页面/手动刷新、隐藏不查询、500 条截断和失败降级。
8. 完整弹窗继续显示 hash + refs + 主题 + 作者 + 时间，内嵌摘要样式不得污染完整模式。
9. 下方 `ChangesPanel`、M/U/D 双击、文件树切换及 Git 状态服务保持不变。

## 4. 方案决策

### D1 以 summary mode 取代 graph-only 语义

- 将 `GitGraphView`、`GitGraphContent`、`GraphColumnDelegate` 及接线中的 `graph_only` / `set_graph_only()` 改为 `summary_mode` / `set_summary_mode()`。
- summary mode 明确定义为“拓扑 + 提交主题”双列，不复用早期“refs 与主题优先”的旧 compact 规则。
- `GitGraphPanel` 启用 summary mode；`GitGraphDialog` 保持完整模式。
- 保留现有 `CommitGraphModel`、`CommitRow` 和完整 id 选中逻辑，不新增第二套模型或取数路径。

### D2 图列固定内容宽，主题列承接剩余空间

- `COL_GRAPH` 继续 Fixed，宽度始终为 `GitGraphRenderer.content_width(max_graph_cells)`；summary mode 删除 `max(content_width, viewport.width())` 的旧特例。
- `COL_COMMIT` 继续 Stretch，在 summary mode 下显示并占用图列之外的剩余宽度。
- `resizeEvent()` 只让 Qt 重分配主题列并维持图列内容宽，不重新取数、不居中图列、不随窗口宽度拉大 lane 间距。
- 超宽时由现有横向滚动条处理；240px、360px、440px 均验证常见多分支仓库同时能看见拓扑和主题。

### D3 提交列增加低噪声摘要绘制

在现有 `CommitColumnDelegate` 增加 summary 分支：

- 仅绘制 `CommitRow.subject`，沿用现有左右内边距、正文色和 `QFontMetrics.elidedText()`。
- HEAD 行使用粗体主题；不绘制 `commit`、`refs` 或额外徽标。
- 完整模式继续执行现有 hash + refs + 主题逻辑，行为不变。
- 截断提示在 summary mode 只由提交列绘制，图列不重复显示同一提示；提示行无提交 tooltip。

### D4 两列共享整行状态与 tooltip

- 将悬停行作为 `GitGraphView` 的统一状态，同步给图形委托和提交委托；两列使用相同 accent 弱色背景，选中继续沿用整行选择。
- summary mode 的 tooltip 事件不再限定图列；`COL_GRAPH` 与 `COL_COMMIT` 均从 `CommitGraphModel` 获取同一份完整元数据。
- 鼠标移出、模型重置和刷新时清理两列悬停；无提交的截断提示行不显示伪提交信息。
- 保留只读单选、上下方向键和现有滚动行为，不新增点击提交、checkout 或详情操作。

## 8. 非目标

- 不把拓扑图单独居中，不随泳道数量或 viewport 宽度移动整张图。
- 不在内嵌页恢复短 hash、refs 徽标、作者、时间或完整四列。
- 不增加图/列表切换、冻结图列、提交详情、搜索、过滤或任何 Git 写操作。
- 不改变 Theia 算法、结构化取数、三类边几何、主题令牌、加载边界和 500 条上限。
- 不为摘要列新增取数、缓存、轮询或 watcher。
