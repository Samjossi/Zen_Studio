# 中文输入法（fcitx5）失效修复计划

> **日期**：2026-07-31
> **关联文档**：《PySide6_Linux_中文输入法失效诊断手册_V1.1.md》（下称"手册"）
> **状态**：已实施（2026-07-31 17:1x，插件编译部署完成，运行期验证通过）

---

## 1. 问题现象

GUI 对话区输入框（`gui/panels/chat/input.py` 的 `ChatInput`，QTextEdit）无法通过
fcitx5 打字输入中文：无预编辑、无候选窗；粘贴中文正常。

> 注：该问题为**应用级全局问题**——所有 QTextEdit/QLineEdit 均失效
> （`gui/popups.py`、`gui/settings_dialog.py`、`gui/panels/viewer/code_viewer.py`
> 中的输入控件同理），非 ChatInput 自身缺陷。

## 2. 诊断结果（2026-07-31 实测）

按手册 §2 逐项执行，快照如下：

| 检查项（手册条目） | 实测结果 |
|:---|:---|
| §2.1 venv PySide6/Qt 版本 | **PySide6 6.11.1 / Qt 6.11.1** |
| §2.2 wheel 插件目录 | 仅 `libcompose…so`、`libibus…so`、`libqtvirtualkeyboard…so`，**无 fcitx** |
| §2.3 系统 fcitx5/Qt | fcitx5-frontend-qt6 `5.1.4-1build5`；系统 Qt **`6.4.2`** |
| §2.4 输入法环境 | `QT_IM_MODULE=fcitx`，fcitx5 守护进程运行中，X11 会话 |
| §2.5 加载失败原因 | 未运行（版本对比已足以定性，见下） |

**根因判定（手册 §3，"不一致"分支，实测命中）**：

- venv wheel 自带 **Qt 6.11.1**，系统 fcitx5 插件基于 **Qt 6.4.2** 编译；
- Qt 私有 ABI（`Qt_6_PRIVATE_API`）不跨版本兼容 → wheel 无法加载系统 fcitx5 插件；
- wheel 又不自带 fcitx 插件 → Qt 侧没有任何可用输入法后端；
- 粘贴正常的原因：粘贴走剪贴板通道，不经过输入法。

**结论**：与手册记录的经验**完全一致**，属于 wheel 版 Qt 与系统输入法插件的版本错配，
非应用 bug，非 PySide6 bug。

## 3. 场景判定（手册 §4.0 两问）

- **Q1 输入法后端**：用户跑 **fcitx5** → 手册方案 ①（ibus 零改动）**不适用**
  （fcitx5 不提供 IBus D-Bus 接口仿真）。
- **Q2 场景**：本项目兼有开发调试与发行打包两形态
  （`building/` 内含 PyInstaller spec 与 `build_appimage.sh`），且
  `pyproject.toml` 依赖为 `pyside6>=6.11.1`、`uv.lock` 锁定 6.11.1。

## 4. 方案选择

| 方案（手册条目） | 可行性评估 | 取舍 |
|:---|:---|:---|
| ① ibus 零改动 | ❌ 不适用（fcitx5 用户） | 排除 |
| ② venv 降级 PySide6 至 6.4.2.* | ⚠️ 技术上可用，但违背 `pyside6>=6.11.1` 约束，且降级两大版本存在功能/兼容回归风险（近期大量 GUI 改造基于 6.11） | **不推荐**；仅作为临时应急调试手段保留 |
| ③ 编译匹配 Qt 6.11.1 的 fcitx5-qt 插件 | ✅ 根治，开发与发行（AppImage 随 site-packages 内置）一次解决 | **采用** |

**选定方案 ③：编译与 wheel 内 Qt 6.11.1 完全同版本的 fcitx5-qt6 插件。**

## 5. 实施步骤（手册 §4 方案③ 落地）

### T1 移植编译脚本

将另一项目已验证的 `打包脚本/build-fcitx5-qt6-plugin.sh` 移植为本项目
`building/build-fcitx5-qt6-plugin.sh`，要点（手册 §4 方案③ 步骤 1–5 与 §5 约束）：

1. 用 `aqtinstall` 安装 **Qt 6.11.1** 到 `.build-tools/Qt/`（aqt 官方二进制自带完整
   私有头，无需 qtbase 源码树）；
2. 克隆 `fcitx/fcitx5-qt`，checkout 与系统 fcitx5 匹配的 tag（**5.1.4**）；
3. Qt ≥ 6.10 必打 CMake 补丁：
   `find_package(Qt6Gui … Private)` → `find_package(Qt6GuiPrivate … CONFIG REQUIRED)`；
4. 最小化 CMake 配置：`ENABLE_QT4/QT5=OFF`、`BUILD_ONLY_PLUGIN=ON`、
   纯 X11 下 `ENABLE_QT6_WAYLAND_WORKAROUND=OFF`；
5. 脚本内置版本一致性校验：从 venv 读出实际 Qt 版本，与 aqt 安装版本不一致则
   拒绝编译（防手册 §2.1 记录的返工事故）。

### T2 编译产物安装

产物 `libfcitx5platforminputcontextplugin.so`（约 1 MB）复制到
`.venv/lib/python*/site-packages/PySide6/Qt/plugins/platforminputcontexts/`。

> `Fcitx5Qt6DBusAddons` 静态链接进插件，无额外私有库需处理；
> 其余依赖（libxkbcommon、libX11 等）与 Qt xcb 平台插件相同。

### T3 打包链路接入

确认 `building/zen-studio.spec` / `build_appimage.sh` 的 site-packages 收集逻辑
会自然带上新增插件文件；若有显式 exclude 清单需核对放行。

### T4 验证（手册 §2.5 + §6）

1. `QT_DEBUG_PLUGINS=1 QT_IM_MODULE=fcitx .venv/bin/python main.py 2>&1 | grep -iE 'fcitx|incompatible'`，
   按手册 §2.5 判读表确认 `loaded library "…libfcitx5…"`；
2. 手册 §6 验证清单逐项过：对话框拼音预编辑+候选窗上屏、英文数字无重复、
   粘贴、预编辑态 Backspace、ibus 兜底、应用回归（剪贴板/快捷键/托盘/主题 + pytest）；
3. AppImage 形态复测第 1 项。

### T5 维护约束固化

- 插件绑定 Qt 版本：**每次升级 PySide6 必须重编插件**（T1 脚本版本校验已兜底）；
- 在 `building/README.md` 增补一行说明，指向本计划与手册。

## 6. 红线（手册 §5 工程师必读约束，本项目同样适用）

- 🚫 不动全局系统包，不改 `/usr/lib`；
- 🚫 不向 `QT_PLUGIN_PATH` 追加系统插件目录；
- 🚫 不试 XIM（Qt6 已移除该插件）；
- ✅ `pyproject.toml` / `uv.lock` 保持 6.11.1 锁定不变。
