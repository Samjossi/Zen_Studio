## 1. 背景与问题

左栏（聊天面板）与中栏（文件查看面板）的文本控件，在用户按住 **Ctrl + 滚动鼠标滚轮** 时，会放大/缩小控件内字体。

该行为**并非本项目代码实现**，而是 Qt 富文本控件的**内建默认行为**：`QTextEdit` / `QTextBrowser` / `QPlainTextEdit` 的 `wheelEvent` 在检测到 Ctrl 修饰键时，会自动调用 `zoomIn()` / `zoomOut()` 改变文档字号。

副作用：

- 与本项目既有的**全局字号体系**冲突——字号唯一权威入口是设置中心「外观 ▸ 字号」（`MainWindow._apply_font_size` 应用链：持久化 → 全局字体 → 各面板 `refresh_font()` 同步），Ctrl+滚轮的缩放绕开该体系，形成「影子字号」；
- `zoomIn/zoomOut` 改变的是控件文档内部缩放，不持久化、不随主题/字号链重刷，重启或 `refresh_font()` 后行为不一致；
- 用户误触（如 Ctrl 复制时顺手滚轮）会导致字体莫名其妙变大变小。

## 3. 目标

- 左栏、中栏上全部文本控件：**Ctrl+滚轮不再改变字体大小**；
- 普通滚轮滚动（无 Ctrl）行为完全不变；
- 图片页、PDF 页、终端面板现有滚轮行为不受影响；
- 全局字号仍由设置中心唯一入口控制。

## 4. 方案设计

### 4.1 方案选型

| 方案 | 做法 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **A（推荐）** | 各控件重写 `wheelEvent`：检测到 Ctrl 修饰键时吞掉事件（不调用基类实现） | 改动最小、意图最明确、无全局副作用 | 四处重复几行代码 |
| B | 写一个公共 Mixin/工具函数（如 `gui/popups.py` 或新 `gui/widgets.py`），四处继承/调用 | 消除重复 | 引入新公共层，四处类声明都要改，收益不成比例 |
| C | 在控件上安装事件过滤器拦截 `Wheel` 事件 | 不动类实现 | 过滤器注册点分散、可读性差 |

选 **A**：四处各加一个 `wheelEvent` 重写，3 行核心代码，符合项目「改动最小、意图明确」的惯例。

### 4.2 Ctrl+滚轮时的行为细节

| 选项 | 行为 | 取舍 |
|:---|:---|:---|
| **A1（推荐）** | Ctrl+滚轮：事件被接受但什么都不做（不缩放也不滚动） | 语义最干净：Ctrl+滚轮在本应用无任何含义 |
| A2 | Ctrl+滚轮：剥离 Ctrl 按普通滚动处理 | VS Code 默认行为；但用户可能误触 Ctrl 时意外滚动 |

选 **A1**：直接吞掉，避免误触引发意外滚动。

### 4.3 实现要点

四个类中各加：

```python
def wheelEvent(self, event) -> None:
    """禁用 Qt 内建 Ctrl+滚轮缩放字体：Ctrl 按下时吞掉事件，其余走基类滚动。"""
    if event.modifiers() & Qt.KeyboardModifier.ControlModifier:
        event.accept()
        return
    super().wheelEvent(event)
```

注意点：

- `Qt` 需从 `PySide6.QtCore` 导入（四文件均已有 `Qt` 导入或随现有 import 增补，实施时核对）；
- `event.accept()` 显式接受，防止事件继续向父控件传播（滚轮事件未接受时会冒泡到父级可滚动区域）；
- 不动各控件的 `refresh_font()` 与全局字号应用链——它们本就不感知 `zoomIn` 的影子缩放，禁用后自然回归一致。
