# CLI 接口模式精简（一步到位）计划

## 1. 背景与问题

### 1.1 背景

项目接口模式有 ACP 与 CLI 两条传输层（同一 kimi 二进制下的 `kimi acp` 长驻 JSON-RPC 与 `kimi -p` 一次性子进程）。经只读调研（2026-07-31，调用链与行号见 §7）确认：

- **功能维度 ACP 已完全覆盖 CLI 且多项超越**：token 级流式（CLI 仅消息粒度）、思维链可见（CLI 无）、协议级取消不毁会话（CLI 杀进程）、同会话热切模型（CLI 下轮生效）、四态权限审批（CLI 固定 auto 一刀切）。CLI 无任何 ACP 不具备的用户可见能力。
- **GUI 层已注册表化**：`panel.py` / `tabs.py` / `model_bar.py` / `settings_dialog.py` 零 kimi-cli 硬编码，摘掉注册项即从三级菜单自动消失。
- **决策已拍板**：精简掉 CLI 模式，仅保留 ACP；采用**一步到位**（不做软移除过渡期），接受"kimi 后台丧失传输层降级冗余"的代价。
