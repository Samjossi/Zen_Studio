## 3. 与计划的偏差

- 计划允许为 provider 增加小型生命周期接口；实际采用 `mark_stalled()` 与只读 `recovery_pending`，未修改通用 `LanguageModel` Protocol，其他后端经鸭子类型保持原行为。
- 模型即时切换失败不再清空原会话 ID，而是保留下轮恢复并严格应用当前选择；这是 D1/D7 在既有 `set_model()` 分支上的必要隐藏改动。
- 恢复失败的草稿保留兼容既有单输入框语义：已有排队草稿时不覆盖；输入框为空时才回填本次发送文本。
- 冻结态验证使用临时 runtime hook，属于测试构建注入；验证后已移除并重新构建最终 AppImage，未把诊断探针带入交付产物。

## 4. 经验沉淀

- 连接身份与会话身份必须分离：进程死亡只意味着传输失效，不等于用户放弃上下文。
- 恢复与重试必须分离：恢复原会话后只发送用户的新指令，才能避免不确定工具副作用被重复执行。
- 失效函数不能持写锁重入；各写分支先释放锁，再进入同一幂等收口，同时唤醒所有等待面。
- `session/resume` 的能力字段、参数和响应形状须由真实 CLI 探针确认；不能由 `session/load` 或文档类名推定。
- 冻结态注入只用于验证构建，最终必须移除临时 hook 并重新构建，避免把测试入口留在发布产物中。
