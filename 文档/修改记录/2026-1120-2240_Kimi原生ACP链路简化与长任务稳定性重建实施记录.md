## 6. 偏差与边界

1. `set_model()` 失败不再设置 `_needs_recovery`：计划只把恢复边界收敛到真实连接失效；普通配置拒绝不应触发进程重建。若配置失败同时导致连接死亡，`recovery_pending` 仍由 `is_alive` 判定。
2. 额外删除了 `panel.py` 中已无实现者的通用 `mark_stalled` 分支，避免留下 Kimi 专属死代码；其他后端本来就没有该方法，行为不变。
3. 额外清理了 `术语表.md` 的“临时提示面板”术语，并把看门狗术语限定为非 Kimi 后端；计划 T6 只点名设置说明，这是同一旧口径的遗漏点。
4. `_collect_turn_end_usage()` 仍在 response 后 ≤3 秒内转发迟到的非 usage 帧（可能包含迟到正文），这是为了不丢已到达的展示数据；它不参与终态、恢复或待发判断，未恢复第二套生命周期。
5. 未修改本机 `~/.kimi-code` 的 CLI、配置或凭据；真实验收只读取凭据并写入 CLI 自己的会话数据。未修改 `config/settings.json` 中可能残留的旧键，代码已不再读取。
6. 上游 U1–U4 未通过，因此本次只能声明“IDE 简化与自有故障已修复；上游通知轮次仍阻断完整长任务目标”，不声明用户原始长任务已根治。

## 7. 经验沉淀

- 删除本地补偿后，上游提前 `end_turn` 会直接可见；这比继续堆 drain 更诚实，也更容易把责任分层。验收必须同时记录“工具已执行”和“正文是否到达”，不能把工具副作用当作成功。
- 空 `end_turn` 可能发生在 3 秒内且没有任何 update 帧；仅靠 provider 的 chunk 序列无法区分“模型没说话”和“上游提前收尾”，需要裸 ACP 帧序或 CLI 内部日志作为第二证据。
- AppImage GUI 验收可用 `Xvfb + xdotool + 隔离 XDG_CONFIG_HOME` 完成；ASCII 输入前必须禁用 fcitx（`QT_IM_MODULE=qt`、`XMODIFIERS=@im=none`），否则会被拼音输入法组合成中文。隔离配置目录路径要短，Unix domain socket 路径超过约 108 字节会让 `QLocalServer.listen` 失败并静默退出。
- 真实 Kimi CLI 在 workspace-write 沙箱下会因无法写 `~/.kimi-code` 报 `session/new -32603 storage write failed`；这是沙箱权限问题，不是 ACP 故障，验收时应与协议失败分开记录。
