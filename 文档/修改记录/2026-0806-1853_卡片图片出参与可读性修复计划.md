> **状态**：已实施（2026-08 归档时核实：_compose_output_html 共用组装、TextOutputCard 升级等已落地于 gui/panels/chat/cards.py）

> **优先级**：高
> **前置**：2026-0806-1712 计划（T1–T5 已实施，images 通道已铺到载荷）

## 1. 背景与症状

0806-1712 计划把出参图片通道（`ToolUpdatePayload.images`）从协议层铺到了载荷，但**消费方只有 McpCard 一家**（全项目 grep 实证：`payload.get("images")` 仅 `cards.py` McpCard 一处）。逐卡排查发现其余卡片存在同类渲染缺口，用户实证：AI read 图片时，用户看到的只是一长串地址，根本不知道 AI 在读哪张图。

| # | 症状 | 影响面 | 证据 |
|:---:|:---|:---|:---|
| N1 | **read 卡（TextOutputCard）不消费 `images`**：read 图片文件时，后端返回 content 数组（text 项 `<image path>` 被协议层剔除后 text 为空、images 有值），`_on_completed` 只判 `output` 非空——出参区**整片空白**，连行数徽标都没有（`output_total_lines=0`）。卡片 ✔ 完成但用户什么都看不到 | read/search/fetch 三 kind | `cards.py` TextOutputCard `_on_completed` 仅读 `output` |
| N2 | **read 图片的另一形态：路径纯文本裸露**：后端把图片路径当纯文本 output 返回时，出参区显示一长串路径原文，无缩略图、无文件名提炼——"用户看来它只是一长串的地址" | read kind | 用户实证反馈 |
| N3 | **read 卡副标题无可读性**：`_tool_call_summary` kind=="read" 返回完整路径全文，TextOutputCard 未覆写 `set_subtitle`，单行省略显示一长串地址；DiffCard 已有两段式（文件名常态 + 目录弱化）而 read 卡没有——图片场景用户最想知道的就是"哪张图" | read/edit 不对称 | `cards.py` DiffCard `set_subtitle` 两段式为私有实现，未上抽 |
| N4 | **SubagentCard / QuestionCard 不消费 `images`**（防御性缺口）：子代理返回图片（如 Agent 读图后回传截图）场景下图片同样丢失 | think/Agent | 同上 grep 实证 |
| N5 | **AI 正文流中的本地图片路径无内嵌渲染**（观察项）：`agent_message_chunk` 走 TextStreamBlock 纯文本流，正文中 markdown 图片 `![](path)` 或裸路径不渲染为图像 | 正文流（非卡片） | `transcript.py` TextStreamBlock |
| N6 | **真机 ReadMediaFile 疑似仍是旧行为**（待复核）：用户真机截图显示入参"（无）"、出参裸 JSON + 300 字符截断——与 1712 计划修复前行为完全一致。mock 全过但 A7 真机冒烟未做，需确认是"应用未重启/旧截图"还是"真机帧结构与 mock 蓝本有出入" | ReadMediaFile 真机 | 用户真机截图（2026-08-06） |

## 2. 根因分析

| # | 根因 | 对应症状 |
|:---:|:---|:---:|
| R1 | `TextOutputCard._on_completed` 只读 `output`、不读 `images`；出参载体是 BodyText（QPlainTextEdit 纯文本），结构性渲不出图——1712 计划 T4 的 McpCard 载体升级（BodyHtml + `<img>`）未推广到本卡 | N1 N2 |
| R2 | 空 text + 有 images 场景无任何兜底显示逻辑：`if output := ...` 空串跳过 → 出参区不显示，`total=0` → 徽标也不挂 | N1 |
| R3 | DiffCard 的两段式路径副标题是私有覆写，未上抽为可复用件；TextOutputCard 直接用基类单行省略 | N3 |
| R4 | images 消费方仅 McpCard 一家（1712 计划 T4 的范围决策——当期只承诺 ReadMediaFile 经 McpCard 受益，其余卡未跟进） | N1 N4 |
| R5 | 1712 计划 §7 已记"mock 与真实数据偏差"风险：mock 蓝本靠推断非真机抓帧；A7 五 provider 冒烟未执行 | N6 |

**范围判断**：
- N5（正文流图片）属正文渲染范畴，且 markdown 查看器已有独立渲染链路；本计划**不承诺**，列为观察项，若确证为高频痛点另立计划。
- N6 优先复核——若真机仍旧，说明 1712 修复有未命中的帧形态，须先补真机抓帧再定修复，本计划 T0 覆盖。

## 3. 修复方案

### T0：真机抓帧复核（N6 先行，结果决定 T1 范围）

- 用 kimi 后端真机触发一次 ReadMediaFile 与一次 read 图片，抓 session/update 原始帧存档 `.temp/read_frames_kimi.json`（1712 计划 §7 建议动作，本期补上）。
- 比对 mock 蓝本：若真机帧结构与 mock 有出入（如 `rawOutput` 键名/包裹形态不同），先修正 1712 协议层分发逻辑，再推进 T1。
- 若真机表现正常（截图是应用未重启所致），N6 关闭。

### T1：TextOutputCard 图片出参与载体升级（修 N1 N2 / R1 R2）

**改动点 1 — 共用组装函数上抽**（`cards.py`）：McpCard._compose_output_html 上抽为模块级函数 `_compose_output_html(colors, output, images)`，McpCard 与 TextOutputCard 共用（单一来源，防两处漂移）。

**改动点 2 — TextOutputCard 出参区载体升级**：BodyText → BodyHtml（与 McpCard T4 同方案：text 转义逐行 `<br>` + 等宽 font，不用 `<pre>` 防横向滚动；images `<img>` width 硬限）。行数徽标、「仅显示前 N 行」尾注、复制钮逻辑保留不变。

**改动点 3 — 空 text + images 兜底**（R2）：`output` 为空但 `images` 非空时同样显示 出参区（图片即全部出参）；徽标仅在 `total > 0` 时挂（现状保留）。

**改动点 4 — 纯文本路径形态**（N2）：协议层已对 `<image path>` 标签形态提取 file:// 图片；对"裸路径纯文本"形态（整段 output 就是一个存在的本地图片路径），渲染层组装 HTML 前探测：`output.strip()` 为单行、以图片后缀（png/jpg/jpeg/gif/webp/bmp）结尾 → 追加一条 `file://` 图片渲染（路径文本保留显示）。探测须保守：仅单行 + 已知后缀两条件同时满足才触发，不联网、不读盘验证。

### T2：read 卡副标题两段式（修 N3 / R3）

- DiffCard.set_subtitle 的两段式逻辑（文件名常态色 + 目录 reasoning_fg 弱化）上抽为 `ToolCard._set_path_subtitle(text)` 共用方法；DiffCard 改调共用件（行为不变），TextOutputCard 覆写 `set_subtitle` 调用之。
- 仅 read kind 启用（search/fetch 副标题是 pattern/url，非路径，不套两段式）。

### T3：SubagentCard 防御性消费 images（修 N4）

- `_on_completed` 成果摘要落 BodyText 后，`images` 非空时追加一个 BodyHtml 图片块（复用 T1 上抽的组装函数，`output="" images=[...]`）。
- QuestionCard 评估结论：问答出参为 `{"answers":{...}}` JSON，无图片语义场景，**不消费**（记录决策，防后续重复评估）。

### T4：mock 场景扩充 + 截图闭环（验证设施）

`scripts/shot_tool_cards.py` 新增场景：

| 场景 | mock 帧 | 截图看点 |
|:---|:---|:---|
| `07_read_图片content数组` | kind="read" 首帧 + completed（rawOutput.output 为序列化 content 数组：text `<image path>` + image_url data-URI） | 出参区图片内嵌渲染，不再空白；无 `<image>` 标签裸露 |
| `08_read_裸路径文本` | kind="read" + completed（output 为单行 `/path/to/pic.png`） | 路径文本保留 + 下方缩略图；副标题两段式 |
| `09_agent_返回图片` | title="Agent" + completed（output 结果正文 + content image 块） | 成果正文 + 图片同卡显示 |

流程沿用 1712 闭环：改码 → `.venv/bin/python scripts/shot_tool_cards.py` → 读图逐张核对 → 对照 manifest 打勾。

## 5. 风险与注意事项

| ⚠️ | 裸路径探测误判 | T1 改动点 4 的"单行 + 图片后缀"探测必须保守——误把普通文本行当路径渲染破图比不渲染更糟；不满足两条件原样文本，宁漏勿错 |
