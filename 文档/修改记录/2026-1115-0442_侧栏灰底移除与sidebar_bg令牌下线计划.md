# 侧栏灰底移除与 sidebar_bg 令牌下线计划

> **状态**：已实施（2026-11-15 21:07，UTC+8；回写见 §9）
> **范围**：`assets/themes/base.qss`、`src/ide/gui/theme.py`、`src/ide/gui/title_bar.py`（注释）、四处 `#SidePanel` 挂名点的注释；四主题全部受影响；不打包构建产物
> **时间**：2026-11-15 04:42（设计，UTC+8）；2026-11-15（移植适配本项目）
> **优先级**：中
> **决策来源**：姊妹项目选型方案 C（`sidebar_bg` 令牌移出主题系统、侧栏固定透明）。本项目不再单立选型文档，方案 C 的论据见 §1。
> **说明**：本计划移植自姊妹项目（那边已执行并验证）。主要适配：删除姊妹项目 `src/vista/` 两处消费方（本项目不存在）；姊妹项目的「计划外改动」（title_bar.py 注释悬空引用）升级为本计划的计划内步骤。

## 1. 背景与目标

`sidebar_bg` 令牌承担 IDE 侧栏容器（`#SidePanel`）底色。本项目四主题下它与 `window_bg` 色差仅 ~1–4（cloud `#fafafb`/`#ffffff`、wheat `#fefdfb`/`#fffefd`、sky `#fbfdfe`/`#fdfeff`、mint `#fbfefb`/`#fdfffd`），灰框几乎不可见——**维持令牌的视觉收益趋近于零**，却要为每款新主题多调一枚近似色。姊妹项目的情况更糟（部分主题色差 ~9 显形浅灰实心方框），已判定该侧栏分区底色没有必要并定案方案 C：**令牌移出主题系统，侧栏固定透明**，从机制上根治"未来新主题再出现灰框"。本项目跟随同一决策，同时减少一枚近似令牌的维护面。

目标：

1. `#SidePanel` 固定透明，侧栏与窗底同色，任何主题不再有灰框；
2. `sidebar_bg` 从 `QSS_TOKEN_KEYS` 与四主题调色板中删除；
3. 消费方迁移完毕，应用启动无 KeyError，全量测试绿。

`render_theme` 走 `Template.substitute(全调色板)`——模板残留占位符或调色板残留多余键都不报错，**唯独消费方取键会 KeyError**（fail-fast）。本项目已 grep 确认**无任何代码消费方**取 `palette['sidebar_bg']`（值仅存在于模板与调色板），故处置重点是模板 + 注释悬空引用。`_apply_palette` 的 QPalette 角色不使用本令牌。

## 8. 同源经验（姊妹项目执行沉淀）

- **共享令牌下线「三步核查法」**：模板占位符 → 代码取键方 → 注释悬空引用，同一条 grep 串起②③（姊妹项目 grep 复核时 title_bar.py 的 docstring 即③捕获——本计划已将其列为计划内步骤）。
- 无头 `widget.grab()` 必须先 `show()` + `processEvents()`；自动像素采样取面片区、避开文字与 1px 边缘，否则抗锯齿像素误报。
- 姊妹项目当时是「灰框显形 → 选型 → 下线」；本项目灰框不显形，执行本计划的主观观感变化几乎为零——**验证的重心放在「零回归」而非「灰框消失」**。

### 9.3 经验沉淀

- **活规范文档是第三类悬空引用**：令牌下线「三步核查法」（模板占位符 → 代码取键方 → 注释悬空引用）应扩为四步——加查 `文档/理论依据/` 规范类文档的令牌清单/接线表。本项目 `2026-0722-1710` 令牌清单自称「新增组件可用的全部颜色词」，漏改会把下线令牌重新推荐给未来的组件作者。
- 窗口底/被测色期望值**硬编码进探针**（非从调色板回读），避免「渲染回读 == 调色板」的自证清白式循环断言；卡内/描边等未动令牌回读调色板即可。
- 零观感漂移类改动的像素断言取**绝对期望值**（== 窗底值），不依赖修前帧 diff——计划 §8 已预判「看不出变化即正确」，绝对断言让探针无需回退代码取 pre 帧。
