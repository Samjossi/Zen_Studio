# 双深色主题移除与资源包单套化落地计划

> **状态**：已实施（待真机终验）
> **范围**：`src/gui/theme.py` 的石墨/深夜主题与六套深色资源包、设置中心主题枚举、存量配置回退、受影响测试与现行文档
> **时间**：2026-11-06 05:07（设计，UTC+8）/ 2026-11-06 05:32（实施）
> **优先级**：中

## 1. 背景与目标

当前主题注册表包含六个主题：云白、暖米、晴空、薄荷、石墨、深夜。其中石墨（`graphite`）与深夜（`midnight`）为深色主题，并额外维护语法高亮、终端 ANSI、查看器控件、Git 状态、Git Graph、聊天面板六套 `*_PACK_DARK` 资源包。双套配色增加了后续 GUI 开发、回归测试和视觉走查成本。

本次目标：

1. 完整移除石墨、深夜两个主题，设置中心仅保留云白、暖米、晴空、薄荷四项。
2. 删除只服务深色主题的六套资源包，恢复“四个亮色主题共享一套资源包”的单套结构。
3. 保留注册表、统一 QSS 模板和注入式资源包架构，不为移除主题引入新的分支或兼容层。
4. 四个亮色主题的 QSS 渲染结果和资源包内容保持原样，避免夹带配色或样式调整。
5. 存量配置中的 `graphite`、`midnight` 启动时静默回退默认主题云白，不崩溃、不显示失效主题、不要求用户手改配置。

## 2. 现状与牵连面

### 2.1 主题与资源包单点

`src/gui/theme.py` 是当前唯一需要删除功能数据的运行时代码：

- `THEME_PALETTES` 中的 `graphite`、`midnight` 两条目包含各自 QSS 令牌、标题栏配色及资源包引用。
- `SYNTAX_PACK_DARK`、`TERMINAL_PACK_DARK`、`CHROME_PACK_DARK`、`GIT_STATUS_PACK_DARK`、`GIT_GRAPH_PACK_DARK`、`CHAT_PACK_DARK` 仅被这两个深色主题消费。
- 四个亮色主题已经共享 `SYNTAX_PACK`、`TERMINAL_PACK`、`CHROME_PACK`、`GIT_STATUS_PACK`、`GIT_GRAPH_PACK`、`CHAT_PACK`，无需改名或复制。
- 模块 docstring、资源包和注册表附近注释仍描述“亮暗双套”，需同步改为单套表述。

### 2.2 设置入口与旧配置

- `src/gui/settings_dialog.py` 通过 `list_available_themes()` 动态填充主题下拉框；删除注册项后自动从六项变四项，功能代码无需修改。
- `src/gui/theme.py` 的 `load_settings()` 已对未注册主题回退 `DEFAULT_SETTINGS[KEY_THEME]`；`src/gui/settings.py` 的默认主题为 `cloud`，因此旧配置可直接复用现有回退路径。
- 回退只影响本次读取结果，不主动重写用户配置；本次不修改真实 `config/settings.json`，旧值随用户后续设置写回自然消失。
- `src/gui/main_window.py` 的持久化与“重启后生效”策略不涉及主题名单，保持不变。

### 2.3 测试与文档

需调整的永久测试：

- `tests/test_diff_view.py`：仍断言六主题、亮暗两套值，并使用石墨验证暗色 diff 叠底。
- `tests/test_context_menu.py`：三个查看器用例以石墨作为构造主题，虽非深色专项，删除后须改用现有亮色主题。
- `tests/test_git_graph_panel.py`：主题重渲染不重复查询 Git 的用例使用石墨，改用亮色主题即可继续验证原契约。

需同步的现行说明：

- `README.md`：主题体系仍写“六款”及明暗族名单。
- `术语表.md`：仍有“主题六款”条目。
- `src/gui/README.md`：主题注册表、高亮器和终端配色仍含暗色或明暗双套描述；主题行还存在旧符号表述，本次一并按实际 `THEME_PALETTES` 结构修正。
- `src/gui/window_shadow.py`、`src/gui/panels/find_bar.py`：注释中的“六主题”改为“四主题”或“全主题”。

`assets/themes/base.qss` 与主题数量无关；`assets/themes/README.md` 未记录六主题或深色资源包，均无需修改。历史计划、修改记录是过去事实快照，不做追改。

## 3. 方案决策

### D1 直接删除注册项与深色资源包，不保留隐藏兼容项

- 从 `THEME_PALETTES` 整体删除 `graphite`、`midnight`，使主题查询、设置下拉、渲染和持久化校验共享同一个四项名单。
- 删除六个 `*_PACK_DARK` 常量及只服务它们的注释，不把死代码留作“以后可能恢复”的备用数据。
- 四个亮色条目继续引用现有单套资源包，保持对象共享关系与各项色值不变。
- 不新增 `REMOVED_THEMES`、主题映射表或专门迁移分支；现有“未注册即回退云白”已经覆盖旧配置。

### D2 亮色零变化作为第一验收门

实施前用生产 `render_theme()` 为四个亮色主题保存基线 QSS，并记录六类资源包内容到 `.temp/`；实施后以同一输入重新生成并逐项比较：

- 云白、暖米、晴空、薄荷的渲染 QSS 必须逐字节相等。
- 四个主题的 QSS 令牌、`title_bar` 和六类资源包值必须逐项相等。
- 若出现差异，先判定为误改并修正，不以视觉近似替代等价验证。

### D3 测试保留原契约，不保留深色专项断言

- 将“六主题且亮暗两套值不同”改为“四个注册主题都含完整 diff 色键，且共享同一套值”。
- diff 的 `apply_theme()` 用例改为在两个保留亮色主题间调用，断言主题状态更新、HTML 按当前亮色包重渲染；删除只属于暗色 alpha 叠底的断言。
- 右键菜单和 Git Graph 用例只替换构造主题，不改变菜单、剪贴板、缓存重渲染及“不新增 Git 查询”的原断言。
- 新增集中主题回归，固定四项名单、无效主题回退、QSS 渲染和资源包共享关系，防止后续误把深色死数据重新引入。

### D4 文档只更新当前事实，历史记录原样保留

- 当前 README、术语表、模块说明和有效注释统一为四款亮色主题、单套共享资源包。
- 不批量改写 `文档/修改记录/`、既有 `work plans/` 中曾经实施六主题的历史内容。
- 残留核对以运行时代码、测试和现行说明为范围，不要求历史文档中的 `graphite`、`midnight`、石墨、深夜零命中。
