# 文件引用链接着色补全计划

> 现状已有 L2-5 文件链接化机制，但覆盖面极窄：仅 AI 流式正文中反引号包裹的带扩展名路径被着色。本计划补齐用户消息气泡卡、`@路径` 引用形式、以及其它消息块的文件引用着色，使"被引用的文件"在对话界面中一律呈现链接色并可点击打开。

## 1. 目标行为

| 场景 | 现状 | 目标 |
|:---|:---|:---|
| 用户消息气泡卡中的 `` `gui/theme.py` `` | 裸文本，无颜色 | 链接色 + 下划线，可点击打开文件 |
| 用户消息气泡卡中的 `@gui/theme.py`（拖放/粘贴产生的引用） | 裸文本，无颜色 | 链接色 + 下划线，可点击打开文件 |
| AI 回复中反引号 `` `path.ext[:line]` `` | 🟢 已着色（L2-5） | 保持现状 |
| AI 回复中 `@路径` 形式（AI 复读用户引用时） | 裸文本，无颜色 | 链接色 + 下划线，可点击打开文件 |
| 无扩展名文件（`Makefile`、`LICENSE`）、目录路径 | 不匹配，无颜色 | 在保守判定下着色（见 D3） |
| 推理块 / 工具行 / todo 清单中的路径 | 裸文本 | 本期不做（见 §7） |
| 输入框 `ChatInput` 内的 `@路径` | 裸文本 | 本期不做（见 §7） |

### 2.3 渲染链路现状

```
【AI 回复】chunk → _flush_stream → insertText → _linkify_range  ★ 唯一链接化点
【用户消息】_on_send → append_user_message → HTML 转义 → table 气泡卡  ★ 无链接化
【点击】anchorClicked → _on_output_link → file_open_requested → ViewerPanel.open_file
```

## 3. 设计要点

### 3.1 两条渲染通道，同一套判定正则

- **AI 流式通道**：维持 `QTextCharFormat` 就地加工方式（`_linkify_range`），正则升级后自然覆盖 `@路径`。
- **用户消息通道（HTML 气泡卡）**：`_linkify_range` 基于纯文本游标，无法直接用于 HTML 卡片。方案：在 `append_user_message` 拼装 HTML 前，先对转义后的文本做正则替换，把命中片段包成 `<a href="file:..." style="color:...">`。Qt 富文本子集支持 `<a>` 的颜色/下划线样式，`anchorClicked` 事件照常触发，点击链路零改动。

### 3.2 用户气泡卡 HTML 替换的正确性约束

- **必须先 HTML 转义、后做正则替换**：否则路径中的 `&`、`<` 会破坏文档结构；替换产物 `<a>` 标签本身在转义后插入，不受影响。
- **正则不能误伤 HTML 实体**：转义产物含 `&lt;` `&gt;` `&amp;` `&quot;`，`@路径` / 反引号路径的字符集与实体语法不冲突，但需在单测中以含 `<>&` 的路径文本断言。
- **气泡卡内 `<br>` 已替换换行**，路径正则本身不含 `\n`，无影响。

### 3.3 `@路径` 形式的判定规则

- 触发符：`@` 起始，路径字符持续到空白/标点为止；目录带尾 `/`（与 `input.py` `_mention_text` 的产出格式严格对齐）。
- 锚文本不含 `@` 前缀着色时保留 `@`（即 `@` 也纳入链接范围，视觉与点击一致）。
- **误报防护**：排除邮箱形态（`@` 前为字母数字且整体无 `/`、无扩展名、磁盘上不存在时不链接化——见 D3 的存在性校验）。
- `@` 后无路径字符（裸 `@`）不匹配。

### 3.4 链接色与主题纪律

遵守项目"单一来源、不新增键"纪律：复用 `CHAT_PACK["timeline_read_fg"]`（`#006ab1`）。用户气泡卡为深色背景时（`user_bubble_bg`），`#006ab1` 对比度需在四主题下逐一目验；若某主题对比度不足，再决策是否新增 ChatPack 键（此时才允许突破，并记录在实施记录中）。

### 3.5 点击行为一致性

用户消息中的文件链接与 AI 回复中的文件链接走同一条 `anchorClicked → _on_output_link` 链路，行号语义一致（`#L{n}` 或 `:n` 均解析为行号）。

## 4. 决策表

| 编号 | 决策点 | 初步倾向 | 依据 |
|:---|:---|:---|:---|
| D1 | 链接色来源 | 复用 `timeline_read_fg` | 单一来源纪律；L2-5 已论证同值 |
| D2 | 用户消息链接化的实现载体 | HTML `<a>` 标签替换 | 气泡卡本就是 HTML；`_linkify_range` 不适用 |
| D3 | 无扩展名/裸路径是否着色 | 仅 `@` 形式放开存在性校验后着色；非反引号裸路径不放开 | 裸路径误报率不可控；`@` 是用户显式引用动作，配合工作区存在性校验误报低 |
| D4 | 存在性校验 | 链接化时查 `QDir(workspace).exists(rel)`，不存在则不着色 | 输入框产出的 `@路径` 保证存在；AI 复读的路径可能臆造 |
| D5 | `@` 纳入链接范围 | `@` 与路径整体着色、整体可点 | 视觉一致，避免半着色割裂 |
| D6 | 气泡卡深色背景对比度 | 先复用同色，四主题目验后再定 | 见 3.4 |
