## 1. 背景与目标

### 1.1 上次修复为什么没有解决本次现象

`2026-1120-0946_ACP轮次中断止血与stopReason修复落地计划.md` 已让 Kimi 的非成功 `stopReason` 不再冒充成功，并让 `cancelled` 进入正确收尾通道。这部分修复保留，不回退。

但它处理的是 **prompt 已返回终态之后如何归类**。本次截图中的故障发生在更早阶段：

1. Kimi 为提交/推送做准备，运行 `git log`、`git diff` 或 `git show`；
2. Git 在 PTY 中启动交互式分页器，后台 Bash 一直等待；
3. Kimi 两次调用 `TaskStop`，理由分别为「改用 --no-pager 获取完整差异，关闭交互式分页器」和「已获取提交摘要，关闭交互式分页器」；
4. 两个任务分别运行 129.659 秒和 70.053 秒后才被杀死，用户的工作流随之中断。

因此，仅修正终态分类无法防止分页器阻塞。上次计划还明确记载真实 Kimi 与冻结态 AppImage 验收未完成；525 项测试全绿只能证明假后端覆盖的协议分支，不能证明本次真实工具链已恢复。

### 1.2 本期目标

- AI 执行普通 `git log/diff/show` 时不再进入交互式分页器，不依赖模型记得添加 `--no-pager`；
- 同时覆盖 Kimi 内置后台 Bash 与 ACP `terminal/*` 落到 IDE 真 PTY 的两条路径；
- 修复 `terminal/create.env` 已接收却被桥接层丢弃的问题；
- 不污染 IDE 全局环境和用户手动打开的终端；
- 用真实 Kimi 在本地仓库完成提交与推送，阻断性验收原始场景。

截图没有给出最终 `session/prompt` 响应，故本计划不臆断最后一次 `stopReason` 一定是 `cancelled`。已确认的直接故障是分页器挂住工具任务；终态日志用于验收，不作为预设结论。

## 2. 已确认证据

### 2.1 真实 PTY 对照复现

在同一项目、同一个 `git log --oneline`、同一个 5 行高 PTY 中，仅改变分页环境：

| 环境 | 1.5 秒后进程状态 | 输出特征 |
|:---|:---|:---|
| 继承当前环境，未设置 `GIT_PAGER/PAGER` | 仍存活，需要强制结束 | 出现分页器控制序列 |
| `GIT_PAGER=cat`、`PAGER=cat` | 已自然退出 | 完整输出直接写往 PTY |

这与截图中「后台任务长时间存活，随后由 `TaskStop` 关闭交互式分页器」完全一致。探针只读项目 Git 历史，HOME/XDG 配置指向项目 `.temp/`，结束后已清理探针目录，未改工作树。

### 2.2 两条代码路径都没有完整防护

- **Kimi 内置工具路径**：`src/ide/llm/providers/acp.py` 的 `AcpConnection` 使用 `subprocess.Popen` 启动 `<agent> acp`，未传 `env`，因此 agent 及其内置 Bash 后代原样继承 IDE 环境。
- **ACP AI 终端路径**：`src/ide/gui/panels/terminal/session.py` 的 `PtySession.start()` 已支持 `env_extra`，但 `src/ide/gui/panels/terminal/agent_bridge.py` 的 `_create_gui()` 收到 `env` 后未使用；`src/ide/gui/panels/terminal/panel.py` 的 `spawn_agent_session()` 与 `_spawn_entry()` 也没有继续传递该参数。
- AI 终端使用真 PTY，Git 默认按交互终端启用分页器，所以仅给 ACP 主进程加环境变量不能覆盖这条路径。
- `src/ide/core/child_env.py` 的 `sanitize_environ()` 在 IDE 启动时全局净化私有库路径。若直接把分页器变量写进 `os.environ`，会连同用户手动终端一起改变，不符合本期边界。

## 3. 根因与责任边界

### 3.1 直接根因

**AI 子进程没有统一的非交互分页环境；同时 AI 终端的协议 env 在桥接层断链。**

`TaskStop` 只是故障后的清理动作，不是应被禁用的功能。看门狗和 `stopReason` 分类也只是后续保障，都不能替代源头防阻塞。

### 3.2 本期明确不修

- 不改模型提示词来「提醒模型使用 `--no-pager`」：提示只能降低概率，不能保证 shell 后代行为；
- 不拦截或改写模型命令，不自动给任意命令拼接参数；
- 不设置 `TERM=dumb`、`CI=1`，避免改变无关程序的输出与测试行为；
- 不设置 `GIT_EDITOR=true`、`GIT_SEQUENCE_EDITOR=true`，避免把编辑器交互问题变成静默提交或变基；
- 不设置 `GIT_TERMINAL_PROMPT=0` 或 SSH `BatchMode`：凭据/主机密钥提示属于另一类故障，当前截图没有相关证据；
- 不修改上次完成的 `stopReason`、取消优先级、恢复层和看门狗逻辑。

## 4. 设计决策

### D1 只为 AI 子进程叠加两个确定变量

在 `src/ide/core/child_env.py` 新增纯函数，输入一个环境映射，返回新字典，不修改入参：

- 强制 `GIT_PAGER=cat`：覆盖 Git 的 `core.pager` 与用户继承值；
- 强制 `PAGER=cat`：覆盖其他遵循通用 `PAGER` 的 AI 工具；
- 其余键逐项保留；即使调用方传入 `GIT_PAGER/PAGER`，最终也以非交互值为准。

函数只负责生成环境副本，不调用 `os.environ.update()`，不纳入 `sanitize_environ()` 的全局启动流程。

### D2 ACP 主进程统一注入，覆盖 agent 内置工具后代

`AcpConnection` 启动时以 `os.environ` 副本为底调用 D1 函数，并将结果显式传给 `subprocess.Popen(env=...)`。

改动位于共享 ACP 连接层，不新增 Kimi 专用分支：所有 ACP agent 的自动工具都应具备非交互分页语义；现有 provider 的协议和能力矩阵不变。

### D3 AI 终端补齐 env 透传，并在最后叠加非交互覆盖

调用链改为：

`terminal/create.env` → `AgentTerminalBridge._create_gui()` → `TerminalPanel.spawn_agent_session()` → `_spawn_entry()` → `PtySession.start(env_extra=...)`。

桥接层以协议 env 为底调用 D1 函数，再传给面板。`PtySession` 继续负责叠加到自身环境副本与 `TERM=xterm-256color` 上，不改为向 `env_extra` 传整份 IDE 环境，避免意外覆盖 PTY 的 TERM 设置。

用户手动 `_spawn()` 不传 `env_extra`，行为逐字不变。协议 env 的普通自定义键必须保留，只有两个分页键被强制覆盖。

### D4 不用超时和杀死任务冒充根治

现有 `TaskStop`、看门狗、取消与失败收尾全部保留作兜底。本期的首要验收是普通 Git 命令自然退出，而不是更快杀死分页器。

### D5 真实场景是完成门槛，不是可选补充

内存假进程只验证 env 参数和协议透传；真实 PTY 验证 Git 行为；真实 Kimi + 本地裸远程仓库验证用户原始工作流。三项缺一，不得回写「已修复」。

## 8. 风险与注意点

### 8.1 `cat` 会输出完整结果

禁用分页后，普通 `git log` 可能一次输出较长历史。这是非交互工具的正常语义，工具层可按既有规则截断展示；不得因此恢复交互分页。自动回归使用 `git log -5`，真实验收要求模型取有界历史，避免无意义的大输出。

### 8.2 不要把变量写进全局净化流程

`sanitize_environ()` 会影响整个 IDE 及所有后代。AI 覆盖必须在两个 AI spawn 边界生成，确保用户手动终端仍可使用 `less`。

### 8.3 env 合并顺序是协议正确性的一部分

桥接层既要修复「完全丢弃 env」，也要保证最终分页值不被协议入参覆盖。测试必须走到 PTY，而不是只检查桥接层局部字典。

### 8.4 不承诺解决所有推送阻塞

HTTPS 凭据、SSH 密钥口令、主机真实性确认、提交编辑器都可能造成等待，但与本次已确认的分页器不同。本期只承诺消除分页器这一触发源；其他问题需独立证据和独立决策。

### 8.5 真实验收不可再缺席

上次实施记录已明确真实 Kimi 与 AppImage 未验证。若本次仍只做到假后端和全量 pytest，状态只能是「代码已实施，真实场景待验证」，不能对用户宣称问题已修复。
