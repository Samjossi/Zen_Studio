## 1. 目标

聊天面板从"仅 DeepSeek API key 直连"升级为**双后端**：DeepSeek API（现有）+ 本机 Kimi Code CLI（AI agent，OAuth 已登录）。模型下拉联动刷新版本列表。官方文档：[kimi.com/code/docs](https://www.kimi.com/code/docs/kimi-code-cli/guides/getting-started.html)。

## 2. 本机环境实测结论（2026-07-18）

### 2.1 Kimi CLI 现状

| 项 | 实测值 |
|:---|:---|
| 路径/版本 | `~/.kimi-code/bin/kimi`，0.19.0 |
| 认证 | OAuth 已登录（`managed:kimi-code`） |
| 可用模型别名 | `kimi-code/kimi-for-coding`（默认）、`kimi-code/kimi-for-coding-highspeed`（`kimi provider list --json` 可查，capabilities 含 thinking/tool_use） |

### 2.2 对接方式选型

| | A. `-p` + stream-json 子进程 | B. `kimi acp`（ACP/JSON-RPC） | C. `kimi server`（REST+WS） |
|:---|:---|:---|:---|
| 形态 | 每轮 spawn 短进程，逐行读 stdout JSON | 长驻子进程，双向 JSON-RPC | 长驻本机服务，HTTP/WebSocket |
| 流式 | 消息粒度（assistant 完整消息逐行） | token 粒度（`agent_message_chunk`） | token 粒度 |
| 多轮 | meta 行回传 `session_id`，`-S <id>` 精确续接 | `session/load` 原生支持 | 原生支持 |
| 工具审批 | `-p` 固定 auto 权限（无审批回环，静态 deny 生效） | `session/request_permission` 双向协商 | 完整 |
| 实现成本 | 🟢 低（约百行，与现有 Worker/generator 架构同构） | 🔴 高（需实现 ACP 客户端 + 审批回环） | 🟡 中（服务生命周期管理 + WS 客户端） |
| 参考 | Multi_Cli_Studio JSONL 模式 | Multi_Cli_Studio ACP 模式 | — |

🟢 **选定方案 A**：第一期以最小成本打通 agent 对话；ACP（方案 B）留作后续升级（可获 token 流式与审批回环）。

### 2.3 stream-json 实测结构（本机已验证）

```jsonl
{"role":"assistant","content":"……完整回复……"}                    ← 正文（完整消息粒度，非 token 增量）
{"role":"meta","type":"session.resume_hint","session_id":"session_xxx","command":"kimi -r session_xxx",...}  ← 末行，多轮续接凭证
```

- 官方文档说明：带工具调用时先输出含 `tool_calls` 的 assistant 消息、再输出对应 tool 消息、然后继续 assistant 消息；**thinking 不写入 JSONL**（kimi 思维链第一期不可见，接受）
- `-p` 模式固定 auto 权限：普通工具调用自动批准，不向用户提问；静态 deny 规则仍生效

### 3.1 KimiCliLLM 设计

| 点 | 决策 |
|:---|:---|
| 协议 | 实现 `LanguageModel.chat(messages) -> Iterator[Chunk]`；只取最后一条 user 消息作 prompt（**历史由 CLI 侧会话管理**，与 DeepSeek 实现的全量历史不同，协议内各自解释） |
| 命令 | `kimi -p <prompt> --output-format stream-json [-m alias] [-S session_id]`，cwd=项目根 |
| 多轮 | 首轮无 `-S`；解析 meta 行 `session.resume_hint` 存 `_session_id`，后续轮带 `-S <id>` |
| 上屏 | assistant.content → `Chunk("text", ...)`（消息粒度）；assistant.tool_calls → `Chunk("reasoning", "• 调用工具 xxx")` 复用灰字通道展示 agent 动作；tool 消息第一期忽略 |
| 模型 | `set_model(alias)`；`-m` 省略时用 CLI 默认（`kimi-for-coding`） |
| 版本清单 | 启动时 `kimi provider list --json` 解析模型别名（缓存）；失败（未装/未登录）→ 后端项禁用并提示 |
| 会话重置 | `reset_session()`（清 `_session_id`），本期无 UI 入口，列入后续 |

### 3.2 面板联动

- `ModelBar`：模型下拉项 = DeepSeek API / Kimi CLI（不可用时禁用）；版本下拉按所选模型刷新（DeepSeek → 4 个 `ModelVersion`；Kimi CLI → 模型别名列表）
- 信号改为 `selection_changed = Signal(str, object)`：携带 registry 后端名 + 版本载荷（`ModelVersion` 或别名 `str`）
- `ChatPanel` 持有 `_llm_name`（默认 `"deepseek"`），`_on_send` 用 `get_llm(self._llm_name)` 构造 worker；版本切换经 `isinstance` 分派 `set_version()` / `set_model()`
- **行为约定**：切换后端不迁移上下文（DeepSeek 历史与 kimi 会话各自独立），切换即从新上下文开始；思维链灰字通道对 kimi 复用为工具调用展示

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| `-p` 固定 auto 权限：agent 可在项目目录写文件/执行 shell 且无审批 | 🟡 | 工作目录限定项目根；静态 deny 规则生效；README 明确告知用户该后端具备自主操作能力 |
| 每轮 spawn 进程冷启动 + 消息粒度上屏，响应体感为"等待后整段出现" | 🟡 | placeholder 提示"Kimi CLI 响应中…"；后续 ACP 升级解决 |
| `_session_id` 失效（会话被清理/过期）致续接失败 | 🟢 | 错误上屏并自动 `reset_session()`；用户重发即可开新会话 |
| CLI 版本升级导致 JSONL 结构变化 | 🟢 | 解析按字段名容错（`obj.get()`）；`kimi doctor` 可校验 |
| 切换后端时上下文不互通造成用户困惑 | 🟢 | 输出区切换提示一行（"已切换到 Kimi CLI，开始新会话"） |
