## 1. 问题现象（用户反馈）

文件树双击 wav 音频文件后，查看面板媒体页显示音频占位（文件名 + 播放按钮 + 进度条），但：

- 双击不会自动播放；
- 点击播放按钮无反应；
- 时间标签恒为 `-:-- / -:--`（媒体从未加载就绪，也无任何错误提示）。

## 2. 关键定位结论

代码探查发现播放链路**早已完整实现**（`open_media` 置 `_autoplay` + `LoadedMedia` 自动 play、播放按钮信号已连接），源码态 offscreen 端到端探针可正常播放。用户现场的 `-:-- / -:--` 表明媒体卡在加载阶段且**无任何信号上抛**——根因在运行环境层面（Qt Multimedia FFmpeg 后端加载失败/停滞、无音频输出设备、wav 编码异常且错误消息为空被静默吞掉），而非功能缺失。

## 3. 实施内容

### 3.1 诊断埋点（`media_viewer.py`）

- 模块级 `logger = logging.getLogger(__name__)`，接入 `main.py` 统一日志（`config/logs/zen-studio.log` + stderr 双输出；打包态日志文件是唯一观测面）。
- 埋点覆盖：后端初始化完成、`open_media`/`stop`/`_toggle_play`、每次 `mediaStatusChanged` 状态变迁、`errorOccurred`（含错误枚举值；空串"错误清除"降级 DEBUG 落痕不上抛）。

### 3.2 加载超时守卫（`media_viewer.py`）

- `_LOAD_TIMEOUT_MS = 5000`：`_ensure_player` 懒创建单次 `QTimer`，`open_media` 挂源即武装。
- 解除武装点：`LoadedMedia`/`InvalidMedia` 到达、`stop()`、失败上抛。
- 超时触发 → `_on_load_timeout`：WARNING 日志 + `_fail("音频/视频加载超时：Qt 音频后端不可用或无输出设备")`。

### 3.3 失败统一出口 `_fail`（`media_viewer.py`）

- 同一轮打开只上抛一次（`_failed` 标志，`open_media` 复位），消除超时与错误并发时的重复上抛/重复出声。
- 音频失败自动降级 `sound_player.play_system()` 保底出声，成功则失败文案追加「已降级系统播放器出声」；视频不降级。

### 3.4 探测链共用化（`sound_player.py`）

- 私有 `_play_system` 提为导出 `play_system(path) -> bool`（无可用播放器返回 False），供媒体查看器复用；`sound_player` 内部两处调用同步切换，行为不变。

## 4. 验证

- 新增 `tests/test_media_viewer.py` 8 个用例：自动播放链路、超时武装/解除、音频降级/视频不降级、空错误静默、失败单次上抛、stop 生命周期、`play_system` 无播放器兜底。媒体后端用 `_FakePlayer` 替换 `_ensure_player` 产出，保证 offscreen/无声卡环境确定性。
