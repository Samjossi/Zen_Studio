# 移除 API KEY 直连、统一本机 Agent CLI 后端实施计划

> **状态**：已归档（2026-07-18 实施完成；原位置 `work plans/`）
> **范围**：`llm/` 包 — 移除 DeepSeek API KEY 直连，统一为本机 agent CLI 后端；`gui/panels/chat/` — 模型下拉收敛
> **时间**：2026-07-18 14:55（设计，UTC+8）
> **优先级**：高
> **前置依赖**：⚠️ 须先完成 `2026-0718-1445_KimiCLI后端接入实施计划.md`（Kimi CLI 后端接入），否则移除后无可用后端

## 1. 目标

**简化系统 + 提升安全性**：移除 DeepSeek API KEY 直连方式，聊天面板统一经本机 agent CLI 对话。改造后：

- 代码库**不存放、不读取、不输入任何 API KEY**（凭证由各 CLI 自行管理，如 kimi 的 OAuth）
- 借助封装完善的 CLI 获得更强的 agent 能力（工具调用、文件操作、会话管理均由 CLI 内建）

本期只解决"移除"问题；OpenCode CLI、Kilo Code CLI 接入列为下一步（见第 8 节）。

## 2. 移除清单

| 对象 | 处置 | 说明 |
|:---|:---|:---|
| `llm/providers/deepseek.py` | **删除文件** | API KEY 直连实现（`OpenAI` SDK + `api_key/deepseek` 读取） |
| `llm/__init__.py` DeepSeek 相关导出 | **移除** | `DeepSeekLLM`/`MODELS`/`ModelVersion`/`label_for` 导出与注册表登记 |
| `openai` 依赖 | **`uv remove openai`** | 仅 deepseek.py 消费，移除后无引用 |
| `api_key/deepseek` 文件 | **代码零引用；文件本身保留** | 本地文件由用户自行处置，不删用户数据；`.gitignore` 的 `api_key/` 条目保留（防未来误存密钥） |
| `Chunk`/`LanguageModel`/注册表 | **保留** | Kimi CLI 后端复用同一协议（reasoning 通道用于工具调用灰字展示） |
| ModelBar 模型下拉 | **收敛为 Kimi CLI 单项** | 移除 DeepSeek API 项（待 OpenCode/Kilo Code 接入后恢复多项） |
| ChatPanel `_llm_name` | **固定 `"kimi-cli"`** | 多后端切换逻辑保留骨架，本期单后端 |

## 3. 安全收益（README 需重写对应章节）

| 维度 | 改造前 | 改造后 |
|:---|:---|:---|
| 凭证存储 | `api_key/deepseek` 明文文件 | 无（CLI 自管 OAuth/配置） |
| 凭证输入 | 用户需自行申请并落盘 | 无需任何操作（`kimi login` 一次完成） |
| 泄露面 | 密钥文件误提交风险（靠 .gitignore 防） | 代码库零密钥字面量、零密钥读取路径 |
