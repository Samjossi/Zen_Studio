## 1. 问题与根因证据

用户从蓝牙音响输入切换到声卡输入时，Zen Studio 可能整个退出；开机后首次切换更容易出现。2026-11-09 07:18:11 的事故日志确认：提示音播放后驻留的 Qt 音频上下文在系统音频设备图变化期间进入 PipeWire 原生协议模块，`QAudioContext` 线程于 `libpipewire-module-protocol-native.so` 内段错误，主进程没有机会执行 Python 异常处理或正常收尾。

同一秒内还出现默认 source/sink 不可用、蓝牙 Hands-Free Voice gateway 断开及 WirePlumber 链接失效。具体上游对象生命周期缺陷和单次触发机制仍未通过核心转储定根，本修复不冒充上游问题已经解决。

## 2. 实施内容

- **提示音进程隔离**（`src/gui/sound_player.py`）：删除 `QSoundEffect` 主路径及 `_effect` 单例、`QUrl` 源加载、Loading 补播、Error 态复查等整套 Qt 音频状态机；`_play` 直接走既有 `aplay/paplay/play` 外部播放器出口。原生音频故障即使再次发生，也只影响短命播放器子进程，不再直接带走 IDE。
- **子进程生命周期加固**：保留异步 `Popen`，用 GUI 线程单次 `QTimer` 非阻塞 `poll()` 回收；有存活播放器时继续复查，全部结束后停止，不阻塞 GUI、不新增轮询线程，也不依赖下一次播放收割最后一次留下的僵尸进程。
- **失败诊断与降级**：`Popen` 的 `OSError` 按播放器逐个尝试，全部失败返回 `False`；回收时发现非零或负信号返回码，记录子进程 PID、返回码与 IDE PID，不向主流程抛异常。
- **行为保持不变**：事件到提示音文件映射、设置开关、手动试听、同事件 0.5 秒合并、跨事件不压制、缺文件静默与多窗口独立进程模型均未改。
- **测试纪律同步**（`tests/README.md`）：提示音测试从 Qt 假音频后端改为 `subprocess.Popen` 打桩，继续禁止门禁真实外放。
- **回归测试更新**（`tests/test_notification.py`）：删除旧 Qt 状态机用例，新增外部进程命令形态、无播放器、启动失败逐级降级、全部失败、非零/信号退出回收、仅存活进程续订回收及禁止重新引入 Qt 音频单例的架构守卫。

## 4. 真机验收开放项

以下项目必须由用户在受控环境使用新 AppImage 验证，当前不得标记为已通过：

1. 冷启动后第一次从蓝牙输入切到声卡输入，IDE 必须存活。
2. 提示音播放结束后驻留、播放过程中切换及多次往返切换，IDE 均必须存活。
3. 完成、失败、提问与试听仍按既有语义出声。
4. 未初始化媒体查看器时，提示音不得再创建常驻 `QAudioContext`。
5. 已初始化媒体查看器的独立边界测试仍需执行；该路径保留 `QMediaPlayer + QAudioOutput`，若仍发生原生崩溃，应另立进程隔离计划，不得声称本修复已覆盖。
6. 若再出现退出，立即停止重复测试并保存事故前两分钟起的系统及用户日志；上游 PipeWire 具体缺陷仍需完整原生栈才能定位。
