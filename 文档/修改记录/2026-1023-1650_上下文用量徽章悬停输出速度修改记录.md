> **范围**：AI 聊天面板状态行、kimi ACP 后端、协议定型
> **时间**：2026-10-23 16:50（UTC+8）

## 变更摘要

徽章悬停 tooltip 新增一行：「上轮输出速度：X.X tok/s（输出 N tokens / 生成 S 秒）」。分子为本轮各次 API 调用的 `usage.output` 求和，分母为各次调用配对 `usage.record.time − llm.request.time` 求和——只计模型生成时间，工具执行与审批等待（落在两次请求之间的缝隙）天然排除。仅 kimi 后端产出（push 帧与 estimate 均无 output 计量），其余后端该行缺省不显示。

## 关键实施点

- **T0 实测**（本机真实 wire.jsonl，一轮 16 次调用）：`usage.output` 是单次调用值（序列 277→201→326… 非单调），直取求和禁止差分；每条 wire 记录带 `time`（epoch 毫秒）；单次调用事件序 `llm.request → usage.record → content.part → tool.call/result`。
- **协议**：`src/llm/base.py` 新增 frozen dataclass `TurnSpeed`（`output_tokens`/`gen_seconds`），`Chunk` 末位加 `speed` 可选字段（带默认值，旧构造点零影响）；`llm/__init__.py` 导出。
- **kimi 后端**：`src/llm/providers/kimi_acp.py` 抽出 `_read_wire_records`（全量一次读）与 `_read_wire_turn_stats`（一次读取三件套：record 条数/request 条数/末条用量定型），`_read_wire_usage` 改为薄封装（签名与语义不变）；新增 `_read_wire_turn_speed`（基线截断 + 文件序配对 + 残缺条目跳过）；`_iter_turn_chunks` 基线双记，response 收尾随 usage chunk 同帧携带 speed。
- **等待条件修订**：`_poll_wire_usage` 由「usage 条数 > 基线」改为「新增 usage.record 数 ≥ 本轮新增 llm.request 数」（多步轮次前几条记录会提前满足旧条件、等不到末条）；request 基线失真（新增 ≤ 0）时回退旧语义；上限仍 3s，超时按已落盘子集计算。
- **GUI**：`src/gui/panels/chat/panel.py` `_turn_speed` 簿记（内存态与 `_usage` 同寿命，切后端清零；失败/中断轮不更新）；`_on_chunk` usage 分支同帧接收 speed；`_compose_usage_tooltip` 加 `speed` 参数（`turn_started_at` 后、`now` 前），速度行跟在「上轮任务」行之后。
