## 1. 目标

以 **ACP（Agent Client Protocol）** 替代"每轮 spawn + stream-json"的对接方式：`kimi acp` 长驻子进程，经 stdin/stdout 双向 JSON-RPC 驱动会话。这是 Zed/JetBrains 集成 Kimi Code 的官方方式，与 Zen_Studio 的 IDE 定位天然对齐。

## 2. 动机：与路线 A 方案对比

| 维度 | 现状（路线 A：`-p` + stream-json） | 路线 C（`kimi acp`） |
|:---|:---|:---|
| 进程模型 | 每轮 spawn 短进程，冷启动开销 | 长驻单进程，会话即协议对象 |
| 流式粒度 | 消息粒度（整段上屏） | **token 粒度**（`agent_message_chunk` 增量） |
| 多轮 | meta 行回传 `session_id`，`-S` 续接 | `session/new` / `session/load` / `session/resume` 原生语义 |
| 工具审批 | 无（`-p` 固定 auto，静态 deny 兜底） | **`session/request_permission` 双向协商**，可在 UI 弹窗审批 |
| 文件读写 | agent 直写磁盘 | `fs/read_text_file` / `fs/write_text_file` **反向 RPC 可路由到客户端**（未来可读写编辑器缓冲区/未保存内容） |
| 会话浏览 | 无 | `session/list` 枚举磁盘会话（新会话/历史会话 UI 的协议基础） |
| 模型切换 | 下次请求 `-m` 生效 | `session/set_config_option` 会话内即时生效 |
| 错误恢复 | 进程退出码 + stderr | 长连接，可 `session/cancel` 主动中断当前轮 |
| 思维链 | stream-json 不含 | ⚠️ 待调研：`session/update` 通知类型清单未列 `agent_thought_chunk`，需实测确认 |

## 3. 官方能力矩阵（2026-07-18 摘自 [kimi acp reference](https://moonshotai.github.io/kimi-code/en/reference/kimi-acp)）

- **stable agent-side 10/12**：`initialize`、`authenticate`、`session/new|load|resume|prompt|cancel|list|set_mode|set_config_option` 全实现（缺 `session/close`、`logout`，不影响主流程）
- **stable client 反向 RPC 4/9**：`session/update`（`agent_message_chunk`/`tool_call*`/`plan`/`config_option_update`/`available_commands_update`）、`session/request_permission`（审批与提问共用通道）、`fs/read_text_file`、`fs/write_text_file`
- **unstable**：仅 `session/set_model`（1/19）
- ⚠️ **terminal 反向 RPC 未接通**：shell 命令在 kimi 本地执行，Zen_Studio 无法接管终端展示，shell 输出只能经 `tool_call` 事件摘要呈现（与现状一致，可接受）
- 输入能力：支持 `image` / `resource` / `resource_link` prompt 块（图片输入未来可用）；audio 不支持
- 官方参考实现：Zed `agent_servers` 配置（command=`kimi`, args=`["acp"]`）；SDK：`@agentclientprotocol/sdk@0.23.0`

## 4. 架构设计（草案）

```
gui/panels/chat/panel.py ──► KimiAcpLLM（实现 LanguageModel 协议）
                                │
                                ▼
                           AcpSession（会话状态：session_id、配置项）
                                │
                                ▼
                           AcpClient（长驻子进程管理 + JSON-RPC 帧收发
                                      + 请求/通知/反向请求分发）
                                │
                                ▼
                           spawn `kimi acp`（stdin/stdout 管道，cwd=项目根）
```

| 模块 | 职责 | 关键点 |
|:---|:---|:---|
| `AcpClient` | 帧层：ndjson（每行一个 JSON-RPC 消息，以 SDK 0.23.0 实测为准）；请求 id 配对；通知与反向请求分发；进程崩溃检测与重启 | 反向请求（`session/request_permission`、`fs/*`）必须在读取循环内同步应答，否则 agent 阻塞 |
| `AcpSession` | 一次 `session/new` 的生命周期；`session/prompt` 发送与 `session/update` 订阅 | `session/load` 支持历史回放（恢复 UI 消息的协议路径） |
| `KimiAcpLLM` | `LanguageModel.chat()` 适配：`session/update` → `Chunk` 映射（见下）；`set_model` → `session/set_config_option`；`reset_session` → 下次 `session/new` | 与现有 Worker/generator 架构保持同构，面板零改动（审批 UI 除外） |

**Chunk 映射草案**：

| `session/update` 通知 | Chunk |
|:---|:---|
| `agent_message_chunk`（text 增量） | `Chunk("text", delta)` —— 首次获得 token 级流式，渲染层需支持追加（现状为整段替换，工作量集中在渲染） |
| `tool_call` / `tool_call_update` | `Chunk("reasoning", "• 调用工具 xxx")` 灰字（沿用现有通道） |
| `plan` | 灰字展示（计划条目摘要） |
| `session/request_permission`（反向请求） | **不经 Chunk**：阻断式弹窗 → 用户选择后回应当选项 id |

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| JSON-RPC 帧格式/通知细节与文档描述偏差 | 🟡 | C1 摸底先行，以实测为准；对照 `@agentclientprotocol/sdk@0.23.0` 源码 |
| 审批回环处理不当导致 agent 永久阻塞（等不到应答） | 🔴 | AcpClient 读取循环内集中应答；所有反向请求带超时兜底拒绝；C3 前一律自动允许 |
| 长驻进程生命周期（僵死、句柄泄漏、Zen_Studio 退出残留） | 🟡 | 父子进程退出联动（参考新版 CLI 已处理 SIGHUP/EIO）；退出时显式 terminate |
| thought chunk 不存在导致思维链仍不可见 | 🟢 | 与现状持平，非回退；结论写入 C1 纪要 |
| 渲染层 token 追加改造牵扯面大 | 🟡 | C2 内先整段累积 + 末尾 flush 的保守策略（行为同现状），再迭代真增量 |

| 调研项 | 实测结论 |
|:---|:---|
| 帧格式 | ✅ **ndjson**：每行一个完整 JSON-RPC 消息，无 Content-Length 头 |
| initialize | `protocolVersion=1`；`agentInfo={Kimi Code CLI, 0.27.0}`；`authMethods=['login']`（terminal 型 device-code） |
| 认证 | 已 OAuth 登录时 `session/new` **直接可用，无需 authenticate**；未登录报 `-32000 authRequired` |
| agentCapabilities | `loadSession`、`promptCapabilities{image,embeddedContext}`、`mcpCapabilities{http,sse}`、`sessionCapabilities{list, resume}` |
| session/new | 返回 `sessionId` + **`configOptions`**（model/thinking 选择器，含 3 个别名与当前值）→ 模型切换走 `session/set_config_option{configId:"model"}` |
| **思维链** | ✅ **`agent_thought_chunk` 存在且高频**（单轮 71 块）——stream-json 不可见的思维链在 ACP 可见，映射 reasoning 灰字通道 |
| 流式 | `agent_message_chunk` token 增量（单轮 13+ 块），面板逐块追加以支持 |
| 权限请求 | 选项 `optionId` 为 agent 提供原值（`approve_once`/`approve_always`/`reject`，**≠ kind 名**），回应必须原样回传；kind 分类为 `allow_once/allow_always/reject_once` |
| 权限摘要 | 权限请求的 `toolCall.content` 携带可读描述（"Requesting approval to Running: ls \*.md"）；`rawInput` 审批时刻**不携带**（批准后的 tool_call_update 才出现）；工具参数在审批前经 `tool_call_update.content` 渐进流式 |
| 权限触发面 | 默认权限模式下 **Bash 需审批**，工作区内 **Write 自动通过**（CLI 权限策略，与 `-p` 的 auto 语义不同，ACP 走用户配置模式） |
| session/list | 可用（返回磁盘会话清单），留待 C5 消费 |
| 其他通知 | `available_commands_update`（slash 命令）、`usage_update`（文档有，实测未刻意触发）——本期忽略 |
