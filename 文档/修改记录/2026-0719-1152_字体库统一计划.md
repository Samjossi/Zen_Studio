# 字体库统一计划

## 1. 背景

用户要求：统一使用项目字体库 `assets/fonts/` 内的字体，不再使用全局（系统）字体。现状三处字体消费点：

| # | 消费点 | 现状 | 是否库内字体 |
|:--|:---|:---|:--:|
| 1 | 全局 UI（`gui/theme.py`） | 自带思源黑体 CN（注册失败回退系统 Noto Sans CJK SC；`font_family` 为可配置项） | 🟡 半（有系统回退路径） |
| 2 | 终端（`gui/panels/terminal/widget.py`） | `QFontDatabase.systemFont(FixedFont)` 系统等宽字体 | 🔴 否 |
| 3 | 代码查看器（`gui/panels/viewer/code_viewer.py`） | 同上 | 🔴 否 |

硬约束：终端以字符 `M` 宽度计算单元格（`_cell_w`），pyte 网格渲染**强制依赖等宽字体**；查看器代码缩进/表格对齐同理。字体库现有 7 档思源黑体 CN 全为比例字体，**无等宽字体**，统一必须先补库。

## 2. 参考项目调研结论

调研了三个参考项目的字体实现（2026-07-19）：

| 项目 | 技术栈 | UI 字体 | 等宽字体（终端/编辑器） | 自带字体文件 |
|:---|:---|:---|:---|:--:|
| `参考代码/Multi_Cli_Studio/` | Tauri + Web（xterm.js） | Google Fonts 在线加载 Inter，`system-ui` 回退（`src/styles/globals.css` 的 `--font-sans` 令牌） | xterm `fontFamily: "JetBrains Mono, Cascadia Code, Consolas, monospace"`，纯点名系统字体 | ❌ 无 |
| `参考代码/theia-zen/`（Eclipse Theia） | Web（Monaco + xterm.js） | CSS 变量 `--theia-ui-font-family`，按 OS/语言分层（Linux 中文栈含 Source Han Sans SC） | `editor.fontFamily = 'Droid Sans Mono', 'monospace', monospace`；终端 `terminal.integrated.fontFamily` **默认继承 editor.fontFamily** | ❌ 无（仅 codicon 图标字体） |
| `参考代码/VS_Code_Python/`（实为 PyGPT） | **PySide6**（与本项目同栈） | **自带 Lato**（`data/fonts/` 全量注册 + QSS `* { font-family: 'Lato' }` 强制） | **自带 Monaspace Neon**（GitHub 等宽族），CSS class 指定编辑器/解释器 | ✅ Lato + Monaspace |

要点提炼：

1. **PyGPT 与本项目机制同构**（PySide6 + `QFontDatabase.addApplicationFont` 目录扫描注册），证明"自带字体文件"路线在 Qt 桌面端成熟可行；其策略为**双字体族**：UI 用比例字体（Lato）、代码/终端用等宽字体（Monaspace Neon）。
2. Theia 与 Multi_Cli_Studio 均不自带文字字体，靠系统字体栈点名 + 泛型 `monospace` 兜底——这正是本项目要摆脱的"全局字体"模式。
3. 行业共识：**终端与编辑器共用同一等宽字体族**（Theia 终端直接继承 editor.fontFamily），等宽族独立于 UI 族存在，"统一字体库"不等于"全界面一种字体"。

## 3. 目标

采用**双字体族**策略（调研结论 §2 要点 1/3）：全部字体收敛到 `assets/fonts/` 一个来源，不再出现任何系统/全局字体引用。

1. 全局 UI 字体：强制使用库内思源黑体 CN，移除系统回退路径与 `font_family` 配置项
2. 终端 + 代码查看器：改用库内新增等宽字体族（Sarasa Term SC，§4.2），移除 `systemFont(FixedFont)` 调用
3. 三处字体消费点统一由 `gui/theme.py` 的注册函数供给

非目标（本期不做）：字体大小的用户配置界面、等宽字体族的用户可切换（Theia 式 preference，留待有需求再立计划）。

## 4. 选型决策

### 4.1 UI 字体族：思源黑体 CN（维持，去回退）

- 库内已有 7 档，注册机制成熟（`gui/theme.py`）
- 移除 `FALLBACK_FAMILY`（Noto Sans CJK SC）回退路径与 `settings["font_family"]` 消费：分发包字体必然存在，缺失属打包错误，启动打印告警后由 Qt 自然回退兜底（与 PyGPT `setup_font()` 的"注册失败仅打印"策略一致）

### 4.2 等宽字体族：更纱黑体 Sarasa（新引入）

参考项目的等宽选型（JetBrains Mono / Droid Sans Mono / Monaspace Neon）**均为纯拉丁等宽**：中文走系统回退，中英文宽度比不保证 2:1。本项目终端高频出现中文（项目路径、grep 中文输出、git 中文提交信息），网格渲染对 2:1 宽度比是硬要求，纯拉丁等宽不满足。

**选定：Sarasa Gothic（更纱黑体），取 SC 版本**，理由：

- 基于 Iosevka（等宽拉丁）+ 思源黑体（CJK）合并，**中英文严格 2:1**，与 UI 字体（思源黑体）同源，视觉风格天然统一
- 许可 SIL OFL 1.1，允许随项目再分发（与思源黑体同许可，合规路径已走通过一次）
- 变体取 **Term SC**：终端优化版（无连字、标点宽度终端友好）；查看器与终端共用同族（对齐 Theia "终端继承编辑器字体"共识）
- 入库字重：Regular + Bold 两档（Bold 供终端 ANSI 粗体与查看器语法高亮加粗使用）

备选与放弃项：

| 方案 | 放弃原因 |
|:---|:---|
| JetBrains Mono / Monaspace 入库 | 纯拉丁等宽，中文混排破坏终端网格（§4.2 首段） |
| 终端/查看器维持系统等宽 | 不满足"只用库内字体"目标 |
| 思源黑体强用作等宽 | 比例字体，终端网格直接错乱（已论证） |

### 4.3 体积成本（用户需知晓）

CJK 大字库：Sarasa Term SC 单字重 TTF 约 20MB+，Regular + Bold 合计约 40~50MB 入库。现有思源黑体 7 档已占 57MB，仓库字体总量将超 100MB。可接受（离线分发一致性优先），后续若需瘦身可裁剪字重或换 TTC 合集。
