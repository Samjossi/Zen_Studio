## 1. 问题现象（用户反馈）

DSH（DeepSeek Harness）后台下图片卡片异常，与 Kimi 后台观感不一致：

1. 用户给 AI 发图：粘贴图片退化为 `@路径` 文本上屏，气泡无缩略图预览。
2. AI 读图：DSH 看图工具 `read_image` 的卡片只显示路径、无入参略缩图、无出参图。

## 2. 根因

- **读图卡链路三处失配**：DSH 看图工具名 `read_image` 未收录进卡片分派表（`_TOOL_NAME_CARDS` 仅收 Kimi 的 `readmediafile`），kind 兜底推导成 read → 落 TextOutputCard（只渲染文本、丢弃 images 载荷）；入参略缩图数据源 `_extract_media_path` 只认 `path`/`filePath`，不认 DSH 的 `file_path`；入参已知键表无 snake_case 键，入参区整体 JSON 兜底。
- **用户侧能力位静态写死**：registry `supports_images=False` 是 2026-10-18 spike 的静态结论（acp profile 默认未挂附件存储），运行时 initialize 实测的 `promptCapabilities.image` 从未被消费，dsh 侧挂载附件存储后 GUI 无法自动恢复附件能力。

## 3. 实施内容

- **协议层键扩展**（`src/ide/llm/providers/acp.py`）：`_extract_media_path` 增 `file_path` 三态并联，无扩展名兜底工具名集合放宽为 {`readmediafile`, `read_image`}；`_INPUT_DETAIL_KEYS` 的 read/edit 两组补 `file_path`/`old_string`/`new_string`/`replace_all`（DSH snake_case 命名口径与 kimi 系 camelCase 并联）；`_tool_call_summary` read 分支同步补 `file_path`。
- **卡片分派**（`src/ide/gui/panels/chat/cards.py`）：`_TOOL_NAME_CARDS` 增补 `"read_image": MediaReadCard`；MediaReadCard/McpCard 本体零改动（出参 images 通道、略缩图渲染、降级纪律现成复用）。
- **能力动态翻案**（`src/ide/llm/providers/dsh_acp.py`、`src/ide/gui/panels/chat/panel.py`、`src/ide/llm/registry.py`）：`DshAcpLLM` 新增 `supports_images_override` 实例位，initialize 后按 `agentCapabilities.promptCapabilities.image` 置真值（结构缺失按 False 安全降级）；`ChatPanel._supports_images()` 鸭子类型优先消费覆盖位、回退注册表静态位；`_on_finished` 轮末幂等重刷 `_apply_image_capability()`（首轮 initialize 后附件入口即放行）；`_apply_image_capability` 增能力位跃迁簿记 `_images_applied`，能力位未变即短路——防「残留附件」提示随轮末刷新重复弹（计划未明写的隐藏改动点）；registry 注释更新为「静态 False 兜底初值，运行时以 initialize 实测为准」。
- **降级语义不变**：能力外后端粘贴图片仍走 @路径 透传 + 系统提示，一字未改。
