# 思维链卡 body 空白缺陷视觉闭环修复计划

## 1. 背景

0645 融合计划（期一+期二，2026-08-03 当日落地）实机验证发现：
**ThinkingCard 流式期间与手动展开后，body 内什么字都没有**——标题行
（chevron + "… Thinking" + 复制按钮）正常，思维链明显已经到达
（卡被创建、标题提取生效），但 body 区域无可见文本。

同期冒烟 `.temp/smoke_chat_cards.py` 50 项断言全过却未拦住本缺陷——
**冒烟只断言逻辑状态**（`is_open()`、标题文本、`toPlainText()` 内容
存在性），**从未断言像素级可见性**（body 实际高度、截图）。这是
0645 验证方案（§7-3）的盲区，本计划同时补齐。

用户拍板的方法论要求：**offscreen 截图 + MOCK 模拟真实帧序列 +
自动展开 + 多模态视觉查看截图 + 修改 + 复验，形成闭环**——不靠读代码
臆断，靠截图亲眼确认修前空白、修后可见。

## 2. 预检实证（2026-08-03 07:41，已执行）

写计划前已做最小复现探针（`.temp/probe_thinking_empty.py`，offscreen，
mock 三帧 reasoning 流 + end_reasoning + 手动展开），结果：

```
[streaming] open=True  buffer_len=45 body_visible=True  text_widget_h=22  plaintext_len=45
[finished]  open=False buffer_len=45 body_visible=False text_widget_h=22  plaintext_len=45
[expanded]  open=True  buffer_len=45 body_visible=True  text_widget_h=22  plaintext_len=45
```

**文本在 widget 里（45 字符），body 也可见，但文本块高度恒 22px
（一行高）**——四行文本被压进一行高的视窗，叠加 `set_text` 的尾滚
语义（滚动条置底），用户看到的是被裁切的末行残影即「什么字都没有」。

缺陷复现成立，与用户实机现象吻合。

## 3. 根因（已定位，实证）

`cards.py` `_HugHeightMixin._fit_height` 用
`int(doc.size().height()) + 6` 计算内容高度。该值对两种 body 语义不同：

| body 类 | 底层 documentLayout | `doc.size().height()` 单位 | 实测 |
|---|---|---|---|
| BodyHtml（QTextBrowser） | QTextDocumentLayout | **像素** | 3 行 → 86.0 ✅ |
| BodyText（QPlainTextEdit） | QPlainTextDocumentLayout | **块数（行数）** | 4 行 → 4.0 ❌ |

BodyText 算出的目标高度 = 4 + 6 = 10px → 被下限钳到 22px（一行高），
`setFixedHeight(22)` 锁死。**所有 BodyText 实例的 body 永远只有一行高**。

### 3.1 影响面（不止思维链卡）

BodyText 是全族文本 body 的统一基础设施，受影响面：

- **ThinkingCard** body（用户报告点）；
- **BashCard** 命令块 + 输出块 + 行数尾注前的全部正文；
- **TextOutputCard**（read/search/fetch）正文；
- **SubagentCard** 成果摘要；
- **MCP 卡**入参/出参 JSON 两节；
- **通用入参区**（D3）与 **failed 错误全文块**。

即 0645 §2.1 规格表的 body 列几乎全灭——只是默认折叠的卡把缺陷
藏住了，ThinkingCard 流式展开首当其冲暴露。修复点收敛于 BodyText
一处，全族共益。BodyHtml 系（TextStreamBlock/UserBubbleBlock/
SystemBlock/DiffCard hunk 卡）不受影响。

## 4. 修复方案（待拍板）

### 4.1 技术方案

`_HugHeightMixin` 拆出内容高度钩子 `_content_pixel_height()`：

- **默认实现**（BodyHtml 沿用）：`int(doc.size().height())`（像素，不变）；
- **BodyText 覆写**：遍历 block 累加 `blockBoundingGeometry(block)
  .height()`（像素、含折行——长行 wrap 后一块多行必须算足），再加
  `document().documentMargin() * 2` 与 frame/contentsMargins 余量。

`setTextWidth(viewport.width())` 前置逻辑不变（保证折行测算基于真实
宽度）；上限封顶（BODY_MAX_HEIGHT 320）与 22px 下限钳制不变。

候选替代（弃）：`blockCount * lineSpacing` 简易式——**不折行场景正确、
折行场景欠算**（QPlainTextEdit 的 block 是段落，wrap 不增 blockCount），
bash 长命令行/URL 抓取正文必踩，不取。

### 4.2 决策表

| # | 决策点 | 候选 | 建议选定 | 依据 |
|---|--------|------|----------|------|
| D1 | BodyText 高度算法 | A：blockBoundingGeometry 逐块累加；B：blockCount × lineSpacing | ✅ **A** | B 折行欠算（§4.1）；A 是 Qt 自适应 QPlainTextEdit 的标准做法 |
| D2 | 回归防线的形态 | A：冒烟补「展开后 body 高度 ≥ 内容像素高」断言；B：只靠截图人工看 | ✅ **A** | 本次缺陷正是「只断逻辑不断像素」漏出的；断言可机器复跑，截图为辅助 |
| D3 | 视觉闭环的载体 | A：offscreen grab 截图 + 多模态 Read 查看；B：xcb 真窗截图 | ✅ **A** | 项目既有先例（`.temp/shot_*.py` 族）；offscreen 无需显示服务器、可复跑 |
