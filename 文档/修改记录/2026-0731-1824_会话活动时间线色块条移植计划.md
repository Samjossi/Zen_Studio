# 会话活动时间线色块条移植计划

> 将 Kilo Code VS Code 插件的 **TaskTimeline**（AI 活动横排色块条，用户截图

### 2.2 核心机制（移植要点）

1. **数据粒度**：每个 assistant 消息的每个 part（text/reasoning/tool/
   step-finish）一个色块；user 消息与 step-start 不上条（`collect()`）。
2. **颜色语义**（`colors.ts`，全部走 CSS 变量双主题）：
   - read 类工具（read/glob/grep/find/ls/diagnostics）→ 链接蓝；
   - write 类工具（edit/write/patch/multi_edit/apply_patch）→ 焦点色（另一档蓝）；
   - 其他工具（execute/fetch/MCP…）→ 徽章色；
   - 工具 state.status=error → 错误红（**最高优先级**，覆盖类型色）；
   - text / reasoning → 描述灰；step-finish → 成功绿。
3. **尺寸语义**（`sizes.ts`）：宽度恒定（`BAR_W=12`，无逐 part 时长数据故等宽）；
   高度 ∝ 内容量（text/reasoning 取字符数，tool 取 input JSON + output 字符数），
   `MIN_H=8`、`MAX_HEIGHT=26`、归一化到当批最大值。
4. **布局与命中**（`geometry.ts`）：gap=1 横排累加 x；SVG path 按颜色分组
   合并（同色一条 path，减少节点）；`hit()` 二分查找命中色块；
   `navigate()` 方向键/Home/End 导航。
5. **滚动跟随**（`sizes.ts pinned()` + TaskTimeline）：视口距右缘 ≤ 一个条宽
   时视为「贴底」，新增色块自动滚到最右；用户主动滚离后不再跟随。
6. **交互**：悬停出 tooltip（条目中点定位、视口边缘钳制 160px 边距）并联动
   高亮聊天区对应条目；点击派发 `scrollToMessage` 事件跳转；拖拽/滚轮横滚。

### 2.3 与本仓的数据差距（如实评估）

| 参考侧数据 | 本仓现状 | 对策 |
|---|---|---|
| 逐 part 结构（text/reasoning/tool 天然分块） | ACP Chunk 流：text/reasoning 为流式增量，tool_call/tool_call_update 逐工具 | 路由层设「当前段」聚合：连续同 kind 增量归入同一色块，kind 切换开新块（等价 part 语义） |
| tool 的 input/output 全文长度（条高依据） | ToolCallPayload 只有 title/summary（协议层预格式化，GUI 不解析 rawInput——1602 纪律） | 高度代理量：tool 取 `len(title)+len(summary)`；text/reasoning 取累计字符数；todo 取 entries 条数。**不为此扩协议载荷** |
| 错误态（part.state.status=error） | tool_call_update 的 failed 终态 + error 字段 | toolCallId → 色块索引簿记（复用 `_tool_titles` 同范式），failed 帧将对应块改红色 |
| 点击跳转目标（msgId/partId 锚点） | ChatOutput 无逐工具锚点（1602 一级未做工具行锚点，仅 todo 块有） | 一级不做跳转，仅 tooltip；二级再议（见 §7） |

## 3. 移植设计

### 3.1 架构分层（沿用 1602 抽象/路由/渲染三层纪律）

```
llm Chunk 流（现状不动，零协议层改动）
   │  ChatPanel._on_chunk 旁路分接（新增一行调用，不改动有分支语义）
   ▼
ActivityTimeline（gui/panels/chat/timeline.py，新模块）
   ├─ 记录层：段聚合 + toolCallId 簿记（等价 collect/colors/sizes 的 Python 版）
   └─ 渲染层：QWidget.paintEvent 自绘圆头矩形条（等价 geometry/SVG path）
```

### 3.2 色块数据模型（等价 TimelineBar）

```python
@dataclass
class TimelineBar:
    category: str   # text / reasoning / tool_read / tool_write / tool_other / todo / error
    tip: str        # tooltip 文本（工具：title — summary；text/reasoning：固定词）
    content: int    # 内容量（高度归一化依据，随流式累加）
    tool_call_id: str | None = None  # 工具块簿记键（failed 改色用）
```

「当前段」聚合规则：`_on_chunk` 收到 text/reasoning 增量时，若末块
category 相同则累加 content 并重算高度，否则开新块；tool_call 恒开新块；
todo 帧更新既有 todo 块 content（或首帧开块）。轮次收尾（`_on_finished`/
`_on_stopped`）作废「当前段」指针，下一轮强制开新块——与
`reset_activity_anchors` 同位置调用，防跨轮串位。

### 3.3 颜色映射（参考 palette → 本仓 ChatPack）

| category | 参考色（VS Code 变量） | 本仓落点 |
|---|---|---|
| tool_read | 链接蓝 | **新增键** `timeline_read_fg` |
| tool_write | 焦点蓝 | **新增键** `timeline_write_fg` |
| tool_other | 徽章色 | **新增键** `timeline_tool_fg` |
| text / reasoning | 描述灰 | 复用 `reasoning_fg`（不新增键，沿用 1602 T7 弱化色复用纪律） |
| todo | （参考侧无此块） | 复用 `tool_fg` |
| error（工具 failed） | 错误红 | 复用 `tool_error_fg`（WARNING_COLOR 单一来源纪律） |

tool_kind → category 映射直接可用 ACP 既成语义：
`read/search → tool_read`；`edit → tool_write`；`execute/fetch/think/other
→ tool_other`——比参考侧的「工具名集合猜读/写」更准（协议层 kind 是
agent 自报的，非猜测），这是本仓移植的一个改进点。

### 3.4 尺寸与几何（直译 sizes.ts / geometry.ts）

- 宽度恒定 12px、gap 1px、MIN_H=8、MAX_H=26，归一化到当批最大 content
  （常量原值照搬，实证观感良好，不重新发明）。
- 圆头矩形：QPainter.drawRoundedRect（仅顶部圆角可用 QPainterPath 拼接，
  或直接全圆角——一级从简全圆角 radius=2，视觉差异可忽略）。
- `hit()` 二分命中、`pinned()` 贴底跟随判定（slack=一个条宽）直译，
  约 30 行 Python。

### 3.5 挂载点与布局

- 新增 `ActivityTimeline` 固定高度条（约 30px：MAX_H 26 + 上下各 2），
  置于**输出区与输入框之间**（`_splitter` 内 output 与 input_box 之间不可行
  ——splitter 子件会被拖拽均分；改置于卡片布局 splitter 之下、底行之上，
  或 input_box 内输入框上方——按 D2 拍板）。
- 横向溢出：不自挂 QScrollArea（滚动条破坏细条观感），自绘偏移量 +
  滚轮横滚 + 自动跟随（pinned 判定），等价参考实现。

### 3.6 主题注入

`ChatPack` 新增三键（`timeline_read_fg` / `timeline_write_fg` /
`timeline_tool_fg`），亮暗双主题各给一套 hex；`ChatPanel.apply_theme`
同步调 `timeline.set_colors(...)`——沿用 1602 T7 的
`set_activity_colors` 注入范式。
