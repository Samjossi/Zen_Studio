# Dream ACP 开发中状态如实告知计划

> **状态**：已实施（2026-08-14：T1/T2/T3 完成，§4 验证经 offscreen 探针 `.temp/probe_dream_dev_note.py` 15 项断言全过，抓帧 `.temp/dream_dev_note_shots/`）
> **范围**：`llm/registry.py`、`gui/panels/chat/panel.py`、`llm/README.md`
> **时间**：2026-08-14 06:03（设计，UTC+8）
> **优先级**：中（无功能阻断，但现状对用户构成误导）

---

## 1. 背景与问题

Dream ACP 后端（`llm/providers/dream_acp.py`）是纯 ACP 协议接口层：拉起本机 `dream acp` 长驻子进程，走 stdio ndjson JSON-RPC，**本身不含任何模型推理**。设计上（`2026-0812-1752_DREAM模型收敛dream-creator与auto档位对接计划.md`）：

- 模型别名收敛为唯一值 `dream-creator`，且为不透明字符串——IDE 不解析、不知道、也不允许知道它背后是什么模型；
- 实际出答案的模型由 Dream CLI 服务端配置（`~/.dream/`）决定，IDE 零感知。

由此产生的误导：用户切到「Dream ACP」后，界面上它与 Kimi / Reasonix 等成熟后端并列，无任何信号表明——

| 编号 | 误导点 | 事实 |
|:---:|:---|:---|
| M1 | 看起来是正式可用的后端 | 该后端仍在开发中（`dream-acp/` 目前仅协议文档 + 演示 agent + spike 脚本） |
| M2 | `dream-creator` 像某个具体模型 | 它不代表具体模型；实际模型由 Dream CLI 服务端配置决定，当前可能为 DeepSeek |
| M3 | 回答像是「Dream 模型」给出的 | 回答实际来自服务端配置的上游模型 |

2026-08-14 与用户拍板的处置原则：**如实告知放在对话流里**（用户看答案的位置就是告知出现的位置），但由**客户端确定性地输出系统消息**，不靠注入 prompt 让模型自报家门——disclosure 必须 100% 出现、措辞 100% 准确，这两条 LLM 输出保证不了，且告知是客户端的责任。

项目已有现成机制可复用：聊天输出区的「系统」消息块（`gui/panels/chat/output.py` 的 `append_message("系统", ...)`），后端切换、图片退化、发送失败均走此路；切后端时本就会输出一行切换提示（`gui/panels/chat/panel.py` 的后端切换分支）。

---

## 2. 方案

总原则：**机制通用化（任意后端可挂告知文案），呈现对话流化（系统消息块），改动最小化。**

### T1：`BackendSpec` 新增可选告知字段 `dev_note`

- `llm/registry.py` 的 `BackendSpec` 增加 `dev_note: str | None = None`（放默认值字段区，与既有 `supports_images` / `efforts` 等同款可选风格）；
- dream-acp 注册项填写如实告知文案（初稿，实施时可按用户措辞微调）：

  > Dream ACP 为开发中的接口层，本身不含模型。当前回复由本机 Dream CLI 服务端配置的模型生成（可能为 DeepSeek），界面所示 dream-creator 不代表具体模型。

- 其余四个后端不填，行为零变化。

### T2：切换到带 `dev_note` 的后端时，对话流追加系统告知

- 在 `gui/panels/chat/panel.py` 既有后端切换分支（现输出「已切换到 X 后端，开始新会话」之处）：切换完成后查 `spec_of(backend).dev_note`，非空则追加一条 `append_message("系统", dev_note)`；
- 应用启动即落在 dream-acp（持久化恢复，无切换事件）的场景：该后端会话**首次发送**时若本标签尚未告知过，补一条同款系统消息（标签级布尔标记，防每次发送刷屏）；
- 告知为纯本地 UI，无任何字节进 ACP 帧，不进 prompt、不污染上下文、不烧 token。

### T3：菜单标注与文档同步

- dream-acp 注册项 `label` 改为 `Dream ACP（开发中）`——ModelBar 与设置中心下拉、以及既有切换提示行自动带标注（持久化值是 `name="dream-acp"`，不受影响，无迁移问题）；
- `llm/README.md` 的 dream-acp 条目补一段定位说明（开发中接口层、模型由服务端配置决定、IDE 侧告知机制）。

---

## 3. 明确不做

- ❌ 不向 prompt 注入任何「自报家门」指令（不可靠，且污染上下文）；
- ❌ 不改 dream-acp 的 `name`、模型收敛值 `dream-creator`、ACP 协议面任何行为；
- ❌ 不尝试探测或显示服务端实际模型（IDE 侧无此信息通道，臆造即新的不实）；
- ❌ 不做弹窗/模态对话框（打断式告知与「对话流内自然出现」的既定方向相悖）；
- ❌ 其他后端不挂 `dev_note`，零行为变化。

---

## 4. 验证

按 `维护手册/视觉验证闭环开发指南.md` 执行视觉闭环（offscreen 探针 + 截图）：

1. 切到 Dream ACP 后端 → 对话流依次出现切换提示行 + 系统告知消息，措辞与 T1 文案一致；
2. 同一标签内再发消息、来回切换后端 → 告知不重复刷屏（切回 Dream 再次出现属预期，每次切换一条）；
3. 重启应用（持久化为 dream-acp）→ 首次发送时对话流出现告知，第二次发送不再出现；
4. 回归：切到 Kimi / Reasonix 等无 `dev_note` 后端 → 仅有原切换提示行，无告知消息；
5. 回归：ModelBar 与设置中心下拉显示「Dream ACP（开发中）」，既有 `model_backend` 持久化值 `dream-acp` 正常读写；
6. 确认告知消息不出现在发给 agent 的 prompt 中（ACP 帧无对应字节）。
