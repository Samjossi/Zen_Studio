# 后台模型记忆持久化计划

## 1. 背景与问题

### 1.1 背景

当前模型选择持久化只有**全局单值**：`settings.json` 存 `model_backend`（接口实现名）+ `model_version`（模型别名或 None，None = 落该接口模型列表首项）。注册表 `llm/registry.py` 现有 4 个后台（kimi-acp / reasonix-acp / opencode-acp / kilocode-acp，一后台一接口，UI 三级为「后台 → 接口 → 模型」）。

问题场景：用户在 Kimi 下选了 `kimi-code/k3-256k`，切到 Reasonix 后 `model_version` 被覆盖为 Reasonix 的别名；再切回 Kimi 时旧别名已失效，`ModelBar.set_selection()` 静默回退到模型列表**首项**（`model_bar.py:300-302`）——用户常用的非首项模型选择丢失，每次切回都要重选。

目标：每个接口（用户体感即"每个后台"）各自记住用户最后选定的模型；首次接触的接口仍落首项；切回时恢复记忆值。

现有调用链（选择 → 持久化 → 广播）：

```
ModelBar._on_vendor/interface/model_picked()          (model_bar.py:352-370)
  → selection_changed.emit(backend, version)
  → ChatTabs._on_selection_changed                     (tabs.py:186-191)
      ├─ update_settings({model_backend, model_version})   ← 全局单值写盘
      └─ _broadcast_selection()                          (tabs.py:204-212)
          ├─ ChatPanel.set_model_selection()             (panel.py:136-166)
          └─ MainWindow._on_modelbar_changed             (main_window.py:240)
```

设置中心路径：`settings_dialog.py:355-378`——后台/接口切换已以 `version=None` 收敛 `ctx.apply_model_selection()`，模型切换以实别名收敛。

### 1.3 存量兼容现状

- 当前实际配置：`config/settings.json` 为 `"model_backend": "kimi-acp"`、`"model_version": "kimi-code/k3"`——单值结构，需一次性迁移进记忆表。
- `load_settings()` 未登记键读取即丢弃（`settings.py:117`），旧键移除后随下次 `update_settings` 全量写回自然消亡，机制现成。
- 多开并发：`update_settings` 以 flock 串行化"读-合并-写"（`settings.py:146-157`），但 patch 的合并发生在**锁外调用方**——记忆表 dict 若在锁外读取-修改再整体提交，多开写不同接口记忆会互相覆盖，需锁内合并助手（见 D5）。

## 2. 决策

| # | 决策点 | 选定 | 理由 |
|---|--------|------|------|
| D1 | 记忆表挂载层级 | 挂**接口级**：新键 `model_versions: dict[str, str]`（接口实现名 → 模型别名）；`model_backend` 保留表"当前接口" | 模型目录本就挂接口级（D6 红线 1）；当前一后台一接口，用户体感等价"每个后台记各的"；未来一后台多接口时语义仍正确。后台仍不入 settings（2026-0730-0150 D2 不破） |
| D2 | 旧 `model_version` 键处置 | 读取时一次性迁移：`model_version` 为 str 且 `model_backend` 已知 → seed `{model_backend: model_version}`；旧键从 `DEFAULT_SETTINGS`/TypedDict 移除，改 `_LEGACY_KEY_MODEL_VERSION` 仅供迁移读取，随下次写盘自然消亡 | 沿用 `permission_auto_allow` 迁移先例（settings.py:108-120），零迁移脚本、无 downtime |
| D3 | 信号载荷语义 | **None = "用户未指定模型"（切后台/接口路径），str = "用户显式选定模型"**；`ModelBar._on_vendor_picked`/`_on_interface_picked` 改 emit `(backend, None)`；`_on_model_picked` 不变 | 现状切换路径 emit 回退首项别名（耦合点 5），与"显式选首项"不可区分——不区分就会把"静默回退首项"误写进记忆，用户再无"跟随列表首项"状态。信号签名 `(str, object)` 不破 |
| D4 | 解析与写盘收敛 | 仍在 ChatTabs 单一来源：收到 None → 查记忆 `model_versions.get(backend)` 作有效值（无记忆 → None → UI 落首项，**不写记忆**）；收到 str → 记忆[backend]=别名并写盘；广播载荷为解析后有效值 | 写盘单一来源原则不变（2026-0724-2354 计划）；无记忆不写 = 保留"跟随首项"默认态，模型列表顺序变化仍跟随 |
| D5 | 记忆写盘并发 | settings.py 新增 `remember_model_version(backend, alias)`：flock 内"读全量 → 改 dict 单条目 → 原子写回" | 锁外合并 dict 再整体 `update_settings` 会在多开写不同接口记忆时互相覆盖（§1.3）；锁内合并复用现有 flock/原子写设施 |
| D6 | 记忆别名失效 | UI 回退首项，**记忆保留不擦除** | 模型下线多为临时态，回归即恢复记忆；与红线 5"回退不落盘"一致；失效残留别名永不生效，无副作用 |

**不做的事**：

- 不改注册表/`llm/` 任何文件（记忆是纯 GUI 偏好层，对应 D1）。
- 不给 ModelBar 注入记忆表、不让其读 settings——本组件"不管持久化"边界不破（`model_bar.py:251`），解析职责全在 ChatTabs（对应 D4）。
- 不做"记忆容量上限/LRU 淘汰"——4 个接口量级，dict 天然有界。
- 不持久化后台（vendor）键，仍由 `vendor_of(backend)` 推导（对应 D1）。
- 不动设置中心后台/接口切换的 `version=None` 收敛调用（`settings_dialog.py:355-370` 天然契合 D3，零改动）。

## 3. 改造方案

### 3.1 T1：`gui/settings.py` —— 新键 + 迁移 + 锁内合并助手

1. 键常量：`KEY_MODEL_VERSION` 改名 `_LEGACY_KEY_MODEL_VERSION`（与 `_LEGACY_KEY_PERMISSION_AUTO_ALLOW` 同范式注释）；新增 `KEY_MODEL_VERSIONS = "model_versions"`。
2. `AppSettings`/`AppSettingsPatch`：`model_version: str | None` 移除，新增 `model_versions: dict[str, str]`（注释：接口实现名 → 用户显式选定的模型别名；缺失 = 未定制，跟随列表首项）。
3. `DEFAULT_SETTINGS`：`KEY_MODEL_VERSION: None` 移除，新增 `KEY_MODEL_VERSIONS: {}`。
4. `load_settings()` 迁移段：旧 `model_version` 为 str 且 `model_backend` 为 str → `settings[KEY_MODEL_VERSIONS].setdefault(backend, legacy)`；加载值类型防御——`model_versions` 非 dict 则回退 `{}`，条目键/值非 str 则剔除（与"缺失字段回退默认"姿态一致）。
5. 新增 `remember_model_version(backend: str, alias: str) -> None`：与 `update_settings` 同 flock/原子写路径，锁内 `load_settings()` → `versions[backend] = alias` → 写回（`update_settings` 锁内调 `load_settings` 的既有结构可直接复用，注意 flock 可重入性——实现上在锁内直接读文件而非再调 `load_settings` 之外层加锁，沿用现有函数内聚锁模式即可）。

### 3.2 T2：`gui/panels/chat/model_bar.py` —— 切换路径载荷改 None

- `_on_vendor_picked`（:352-357）：`emit(self.current_backend(), self.current_version())` → `emit(self.current_backend(), None)`。
- `_on_interface_picked`（:359-364）：`emit(backend, self.current_version())` → `emit(backend, None)`。
- `_on_model_picked`（:366-370）：不改（emit 实别名）。
- 组件 docstring（:91-94 信号注释、:21-34 三级语义段）补充载荷语义：None = 未指定，由状态层解析记忆/首项。
- UI 即时反馈不变：切换后菜单仍先勾选首项（`_refresh_models` :348-349），随后广播 `set_selection` 按解析值重勾选——同一事件循环内完成，无可见闪烁。

### 3.3 T3：`gui/panels/chat/tabs.py` —— 解析 + 写记忆

- 导入替换：`KEY_MODEL_VERSION` → `KEY_MODEL_VERSIONS` + `remember_model_version`。
- 初始化（:72-73）：`self._version = settings[KEY_MODEL_VERSIONS].get(self._backend or "")`，结果可能是 None（未定制 → UI 落首项）。
- `_on_selection_changed`（:186-191）：
  ```python
  self._backend = backend
  if isinstance(version, str):            # 用户显式选模型（D3）
      self._version = version
      remember_model_version(backend, version)   # 锁内合并写（D5）
      update_settings({KEY_MODEL_BACKEND: backend})
  else:                                   # 切后台/接口：查记忆（D4）
      self._version = load_settings()[KEY_MODEL_VERSIONS].get(backend)
      update_settings({KEY_MODEL_BACKEND: backend})
  self._broadcast_selection()
  ```
- `apply_model_selection`（:193-202）同构处理（设置中心模型切换传实别名 → 写记忆；后台/接口切换传 None → 查记忆）。

## 5. 验收标准

1. `grep -rn "KEY_MODEL_VERSION\b" gui/` 仅剩 `_LEGACY_KEY_MODEL_VERSION` 定义与迁移读取处；`model_version` 裸字符串不出现在消费侧。
2. 核心场景：Kimi 下选非首项模型（如 `k3-256k`）→ 切到 Reasonix（落其首项或记忆值）→ 切回 Kimi → 模型按钮直显 `k3-256k`，菜单 ✓ 勾在 `k3-256k`。
3. 首次接触场景：切到从未定制过的接口 → 模型落列表首项；`config/settings.json` 的 `model_versions` 不新增该接口条目（跟随首项态保留）。
4. 旧配置迁移：改造前 `settings.json`（含 `"model_version": "kimi-code/k3"`）启动后记忆表 seed 为 `{"kimi-acp": "kimi-code/k3"}`；下一次任意写盘后旧 `model_version` 键消亡。
5. 设置中心路径：AI 模型页切接口 → 模型下拉回显记忆值；选模型 → 写记忆；与 ModelBar 双向同步一致。
6. 失效别名：手工把 `model_versions` 中某别名改为不存在值 → 启动后 UI 落首项、记忆条目保留不擦。
7. 多开：两个实例分别在不同接口下选模型，两份记忆均保留（flock 锁内合并不互相覆盖）。

## 6. 风险与回归点

- **🟡 信号载荷语义变化（已设计化解）**：`selection_changed` 切换路径由"首项别名"改 None，所有消费侧（tabs 双入口、panel、main_window、设置中心）逐一核对——T3/T4/T5 覆盖；签名 `(str, object)` 不破，接线零改动。
