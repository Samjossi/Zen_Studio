# 无边框窗口阶段三增强项结论（拆出档案）

本文档承接《2026-0730-0043_无边框窗口体验完善计划》§3.3 的增强项清单（E1–E5），
将阶段三从原计划中拆出独立归档，并记录实机验证后的最终结论。

## 1. 结论总览

| # | 项 | 原定位 | 实机验证结论 |
|:--|:---|:---|:---|
| E1 | 窗口阴影 + 微圆角 | 中复杂度，后续单开计划 | ✅ **已实现（阴影）**：窗口阴影已落地，边界感/视觉漂浮问题解决；**圆角不需要**，直角观感可接受，不再追加 |
| E2 | 贴边吸附（Aero Snap 类） | 低–中复杂度，先实测再定 | ✅ **已实现**：实测确认 WM 接管路径下系统 tiling 免费获得（如设计预判），无需自绘 |
| E3 | 标题栏右键系统菜单 | 低复杂度，可并入 E1 计划 | ❌ **没必要**：现有三按钮 + 双击 + 拖拽已覆盖日常操作，右键菜单增量价值低 |
| E4 | 拖拽/缩放中 ESC 取消 | 低复杂度，随 E2 评估 | ❌ **没必要**：实机走 WM 原生路径（`startSystemMove/Resize` 接管），取消语义由系统自带；手动兜底为罕见后备路径，不值得专门实现 |
| E5 | 窗口标题追加 Git 分支名/脏标记 | 候选，用户提出再做 | ❌ **没必要**：暂无多开窗口辨识度诉求，维持"用户提出再做"的搁置结论 |

## 2. 验证依据

### E1 窗口阴影 + 微圆角（阴影已实现，圆角不需要）

无边框窗口在亮色桌面上无边界感的视觉缺陷已通过**阴影**解决，窗口在亮/暗
桌面背景下均有清晰边界，四主题下观感一致。原设计中"触碰精密边距体系"的
风险已在实施中消化，无遗留回归。

**微圆角不做**：阴影落地后直角窗口观感可接受，圆角需配合透明背景与外扩
margins 重调边距体系，投入产出比不成立，从 E1 范围中永久剔除。

### E2 贴边吸附（已实现）

原计划预判：`startSystemMove` 由 WM 接管时 GNOME/KDE 自带 tiling 可能免费
获得——**实机验证成立**。拖动窗口至屏幕边缘即触发系统级半屏/最大化吸附，
行为与原生窗口一致，无需应用层自绘。

### E3/E4/E5（评估为没必要）

- **E3**：标题栏右键菜单（还原/移动/大小/最小化/最大化/关闭）所覆盖的操作，
  现有交互已全部可达：双击 = 最大化/还原，拖拽 = 移动，边缘热区 = 缩放，
  三按钮 = 最小化/最大化/关闭。右键菜单仅是多一条入口，无功能增量。
- **E4**：ESC 取消仅在手动 `setGeometry` 兜底路径才有实现意义，而实机走 WM
  原生接管路径，取消语义系统自带。兜底路径触发概率极低，投入产出比不成立。
- **E5**：属"用户提出再做"的候选项，当前无实际诉求，维持搁置。

## 3. 归档决定

- 阶段三（E1–E5）**不再单独立实施计划**。
- 《2026-0730-0043_无边框窗口体验完善计划》中 §3.3、§4 阶段三小节摘除，
  改为引用本文档。
- 若未来出现 E3/E4/E5 相关的真实用户诉求，再按新计划流程立项，不视为本
  计划范围的延续。
