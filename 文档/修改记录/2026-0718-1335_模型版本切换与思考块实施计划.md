## 3. 架构设计

```
llm/
├── base.py                  # 改：新增 Chunk 数据类；chat() 签名 Iterator[str] → Iterator[Chunk]
└── providers/
    └── deepseek.py          # 改：MODELS 常量 + set_model() + 流式解析 reasoning_content 分支

gui/panels/chat/
├── model_bar.py             # 新：ModelBar(QWidget) — 模型标签 + 版本下拉框 + model_changed 信号
├── panel.py                 # 改：splitter 下部改容器（ModelBar + ChatInput）；按 Chunk.kind 分发；发送中锁定下拉
├── worker.py                # 改：chunk_received 信号 str → object（携带 Chunk）
└── output.py                # 改：新增 append_reasoning_chunk()（灰字斜体）与 end_reasoning()（分隔换行）
```

| 组件 | 职责 |
|:---|:---|
| `Chunk`（dataclass） | 流式块：`kind: Literal["text","reasoning"]` + `text: str`，冻结不可变 |
| `MODELS`（常量） | `{"deepseek-chat": "V3.2 通用", "deepseek-reasoner": "V3.2 思考"}`，模型 ID → 版本别名 |
| `DeepSeekLLM.set_model()` | 切换当前版本（校验在 `MODELS` 内），下次请求生效 |
| `ModelBar` | 输入区底行：`QLabel("模型")` + `QComboBox`；下拉项显示 `DeepSeek · V3.2 通用（deepseek-chat）` 格式，`itemData` 存模型 ID |
| `ChatOutput.append_reasoning_chunk()` | 灰（#888）斜体 `QTextCharFormat` 逐块插入，避免 insertHtml 流式不闭合问题 |

**关键行为约定**：

- DeepSeek reasoner 流式时先吐思维链后吐正文；panel 跟踪 `_seen_reasoning` 标志，首个 `text` 块到达前调 `output.end_reasoning()` 插入分隔换行。
- `reasoning` 块**只上屏**，不入 `_stream_buffer` 与 `_history`（DeepSeek 官方约束：多轮请求不得回传思维链，违反会 400）。
- provider 为注册表单例，版本是其内部状态；切换即 `get_llm("deepseek").set_model(...)`，正在进行的流式不受影响。

## 4. 功能裁剪（本期）

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| reasoner 思维链长、首 token 延迟高，用户误以为卡死 | 🟡 | 思维链本身即"正在思考"的可视反馈；placeholder 提示语保持"AI 回复中…" |
| openai SDK 类型定义无 `reasoning_content` 字段 | 🟢 | 用 `getattr(delta, "reasoning_content", None)` 容错访问（chat 版本无此字段返回 None） |
| 灰字在暗色主题下对比度不足 | 🟢 | 色值取 `#888` 中间灰，明暗主题均可读；走查时双主题截图确认 |
| 单例 provider 的版本状态被未来多消费者互相污染 | 🟢 | 本期面板是唯一消费者；多面板/多会话时代改为请求级传参（列入备案） |
| 思维链未剥离误入历史导致 API 400 | 🟡 | 渲染与历史双通道分离由 `_stream_buffer` 只收 `text` 块保证；验证标准含多轮回归 |
