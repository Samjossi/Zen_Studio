## 6. 经验沉淀：GUI 视觉验证闭环方法论（本次成功路径）

本次修复的真正增量不在代码（方案 A 已在 2055 计划趟平），而在
**收敛出一套可复用的视觉验证闭环打法**。按「怎么看 / 怎么动 /
怎么量 / 怎么收敛」四层存档。

### 6.1 怎么看屏幕（三条"眼睛"通道）

| 通道 | 机制 | 适用 |
|---|---|---|
| IDE 自带自动截图 | `--auto-screenshot --screenshot-interval 1` 启动，主窗口每秒 `grab()` 落 `./.tmp/screenshot_*.png`；AI 用读图工具取最新帧即"看到"真机画面 | 真机走查、布局核对 |
| offscreen 控件级截图 | `QT_QPA_PLATFORM=offscreen` 起 QApplication，真实实例化生产控件后 `widget.grab()` 出图存 PNG | 无显示器/CI、控件级验证 |
| 像素扫描 | 对 QImage 逐行扫像素做定量断言，代替"看着差不多" | 选区带、间距、对齐类度量 |

### 6.2 怎么动（XTEST 真机驱动——本轮被用户否决，坑存档）

- 工具：python-xlib `fake_input`（XTEST 扩展）发点击/拖拽/组合键。
- **坑 1 坐标**：python-xlib `translate_coords` 在窗口被 WM reparent
  后给出错误负坐标（窗口实际 (50,50)，它报 (-50,-50)），点击全落空。
  解法：`xwininfo -name "窗口名"` 取 `Absolute upper-left X/Y` 作基准原点。
- **坑 2 中文输入**：XTEST 逐键打 ASCII 会被 fcitx 拦截转成预编辑文本。
  解法：独立 PySide 小进程把中文写入 CLIPBOARD 并存活 60 秒保住
  剪贴板所有权，随后只发 `ctrl+v`（`.temp/xpaste.py`）。
- **坑 3 侵入性（致命）**：真机驱动在用户活跃桌面上抢鼠标键盘，
  用户直接关闭了被驱动窗口。**裁定：XTEST 驱动仅限无头会话或用户
  不在场；用户在场时真机环节必须退化为「用户自然操作」。**

### 6.3 怎么量（offscreen 双帧差分度量法——本次最有价值的产出）

以 `.temp/verify_input_selection.py` 为模板：

1. **复现真机级联环境**：探针给 QApplication 挂应用级 qss
   （`QMainWindow, QDialog { selection-background-color: ... }`，
   与 `assets/themes/base.qss` 同款继承规则）。不挂则控件级抑制 qss
   行为测不准，offscreen 与真机不一致——这是 offscreen 能代表
   真机的前提。
2. **双帧差分定位选区带**：同一控件先无选区 `grab()` 一帧、再程序
   置选区 `grab()` 一帧；逐行对比两帧像素，差异行即选区带行 →
   得带纵向跨度 `[bs₀, bs₁]` 与横向范围。
3. **回无选区帧找字形墨行**：在带横向范围内扫暗像素（RGB 和 <300），
   得文字墨盒跨度 `[is₀, is₁]`。
4. **定量断言**：上留白=is₀−bs₀、下留白=bs₁−is₁、中心偏差=两跨度
   中点差；阈值 `|上下留白差|≤2` 且 `|偏差|≤1px`。本次修复前实测
   上 1px/下 7px、偏差 **+3.0px**（复现偏下）；修复后 3px/3px、
   **+0.0px**。

### 6.4 怎么收敛（两级闭环）

- **第一级（机器）**：修复前先跑探针拿「复现证据」，修复后
  **同一脚本**复测归零——同脚本前后对照是最强证据；再叠存量冒烟
  （本次 20+25 断言）防回归。
- **第二级（人）**：offscreen 度量无法替代人眼终裁，真机最后一环
  由用户日常使用中顺手确认（本次 22:05「成功了」）。
