## 1. 问题现象

用户实测反馈：变更面板里双击一个**新建的、尚未被基准版本收纳的文件**（如刚 `git add` 的新文件），Diff 视图（变更对比弹窗）整页空白，只显示一句"基准侧无该文件内容（文件可能未纳入版本管理）。"，看不到文件本身的任何内容。

## 2. 根因分析

数据链路三级确认：

1. 双击分派：`src/gui/panels/changes/panel.py` `_on_double_clicked`——状态归并规则（`src/core/git/status.py` 模块头注释）把 `A`（已暂存新文件）归入 MODIFIED，故新建文件双击走 `diff_opened` 打开对比视图；
2. 基准拉取：`src/core/git/content.py` `fetch_base_content` 依次 `git show @{upstream}:<path>` / `git show HEAD:<path>`——新文件在两个 ref 中均不存在，返回 `None`；
3. 降级分支：`src/gui/diff_view_dialog.py` `reload` 拿到 `base is None` 直接走占位文案，**未走"基准视为空文本"的 diff 路径**。

期望行为（git GUI 生态标准呈现）：新文件基准侧视为空文本，`unified_rows("", worktree)` 产出整篇全绿（全 `+` 新增行）的 diff。

## 3. 方案

**D1：空基准/空工作区对称回退（`src/gui/diff_view_dialog.py` `reload`）。**

- `base is None` → `base = ""`，继续走正常 diff 渲染（效果：全绿新增）；
- 对称场景：`worktree is None` 时先按 `Path(repo_root, rel).exists()` 区分——文件不在盘上（暂存后被删等边界态）→ `worktree = ""`（效果：全红删除）；文件在盘但读不出（二进制/编码失败）→ 维持"读取失败"占位文案不变；
- 信息行标注：命中空基准分支时基准说明改为「基准：无（新文件，基准侧为空）」，命中空工作区分支时标注「工作区：无（文件已删除）」；
- `MAX_DIFF_LINES` 上限检查、无差异占位等后续逻辑不变，空串天然兼容；
- 模块头 docstring 的降级占位清单同步更新（「基准侧无内容」从占位分支移除，改为空基准 diff 路径）。

边界说明：base 为 `None` 无法区分「ref 中不存在」与「ref 中是二进制」，一律按空基准处理——新文件场景是绝对主case，二进制误判仅表现为全绿呈现，可接受，不为边界加重数据层。

**D2：占位页垂直居中。**
`_placeholder` 增加 `Qt.AlignmentFlag.AlignCenter`：现状文案贴左上、下方大片空白（用户截图实证），居中后观感对齐常规占位页。

**D3：信息行长路径中间省略 + tooltip 全路径。**
现状长路径被挤压截断、看不出完整文件名（用户截图实证）。存储完整信息文案，设置时用 `QFontMetrics.elidedText(ElideMiddle)` 按标签当前宽度省略，`resizeEvent` 中重省略；`setToolTip` 挂完整文案（路径 + 基准说明）。

**明确不做**：未跟踪文件（`??`）双击走 `file_opened` 的语义不动——是否让未跟踪文件也享受「空基准全绿」diff 涉及交互语义变更，单独评估另立计划。
