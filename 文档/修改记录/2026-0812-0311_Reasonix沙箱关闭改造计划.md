# Reasonix 沙箱关闭改造计划（对齐其他 CLI 行为）

> 编制日期：2026-08-12
> 状态：**已实施，用户实测验证通过**（2026-08-12）
> 前置文档：《文档/修改记录/2026-0812-0301_Reasonix沙箱不可用导致AI反复尝试bash问题调查报告.md》（根因三层结论）

---

## 1. 目标

让 Reasonix 的 bash 执行逻辑与 Kimi Code / OpenCode 等其他 CLI 一致：**不经 OS 级沙箱，审批通过后直接在宿主机执行**，彻底消除「bash sandbox requested but unavailable」导致的 bash 工具瘫痪与 AI 换命令死循环。

## 2. 关键代码事实（决定方案形态）

在 `.temp/DeepSeek-Reasonix`（官方仓库浅克隆）中核实：

- `reasonix acp --sandbox-bash` 启动旗标**只接受 `auto | enforce`，没有 `off`**（`internal/cli/acp.go:42` 定义，`:67-69` 校验拒绝其他值）。旗标只能收紧不能放松。
- ACP 模式有效模式取自 `cfg.BashMode()`（`acp.go:203`），即 **`~/.reasonix/config.toml` 的 `[sandbox] bash` 配置在 ACP 模式下完全生效**。
- 因此 **Zen Studio 侧（`llm/providers/reasonix_acp.py:295` 的启动参数）无法通过加旗标关闭沙箱**，唯一干净入口是 config.toml。
- Zen Studio 项目代码已知该配置路径：`llm/context_limits.py:25-34`（`$REASONIX_HOME/config.toml` → `~/.reasonix/config.toml`）。

## 3. 方案

### 方案 A：config.toml 写入 `[sandbox] bash = "off"`（推荐）

**改动文件（项目外，需用户授权）**：`~/.reasonix/config.toml`（若设置了 `REASONIX_HOME` 则为 `$REASONIX_HOME/config.toml`）

在文件末尾追加（若已有 `[sandbox]` 段则改其 `bash` 值）：

```toml
[sandbox]
bash = "off"
```

- 一次改动同时覆盖 Zen Studio ACP 会话与终端 `reasonix code` 两种用法。
- 零系统改动、可逆（删掉该行即恢复 enforce）。
- 生效后行为与 Kimi Code/OpenCode 对齐：bash 直接执行，安全边界依赖 Zen Studio 既有的审批回环（`session/request_permission`）。
- 代价：shell 命令不再隔离（写文件工具仍受 `workspace_root` 约束，与现状一致）。

### 方案 B：修复 bwrap 保留沙箱（备选，用户已倾向放弃）

`sudo sysctl kernel.apparmor_restrict_unprivileged_userns=0` + 持久化。放宽全系统安全加固，详见调查报告 §4。本计划不采用，仅留档。

## 4. 实施步骤（方案 A）

1. **探测**：确认 `$REASONIX_HOME` 是否设置，定位生效的 config.toml；检查文件是否已有 `[sandbox]` 段（避免重复段落导致 TOML 解析错误）。
2. **备份**：复制为 `config.toml.bak-20260812`（同目录）。
3. **写入**：追加或修改 `[sandbox] bash = "off"`。
4. **验证一（配置层）**：用 Zen Studio 的 `.venv` Python `tomllib` 解析该文件，确认 `["sandbox"]["bash"] == "off"` 且无语法错误。
5. **验证二（端到端）**：重启 Zen Studio 的 Reasonix 会话标签，让 AI 执行一条简单 bash 命令（如 `date`），确认不再出现 sandbox unavailable 报错。
   - 补充验证（可选）：reasonix 会话内 `/sandbox` 应显示模式为 off。

## 5. 影响面与回滚

- 影响面：仅 Reasonix 一个后端；Zen Studio 项目代码**零改动**（无需改 `reasonix_acp.py`，ACP 旗标无 off 值，加了也无效）。
- 回滚：删除 `[sandbox] bash = "off"` 行，或从备份恢复。
- 文档联动：实施后在《文档/理论依据/后端CLI工具维护说明手册.md》§4 补一句「本机已配置 `[sandbox] bash = "off"`（2026-08-12，因 AppArmor 拦截 bwrap）」。
