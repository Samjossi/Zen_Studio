# 文件树与 Git 树切换按钮落地计划

> **状态**：已确认
> **范围**：文件树头部与内容区（`src/gui/panels/file_explorer/`）、Git 状态扇出（`src/gui/controllers.py`）、主题样式（`assets/themes/base.qss`）、测试与 GUI 文档
> **时间**：2026-11-05 22:29（设计，UTC+8）
> **优先级**：中

## 1. 需求

1. 在右栏上文件树头部的最右侧新增一个切换按钮，与项目名、当前分支名同行。
2. 默认显示现有文件树；点击按钮后，内容区原地切换为 **Git 树**，再次点击返回文件树。
3. 第一期 Git 树直接复用现有**扁平变更文件列表**，保留状态着色、增删行数和双击打开差异等既有交互；不构建目录层级，优先把切换链路简单跑通。
4. 切换按钮复用文件树搜索钮、刷新钮的视觉语言：圆形、常态半透明、悬停恢复不透明、背景与 hover 走全局 `QToolButton` 主题规则。
5. 文件树与 Git 树共用现有头部和右栏上槽位，不改变三栏主布局；右栏下现有 `ChangesPanel` 保留不动。

## 2. 现状与可行性结论

### 2.1 头部与内容区

`FileExplorer` 当前头部由双 stretch 夹持项目名和分支标签，内容区直接放置 `self.tree`。按钮可在头部右侧追加；内容区可改为 `QStackedWidget` 双页：

- 第 0 页：现有文件树 `self.tree`。
- 第 1 页：复用现有变更列表的无头部实例。

切换只改当前页，不销毁或重建文件树模型，因此文件树展开状态、选中状态和搜索代码所依赖的 `self.tree` 均保持有效。

### 2.2 Git 数据与刷新

无需新增 Git 命令、定时器或文件监视器：

- `GitStatusService.collect_changes()` 已返回完整 `ChangeEntry` 清单，包含仓库相对路径、状态和增删行数。
- `GitStatusController.refresh()` 已有六事件源、300ms 去抖和统一扇出，可在同次刷新中把同一份变更清单喂给 Git 树与右栏下变更面板。
- 分支切换、外部改盘、AI 改盘和手动刷新均沿用现有链路，不为 Git 树建立第二套数据通道。

### 2.3 既有交互复用

`ChangesPanel` 已定义以下语义，Git 树文件行应保持一致：

| 条目 | 双击行为 |
|:---|:---|
| 已修改 M / 未跟踪 U | 打开变更对比视图 |
| 已删除 D | 发射删除提示，不尝试打开不存在的文件 |
| 冲突等其他可打开条目 | 在查看器打开文件 |

直接抽取并复用其扁平列表，包括状态色、删除线、`+N` / `-N` 列及信号分派规则；不把整个 `ChangesPanel` 嵌入文件树，避免带入重复的头部、标题和收起按钮。

## 3. 方案决策

### D1 Git 树形态：第一期复用扁平变更列表

- 直接复用 `ChangesPanel` 现有的三列扁平列表：仓库相对路径、增行、删行；保持状态色、删除线和统计列样式不变。
- 不按路径构建目录节点，不实现目录展开/折叠，也不保存或恢复目录展开状态。
- 空变更沿用「（无变更）」占位；非 Git 环境不进入 Git 树。
- 文件行 tooltip、双击打开差异和删除提示均沿用现有行为。
- 为复用列表，将列表本体从 `ChangesPanel` 抽成无头部的 `ChangesList`；上方 Git 页和右栏下面板各持有一个实例，共享实现而非复制代码。
- 目录层级树属于后续可选增强，需另立计划；本期不包含暂存区、提交、分支切换、提交历史图等 SCM 功能。

### D2 切换按钮：头部最右侧圆形按钮

- 使用 `QToolButton`，objectName 为 `FileTreeModeButton`，父子关系与生命周期归 `FileExplorer`。
- 尺寸按头部行高收敛为 **24×24px**，圆角 12px；复用搜索钮、刷新钮的视觉范式，但不照搬悬浮钮的 32px 尺寸，以免撑高头部。
- 常态 `QGraphicsOpacityEffect` 透明度沿用 0.5，Enter 恢复 1.0、Leave 回落 0.5；鼠标指针为手型。
- 按钮固定使用双向切换符号，不随页面变化；仅 tooltip 动态更新：文件树模式为「切换到 Git 树」，Git 树模式为「返回文件树」。固定字形可避免与分支标签的 `⎇` 重复，并省去双字形状态同步。
- 不引入图标字体依赖，符号候选池如下；截帧发现默认字形缺失时按优先级回退：

| 优先级 | 符号 | 码位 / 语义 | 定位 |
|:---|:---:|:---|:---|
| 默认 | `⇄` | U+21C4，右箭在上、左箭在下 | 上下叠置的反向箭头，最符合双向切换语义 |
| 首选回退 | `⇆` | U+21C6，左箭在上、右箭在下 | 与默认符号同系列，仅方向相反 |
| 最终兜底 | `↔` | 单条左右双头箭头 | 字形覆盖广，双向含义直观 |
| 留档备选 | `⇅` `⇵` | 上下方向的成对反向箭头 | 更偏上下互换，优先级低于左右切换 |
| 留档备选 | `⇌` `⇋` | 可逆 / 反向可逆箭头 | 带化学可逆语义，不如 `⇄` 直接 |
| 留档备选 | `⮂` | U+2B82，三角头双向叠箭 | 字形较冷门，需字体覆盖验证 |
| 留档备选 | `↕` `⟷` `⟺` | 上下双头 / 细长左右 / 长双线左右箭头 | 形态或方向不如默认符号贴合 |
| 留档备选 | `⇔` `↹` `⇿` | 粗双线等价 / Tab 切换 / 空心双向箭头 | 分别带等价、Tab、空心箭头语义，仅留档 |
- 头部左右保留等宽占位，避免右侧按钮把「项目名 + 分支名」视觉中心推向左侧；按钮始终位于该行最右边。
- 初始及非 Git 环境隐藏按钮并强制回到文件树页；正常 Git 仓库显示。模式仅保留在当前窗口会话内，不新增设置项或持久化字段。

### D3 内容切换与文件树专用控件

- 用 `QStackedWidget` 包裹文件树和 Git 树，头部始终保留，因此切换后项目名、分支名与返回按钮仍可见。
- 切到 Git 树时隐藏文件树右下角刷新钮、左下角搜索钮；若搜索栏正在展开，同时收起并复位文件树搜索状态。
- 返回文件树时恢复两个悬浮钮，并按当前面板尺寸重新定位；原文件树模型、展开和选中状态不重建。
- Git 树不使用文件树的右键菜单、拖出、重命名、搜索或模型重建逻辑。

### D4 数据喂入与信号接线

- `FileExplorer` 新增 `apply_git_changes(changes, repo_root, theme)`，仅负责把控制器已聚合的数据交给 Git 树；`apply_git_status()` 继续负责文件树着色、分支标签和切换按钮可用状态。
- `GitStatusController.refresh()` 每次只调用一次 `collect_changes()`，将同一清单分别喂给 `FileExplorer` 和 `ChangesPanel`，避免未跟踪文件行数统计被重复读取。
- Git 树控件的 `file_opened` 由 `FileExplorer.file_opened` 转发；`FileExplorer` 新增 `diff_opened`、`deleted_activated` 转发信号。
- `GitStatusController` 将这两个信号接入现有差异弹窗与删除提示槽，和 `ChangesPanel` 共用后续管线；`MainWindow` 布局无需调整。
- 主题切换时，Git 树使用缓存数据按新主题重绘，不触发额外 Git 查询。

## 4. 实施步骤

### 4.1 抽取可复用的扁平变更列表

新增 `src/gui/panels/changes/list.py`，并修改 `src/gui/panels/changes/panel.py`：

1. 将现有三列 `QTreeWidget` 的构建、状态着色、删除线、统计列、空态和双击分派原样抽成 `ChangesList`。
2. `ChangesList` 暴露 `apply_changes()`、`apply_theme()` 和 `file_opened` / `diff_opened` / `deleted_activated` 信号，不带头部长条、标题或收起按钮。
3. `ChangesPanel` 保留现有头部、标题计数、布局和信号接口，内部改为组合 `ChangesList` 并转发信号；右栏下外观和行为不变。
4. 上方 Git 页直接创建另一个 `ChangesList` 实例，不复制渲染与分派代码，也不新增目录层级构建逻辑。

### 4.2 改造 `FileExplorer`

修改 `src/gui/panels/file_explorer/explorer.py`：

1. 构建头部右侧切换按钮和左右等宽占位，接入点击切换与 hover 透明度事件。
2. 将 `self.tree` 放入双页 `QStackedWidget`，创建并加入 `ChangesList`；现有模型、搜索和右键代码继续引用原 `self.tree`。
3. 新增模式切换槽，统一处理当前页、按钮 tooltip、搜索栏复位、悬浮钮显隐和位置。
4. 新增 `apply_git_changes()` 与两路转发信号；`apply_git_status()` 在非 Git 状态隐藏按钮并回退文件树页。
5. `apply_theme()` 同步刷新 Git 树主题；`resizeEvent()` 保持现有分支截断与悬浮钮定位行为。
6. 更新模块 docstring 的头部构成和双页内容说明。

### 4.3 接入现有 Git 刷新链

修改 `src/gui/controllers.py`：

1. `refresh()` 中先生成一次变更清单，再分别喂入文件树内 Git 树和右栏下 `ChangesPanel`。
2. 接线 `FileExplorer.diff_opened` 到 `_open_diff_view`，`deleted_activated` 到既有状态栏提示。
3. 更新类与刷新方法 docstring，将扇出描述改为「文件树着色及内嵌 Git 树 / 查看器徽标 / 变更面板 / 状态栏统计」；事件源数量和去抖机制不变。

### 4.4 主题样式

修改 `assets/themes/base.qss`：

1. 新增 `#FileTreeModeButton`，复用全局 `QToolButton` 背景和 hover，仅设置 `padding: 0`、24px 尺寸对应的圆形圆角及适配字形的字号。
2. 不复制背景色、hover 色等主题色值；四主题继续由全局规则统一着色。
3. 若固定符号的视觉中心偏移，仅在该选择器内做像素级 padding 微调，并以截帧结果为准；页面切换不重算字形样式。

### 4.5 测试

新增 `tests/test_file_tree_git_mode.py`，并保留、必要时调整 `tests/test_changes_panel.py` 的既有回归：

- 列表抽取：既有状态渲染、空态和 M/U/D 双击分派测试继续通过；`ChangesPanel` 的公开信号接口不变。
