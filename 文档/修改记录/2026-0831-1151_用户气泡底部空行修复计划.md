## 0. 问题总览

用户气泡存在两类"空行"观感，根因相互独立：

| 编号 | 现象 | 频率 | 根因性质 |
|:---|:---|:---|:---|
| 问题一 | 气泡底部恒有 ≈16px 留白，整体冗余约一行 | 每条必有 | 三层布局留白叠加（纯观感，可接受但可收紧） |
| 问题二 | 气泡内偶发**巨大空白**（约 200px）且气泡内出现滚动条 | 偶发 | 失效图片占位 + 滚动条范围时序残留（🔴 缺陷） |

用户实测确认：问题一无关紧要，**本计划主修问题二**，问题一作为可选收紧项保留。

## 1. 问题一：恒定底部留白（轻量，可选）

### 1.1 定责结论

当前生效渲染轨为 cards 卡片轨（`config/settings.json` 中 `chat_renderer: "cards"`）。用户消息链路：

`gui/panels/chat/input.py`（`trigger_send`，发送前已 `strip()`）→ `gui/panels/chat/panel.py`（`append_user_message`）→ `gui/panels/chat/transcript.py`（`ChatTranscriptView.append_user_message` → `UserBubbleBlock`）→ 正文控件 `BodyHtml`（`gui/panels/chat/cards.py`，QTextBrowser 子类）。

"空行"是**三层底部留白叠加**，总高度恰好约等于一行，逐层拆解：

| 层 | 位置 | 机制 | 底部贡献 |
|:---|:---|:---|:---|
| 1 | `gui/panels/chat/cards.py` `_HugHeightMixin._fit_height` | 高度计算无条件 `内容高 + 6`，6px 全部落在文档之后 | 6px |
| 2 | `gui/panels/chat/cards.py` `BodyHtml` | 未覆盖 QTextDocument 默认 `documentMargin = 4px`，而 `_content_pixel_height` 取的 `document().size().height()` 本身含上下各 4px | 4px |
| 3 | `gui/panels/chat/transcript.py` `UserBubbleBlock` | 气泡布局 `setContentsMargins(8, 6, 8, 6)`，卡内底部内边距 | 6px |

以用户实测配置（Source Han Sans CN 13pt，行高 25px）：单行消息的气泡内**底部留白 16px、顶部 10px**，底部比顶部多 6px。该区域内无任何字符，与"复制不到内容但确有空行"的症状吻合。

### 1.2 已排除的嫌疑

- 🟢 **Markdown 渲染链路**：项目根目录的 `markdown_it/` 仅被 `gui/panels/viewer/markdown_view.py`（Markdown 文件预览器）使用；用户消息走 HTML 转义 + `linkify_html` 链接化，不经 markdown → HTML，不存在 `</p>` 块级 margin 问题。
- 🟢 **尾部真实换行**：发送路径均已 `strip()`；`UserBubbleBlock` 内 `body.replace("\n", "<br>")` 虽在内容带尾换行时会产生真空行，但当前不可达。
- 🟢 **QSS**：`assets/themes/base.qss` 无相关 padding/段落间距规则（Qt QSS 本身也不能设置段落间距）。
- 🟡 **旧 classic 轨**：`gui/panels/chat/output.py` `ChatOutput.append_user_message` 在气泡 table 后 `append("")` 追加真实空段落，table 另有 `cellpadding="8"`。仅 classic 轨生效，非当前症状来源。

### 1.3 修复方案（可选，随问题二一并实施）

`_fit_height` 的 `+6` 是卡片族共用收敛点，🔴 不得直接改默认值（改动即全卡片族高度漂移）。做法：

1. `gui/panels/chat/cards.py` `_HugHeightMixin._init_hug` 增加参数 `bottom_padding: int = 6`，`_fit_height` 改用 `self._bottom_padding`；`BodyHtml`/`BodyText` 透传（默认 6，存量调用点零改动）。
2. `gui/panels/chat/transcript.py` `UserBubbleBlock` 构造 BodyHtml 时传 `bottom_padding=2`，并对该实例 `document().setDocumentMargin(2)`。
3. 气泡布局 `setContentsMargins(8, 6, 8, 6)` 不动（同时决定顶部间距，避免上松下紧）。

预期：底部留白 16px → 约 4px，与顶部基本持平。

## 2. 问题二：偶发巨大空白 + 气泡内滚动条（主修）

### 2.1 mock 复现

offscreen 环境（`QT_QPA_PLATFORM=offscreen`，`.venv` Python）对 `ChatTranscriptView` mock 发送 12+ 种消息实测，复现脚本留存于 `./.temp/`：

| 脚本 | 用途 |
|:---|:---|
| `.temp/probe_bubble_height.py` | 12 用例全量高度测量 |
| `.temp/probe_bubble_height2.py` | 图片用例深挖 + grab() 截图目检 |
| `.temp/probe_bubble_height3.py` | `documentSizeChanged`/`rangeChanged` 信号时序定责 |
| `.temp/probe_bubble_height4.py` | 纯文本 192px 阈值补验 |

**稳定复现的最小用例**（与用户截图逐点吻合）：两行文本 + 一张已不存在的图片附件。实测气泡总高 250px（文本仅占顶部约 50px），下方一块 200×200 破损图片占位（视觉即"大片空白"），气泡内右侧滚动条常显。纯文本任意变体（空行、@提及、URL、折行、宽度时序变化）均**无法**复现巨大空白。

### 2.2 根因（两重叠加）

**① 巨大空白来源 —— live 路径图片无存在性检查**

`gui/panels/chat/transcript.py` `UserBubbleBlock` 构造时对 `images` 直接拼 `<img src="file://..." width="200">`，**不查文件是否存在**；而历史回放路径 `gui/panels/chat/panel.py`（`replay_session`）有 `Path(img["path"]).exists()` 过滤——两条路径行为不一致。

图片文件真实可达的消失路径：粘贴图落盘 `.tmp/pasted/`，`gui/panels/chat/input.py` `_prune_pasted_images` 只保留最近 20 个——同一会话粘贴超 20 张后，早期气泡引用的 PNG 被惰性删除，旧气泡下次排版即 404；或用户移动/删除了以文件形式添加的本地图片。

缺失图片在 QTextDocument 中渲染为 **200×200 占位块**（宽取自 `width="200"` 属性），doc 高度 +200px，即"巨大空白"。

**② 滚动条残留 —— `_fit_height` 的 setFixedHeight 与 Qt 滚动条范围更新时机脱节**

`gui/panels/chat/cards.py` `_HugHeightMixin._fit_height` 末尾 `setFixedHeight(doc_h + 6)` 是纯高度变化。实测时序：`setHtml` 时 BodyHtml 仍是 QTextBrowser 默认高 **192px**，`documentSizeChanged(doc_h)` 发射瞬间 Qt 按 `doc_h − 192` 设置滚动条范围；若 doc_h > 192 滚动条即出现。随后 `_fit_height` 把高度改成 doc_h+6，但 **QTextBrowser 只在文档宽度变化引发重排时才重算滚动条范围，纯高度 resize 不重算**——范围永远定格在 `doc_h − 192`。

定格条件：doc_h > 192 且此后无事件再改变文档尺寸。短行文本/定宽图片占位不回流 → 定格常显；长折行文本或异步加载完成的图片会再触发一次重排 → 自愈；任何窗口宽度变化也自愈。这就是"偶发"的来源：取决于内容类型与信号交错次序。

数据自洽验证：滚动条范围恒等于 `doc_h − setHtml 时刻的控件高`，三轮实测全部吻合（52=244−192、176=368−192、158=226−68 等）。

### 2.3 实测数据摘录

offscreen，view 宽 600，行高约 18px：

| 用例 | 气泡高 | doc 高 | 内滚动条 | 备注 |
|:---|:---|:---|:---|:---|
| 单行短消息 | 44 | 26 | 无 | 基线正常 |
| 两行（截图同款文本） | 62 | 44 | 无 | 纯文本正常 |
| 图片-存在 | 194 | 176 | 有/无（时序敏感） | 无空白，滚动条偶发残留 |
| 图片-不存在 | 244 | 226 | 有（常显） | 200×200 占位=大片空白 |
| **两行文本+不存在图片** | **250** | **244** | **有（常显）** | **截图症状完整复现** |
| 20 行纯文本（doc 368>192） | 374 | 368 | 有（max=176） | 纯文本也触发残留滚动条，但无空白 |
| 10 行纯文本（doc 188<192） | 194 | 188 | 无 | 192px 阈值验证 |
| 窄→宽 / 未 show→show / 宽→窄 | 收敛正常 | — | 无 | 宽度时序假设已排除 |

### 2.4 修复方案

**修复 ①（消灭空白来源）**：`gui/panels/chat/transcript.py` `UserBubbleBlock` 图片分支加 `Path(img["path"]).exists()` 过滤，与 `gui/panels/chat/panel.py` 回放路径对齐。缺失图片直接不渲染（或降级为 `[图片已失效]` 之类的文本占位——二选一，倾向文本占位，保留"这里曾经有图"的信息，避免用户困惑）。

**修复 ②（根治滚动条残留）**：`gui/panels/chat/cards.py` `_HugHeightMixin._fit_height` 的 `setFixedHeight` 之后，强制滚动条范围重算。候选做法：

- A. `setFixedHeight` 后调用 `self.updateGeometry()` + 对文档触发一次无副作用的重排（如 `doc.setTextWidth` 重设同值不一定触发，需实测验证）；
- B. 直接校正：`self.verticalScrollBar().setRange(0, 0)` 并 `setVisible(False)` 的兜底（在 `_fit_height` 确认 `target >= doc 高` 时，滚动条本就应消失）；
- C. 更换信号源：不用 `contentsChanged`，改挂 `documentSizeChanged`，在其槽内先完成高度调整再让 Qt 算范围。

倾向先做 B 的兜底（逻辑最直接、无副作用），实施时以 mock 脚本复测确认滚动条范围归零为准；若 B 有边角问题再评估 A/C。

**注意**：修复 ② 影响整个卡片族（BodyHtml/BodyText 共用 `_fit_height`），但该修复语义是"内容不超限时滚动条不该出现"，对所有卡片都是纠偏，无回归风险方向。

### 2.5 验证方案

1. **复现脚本回归**：重跑 `.temp/probe_bubble_height*.py` 全套，确认：
   - "两行文本+不存在图片"用例：气泡高回落到文本实际高度（约 62px），无 200×200 占位，滚动条不出现；
   - "20 行纯文本"用例：滚动条范围归零；
   - "图片-存在"用例：图片正常显示，滚动条范围归零；
   - 全部纯文本基线用例高度与修复前一致（±2px 内）。
2. **视觉验证闭环**：按 `维护手册/视觉验证闭环开发指南.md`，参考 `.temp/probe_bubble/` 下既有 grab() 截图方式，对修复后各用例截帧目检。
3. **真实环境手测**：粘贴图片发送 → 删除/改名该图片文件 → 触发气泡重排（切换会话再切回），确认无巨大空白；发送 10+ 行长消息确认无气泡内滚动条。
4. 修复 ① 若采用文本占位方案，需额外确认占位文案不含可点击死链。

## 4. 风险与边界

- ⚠️ 修复 ① 的占位文案方案会改变历史气泡的呈现（缺失图从 200×200 空白变为一行文字），属预期改善，但需在验证步骤 3 中目检确认观感。
- ⚠️ 修复 ② 实施后需抽查存量卡片（工具卡、思维链卡），确认限高封顶出块内滚动条的正常场景（doc 高 > `BODY_MAX_HEIGHT`）**不受影响**——滚动条在该场景是预期行为，兜底逻辑只在"内容未超限时滚动条残留"时生效。
- 🔴 问题一的 `bottom_padding` 默认值必须保持 6，仅气泡传小值，禁止改默认值。
- 本次不处理 classic 轨的存量观感问题（独立提交）。
