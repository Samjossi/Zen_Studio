# AI 终端 tab release 后自动关闭计划

> **状态**：待实施
> **时间**：2026-08-18 11:20（UTC+8，编写）
> **起因**：ACP 反向能力落地后，agent 每条 Bash 命令开一个 `🤖` tab 且**永久残留**——`_release` 只清协议簿记、刻意留 tab（`agent_bridge.py:192` 注释「tab 保留供用户查看」，2026-08-18 晨间决策）。AI 活跃时标签栏被退出态 AI tab 淹没（用户实机截图实证），淹没用户自有终端。
> **决策**：2026-08-18 用户选定「release 后自动关闭」方案（替代"用户/AI 分区"方案——分区治标不治本，tab 只增不减的根因是只开不关）。

---

## 1. 核心判据

agent 调 `terminal/release` 的协议语义即「该终端我不再查询」——此后不会再有 `output()`/`wait_for_exit()` 请求（输出已在 release 前经尾部缓冲交付 agent，聊天区 Bash 工具卡另有留档）。**release 即关 tab 协议上无损**，执行期间 tab 照常可见、可 Ctrl+C、可手关，能力零回退。

## 2. 改动点（两文件，均小改）

### T1 面板新增公开关闭入口（`gui/panels/terminal/panel.py`）

```python
def close_agent_session(self, session_entry: _Session) -> None:
    """AI 桥 release 后自动关 tab：按会话对象定位（用户可能已手关，
    找不到即 no-op）；复用 _close_tab 既有路径（terminate 幂等 +
    session_closed 信号 + 空状态归零）。"""
```

- 在 `self._sessions` 里查 `session_entry` 索引，命中则 `_close_tab(idx)`，未命中直接返回
- 放在「公开接口」分区（`panel.py:314` 一带），供桥调用，不暴露 `_close_tab` 索引语义

### T2 桥 release 挂接自动关闭（`gui/panels/terminal/agent_bridge.py`）

- `_release`（`agent_bridge.py:192`）：簿记 pop、`_flush_waits` 之后，若 `rec.entry is not None`，`self._invoke_gui(lambda: self._panel.close_agent_session(rec.entry))` 关 tab
- 更新 `_release` docstring：删除「tab 保留供用户查看」旧语义，改为「release 即关 tab（协议语义：agent 不再查询）；执行期可视性不变」
- 更新类/模块 docstring 中「可手关 tab（等价 kill+release）」相关描述（语义不变，但 release 不再留 tab）

## 3. 边界与安全性核查（实施时逐条过）

| 场景 | 预期 |
| --- | --- |
| 正常流（create → 退出 → wait → release） | tab 在 release 时消失；输出已在 release 前交付 agent |
| kill → release | kill 只杀进程不动 tab，release 时才关（行为收敛于单一点） |
| 用户已手关 AI tab，agent 后补 release | `close_agent_session` 找不到 entry，no-op 不炸 |
| release 关 tab 触发 `session_closed` → `_on_tab_closed` | 簿记已 pop，查找落空，no-op（既有逻辑天然兼容） |
| 关闭的是当前可视 tab | `_close_tab` 既有逻辑切邻居 tab / 全关进空状态，无需特判 |
| 会话已退出再 `_close_tab` | `PtySession.terminate` 幂等，安全 |
| 用户自有「终端N」tab | 永不经 bridge 路径，不受影响 |

## 4. 非目标（本轮不做）

- agent 不调 release 的残留（连接死亡时 `on_connection_dead` 只兜底 wait，tab 仍留）——属异常路径，另行评估
- 用户/AI 标签分区 UI（已否决，见起因）
- 延迟关闭 / 设置开关（若实机观感"关得太快看不及"再加，先保持最简）
