# 菜单栏"镜像余量"消除与菜单↔面板间距重构计划

## 1. 重要发现：Qt qss 的 QMenuBar padding-top 镜像行为（已实验证实）

2026-07-20 18:10 最小实验（`padding-top` 分别取 0/6/21，`QMainWindow` + 单菜单，离屏实测）：

| padding-top | 菜单栏总高 | 文字区位置 | 文字区底→栏底余量 |
|:---|:---|:---|:---|
| 0 | 26 | 0..26 | **0** |
| 6 | 38 | 6..32 | **6** |
| 21 | 68 | 21..47 | **21** |

**规律：`QMenuBar { padding-top: Npx }` 会把 N 镜像到菜单栏底部**——菜单栏总高 = 内容高 + 2N。诊断同时证实菜单栏底（y=63）与中央容器顶（y=63）之间**不存在任何夹层/隐形状态栏**，菜单文字到卡片顶的全部空间均在菜单栏自身高度与两级边距之内。

**后果**：四边距均衡改造为"菜单文字距上缘 24px"设了 `padding-top: 21px`，底部被动鼓出 21px 镜像余量——菜单↔面板间距失控的根源。

## 2. 当前空间构成全景（实测，括号内为可调位置）

```
窗口上边缘
  ├─ 21px   QMenuBar padding-top        （base.qss QMenuBar 段）
  ├─  4px   ::item 上 padding           （base.qss QMenuBar::item padding: 4px 10px）
  ├─ 13px   菜单文字（10pt 字高）
  ├─  4px   ::item 下 padding           （同上一条）
  ├─ 21px   ★ 镜像余量（padding-top 的镜像副产品，无独立开关）
  ├─  6px   面板外边距上缘              （各面板 setContentsMargins 第 2 值）
  └─  0px   容器上边距                  （main_window.py setContentsMargins(12, 0, 12, 0)）
卡片顶（y=69）
```

## 3. 目标设计

**用户定值**：取消镜像余量，菜单栏底→卡片顶间距改为 **12px**；菜单文字距上缘 24px 保持不变。

### 3.1 方案 A（首选）：margin-top 替代 padding-top

`margin-top` 将菜单栏整体下推而**不增加自身高度**，天然无镜像：

```css
QMenuBar {
    background-color: transparent;
    margin-top: 20px;      /* 20 + ::item 上 padding 4 = 文字距上缘 24px（不变） */
    /* padding-top 删除——镜像余量随之消失 */
}
```

目标构成：

```
窗口上边缘
  ├─ 20px   margin-top（菜单栏外推，不占自身高度）
  ├─  4px   ::item 上 padding
  ├─ 13px   菜单文字
  ├─  4px   ::item 下 padding
  ├─  0px   ★ 镜像余量消除（菜单栏底 = 41px）
  ├─  6px   容器上边距（main_window.py：0 → 6）
  └─  6px   面板外边距上缘（不动）
卡片顶（y=53，菜单栏底→卡片顶 = 12px ✓）
```

- 附带收益：中央区增高 16px（69→53）。
- 模板单点修改，五主题统一生效。

### 3.2 方案 B（回退）：padding-top 保留 + 菜单栏定高截断

若实验证实 `QMainWindow` 内建布局不采纳 menubar 的 qss `margin-top`（menubar 由 `setMenuBar` 特殊管理，存在此风险）：

- 保留 `padding-top: 21px`（文字位置不变）；
- `apply_theme()` 后按 `actionGeometry` 实测项高，`menuBar().setFixedHeight(padding_top + item_height)` 强制截掉镜像余量；
- 风险：qss 样式在高度 < sizeHint 时可能垂直居中重排文字区，须像素级验证文字仍在 y=24。

## 7. 教训与防再犯（本次最重要的沉淀）

1. **QMenuBar 的 qss padding-top 会被镜像到底部**（栏总高 = 内容高 + 2N），这是 Qt 样式表对该部件的固有计算行为，无 qss 开关可单独关闭。本次"菜单↔面板间距失控"的全部根源即此——任何涉及菜单栏垂直几何的调整，都必须把"双向生效"作为第一前提。
2. **QMainWindow 特殊管理部件（menubar/statusbar/toolbar）不遵循普通布局规则**：`setMenuBar` 纳入内建布局后，qss `margin` 被完全忽略（0/20 两组实测几何不变），几何控制只剩"padding + 代码定高"一条路。对这类部件假设"和普通 widget 一样"必踩坑。
3. **隐性间距是失控之源**：镜像余量 21px 从不存在于任何一行我们写的代码里，却主导了视觉。整改原则——所有间距必须**显式、单点、可独立调参**（整改后：菜单文字位置 = padding-top 21px 单点；菜单栏底→卡片顶 = 容器 6 + 面板 6 显式链；底部 = 面板 6 + 状态栏定高 26 显式链）。隐性机制要么消除，要么注释显形。
4. **像素级取证优先于方案直觉**：本次先跑诊断脚本与 0/6/21 实验矩阵再定方案，先行实验一票否决了"看起来更干净"的 margin 方案 A——若凭直觉直接实施 A，将白改一轮且留下面板间距错位的烂摊子。涉及 Qt 几何的改动，"最小实验 → 裁定方案 → 动产品代码"应作为固定流程。
5. **三道显式防线已就位**（防后续再犯）：① `base.qss` QMenuBar 段教训注释（代码现场，改 padding 必先读到）；② 本计划 §1 实验数据表与 §7 教训（文档沉淀）；③ `main_window.py` docstring 四边距体系段写明全部间距构成与责任方（`_fit_menubar_height` / `_fit_statusbar_height` 各注释挂接本计划编号）。
