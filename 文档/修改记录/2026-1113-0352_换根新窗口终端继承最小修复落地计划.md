## 1. 背景与接续说明

用户从终端执行 `uv run main.py` 后，无参启动的是空白 IDE。打开工作区时，Zen Studio 不在原进程内换根，而是由第一个 IDE 创建绑定目标根的第二个 IDE，再在探活成功后关闭第一个 IDE。

原 `_spawn_window()` 直接调用 `subprocess.Popen(cmd)`，导致第二个 IDE 继承启动终端的 stdin/stdout/stderr 和终端会话。第一个 IDE 退出后，Shell 已显示提示符；第二个 IDE 的 DSH、提示音、通知和退出日志仍写入该终端，覆盖提示符，形成“第二个 IDE 关闭后终端不返回提示符”的假象。

真实 PTY 探针已经证明：

- 第一个 IDE 退出后，Shell 能执行命令；
- 第二个 IDE 退出后没有重新显示提示符，但 Shell 仍能执行命令；
- 本实例主进程和 Agent 均能回收；
- 直接根因是第二个 IDE 继承并污染启动终端，不是 ACP 阻塞退出。

上一轮曾同时实施 ACP 回收、Worker 等待和应用退出协调等加固。经用户讨论决定，**这些代码变更不保留，只保留文档与诊断证据**。本计划是新对话的唯一实施入口，目标是重新落地已验证的最小根因修复，不恢复上一轮扩大范围的退出重构。

## 2. 需求

1. 换根、打开新窗口和最近项目回放创建的独立 GUI，不得继续向启动终端写入迟到日志。
2. 第一个 IDE 退出后，Shell 提示符保持清晰可用；第二个 IDE 的运行和退出不得破坏提示符显示。
3. 第二个 IDE 的正常日志不得丢失，仍须写入应用统一日志文件。
4. 新 GUI 不得与启动 Shell 共用标准输入，也不得继承不必要的终端会话与信号耦合。
5. 不改变一窗一根、换根探活、工作区绑定和 ACP Agent 复用机制。
6. 不使用模拟 `Ctrl+C`、伪造提示符、`os._exit()` 或按进程名杀进程作为修复手段。

## 3. 已确认根因与边界

根因位于 `src/ide/gui/main_window.py` 的 `_spawn_window()`。该方法是以下入口的共用进程创建点：

- 空白窗口打开工作区并替换旧窗口；
- 工作区内打开另一个目录并换根；
- 在新窗口打开文件夹；
- 新建空白窗口；
- 最近项目回放创建新窗口。

原实现未设置标准流和会话参数，使生命周期更长的第二个 GUI 继续依附于启动终端。

本计划明确不修改：

- `src/ide/llm/providers/acp.py`；
- DSH 私有 Provider；
- `src/ide/gui/panels/chat/panel.py` 与聊天标签容器；
- 提示音和桌面通知模块；
- `main.py` 的退出日志与看门狗；
- 内嵌终端 PTY 生命周期。

若实施时出现新的卡死证据，应另行记录，不得借本计划恢复上一轮的大范围退出改动。

## 4. 实施方案

### 4.1 修改共用新窗口入口

在 `src/ide/gui/main_window.py` 的 `_spawn_window()` 中，保留现有开发态/打包态命令构造，仅将进程创建改为：

```python
# src/ide/gui/main_window.py
proc = subprocess.Popen(
    cmd,
    stdin=subprocess.DEVNULL,
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL,
    start_new_session=True,
)
```

参数语义：

- `stdin=DEVNULL`：避免新 GUI 或组件与启动 Shell 竞争输入；
- `stdout=DEVNULL`、`stderr=DEVNULL`：阻止新 GUI 的迟到日志覆盖 Shell 提示符；
- `start_new_session=True`：让独立 GUI 建立独立会话，切断终端前台进程组和信号的不必要耦合。

日志观测入口仍是 `config/logs/zen-studio.log`（开发态）。不得因为终端不再显示子窗口日志而删除或绕过文件日志。

### 4.2 保持现有行为

- 保留 `_spawn_window()` 返回的 `Popen` 句柄，供既有启动探活使用；
- 保留退出码 `EXIT_ROOT_OCCUPIED` 的唤活语义；
- 保留开发态与 frozen/AppImage 的命令选择逻辑；
- 保留状态栏提示、布局预写和旧窗口延迟关闭；
- 不新增依赖、设置项、进程注册表或全局终止逻辑。

至少覆盖：
