# 中栏右键菜单精简与「使用 Typora 打开」标题行按钮计划

## 1. 背景

用户提出：中栏（ViewerPanel）右键菜单疑似多余——MD 文档与代码的右键菜单不同，
且菜单项看起来都有替代入口。经代码走查确认（2026-08-06 06:4x，三轮复述校准）：

- **代码页**（`CodeViewer`，含 MD 源码模式复用页）：右键 = Qt 内建
  `createStandardContextMenu()` 标准编辑菜单；控件永久只读，实际可用项仅
  「复制」「全选」，替代入口为 Ctrl+C / Ctrl+A（Qt 内建快捷键）；
- **MD 阅览页**（`MarkdownView`，QTextBrowser）：右键 = 同款标准菜单 +
  自研一项「使用 Typora 打开」；该项在**左栏文件树右键**有完全同构入口
  （`file_explorer/actions.py:89`，共享 `default_launcher` 实例）。

用户拍板（2026-08-06 06:5x）：**不做整体移除**（"移除删除掉也是很麻烦的事情，
后面要加功能也是很麻烦"），改为：

1. 代码页与 MD 页右键菜单**都保留，精简为仅「全选」一项**；
2. MD 页**标题行新增「使用 Typora 打开」按钮**（右键中的 Typora 项随之移除）；
3. 系统未安装 Typora 时按钮**隐藏**（与右键"不显示该菜单项"语义对齐，用户拍板）。

## 2. 现状诊断

### 2.1 右键菜单现状（两处分叉）

| 页 | 文件 | 现状实现 |
|---|---|---|
| 代码页 | `code_viewer.py:64-66` | `contextMenuEvent` → `exec_standard_context_menu()`（Qt 内建标准菜单 + 透明化） |
| MD 阅览页 | `markdown_view.py:147-168` | `_build_context_menu` = `createStandardContextMenu(pos)` + 分隔线 + 「使用 Typora 打开」（仅当前为 md 且 `TyporaLauncher.is_available()` 时创建） |

两处右键框架（`contextMenuEvent` 覆盖、透明化、构建/弹出分离）均为
2026-07-20 弹出层透明化修复（0751 计划）产物，**框架保留、内容替换**即
可满足本计划，无删除负担。

### 2.2 保留「全选」而非「复制」的理由（D2 依据）

只读查看器的高频路径是「全选 → Ctrl+C 摘抄全文发 AI」。Ctrl+C 在无选区
时不起作用，「复制」项无选区时亦恒灰；「全选」无前置条件、随时可用，
是右键菜单中唯一不依赖选区状态的有效项。留它一项即可走通
「右键全选 → Ctrl+C」两步路径。

### 2.3 标题行按钮先例（D3 依据）

标题行按页显隐按钮组已有两个完全同构先例（`panel.py`）：

- 图片页 `_build_image_buttons`（◀ ▶ 实际像素 / 适应，186-204 行）；
- PDF 页 `_build_pdf_buttons`（◀ ▶ 缩放 / **外部打开**，272-296 行）——
  其「外部打开」（系统 PDF 阅读器）与本计划「使用 Typora 打开」语义同构。

另 MD 页已有 `_md_switch_box`（阅览/源码开关组，仅 MD 页可见，
206-228 行），各 `_open_*` 方法的显隐控制链已就位，Typora 按钮
并入该容器即可零新增显隐接线。

## 3. 设计决策

### D1 右键菜单精简：自建单项「全选」菜单（两页同构）

- 不再调 `createStandardContextMenu()`，改为 `QMenu` 自建单项：
  `menu.addAction("全选", self.selectAll)`；
- 仍经 `make_translucent_popup()` 透明化（popups 规约不变）；
- `MarkdownView._build_context_menu` 保留构建/弹出分离形态（返回 menu
  供探针断言），方法体替换；`CodeViewer` 菜单仅一项无变体，直接内联于
  `contextMenuEvent`（单项菜单无显隐分支，分离无断言价值，从简）；
- `code_viewer.py` 的 `from gui.popups import exec_standard_context_menu`
  改为 `from gui.popups import make_translucent_popup`；
- 效果：右键只弹一项「全选」；复制走 Ctrl+C（有选区时）；Qt 标准菜单
  的「复制链接地址」（右键恰在链接上时）随之消失——已确认可接受
  （链接左键即开，复制链接属极低频）。

### D2 保留项定夺：仅「全选」（用户拍板）

依据见 §2.2。未来加项（如「复制选中内容带行号」等）在
`_build_context_menu` / `contextMenuEvent` 内 `addAction` 即可，
扩展通道保留。

### D3 Typora 入口迁移：标题行按钮（并入 MD 开关组容器）

- `panel.py` 的 `_build_md_switch` 容器内、开关之后追加一个
  QToolButton「使用 Typora 打开」（tooltip：「在 Typora 中打开当前
  Markdown 文件」）——复用 `_md_switch_box` 的按页显隐（`_open_markdown`
  置可见、其余 `_open_*`/`_show_placeholder` 置隐藏均已在现状覆盖），
  零新增显隐接线；
- 点击 → `self.markdown_view.open_in_typora()`（D4 新增公开方法）；
  失败沿用 `typora_failed` → `_show_hint` 弱提示链（panel.py:154 接线
  不动）；
- 与 PDF 页「外部打开」按钮体验对齐（D3 先例，§2.3）。

### D4 `MarkdownView.open_in_typora()` 公开方法 + 按钮可用性隐藏

- `markdown_view.py` 新增公开方法 `open_in_typora() -> None`：守卫
  （无当前路径 / 启动器不可用则直接返回）→ `self._typora.open(
  self._current_path)` → 失败发 `typora_failed`——逻辑即现右键分支
  （163-168 行）平移，`TyporaLauncher` 构造注入与信号原样保留；
- **Typora 未安装时按钮隐藏（用户拍板）**：`_open_markdown` 上屏时按
  `self.markdown_view.typora_available`（新增只读属性，转发
  `self._typora.is_available()`）设置按钮可见性；Typora 安装状态运行期
  基本不变，打开文件时判定一次即可，不做动态监听；
- 右键菜单中的 Typora 项与分隔线随 D1 一并移除（`_build_context_menu`
  方法体整体替换）。

### D5 `gui/popups.py` 与历史文档不动

- `exec_standard_context_menu()` 及两个即用子类**保留**——聊天区
  （input/output/transcript）、终端、权限对话框仍在用，仅中栏不再引用；
- `文档/修改记录/` 历史计划属档案不回改；仅同步 `gui/README.md:111`
  表格描述与各文件头部注释（markdown_view.py 第 7 行、panel.py 第 29 行）。

## 5. 验证方案（T5，offscreen 探针）

1. **代码页右键**：`CodeViewer` 注入文本后触发 `contextMenuEvent` 路径
   （直调 `_build`/菜单构建逻辑或事件注入）→ 断言菜单恰一项、文本
   「全选」；触发后 `textCursor().hasSelection()` 且选区覆盖全文；
2. **MD 页右键**：`MarkdownView._build_context_menu(pos)` 返回菜单恰一项
   「全选」、无分隔线、无 Typora 项（含 `_current_path` 已置且假启动器
   可用时亦不得出现）；
3. **Typora 按钮显隐两态**：假 `TyporaLauncher` 注入（`is_available`
   True/False 各一例）→ `_open_markdown` 后断言按钮可见性对应
   True/False；打开非 md 文件后整组（开关 + 按钮）隐藏回归；
4. **按钮调起**：可用态点击按钮 → 假启动器 `open` 收到当前 md 路径；
   假启动器返回错误串 → `typora_failed` 信号携带该串（弱提示链不变）；
5. **回归**：文件树右键「使用 Typora 打开」（`file_explorer/actions.py`）
   零改动；聊天区右键标准菜单（`exec_standard_context_menu` 其余调用方）
   不受影响；现有查看器冒烟（若有）复跑零回归。

## 6. 风险与取舍

- ⚠️ **「复制」右键项消失的发现性成本**：无选区时复制本就不可用，
  高频路径「全选 → Ctrl+C」由保留的「全选」项兜底；纯鼠标用户（不记
  快捷键）复制片段的能力消失——已就此与用户校准，接受该取舍。
- ⚠️ **「复制链接地址」边缘项消失**：Qt 标准菜单在链接上的附带项随之
  去除；链接左键即开，影响可忽略（§1 校准结论）。
- **菜单文案改中文「全选」**：原 Qt 标准菜单随系统语言，自建菜单固定
  中文——与本应用全中文 UI 一致，无新增不一致。
- **按钮隐藏与右键"不显示"语义对齐**：未装 Typora 的用户无任何感知，
  与现状一致；已装用户获得更显性入口（标题行 vs 右键），体验净增。

## 7. 非目标

- 中栏右键菜单的**整体移除**（用户明确否决：删了再加回麻烦）；
- 聊天区 / 终端 / 文件树 / 权限对话框的右键菜单任何改动；
- `gui/popups.py` 的删除或缩减（`exec_standard_context_menu` 仍有
  多处消费方）；
- Typora 之外的"外部打开"泛化（如代码页「用系统编辑器打开」）——
  无需求，远期候选；
- 历史修改记录文档回改。
