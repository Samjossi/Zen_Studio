## 1. 目标与语义

除非用户主动关闭会话标签，否则程序关闭后下次重启，恢复上次退出时各
会话标签的**文字对话记录**（user/assistant 正文），并在对话区明确标注
其为只读历史。

语义边界（一期定论）：

- 恢复的仅 `_history` 中的文字对话；思维链、工具卡片、todo、用量徽章
  等渲染层事件**不恢复**（它们本就不入 `_history`，只上屏）。
- 恢复的消息**只上屏、不入 `_history`、不回传 provider**：全部现存
  provider 均为 ACP 系（kimi/kilocode/opencode/reasonix/dream），历史由
  agent 会话自管、每轮只发末条 user 消息；重启后 agent 侧是 `session/new`
  全新会话，界面恢复的历史对 AI 不可见，须在标注文案中如实告知。
- 「用户主动关闭」= 关到零标签或关掉某标签 → 该标签不进入下次恢复。
  实现上不靠「关闭时剔除」，而靠**保存即全量快照**：存档内容 = 保存时刻
  存活标签的集合，天然满足此语义。

## 2. 存储设计

仿 `gui/window_state.py` 的按工作区分文件范式，新建
`gui/panels/chat/session_store.py`：

- 路径：`config/sessions/<hash8>.json`（`hash8` = 工作区根 sha256 前 8
  位，与 `window_state_file_for()` 同算法）；开发态落项目内 `config/`，
  打包态经 `core/paths.py` 的 `USER_CONFIG_DIR` 自动落
  `~/.config/zen-studio/sessions/`。
- 写盘复用 `gui/settings.py` 的 `write_json_atomic`（临时文件 +
  `os.replace` 原子写）；读取仿 `load_window_state` 的防御：文件缺失 /
  JSON 损坏 / 结构非法 → 静默回退空存档，不阻断启动。
- 文件结构（TypedDict 定型，键名经常量引用，禁止裸字符串）：

```python
# gui/panels/chat/session_store.py
class SessionRecord(TypedDict):
    backend: str | None        # 标签后台（恢复时作新建注入值）
    version: str | None        # 模型别名
    history: list[Message]     # llm/base.py 的 Message，字典天然可序列化

class SessionArchive(TypedDict):
    sessions: list[SessionRecord]   # 按标签顺序，上限 MAX_TABS = 4
```

- 不存 effort（跟随既有 model_efforts 记忆表机制，重启自动恢复）；
  不存标签序号「会话 N」（恢复后按存档顺序重新编号，语义与「全关重置
  序号」一致）。
- 空历史标签（`history == []`）不入存档。

## 3. 改动点

### T1 新建存档模块（`gui/panels/chat/session_store.py`）

- `session_file_for(workspace_root) -> Path`：哈希分文件路径推导。
- `load_sessions(workspace_root) -> list[SessionRecord]`：读 + 结构防御
  （逐条校验 role/content 类型，非法条目丢弃；超 4 条截断）。
- `save_sessions(workspace_root, records) -> None`：全量覆盖写
  （原子写）；`records` 为空列表时**删除文件**（全关后退出 → 下次不
  恢复任何会话，与「主动关闭即不保留」语义闭环）。

### T2 ChatPanel 导出/重放接口（`gui/panels/chat/panel.py`）

- `export_session() -> SessionRecord | None`：`history` 为空返回 None；
  否则返回 `{"backend": 当前 ModelBar 有效后台, "version": ...,
  "history": _replayed_history + _history}`（两段拼接见文首实施修正）。
- `replay_session(record) -> None`：构造后经 ChatTabs 调用——
  逐条 `output.append_user_message(text, images)` /
  `output.append_message("AI", content)` 重放上屏，末尾追加一行系统
  分隔文案：「🕘 会话记录（ 不计入上下文 ）」（2026-08-19 用户选定，
  替代初版长句）。**不动 `_history`**，`_stream_buffer` 等运行态不触碰。
- 图片附件防御：重放时 `images` 中路径已不存在（落盘 PNG 被清理）则
  跳过该附件只显文本，不炸。

### T3 ChatTabs 保存/恢复编排（`gui/panels/chat/tabs.py`）

- `save_sessions() -> None`：收集 `_panels()` 各 `export_session()`，
  交给 `save_sessions(workspace_root, records)`。
- `restore_sessions() -> None`：`load_sessions` 非空时——先回收构造
  期自动新建的空首标签（`_close_tab(0)` 既有路径，panel 未发过消息
  直接关，无 provider 会话损失），再逐条 `add_tab()` 后
  `replay_session(record)`；首条记录注入 backend/version 恢复
  （`set_model_selection` 静默路径，阻断信号防写盘回环）。
- 存档为空 → no-op，保留自动首标签（现状行为不变）。
- 恢复的标签数 ≤ MAX_TABS，超出截断（防御手改存档）。

### T4 生命周期挂点（`gui/main_window.py`）

- 保存：`closeEvent` → `_save_layout_state()` 旁加一行
  `self.chat_tabs.save_sessions()`（窗口状态同款「关闭时一次性保存」
  挂点，面板显隐恢复逻辑不涉及）。
- 恢复：`_restore_window_state()` 末尾、`WindowStateStore.restore()`
  之后调 `self.chat_tabs.restore_sessions()`——此时 ChatTabs 构造
  完毕（含自动首标签）、布局已恢复，重放上屏立即可见。

## 4. 边界与多开

| 场景 | 预期 |
| --- | --- |
| 正常退出再启动 | 各标签文字记录按原样重放，末尾有只读标注 |
| 用户关掉某标签后退出 | 该标签不在快照中，下次不恢复 |
| 全部标签关闭后退出 | 存档文件被删除，下次启动只有自动首标签（现状） |
| 存档 JSON 损坏 / 手改结构非法 | 静默回退空存档，正常启动 |
| 空历史标签（新建未对话） | 不入存档，不恢复 |
| 恢复后继续对话 | 新消息正常入 `_history` 发送；恢复段不回传 |
| 图片附件文件已被清理 | 重放跳过附件只显文本 |
| 同工作区多开 | 各自 closeEvent 全量写同一文件，后写胜（与窗口状态同语义，文档注明即可） |
| reset_settings 重置偏好 | 不动 `config/sessions/`（与 window_state 分文件同理，天然隔离） |
| 打包态 AppImage | 读写 `~/.config/zen-studio/sessions/`，需重建 AppImage 后生效 |

## 5. 非目标（本期不做）

- agent 侧上下文续接（`session/load` / CLI resume 对接）——恢复的历史
  AI 不可见，界面上以标注文案如实告知。
- 思维链 / 工具卡片 / todo 等渲染层事件恢复（需另记事件流，复杂度另档）。
- 崩溃 / 强杀场景的会话保全：一期只在 closeEvent 保存，非正常退出丢
  本次记录（与窗口状态同约束）；`turn_finished` 轮末增量落盘列为二期
  候选。
