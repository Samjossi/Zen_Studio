## 1. 背景与目标

现状：`kimi-acp` 后端每个需审批的工具调用（默认权限模式下 Bash 必触发）都弹 `PermissionDialog`；"始终允许"仅回传 `approve_always` optionId，kimi agent 侧不记忆，下次照弹。

目标（方案 F，AI-first 定位）：

| 行为 | 现状 | 目标 |
|:---|:---|:---|
| 普通工具调用（读/写/普通 Bash） | 弹窗 | **自动放行，零弹窗** |
| 危险命令（Bash 命中黑名单） | 弹窗 | **弹窗**（唯一保留弹窗的场景，显示命中原因） |
| 目录越界 | cwd 软约束（已内建） | 软约束保留 + P2 摸底硬围栏 |
| 人操作负担 | 每次审批必点 | **零**（仅黑名单命中时看一眼） |

定位纪律：不做工具级/命令级白名单、不做会话层、不做五态按钮（细粒度控制，定位外，演进备案见选型文档 §6.1）。

## 2. 设计

### 2.1 决策流

```text
session/request_permission（reader 线程）
  → panel._ask_permission(params)
    → decide_permission(params)（纯函数，llm/permission_policy.py）
      ├─ 非 Bash 类（kind≠execute）→ "allow"
      ├─ Bash 类：extract_command_text() 提取命令文本
      │    ├─ 命中 DANGEROUS_COMMAND_PATTERNS → "ask"（附命中原因）
      │    └─ 未命中 / 提取不到文本 → "allow"（放手语义，风险见 §6）
    → "allow"：select_option_id(options, allow) 同步返回（零 GUI、零阻塞）
    → "ask"：走现有弹窗路径（QTimer.singleShot 转 GUI 线程，180s 超时按拒绝）
```

### 2.2 模块划分（AFCP 单一职责，零 Qt 依赖可单测——同 SelectionController 先例）

| 模块 | 职责 | 关键点 |
|:---|:---|:---|
| `llm/permission_policy.py`（新增） | 纯逻辑：`decide_permission()` 决策、`select_option_id()` 按 kind 选 optionId、`extract_command_text()` 提取命令、`DANGEROUS_COMMAND_PATTERNS` 常量 | 零 Qt、零 IO、零阻塞——reader 线程直接调用安全；optionId 选择优先序同 Multi_Cli_Studio `gemini_select_permission_option`（allow → `allow_always ∨ allow_once`） |
| `gui/panels/chat/panel.py`（改） | `_ask_permission` 前置决策：allow 直接返回 optionId，ask 走现有弹窗 | 自动放行路径不触碰 `threading.Event`/QTimer，弹窗路径零改动 |
| `gui/panels/chat/permission_dialog.py`（改） | 构造加可选 `danger_reason` 参数：标题行警示 + 原因展示 | 仅黑名单命中时使用；按钮三态保留（允许一次/始终允许/拒绝——危险场景用户可能需要拒） |
| `gui/settings.py` + 设置菜单（改） | `permission_auto_allow` 开关（默认开），菜单勾选即时生效 | 逃生舱：关掉即恢复逐次确认现状；沿用 `KEY_*` 常量 + `AppSettings` TypedDict 规范 |

### 2.3 危险命令黑名单（P1，初版清单，每条注明"为什么危险"）

| 模式 | 为什么危险 |
|:---|:---|
| `rm -rf /`、`rm -rf /*`、`rm -rf ~`、`rm -rf .git` | 递归强删根/家目录/版本库，不可逆 |
| `mkfs.*`、`fdisk`、`parted` | 格式化/重分区，毁盘 |
| `dd of=/dev/...`、`> /dev/sd[a-z]` | 覆写块设备 |
| `shutdown`、`reboot`、`poweroff`、`halt`、`init 0/6` | 关机重启，工作中断 |
| `:(){ :|:& };:`（fork 炸弹） | 资源耗尽，系统瘫痪 |
| `kill -9 -1`、`kill -9 1`、`pkill -9`、`killall` | 杀 init/全部进程 |
| `chmod -R 777 /`、`chown -R ... /` | 递归改根权限，系统损坏 |
| `git push --force`、`git push -f` | 不可逆覆盖远端历史（本项目仓库） |
| `passwd`、`useradd`、`userdel`、`visudo` | 系统账户变更 |
| `systemctl stop/disable`、`iptables -F`、`ufw disable` | 断服务/清防火墙 |
| `curl ... \| sh`、`wget ... \| bash` | 管道执行远程脚本，供应链风险 |
| 写操作指向 `/etc/`、`/usr/`、`/boot/`、`~/.ssh` | 越出项目目录（与护栏一呼应，best-effort） |

匹配纪律：命令文本归一化（压缩空白、小写）后正则粗匹配；**失败方向安全**——漏匹配→不弹（接受的残余风险），误匹配→弹一次窗（人看一眼）。

## 5. 验证标准

| 项 | 标准 |
|:---|:---|
| 单测（`.temp/` 脚本） | 伪造 `PermissionParams`：普通命令（`ls`、`git status`）→ allow 且 optionId 正确；危险命令（`rm -rf /`、`git push -f`）→ ask 且原因正确；options 缺 `allow_always` 时回落 `allow_once`；options 为空 → None；非 Bash 工具（Write/Read）→ allow |
| 真实链路走查 | kimi-acp 发问让 agent 跑 `ls`——**不弹窗**，命令执行；诱导危险命令——**弹窗且显示原因**，允许/拒绝行为正确；拒绝后 agent 收到否定并调整 |
| 开关 | 菜单取消勾选→恢复逐次确认（现状行为）；重新勾选→自动放行；重启后状态持久化 |
| 线程纪律 | 自动放行路径无 GUI 调用（代码走查 + 走查期无卡死/无 agent 挂起） |
| 回归 | kimi-cli 后端发问正常（零改动）；审批超时兜底保留（黑名单弹窗 180s 无响应按拒绝）；进程崩溃重启不受影响 |
| 合规 | py_compile 全过；ast 函数 ≤50 行/嵌套 ≤3 层；黑名单常量化（AFCP 3.4） |
