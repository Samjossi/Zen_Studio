# 过滤网关聚合模型计划

## 1. 目标与决策

### 1.1 目标

ModelBar 三级菜单只列出**已认证直连 provider** 的模型，剔除两家
agent 官方网关聚合的模型目录：

- Kilo Code：剔除 `kilo/` 前缀（Kilo Gateway 聚合，用户不使用）——
  294 项 → 14 项，菜单加载与浏览负担大幅减轻。
- OpenCode：剔除 `opencode/` 前缀（OpenCode Zen 官方模型）——
  15 项 → 8 项，同类问题一并修复。

### 1.2 决策

| # | 决策点 | 选定 | 理由 |
|---|---|---|---|
| D1 | 过滤位置 | **provider 私有 list_models 内过滤** | 模型目录挂接口级（D6 红线 1），各 provider 各自解析各自过滤，公共层零改动 |
| D2 | 过滤范围 | **仅枚举层**，set_model 不校验 | 别名不透明透传（D6 红线 2）：持久化设置中已存的网关别名仍可直通生效，过滤只是菜单呈现策略 |
| D3 | 前缀写法 | 模块级常量 `GATEWAY_MODEL_PREFIX`（`"kilo/"` / `"opencode/"`） | 单点声明、docstring 记录语义，未来如需放行为单点改动 |
| D4 | 空列表兜底 | 沿用现语义：空列表 → agent 默认模型 | 仅认证网关、无直连 provider 的用户菜单为空，对话功能不受影响 |

**不做的事**：不引入「显示/隐藏网关模型」设置项（YAGNI，用户明确
不使用）；不动 ACP session/new 的 configOptions（agent 默认模型不受
过滤影响）；不做菜单搜索/折叠（过滤后 14/8 项已无此需求）。

## 2. 实测记录（2026-07-30 本机）

### 2.1 kilo models（7.4.17）

| 前缀 | 数量 | 性质 |
|---|---|---|
| `kilo/` | 280 | Kilo Gateway 聚合目录（含全部 `kilo/~anthropic/...` 别名行） |
| `zai-coding-plan/` | 6 | 已认证直连 |
| `deepseek/` | 4 | 已认证直连 |
| `kimi-for-coding/` | 4 | 已认证直连 |

过滤后 14 项；`~` 别名行全部位于 `kilo/` 下，随前缀过滤一并剔除，
无需特判。

### 2.2 opencode models

| 前缀 | 数量 | 性质 |
|---|---|---|
| `opencode/` | 7 | OpenCode Zen 官方模型（`big-pickle` 等） |
| `deepseek/` | 4 | 已认证直连 |
| `kimi-for-coding/` | 4 | 已认证直连 |

过滤后 8 项。

### 2.3 边界情形实测结论

- **opencode agent 默认模型是 `opencode/big-pickle`**（Zen 模型）：
  过滤后菜单不含它，但用户不选模型时 provider 沿用 agent 默认
  （configOptions currentValue），对话不受过滤影响——过滤仅作用于
  枚举呈现层（D2）。
- **持久化兼容**：settings 中已存的 `kilo/...` / `opencode/...` 别名
  经 set_model 原样透传仍生效（不校验），仅不再出现在菜单中；
  用户改选直连模型后持久化值自然更新。
- **仅网关用户**：无任何直连 provider 时过滤结果为空列表 →
  ModelBar 三级为空、用 agent 默认模型（与「未登录」兜底语义一致）。

## 3. 改造方案

### 3.1 `llm/providers/kilocode_acp.py`

- 模块级新增常量：`GATEWAY_MODEL_PREFIX = "kilo/"`（Kilo Gateway
  聚合目录前缀，用户不使用，菜单剔除；仅影响枚举呈现，set_model
  不透传校验，D6 红线 2 不破）。
- `list_kilocode_models()` 解析段追加一行过滤：
  `[m for m in lines if not m.startswith(GATEWAY_MODEL_PREFIX)]`。
- 模块 docstring 差异清单第 2 条同步改写：294 项目录改为「枚举时
  剔除 `kilo/` 网关前缀（280 项），仅呈现直连 provider（本机 14 项）」；
  `~` 别名行「不特判」叙述改为「全部位于 `kilo/` 下随前缀一并剔除」。

### 3.2 `llm/providers/opencode_acp.py`

- 同构改动：`GATEWAY_MODEL_PREFIX = "opencode/"` + list 解析段过滤。
- docstring 差异清单第 1 条补充过滤语义与边界说明（agent 默认
  big-pickle 为 Zen 模型，不受菜单过滤影响，§2.3）。

## 5. 验收标准

1. `list_kilocode_models()` 返回均不含 `kilo/` 前缀（本机 14 项）；
   `list_opencode_models()` 均不含 `opencode/` 前缀（本机 8 项）。
2. ModelBar 两后台三级菜单项数与上一致，打开耗时显著下降。
3. 已存网关别名的 settings 回读、对话不回归（D2 透传语义）。
4. 两烟测全过；全库 grep 确认过滤逻辑未泄漏进公共层。

## 6. 风险与回归点

- **用户日后想用网关模型**：需改常量或加设置项——本期 YAGNI，
  计划中明示取舍（§1.2 D3 单点声明，改动成本一行）。
- **kilo 直连 provider 增加**：新认证 provider 自动出现在菜单
  （非 `kilo/` 前缀即保留），无需维护白名单——前缀黑名单而非
  白名单正是为此选择。
- **opencode 默认模型不可见于菜单**：用户首次打开菜单看不到当前
  生效的 big-pickle，可能困惑——docstring 与计划明示（§2.3），
  UI 不提示（零改动红线）；用户改选任意直连模型后该状态即消除。
