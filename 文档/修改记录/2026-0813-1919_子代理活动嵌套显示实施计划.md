# 子代理活动嵌套显示实施计划（reasonix 协议线 + kimi 旁路线）

> **状态**：已实施（2026-08-13）。合成验证全绿：37/37 断言通过、嵌套截图 40/41/42 达标入档（`文档/帧存档/`）、既有场景 03 与回归测试无变化。遗留：真机复测（reasonix 与 kimi 各跑一次含子代理的轮次人工确认）待用户在 GUI 中执行。
> **范围**：`llm/base.py`、`llm/providers/acp.py`、`llm/providers/kimi_acp.py`、`gui/panels/chat/cards.py`、`gui/panels/chat/transcript.py`、`gui/panels/chat/panel.py`、`scripts/`、`文档/帧存档/`
> **时间**：2026-08-13 19:19 (UTC+8)
> **优先级**：高

## 1. 背景

需求：主代理调用子代理（Agent/task 工具）时 GUI 只显示一张卡片，子代理内部
活动不可见。目标形态：子代理活动实时透出，**复用现有工具卡片**，嵌在
SubagentCard 内部区域并标记归属，两级封顶（agent 侧已限制一层委派）。

前置实测（`2026-0813-1909_子代理内部事件ACP协议实测报告.md`）确立的事实：

- **reasonix**：协议原生下发子代理内部 tool_call/tool_call_update 帧，父子关系
  编码于层级 toolCallId（`父ID/子ID`），纯渲染层 + 轻量协议映射即可实现。
- **kimi**：ACP 通道仅起止；但会话落盘 `agents/<子代理名>/wire.jsonl` 完整记录
  子代理 tool.call/tool.result/think 且轮次内增量写盘，旁路可挖（与既有轮次内
  用量轮询同机制）。
- **kilocode**：仅起止，无协议内解，维持现状（本计划不含）。
- 渲染层复用条件已具备：卡片组件自包含（色袋 + 开合 Map + 载荷 dict），
  `apply_update` 纯方法驱动，已有 offscreen 独立复用先例
  （`scripts/shot_tool_cards.py`）。

## 2. 目标与非目标

### 2.1 目标

1. reasonix 后端：子代理内部工具调用以嵌套卡片实时显示在父 SubagentCard 内。
2. kimi 后端：经 wire.jsonl 旁路达到同等显示效果（尽力而为，失败静默回退现状）。
3. GUI 只消费**一种**嵌套事件形态（带父指针的载荷），数据来源差异封闭在协议层。

### 2.2 非目标

- kilocode / opencode / dream 的子代理显示（无协议内数据源，挂起）。
- 多层（≥3 级）嵌套渲染——agent 侧一层委派封顶，只处理两级。
- 子代理内 QuestionCard 交互（子代理提问场景罕见，见 §7 风险 R3）。
- dream-acp 协议文档变更（本计划不新增线协议内容；kimi 旁路是客户端私有行为）。

## 3. 总体设计

### 3.1 统一抽象：父指针载荷

在 `llm/base.py` 的 `ToolCallPayload` / `ToolUpdatePayload` 各加一个可选键
`parent_tool_call_id: str`。语义：该帧属于某个子代理的内部活动，应渲染进
`parent_tool_call_id` 对应卡片的内嵌区域，而非主流平铺。GUI 只认这个键，
不关心它来自层级 ID 解析还是 wire 合成。

### 3.2 两个数据源适配器（协议层封闭差异）

- **reasonix 适配器**（`llm/providers/acp.py` 公共映射内）：`_map_tool_call` /
  `_map_tool_call_update` 检测 toolCallId 含 `/` 时拆段——末段为本人 ID、
  首段为父 ID，载荷写入 `parent_tool_call_id`，toolCallId 保留全串（唯一性）。
  纯字符串判定，对无层级 ID 的后端（kimi/kilocode/dream）零影响。
- **kimi 旁路适配器**（`llm/providers/kimi_acp.py`）：轮次内发现
  `agents/<子代理名>/wire.jsonl`，增量解析 `context.append_loop_event` 的
  tool.call/tool.result，**合成与 reasonix 形态一致的 Chunk**（tool_kind 按
  wire 工具名映射：Bash→execute、Edit/Write→edit、Read/Glob/Grep→read 等，
  复用现有工具名→kind 约定）。合成帧携带 `parent_tool_call_id`（= 在途
  Agent 调用的 toolCallId）。

### 3.3 渲染层单一路径

`SubagentCard` 增加内嵌子卡片容器：自有 `_tool_cards` 簿记 + 两个 append 方法
（仿 `gui/panels/chat/transcript.py` 的 30 行模式），复用 `make_tool_card`
工厂与 `apply_update`。容器独立 `OpenStateMap` 实例（避免与主流开合记忆串扰）。
父卡完成/失败的最终状态流转不变；子卡片区随父卡折叠一起显隐（复用
CollapsibleCard 既有 body 机制，子卡片区作为 body 内一个 section）。

### 3.4 数据流（两条线汇合后）

```
reasonix: ACP 层级 ID 帧 ──map_session_update──┐
                                               ├→ Chunk(parent_tool_call_id=…)
kimi:    wire.jsonl 增量 ──合成适配器(旁路)──────┘         │
                          ChatPanel._on_activity_chunk 路由 │
              ┌── 无父指针：走现状 append_tool_call（主流平铺）
              └── 有父指针：按 ID 找父 SubagentCard → 父卡内嵌容器 append
                          （父卡不存在 → 降级平铺主流，容错不丢帧）
```

## 4. 任务分解

### T1 载荷契约扩展 + reasonix 层级 ID 解析

- `llm/base.py`：`ToolCallPayload` / `ToolUpdatePayload` 加可选键
  `parent_tool_call_id`（TypedDict total=False，纯声明）。
- `llm/providers/acp.py`：`_map_tool_call` / `_map_tool_call_update` 拆 `/` 段。
  注意现有 `is_subagent` 标记（kind=think）不动；层级 ID 解析与后端无关，
  谁发层级 ID 谁生效。
- 单测：reasonix 实测帧（`文档/帧存档/subagent_probe_reasonix_20260813_190102.json`
  中的 toolCallId 样本）驱动的映射断言。

### T2 SubagentCard 内嵌子卡片容器

- `gui/panels/chat/cards.py` `SubagentCard`：
  - body 增设「子代理活动」区（初态隐藏，首个子帧到达时现身），内部
    `QVBoxLayout` 承载子卡片；
  - 自有 `_tool_cards: dict[str, ToolCard]` + `append_child_call(payload)` /
    `append_child_update(payload)`，内部调 `make_tool_card` + `apply_update`；
  - 高度策略：子卡片区整体超上限（对齐 `BODY_MAX_HEIGHT` 量级）出块内滚动，
    不撑爆父卡；
  - 父卡 completed 后子卡片区只读定格（迟到子帧仍幂等回填，不新建）。
- 不改动其他卡片类；`make_tool_card` 工厂签名不动。

### T3 路由改造（主流 → 父卡内嵌）

- `gui/panels/chat/transcript.py`：`append_tool_call` / `append_tool_update`
  开头判 `parent_tool_call_id`——有则查 `_tool_cards` 找父卡，委派父卡
  内嵌方法；父卡缺失降级走现状平铺（防丢帧）。
- `gui/panels/chat/panel.py` `_on_activity_chunk`：确认 `_allow_progress_frame`
  闸门对带父指针的 in_progress 帧不误杀（嵌套子帧的节流语义与主流一致即可，
  必要时闸门簿记键改为含父前缀的全串）。
- 容错矩阵：子帧先到父卡未建（理论乱序）→ 暂存或平铺；父卡已完成子帧迟到 →
  幂等回填不新建。

### T4 kimi wire 旁路适配器

- `llm/providers/kimi_acp.py`：
  - **目录发现**：轮次内 Agent 调用在途期间，监听 `_session_dir_of` 所得
    会话目录 `agents/` 下新增子目录（`agent-N` 形态），与在途 Agent
    toolCallId 建立关联（单在途假设：同一时刻一个子代理，两级封顶下成立；
    多在途时按目录创建时序先到先得，关联不上则放弃该路降级）。
  - **增量解析**：按字节偏移增量读 wire 尾部（沿用 `_WIRE_TAIL_BYTES`
    窗口防大文件全量读），解析 `context.append_loop_event`：
    tool.call → 合成 tool_call Chunk（title=工具名、tool_kind 按名映射、
    rawInput 提取 command/diff/input_detail 复用协议层既有提取函数）；
    tool.result → 合成 tool_call_update Chunk（completed + output）。
    content.part(think) v1 跳过（子代理思维链不进卡，见 §7 R4）。
  - **合流**：旁路在独立线程跑，合成 Chunk 经队列注入
    `_iter_turn_chunks` 消费循环（与 conn.next_update 双源汇合；注意
    next_update 阻塞语义，需改为带超时的轮询汇合），轮次结束/进程死亡即停。
  - **降级**：目录发现失败、wire 缺失/格式漂移（json 解析失败率超阈值）
    → 静默关闭旁路，行为回退现状（仅起止 + 成果摘要）。
- 设置项：`config/settings.json` 加开关（默认开，可关回纯 ACP 行为）。

### T5 可视化验证 + 帧证据制度化

- 遵循 `维护手册/视觉验证闭环开发指南.md` 闭环：mock 帧走真实链路
  （map_session_update → 路由闸门 → make_tool_card + apply_update）→
  offscreen `grab()` 截图 → 读图确认。
- `scripts/shot_tool_cards.py` 扩充嵌套场景 mock：reasonix 实测帧序列
  （`文档/帧存档/subagent_probe_reasonix_20260813_190102.json`）作蓝本，
  产出「父卡 + 6 张嵌套子卡」运行中/完成两态截图，归档 `文档/帧存档/`。
- kimi 旁路单测：以实测 `agents/agent-0/wire.jsonl` 样本（拷贝入
  `.temp/` 脱敏）驱动解析器，断言合成 Chunk 序列形态。
- 真机复测：reasonix 与 kimi 各跑一次 `scripts/probe_subagent_frames.py`
  同款 prompt，人工确认 GUI 嵌套显示正确。

### T6 文档同步

- `AGENTS.md`、受影响目录 `README.md`（如 `llm/`、`gui/panels/chat/`）按
  实际改动同步；kimi 旁路机制补入 `维护手册/后端CLI工具维护说明手册.md`
  （私有通道无契约，须登记格式假设与失效排查路径）。

## 5. 实施顺序与依赖

```
T1（契约+解析）→ T2（父卡容器）→ T3（路由）→ T5（验证）
                              ↘ T4（kimi 旁路，可并行）↗
T6 收尾
```

- reasonix 线（T1+T2+T3）是纯客户端改动，先行落地即可用；
- T4 与 T2/T3 解耦（合成同一种 Chunk），可并行开发；
- 每 T 完成即过对应验证，不攒批。

## 6. 验证标准

- reasonix：真机轮次中子代理 6 个内部调用全部以嵌套卡实时出现，父子归属
  正确，父卡完成后摘要与现状一致；主流其他工具卡行为零回归。
- kimi：旁路生效时嵌套卡内容与 wire 记录一致（工具名/入参/回执）；
  旁路关闭或失效时行为与现状逐像素一致。
- 既有卡片防回归 mock（`scripts/` 下既有断言）全绿。

## 7. 风险与对策

| 编号 | 风险 | 等级 | 对策 |
|:---|:---|:---|:---|
| R1 | kimi wire 是私有格式，CLI 升级可能漂移 | 🟡 | 解析失败率阈值熔断 + 设置项开关 + 维护手册登记格式假设（T6） |
| R2 | 多在途子代理（AgentSwarm）下 wire 目录与 toolCallId 关联错配 | 🟡 | v1 单在途假设 + 关联不上即降级；多在途支持留作后续迭代 |
| R3 | 子代理内出现 AskUserQuestion 卡，嵌套复用触发全局注册表串扰（`cards.py` `_QUESTION_CARD_REGISTRY` 单例语义） | 🟡 | v1 子问题卡不嵌套（按文本兜底显示）；交互化留待后续 |
| R4 | 子代理思维链（think）信息量大，嵌套显示噪音 | 🟢 | v1 跳过 think，只渲染工具调用；后续可按需加思维链卡 |
| R5 | `_allow_progress_frame` 闸门误杀嵌套 in_progress 帧 | 🟢 | T3 显式处理并加断言 |
| R6 | 嵌套卡片高度撑爆对话区 | 🟢 | 块内滚动上限（T2），截图验证（T5） |
