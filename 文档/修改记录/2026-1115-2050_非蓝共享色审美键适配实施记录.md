## 1. 改动内容

1. **语法七审美键按主题色相适配**（§5.1 表，wheat/sky/mint；cloud 全基线不动）：Namespace/Builtin 紫、Function 品紫、Decorator 橄榄、String 绿、Number 赭、Comment 灰、Operator 近黑全部随主题族转色（暖米转暖紫/玫/橄榄绿，晴空转深紫/蓝绿，薄荷深化贴 accent 族）。Token.Error 红为语义色不动（仅大写归一小写）。
2. **六包八灰键冷暖跟随**（§5.2 表）：chrome 行号对、chat reasoning_fg/tool_fg/user_bubble_bg/tool_output_bg、git_status ignored、git_graph hash_fg。语义/功能色四主题同值不动：终端 ANSI 16 色（含 find_bg/find_cur）、git_status 状态三键、git_graph 徽标四色、chat diff_* 四键与 timeline_tool_fg/usage_hot_fg/tool_error_fg（既有断言守护，见 §2）。
3. **D6 预解耦**：chrome 包新增 `code_bg` 键（四主题统一 `#f5f5f5`，即适配前基线观感），`markdown_view.py` 行内代码/代码块/表头底由借用 `line_number_bg` 改取 `code_bg`——否则行号栏随主题染色会连带染色 md 代码底（姊妹项目漏掉此点、被迫单立 1255 回改计划的实证坑，本计划在计划层拍板同步做掉）。`ChromePack` TypedDict 同步加键。
4. **大写色值归一小写**：四主题 syntax 的 `#7A3DB8`/`#007A1C`/`#A0522D`/`#CC0000` → 小写（Qt HTML 导出色值归一小写，大写使「包值 in html」型断言假阴性——姊妹项目经验）。同色同值，零观感变化。
5. **测试拆分**（`tests/test_theme.py`）：
   - 旧「非蓝键 = 旧共享基线」断言拆为 `_MAINTAINED_KEYS`（维持集，对基线逐值相等）+ `_THEME_ADAPTED`（四主题逐值锁定表，同蓝键表构）；
   - 新增每包「维持 ∪ 适配 ∪ 蓝 = 全键」分区等式断言（拆分漏键的结构性拦截）；
   - 新增 §5.3 对比度机器断言（QColor 相对亮度公式）：正文级键白底 ≥ 4.5、弱层级键 ≥ cloud 同键现状、行号对按各自底成对 ≥ cloud 现状对；

## 3. 为什么做（适配动机）

去共享化（1643 计划）把六包物理拆进四主题，但非蓝键仍全保持旧共享基线——暖米主题的代码字符串仍是鲜绿 `#007a1c`、命名空间仍紫 `#7a3db8`，与米黄窗口同框刺眼；wheat 的注释灰、气泡底是冷灰，与暖族底色不同温。用户拍板选项 3「仅审美键」口径：语法审美键全量按主题色相适配、中性灰冷暖跟随主题；语义/功能色（终端/git 状态/diff/徽标）一律不动。共享色迁移时只做了机械搬运、未随主题色相适配，本记录补齐这一层。
