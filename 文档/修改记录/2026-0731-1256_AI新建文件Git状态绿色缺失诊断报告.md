# AI 新建文件 Git 状态绿色缺失诊断报告

## 1. 问题现象

IDE 持续运行期间，AI（OpenCode / KiloCode ACP 子进程）新建的文件
在文件树中**出现但不着绿色**，其父目录链也**不变绿色**；
变更面板「已变更」计数同样不更新。窗口切换一次（或视图菜单手动
刷新）后颜色恢复正常。

## 2. 着色链路全环梳理

Git 状态绿色（untracked）从数据到上屏共五环：

| 环 | 位置 | 职责 |
|---|---|---|
| ① 数据采集 | `core/git/status.py` `fetch_status_map()` | `git status --porcelain --untracked-files=all` → 状态映射 |
| ② 服务缓存 | `core/git/service.py` `GitStatusService.refresh()` | 缓存 `_status` / `_dir_status`（目录冒泡聚合）/ `_collapsed_keys` |
| ③ 查询接口 | `service.py` `status_of()` / `status_of_dir()` | 绝对路径 → 相对路径 → 查表 |
| ④ 渲染代理 | `gui/panels/file_explorer/model.py` `GitStatusProxyModel.data()` | ForegroundRole 按状态查主题色 |
| ⑤ 触发编排 | `gui/controllers.py` `GitStatusController.refresh()` | 唯一调用 `service.refresh()` 的入口 |

## 3. 诊断方法与实证记录

### 3.1 脚本探针（数据层无嫌疑）

项目 venv 直跑 `GitStatusService`（root 指向本仓库）：

```
svc.refresh() 后：
  新文件 status_of          → untracked   ✓
  新目录 status_of_dir      → untracked   ✓（目录冒泡正常）
  子目录 status_of_dir      → untracked   ✓
refresh 之后再建新文件：
  缓存外文件 status_of      → None        ✗（复现无绿色）
  再次 refresh()            → untracked   ✓
```

**结论**：环 ①②③④ 全部正常；问题只可能是环 ⑤——
**缓存没有随 AI 写盘而刷新**。

## 4. 诊断结论：断点在「触发层」，不在「数据/渲染层」

`GitStatusController` 的刷新触发源只有三处（`gui/controllers.py`
与 `gui/main_window.py:changeEvent`）：

1. **窗口激活**（`ActivationChange` → `schedule_refresh()`）——
   兜底终端 checkout 等外部 git 操作；
2. **查看器外部重载信号**（`viewer_panel.externally_reloaded`
   → 去抖）——仅覆盖"已打开文件被外部改写"；
3. **视图菜单手动刷新**。

AI 写文件的链路是：聊天面板 → ACP 子进程（`opencode acp` /
`kilocode acp`，`llm/providers/*_acp.py`）→ **子进程直接写磁盘**。
此时 IDE 窗口保持焦点（无激活事件）、查看器未打开该文件
（无重载信号）、无人点菜单——**三个触发源无一命中**，
`service.refresh()` 不被调用，`_status`/`_dir_status` 缓存保持
旧值，新文件 `status_of()` 返回 `None`，环 ④ 拿不到颜色。

**不对称的关键**：文件树有两套互相独立的"监视"——
`QFileSystemModel`（始终监视磁盘，新文件**结构**即时上树）与
`GitStatusService`（纯事件驱动，无文件监视，**状态**滞后）。
AI 新建文件后"看得见、没颜色"，正是两套系统刷新节奏脱节的
外在表现。变更面板、查看器徽标、状态栏统计同属一份缓存，
一并滞后。

## 5. 修复方向建议（本次仅诊断，未实施）

- **方案 A（治本，推荐）**：AI 侧补事件源。ACP 一轮对话结束
  （或检测到写盘工具调用完成）时，聊天面板发信号 →
  `git_controller.schedule_refresh()`（复用 300ms 去抖）。
  精准、零浪费，但只覆盖 AI 路径。
- **方案 B（兜底，推荐与 A 组合）**：利用 `QFileSystemModel`
  现成的结构变更信号（`rowsInserted` / `directoryLoaded` /
  `fileRenamed`）汇流进同一去抖 → `schedule_refresh()`。
  通用覆盖一切外部写盘（含终端 `touch`、其他编辑器），
  天然去抖合并。
- **方案 C（重，不推荐）**：自挂 `QFileSystemWatcher` 监听仓库
  `.git/index` 与工作区——与 QFileSystemModel 监视重复，
  目录多时句柄开销大。

A+B 组合后，"AI 新建文件无绿色"与更广义的"外部写盘状态滞后"
同时闭合。
