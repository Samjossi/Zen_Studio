# 面板 UI 构建代码方法级拆分计划

## 1. 背景与目标

`TerminalPanel.__init__`（约 95 行）与 `ChatPanel.__init__`（约 40 行）将控件创建、样式设置、布局装配、信号接线混在一处，阅读与 AI 局部编辑时需穿越大量无关代码。

**目标**：在**不改变任何运行时行为**的前提下，将 `__init__` 按职责拆分为 `_build_*` 私有方法，使 `__init__` 成为结构目录。

**明确不做**（已论证为负收益或不适合本项目）：

- ❌ 不引入 Qt Designer / `.ui` 文件
- ❌ 不拆分独立的 ui 文件/类（uic 风格）
- ❌ 不改动 `ViewerPanel`（`__init__` 仅约 30 行，拆了反而碎）
- ❌ 不改动 `main_window.py`（已有 `_build_menus`，剩余装配代码量少）
- ❌ 不调整任何布局结构、尺寸、样式、信号连接关系

## 2. 拆分方案

### 2.1 `gui/panels/terminal/panel.py`

| 方法 | 收纳内容 |
|:---|:---|
| `__init__` | 状态字段初始化 + 按序调用下列方法 + 首启延迟逻辑（`_pending_start`、事件过滤器安装） |
| `_build_header()` | tab 区（`QTabBar` 及属性）、`+` 按钮（含字号计算）、状态标签、清屏按钮、头部栏 `QHBoxLayout` 装配、`_lock_header_height()` 调用 |
| `_build_terminal_area()` | `TerminalWidget` 创建、占位文案、面板主 `QVBoxLayout` 装配（header + terminal） |
| `_build_find_bar()` | 查找浮层整体（`QFrame` + 输入框 + 三个按钮 + `find_row` 布局 + 初始隐藏） |
| `_connect_signals()` | 跨组件信号集中接线：tab 切换/关闭、新建、清屏、`terminal.context_menu_requested` / `find_requested`、查找输入框 `textChanged` |

**例外约定**：查找浮层内部三个按钮（`btn_prev`/`btn_next`/`btn_close`）为局部变量且信号自闭环，其 `connect` 保留在 `_build_find_bar()` 内，不上收。

### 2.2 `gui/panels/chat/panel.py`

| 方法 | 收纳内容 |
|:---|:---|
| `__init__` | 状态字段初始化 + 子组件创建（`ChatOutput`/`ChatInput`/`ModelBar`）+ 后端同步（`_llm_name`、`_sync_backend_model`）+ 按序调用下列方法 |
| `_build_layout()` | 输入区容器（model_bar + input）、垂直 `QSplitter`、面板主 `QVBoxLayout` 装配 |
| `_connect_signals()` | `send_requested`、`selection_changed`、`stop_requested`、`_wire_permission_handler()` 调用 |

## 4. 验证方式

纯重构，无行为变更，验证以"能起来、接线不断"为准：

1. **编译检查**：`.venv/bin/python -m py_compile` 两个目标文件
2. **离屏实例化冒烟**：`QT_QPA_PLATFORM=offscreen` 下实例化 `MainWindow`，断言关键控件存在且信号已连接（tab 区、查找浮层初始隐藏、聊天面板 splitter 子件数量）
3. **人工确认**：用户实际运行 `main.py`，确认终端首启 spawn、查找浮层（Ctrl+F 或右键入口）、聊天发送、分隔栏持久化表现与重构前一致
