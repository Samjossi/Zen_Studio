> **时间**：2026-11-22 19:33（设计，UTC+8），2026-11-22 19:44（修订采样节拍）
> **优先级**：高
> **依据**：用户确认将只读轮内计量恢复到当前极简重写；`2026-1120-1023_Kimi上下文用量徽章轮内刷新与迟到通知修复落地计划.md`、`2026-1122-1847_Kimi提供商极简重写落地计划.md`、`2026-1122-1904_Kimi提供商极简重写实施记录.md`

> **最高优先级安全红线：本功能的轮询与补采路径只准只读 `session_index.jsonl` 和 `wire.jsonl`，严禁触碰 ACP 队列。**

## 1. 背景与目标

### 1.1 问题

极简重写删除私有 `wire.jsonl` 用量通道后，Kimi 只在官方 ACP 主链路收到 `usage_update` 时更新上下文用量徽章。真实长任务中，首轮可持续十分钟以上，期间即使已发生多次模型调用并消耗大量 Token，徽章仍可能一直显示 `—`，直到轮末才出现百分比。

历史调查已确认：Kimi 官方 `usage_update` 的发送时机不能满足轮内刷新需求；旧实现之所以能在长任务中更新，是因为额外读取了 `agents/main/wire.jsonl` 中已经落盘的真实计量。

### 1.2 目标

1. 在现行极简 provider 上恢复轮内真实上下文水位：有效计量落盘后，Kimi 4 秒采样节拍内刷新徽章，不再普遍等待整轮结束。
2. 只读取会话索引、模型目录和 `wire.jsonl`，不读取或修改 ACP 队列，不发送任何额外 ACP 请求，不改变 Kimi 子进程生命周期。
3. 保持“`session/prompt` 响应即终态”：不恢复终态确认、轮末 drain、同步提示、待发闸门或 `session/close` 停止分流。
4. 无真实数据时继续显示 `—`，不按输出字符数、时间或 Token 消耗插值伪造上下文百分比；已有有效值不得被空轮询、坏行或文件瞬逝清掉。
5. 轮询异常只影响用量展示，不得改变正文、工具卡、审批、停止、断连恢复及多标签会话行为。

### 1.3 成功判定

必须同时满足：

- 自动化覆盖增量读取、残行、大工具输出、失败重试、会话隔离及并发读写，全部通过；
- 真实 Kimi 长开发任务中，首个有效计量落盘前显示 `—`，落盘后 4 秒采样节拍内出现真实百分比，后续计量继续更新；
- 活跃轮次中调用 `poll_usage()` 不调用 `next_update()`、`purge_updates()`、`request()`、`cancel_turn()`、`abort_turn()` 或 `terminate()`；
- `post_turn_usage_grace_s` 保持 `0.0`，响应到达仍立即收尾，原有极简轮次契约测试继续通过；
- 完整门禁通过，真实停止、断连恢复与多标签矩阵无回归；
- 现行文档不再把“不读取私有 wire 判断轮次终态”误写成“完全不读取 wire”，也不再描述已删除的轮末用量回收机制。

### 1.4 明确不做

- 不恢复 `turn_state.py`、私有终态判断、`_confirm_turn_end`、drain、`status` 同步块或 `_turn_pending`；
- **严禁为徽章读取或修改 ACP 队列**：不恢复空闲队列回收、response 后 3 秒收集、轮后 10 秒宽限或下一轮 purge 前回收，也不得以其他函数名变相实现；
- 不恢复子代理 wire 旁路、轮末输出速度、Token 累计消耗或热力图采集；
- 不用 `llm.request.maxTokens` 充当上下文窗口，不新增静态模型窗口表；
- 不修改 `src/ide/gui/panels/chat/panel.py` 的计时器、徽章文本、tooltip 或布局；
- 不修改 `src/ide/llm/providers/acp/`、DSH/Local provider、公共 `UsageStats` 字段或模型缓存通用语义；
- 不复制、改写、移动或删除 Kimi 在用户目录中的任何会话文件。

迟到官方 `usage_update` 的轮后回收、Token 热力图和子代理展示若需恢复，必须分别独立评估，不得夹带入本计划。

### 3.2 单向数据流

```text
# 数据流（逻辑示意）
Kimi CLI 追加 session_index.jsonl / wire.jsonl
                  │
                  ▼（只读，无 AcpConnection 参数）
KimiAcpLLM.poll_usage() → UsagePoller.poll() → UsageStats(source="transcript")
                  │
                  ▼
现有 ChatPanel 2 秒 QTimer → Kimi 4 秒采样节流 → 上下文用量徽章
```

该数据流没有指向 ACP 连接、轮次状态机或子进程控制面的反向边。`UsagePoller.poll()` 的接口不接收 `AcpConnection`、轮次锁、帧映射回调或任何队列对象，从结构上排除偷帧与协议控制。

## 4. 设计决策

### D1 轮内只读文件，官方主链路保持不变

- **先执行红线再谈功能**：本路径只打开普通文件做只读解析；不得接收连接、队列、帧映射回调或轮次锁参数。任何 ACP 队列操作，无论读取一帧、非阻塞排空还是“只取 usage”，都视为违规。
- 轮内徽章新增值只来自 `wire.jsonl` 已落盘记录；官方 `usage_update` 仍由现有 `_iter_turn_chunks()` 在正常帧循环中上屏。
- response 到达仍立即 return；`post_turn_usage_grace_s=0.0` 不变。response 后才到达的官方推送不回收，徽章保留最后一次有效轮内水位。
- `poll_usage()` 不获取 `_turn_lock`，因为它不接触 worker 与 ACP 共享队列；其自身状态用独立小锁保护。
- GUI 的 2 秒 `QTimer` 保持不变；poller 以单调时钟限制每个 session 每 4 秒最多真正采样一次。距上次采样不足 4 秒的 tick 直接返回最后有效值，不读会话索引或 wire，也不重置节流时钟。
- 新会话、reset、resume 和模型切换后的第一次轮询必须立即采样，不因上一会话的节流时间而延迟；首次有效计量落盘后的正常刷新最坏等待一个 4 秒采样间隔，外加 GUI 调度误差。
- 首个有效记录落盘之前允许持续显示 `—`。本计划保证的是“落盘到上屏”的延迟，不保证发送后固定墙钟时间内一定有计量。

### D2 增量游标与有界读取

- 每个 session 独立保存文件路径、字节偏移、未完成残行、最近模型别名、最后有效 `UsageStats` 和是否已见 `token_counting.measured`。
- 首次读取只取文件末尾 64KB，并丢弃首个被截断的不完整行；之后只读新增字节，不在 GUI tick 全量扫描 MB 级文件。
- 文件未增长时返回最后有效值；大型工具输出只推进游标，不清空已有水位；新计量到达后再替换。
- 末条残行保留到下次拼接；完整坏 JSON 行跳过。文件缩小或截断时清空该 session 的偏移、残行、模型与水位状态后重建。
- 文件缺失、权限错误、瞬逝或字段异常均 fail-soft，不向 GUI 抛异常，不影响聊天。

### D3 会话目录与模型窗口只缓存成功

- 从 `~/.kimi-code/session_index.jsonl` 按 session ID 反查会话目录，倒序取最后匹配；缺失或坏行不抛出。
- 仅缓存成功定位；失败按 2/5/15 秒有界退避，避免每个 tick 重读全量索引。session 切换立即隔离旧缓存。
- 模型窗口取 `context_sizes_from_catalog()` 的 `maxContextSize`。目录加载只在 `_ensure_session()` 所在 worker 路径执行，只有解析到非空映射才标记成功；空目录在下轮 worker 准备时重试。
- GUI tick 只读已缓存窗口，不执行 `kimi provider list`，不创建线程或子进程。
- 无法确定模型窗口时返回 `None`/最后有效值，绝不猜测窗口或制造百分比。

### D4 真实水位口径

- 优先按文件顺序接受最新 `token_counting.measured.tokens`，其值为当前上下文水位。
- 未见过 measured 时，以 `usageScope=="turn"` 的 `usage.record` 兜底：`used = inputOther + inputCacheRead + inputCacheCreation + output`。
- 四项必须是严格非负整数（布尔值不算），`tokens` 必须是非负整数，`size` 必须是正整数；字段不完整则忽略该条，不清除旧值。
- 模型别名优先取轮内请求记录，缺失时使用当前 provider 模型别名；结果固定为 `UsageStats(used=..., size=..., cost=None, source="transcript")`。
- 这里只计算上下文水位，不生成 `TurnSpeed`、`TurnConsumption`，不写 Token 账本。

### D5 生命周期与并发隔离

- 新建会话、显式重置和 resume 成功后清空会话目录与游标，防止跨会话串值。
- 模型切换清除游标和最后水位，但保留仍然有效的模型目录；不得把旧模型窗口套到新模型。
- 多标签各自持有 provider 与 poller，不使用模块级可变会话状态。
- 锁只保护 poller 的缓存和游标；不得在持锁期间调用 CLI、ACP 或执行其他阻塞等待。文件读取异常必须局部消化。
- `close()` 仍只走现行终止路径；不得因为 poller 增加 `session/close`、cancel 或额外连接操作。

### D6 日志与隐私

- 只记录失败类别、重试次数、事件类型、脱敏数值和必要的状态迁移；不写 prompt、工具参数/输出、完整 wire 行、会话正文或凭证。
- 测试与探针的合成文件、截图、日志全部放项目 `.temp/`，不得使用系统临时目录。
- 用户目录中的 Kimi 文件仅供只读；自动化故障场景使用 `.temp/` 合成文件，不通过损坏真实会话来测试容错。

### T2 实现纯文件 `usage_poll.py`

1. 实现会话索引反查、wire 路径派生和每会话游标。
2. 实现 64KB 首读、后续增量、残行缓冲、截断重建与最后有效值。

6. 运行纯文件定向测试，确认旧实现中曾出现的永久负缓存、64KB 窗口丢失和半行误解析均有回归覆盖。

### T3 极简 provider 接线

1. 在 provider 实例中装配独立 poller，并在 worker 的 `_ensure_session()` 路径准备非空模型窗口。

3. 在新建/重置/resume、模型切换处按 D5 清理对应状态。
4. 不修改 `_iter_turn_chunks()`、`_classify_stop_reason()`、`cancel()`、`close()` 和 `capabilities()` 数值。
5. 运行 Kimi provider、能力快照、映射器、注册表与 provider 边界测试。

### T4 现有 GUI 入口闭环

1. 用最小 ChatPanel harness 调真实 `_poll_usage_tick()`：provider 连续返回 `None → transcript stats → None`，断言先保持空态、随后更新、最后保留有效值。
2. 验证 usage 不进入正文、历史、时间线或 Token 消耗账本；本计划不新增 usage chunk 的轮末簿记。
3. 用 offscreen 探针确认 `—` 到真实百分比的可见变化及 tooltip 的“会话记录”来源说明；截图存 `.temp/`，不新增常驻脚本。
4. 确认公共 `_usage_timer` 仍为 2 秒，Kimi 实际读盘由 poller 节流到 4 秒；停止/完成后计时器仍按 `post_turn_usage_grace_s=0.0` 停止，切后端和标签销毁行为不变。

## 7. 已确认决策

1. **最高优先级规则：只读 `wire.jsonl`，绝不触碰 ACP 队列。**宁可缺少徽章数据，也不能为取用量读取、排空、清理或重排任何 ACP 帧。
2. 恢复的是**只读轮内上下文水位**，不是恢复旧 Kimi 轮次管理。
3. 保留现有 2 秒 GUI `QTimer`，Kimi poller 内部按 4 秒真正采样，中间 tick 返回缓存；不新增第二套计时器，不修改聊天面板生产代码。
4. 只显示真实计量；首个有效记录之前继续 `—`，已有值不被空轮询清除。
5. response 即终态、零轮后宽限、无 ACP 队列回收是本次不可突破的边界。
6. 官方推送仍在原主链路消费；本计划不承诺接收 response 后的迟到推送。
7. 输出速度、Token 累计消耗、热力图和子代理旁路不在本次交付内。
8. 真机验收必须覆盖长开发任务及停止、断连、多标签；自动化全绿不能替代这些场景。

**经验沉淀**：

1. 私有 wire 解析必须同时以真实当前 CLI 验证。`token_counting.measured.tokens` 齐全并不等于能产出徽章：默认模型时 provider 别名为 `None`，若 wire 又无 `llm.request`，缺少 `profile.bind` / `usage.record` 的别名兼容会让全部水位静默为空。
2. 轮询器接口只接收 session ID 与模型别名，连接爆炸桩和持有 `_turn_lock` 的并发用例共同证明只读边界；文件游标锁与轮次锁完全分离，是不需要“非阻塞偷帧”的结构性保障。
3. 4 秒节流应作用于完整采样路径，包括会话索引；中间 tick 返回最后有效水位。残行、坏行、空文件、大输出和文件瞬逝都只影响当次解析，不能清除已有水位。
4. 自动化、离屏控件和真实 provider 验证回答的是不同问题；短任务多次刷新不能替代十分钟以上长任务，未覆盖项必须保留在验收结论中。
