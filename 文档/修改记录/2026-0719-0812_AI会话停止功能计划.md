## 1. 目标与决策摘要

为左栏 AI 会话增加停止能力：响应进行中可点击"■ 停止"，**立即打断**（含阻塞期）、**释放底层资源**（kimi-cli 子进程 / kimi-acp 轮次）、**恢复输入可用**，中断轮历史整体回滚。

**决策组合 B+A+A+B**（选型报告第 4 章）：

| 维度 | 决策 |
|:---|:---|
| 中断机制 | **B. 按后端分发的协议中断**：kimi-acp 发 `session/cancel`；kimi-cli 对活动子进程 `terminate()` |
| 资源清理 | **A. generator `close()` + provider `finally`**：正常/异常/停止三路径共用兜底 |
| UI 交互 | **A. 停止按钮 busy 时出现**（适配本项目无发送按钮的现状，见任务 3.1 说明） |
| 状态收尾 | **B. 整体丢弃回滚**：`_history.pop()` 用户消息，半截回复不入历史；屏幕内容不擦除，追加系统标注 |

**双保险**：协议取消（立即层）+ worker 标志轮询（检查点层，接残余流）+ 未启动先置标志（竞态层）。

## 2. 边界与已知限制（验收前必读）

1. **agent 侧会话痕迹不可回滚**：两后端历史均由 CLI/agent 会话管理（`kimi_cli.py:78` / `kimi_acp.py:272` 仅取最后一条 user 消息作 prompt）。`_history.pop()` 只保证 **panel 账面干净**（为未来 HTTP API 后端准备的正确性）；kimi 会话内部仍记得被中断的轮次（与 kimi CLI 交互模式按 Ctrl+C 的语义一致）。**不为此调 `reset_session()`**——那会丢失全部对话上下文，代价倒置。
2. **停止标注文案**：定为 `⏹ 已手动停止`（不暗示"会话已回滚"，与边界 1 相符）。
3. **工具副作用不回滚**：停止前 agent 已执行的文件改动/命令不撤销（三家参考实现同此边界）。
4. **kimi-acp 连接是长驻资产**：`cancel()` 只发 `session/cancel` 结束当前轮次，**绝不 terminate 连接进程**（杀掉会毁会话）；kimi-cli 相反，每次请求独立子进程，`terminate()` 即完整清理。

## 3. 阶段划分与任务清单

### 阶段 1：LLM 层取消原语（依赖：无）

| # | 任务 | 文件 | 要点 | 优先级 |
|:--|:---|:---|:---|:--|
| 1.1 | `LanguageModel` 协议补 `cancel()` | `llm/base.py` | Protocol 加方法约定："取消当前进行中的 chat 调用；无进行中调用时须为无害 no-op；从非 chat 线程调用须安全"；文档注明默认实现责任在 provider | 高 |
| 1.2 | kimi-cli：活动进程跟踪 + `cancel()` + `finally` 清理 | `llm/providers/kimi_cli.py` | ① `__init__` 加 `_active_proc: subprocess.Popen \| None = None`；② `chat()` spawn 后登记、迭代主体包 `try`，`finally`：`proc.poll() is None` → `terminate()` → `wait(timeout=3)` 超时 `kill()`，登记置 `None`；③ `cancel()`：对 `_active_proc` 存活则 `terminate()`（跨线程安全，仅发信号） | 高 |
| 1.3 | kimi-acp：`cancel()` 发 `session/cancel` | `llm/providers/kimi_acp.py` | ① 确认 `_AcpConnection` 的 notification 原语（无 `response` 的写消息方法；ACP 规范 `session/cancel` 为 notification，若无现成方法则补 `notify()`）；② 轮次中标志（`begin_turn`/`end_turn` 处维护）；③ `cancel()`：连接存活 + 轮次中 → 发 `{"sessionId": self._session_id}`；非轮次中 no-op；不触碰 `_turn_lock`（cancel 从 GUI 线程来，锁在 worker 侧持有） | 高 |

## 6. 风险与备案

| 风险 | 应对 |
|:---|:---|
| `session/cancel` 后 agent 仍有残余 update 到达 | worker 检查点层丢弃残余 chunk（标志已置，循环不再 emit）；`end_turn()` 现有配对清理 |
| kimi-acp `_AcpConnection` 无 notification 原语 | 任务 1.3 已含补 `notify()` 的预案（约 10 行，复用现有写消息锁） |
| 停止按钮在窄侧栏的视觉占位 | 模型行右侧小图标按钮（16px），qss 随主题；busy 时才可见 |
| 审批模态框弹出期间点击停止 | 本期边界：`session/cancel` 到达后 agent 放弃该工具调用，审批框超时兜底（现有 180s）自然解除；实测若卡死再升级（theia `cancelConfirmation` 思路，选型报告 §6 备案 5） |
