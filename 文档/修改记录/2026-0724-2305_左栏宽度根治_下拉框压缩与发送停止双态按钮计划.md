# 左栏宽度根治：下拉框最小宽度压缩 + 发送/停止双态按钮计划

## 1. 背景与目标

`2026-0724-2244_左栏宽度随对话角色变化诊断报告.md` 已确诊：左栏宽度随对话变化的根因是 **busy 期间 ModelBar 弹出的「■ 停止」按钮抬高左栏最小宽度，QSplitter 为满足子控件 minimumSizeHint 自动撑宽左栏，且只撑不缩（棘轮效应）**。附带发现：两个 QComboBox 按「最长条目文本宽度」计算 minimumSizeHint，使左栏静态下限锁死在约 540px，默认布局左栏 320px 永远不可达。

经讨论（2026-07-24 晚），用户拍板：

- **方案 A 采纳**：压缩下拉框最小宽度，消除「最长条目决定左栏下限」；
- **方案 B 改良**：不做浮动停止按钮，改为**在输入区底行增加常驻「发送」按钮，busy 时同按钮变为「停止」**（单按钮双态），停止按钮退出 ModelBar。

本期目标（量化验收见 §7）：

1. busy 置位/复位全程，左栏宽度零变化（动态撑宽根除）；
2. 左栏静态最小宽度从约 540px 显著压降（实测目标 ≤ 420px，见 T1 调优）；
3. 发送按钮与 Enter 完全等价；停止语义本地化为「点哪页停哪页」。

## 2. 参考实现取证（2026-07-24 晚走查）

| 项目 | 形态 | 位置 |
|:---|:---|:---|
| Multi_Cli_Studio（Tauri/React） | **单按钮双态**：输入框右下角唯一 submit 按钮，流式中同按钮变停止（图标 SendHorizontal ↔ Square，提示「发送消息 ↔ 停止生成」），点击按状态分流；空文本禁用发送 | `参考代码/Multi_Cli_Studio/src/components/chat/ChatPromptBar.tsx` |
| theia-zen（Theia ai-chat-ui） | **同位置互斥**：输入区右侧 action 位，pending 时渲染 `codicon-stop-circle`（取消 Esc），否则 `codicon-send`（发送 Enter）；空文本禁用发送 | `参考代码/theia-zen/packages/ai-chat-ui/src/browser/chat-input-widget.tsx` |
| VS_Code_Python（pygpt_net，PySide6） | **双按钮显隐**：输入区下方按钮行右对齐，send_btn 常驻 + stop_btn busy 时显示——与现状同模式，仅位置不同，**显隐仍会改变所在布局 sizeHint** | `参考代码/VS_Code_Python/src/pygpt_net/ui/layout/chat/input.py` |

结论：两家主流实现均为「单按钮双态 / 同位置互斥」，控件集合不随状态增减，sizeHint 恒定。用户改良版方案 B 与此一致，且用普通布局按钮实现（无浮动覆盖的定位/层级/重绘复杂度），为本期定案。

## 3. 设计决策

| 编号 | 决策 | 理由 |
|:---|:---|:---|
| D1 | 双 QComboBox 调 `setMinimumContentsLength(N)` + `setSizeAdjustPolicy(AdjustToMinimumContentsLengthWithIcon)` | Qt 内建机制，sizeHint/minimumSizeHint 按 N 个字符宽固定计算，与最长条目脱钩；弹窗列表仍显示全文 |
| D2 | 单按钮双态（发送 ↔ 停止同键切换），**不采用**双按钮显隐 | 显隐改变控件集合即改变 sizeHint（pygpt_net 模式正是现状病根）；双态切换只改文本与点击路由，布局完全静态 |
| D3 | 按钮归属 `ChatPanel`（每标签一个），停止语义本地化 | 替代全局 ModelBar 停止按钮 + `ChatTabs._route_stop` 路由；「点哪页停哪页」所见即所得，语义更精确 |
| D4 | 按钮位置：输入区底行右对齐（`stretch + 按钮`） | 用户指定「输入区底下」；实现为一行 QHBoxLayout，零定位技巧；pygpt_net 同位置先例 |
| D5 | 按钮恒宽：`setFixedWidth` 写死 + 「发送」「停止」两字等长文本 | 任何状态下 sizeHint 恒定的兜底保障，杜绝字体度量差异 |
| D6 | 空文本禁用发送态：`input.textChanged` 实时刷新按钮 enabled | 与 Enter 路径的「空文本不发送」对齐（两家参考实现均如此）；这是本期唯一新增的常态化信号连接 |
| D7 | ModelBar 瘦身：移除 stop_button / stop_requested，set_busy 仅保留双下拉禁用 | busy 不再引起 ModelBar 任何 sizeHint 变化，诊断报告 §3 链路在第 1 步切断 |
| D8 | 配色沿用主题既有色值与全局 QPushButton 范式，停止态以动态属性配 qss 选择器区分，不引新色值 | 项目既有惯例（占位页「新建会话」同款约束） |

⚠️ 有利现状（实现依据）：`ChatPanel._set_busy` 并不禁用输入框（仅切换 placeholder，重复发送由 `_on_send` 的 `worker.isRunning` 守卫拦截），故不存在「整体禁用连带点不了停止」的坑——ModelBar 当年注释警告的问题在新位置天然不成立。

## 4. 任务分解

### T1　方案 A：压缩下拉框最小宽度（`gui/panels/chat/model_bar.py`）

- 对 `_model_combo`、`_version_combo` 统一调用：
  - `setMinimumContentsLength(N)`（N 初值 12，验收阶段按实测调优，见 §7）；
  - `setSizeAdjustPolicy(QComboBox.SizeAdjustPolicy.AdjustToMinimumContentsLengthWithIcon)`。
- 为被裁剪显示的选中项补 tooltip（当前项全名），防「未检测到」等长标签不可读。
- 验收点：ModelBar 静态最小宽度由 528px 降至实测目标 ≤ 400px 量级；弹窗列表条目全文显示不受影响。

### T2　ChatInput 抽出公共发送入口（`gui/panels/chat/input.py`）

- 新增 `trigger_send()` 公共方法：取文本 → 非空且 `isEnabled()` → 发射 `send_requested`。
- `keyPressEvent` 的 Enter 分支改为调用 `trigger_send()`（逻辑单一来源，按钮与键盘严格等价）。

### T3　ChatPanel：发送/停止双态按钮（`gui/panels/chat/panel.py`）

- 新增成员 `_send_button`（QPushButton，objectName `chatSendButton`，`setFixedWidth` 写死，初值 64px）。
- 输入区布局改造：splitter 第二格由 `self.input` 换为容器（QVBoxLayout：`input` + 底行 QHBoxLayout[`stretch`, `_send_button`]）；splitter 句柄与 `save_state`/`restore_state` 持久化格式不变。
- 按钮点击路由 `_on_send_button()`：
  - busy（worker 运行中）→ `request_stop()`；
  - 空闲 → `self.input.trigger_send()`。
- `_set_busy` 扩展：切换按钮文本「发送 ↔ 「■ 停止」、切换动态属性 `stop`（qss 双态配色）、busy 时按钮恒 enabled；非 busy 时 enabled 由文本非空决定。
- 接 `input.textChanged` → 空闲态下刷新按钮 enabled（D6）。
- `_set_busy` 的 placeholder 文案同步改指向新按钮（「响应中…点击 ■ 停止可中断」语义保留、位置描述更新）。

### T4　ModelBar 瘦身（`gui/panels/chat/model_bar.py`）

- 删除 `stop_button`、`stop_requested` 信号、`set_busy` 中的显隐行及布局挂接；`set_busy` 仅保留双下拉禁用。
- 模块与类 docstring 同步更新（移除「停止按钮」相关描述）。

### T5　ChatTabs 移除停止路由（`gui/panels/chat/tabs.py`）

- 删除 `_route_stop` 与 `stop_requested.connect` 接线；`_recompute_busy` 保留「任一标签 busy → 禁用全局双下拉 + 发射 busy_changed」（菜单联动不变）。
- 模块 docstring 的「停止按钮路由」条目更新为「停止归各标签输入区按钮本地处理」。

### T6　qss：发送按钮双态样式（`config/themes/base.qss`）

- 新增 `#chatSendButton` 基础规则（沿用全局 QPushButton 实体化范式：实底 + 描边 + 6px 圆角）。
- 新增 `#chatSendButton[stop="true"]` 停止态规则（警示配色，取主题 palette 既有键，不引新色值；切换属性后 `unpolish/polish` 刷新）。

### T7　（可选）Esc 中断生成（`gui/panels/chat/panel.py`）

- busy 期间输入区 Esc 快捷键 → `request_stop()`（两家参考实现均有「取消（Esc）」先例）。
- 默认纳入本期；若评审认为超出范围则降级为后续项。

### T8　默认布局数值校正（`gui/panels/chat/panel.py`、`gui/main_window.py`，按实测数据决定）

## 6. 验证方案

1. **探针自动化验收**（主）：改造既有 `.tmp/probe_left_pane.py`（offscreen 平台），重跑「基线 → busy 置位 → AI 流式 → 复位」全链路，逐阶段断言：
   - `_splitter_main.sizes()[0]` 全程**零变化**（诊断报告 §4 的 85px 跳变必须消失）；
   - ModelBar 静态最小宽度 ≤ T1 目标值；
   - 每阶段截图（沿用 `.tmp/probe_*.png` 命名），多模态读图核实按钮双态与布局稳定。
2. **功能走查**（`uv run main.py` 实测）：
   - 发送按钮与 Enter 等价（含空文本禁用、发送后清空输入框）；
   - busy 中点停止：流式中断、输出「⏹ 已手动停止」、按钮回发送态；
   - 多标签：A 标签 busy 时 B 标签按钮形态独立；停 A 不影响 B；全局双下拉仍被禁用（菜单联动回归）；
   - 关闭 busy 标签、窗口关闭/重启后的分隔栏状态持久化无异常；
   - （T7）Esc 中断等价于点击停止。
3. **回归基线**：「恢复默认布局」后反复收发多轮，左栏宽度始终粘滞在用户/默认值，无任何自动撑宽。
