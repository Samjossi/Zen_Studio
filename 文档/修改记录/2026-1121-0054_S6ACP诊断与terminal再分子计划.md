## 1. 背景与目标

`acp/connection.py` 同时承担 JSON-RPC 收发、进程生命周期、反向请求分发、terminal/* 处理、stderr 脱敏与诊断日志。连接主路径与两类外设设施混在一个文件里，terminal 与脱敏无法独立测试。

本子计划目标：

1. 新建 `acp/diagnostics.py`，承接脱敏、有界 stderr ring 与诊断日志。
2. 新建 `acp/terminal.py`，承接 terminal/* 反向请求、env 解析与终端输出处理。
3. `connection.py` 只保留收发、请求配对、连接代次、进程失效与轮次原语，行为不变。

## 6. 实施结果回写（2026-11-21 01:47 UTC+8）

S6 全部完成。以下为实施过程中相对原计划的偏差、验证结果与可复用经验。

### 6.1 与计划的偏差

1. **诊断 helper 改名 `log_connection_diagnostics`**：为了避免与 `AcpConnection.log_diagnostics()` 形成计划禁止的「同名包装 shim」，模块函数改用 `log_connection_diagnostics`；连接方法保留为 provider 公共入口（`kimi/provider.py` 直接调用 `conn.log_diagnostics(...)`），内部只组装连接状态后委托新 helper。
2. **`_pending_waits` 随 terminal 分发器迁移**：挂起 wait 的 response id 集从连接对象移入 `TerminalDispatcher`，改由分发器自己的 `_lock` 保护；连接层 `_write_lock` 仍负责跨线程写帧串行化。死讯路径保持原顺序：先调用 `handler.on_connection_dead()`，再清空 pending 集；此时 `is_alive` 已为 False，回调触发的写帧被 `_write_reverse` 拒绝，不会补发响应。
3. **`_parse_terminal_env` 从 `protocol.py` 迁到 `terminal.py` 并去私有化**：新名 `parse_terminal_env`，实现逐字符保留（dict 直通、list 过滤、空结果转 None）。全库确认无其他引用，未在 `protocol.py` 保留兼容别名。
4. **日志记录器分类变化**：诊断与 terminal 日志的消息文本、级别与脱敏格式不变，但 logging category 从 `ide.llm.providers.acp.connection` 变为 `ide.llm.providers.acp.diagnostics` / `ide.llm.providers.acp.terminal`。若外部按旧 logger 名过滤，需要同步；本仓库无此依赖。
5. **`_complete_wait` 注解放宽为 `int | str`**：旧实现注解为 `int`，但原 `_pending_waits` 已是 `set[int | str]`，且 JSON-RPC id 可为字符串；仅注解与实现一致，无运行时行为变化。
6. **`terminal.py` 通过构造参数持有写帧原语**：`TerminalDispatcher` 不 import 连接层，也不反向持有连接对象；构造时注入 `write_reverse` 可调用对象，`dispatch()` 返回 bool 供连接层决定是否走 -32601 兜底。
7. **文档同步**：`src/ide/llm/README.md` 更新连接层职责并新增 diagnostics/terminal 两行；`维护手册/后端CLI工具维护说明手册.md` 的 `providers/acp/` 目录职责补「诊断/terminal 分发」。属现行说明同步，无代码行为变化。
8. **terminal 无独立超时/取消实现**：旧 `_handle_terminal` 本就没有 terminal 级超时或取消分支；`session/cancel` 是连接轮次原语，未改动。测试以「wait 延迟回调、重复回调丢弃、连接死讯清理」锁定实际存在的异步语义，未虚构新超时路径。

### 6.3 经验沉淀

1. **异步应答簿记跟着分发器走，写帧原语留在连接层**：把 `_pending_waits` 一并迁入 `TerminalDispatcher` 后，死讯清理只需一次 `on_connection_dead()`；关键是保持「先让 handler 触发回调、再清 pending」的顺序，并确保回调写帧仍受连接 `is_alive` 拒绝，否则会在死讯路径补发无意义响应。
2. **拆分时检查 logger category**：模块搬家会顺带改变 logging category，消息文本不变也属于可观察差异；回写必须记录，避免未来按旧 logger 名排查时误判日志丢失。
3. **「同名包装 shim」要用改名消除歧义**：连接层必须保留 provider 调用的 `log_diagnostics()` 方法，但模块 helper 改名为 `log_connection_diagnostics` 后，代码意图变成「状态组装 + 委托」，不再像搬剩的空壳。
4. **旧/新对照要先处理已迁走的私有 import**：旧 `connection.py` 仍 `from ...protocol import _parse_terminal_env`，直接加载会失败；用 `importlib` 先加载旧 protocol 并临时顶替 `sys.modules` 中的当前模块，是低成本复用 git HEAD 旧实现的可行办法。
5. **ring 容量测试用整数关系锁定**：8KB / (300 字节 + 换行) 恰好保留 27 行（27×301=8127），比只断言「不超过上限」更能发现边界漂移；UTF-8 字节计数则用 12 字节中文串 + 13 字节上限精确验证。
6. **连接层集成桩不必启动 Popen**：`object.__new__(AcpConnection)` 装配 `_handle_reverse`/`_mark_dead` 所需字段，再用带 `is_alive` 检查的写帧桩，就能覆盖「分发」「-32601 兜底」「死讯不补发」三条连接层职责，避免测试引入真实子进程与线程。
