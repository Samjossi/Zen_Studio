## 1. 背景与目标

当前仅 `light.qss` / `dark.qss` 两套主题，视图菜单为硬编码的两个勾选项。需求：

1. **新增数套主题，全部为亮色**（本文提案 3 套：暖米 / 晴空 / 薄荷，色系与数量待评审拍板）；
2. **现有"浅色主题"改名**——苹果风改造后它已是一套有明确风格的设计，应拥有独立名字而非泛称"浅色"。

目标：建立**可扩展的主题注册机制**（新增主题 = 放一个 qss + 注册一行），落地改名与 3 套新亮色主题，暗色主题保留不动。

## 2. 现状机制与耦合点

| # | 耦合点 | 位置 | 现状 |
|:--|:---|:---|:---|
| C1 | 主题加载 | [theme.py](../../gui/theme.py) | 读 `settings.json` 的 `theme` 字段 → 拼 `config/themes/<名>.qss`；文件缺失静默回退空样式 |
| C2 | 主题菜单 | [main_window.py](../../gui/main_window.py) | 硬编码"浅色主题/暗色主题"两个 checkable action，勾选态手动互斥 |
| C3 | 语法高亮配色 | [highlighter.py](../../gui/panels/viewer/highlighter.py) | `PALETTES` 以 `"light"/"dark"` 为键，`set_theme(主题名)` 直接查表 |
| C4 | 终端调色板 | [palette.py](../../gui/panels/terminal/palette.py) | 同上 |
| C5 | 查看器行号/当前行配色 | [code_viewer.py](../../gui/panels/viewer/code_viewer.py) | `CHROME` 同上 |
| C6 | 主题切换分发 | [main_window.py](../../gui/main_window.py) `_switch_theme` | 把**主题名**直接传给 C3/C4/C5 的 `apply_theme/set_theme` |

关键结论：C3/C4/C5 只认 `"light"/"dark"` 两个键。新增亮色主题（如 `wheat`）若按现状直接把主题名传下去，`PALETTES.get("wheat")` 查无此键会静默回退 `"light"`——结果碰巧正确，但语义脆弱（后续给某主题配专属高亮时无从挂载）。必须引入**"主题族"（family）**概念：每个主题归属于 `light` 或 `dark` 族，C3/C4/C5 只吃族名。

## 3. 主题体系设计

### 3.1 主题注册表（THEME_META）

[theme.py](../../gui/theme.py) 新增唯一注册点：

```python
# gui/theme.py
THEME_META: dict[str, dict[str, str]] = {
    # 键 = qss 文件名（不含扩展名）；label = 菜单显示名；family = 族
    "cloud": {"label": "云白", "family": "light"},
    "wheat": {"label": "暖米", "family": "light"},
    "sky":   {"label": "晴空", "family": "light"},
    "mint":  {"label": "薄荷", "family": "light"},
    "dark":  {"label": "暗色", "family": "dark"},
}
```

配套接口：

| 接口 | 语义 |
|:---|:---|
| `available_themes() -> list[str]` | 注册表顺序 ∩ `config/themes/` 实际存在的文件（注册但未放文件的不进菜单，防半成品暴露） |
| `get_family(theme: str) -> str` | 主题名 → 族名；未注册回退 `"light"` |
| `get_label(theme: str) -> str` | 主题名 → 菜单显示名 |
| `is_valid(theme: str) -> bool` | 校验持久化值有效性 |

新增主题流程（文档化于 theme.py  docstring）：放 `<名>.qss` → THEME_META 注册一行 → 完事。

### 3.2 菜单动态化与互斥

[main_window.py](../../gui/main_window.py) `_build_menus` 改为遍历 `available_themes()` 动态生成 action：

- 使用 `QActionGroup`（`setExclusive(True)`）管理互斥勾选，替代现状手动双 `setChecked`；
- 勾选态 = 当前 `settings["theme"]`；触发 → `_switch_theme(主题名)`；
- 切换提示复用现有 `statusBar().showMessage(f"已切换为{label}主题", 3000)`。

### 3.3 族接口改造（C3-C6）

- `_switch_theme` 分发改传**族名**：`viewer_panel.apply_theme(get_family(theme))`、`terminal_panel.apply_theme(get_family(theme))`；
- [viewer/panel.py](../../gui/panels/viewer/panel.py)、[terminal/panel.py](../../gui/panels/terminal/panel.py) 构造时 `load_settings()["theme"]` 同样过 `get_family()` 再传给 highlighter/palette/CHROME；
- C3/C4/C5 内部实现**零改动**（继续以 `"light"/"dark"` 为键），仅入参语义从"主题名"明确为"族名"，改参数名与注释。

### 3.4 持久化兼容与回退

改名后旧 `settings.json` 的 `"theme": "light"` 成为无效值。`load_settings()` 增加校验：`theme` 不在注册表或对应 qss 文件缺失 → 静默回退 `DEFAULT_SETTINGS["theme"]`（新默认值 = 改名后的现有主题，保证老用户观感连续）。无需专门迁移代码。

## 5. 新增亮色主题配色提案

三套均复用现有苹果风 qss 结构（无边框、色块分区、圆角、隐形滚动条），仅换色值。色板令牌与现有 light.qss 一一对应：

| 令牌 | 云白（现有） | 暖米 wheat | 晴空 sky | 薄荷 mint |
|:---|:---|:---|:---|:---|
| 窗口底 | `#ffffff` | `#faf7f2` | `#f8fafc` | `#f7faf7` |
| 文字 | `#1d1d1f` | `#463f33` | `#1e293b` | `#20301f` |
| 侧栏底 | `#f5f5f7` | `#f2ede3` | `#edf3f8` | `#edf5ed` |
| 输入色块（全局） | `#f5f5f7` | `#f2ede3` | `#edf3f8` | `#edf5ed` |
| 侧栏输入浮起 | `#ffffff` | `#ffffff` | `#ffffff` | `#ffffff` |
| 强调/选中色 | `#0765d4` | `#c26a1a` | `#0284c7` | `#15803d` |
| 树/列表 hover | `rgba(0,0,0,.045)` | `rgba(120,90,40,.08)` | `rgba(2,132,199,.08)` | `rgba(21,128,61,.08)` |
| 分隔线 | `#e5e5e5` | `#e8e0d2` | `#dde7ee` | `#dfe9df` |
| 菜单底 | `#f5f5f7` | `#f2ede3` | `#edf3f8` | `#edf5ed` |
| 滚动条滑块 | `rgba(0,0,0,.22)` | 同左 | 同左 | 同左 |
| PanelHint 灰 | `#86868b` | `#9a8f7d` | `#7d8da0` | `#7f9a84` |
| ToolTip | `#323236` 白字 | 同左 | 同左 | 同左 |

设计说明：

- **暖米**：燕麦/拿铁暖纸感，文字改深棕灰 `#463f33` 替冷黑，长时间阅读更柔；
- **晴空**：冷白微蓝，贴近"浅色 IDE"经典观感；
- **薄荷**：极浅绿底，护眼取向；
- 三套的文字色与底色对比度均 ≥ 12:1，满足可读性。

**待拍板②**：三套色系/套数是否调整（增删或改色值）。

**待拍板③**：强调色策略——上表为**每套独立强调色**（暖橙/天蓝/深绿，主题性格更强）；保守选项是全部沿用 `#0765d4`（品牌统一、实现更简）。推荐独立。
