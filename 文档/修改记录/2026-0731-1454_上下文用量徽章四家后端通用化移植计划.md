# 上下文用量徽章四家后端通用化移植计划

> ✅ **已实施**：2026-07-31 15:15 用户拍板 D1–D4 全部按初步倾向执行；
> E1–E3 只读实证同日闭环（结论见 §4.3 补记），实施按实证结果对方案做
> 了三处修订（见 §4.4），T1–T7 全部落地，四家真机实测通过（§6 补记）。

## 1. 背景与动机

1412 计划落地后实测发现：`usage_update` 是 **kilocode / opencode 两家
专有**的 ACP 推送，**kimi / reasonix 的 ACP 出口均不转发用量数据**
（1412 文档 T5 实测矩阵）。用户诉求：百分比徽章对四家后端通用。

## 2. 官网机制查证（2026-07-31 14:54）

**核心问题：其他 IDE/官方前端用 kimi/reasonix 时怎么知道上下文百分比？**

答案：**没有魔法渠道——是 agent 自己内部知道，只是 ACP 出口没接。**

- **Kimi Code CLI**：官方帮助页「Sessions & context」明确写道
  「The status bar at the bottom of the CLI displays the current context
  utilization in real time」（CLI 底部状态栏实时显示上下文利用率，用量
  高时提示 /compact）。数据源是 agent 与模型 API 的直接交互——OpenAI
  兼容协议每次响应必带 `usage` 字段，agent 内部天然持有；kimi 只是
  **未将其转发到 ACP**（本机实测：ACP update 流无 usage_update，
  prompt 响应帧仅 `stopReason`）。
  另据官方「Getting started」：本地数据存于 `~/.kimi-code/`（config、
  **session records**、logs）——会话落盘记录是潜在的协议外数据源。
- **Reasonix**：官网文档描述其 TUI 响应式底栏「按可用性显示 Git、
  缓存、**上下文**、压缩余量、任务和余额遥测」。Reasonix 直连 OpenAI
  兼容 provider（DeepSeek），用量同样来自 API 响应 `usage`（其主打
  前缀缓存，缓存命中 token 是内部核心指标）。其官方 ACP.md（219 行
  全文查证）**通篇无 usage 相关方法/通知**——确认 ACP 面无出口；
  但 prompt 响应携带 **`transcriptPath`**（指向官方持久化转录
  `~/.reasonix/sessions/*.jsonl`，属 ACP 会话生命周期正式产物，
  `session/load` 回放即依赖它），是本计划 L2 路径的依据。

**结论**：用量数据在四家 agent 内部都存在（模型 API 响应 `usage`），
kilocode/opencode 多做了一步把它包成 `usage_update` 推给 ACP 客户端；
kimi/reasonix 没做这一步。通用化 = IDE 侧为后两家找协议外数据出口
或接受估算降级。

## 4. 方案：多级数据源降级链

徽章数据源从「唯一依赖 usage_update」改为按精度分级的降级链，
provider 层统一在轮次结束时产出 `UsageStats`，GUI 层架构不变：

```
L0  usage_update 推送（kilocode/opencode，现状已通）—— 最准，used/size 同帧
L1  prompt 响应 result.usage ÷ IDE侧上限表
    —— kilocode/opencode 已实证有；仅作 L0 冗余，不单独使用
L2  transcript 转录文件解析（reasonix 专有路径）—— 响应给 transcriptPath，
    读 jsonl 取最后一条 assistant 的 usage ÷ IDE侧上限表（依赖 E1）
L3  本地估算（kimi 兜底）—— 已发历史 tokenizer 粗估 ÷ 上限表（依 D1；
    偏差来源：agent 注入的 system prompt/工具定义 IDE 不可见）
```

> **实施注记（2026-07-31，详见 §4.3/§4.4）**：E2 实证后 kimi 走 L2 类
> 路径（wire.jsonl 真值，source="transcript"），L3 兜底未启用；E1 实证
> 后 reasonix 的 L2 从「取 usage 字段」修订为「快照文本 chars/4 估算」
> （source="estimate"）；L1 维持「不作独立数据源」边界不动。

### 4.1 UsageStats 扩来源字段

```python
@dataclass(frozen=True)
class UsageStats:
    used: int
    size: int
    cost: float | None
    source: Literal["push", "response", "transcript", "estimate"] = "push"
```

GUI 对非 `push` 来源标注口径（§5-D3）。

### 4.2 模型上下文上限表（新模块 `llm/context_limits.py`）

- 静态内置表：registry 模型别名字符串 → context tokens
  （`"kimi-code/k3-256k": 262144`、`"deepseek/deepseek-chat": 128000` …）；
- 数值来源：各家官方文档公开数据，与 kilocode/opencode 推送的
  size 实测值交叉校验（实测已见 262144 / 1000000 / 200000 三种）；
- 缺表项 → 该后端降级隐藏徽章，不臆造上限（§5-D4）。

1. **上限表模块职责改变**（§4.2 废弃手写表）：`llm/context_limits.py`

4. **D3 微调**：`~` 前缀仅对 estimate 来源；transcript 来源与 push 同
   形态显示（真值不误导为估算），tooltip 三级文案分级注明数据来源——
   符合 D3「诚实呈现精度等级」的本意。
