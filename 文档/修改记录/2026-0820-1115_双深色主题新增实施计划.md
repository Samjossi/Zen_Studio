# 双深色主题新增实施计划

## 1. 目标

1. **新增两套深色主题**：`THEME_PALETTES` 注册表追加两个深色条目，外观菜单扩为六项（四亮两深）。
2. **深色资源包**：语法高亮/终端 ANSI/查看器行号/Git 状态色/Git Graph 徽标/聊天面板六套资源包各配一份深色值，深色两主题共享引用（沿用亮色四主题共享单套的既有纪律）。
3. **链路零改动**：`base.qss` 模板不动、`switch_theme` 八方转发链不动、菜单/持久化不动——纯数据增量。

**非目标**：不引入第三方主题库；不恢复明暗族分类判断代码（`get_family` 维持废除状态）；不做跟随系统自动切换。

## 2. 背景：qdarktheme 评估结论（2026-08-20 会话）

用户提议评估 qdarktheme（PyQtDarkTheme）一键深浅色方案，审阅代码后否决，理由：

| 评估点 | 结论 |
|:---|:---|
| 覆盖范围 | qdarktheme 只解决 app 级 QSS（`assets/themes/base.qss` 471 行模板）；占耦合大头的六套自绘/富文本资源包（终端 paintEvent、QSyntaxHighlighter、聊天卡片 HTML、Git Graph QPainter）它完全帮不上 |
| 范式冲突 | 本架构为「1 模板 × N 色板注册表」，四主题菜单、令牌校验、八方转发链均为此设计；qdarktheme 仅固定 dark/light 两套，替换等于重写而非简化 |
| 视觉资产 | base.qss 苹果风圆角/描边/卡片体系及配套 hack（`gui/popups.py` 弹层透明化、`scripts/check_qss_selector_guard.py` 级联守卫）为产品视觉特征，换库整体丢失且需逐项回归 |
| 维护风险 | qdarktheme 最新发布停留 v2.1.0（2023 年初），长期依赖不划算 |

**结论**：现有模板架构本身即为多主题设计，新增深色主题 = 「注册表加条目 + 配深色资源包」，成本低于任何换库方案。

### 4.1 主题命名（决策点 D1）

### 4.2 数据结构

```python
# gui/theme.py：新增六套深色资源包（模块级常量，深色两主题共享引用）
SYNTAX_PACK_DARK      = {Token.Keyword: {"color": "...", "bold": True}, ...}
TERMINAL_PACK_DARK    = {...}   # TerminalPack 同构
CHROME_PACK_DARK      = {...}   # ChromePack 同构
GIT_STATUS_PACK_DARK  = {...}   # GitStatusPack 同构
GIT_GRAPH_PACK_DARK   = {...}   # GitGraphPack 同构
CHAT_PACK_DARK        = {...}   # ChatPack 同构

THEME_PALETTES = {
    "cloud": {...}, "wheat": {...}, "sky": {...}, "mint": {...},   # 原四项不动
    "graphite": {
        "label": "石墨",
        # 26 个 QSS 令牌全量手写（深色值）
        ...,
        "title_bar": {...},  # 每主题一包四键，纪律不变
        "syntax": SYNTAX_PACK_DARK, "terminal": TERMINAL_PACK_DARK,
        "chrome": CHROME_PACK_DARK, "git_status": GIT_STATUS_PACK_DARK,
        "chat": CHAT_PACK_DARK, "git_graph": GIT_GRAPH_PACK_DARK,
    },
    "midnight": {
        "label": "深夜",
        # 与 graphite 的差异集中在 QSS 令牌（底色/描边/accent 偏蓝），
        # 资源包共享引用同一组 *_DARK 常量；个别确需区分的单项用
        # {**CHROME_PACK_DARK, "find_bg": "..."} 覆盖，不另开整包
        ...,
    },
}
```

- **资源包共享即引用，不复制**——与亮色纪律一致；两深色主题间若个别值需区分，按既有 docstring 预留的 `{**PACK, ...}` 单项覆盖模式处理。
- **不恢复明暗判断代码**：不加 `get_family` 类函数，六套 `*_DARK` 仅作数据存在，主题语义全靠注册表。
- **WARNING_COLOR 不动**：`#c0392b` 为全局警示色单一来源，深色下对比度在走查中确认，不足再议（单项调整，不开包键）。

### 4.3 配色来源策略

1. 起点：`git show 04453ce^:gui/theme.py` 取回旧 dark 条目的 26 令牌 + 四套 `*_PACK_B` 作为 graphite 底稿。
2. 逐项审校：旧 dark 是 7 月配色，此后新增的键（`GIT_GRAPH_PACK`、`CHAT_PACK` 的 diff/timeline 键、`title_bar` 子包等）旧包没有，须按 §3.1 清单补齐。
3. midnight 以 graphite 为底改蓝色调；两主题的语法高亮/终端配色须保证深底下对比度（参考 VS Code Dark+ 成熟色值，不臆造）。
