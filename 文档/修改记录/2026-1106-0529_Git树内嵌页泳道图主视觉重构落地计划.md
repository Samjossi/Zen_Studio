# Git 树内嵌页泳道图主视觉重构落地计划

> **状态**：草稿（待审阅）
> **范围**：右栏上内嵌提交拓扑图的图主视觉、泳道几何、节点与连接线、悬停信息、滚动与状态恢复、测试和视觉验收
> **时间**：2026-11-06 05:29（设计，UTC+8）
> **优先级**：高

## 1. 问题确认与目标纠偏

`2026-1106-0448_Git树切换页提交拓扑图落地计划.md` 已让右栏上 Git 页显示提交 DAG，但真实多分支仓库暴露出主次颠倒：左侧泳道窄而密集，refs 胶囊与提交主题占据主要视觉面积，用户首先看到的是提交文本列表，而不是分支图。

当前图线并非直接以文本字符上屏，而是把 Git 的图线字符转换成 `QPainter` 图元；问题在于**图线格仍按等宽字符宽度排列，图形列只是文本行左侧的狭窄附属区**。仅把 `/`、`\` 换成贝塞尔曲线，不能解决图的信息层级和复杂拓扑可读性。

本计划将内嵌页纠偏为：

- **拓扑图是唯一主内容**：提交节点、分支泳道、分叉与合并关系占据页面，不再常驻显示提交主题、hash 或 refs 文本徽标。
- **文本是按需解释**：整行悬停显示完整提交主题、短 hash、作者、相对/绝对时间、HEAD/本地分支/远程分支/标签等 refs。
- **完整弹窗承担详细阅读**：视图菜单中的完整四列弹窗保持现有 hash + refs + 主题 + 作者 + 时间布局，不与内嵌图一起改成纯图。

## 2. 需求

1. 内嵌 Git 页只保留一列拓扑图，不显示提交列、作者列、时间列和表头；不得再把 refs 与提交主题作为常驻正文。
2. 增大泳道间距、节点尺寸和连接行高度，使多分支、连续分叉、长并行分支与合并曲线可辨认。
3. 保留 ANSI lane 色到主题 `TERMINAL_PACK` 的映射，不新增主题色键；HEAD、悬停和选中状态在六套主题下均可辨。
4. 整行 tooltip 提供完整提交元数据；隐藏文本列后，悬停信息仍必须在图形列正常出现。
5. 图线所需宽度超过面板时提供横向滚动，不压缩泳道，也不让文本重新挤占图线空间。
6. 保留进入页面加载、页内手动刷新、隐藏时不查询、500 条上限、空仓库/非仓库/富文本降级和主题/字号跟随语义。
7. 刷新继续恢复选中提交与滚动位置，并补充横向滚动恢复；页面缩放不得重置浏览位置。
8. 完整弹窗、右栏下 `ChangesPanel` 及 M/U/D 三路双击行为保持不变；内嵌图继续只读。

## 3. 现状根因

### 3.1 信息层级错误

- `GitGraphView` 的紧凑模式仍保留图形列和提交列，提交列继续绘制 refs 胶囊与主题。
- `GitGraphPanel` 因而仍是“带图线的提交列表”，不是“可悬停查看提交信息的拓扑图”。
- 原计划的“refs 与提交主题优先”只适用于窄文本列表，不符合图主视觉目标，本计划明确取代该展示决策。

### 3.2 图形几何仍沿用文本度量

- `GraphColumnDelegate` 以等宽字符 `0` 的宽度作为唯一格宽来源，默认字号下泳道只有约数像素间距。
- 节点半径同时受格宽和行高限制，复杂分支中节点与线宽都偏小。
- 纯图线连接行半高会进一步压缩连续斜线和曲线；多段连接行密集出现时，视觉上容易退化成细折线。
- 图形列宽只按最大格数计算，剩余空间全给提交文本，不能利用整个内嵌页面表达拓扑。

### 3.3 复杂图线与验证覆盖不足

- 当前未知图线字符静默忽略；复杂合并或拐角字符若未覆盖，可能形成断线。
- 永久 fixture 主要覆盖“一条特性分支合回主干”，不足以暴露三条以上并行泳道、连续合并和密集连接行问题。
- 既有多分支真实仓库走查证明：曲线图元本身存在，不代表整体拓扑已经清晰可读。

## 4. 方案决策

### D1 继续复用 Git 拓扑，不自研 DAG 算法

- 继续使用 `fetch_commit_rows()`、`CommitGraph` / `CommitRow` 和 Git `--graph --all` 输出的图线格。
- 不新增 parents/lane 分配算法，不引入 Graphviz、WebEngine、QGraphicsView 或第三方拓扑库。
- 本次重构的是内嵌展示层级、几何度量和图元覆盖，不改变提交排序、引用视野与 500 条上限。
- `src/core/git/log.py` 原则上不改；只有真实图线字符盘点证明解析层丢字段时才另行补充。

### D2 内嵌页改为 graph-only，完整弹窗保持详细表格

- 将近期增加的“紧凑两列”语义改为明确的“graph-only 单列”语义，可使用 `set_graph_only()` / `graph_only=True` 命名，避免继续把两种信息层级都称为 compact。
- graph-only 模式隐藏 `COL_COMMIT`、`COL_AUTHOR`、`COL_DATE` 和表头，仅显示 `COL_GRAPH`；内嵌页不再调用提交列文本委托。
- `GitGraphPanel` 使用 graph-only；`GitGraphDialog` 使用完整模式，原有文本、refs 胶囊和四列布局不变。
- 不增加“图 / 列表”切换按钮，不在内嵌页保留另一套文本形态；需要详细阅读时继续使用现有完整弹窗。

### D3 建立独立泳道几何，不再以字符宽直接充当格宽

为图形委托建立统一的布局度量，节点、直线、曲线和列宽必须消费同一套结果：

- `lane_gap` 默认至少 18px，并按等宽字体度量随全局字号放大；不得再出现默认字号下单个位数像素泳道间距。
- 提交节点直径默认至少 8px，线宽保持约 2px；节点和线宽设置上下限，避免大字号下比例失控。
- 图形内容宽为 `最大泳道格数 × lane_gap + 左右安全边距`。可视列宽取内容宽与 viewport 宽的较大值，使选中/悬停背景覆盖整行，但泳道本身保持左对齐，不为填满空白而拉成超宽弧线。
- 图形内容超宽时启用横向滚动；240px 窄面板只保证最小间距，不缩小节点或压缩 lane 来强行容纳。
- graph-only 的提交行和纯连接行使用统一行高，不再使用半高连接行；行高由字体度量加图形余量计算，并设置适合鼠标悬停的最小高度。
- 完整弹窗保留现有半高连接行与列宽策略，避免本次内嵌改造改变详细弹窗布局。

### D4 以节点和连续曲线为图形核心

- `*` 绘制为清晰实心圆；`|` 为连续竖线；`-` / `_` 为水平连接；`/`、`\` 继续使用三次贝塞尔曲线。
- 曲线端点必须落在统一布局度量给出的泳道中心与行边界，相邻提交行/连接行共享端点，禁止各图元各自取不同格宽或行高。
- 对真实复杂仓库盘点 Git 输出的拐角和多头合并字符；补全必要图元，避免未知字符静默忽略造成可见断线。无法安全表达的形态继续走现有富文本降级，不伪造 parents 关系。
- HEAD 节点使用主题 accent 外环或双环强调；普通 refs 不再绘制文本胶囊，具体本地/远程/标签名称全部收进 tooltip。
- 悬停行使用低透明度 accent 背景并强化当前节点，选中行沿用既有选中语义；不得新增硬编码主题色。

### D5 整行悬停与只读交互

- tooltip 至少包含：短 hash、完整主题、作者、相对时间、绝对时间、refs 类型与完整名称。
- 图形列的每个有效提交行都返回 tooltip；纯连接行和截断提示行不伪造提交信息。
- 使用 Qt 标准 tooltip 事件链，保证鼠标位于节点、泳线或该行空白区域时均可查看，不要求精确命中小圆点。
- 保留上下方向键、单选和滚动浏览；节点点击不触发 checkout、详情、diff 或其他写操作。
- 无提交元数据的连接行仍参与图形绘制，但不抢占提交选中状态。

### D6 缩放、刷新与缓存边界

- `GitGraphView.resizeEvent()` 只重算可视列宽，不重新取数；viewport 变宽时利用空白承载整行状态，变窄时保留横向滚动。
- 刷新前记录提交 hash、垂直和横向滚动值；模型重置后按 hash 恢复选中，滚动值由新范围钳制。
- 字号调整重算 lane_gap、节点、行高和图形列宽；主题切换只重绘缓存图，不执行额外 Git 查询。
- `GitGraphContent` 的三页栈、加载、富文本降级和缓存逻辑继续共享；不得为 graph-only 另建取数路径或轮询。

## 5. 实施步骤

### T1 改造 graph-only 视图结构

1. 将内嵌紧凑两列改为单列拓扑图，隐藏提交文本列；完整弹窗仍显示四列。
2. 用明确的 graph-only 配置替换 compact 命名，同步 `GitGraphContent` 与 `GitGraphPanel` 的接线。
3. 保留既有选中、键盘、模型和委托结构，不新造第二套提交模型。

### T2 统一泳道布局与复杂图元

1. 在 `GraphColumnDelegate` 中集中实现 lane_gap、节点半径、行高、内容宽和安全边距计算。
2. 让节点、竖线、横线和贝塞尔曲线全部消费同一布局结果，取消 graph-only 半高连接行。
3. 盘点并补齐真实仓库出现的拐角/多头合并图线字符，保持 ANSI lane 色映射。
4. 实现 HEAD、悬停、选中状态和超宽横向滚动，完整弹窗几何不受影响。

### T3 完善悬停、缩放与刷新状态

1. 保证 graph-only 图形列整行 tooltip 包含全部提交元数据和 refs 类型。
2. 在 resize、字号变化和模型重置后重算列宽，不重复查询 Git。
3. 刷新恢复提交 hash、垂直与横向滚动位置；提交消失时安全取消选择。

### T4 永久测试

调整 `tests/test_git_graph_view.py`、`tests/test_git_graph_panel.py`，必要时补充聚焦用例：

- graph-only 只有图形列可见，完整弹窗仍有四列且提交列文本行为不变。
- 默认字号下 lane_gap、节点直径和行高达到最小值；字号调整后同步增大，不出现不同委托度量漂移。
- `/`、`\`、横线、竖线和新增拐角图元均有渲染像素断言；相邻行端点连续，连接行不再半高。
- 构造至少三条并行泳道、连续分叉、合并和长分支的 `.temp/` 真实 Git fixture，验证模型格数与列宽；超宽时横向滚动条有效。
- 通过真实 tooltip 事件验证图形列能显示完整元数据，连接行无提交 tooltip。
- 选中 hash、垂直和横向滚动跨刷新恢复，消失提交不报错；resize 不触发取数。
- 既有加载次数、隐藏不查询、空仓库、非仓库、富文本降级、下方变更列表和完整弹窗回归继续通过。

- 更新 `术语表.md` 和相关模块 docstring，删除“内嵌紧凑视图常驻 refs 与主题”的旧描述。

### 6.2 视觉闭环

## 8. 非目标

- 不在内嵌页保留常驻提交主题、hash、作者、时间或 refs 文本徽标。
- 不增加“拓扑图 / 提交列表”切换，不把内嵌页做成第二个完整弹窗。
