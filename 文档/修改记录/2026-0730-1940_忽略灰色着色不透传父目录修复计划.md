# 忽略灰色着色不透传父目录修复计划

## 1. 问题现象

以 Zen Studio 打开 Zen_VocoType 项目时，文件树中大量**本不该灰色**的
顶层文件夹（`文档/`、`协议/`、`tools/`、`Zen_VocoType_Client/`、
`Zen_VocoType_Launcher/`、`Zen_VocoType_Protocol/`、
`Zen_VocoType_Service/`）名称全部显示为灰色；而同样位于仓库内的
`work charter/`、`work options/`、`work plans/` 颜色正常。

用户直觉：灰色 = 被 gitignore 的条目。但实际上述目录均已被 git 跟踪
且无 ignored 状态条目，灰色来源另有其因。

## 2. 诊断结论（已实证）

### 2.1 灰色来自 Git ignored 状态色，与已移除的「过滤噪音目录」无关

- 文件树灰色唯一来源是 Git 状态着色的 ignored 色 `#a8a8a8`
  （`gui/theme.py:154`，git_status 资源包）；
- 原「过滤噪音目录」功能（旧 `NoiseFilterProxyModel.filterAcceptsRow`）
  只做**隐藏**条目，从不做任何着色——它对灰色零贡献；
- 《2026-0730-1933_移除噪音过滤与全量文件可见改造计划》**已实施完毕**
  （2026-07-30 19:50）：噪音过滤整体移除，代理模型改名
  `GitStatusProxyModel`（基类 `QIdentityProxyModel`，着色为唯一职责），
  文件树全量可见。灰色问题在移除后依然存在，实证了"灰色与噪音过滤
  无关"的诊断，必须按本计划单独修复。

### 2.2 根因：ignored 被纳入目录聚合冒泡表

`core/git/service.py`：

```python
_DIR_STATUS_PRIORITY: dict[str, int] = {
    status.IGNORED: 0,      # ← 问题所在
    status.UNTRACKED: 1,
    status.MODIFIED: 2,
    status.CONFLICT: 3,
}
```

`_build_dir_status()`（service.py:100-131）对表中每个状态沿**父链逐级
向上冒泡**（仅剪枝于同级/更高状态，止于仓库根）。ignored 虽优先级
最低（rank 0），但**仍然冒泡**：任何目录子树内存在一个 ignored 条目
（`__pycache__/`、`logs/*.log`、`tools/bin/`、`models/`……），其
全部祖先目录即被染上 ignored 灰。

实证（Zen_VocoType 仓库，`git status --porcelain --ignored -uall`）：

- `Zen_VocoType_Client/logs/client.log`、`__pycache__/` 等均为
  ignored → 灰色冒泡至 `Zen_VocoType_Client/`，Launcher/Protocol/
  Service 同理全灰；
- `tools/bin/appimagetool`、`tools/__pycache__/` 为 ignored →
  `tools/` 灰；
- `参考代码/`、`dist/` 自身被 gitignore → 自身灰，属正常行为；
- `work charter|options|plans/` 子树零状态条目 → 颜色正常（对照组）。

### 2.3 与 VS Code 语义的对齐缺口

VS Code 装饰传播语义：ignored 资源**仅自身暗显，不向父目录传播**；
modified/untracked/conflict 才沿目录上冒。目录聚合计划
（2026-0725-0933）为 deleted 单列了"不冒泡"特例，却遗漏了 ignored
同属"不冒泡"一类——这是设计时的对齐缺口，非实现笔误。

### 2.4 不受影响、须保持的既有行为

- ignored **条目自身**的灰色（`参考代码/`、`dist/`、各
  `__pycache__/`）保留；
- ignored 折叠目录（`!! dir/`）内文件经 `status_of()` 前缀匹配
  （service.py:148-151）显示灰色，保留（对齐 VS Code：ignored 目录
  内容同样暗显）；
- modified/untracked/conflict 的父目录冒泡保留；
- 变更面板已排除 ignored（service.py:173），不受影响。

## 4. 改造方案

### 4.1 服务层（service.py）：ignored 止步于自身

`_build_dir_status()` 最小改动：ignored 折叠键**自身照常入缓存**
（保留 118-122 自身写入逻辑与 rank 比较），随后跳过父链冒泡：

```python
for rel, file_status in self._status.items():
    if file_status not in _DIR_STATUS_PRIORITY:
        continue
    key = rel.rstrip("/")
    ...
    if rel.endswith("/"):
        # ignored 折叠目录键：目录自身直接入缓存（不虚构子文件）
        ...（不变）
    if file_status == status.IGNORED:
        continue  # ignored 不冒泡：自身暗显即止，不透传父目录
    for parent in PurePosixPath(key).parents:
        ...（不变）
```

非折叠 ignored 文件条目（如 `logs/client.log`）同样经此 `continue`
止步——其自身颜色由 `status_of()` 直接查询提供，本就无需入聚合缓存。

`_DIR_STATUS_PRIORITY` 表保留 ignored 项（自身入缓存的 rank 比较仍
依赖它），表注释更新为"ignored 仅用于自身入缓存，不参与冒泡"。

### 4.2 docstring 同步

- `service.py`：`_DIR_STATUS_PRIORITY` 上方注释（20-22）、
  `_build_dir_status()` docstring、`status_of_dir()` docstring——
  冒泡集合改为"conflict > modified > untracked；deleted/ignored
  不冒泡（ignored 仅自身入缓存暗显）"；
- `model.py` 模块 docstring（8-11 行）聚合叙述同步。

### 4.3 单测更新（test_git_dir_status.py）

- 场景 5 改为"ignored 不冒泡"：`g/build` 自身仍 → ignored（断言 64
  保留），断言 65 改为 `"g" not in svc._dir_status`；
- 场景 6 断言不变（`h` → modified、`h/build` → ignored，天然验证
  "ignored 缺席不干扰 modified 冒泡"）；
- 新增场景：非折叠 ignored 文件不冒泡——
  `{"j/cache/x.pyc": st.IGNORED}` → `"j/cache"`、`"j"` 均不在缓存，
  且 `svc.status_of(f"{REPO}/j/cache/x.pyc") == st.IGNORED`（文件
  自身灰保留）。
