# AI 新建文件 Git 状态绿色缺失修复计划（A+B 组合）

## 1. 背景与问题

问题与根因已在同目录诊断报告
`2026-0731-1256_AI新建文件Git状态绿色缺失诊断报告.md` 中闭环实证，
本文档不再重复论证，仅摘录结论作为改造依据：

- **现象**：IDE 运行期间 AI（OpenCode / KiloCode ACP 子进程）新建的
  文件在文件树中**出现但不着绿色**，父目录链不冒泡，变更面板计数
  不更新；窗口切换一次后恢复。
- **根因**：着色链路五环中数据层（①采集 ②缓存 ③查询 ④渲染）全部
  正常，断点在 **⑤触发层**——`GitStatusController` 原三处触发源
  （窗口激活 / 查看器外部重载 / 视图菜单手动刷新）均不覆盖
  "ACP 子进程直接写磁盘"路径；`QFileSystemModel`（始终监视磁盘，
  结构即时上树）与 `GitStatusService`（纯事件驱动，状态滞后）两套
  系统刷新节奏脱节是"看得见、没颜色"的直接成因。

诊断报告给出三方向：A（AI 侧补事件源，治本）、B（汇流
QFileSystemModel 结构变更信号，兜底）、C（自挂 QFileSystemWatcher，
与现有监视重复，不推荐）。**用户选定 A+B 组合**，本文档为其实施记录。

## 2. 决策

| # | 决策点 | 选定 | 理由 |
|---|--------|------|------|
| D1 | 方案组合 | **A+B 同时落地** | A 精准覆盖 AI 路径（轮次结束即刷，零浪费）；B 通用兜底一切外部写盘（终端 `touch`、其他编辑器），两者互为冗余，单任其一均有盲区 |
| D2 | A 的信号发射点 | `ChatPanel._on_finished`（正常/失败）与 `_on_stopped`（用户中断）**三态统一发射** `turn_finished` | AI 写盘不保证只发生在成功轮次；失败/中断轮也可能已落盘部分文件，三态全覆盖才无漏刷 |
| D3 | A 的信号路由 | `ChatPanel.turn_finished` → `ChatTabs` 同名单转 → `main_window._init_git_status` 接线 `git_controller.schedule_refresh()` | 沿用 `busy_changed` 既有转发范式（panel → tabs → 主窗口），不新开路由模式；复用控制器 300ms 去抖，连发轮次天然合并 |
| D4 | B 的信号选取 | `rowsInserted` / `rowsRemoved` / `fileRenamed` / `directoryLoaded` 四路汇流进**同一** `_debounce.start` | 新建/删除/重命名/目录内容变更全量覆盖结构变更；四路共处一个去抖计时器，并发触发合并为一次 `git status`；懒加载展开目录同样触发 rowsInserted/directoryLoaded，属无害冗余（去抖合并，一次 git status 仅数十毫秒） |
| D5 | B 的参数丢弃 | lambda 丢参（`lambda *_args: self._debounce.start()`） | 四路信号均带参（QModelIndex/int/str 不等），直连 `QTimer.start` 有重载歧义风险；现有 `externally_reloaded.connect(self._debounce.start)` 直连仅因该信号无参 |
| D6 | 标签关闭防护 | `ChatPanel.close()` 中对称 `turn_finished.disconnect()` | 与 `busy_changed.disconnect()` 同范式：迟到的轮次收尾不再从已摘出标签触发 Git 刷新；`worker.disconnect(self)` 已阻断 `_on_finished` 调用，此为双保险 |

**不做的事**：

- 不实施诊断报告方案 C（自挂 `QFileSystemWatcher` 监听 `.git/index`
  与工作区）——与 QFileSystemModel 自带监视重复，目录句柄开销大。
- 不覆盖"外部仅改写已有文件内容"场景——该场景无结构变更，
  `rowsInserted` 不触发；AI 路径已由 A 闭合，终端改写已有文件由
  窗口激活兜底（改文件后切回窗口即刷），与诊断报告边界一致。
- 不改 `GitStatusService` / `GitStatusProxyModel` / 着色链路任何
  数据层代码——诊断已实证四环无嫌疑。
- 不为 `turn_finished` 增加载荷（如无参足够）——刷新是全量
  `service.refresh()`，无需告知变了哪些文件。

## 3. 改造方案（已实施）

### 3.1 T1：`gui/panels/chat/panel.py` —— 新信号 + 三态发射

1. 类信号区新增 `turn_finished = Signal()`（注释标注用途与诊断报告
   出处）。
2. `_on_finished()` 末尾（`_set_busy(False)` / `self._worker = None`
   之后）发射；`_on_stopped()` 末尾同样发射（D2）。
3. `close()` 清理段对称断开 `turn_finished`（D6），`try/except
   (TypeError, RuntimeError)` 与既有 `busy_changed.disconnect()`
   同式。

### 3.2 T2：`gui/panels/chat/tabs.py` —— 容器单转

1. 类信号区新增 `turn_finished = Signal()`（D3 路由中段）。
2. `add_tab()` 接线 `panel.turn_finished.connect(self.turn_finished)`；
   标签关闭后 panel 销毁，Qt 自动断开其发出的连接，无需额外清理。

### 3.3 T3：`gui/main_window.py` —— 主窗口接线

`_init_git_status()` 末尾接线
`self.chat_tabs.turn_finished.connect(self.git_controller.schedule_refresh)`
（chat_tabs 创建早于 git_controller，顺序天然满足）。

### 3.4 T4：`gui/controllers.py` —— B 方案汇流 + 文档同步

1. `GitStatusController.__init__` 在 `_debounce` 建成后、初始
   `refresh()` 之前，将 `file_explorer.model` 四路信号经 lambda
   丢参接 `_debounce.start`（D4/D5）。
2. 类 docstring 事件源「三处」修订为「五处」，补注各源语义。

## 5. 边界与遗留

- **内容改写盲区**：外部进程仅修改已跟踪文件内容（不增删改名）
  时，B 不触发；由 A（AI 路径）与窗口激活（终端路径）覆盖。
  若未来出现"IDE 长驻前台 + 非 AI 外部工具原地改写"的着色滞后
  投诉，再评估是否引入内容变更监视（届时方案 C 可重议）。
- **懒加载冗余刷新**：用户浏览文件树展开目录会偶发一次去抖后的
  `git status`（D4 已评估为无害）；实测无可感卡顿。
- 冒烟脚本按项目约定留于 `.temp/`（gitignore 内，不入库）。
