> **状态**：已实施（修改记录：`2026-1119-1011_DSH图片卡片对齐Kimi修改记录.md`）
> **范围**：DSH 后端图片卡片链路——`src/ide/llm/providers/acp.py`（公共帧映射）、`src/ide/llm/providers/dsh_acp.py`、`src/ide/gui/panels/chat/cards.py`（卡片分派）、`src/ide/gui/panels/chat/panel.py`（图片能力消费）、`src/ide/llm/registry.py`（注释）；不含其余 snake_case 入参键完善（另立计划）

## 1. 背景与目标

用户反馈 DSH（DeepSeek Harness）后端下两类图片卡片异常：

1. **用户给 AI 发图**：粘贴图片后退化为 `@路径` 文本引用上屏，用户气泡无缩略图预览。
2. **AI 读图**：DSH 看图工具 `read_image` 的卡片只显示路径、无入参略缩图、无出参图。

目标状态：DSH 后端读图卡与 Kimi 后端 `ReadMediaFile`（MediaReadCard）观感等齐——入参路径 + 入参略缩图 + 出参图片；用户发图在 DSH 侧真实具备图片能力时恢复附件缩略图体验（能力不具备时维持 `@路径` 降级，不造假能力）。

## 2. 方案拆解（结构映射）

### 读图卡链路（AI 读图）

```
dsh 工具/结果帧
  tool_call:    title="read_image", kind="other", rawInput={"file_path": "..."}   ← 参考代码 deepseek-harness 实测投影（updates.ts）
  tool_call_update: content=[{type:"content", content:{type:"image", data:base64, mimeType}}]
        │
        ▼  src/ide/llm/providers/acp.py（map_session_update 公共映射）
  _map_tool_call: _extract_media_path(rawInput) → payload["media_path"]
                  _format_input_detail → payload["input_detail"]
  _map_tool_call_update: _extract_raw_output → payload["images"]（ACP image 块 → data-URI）
        │
        ▼  src/ide/gui/panels/chat/cards.py
  make_tool_card: _TOOL_NAME_CARDS["read_image"] → MediaReadCard（McpCard 子类）
                  ├─ _set_media_path: media_path → 入参略缩图 <img>
                  └─ McpCard 出参区: images → <img>（既有通道，零改动）
```

### 用户发图链路

```
GUI 粘贴/拖图 → panel._supports_images() ──能力内──→ 附件行 + 气泡缩略图 + build_prompt_blocks image 块
                                    └──能力外──→ @路径 文本 + 系统提示（既有降级，保留）
supports_images 取值：provider.supports_images_override（dsh initialize 实测）优先，registry 静态位兜底
```

## 4. 设计决策

1. **`read_image` 走 MediaReadCard，不动 TextOutputCard**：卡片体验问题在分派与数据源，不在 TextOutputCard 本身；修正分派后出参图经 McpCard 既有 images 通道渲染，改动面最小。
2. **协议层键扩展一次性补 snake_case**：`_extract_media_path`/`_INPUT_DETAIL_KEYS`/`_tool_call_summary` 增补 `file_path`，顺带补 `edit` 的 `old_string`/`new_string`/`replace_all`——同一根因（DSH 参数 snake_case 命名）的最小闭环；其余工具键完善另立计划。
3. **无扩展名图兜底工具名集合增 `read_image`**：`read_image` schema 仅接受图片格式（png/jpeg/webp/gif，均在现有白名单），纯防御性扩展，不影响既有 `readmediafile` 判定。
4. **用户侧能力动态翻案而非永久静态 True**：DSH acp profile 是否支持图片取决于 dsh 侧挂载（附件存储 + 路由声明 image 输入，initialize 才说真话）。`DshAcpLLM` initialize 后按 `agentCapabilities.promptCapabilities.image` 置实例级覆盖位，GUI 鸭子类型优先消费；registry 静态 False 保留为兜底初值。协议谎报能力的风险由 DSH 侧 admission 兜住（非视觉路由收图会整轮报错，错误如实上屏）。
5. **能力外维持既有降级**：翻案前行为（@路径 + 系统提示）一字不改。

## 6. 风险与注意点

- **非视觉路由收图整轮失败**：能力翻真后用户选无 image 输入声明的路由（如纯文本路由）发图，DSH admission 拒收整轮（AcpContentError），错误经既有 `_raise_on_turn_error` 链上屏。属后端真值如实呈现，不做客户端路由预检（路由能力 GUI 侧不可得）。
- **首轮前能力未知**：provider 未建时 override 不可得，静态 False 行为延续；`_on_finished` 刷新后附件入口才放行。首帧即发图场景仍走降级，可接受。
- **dsh 版本漂移**：initialize 结构假设以 spike 存档为锚（`agentCapabilities.promptCapabilities.image`），结构缺省按无能力处理，不崩 UI。
- **既有用例断言面**：`read_image` kind 兜底、TextOutputCard 承接读图的相关断言（如有）随分派修正同步更新，禁止为过测试改产品语义。
- **附件落盘**：能力翻真后粘贴图走 AttachmentStrip 既有落盘 PNG 机制（`panel._send_turn` 回滚恢复数据源现成），零新增存储面。

### 实施结果回写（2026-11-19 10:11 UTC+8）

T1–T5 全部完成，修改记录见 `2026-1119-1011_DSH图片卡片对齐Kimi修改记录.md`。以下为实施过程中相对原计划的偏差与经验。

**与计划的偏差**：

- 计划 T3 只写「`_on_finished` 幂等重调 `_apply_image_capability()`」。实施时发现该函数在「能力外且附件行有残留附件」时会弹系统提示，轮末每次刷新都调会导致提示随轮次重复弹——遂给 `_apply_image_capability` 增能力位跃迁簿记 `_images_applied`（类属性初值 None），能力位未变即短路。属计划未明写的隐藏改动点，行为方向与计划「幂等刷新」一致。
- 计划 T4 预警「`read_image→read` 的 kind 兜底断言可能需要同步更新」：实际既有用例未断言 read_image 场景，`test_acp_kind_fallback.py` 零改动全绿。
- 测试文件名计划未指定，落地为 `tests/test_dsh_image_cards.py`（12 用例），与 `test_dsh_backend.py` 同目录同范式。

**验证结果**：

- 新增 12 用例 + 相关回归 28 用例全绿；门禁 `bash scripts/check.sh` 全绿（隐私扫描 + ruff + pytest 494 全过；6 条 warnings 为 `test_turn_abort.py` 存量 Qt 信号断开告警，与本次无关）。
- 真机探测（本机 dsh 0.2.2-rc.1，`DSH_HOME` 重定向 `.temp/dsh_probe_home`，零 LLM API 消耗）：真实 initialize + session/new 成功，`supports_images_override=False`，与 spike 结论一致（本机 profile 未挂附件存储）。
- 未做的验证：真实 dsh 会话读图端到端验收（需消耗 API），留用户确认；dsh 侧挂载附件存储后的三件套验收同理。

**经验沉淀**：

- 能力位类需求（supports_images）静态注册表只能作兜底初值，真值必须在运行时握手（initialize）实测——「谁主张能力谁举证」原则可推广到其他后端能力位。
- 轮末/事件末的「幂等刷新」调用点必须先检查被刷新函数的所有副作用（系统提示、信号广播），否则刷新本身制造重复噪音；簿记上次应用值是最简解法。
- 桩化 ACP 连接的 `request` 签名要容忍关键字实参（`timeout=60`），否则真实调用点的关键字传参会撞桩签名——`tests/test_dsh_image_cards.py` 的 `_FakeConn` 已按此口径写。
