# 新增 OpenCode 后台计划

## 1. 目标与决策

### 1.1 目标

ModelBar 三级下拉新增第四个后台「OpenCode」（本机 OpenCode CLI，
v1.18.9 已安装实测可用），与 Kimi / Reasonix 并列。

### 1.2 决策（待用户拍板，文中按推荐项展开）

| # | 决策点 | 推荐 | 备选 |
|---|---|---|---|
| D1 | 接口形态 | **ACP**（`opencode acp`，长驻子进程 + ndjson JSON-RPC） | run 形态（`opencode run --format json`，每轮 spawn） |
| D2 | 接口数量 | **先只接 ACP 一个接口**（最小增量） | 同 kimi 双接口（acp + run）一并接入 |
| D3 | 模型枚举 | **`opencode models` 纯文本逐行解析** | session/new 的 configOptions 反查（需先起会话，重） |
| D4 | 默认后台 | **不变**（仍为 kimi-cli） | 切换为 opencode-acp |

**推荐 ACP 的理由**（§2 实测支撑）：OpenCode 的 ACP 实现与现有
`AcpConnection` 泛化层**协议级兼容**——initialize / session/new /
session/set_config_option / session/prompt / 流式 update 全链路实测
通过，接入代码量与 reasonix_acp 同量级（约 200 行，其中大半是
docstring 与 bin 探测），且 token 级流式、思维链、协议级取消、
审批回环全部免费获得。run 形态（kimi-cli 模式）仅消息粒度上屏，
无任何优势项。

## 2. 调研实测记录（2026-07-30，本机 opencode 1.18.9）

全部实测在项目根目录、经 `~/.opencode/bin/opencode` 完成：

### 2.1 二进制探测

- 安装方式：curl 官方脚本，落在 `~/.opencode/bin/opencode`；
  `.bashrc` 追加 PATH，但**桌面会话/非登录 shell 不一定含此 PATH**
  → `_find_bin` 需 fallback 到 `~/.opencode/bin`（对齐 kimi
  `~/.kimi-code/bin`、reasonix `~/.reasonix/bin` 三级范式）。
- OpenCode 无 `OPENCODE_HOME` 类安装根环境变量（官方环境变量表
  只有 `OPENCODE_CONFIG` / `OPENCODE_CONFIG_DIR` 等配置路径），
  故探测链为两级：PATH → `~/.opencode/bin/opencode`。

### 2.2 模型枚举（`opencode models`）

```
opencode/big-pickle
deepseek/deepseek-chat
...
kimi-for-coding/k3
kimi-for-coding/k3-256k
```

- 纯文本输出，每行一个 `provider/model` 全名；**无 `--json` 旗标**
  （`--verbose` 只加元数据列，不利于解析）。
- 数据源是已认证 provider（models.dev 缓存），与 ACP session/new
  的 configOptions.model.options **完全同源**（实测两列表一致，
  15 项）。
- 解析策略：逐行 strip、跳过空行，非 `provider/model` 形态行容错
  跳过；失败/空输出 → 空列表（provider 用 agent 默认模型，与
  kimi/reasonix 同一兜底语义）。

### 2.3 ACP 握手（`opencode acp`）

`initialize`（protocolVersion 1）实测响应：

```json
{"protocolVersion":1,
 "agentCapabilities":{"loadSession":true,"mcpCapabilities":{...},
   "promptCapabilities":{"embeddedContext":true,"image":true},
   "sessionCapabilities":{"close":{},"fork":{},"list":{},"resume":{}}},
 "authMethods":[{"id":"opencode-login",
   "description":"Run `opencode auth login` in the terminal"}],
 "agentInfo":{"name":"OpenCode","version":"1.18.9"}}
```

- 协议同构：与 kimi/reasonix 同为 ACP v1，帧格式 ndjson。
- authMethods 为静态能力声明（同 reasonix 实测结论），**不能作
  未登录信号**；未登录/失效的真实信号在 session/prompt 错误，
  归各 provider 自行翻译（D5 惯例）。

### 2.4 会话与模型切换

`session/new` 实测响应（关键字段）：

```json
{"sessionId":"ses_...",
 "configOptions":[
   {"id":"model","name":"Model","category":"model","type":"select",
    "currentValue":"opencode/big-pickle",
    "options":[{"value":"kimi-for-coding/k3",...}, ... 共 15 项]},
   {"id":"mode","name":"Session Mode","type":"select",
    "currentValue":"build",
    "options":[{"value":"build",...},{"value":"plan",...}]}]}
```

- `configOptions` 结构与 reasonix 完全一致，`configId="model"`
  直通 `session/set_config_option`（实测返回更新后 configOptions，
  currentValue 已变为 `kimi-for-coding/k3`）→ **set_model 即时
  生效机制零新代码**。
- 多出 `mode` 选项（build/plan）：本计划固定 build 默认，不暴露
  UI（plan 模式禁用编辑工具，与 IDE 对话场景不匹配；未来如需
  「计划模式」再单列计划）。

### 2.5 流式对话端到端

`session/prompt`（切模型后，prompt「只回复两个字：收到」）实测：

- update 类型统计：`agent_thought_chunk` ×15、
  `agent_message_chunk` ×1、`available_commands_update` ×1、
  `usage_update` ×1——**全部命中现有 ACP 标准映射**
  （thought → reasoning 灰字、message → text 正文，其余忽略）。
- 响应：`{"stopReason":"end_turn","usage":{...}}` —— 正常收尾。

### 2.6 run 形态（备选，已实测留档）

`opencode run "..." --format json`：stdout 逐行 JSON 事件
（`step_start` / `text`（part.text）/ `step_finish`（tokens/cost）），
`-s <sessionID>` 续接实测通过。事件 schema 与 kimi stream-json
**不同构**（需新映射层），作为 D1 备选留档，本期不实施。

### 2.7 权限与凭证

- 凭证：`opencode auth login` 管理，存
  `~/.local/share/opencode/auth.json`（本机已有 Kimi For Coding、
  DeepSeek 两条）。代码库零密钥惯例不变。
- ACP 审批回环：`session/request_permission` 协议标准方法，
  OpenCode promptCapabilities 声明支持；**事件载荷形态未实测**，
  列为实施期验证项（§6-T6）。兜底：handler=None 时 AcpConnection
  自动允许（现状语义）。

## 3. 改造方案

### 3.1 新增 `llm/providers/opencode_acp.py`（约 200 行）

与 `ReasonixAcpLLM` 高度同构，复用 `AcpConnection` 全量基建。
模块 docstring 逐条记录与 kimi/reasonix 的差异（项目惯例）：

1. **bin 探测**：`_find_bin()` 两级链 PATH → `~/.opencode/bin`；
   常量 `OPENCODE_BIN = "opencode"`。
2. **模型枚举**：`list_opencode_models()` spawn
   `opencode models` 解析纯文本行（§2.2），15s timeout，
   全 try 兜底空列表。
3. **认证文案映射**（D5 各自翻译）：session/prompt 的 error 帧
   宽松匹配 auth/login/credential/unauthorized 关键词 →
   「请先运行 opencode auth login」。
4. **cwd 归一化**：`os.path.abspath`（对齐 reasonix 稳妥做法；
   kimi 无要求不搬）。
5. **mode 固定 build**：不使用 `session/set_config_option` 的
   mode 项，agent 默认即 build。
6. 别名私有语义（D6 红线 2）：`provider/model` 全名不透明透传，
   公共层不解析不拼接。

类骨架（与 ReasonixAcpLLM 逐方法对应）：

```python
class OpenCodeAcpLLM(LanguageModel):
    __init__(model=None, workspace_root=None)   # + atexit.register(close)
    set_model(alias)        # session/set_config_option(configId="model")
    reset_session()         # 清 sessionId，进程保留
    set_workspace_root(root)  # abspath + reset_session（预留，无调用方）
    set_permission_handler(handler)
    close()                 # _closed 先置位 + atexit 注销 + terminate
    cancel()                # session/cancel，不杀长驻进程
    chat(messages)          # _turn_lock 串行化 + begin_turn/迭代/end_turn
    _ensure_session()       # spawn 前后双检 _closed + initialize + session/new
    _iter_turn_chunks(conn) # next_update 循环 → Chunk
    _map_update(obj)        # ACP 标准映射（thought/message/tool_call）
```

注：`sessionCapabilities` 含 close/fork/list/resume，本期均不使用
（每标签一实例、标签销毁即进程终止的现语义不变）。

### 3.2 `llm/registry.py`：注册段追加一项

`list_opencode_models` 三符号（import 与 `__all__`），模块

——该常量现存两枚（kimi 双接口）是 settings 默认值的历史产物，
opencode 不作默认值即无消费方（YAGNI；如需再加）。

## 6. 风险与回归点

- **T6 审批载荷**：OpenCode `session/request_permission` 的
  options 结构未实测，若与 kimi 不同构需按 D5 在 opencode_acp
  内翻译，不动公共层。
- **`opencode models` 输出漂移**：无 --json 契约，未来版本可能
  改格式；解析层全 try 兜底空列表（最坏退化：模型下拉为空、
  用 agent 默认模型，对话功能不受影响）。
- **stdin EOF**：实测管道 stdin 关闭即终止 acp 进程——长驻
  AcpConnection 持管无此问题，但调试脚本需保持 stdin 打开。
- **models.dev 缓存**：`opencode models` 首次运行触网刷新，
  list_models 的 15s timeout 覆盖；`--refresh` 不主动调用。
- **mode=plan 泄漏**：用户若在 OpenCode 侧配置默认 plan 模式，
  编辑工具被禁属预期行为，IDE 不干预（文档提示即可）。
- **多标签进程数**：每标签一 acp 长驻进程，沿用既有标签数上限
  约束（ChatTabs D1），无新增资源压力。
