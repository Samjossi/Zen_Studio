## 1. 背景与目标

### 1.1 现状问题

| 问题 | 现状 |
|:---|:---|
| 权限粒度 | `permission_auto_allow` 仅二态复选框：要么逐次弹窗、要么放手（仅黑名单兜底），用户无法表达"写文件我放心、跑命令我要看"这类中间态 |
| 设置入口 | 设置项散落菜单栏（S3 混合双通道：菜单直挂 + JSON 只读查看），无图形化设置界面；菜单表达力有限（塞不下带说明的多态选项），新增设置项无处安放 |
| 菜单承载力 | 权限说明文案"AI 工具自动放行（危险命令仍弹窗）"已开始超长，四态选项更无法塞进菜单勾选项 |

### 1.2 目标

| 项 | 现状 | 目标 |
|:---|:---|:---|
| 权限粒度 | 二态布尔 | **四态单选**（§3），覆盖"全确认 → 仅命令确认 → 智能放行 → 全放行"光谱 |
| 设置入口 | 菜单散落 | **设置中心对话框**：菜单栏「设置 ▸ 设置中心…」（Ctrl+,）弹出，五分页（§4） |
| 生效方式 | 菜单勾选即时持久化 | 对话框控件 change 即时持久化 + 即时应用（**无确定/取消**，沿用现状先例） |
| 菜单 | 权限复选框 | 移除（迁入对话框）；其余高频项保留直挂（S3 通道延续） |

定位纪律（延续方案 F 裁决，本计划**不突破**）：不做工具级/命令级白名单、不做会话层、不做五态按钮、不做规则管理 UI。四态是单选枚举而非规则引擎，复杂度有界。

## 3. AI 工具权限四态设计

### 3.1 模式枚举

新键 `permission_mode: str`（替换 `permission_auto_allow: bool`）：

| 模式值 | 显示名 | 非 Bash 工具（读/写等） | Bash 普通命令 | Bash 命中黑名单 | 对应旧态 |
|:---|:---|:---:|:---:|:---:|:---|
| `confirm_all` | 逐次确认 | 弹窗 | 弹窗 | 弹窗 | = 旧 `False` |
| `confirm_execute` | 仅命令需确认（新增中间态） | 放行 | 弹窗 | 弹窗 | 新增 |
| `auto_guarded` | 智能放行（**默认**） | 放行 | 放行 | **弹窗**（附命中原因） | = 旧 `True` |
| `auto_all` | 全部放行（高危） | 放行 | 放行 | 放行 | 新增 |

设计要点：

- **光谱连续**：从全确认到全放行四档，用户表达"信任写文件但盯命令"（`confirm_execute`）、"信任日常但防大灾"（`auto_guarded`）、"完全托管"（`auto_all`）各得其所
- **黑名单护栏语义随档衰减**：`auto_all` 即显式关闭护栏，UI 红色警示文案"危险命令（rm -rf /、git push -f 等）也将不再弹窗，请确认你信任当前 AI 后端"
- **逃生舱仍在**：`confirm_all` 即旧"取消勾选"行为，随时可回
- **仍是枚举不是规则**：四态硬编码于决策纯逻辑，不引入用户可编辑规则（方案 E 备案不动）

### 3.2 决策逻辑改造

```python
# llm/permission_policy.py
def decide_permission(params: PermissionParams, mode: str) -> Decision:
    """四态决策：confirm_all 全弹；confirm_execute 仅 execute 类弹；
    auto_guarded 仅黑名单弹；auto_all 全放行。未知 mode 回退 auto_guarded。"""
```

- 签名加 `mode` 参数，纯函数纪律不变（零 Qt、零 IO、reader 线程安全）
- 四态常量化（`PERMISSION_MODES` + 显示名映射，AFCP 3.4）；决策表驱动而非 if 链
- `confirm_execute` 实现：`kind != "execute"` → allow；`kind == "execute"` → ask（不再查黑名单，反正都弹，黑名单原因可附可不附——**附**，用户看一眼就知道是否危险档命中，零额外成本）
- 决策点 `gui/panels/chat/panel.py` `_ask_permission`：读 `permission_mode` 传入；`confirm_all` 短路走现有弹窗路径（= 现状开关关分支）

### 3.3 键迁移

- `settings.py`：`KEY_PERMISSION_AUTO_ALLOW` 删除，`KEY_PERMISSION_MODE` 新增，默认 `"auto_guarded"`；`AppSettings` / `AppSettingsPatch` / `DEFAULT_SETTINGS` 同步
- 旧键处置：遵循模块既有先例——"未登记键读取即丢弃，存量旧键自然失效，无需迁移代码"。旧 `permission_auto_allow: false` 用户回退默认 `auto_guarded`：该开关 0757 计划当天（2026-07-22）才落地、用户面极小，且回退方向是"中间档"而非"全放手"，可接受（风险表 §7 记录）
- `reset_settings` 全量 patch 含新键，自然覆盖；菜单 action 同步代码随复选框移除一并删除

## 4. 设置中心对话框设计

### 4.1 排入逻辑（为什么是这个顺序）

排序原则 = **安全风险 × 使用频率**，辅以"破坏性沉底"：

| 序 | 页 | 排此位的理由 |
|:---:|:---|:---|
| 1 | **AI 工具权限** | 本计划核心诉求；安全风险最高的设置域，置顶 |
| 2 | **AI 模型** | 次高频切换项（后端/版本），与权限同属 AI 域，相邻 |
| 3 | **外观** | 主题/字号，高频低风险 |
| 4 | **终端** | 单键，低频低风险 |
| 5 | **高级** | 打开配置文件（只读）+ 恢复默认设置（破坏性），沉底防误触 |

### 4.2 布局与交互

- **结构**：左侧 `QListWidget` 导航（五页）+ 右侧 `QStackedWidget` 页容器（VSCode 设置风格；比 QTabWidget 更适合带说明文字的长页，且后续加页不改布局）
- **每页控件**：
  - AI 权限页：四态 `QRadioButton` 组，每态一行加粗名称 + 一行灰字说明；`auto_all` 行红字警示；页底折叠区只读展示黑名单 12 条（来源 `DANGEROUS_COMMAND_PATTERNS` 原因文案，不做编辑）
  - AI 模型页：后端 + 版本双下拉（复用 ModelBar 数据源 `BACKEND_LABELS` / `list_kimi_models()`）
  - 外观页：主题下拉（`list_available_themes()` + `get_label()`）、字号 `QSpinBox`（8–24，界同 `MainWindow.FONT_SIZE_MIN/MAX`）
  - 终端页：`Ctrl+C/V 复制粘贴` 复选框（含说明行）
  - 高级页：「打开配置文件」「恢复默认设置…」按钮 + `config/` 路径只读展示
- **生效纪律**：所有控件 change 即 `update_settings` + 调 MainWindow 现有应用槽（`switch_theme` / `_apply_font_size` / `set_terminal_swap_copy_paste` / `apply_model_selection`），**无确定/取消按钮**——与菜单勾选即时持久化先例一致，避免双套生效语义；仅底部「关闭」（Esc 同效）
- **模态**：非模态（`show()` 单例，重复打开 raise 现有实例），用户可边改边看主窗口效果（主题/字号即时预览的刚需）

### 4.3 状态同步

| 方向 | 机制 |
|:---|:---|
| 对话框 → 系统 | 控件 change → MainWindow 应用槽（收敛单点，与菜单/ModelBar 同路径） |
| 系统 → 对话框（打开期间） | 模型选择经 `chat_tabs.model_bar.selection_changed` 监听刷新；恢复默认后对话框 `reload()` 全量重载控件态 |
| 防回环 | 程序化 `setChecked/setValue` 不触发 `triggered`（Qt 纪律沿用）；下拉用 `QSignalBlocker`（与 ModelMenu.sync 先例一致） |
| 菜单 ↔ 对话框 | 菜单保留的主题/字号/终端反转项：change 路径同为 MainWindow 槽 + 同一 JSON 键，天然一致；对话框打开期间外部改动按"系统 → 对话框"刷新 |

| 项 | 标准 |

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| `auto_all` 误选导致危险命令静默执行 | 🟡 | 单选组红字警示 + 说明行明列后果；默认值保持 `auto_guarded`；逃生舱 `confirm_all` 一键可回 |
| 旧 `permission_auto_allow: false` 用户被回退默认 | 🟢 | 键当日才落地用户面极小；回退方向是中间档非全放手；本计划记录在案 |
| 对话框与菜单勾选态割裂 | 🟡 | 权限复选框从菜单移除（单一来源）；其余共享项走同一 JSON 键 + 同一 MainWindow 应用槽，天然一致 |
| 三向同步回环（P2 模型页） | 🟡 | 复用 `QSignalBlocker` / setChecked 不触发纪律；失控则降级只读页（§7 裁剪） |
| 对话框膨胀为"什么都能配"的庞然大物 | 🟢 | §2 盘点表 + §7 裁剪清单把住入口；新设置项入框须先过"是否用户偏好"裁决 |
