## 1. 目标与判定标准

### 1.1 目标

用一条与官方 ACP 文档一一对应的链路替换现有实现：**发 `session/prompt` → 转发 `session/update` → 响应即终态**。不读 `wire.jsonl`，不建第二套轮次状态机，不做 drain，不推同步提示。

### 1.2 「成功」的判定

必须同时满足：

1. 真机矩阵 S1–S3、S5–S7 全部通过（见 §6）；
2. 真实 Kimi CLI 下可连续完成长任务，界面完成态、停止、断连行为可预期；
3. 新包运行时部分（`provider.py` + `updates.py` + `permissions.py`）总行数 ≤ 900；
4. 全量测试通过，无旧包残留导入；
5. S4（后台通知轮）按方案 A 的预期如实记录，**不作为通过门槛**。

### 1.3 明确不做

- 不识别「提前 `end_turn`」，不判断 agent 内部轮次是否仍在执行；
- 不实现「后台轮次同步中」提示、drain 循环、待发闸门；
- 不读 Kimi 私有 `wire.jsonl`（含子代理旁路、私有用量差量）；
- 不为「让停止一定生效」增加 `session/close` 分流判断；
- 不在新实现上留下任何为上游缺陷准备的钩子。

## 2. 目标形态

### 2.1 新包结构

新建 `src/ide/llm/providers/kimi_min/`（并行期临时命名，扶正时改为 `kimi/`）。

| 文件 | 来源 | 预计行数 | 职责 |
|:---|:---|---:|:---|
| `provider.py` | 重写 | ~300 | 会话建立与恢复、轮次主链路、`stopReason` 分类、取消、断连报错 |
| `updates.py` | 从旧包迁移，行为不变 | ~560 | ACP `session/update` → `Chunk` 投影与卡片载荷 |
| `permissions.py` | 迁移 | ~70 | 权限请求分类 |
| `models.py` + `catalog.py` | 迁移 | ~235 | 模型目录枚举与派生 |
| `spec.py` | 迁移并改注册名 | ~64 | 注册声明（并行期 `kimi-min-acp`） |
| `__init__.py` | 迁移 | ~20 | 包导出 |

合计预计 1150–1300 行，硬上限 1400；运行时部分（前三项）目标 ≤ 900 行。**超限即说明防御层又长回来了，必须在汇报中说明原因，不得默默放过。**

### 2.2 旧机制逐项处置

| 旧机制 | 新做法 |
|:---|:---|
| `turn_state.py` 四态判定（`normal/draining/desynchronized/unknown`） | 删除。响应 `stopReason` 即终态 |
| `provider.py` 的 `_confirm_turn_end` drain 循环 | 删除 |
| `status` 块与「后台轮次同步中」提示 | 删除（GUI 的 `_sync_active` 消费逻辑保留，无生产者即不触发） |
| `_turn_pending` 待发闸门 | 删除。轮次结束即允许发送 |
| `wire.py` 私有落盘解析 | 删除 |
| `usage.py` 轮末宽限收集与私有差量 | 删除。仅当 ACP 下发 `usage_update` 帧时照常上屏 |
| `subagent.py` 子代理 wire 旁路 | 删除。子代理若出现在 ACP 帧里仍照常投影 |
| `session/close` 停止分流（`_turn_pending` 驱动） | 简化为只发 `session/cancel` |
| `_needs_recovery` 断连标记 + 下轮 `session/resume` | **保留**：一个布尔 + 一次 resume，是官方恢复语义的最小实现，不属防御层 |
| `stopReason` 分类（`cancelled`/`max_tokens`/`max_turn_requests`/`refusal`/未知 fail-open） | **保留**：这是协议语义，不是兜底 |
| 轮次挂起看门狗 | 不动（`src/ide/gui/settings.py` 与 `src/ide/gui/panels/chat/panel.py` 的公共机制，不属 provider 包） |

## 5. 实施任务

### T1 分支与骨架

建分支、建包、写最小 provider（构造、`capabilities`、`chat` 空实现）、注册并行项。验收：`python -c "import ide.llm.registry"` 通过，应用能启动并列出两个 Kimi 后台。

### T2 会话建立与目录

搬 `models.py`/`catalog.py`，实现 `initialize` → `session/new`（或 `session/resume`）→ 记录 `sessionId`；模型切换与强度档位沿用官方 `configOptions`。验收：真机新建会话成功，模型列表来自 CLI。

### T3 轮次主链路

`session/prompt` + 更新转发 + 响应收尾；迁入 `stopReason` 分类与 error 帧优先判定；`updates.py` 迁移后行为不变。验收：首轮纯文本、工具调用各一轮，卡片与旧实现一致；`cancelled` 走停止通道、`max_tokens` 走失败通道。

### T4 停止与断连

`cancel()` 只发 `session/cancel` + 本地 abort 解封；`dead` 时抛明确错误并置恢复标记，下一次手动发送前 `session/resume`，不自动重发。验收：进行中停止可用；`kill` 子进程后报错文案明确、不自动重发、再发能恢复上下文。

### T5 界面接线

确认后端标签、输入区占位符、完成播报在 Minimal 下正常；确认不产生 `status` 块。验收：无「同步中」文案出现。

### T6 真机验收矩阵

按 §6 执行并留记录（版本、场景、时长、`stopReason`、现象）。

### T7 扶正

1. 删除 `src/ide/llm/providers/kimi/` 整包；
2. `git mv` 新包为 `src/ide/llm/providers/kimi/`，`spec.py` 的 `name` 改回 `kimi-acp`；
3. `registry.py` 去掉并行项，只留一项；
4. 清理 `src/ide/gui/settings.py` 的 `kimi_wire_sidecar` 与对应设置界面项；
5. 迁移/删除引用旧模块的测试（当前 37 个测试文件引用 Kimi 包，逐一确认是契约测试还是实现对偶）；
6. 更新 `术语表.md` 中失效条目（`wire`、待发闸门、同步提示）。

验收：`grep` 无旧模块残留导入；全量测试通过；应用启动与首轮对话正常。

### T8 汇报
