# 打包态 frozen 语义适配修复计划

## 1. 背景与目标

诊断报告确认打包态三症状**同源于一个语义切换**：`core/paths.py` 在 PyInstaller frozen 态将 `PROJECT_ROOT` 改指解包根（`sys._MEIPASS`，AppImage 下即 `/tmp/.mount_*/usr/bin/_internal`），而下游三处消费点仍按「`PROJECT_ROOT` = 项目根」的开发态语义使用：

| 症状 | 根因 | 本计划任务 |
|:--|:---|:--:|
| S1 文件树标题变 `_internal`、默认工作区落解包目录 | `main.py resolve_workspace_root` 无参静默回退 `PROJECT_ROOT` | T1 |
| S3 「打开文件夹」等四条 spawn 链路全灭 | `gui/main_window.py _spawn_window` 命令写死开发形态（拼 `_internal/main.py`，不存在 → argparse exit 2） | T2 |
| ⚠️ 附带：AppImage 下 `--auto-screenshot` 必崩 | `main.py SCREENSHOT_DIR = PROJECT_ROOT / ".tmp"` 指向只读挂载 | T3 |
| — 同类隐患未清 | 其余 `PROJECT_ROOT` 消费点未走查 | T4 |

S2（齿轮图标）经诊断为**误判**（Yaru 主题 `application-x-sharedlib` 本色即齿轮，图标系统完好），本计划**不含任何动作**。

**目标**：打包态无参启动落在有意义的用户工作区；spawn 四链路（新建窗口 / 打开文件夹 / 在新窗口打开文件夹 / 最近项目回放）在 frozen 态全部可用；截图目录不再写只读挂载；`PROJECT_ROOT` 消费点语义全部定性。开发态行为**一律不变**。

## 2. 任务设计

### T1　frozen 判据导出 + 默认工作区二级回退（`core/paths.py`、`main.py`）

**问题**：frozen 判据（`sys._MEIPASS` 探测）目前只在 `core/paths.py` 内部持有（`_MEIPASS` 为私有名），T1/T2/T3 三个消费点都需要「是否 frozen」分支——按 `core/paths.py` 自身注释「frozen 判据全库唯一定义点，禁止散落重写」，须先导出公共判据。

**改动**：

1. `core/paths.py` 新增导出常量：
   ```python
   #: 打包态判据（PyInstaller frozen）公共导出口：全库唯一判定来源，
   #: 消费方一律 import 本常量，禁止各自探测 sys.frozen / sys._MEIPASS
   IS_FROZEN = _MEIPASS is not None
   ```
2. `main.py resolve_workspace_root` 改为双态回退：
   - **开发态**：维持现状（缺省/无效 → `PROJECT_ROOT`）。
   - **frozen 态**：缺省/无效 → **最近项目首项（目录仍存在者）→ 用户主目录** 二级回退。最近项目读 `RecentProjectsStore(USER_CONFIG_DIR / "recent_projects.json").list()`（纯 JSON 读，无 Qt 依赖，可在 `QApplication` 创建前调用；`main.py` 本已 import `gui`，无新增循环依赖）。
   - 无效参数的告警文案同步由「回退项目根」改为「回退默认工作区」（双态共用）。
3. 新增私有辅助 `_frozen_default_workspace() -> str`，承载二级回退链，保持 `resolve_workspace_root` 单层职责。

**联动说明（不改代码，行为说明）**：`main_window.py:118/120` 以「`_workspace_root == str(PROJECT_ROOT)`」决定是否纯标题「Zen Studio」。T1 后 frozen 默认工作区不再等于 `PROJECT_ROOT`，标题将带路径（`Zen Studio — /home/xxx`）——与多开窗口「一眼可辨根路径」的既有设计语义一致，**接受**。

**验收**：开发态 `uv run main.py` 默认根仍为项目根（回归）；frozen 无参启动：有最近项目 → 落其首项，无 → 落 `Path.home()`；文件树标题不再出现 `_internal`，终端 cwd 同步正确（上游 `TerminalPanel(cwd=self._workspace_root)` 恒传值，自然正确）。

### T2　spawn 命令双态分支（`gui/main_window.py _spawn_window`）

**改动**：

```python

    if IS_FROZEN:
        # 打包态：二进制自身即入口（argparse 位置参数恰为 folder）
        cmd = [sys.executable, folder]
    else:
        cmd = [sys.executable, str(PROJECT_ROOT / "main.py"), folder]
    proc = subprocess.Popen(cmd)
    ...
```

- `IS_FROZEN` 自 `core.paths` import（T1 导出），不在本文件探测。
- 开发态命令逐字节不变；frozen 态 `sys.argv` = `[zen-studio, folder]`，与开发态 `main.py <folder>` 等价。
- `_close_after_spawn` 探活防护（2s 窗口、失败保留旧窗）行为不变，继续兜底。

**覆盖链路**（四入口共用 `_spawn_window`，一处修复全通）：`new_window`（新建窗口）、`open_folder_here`（打开文件夹换根）、`open_folder_in_new_window`、`open_recent_project`。

**验收**：frozen 态四链路逐一实机通过——新窗存活超 2s 探活期、绑定正确工作区根；「打开文件夹」新窗就绪后旧窗正常关闭。
