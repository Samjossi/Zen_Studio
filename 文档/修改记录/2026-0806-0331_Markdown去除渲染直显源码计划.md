# Markdown 去除渲染直显源码实施计划（初稿，待审阅）

日期：2026-08-06

（前身为同日 0327「阅览/源码双模式滑块开关计划」，经审阅推翻：开关方案违背简单原则，改为直接移除渲染。）

## 一、需求

1. 阅读 Markdown 文档时**不再渲染**，直接显示源码（与其他文本文件同一形态：CodeViewer 只读 + Pygments 高亮 + 行号）。
2. 移除 Markdown 渲染页，消除渲染带来的排版漂移问题。
3. 需要精美渲染时，用户右键「**使用 Typora 打开**」交给外部专业软件——该既有功能**保留**，入口从 MarkdownView 右键菜单迁移到文本页右键菜单（仅当前文件为 md 时出现）。
4. 不做任何编辑能力，不增加任何模式开关。

## 二、现状分析

- `gui/panels/viewer/panel.py` ViewerPanel：QStackedLayout 五页
  （文本 / 图片 / 媒体 / Markdown / PDF）。`.md/.markdown` 经
  `open_file` → `_open_markdown()` 直进 `MarkdownView` 渲染页。
- `gui/panels/viewer/markdown_view.py` MarkdownView（QTextBrowser + setMarkdown GFM）：
  渲染、相对资源解析、链接三分发（http→浏览器 / 工作区文件→file_link_clicked /
  锚点跳转）、主题样式表、选区带自绘、右键「使用 Typora 打开」
  （TyporaLauncher 见 `core/external_apps`）。
- `gui/panels/viewer/code_viewer.py` CodeViewer：只读 + 行号 + 高亮，
  右键菜单为 `exec_standard_context_menu` 标准菜单透明化。
- 文本页 `open_file` 主路径自带 1MB 截断守卫 + UTF-8 严格解码 + Pygments 高亮
  （`.md` 有 Pygments lexer）——md 走该路径**零新增能力**。

## 三、方案设计

### D1 md 分流删除，并入文本主路径

`open_file()` 中删除 `if suffix in MARKDOWN_EXTS: return self._open_markdown(p)` 分支，
md 自然落入既有文本读取→守卫→高亮→上屏路径。`MARKDOWN_EXTS` 集合保留
（D3 Typora 入口判定要用），但不再作为页面分流依据。

### D2 移除 Markdown 页

- `_build_pages()` 删除 markdown_view 创建与信号接线（file_link_clicked /
  typora_failed），QStackedLayout 回到四页。
- 删除 `_open_markdown()` 方法。
- `show_find()` 删除 markdown_view 降级分支（md 现在是文本页，查找天然可用——
  顺带消灭「Markdown 渲染页不支持查找」的降级体验）。
- `apply_theme()` / `refresh_font()` 删除 markdown_view 两行。
- **删除 `gui/panels/viewer/markdown_view.py` 文件**（渲染能力整体下线，
  不留死代码；Git 历史可溯）。

### D3 Typora 入口迁移：文本页右键菜单（仅 md 文件）

迁移到 CodeViewer 右键菜单，判定条件与原有一致（当前文件为 md 且系统检测到 Typora）：

- CodeViewer 的 contextMenuEvent 现状是单行 `exec_standard_context_menu(self, event)`。
  为避免把控件搞复杂，采用**面板注入回调**的轻量方式：
  CodeViewer 增加可选属性 `extra_menu_actions: Callable | None`（缺省 None，
  探针/独立使用不受累），contextMenuEvent 构建标准菜单后若回调非空，
  由回调返回的 `(text, slot)` 列表追加 action。
- ViewerPanel 装配时注入：当前 `_current_path` 后缀 ∈ MARKDOWN_EXTS 且
  `default_launcher.is_available()` 时返回 `[("使用 Typora 打开", self._open_in_typora)]`，
  否则返回空列表。
- `_open_in_typora()`：`TyporaLauncher.open(Path(self._current_path))`，
  失败 `_show_hint`（沿用原 typora_failed → 弱提示语义，信号随 MarkdownView
  一并删除，面板内直调即可）。
- 菜单透明化沿用 `make_translucent_popup` 规约（exec_standard_context_menu 已含，
  追加 action 在同一 menu 对象上，样式一致）。

### D4 链接点击行为变化（可接受降级，明示）

渲染页的工作区内文件链接点击跳转（file_link_clicked → open_file）随渲染页
一并消失。源码态下 md 内链接就是纯文本，不可点击——与其他源码文件一致，
符合「源码直显」定位；需要导航用 Typora。此变化写入模块 docstring 与修改记录。

### D5 选区带自绘的归属

`gui/selection_band.py` 已通用化（聊天区 ChatOutput 共用），**保留不动**；
仅 MarkdownView 这个使用方消失。
