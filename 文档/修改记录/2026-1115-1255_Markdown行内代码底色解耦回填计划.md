## 1. 背景与需求

0253 计划把 `chrome.line_number_bg` 纳入中性灰冷暖适配，四主题各自染色（wheat `#f5f1e9` / sky `#eff4f8` / mint `#eff5f0`）。但 `markdown_view.py` 的 `code_bg` 是**借用**行号栏底色令牌的：

```python
# src/ide/gui/panels/viewer/markdown_view.py:230
code_bg = palette["chrome"]["line_number_bg"]  # 代码块底借用行号栏底色令牌
```

借用关系由来已久（复现自上一代项目，并非 0253 引入）；此前四主题 `line_number_bg` 统一共享基线 `#f5f5f5`，借来的值不随主题变，行内代码事实上解耦。0253 把被借的值按主题染色后，Markdown 渲染里反引号行内代码、代码块、表头底色的背景色被一并带成主题染色。姊妹项目用户走查后拍板：**行内代码底色原来的共享基线 `#f5f5f5` 本来就与各主题很适配，不该跟着适配改**。

## 2. 现状机制

- 消费方唯一：`markdown_view.py` 生成 Markdown 预览样式，`code_bg` 用于 `code, pre` 背景（:238）与 `table th` 背景（:248，`pre code` 透明豁免 :240）。
- chrome 包由 `ChromePack` TypedDict 定 schema（`src/ide/gui/theme.py:75-80`），四主题共用同一结构，新增键必须四主题全填。
- `tests/test_theme.py` 经 0253 重写后有「每包全部键 = 蓝键 ∪ 适配键 ∪ 维持键」集合等式断言，新键不入表会被该断言拦截——防漏天然闸门。
- 旧共享基线：`line_number_bg` 适配前四主题统一 `#f5f5f5`（cloud 适配后仍是）。

## 3. 目标

1. Markdown 行内代码底色与 `line_number_bg` 解耦：chrome 包新增专用键 `code_bg`，消费方改取新键。
2. 四主题 `code_bg` 一律 `#f5f5f5`，行内代码底色恢复到适配前观感；行号栏自身保持各自染色不回退。
3. `bash scripts/check.sh` 全量门禁通过；offscreen 截图走查通过。

## 5. 改造设计

### 5.1 键归属

chrome 包新增 `code_bg`，语义为「Markdown 行内代码 / 代码块 / 表头底色」。选 chrome 而非 chat 的理由：消费方是查看器渲染（阅读面），与行号栏同属 chrome 阅读语境；且复用 chat 的 `tool_output_bg` 同样是染色键、拿不回旧基线观感。

### 5.2 四主题终值表（全部小写，姊妹项目已走查定稿）

| 主题 | code_bg 终值 | 说明 |
|:---|:---|:---|
| cloud 云白 | `#f5f5f5` | 与现值一致，纯入表 |
| wheat 暖米 | `#f5f5f5` | 由 0253 染色值 `#f5f1e9` 回填 |
| sky 晴空 | `#f5f5f5` | 由 0253 染色值 `#eff4f8` 回填（姊妹项目首批走查主题） |
| mint 薄荷 | `#f5f5f5` | 由 0253 染色值 `#eff5f0` 回填 |

回填默认值 `#f5f5f5`（四主题统一旧基线）——姊妹项目用户已表态「原来的颜色就已经很适配」，且该项目曾逐主题微调后仍全部回到 `#f5f5f5`，**无需再走「首批单主题 → 确认 → 回填」的分批节奏**。

### 5.3 消费方改动

`markdown_view.py:230` 的 `code_bg` 改取 `palette["chrome"]["code_bg"]`，注释更新为专用键语义。
