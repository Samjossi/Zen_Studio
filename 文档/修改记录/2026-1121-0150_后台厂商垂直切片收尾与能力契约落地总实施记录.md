## 跨项偏差与决策

1. **设置 schema 的兼容例外跨 S0/S2**：`kimi_wire_sidecar` 的键名、字段与默认值不能删；S0 只声明键，S2 把 `settings.py` 列为设置键守卫的受控例外，消费层仍只允许厂商包与注册表组合根。
2. **守卫抓到了主路径之外的旁路**：S2 规则 2 发现 `timeline.py` 直读工具载荷；通过三家 presenter 的 `timeline_projection` 下沉解释权，通用时间线只消费中性键。这说明「字段级守卫」必须覆盖旁路消费者，而不只是卡片与面板。
3. **测试/脚本的 monkeypatch 落点是拆分的隐性契约**：S3/P4/S5/S6 都出现补丁目标或 import 路径随模块迁移而变化；子计划均已逐项记录，语义与断言不变。
4. **logger 分类会随模块搬家改变**：S3/S4/S6 的日志消息文本与级别逐字保留，但 logger 名变化；排查时应按新模块名过滤，不能据此判断日志丢失。
5. **S4 不是严格纯搬家**：`WireSidecar` 改为组合 + 幂等启停与 1s 有界 join；新增 `WireLineCursor` 避免 sidecar 复制游标。二者都有明确计划偏差记录，未改帧语义或用量的口径。
6. **S5 把注册表也纳入公共层守卫**：只扫描中性 `spec.py`/`cache.py` 挡不住厂商元数据回流注册表；注册表加入词表扫描并移除设置键例外，才算真正收口。
7. **S6 的「同名包装 shim」用改名消除**：连接层必须保留 provider 调用的 `log_diagnostics()`，模块 helper 改名后，连接方法只做状态组装与委托。
8. **S1 截图归档副本的事实更正**：S1 回写记为「未提交」，实际 S1 提交包含 6 张 `文档/帧存档/` PNG；本文档按 git 事实记录，不把历史归档副本当作新增交付物。
9. **本轮未做真实后台端到端**：S0–S6 均为契约、删除、守卫与纯搬家；真实 Kimi/DSH 端到端与 Local 假 agent 全链路已在上一轮 T7 验收（真实 Local 因本机未安装未验证），本轮以旧/新对照、回放测试与截图哈希锁定等价性。
