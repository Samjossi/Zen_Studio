# 文件树头部显示当前分支落地计划

> **状态**：已实施（用户真机验证通过）
> **范围**：Git 数据层（`src/core/git/service.py`）、文件树头部（`src/gui/panels/file_explorer/explorer.py`）、主题样式（`assets/themes/base.qss`）、测试（`tests/`）
> **时间**：2026-11-05 21:29（设计，UTC+8）
> **优先级**：低

## 需求

1. 文件树（右栏上）头部当前只显示工作区根目录名（如 `zen_studio`），需在同一行追加当前 Git 分支名。
2. 分支变化（终端 checkout / 外部切换）后，头部显示随既有 Git 刷新链路更新，不新增独立探测。
3. 无 Git 环境时回退为现状（纯项目名），不显示任何占位报错。

## 探查结论（已实测核实）

### 数据可行性

在 git 2.43.0 上以临时仓库实测：

| 场景 | `git branch --show-current` | `git symbolic-ref --short HEAD` | `git rev-parse --short HEAD` |
|---|---|---|---|
| 正常分支 | `master` | `master` | 短哈希 |
| **零提交仓库**（刚 `git init`） | **`master`（未生成分支名照出）** | `master` | 退出码 128 |
| detached HEAD | 空串（exit 0） | 失败 | 短哈希 |

- 关键结论：**零提交 ≠ 没有分支名**。git 的 HEAD 始终指向一个分支引用（未生成分支），`branch --show-current` 直接给出名字，无需特殊处理。
- 现有 `src/core/git/log.py` `current_branch()` 已是同款查询（提交历史图弹窗在用），语义：`None` = 命令失败、空串 = detached、非空串 = 分支名（含未生成）。
- detached 场景补 `git rev-parse --short HEAD` 取短哈希（detached 必有提交，该命令不会撞上零提交的 exit 128）。

### 刷新链路（无需新增事件源）

`GitStatusController`（`src/gui/controllers.py`）已有六事件源 300ms 去抖汇流 → `refresh()` → 扇出四面板。其中「窗口激活」事件源正是为兜底终端 checkout 等外部 git 操作而设（见 `schedule_refresh` 注释），分支切换天然被覆盖。`GitStatusController.refresh()` 每次都调 `FileExplorer.apply_git_status(service)`，分支标签挂在这个既有调用里更新即可，**不动控制器、不新设定时器**。

### 头部现状

`explorer.py` 构造段：单 `QLabel`（`path_label`，objectName `PanelTitle`，居中，tooltip 为完整路径），`QHBoxLayout` 双 stretch 夹持。qss 侧 `assets/themes/base.qss` 已有 `#PanelHint`（次级灰提示样式）可直接复用于分支标签。

## 方案决策

### D1 显示形态：与项目名同行（用户已拍板）

头部一行两标签：`项目名`（`PanelTitle`，现状不动）+ `分支名`（新标签，复用 `PanelHint` 灰字样式，弱化主次）。

**分隔符候选池（用户已选定默认 `⎇`，其余留档备选）**：

| 符号 | 码位 | 说明 | 定位 |
|---|---|---|---|
| `⎇` | U+2387 | git 分支惯用符号（VS Code、终端主题通用） | **默认选用**；须截帧验证字体字形覆盖，豆腐块则按表序回退 |
| `⑂` | U+2442 | OCR 分支符，更像分叉图案；字体支持面比 `⎇` 窄 | 首选回退（同批截帧验证） |
| `·` | U+00B7 | 纯分隔点，无分支语义，任何字体都不缺 | 最终兜底 |
| `⌥` | U+2325 | 形状似岔路，但语义是 Option 修饰键，易误读 | 已否决（留档） |
| ` ` | U+F126 | Font Awesome code-branch 图标，形状最标准；属私有区图标字体，需引入字体依赖 | 已否决（不为此加依赖，留档） |
| `⟀` `⑃` 等 | — | 偏冷门，字体覆盖差 | 已否决（留档） |

超长防护：分支名经 `QFontMetrics.elidedText` 中间省略截断（上限取面板宽度的约一半），完整分支名放 tooltip。

### D2 数据层：GitStatusService 增加分支查询

- `refresh()` 在确认 `_repo_root` 后追加一次分支拉取（复用 `log.current_branch`，detached 时补 `rev-parse --short HEAD`），结果存入服务状态，随每次刷新更新。
- 对外暴露 `head_label: str | None` 属性：`None` = 非仓库/探测失败（UI 隐藏标签）；非空 = 已格式化的显示串（分支名或短哈希）。格式化放数据层的理由：调用方只有文件树一处，UI 层零分支判断，与 `collect_changes()` 的「数据层聚合、UI 直显」风格一致。
- 命令失败（如 rebase 锁）沿用服务既有「保留旧缓存静默降级」语义，不清空旧值。

### D3 各场景显示映射

| 场景 | `head_label` | 头部显示 |
|---|---|---|
| 非 git 仓库 / 无 git | `None` | 仅项目名（回退现状） |
| 正常分支 | 分支名 | `zen_studio ⎇ main` |
| **零提交仓库** | 分支名（未生成分支名） | `zen_studio ⎇ main`（不做特殊标注——git 本就视其在分支上，加标注反而制造无信息噪音；如需「尚无提交」提示另立计划） |
| detached HEAD | 短哈希 | `zen_studio ⎇ a1b2c3d`（tooltip 注明「游离头指针（detached HEAD）」） |

> 注：零提交标注、detached 文案两问用户未表态，本表为推荐默认值，实施前可一句话推翻。

### D4 更新时机

`FileExplorer.apply_git_status(service, theme)` 末尾追加分支标签更新：读 `service.head_label`，`None` 则清空并隐藏标签，否则 setText 并显示。主题切换走 `apply_theme` 不触碰文本（样式全在 qss，无色值硬编码）。

## 显示效果示例（改完后实际长这样）

文件树头部 = 截图中顶部写着 `zen_studio` 的那一条。下面每例左为**改动前**，右为**改动后**。

### 场景 1：正常分支（最常见）

Git 服务状态：`is_enabled = True`，`head_label = "main"`

```
改动前                          改动后
┌─────────────────────┐      ┌─────────────────────┐
│     zen_studio      │      │  zen_studio ⎇ main  │
├─────────────────────┤      ├─────────────────────┤
│ ▸ __pycache__       │      │ ▸ __pycache__       │
│ ▸ .build-tools      │      │ ▸ .build-tools      │
│ …（文件树不变）      │      │ …（文件树不变）      │
└─────────────────────┘      └─────────────────────┘
```

- `zen_studio`：半粗黑字（现状的 `PanelTitle` 样式，不动）
- `⎇ main`：紧跟其后，**灰色小字**（复用 `PanelHint` 样式），一眼区分主次
- 悬停 `⎇ main` 上 tooltip 显示完整分支名

### 场景 2：零提交仓库（刚 git init，一次提交都没有）

Git 服务状态：`is_enabled = True`，`head_label = "main"`（git 未生成分支名照出）

```
改动后（与场景 1 完全一样，无任何特殊标注）
┌─────────────────────┐
│  zen_studio ⎇ main  │
└─────────────────────┘
```

即你问的"没有 commit 时怎么办"：**照常显示 `main`**。因为 git 的 HEAD 从 `git init` 那一刻起就指向一个叫 `master`/`main` 的分支（只是还没有任何提交挂在上面），名字本身是可知的。实测输出：

```bash
$ git init repo && cd repo
$ git branch --show-current
master          # ← 零提交，名字照样有
```

### 场景 3：detached HEAD（游离头指针，如 checkout 到某个历史提交）

Git 服务状态：`is_enabled = True`，`head_label = "a1b2c3d"`（短哈希）

```
改动后
┌─────────────────────┐
│ zen_studio ⎇ a1b2c3d│
└─────────────────────┘
```

- 显示 commit 短哈希，悬停 tooltip：`游离头指针（detached HEAD）：a1b2c3d`
- 对应命令行里 `git checkout --detach` 或 `git checkout <某个commit>` 之后的状态

### 场景 4：非 git 目录（比如打开一个普通文件夹）

Git 服务状态：`is_enabled = False`，`head_label = None`

```
改动后 = 改动前（完全回退现状，分支标签整体隐藏）
┌─────────────────────┐
│   我的普通文件夹      │
└─────────────────────┘
```

不显示"无分支""非仓库"之类的占位文字——那是噪音，回退为纯项目名。

### 场景 5：长分支名（截断防护）

假设分支名是 `feature/very-long-branch-name-for-testing`，面板宽度有限时：

```
┌─────────────────────┐
│ zen_studio ⎇ featu… │   ← 分支名超长部分中间省略号截断
└─────────────────────┘
```

- 项目名永远完整显示，只截断分支名
- 悬停 tooltip 仍显示完整分支名

## 实施步骤

### 1. 数据层（`src/core/git/service.py`）

- `__init__` 新增 `_head_label: str | None = None`；`refresh()` 的 repo 确认分支后调用内部 `_fetch_head_label()`：
  - `log.current_branch(repo_root)` 返回非空串 → 分支名；
  - 返回空串（detached）→ `runner.run_git(repo_root, "rev-parse", "--short", "HEAD")` 取短哈希，失败则保留旧值；
  - 返回 `None`（命令失败）→ 保留旧值（静默降级）。
- 非仓库路径（`_repo_root is None`）置 `_head_label = None`。
- 新增只读属性 `head_label`。
- 模块 docstring 使用方式段补一行 `head_label` 说明。

### 2. 文件树头部（`src/gui/panels/file_explorer/explorer.py`）

- 构造段 `path_label` 之后新增 `branch_label`（objectName `PanelHint`），初始隐藏，插入既有 header 布局 `path_label` 之后；双 stretch 保持整体居中。
- `apply_git_status()` 末尾：按 `service.head_label` 更新（含 elidedText 截断与 tooltip——正常分支 tooltip 为完整分支名，detached 为「游离头指针（detached HEAD）：<短哈希>」）。
- 截断与分隔符合二为一抽模块级纯函数 `_format_branch_label(label, metrics, max_width)`（脱离 Qt 可单测，仿 `chat/panel.py` `_format_duration` 先例）。

### 3. 样式（`assets/themes/base.qss`）

- 复用 `#PanelHint` 既有规则，不新增选择器；若实测与标题行距需微调，仅在该规则内补属性。

### 4. 测试（`tests/`，offscreen）

- 数据层：仿 `tests/test_git_dir_status.py` 真临时仓库风格——init 仓库断言未生成分支名照出；提交后切分支断言更新；构造 detached（`checkout --detach`）断言短哈希；非目录/非仓库断言 `None`。
- 纯函数：`_format_branch_label` 超长截断、短名原样。
- 面板级：构造 `FileExplorer` + 注入服务，断言 `branch_label` 文本与显隐（仓库有分支显示、非仓库隐藏回退纯项目名）。

### 5. 文档同步（随代码同提交）

- `术语表.md` §1.6「文件树」行：补「头部显示项目名 + 当前分支（`⎇ 分支名`，detached 显示短哈希，非仓库仅项目名）」。
- `src/gui/panels/file_explorer/explorer.py` 模块 docstring 补头部构成说明。
