## 三、实施要点与工程细节

1. **路径归一化规则**（与选型文档一致，参考 Multi_Cli_Studio 的 `buildWorkspaceMentionText`）：`\` → `/`、去首尾多余斜杠、目录尾加 `/`、拼 `@` 前缀后尾随一个空格
2. **MIME 双写**：`setUrls()` + `text/uri-list` 同时设置（PyGPT 验证的兼容性最佳实践），使系统文件管理器拖入与树内拖出走同一解析路径
3. **解耦约束**：ChatInput/ChatPanel 不 import FileExplorer；工作区根路径由 MainWindow 单向注入
4. **不新增依赖**：全部使用 PySide6 与标准库（`os.path` / `pathlib`）
5. **注释规范**：拖拽相关的非常规处理（屏蔽树内 drop、双写 MIME 的缘由）需写明注释，风格与现有代码一致

### 与计划的偏差说明

1. **1.2 MIME 双写**：`QMimeData.setUrls()` 原生自动生成 `text/uri-list` 格式，等价于 PyGPT 手写双写，故未手写 `\r\n` 拼接；另将 drag 限定为 `CopyAction`，杜绝可写 `QFileSystemModel` 的移动语义（计划外加固）
2. **2.2 插入位置**：由"当前光标处"改为**拖拽落点**（`cursorForPosition(event.position())`），更符合拖拽直觉，与 theia-zen 的 Monaco 落点插入行为一致
3. **2.4 越界策略**：按计划建议采用前者——工作区外路径插入绝对形式 `@路径`
4. **0.4 ACP 验证方式**：ACP 为 stdio JSON-RPC 长驻服务，无法如 `-p` 单发实测，改为"同源推论 + 端到端走查"两步

### 踩坑记录

- **PySide6 生命周期段错误**：冒烟脚本中 `QDropEvent`/`QMimeData` 作为临时对象被 Python GC 回收后，C++ 侧悬垂指针引发段错误（exit 139）；探针内用 `_keepalive` 列表保活解决。真实 GUI 中事件由 Qt 事件循环派发，无此问题
- **Qt6 API 名**：`QTreeView` 的 drop 指示 getter 为 `showDropIndicator()`（setter `setDropIndicatorShown()`，二者不对称）

### 测试结论

- offscreen 冒烟：13 项断言全过（`.venv/bin/python .temp/chat_drop_smoke.py`）
- 主窗口装配冒烟：ChatInput 与 FileExplorer 根路径同源断言通过，窗口构建/关闭无异常
- **人工走查**：4.1 光标观感、4.5 系统文件管理器拖入、4.6 含空格路径、4.8 端到端发送——2026-07-20 需求方真实桌面走查全部确认通过
