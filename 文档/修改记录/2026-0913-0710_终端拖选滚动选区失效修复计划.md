# 终端拖选滚动选区失效修复计划

> **状态**：已实施（2026-09-13）
> **范围**：`gui/panels/terminal/`（widget.py、selection.py、screen.py）、`tests/`
> **时间**：2026-09-13 07:10（设计）/ 2026-09-13 08:37（实施）(UTC+8)
> **优先级**：高

---

## 1. 问题现象（用户反馈）

终端输出长文本（超出可视区、出现回滚滚动条）时，用户按住左键拖选多行：

- 鼠标拖到可视区边缘、需要滚动才能继续选中下面的内容时，**已选中的内容立刻被清空**；
- 期望行为：拖到边缘应自动滚动、选区持续保留并继续扩大，直到能把整段输出一次性复制走。

## 2. 根因定位

终端为自绘字符网格（`gui/panels/terminal/widget.py`），选区状态机在
`gui/panels/terminal/selection.py`（纯逻辑），语义层在
`gui/panels/terminal/screen.py`（pyte HistoryScreen 封装）。

根因有两点，均源于现行设计"选区 = **可视快照行坐标**，视图迁移即失效"：

### 2.1 选区坐标绑定可视快照，一切视图变化都清选区

`SelectionController` 的端点是"当前可视快照里的 (y, x)"，而非缓冲区绝对行坐标。
因此代码在多处主动 `clear_selection()`：

| 清除点 | 位置（widget.py 方法） | 触发场景 |
|:---|:---|:---|
| 滚轮回滚 | `wheelEvent` | 选中后滚一下滚轮即清 |
| 新数据推屏 | `notify_data`（`scroll_offset == 0` 时） | **拖选途中终端仍在输出 → 每来一块输出选区即被清**，这是"拖到一半立刻清空"的主凶 |
| resize / 字号变化 | `resizeEvent` / `refresh_font` | 窗口尺寸变化 |
| 换屏（切 tab/重开/清空） | `set_screen` | 会话切换 |
| 键盘输入 / 粘贴 | `keyPressEvent` / `paste_clipboard` | 输入即清 |

另外滚动条拖动（`_on_scroll`）本身不清选区，但因为坐标是快照相对的，
滚动后高亮会"钉"在错误的行上——选区内容已经错位，形同失效。

### 2.2 拖拽到边缘没有自动滚动（auto-scroll）

`mouseMoveEvent` 把鼠标像素经 `pos_to_cell` **clamp 进可视网格**，拖到下边缘
就只能选中最后一行，无法把选区延伸进回滚区或新输出区。标准终端（xterm、
Konsole、Windows Terminal）在拖到边缘时会定时自动滚动并继续扩选，本程序缺此机制。

## 3. 修复方案

核心思路：**选区坐标从"可视快照行"改为"缓冲区绝对行"**，视图迁移不再使选区
失效；再补**拖拽边缘自动滚动**。

### 3.1 绝对行坐标模型

定义绝对行号 = 拼接缓冲区（`history.top` + 当前屏各行）中的行下标。

- 正常输出推屏时，一行从屏内滚入 `history.top` 末尾，其在拼接缓冲区中的
  下标**不变** → 新数据到达不再需要清选区；
- 滚动只改可视窗口起点，不改绝对坐标 → 滚轮/滚动条不再需要清选区，
  且高亮始终钉在正确的内容上；
- 仍需清除的场景：resize 列数变化（重排 reflow）、`set_screen` 换屏。

改动点：

1. `screen.py`：新增绝对行读取接口，如
   `abs_row_count() -> int` 与 `abs_rows(start, end) -> list[行]`（半开区间，
   越界 clamp），内部复用现有 `history.top + buffer` 拼接逻辑。
2. `selection.py`：选区端点语义改为绝对行坐标；`extract_text` 改为接收
   绝对行序列（由调用方按选区范围取行），不再吃可视快照。
3. `widget.py`：
   - `press`/`drag` 时把像素坐标 → 可视行 → 加当前窗口起点换算为绝对行；
   - `_paint_selection` 反向换算：绝对选区 ∩ 当前可视窗口，只画可见部分；
   - 删除 `wheelEvent`、`notify_data` 中的 `clear_selection()`；
     保留 `resizeEvent`（仅列数变化时）、`refresh_font`、`set_screen`、
     键盘输入/粘贴处的清除语义。

### 3.2 回滚历史上限溢出的处理

pyte `history.top` 是有界 deque（当前上限 1000 行），溢出时**顶部旧行被丢弃**，
绝对坐标整体前移。处理策略（从简）：

- `screen.py` 维护单调递增的"已丢弃行数"计数（或直接用 pyte 暴露的长度差推算），
  换算时把选区行号减去丢弃数；锚点整段被丢弃出历史时选区自然 clamp/清除。
- 若实现时发现 pyte 不暴露该信息，降级方案：溢出发生时一次性清除选区
  （概率极低，可接受），但必须在 docstring 中记录该取舍。

### 3.3 拖拽边缘自动滚动

- `mouseMoveEvent`：拖拽中鼠标 y 超出文本区（上边缘之上 / 下边缘之下，含拖入
  滚动条区）时，按超出量滚动滚动条（每事件 1~3 行），并用 clamp 后的边缘行
  继续更新选区活动端点；
- 增加一个 `QTimer`（如 50ms）：鼠标停在边缘不动时持续滚动 + 扩选，
  移回网格内或松键即停。滚动到底/顶边界自动停；
- 滚动本身走现有 `QScrollBar.setValue` 路径，不再触发选区清除（3.1 已解除）。

### 3.4 复制路径不变

`copy_selection` / 右键菜单"复制" / Ctrl+Shift+C（或反转模式 Ctrl+C）入口不变，
只是 `selected_text()` 内部改走绝对行取文本。

## 5. 验收标准

1. 终端持续输出长文本时，拖选途中选区**不再被新输出清空**；
2. 拖到下边缘自动向下滚动并持续扩选，可一路选到回滚区最底部/最新输出；
3. 选中后滚轮/拖动滚动条查看上下文，选区保留且高亮钉在原内容上；
4. 复制得到的文本与屏幕上选区覆盖的内容一致（跨滚动区、行尾无网格补白）；
5. resize / 换屏 / 键盘输入的原有清除语义不回归；
6. `scripts/check.sh` 全绿。

## 6. 风险与注意

- ⚠️ 绝对行坐标与 pyte 有界历史的相互作用是最大坑点（任务 5），实现时先写
  对应单测再动 widget；
- ⚠️ `notify_data` 不再清选区后，高频输出 + 大选区的重绘成本需留意，必要时
  选区绘制仍走现有 30ms 节流链路即可，不额外优化；
- 注释只写 why，变更历史归 `文档/修改记录/`（本计划完成后归档至该目录）。

## 7. 实施结果（2026-09-13）

按任务清单全部落地，验收标准 1/2/3/4 经实机验证通过（用户确认），5/6 由
`tests/test_terminal_selection.py`（新增 12 项）覆盖，`scripts/check.sh` 全绿。

与方案的偏差：

- 任务 5 采用正方案而非降级方案：`_TolerantScreen` 以 `pushed_lines` 计数
  反推绝对行号基线（`base = pushed_lines - len(history.top)`），回滚溢出时
  旧内容行号保持稳定；另加 `history_generation`（reset / ED 3 时递增），
  widget 按下时记录代数，绘制/取文本前比对，不一致即作废选区。
- 实现中发现 pyte 构造链会经 `reset → _reset_history` 先触达这两个属性，
  故须在 `super().__init__` 之前赋值（源码注释已记）。
