## 1. 定位

项目「章程 → 选型 → 计划 → 修改记录」四级文档流的**归档层**：`work plans/`、`work options/` 等目录中已完成批次的文档封存于此，外加审计报告、理论依据与提示语句等长期参考材料。

⚠️ **归档文档记录的是撰写当时的状态**——其中提及的「已知问题」「待办项」可能已在后续修复，**请勿以归档文档推断当前代码**；当前状态以代码与根目录 `README.md`、`gui/README.md`、`llm/README.md` 为准。

## 2. 子目录

| 子目录 | 内容 |
|:---|:---|
| `文档/修改记录/` | 全部实施计划与诊断报告归档（`YYYY-MMDD-HHMM_标题.md` 时间戳命名，数量最大的子库） |
| `文档/选型记录/` | 技术选型论证归档（聊天面板 / 高亮 / 终端 / Git 装饰 / 菜单体系 / 主题 / 四项预览等） |
| `文档/审计报告/` | 实质代码审计与协议补全建议（含 theia 审计、裸 API/CLI/ACP 三模式对比） |

| `文档/提示语句/` | 可复用提示词与协议模板（AGENTS 变体、配置治理协议、记忆银行、临时目录规范等） |
| `文档/封存文档/` | 完全封存的历史批次（仅存档，不再引用） |
| `文档/GUI显示详细说明/` | GUI 显示机制的详细说明材料 |

## 3. 纪律

- 归档文档命名与头部元信息遵循 `文档编写规范.md`（v3.0）；`文档/` 下文档须在标题后插入 **§3.2 归档声明**（措辞固定，禁止改写）；
- 文件引用一律反引号纯文本：带时间戳文档仅写文件名，无时间戳文档（如本 README）写项目根相对路径；
- 归档为**单向操作**：文档移入本库后不再回改内容（纠错以新文档为准），保持历史现场。
