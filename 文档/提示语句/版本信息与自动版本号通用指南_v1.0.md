# 版本信息与自动版本号通用指南 v1.0

> **版本**：v1.0 | **创建**：2026-09-18 19:36 (UTC+8) | **最后修订**：2026-09-18 19:36 (UTC+8)
> **适用对象**：以 `pyproject.toml` 管理版本、git 管理源码、PyInstaller 打包桌面/命令行产物的 Python 项目。
> **目标**：版本号**单一来源**、构建号随提交**自动递增**、产物**内部携带完整版本元数据**、界面与日志**同源显示**——拿到任何一个产物或截图，都能立刻说出它是哪一版、对应哪次提交。
> **原理一句话**：人只维护 `pyproject.toml` 里的三段基础版本，构建号交给 `git rev-list --count HEAD` 自动 +1，其余一切（产物元数据、界面显示、日志打印）全部从这两处派生，任何地方不允许再出现硬编码版本串。

## 一、解决什么问题

没有版本治理的项目，通常同时患有三个病：

1. **版本号多处硬编码**：`pyproject.toml` 一份、关于对话框一份、设置页一份——改一处忘两处，界面显示的版本永远是错的；
2. **产物无元数据**：打出来的 AppImage / exe 没有任何版本信息，右键属性空白，拿到产物无从得知它是哪一版；
3. **版本递进全靠手改**：没有构建号，同一基础版本两次构建的产物无法区分新旧。

本指南的对应药方：

| 病 | 药 |
|:---|:---|
| 多处硬编码 | `pyproject.toml` 为唯一来源，代码与产物全部派生（§四、§五） |
| 产物无元数据 | 版本写入产物**内部**：Linux 注入版本文件 + desktop 字段，Windows 嵌入版本资源（§六） |
| 无构建号 | 构建号 = git 提交计数，每次提交自动 +1，零维护、可回溯（§二） |

## 二、版本号模型

```
# 版本号构成（示例）
基础版本 0.1.0   ← pyproject.toml，人工拍板、version.py bump 代改
构建号        42  ← git rev-list --count HEAD，每次提交自动 +1，零维护
完整版本 0.1.0.42 ← 四段拼接，产物、界面、日志统一使用
```

设计要点：

- **四段而非三段**：与 Windows 版本资源 `filevers` 原生四段对齐，两端产物内部统一；
- **构建号取提交计数**而非时间戳或自增文件：零仓库 churn（不需要每次构建都改一个计数文件再提交）、天然单调递增、可直接 `git checkout HEAD~N` 回溯到对应提交；
- **产物文件名固定不带版本**：新构建直接覆盖旧文件，新旧不并存堆积；版本只在文件内部与界面上可见。将来出现多版本并存分发需求时，再给文件名追加版本字段；
- **不引入 setuptools-scm 等三方依赖**：一个 `version.py` 自管，先能跑再打磨。

## 三、总体架构

```
pyproject.toml（唯一来源，三段基础版本）
        │
        ├── packaging/version.py ──── 构建脚本 $(...) 捕获完整版本
        │      ├── get   → 0.1.0.42      ├──→ Linux: desktop X-AppImage-Version
        │      └── bump patch/minor/major └──→ Windows: spec 内同规则自算
        │
        └── src/app_info.py（应用内解析链）
               冻结态读 bundle version.txt
               → importlib.metadata → 直读 pyproject.toml 兜底
               → git 仓库内追加提交计数
                     │
                     └──→ 关于对话框 / 设置页 / 启动日志
```

关键约束：**spec（PyInstaller 构建定义）是独立运行的 Python 文件，版本在 spec 内按同规则自算，与 `version.py` 不互相 import**——spec 的运行环境由 PyInstaller 控制，项目内模块未必可导入。

## 四、version.py：版本中枢

放在仓库的打包脚本目录（如 `packaging/`），提供两个子命令：

| 命令 | 行为 |
|:---|:---|
| `get` | 打印完整版本（如 `0.1.0.42`），供构建脚本 `$(...)` 捕获；非 git 环境（如拷贝源码树）退化为三段基础版本 |
| `bump patch/minor/major` | 改写 `pyproject.toml` 基础版本并打印新值；只改文件，提交由人决定 |

完整实现（可直接拷贝，仅需确认 `ROOT` 定位与 lock 刷新段与项目匹配）：

```python
# packaging/version.py
"""版本中枢：pyproject.toml 为版本唯一来源，构建号取 git 提交计数。

完整版本号四段 major.minor.patch.build，与 Windows 版本资源 filevers 对齐。
构建脚本经 `get` 捕获完整版本；spec 运行环境独立，按同规则自算，不 import 本模块。

用法：
    python packaging/version.py get           # 打印完整版本（如 0.1.0.42）
    python packaging/version.py bump patch    # 基础版本 +0.0.1 并打印新值
"""

import re
import subprocess
import sys
import tomllib
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
PYPROJECT = ROOT / "pyproject.toml"


def base_version() -> str:
    with open(PYPROJECT, "rb") as f:
        return tomllib.load(f)["project"]["version"]


def build_number() -> str | None:
    """git 提交计数；非 git 环境（如拷贝源码树、浅克隆失真）返回 None。"""
    try:
        out = subprocess.run(
            ["git", "rev-list", "--count", "HEAD"],
            cwd=ROOT,
            capture_output=True,
            text=True,
            check=True,
        )
        return out.stdout.strip()
    except (OSError, subprocess.CalledProcessError):
        return None


def full_version() -> str:
    base = base_version()
    build = build_number()
    return f"{base}.{build}" if build else base


def bump(part: str) -> str:
    """改写 pyproject.toml 基础版本；只改文件，提交由人决定。"""
    major, minor, patch = (int(x) for x in base_version().split("."))
    if part == "major":
        major, minor, patch = major + 1, 0, 0
    elif part == "minor":
        minor, patch = minor + 1, 0
    else:
        patch += 1
    new = f"{major}.{minor}.{patch}"
    text = PYPROJECT.read_text(encoding="utf-8")
    text, count = re.subn(r'(?m)^version = "[^"]+"', f'version = "{new}"', text, count=1)
    if count != 1:
        raise SystemExit("错误：pyproject.toml 中未定位到 version 行")
    PYPROJECT.write_text(text, encoding="utf-8")
    # uv.lock 记录本项目版本，不刷新则 uv lock --check 失败；不用 uv 的项目删除本段
    try:
        subprocess.run(["uv", "lock"], cwd=ROOT, check=True, capture_output=True)
    except (OSError, subprocess.CalledProcessError) as exc:
        print(f"警告：uv.lock 刷新失败（{exc}），请手动执行 uv lock", file=sys.stderr)
    return new


def main() -> int:
    args = sys.argv[1:]
    if args == ["get"]:
        print(full_version())
        return 0
    if len(args) == 2 and args[0] == "bump" and args[1] in ("patch", "minor", "major"):
        print(bump(args[1]))
        return 0
    print(__doc__, file=sys.stderr)
    return 2


if __name__ == "__main__":
    sys.exit(main())
```

⚠️ `bump` 实测坑：若项目用 uv 管理依赖，`uv.lock` 会记录本项目自身版本，bump 后 `uv lock --check` 失败——所以 `bump` 内置了自动 `uv lock` 刷新。用 pip/poetry 等其他工具的项目，替换或删除该段。

## 五、应用内版本解析链

应用代码（GUI 关于页、设置页、CLI 启动日志）统一从一个 `app_info.py` 取版本，解析链按运行形态逐级兜底：

```
冻结态（PyInstaller）→ 读 bundle 内 version.txt（spec 构建时注入，已是完整版本）
脚本态 → importlib.metadata（项目已 uv sync / pip install -e）
       → 直读 pyproject.toml（未安装过的源码树兜底）
git 仓库内 → 追加提交计数作构建号，与冻结态显示一致
```

完整实现（可直接拷贝，仅需改 `APP_NAME` / `APP_DESCRIPTION` 与包名）：

```python
# src/app_info.py
"""应用身份信息：名称/描述常量 + 版本解析链。

pyproject.toml 是版本唯一来源。冻结态（PyInstaller）读 bundle 内 version.txt
（spec 构建时注入，已是含构建号的完整版本）；脚本态走 importlib.metadata，
未经安装的源码树退化为直读 pyproject.toml；git 仓库内再追加提交计数作构建号。
"""

import importlib.metadata
import subprocess
import sys
import tomllib
from pathlib import Path

APP_NAME = "我的应用"                 # ← 按项目改
APP_DESCRIPTION = "一句话描述"        # ← 按项目改

_ROOT = Path(__file__).resolve().parent.parent


def full_version() -> str:
    frozen = getattr(sys, "_MEIPASS", None)
    if frozen is not None:
        bundled = Path(frozen) / "version.txt"
        if bundled.is_file():
            return bundled.read_text(encoding="utf-8").strip()
    base = _base_version()
    build = _build_number()
    return f"{base}.{build}" if build else base


def _base_version() -> str:
    try:
        return importlib.metadata.version("my-app")  # ← 改为 pyproject.toml 的 name
    except importlib.metadata.PackageNotFoundError:
        pass
    try:
        with open(_ROOT / "pyproject.toml", "rb") as f:
            return tomllib.load(f)["project"]["version"]
    except (OSError, KeyError):
        return "0.0.0"


def _build_number() -> str | None:
    try:
        out = subprocess.run(
            ["git", "rev-list", "--count", "HEAD"],
            cwd=_ROOT,
            capture_output=True,
            text=True,
            check=True,
        )
        return out.stdout.strip()
    except (OSError, subprocess.CalledProcessError):
        return None
```

界面接法（消灭所有硬编码版本串）：

```python
# src/main_window.py（关于对话框示例，GUI 框架无关）
import app_info

box.setText(
    f"{app_info.APP_NAME}\n"
    f"版本 {app_info.full_version()}\n"
    f"{app_info.APP_DESCRIPTION}"
)
```

命令行程序同理，启动首行打印 `f"{APP_NAME} {full_version()}"`，再打印其余运行信息。若项目有多个独立打包的入口（如服务端、工具集），每个入口放一份各自的解析函数即可，规则不变。

## 六、产物元数据注入

原则：**版本写进产物内部，文件名保持固定**。PyInstaller spec 是 Python 文件，版本在 spec 内按 §四 同规则自算（tomllib 读 `pyproject.toml` + git 提交计数），不 import 项目模块。

### 6.1 Linux（AppImage）

spec 顶部自算版本并写出 `version.txt`，经 `datas` 收编进 bundle（PyInstaller 6+ onedir 会落到 `_internal/`，即冻结态 `sys._MEIPASS`，与解析链读取位置一致）：

```python
# packaging/controller.spec（片段：Analysis 之前）
import os
import subprocess
import tomllib

_ROOT = os.path.abspath(os.path.join(SPECPATH, os.pardir))


# 与 version.py 同规则自算（spec 运行环境独立，不互相 import）：
# 基础版本读 pyproject.toml，构建号取 git 提交计数，非 git 环境退化为三段
def _full_version():
    with open(os.path.join(_ROOT, "pyproject.toml"), "rb") as f:
        base = tomllib.load(f)["project"]["version"]
    try:
        build = subprocess.check_output(
            ["git", "rev-list", "--count", "HEAD"], cwd=_ROOT, text=True
        ).strip()
        return f"{base}.{build}"
    except Exception:
        return base


# 冻结态界面读 bundle 内 version.txt（src/app_info.py）
_VERSION_TXT = os.path.join(_ROOT, ".temp", "build", "version.txt")
os.makedirs(os.path.dirname(_VERSION_TXT), exist_ok=True)
with open(_VERSION_TXT, "w", encoding="utf-8") as f:
    f.write(_full_version() + "\n")

# Analysis 的 datas 追加：(_VERSION_TXT, ".")
```

构建脚本在组装 AppDir 时给 desktop 文件追加 `X-AppImage-Version`：

```bash
# packaging/build_linux.sh（片段：desktop 文件拷入 AppDir 之后）
VERSION="$(.venv/bin/python packaging/version.py get)"
echo "X-AppImage-Version=$VERSION" >> "$APP_DIR/myapp.desktop"
```

### 6.2 Windows（exe 版本资源）

spec 生成 VSVersionInfo 版本资源嵌入 exe，右键属性页可见文件说明/产品名/版本；同时注入 `version.txt` 供程序启动时打印。`CompanyName`/版权字段没有真实分发主体时**留空不编**，出现真实主体再补。

```python
# packaging/app.spec（片段：Analysis 之前）
import os
import subprocess
import tomllib

from PyInstaller.utils.win32.versioninfo import (
    FixedFileInfo,
    StringFileInfo,
    StringStruct,
    StringTable,
    VarFileInfo,
    VarStruct,
    VSVersionInfo,
)

_ROOT = os.path.abspath(os.path.join(SPECPATH, os.pardir))


def _full_version():  # 与 6.1 完全相同的规则
    with open(os.path.join(_ROOT, "pyproject.toml"), "rb") as f:
        base = tomllib.load(f)["project"]["version"]
    try:
        build = subprocess.check_output(
            ["git", "rev-list", "--count", "HEAD"], cwd=_ROOT, text=True
        ).strip()
        return f"{base}.{build}"
    except Exception:
        return base


_VERSION = _full_version()

_BUILD_DIR = os.path.join(_ROOT, ".temp", "build")
os.makedirs(_BUILD_DIR, exist_ok=True)

# 冻结态启动打印读 bundle 内 version.txt
_VERSION_TXT = os.path.join(_BUILD_DIR, "version.txt")
with open(_VERSION_TXT, "w", encoding="utf-8") as f:
    f.write(_VERSION + "\n")

# exe 版本资源（右键属性页可见）
_parts = [int(p) for p in (_VERSION.split(".") + ["0"] * 4)[:4]]
_version_info = VSVersionInfo(
    ffi=FixedFileInfo(
        filevers=tuple(_parts),
        prodvers=tuple(_parts),
        mask=0x3F,
        flags=0x0,
        OS=0x40004,
        fileType=0x1,
        subtype=0x0,
        date=(0, 0),
    ),
    kids=[
        StringFileInfo(
            [
                StringTable(
                    "080404B0",  # 中文(简体)+ Unicode 代码页
                    [
                        StringStruct("FileDescription", "我的应用"),
                        StringStruct("ProductName", "MyApp"),
                        StringStruct("FileVersion", _VERSION),
                        StringStruct("ProductVersion", _VERSION),
                    ],
                )
            ]
        ),
        VarFileInfo([VarStruct("Translation", [0x0804, 1200])]),
    ],
)
_VERSION_INFO_FILE = os.path.join(_BUILD_DIR, "version_info.txt")
with open(_VERSION_INFO_FILE, "w", encoding="utf-8") as f:
    f.write(str(_version_info))

# Analysis 的 datas 追加：(_VERSION_TXT, ".")
# EXE 追加参数：version=_VERSION_INFO_FILE
```

⚠️ `PyInstaller.utils.win32.versioninfo` 仅在 Windows 可导入（内部依赖 win32api 与 pefile），Linux 开发机上无法预演该段——属正常现象，Windows 打包机首跑验证即可；`pefile` 在 Windows 上随 PyInstaller 自动安装，无需手动补。

## 七、界面与日志显示约定

- 关于对话框：Logo + 应用名 + `版本 <完整版本>` + 一行描述，全部取自 `app_info`；
- 设置页「版本」行同源显示；**脚本态与冻结态显示必须一致**（解析链已保证）；
- 命令行/服务端程序启动首行打印 `应用名 <完整版本>`，再打印其余运行信息——日志里永远能查到运行的是哪一版；
- 全仓库 grep 不得再出现任何硬编码版本串（验收时执行，见 §八）。

## 八、落地检查清单与验收标准

新项目接入时按序执行：

- [ ] `pyproject.toml` 确认 `version` 字段为三段基础版本；
- [ ] 拷入 `packaging/version.py`（§四），实测 `get` 输出四段版本、`bump patch` 改写正确后还原；
- [ ] 拷入 `src/app_info.py`（§五），改名称/描述/包名三处；界面关于页、设置页、启动日志全部改读 `app_info`；
- [ ] grep 全仓库，消灭剩余硬编码版本串；
- [ ] Linux spec 注入 `version.txt` + 构建脚本 desktop 加 `X-AppImage-Version`（§6.1），重建产物实测：固定名覆盖旧文件、bundle 内版本文件存在、冻结态界面显示完整版本；
- [ ] Windows spec 生成 VSVersionInfo（§6.2），打包机实测：exe 右键属性页元数据齐全、启动首行打印版本；
- [ ] 连续两次构建（中间隔一次提交）产物同名覆盖、版本号自动递增。

验收标准：

- [ ] `pyproject.toml` 为版本唯一来源，代码内无硬编码版本串（grep 验证）；
- [ ] 产物文件名固定，新构建直接覆盖旧文件；exe 属性页元数据齐全，AppImage desktop 带 `X-AppImage-Version`；
- [ ] 界面与日志在脚本/冻结两态显示完整版本与描述；
- [ ] 构建号随 git 提交自动递增；`bump` 子命令一键改基础版本。

## 九、已知坑与边界

- ⚠️ **浅克隆构建号失真**：构建号依赖 git 历史，`--depth 1` 克隆下提交计数恒为 1；打包机 / CI 克隆必须全量历史（CI 中 `fetch-depth: 0`）；
- ⚠️ **未安装的源码树**：`importlib.metadata` 在未 `uv sync` / 未 `pip install -e` 的源码树上拿不到版本，解析链必须保留直读 `pyproject.toml` 兜底（§五实现已含）；
- ⚠️ **lock 文件联动**：uv 管理的项目 `uv.lock` 记录自身版本，`bump` 后必须同步刷新，否则 `uv lock --check` 失败（§四实现已内置）；
- ⚠️ **非 git 环境退化**：拷贝源码树（无 `.git`）下构建号缺失，版本退化为三段——属预期行为，不视为错误；
- 🔴 **禁止**在 spec 里 import 项目模块（含 `version.py` 自身）：spec 运行环境独立，版本规则在 spec 内重写一份，保持「同规则、双实现」。
