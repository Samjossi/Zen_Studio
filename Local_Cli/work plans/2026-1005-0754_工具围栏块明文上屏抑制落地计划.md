## 1. 背景与目标

本地模型工具栈（`2026-1005-0445_本地模型工具栈实现计划_GGUF打通文件读写.md`，
已实施）在 IDE 实测中暴露一个观感缺陷：模型调用工具时，` ```tool_call{...} ``` `
围栏块以**明文形式**出现在聊天正文里，随后才渲染出正式的工具卡片——同一条
工具调用既裸奔又打卡。云端后台（kimi 等）无此现象：它们的 CLI 在内部解析掉
工具调用，只发结构化 `tool_call` 帧，IDE 只渲染卡片。

根因（已定位）：工具循环的流式路径「先全量上屏、后解析」——
`local_cli/acp/tool_loop.py` 的 `_stream_iteration` 把每个正文 chunk 即时作为
`agent_message_chunk` 上屏，整段流结束后才解析出围栏块并补发 `tool_call` 帧，
此时明文早已上屏、无法收回。上一期计划 §6 风险表已将此记录为 v1 接受的取舍
（「后续可做隐藏」），本期即为兑现该后续项。

本期目标：

- ✅ 服务端流式抑制：工具轮次的消息流（`agent_message_chunk` 通道）中**不再
  出现** tool_call 围栏块文本；正式 `tool_call` 帧照常发，IDE 只渲染卡片。
- ✅ 模型在围栏块**之后**追加的正文（实测存在：模型会在围栏后写「已成功写入…」）
  照常补发上屏，不吞模型的正常话语。
- ✅ 普通 markdown 代码块（```json 等任意语言标记）零误伤；纯文本回复上屏内容
  逐字节不变。
- ✅ 解析失败（有围栏起始标记但 JSON 坏/未知工具）时，被扣留的原文**补发上屏**
  ——让用户看到模型的错误输出，与错误回灌的透明语义一致。
- ❌ 不改 IDE 渲染层；不改 parser 语义；不改 `tools_enabled=false` 回退路径
  （该路径不过滤，围栏块按纯文本上屏的 spike 断言保持）；思维链通道不过滤。

验收主线：**IDE 实测场景复测——让本地模型写 poem.md，聊天里只出现工具卡片
与模型的自然语言，全程无围栏块明文；spike 新增「消息流不含围栏标记」断言。**

## 3. 总体设计

### 3.1 核心思路：尾部扣留（holdback）+ 疑似即扣

在 `_stream_iteration` 的上屏出口串一个**流式过滤器**，对正文通道做两态处理：

```text
# 状态机（正文通道；思维链通道直通不过滤）
NORMAL  ──发现完整起始标记──▶  SUSPEND（标记及其后全部扣留，不再上屏）
NORMAL  ──流结束，无标记────▶  扣留余量原样补发（纯文本轮次逐字节不变）
SUSPEND ──流结束────────────▶  交 parser 裁决：
                                 合法工具调用 → 围栏块丢弃，块后正文补发
                                 解析失败     → 扣留原文全部补发（透明）
```

### 3.2 尾部扣留窗口

流式 chunk 可能把起始标记**切开**（如 `"``"` + `"`tool_ca"` + `"ll\n"`），过滤器
必须保证不错检：始终扣住尾部至多「标记长度 − 1」个字符，仅当尾部不再可能是
起始标记的前缀时才放行前缀部分上屏。

- 起始标记的唯一定义来自 `toolkit/definitions.py`（与 parser 的
  `TOOL_CALL_BLOCK_PATTERN` 同源），含模型可能的格式变体（标记后换行/空格）。
- 扣留窗口极小（标记十来个字符），上屏节奏的人眼感知无差异。
- 起始标记出现在正文中间也正确处理：标记前的正文已安全上屏，自标记起扣留。

### 3.3 模块落点

| 变更 | 文件 | 说明 |
|:---|:---|:---|
| 新增流式过滤器 | `local_cli/toolkit/fence_filter.py`（新） | 纯逻辑类（如 `ToolCallFenceFilter`）：喂 chunk、吐「可上屏文本」，流结束时给「扣留原文」；不 import acp/model，verify_extras 可直接单测 |
| 接线 | `local_cli/acp/tool_loop.py` | `_stream_iteration` 上屏前过滤；流结束按 parser 裁决决定补发/丢弃（§3.1 状态机） |
| 共享标记常量 | `local_cli/toolkit/definitions.py` | 若现常量不足以直接表达「起始标记」，在此补齐定义（parser 同步复用，单一出处） |

设计约束：

- **行为不变量**：无围栏块的轮次，上屏字节流拼接后与现状完全一致（扣留只是
  延迟、终必补发）；思维链、usage、tool_call 帧序列全部不变。
- **过滤器不做合法性裁决**：它只认「起始标记」，合法与否仍归流结束后的
  parser——过滤器误扣的唯一后果是延迟上屏，不会错误丢弃。
- cancel/error 收尾路径中扣留未上屏的文本直接弃置（轮次已终结，无补发对象）。

## 5. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---|:---|
| 模型输出标记变体（```后带空格、大小写漂移）导致过滤器与 parser 识别不一致 | 🟡 | 起始标记定义在 definitions.py 单一出处，过滤器与 parser 强制共用；变体容忍度与 parser 正则严格对齐 |
| 过滤器误扣普通代码块 | 🟢 | 只认 `tool_call` 语言标记；误扣后果仅为延迟上屏，流结束必补发，不丢内容 |
| 扣留窗口拖慢上屏节奏 | 🟢 | 窗口仅标记长度级（十余字符），人眼无感；思维链通道直通不受影响 |
| 解析失败时用户看不到模型原始错误输出 | 🟡 | 状态机明确：parser 裁决失败则扣留原文全量补发，透明可追查 |
| 抑制后模型「围栏+已成功」式抢跑话语显得突兀 | 🟢 | 块后正文如实补发是刻意选择（不吞模型话语）；观感问题归 system prompt 文案调优，不在本期 |
