## 1. 背景与目标

Dream CLI 定位为一个**本地语言模型服务端**：在本机加载一个本地语言模型，
通过 ACP（Agent Client Protocol）与 IDE 类前端（Zen Studio）对接。前端以
`dream acp` 启动长驻子进程，走 stdio ndjson JSON-RPC 完成握手、会话、
流式对话、工具审批与取消。

本期目标：

- ✅ 搭建 Dream CLI 服务端工程骨架，**先把连接路线打通**。
- ✅ 支持两种运行模式：**CLI**（`dream acp`，stdio 协议模式）与 **GUI**
  （PySide6 桌面界面）。
- ✅ 本地模型本期**不实现，用 Mock 数据替代**：固定/规则化回复、模拟流式
  输出、模拟 usage 统计，保证协议链路完整可验。
- ❌ 不做真实模型推理（llama.cpp / transformers 等接入留待后续阶段）。
- ❌ 本期不做打包分发（AppImage 等）、不做安装器与 `~/.dream` 落盘逻辑。

验收主线：**前端 IDE 通过 ACP 协议连上本服务端，完成握手 → 建会话 →
流式对话 → 工具审批 → 取消 的全链路，且能用 spike 断言脚本逐条回归。**

## 3. 总体设计

### 3.1 双模式入口

同一套服务端内核，两种启动方式：

```bash
# 模式一：CLI —— ACP 协议模式（前端 IDE 以子进程拉起，argv 恒为 [bin, "acp"]）
dream acp

# 模式二：GUI —— PySide6 桌面界面（本地调试与可视化入口）
dream gui        # 或无参数默认 GUI，待定
```

设计要点：

- **协议内核与 UI 解耦**：ACP 协议层（帧读写、方法分发、会话管理、轮次执行）
  为独立模块，不 import 任何 GUI 代码；GUI 通过内核的公共接口启动/停止
  服务、查看会话与日志。
- **日志纪律**：CLI 协议模式下 stdout **只写协议帧**，一切日志走 stderr
  （协议 §1.2 / 附录 A.6）；GUI 模式下日志落 GUI 面板与文件。
- **模型层抽象**：定义统一的模型接口（如 `generate(messages) -> 流式 chunk`），
  本期由 Mock 实现填充；后续替换为真实本地模型时不改协议层。

### 3.2 架构风格：OOP 模块式

本项目采用 **OOP 模块式**开发，并全程遵守 AFCP v1.2.0（§2 代码编写协议）。
落地约束：

- **单一职责**：每个类只做一件事；协议帧读写、方法分发、会话管理、轮次
  执行、模型推理分别由独立类承担，互不混入。
- **显式数据结构**：协议帧参数、会话状态、usage 统计等一律用 `@dataclass`
  / 显式类型定义，禁止裸字典在模块间传递。
- **小接口抽象**：模型层定义小而专的抽象基类（如 `LanguageModel`，仅声明
  流式生成契约），Mock 与未来的真实模型各自实现；禁止万能接口。
- **组合优先**：继承链不超过两层（抽象基类 → 实现类，仅一层）；协作关系
  通过构造函数显式注入，禁止幽灵全局变量。
- **命名纪律**：类名用名词（单数），方法名用动词；布尔值加
  `is`/`has`/`can`/`should` 前缀；魔法值一律命名常量（错误码、
  `sessionUpdate` 类型字符串等）。
- **注释写「为什么」**：尤其协议附录 A 的实测教训，落码时以注释标明出处
  （如「A.3：轮次失败必须显式标记」）。

### 3.3 模块划分（草案）

```text
# 目录结构（草案，实施时可微调；类名体现 OOP 单一职责）
dream_cli/
├── __main__.py           # 入口：解析 acp / gui 子命令
├── acp/
│   ├── transport.py      # StdioTransport：ndjson 帧读写、写锁串行化
│   ├── dispatcher.py     # RpcDispatcher：JSON-RPC 方法分发、错误码表
│   ├── session.py        # AcpSession + SessionManager：会话状态管理
│   └── turn.py           # TurnRunner：流式轮次、审批回环、stopReason 收尾
├── model/
│   ├── base.py           # LanguageModel 抽象接口（小而专）
│   └── mock.py           # MockLanguageModel：规则回复 + 模拟流式 + 模拟 usage
└── gui/
    ├── app.py            # DreamGuiApp：PySide6 应用入口
    └── main_window.py    # MainWindow：服务状态、日志面板、会话视图
```

### 3.4 协议覆盖清单（本期必须逐条实现）

源自协议文档，作为验收检查表：

- `initialize` → 回 `agentInfo`（协议 §1.3）；不在 `authMethods` 上做文章（A.1）
- `session/new`：`cwd` 相对路径硬拒 `-32602`（§1.4 / A.2）；Mock 模型恒可用，
  不触发未配置错误，但错误路径代码保留
- `session/set_config_option`：模型别名作为不透明字符串处理，未知别名报错
  不崩（§1.5）
- `session/prompt`：容忍空 text 块（A.4）；流式 `agent_message_chunk` +
  `agent_thought_chunk`；`usage_update` 演示 used/size 同帧（§2）
- 工具审批回环：`session/request_permission` 三态 options，拒绝则放弃执行并
  追问（§3）
- `session/cancel`：轮次即停，`stopReason="cancelled"`，停后同会话可续（§1.6）
- 轮次失败显式 `stopReason="error"`，严禁静默空回复（§2.4 / A.3）
- 反向请求用独立 id 编号空间，与客户端整数 id 不碰撞
- 轮次在独立线程执行，主循环持续读帧（cancel/审批应答及时到达）
