## 2. 各阶段落地摘要

- **模型层消息化**：`stream_chat(messages, system_text, model_alias)` 成为新契约；
  基类默认摊平成纯文本委托 `stream_reply`（Mock 零改动，单条 user 消息摊平后
  与原 prompt 逐字节一致，帧不变量靠此成立）；GGUF 侧 system 走消息数组首元，
  `stream_reply` 保留为无 system 薄封装，`tools_enabled=false` 时线载荷与旧版
  完全一致。
- **工具内核**：三工具 `write_file`（必须审批）/ `read_file` / `list_dir`
  （免审批）；parser 一切不合规产结构化错误对象而非异常（格式抖动回灌模型
  自我修正）；executor 一律 `Path.resolve` 后判定位于会话 cwd 内，`..`、
  绝对路径、软链三种逃逸均返回结构化错误；read/list 结果按命名常量阈值截断。
- **轮次层工具循环**：流式 → 解析 → 审批/执行 → 结果以 `【工具结果】`/
  `【工具错误】` user 消息回灌，至多 `tool_max_iterations` 轮，超限以说明性
  文本显式收尾（不静默吞错）；usage 跨迭代累加单帧回报（used/size 同帧）；
  toolCallId 为 `tool-<session 序号>-<迭代序号>`；取消检查覆盖迭代开始前、
  chunk 间、审批返回后三处。
- **回归通路**：Mock 新增「协议工具」关键词（意图仍归 NORMAL，回复内嵌合法
  write_file 围栏块），使真实循环经 ACP 帧全程可被 spike 管道级断言；
  `tools_enabled=false` 一键回退纯文本旧行为亦有 spike 节兜底。
- **真实模型工具轮**：冒烟以独立会话 cwd（`.temp/smoke_tool_round/`）驱动
  Qwen3.5-9B 写 `smoke_poem.md`，审批帧由冒烟脚本自动应答 allow_once；
  落盘为软断言（模型指令遵循问题不染红服务端回归）。

## 4. 与计划的偏离及理由

1. **Mock 常规回复也走工具循环**：计划 §3.5 原文「仅 GGUF 后端生效」与澄清
   冲突——按澄清执行（Mock NORMAL 委托 ToolLoopRunner，无围栏块时单迭代
   收尾，帧序列与纯文本路径逐字节一致；既有 25 项 spike 断言全绿佐证）。
   演示意图（ERROR_DEMO/TOOL_DEMO）路径与关键词保持不变。
2. **tool_loop 与 turn 的审批/出站帧助手为平行实现**：turn→tool_loop 依赖
   方向已定，反向 import 常量会成循环依赖；两边线格式常量各自按协议小节
   声明取值（计划 §3.4 原文即「复用……模式」）。
3. **围栏块正则上移至 `toolkit/definitions.py`**（`TOOL_CALL_BLOCK_PATTERN`）：
   Mock 回显消毒也需要同一格式定义，避免 parser/Mock 两处副本漂移。
4. **verify_extras parser 断言 6 项**（计划列 5 类）：多加「无围栏块返回
   None」，这是无工具轮次单迭代收尾的关键分支。

## 5. 计划外隐患修复（实施中发现）

1. **Mock 回显死循环**：Mock 正文 verbatim 回显全量输入，工具循环第 2 轮的
   摊平文本含上轮围栏块原文，回声会被解析器当成新调用直至撞迭代上限。修复
   为双重防护：发射抑制（输入含回执前缀或围栏块即不再输出）+ 回显前正则
   消毒围栏块；不含围栏块的普通 prompt 回显逐字节不变。
2. **审批返回后的取消检查只覆盖拒绝路径**：已修正为批准/拒绝两路都先查
   cancel 再执行写盘（计划 §3.4 取消语义）。
