# Markdown 渲染预览功能选型

> 本篇与 `2026-0725-1849_图片文件预览功能选型.md` 同属"中栏可预览文件类型扩展"系列，共享同一接入架构（`ViewerPanel.open_file` 按 kind 分流 + `QStackedLayout`）。

## 1. 背景与目标

Zen Studio 中栏查看器对 `.md` 文件当前作为**纯文本**处理（`CodeViewer` + Markdown 词法高亮），能看到源码但**看不到渲染效果**。工作区内大量 `.md` 是文档（`AGENTS.md`、各 `README.md`、`work plans/`、`文档/`），就地渲染预览能显著提升阅读体验。

**目标**：对 `.md` 文件提供"渲染视图"，并支持"源码视图 ↔ 渲染视图"一键切换（符合 IDE 习惯），复用现有 CodeViewer（源码视图已有语法高亮），不引入重型依赖。

## 2. Zen Studio 现状与接入点

- **现状**：`.md` 走文本分支，`CodeViewer` + `PygmentsHighlighter`（Markdown 词法高亮）显示源码。无渲染。
- **markdown 基建**：全库 grep **未发现** `setMarkdown` 调用——Zen Studio 当前未启用任何 Markdown 渲染（聊天面板亦为纯文本/HTML，非 markdown 渲染）。⚠️ 此点修正前述口述（"已具备"实为 VS_Code_Python 才有）。
- **接入点**：`QStackedLayout` 在现有 `CodeViewer`（源码视图）与新增 `MarkdownView`（渲染视图）间切换。**源码视图完全复用现有 CodeViewer，零改动**。

**技术底牌（已实测）**：`QTextBrowser` / `QTextDocument` 的 `setMarkdown()` 随 PySide6 内建，零新增依赖。

## 3. 参考项目调研

| 项目 | Markdown 预览实现 | 可借鉴点 |
|:---|:---|:---|
| theia-zen | 独立 `packages/preview` 包（`markdown-preview-handler.ts` + `preview-widget.ts`），主区打开 `.md` 预览 tab；另有 `editor-preview` 的"预览标签页"机制 | **source/preview 双模式**（源码编辑器与预览 tab 并存/互跳）；控件层（Web）不可移植 |
| Multi_Cli_Studio | 文本查看器（CodeMirror）显示源码，`.md`/`.mdx` 可一键切换 `react-markdown` 渲染视图（`ChatFilePreviewPanel.tsx`，`remark-gfm` 支持 GFM） | **同一面板内源码↔渲染切换**的形态；GFM 表格/任务列表支持；控件层（React）不可移植 |
| VS_Code_Python | `core/render/markdown/renderer.py` 用 `QTextDocument.setMarkdown()` 渲染聊天输出 | **`setMarkdown` 的 PySide6 用法可参考**（同栈） |

**关键观察**：两个 IDE 类参考项目（theia-zen、Multi_Cli_Studio）都采用"源码 ↔ 渲染"双模式，这是 Markdown 预览的业界惯例。VS_Code_Python 验证了 `setMarkdown` 在 PySide6 可用。

## 4. 候选方案

| | 方案 A：`QTextBrowser.setMarkdown()` | 方案 B：`QTextDocument.setMarkdown()` + 自绘 viewport | 方案 C：`markdown` 库 → HTML → `QTextBrowser` | 方案 D：`QWebEngineView` + `marked.js` |
|:---|:---|:---|:---|:---|
| 描述 | `QTextBrowser` 内建 `setMarkdown`，原生渲染 | 同 API 但挂在 `QTextDocument`，自定义只读控件 | Python `markdown`/`mistune` 生成 HTML 再喂 `QTextBrowser.setHtml` | 浏览器内核 + JS 渲染 |
| 依赖 | 无 | 无 | ⚠️ 新增纯 Python 库 | 无，但 🔴 违背路线 |
| GFM（表格/任务列表/删除线） | ✅ Qt 6 `MarkdownFeature.MarkdownDialectGitHub` | ✅ 同 | ✅（库扩展） | ✅ |
| 代码块语法高亮 | ❌（纯文本块） | ❌ | ❌ | ✅ |
| 链接/图片 | ✅（`QTextBrowser` 支持锚点、相对图片需解析） | △（`QTextDocument` 需手动处理资源） | ✅ | ✅ |
| 可交互 | ✅ 链接点击、锚点跳转、可选中复制 | △ | ✅ | ✅ |
| CSS 样式 | 受限（`QTextBrowser` 样式表子集） | 受限 | 同左（HTML 仍受 Qt 富文本子集限制） | 完整 CSS |
| Mermaid/数学/复杂 HTML | ❌ | ❌ | ❌（Qt 富文本不支持） | ✅ |

### 方案 D 否决
WebEngine 已三度否决（同 PDF 选型 §4）。🔴 **否决**。

### 方案 C 否决
Qt 富文本引擎（`QTextBrowser`/`QTextDocument`）对 HTML 的支持是**子集**（无完整 CSS、无现代布局），即使 `markdown` 库生成标准 HTML，最终渲染能力仍被 Qt 富文本上限锁死——多引入一个库却换不到更好的效果。🔴 **否决**。

### 方案 A vs B
`QTextBrowser` 是 `QTextEdit` 的只读子类，自带 `setMarkdown`、链接交互、锚点导航，**最适合只读渲染预览**；方案 B 需自建控件、自行处理资源加载，属重复造轮子。✅ **选 A**。

## 5. 推荐方案：A（`QTextBrowser.setMarkdown`）

| 能力 | 说明 |
|:---|:---|
| 渲染 | `browser.setMarkdown(text, MarkdownFeature.MarkdownDialectGitHub)` 支持 CommonMark + GFM（表格、任务列表、删除线、围栏代码） |
| 源码视图 | 复用现有 `CodeViewer`（已含 Markdown 语法高亮），零改动 |
| 双模式切换 | `QStackedLayout` 在 CodeViewer（源码）↔ MarkdownView（渲染）间切换；标题栏或右键菜单"切换渲染/源码视图"（借鉴 theia-zen `openFor` 与 Multi_Cli_Studio 的一键切换） |
| 链接 | `QTextBrowser` 原生支持相对/绝对链接点击（`setSearchPaths`/`anchorClicked`） |
| 图片 | 支持内联图片；相对路径需解析到工作区根后注册为 resource |
| 主题 | `QTextBrowser` 的样式表（标题/代码块/引用块前景背景）接入 `gui/theme.py` 双主题 |

## 6. 能力边界（诚实声明）

`QTextBrowser.setMarkdown` 的能力上限由 **Qt 富文本引擎**决定：
- ✅ 支持：标题、段落、列表、表格、任务列表、删除线、围栏代码块、引用、链接、内联图片、水平线。
- ❌ 不支持：代码块**语法高亮**（显示为纯文本块）、Mermaid 图表、LaTeX 数学公式、原始 HTML 块（被忽略或降级）、复杂 CSS 样式。

对 Zen Studio 工作区文档（以文字、列表、表格、代码块为主）**完全够用**。若未来需华丽渲染（Mermaid/数学），再评估 WebEngine 或专用组件——当前过度设计。

## 7. 实施要点

1. **新增控件**：`gui/panels/viewer/markdown_view.py`，`QTextBrowser` 派生，封装 `setMarkdown`（GFM 方言）+ 相对图片路径解析 + 主题样式表。
2. **ViewerPanel 改造**：`QStackedLayout` 增加 MarkdownView 页；`.md`/`.markdown` 默认进哪个视图需决策（见 §8）。
3. **双模式切换**：标题栏按钮或右键菜单"渲染视图/源码视图"切换，状态记忆（可存 `settings`）。
4. **相对图片/链接**：以当前 md 文件所在目录为基准解析相对路径（`QTextBrowser.setSearchPaths` 或注册 resource），使文档内嵌图片正常显示。
5. **外部修改重载**：复用现有 watcher，重载时按当前模式（源码/渲染）刷新。
6. **主题**：md 各元素（h1-h6、code、blockquote）样式表随主题切换重建。
7. **验证**：含表格/任务列表/代码块/图片/链接的 md 目检 + 双模式切换 + 相对图片解析 + 双主题 + 外部修改重载。

## 8. 待决策项

2. 切换入口：标题栏按钮（显式）vs 右键菜单（隐蔽）。倾向标题栏按钮（高频操作）。
