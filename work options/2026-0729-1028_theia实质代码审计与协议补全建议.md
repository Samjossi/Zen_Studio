## 1. 审计背景与方法

### 1.1 为什么审 theia-zen

三个参考项目中两家为 MIT（Multi_Cli_Studio、PyGPT），无传染性；
`参考代码/theia-zen` 为 Eclipse Theia monorepo，源文件头部声明
`SPDX-License-Identifier: EPL-2.0 OR GPL-2.0-only WITH Classpath-exception-2.0`，
EPL-2.0 具**文件级弱传染性**——若实质代码进入本库，对应文件必须继续以
EPL-2.0 发布，整体 MIT 将不成立。

注：本地 theia-zen 副本的 LICENSE 文件已被删除（见其
`文档/修改记录/2026-0709-2345_删除仓库License文件计划.md`），但删除 LICENSE
文件不消除协议义务——每个源文件头部的 EPL-2.0 声明独立有效。故审计以
源文件头声明为准。另：`参考代码/` 已在 `.gitignore` 第 2 行忽略
（`git check-ignore -v 参考代码/` 验证命中，`git status --ignored` 标记 `!!`），
该目录不进入 git 历史、不上传云端仓库，仅存于本机。

### 1.2 技术前提：直接复制的天然屏障

| 维度 | Zen Studio | theia-zen |
|:---|:---|:---|
| 语言 | Python 3.12 | TypeScript |
| GUI 框架 | PySide6（Qt Widgets） | Electron + 浏览器 DOM |
| 样式 | QSS（`assets/themes/base.qss`） | CSS |
| 并发模型 | QThread + Python 生成器 | async/await + CancellationToken |

跨语言跨框架，逐行复制在技术上不可能；风险点仅剩**翻译式移植**
（把 TS 代码逐句改写为 Python）与**资产复制**（图标/样式/文案）。

### 1.3 审计手段

| # | 方法 | 覆盖 |
|:--|:---|:---|
| 1 | 全库 grep：theia / SPDX / EPL / TypeFox / STMicroelectronics / copyright 头 | 全部 `.py/.qss/.json/.toml` |
| 2 | theia 特有标识符逆向扫描：cancellationToken、LanguageModelRegistry、ThinkingChatResponseContent、theia-editor-dnd、parentDecorations、compareWeight 等 | 全部 `.py` |
| 3 | 命中文档/注释线索逐一人工比对 theia 原始实现 | 3 处关联点 |
| 4 | 资产目录比对（字体、主题、图标来源） | `assets/` |

## 2. 审计结果

### 2.1 移植痕迹扫描：零命中

- ❌ 无任何 theia/EPL/SPDX 版权头
- ❌ theia 特有标识符在 Zen Python 代码中**零出现**
  （cancellationToken、isCancellationRequested、LanguageModelRegistry、
  frontendDelegate、ThinkingChatResponseContent、theia-editor-dnd、
  parentDecorations、compareWeight 全部无命中）
- ❌ 资产无复制：`assets/fonts/` 为思源黑体/更纱黑体（SIL OFL 1.1，
  与 theia 无关）；`assets/themes/base.qss` 为原创 QSS

### 2.2 theia 关联点逐一比对（共 3 处，全部思想级）

#### 关联点 A：`llm/base.py` —— LLM 统一接口

Zen 注释自述：「仿 theia-zen LanguageModel Protocol」。

| 维度 | Zen `llm/base.py`（41 行） | theia `language-model.ts`（779 行） |
|:---|:---|:---|
| 接口方法 | `chat(messages) -> Iterator[Chunk]` + `cancel()` | `request(UserRequest, CancellationToken) -> Promise<LanguageModelResponse>` |
| 消息模型 | OpenAI 格式 `{"role", "content"}` TypedDict | 自有 `LanguageModelRequestMessage` 体系（Actor/Request/Message 分层） |
| 流式 | Python 生成器同步产出 | async 异步迭代 + TokenUsage 元数据 |
| 取消 | 协议级 `cancel()` 无参方法 | CancellationToken 对象传递 |

**判定**：API 形态、方法签名、消息结构完全不同，仅共享「统一 LLM 接口 +
可取消」这一**架构概念**（且该概念在 VS Code LanguageModelChat、各 AI 框架
中普遍存在）。属概念借鉴，非代码移植。

#### 关联点 B：`core/git/service.py` —— 目录状态冒泡

Zen 注释自述：「对齐 theia propagateDecorationsByUri——继续向上只会更弱」。

| 维度 | Zen `_build_dir_status()` | theia `propagateDecorationsByUri()` |
|:---|:---|:---|
| 数据模型 | Git 状态优先级字典（conflict>modified>untracked>ignored） | Decoration 对象 + weight 权重 + bubble 标志 |
| 路径抽象 | `PurePosixPath.parents` | `URI.parent` 链 |
| 终止条件 | 仓库根 `"."` 不入缓存 | `parent.path.isRoot` |
| 自有语义 | deleted 不冒泡；ignored 折叠键去尾斜杠先入缓存；显式优先级表归并 | 无对应概念 |

**判定**：两者共享的是「子状态沿父链上冒，祖先已有同级/更高优先级即
剪枝」这一**算法思想**（算法思想不受著作权保护）。数据结构、归并语义、
边界处理均为 Zen 独立设计，代码无一句对应关系。

#### 关联点 C：`gui/panels/chat/panel.py` —— Esc 中断生成

Zen 注释自述：「参考实现同效：theia『取消 (Esc)』、Multi_Cli_Studio Escape 中断」。

实现为 PySide6 `QShortcut(QKeySequence(...))` 标准 Qt 代码，与 theia 的
Monaco/DOM keybinding 体系无任何对应。**判定**：交互范式借鉴。

### 2.3 文档层佐证：选型研究而非代码移植

`文档/选型记录/` 共 10+ 篇报告记录了对三个参考项目的**设计选型调研**
（取消令牌模式、拖拽 MIME 设计、思维链块类型、权限解析优先级等），
模式一致：调研三项目的设计取舍 → 记录优劣 → 用 PySide6 独立实现。
所有 theia 引用均为模式级，且注释/文档中透明标注了出处。

## 3. 法律判定

著作权保护**表达**而不保护**思想**（思想/表达二分法，中美法域一致）。
本审计未发现任何 theia 受保护表达（代码文本、注释文本、样式表、资产）
进入本库；三处关联均为思想/算法/范式级借鉴。

**EPL-2.0 义务不附着，Zen Studio 可整体采用 MIT 协议。** ✅
