# 音视频播放功能选型

> 本篇与 `2026-0725-1849_图片文件预览功能选型.md` 同属"中栏可预览文件类型扩展"系列，共享同一接入架构（`ViewerPanel.open_file` 按 kind 分流 + `QStackedLayout`）。**音视频为同一控件栈（`QMediaPlayer`），故合一选型。**

## 1. 背景与目标

Zen Studio 中栏查看器对 `.mp4`/`.mp3` 等媒体文件当前显示"（二进制文件，不支持预览）"。

**目标**：对常见视频/音频格式提供就地播放（播放/暂停、进度拖动、音量），复用现有查看面板基建，不引入重型依赖。

⚠️ **场景价值评估**：不同于图片/PDF/Markdown（IDE 高频文档资产），音视频在代码工作区内出现频率低。本功能**优先级最低**，主要价值在于"偶尔需要看一眼演示视频/听一段录音"时不必跳外部程序。是否实施请审阅定夺。

## 2. Zen Studio 现状与接入点

接入架构与图片/PDF 一致：`QStackedLayout` 增加媒体播放页，`open_file` 对视频/音频扩展名分流。配套一个播放控制条（播放/暂停、进度滑块、时间、音量）。

**技术底牌（已实测）**：`PySide6.QtMultimedia` 与 `PySide6.QtMultimediaWidgets` 随项目 `pyside6>=6.11.1` 就绪（import 探针通过），零新增第三方依赖。

## 3. 参考项目调研

| 项目 | 音视频实现 | 可借鉴点 |
|:---|:---|:---|
| VS_Code_Python | 独立 `MediaPlayer` 工具（`src/pygpt_net/tools/media_player/`）：`QMediaPlayer` + `QAudioOutput`（音频）+ `QVideoWidget`（视频），**PySide6 6.9.1 原生**，含播放/暂停/进度/音量/状态栏 | 🟢 **可移植性 S 级**（同栈，代码可直接移植，仅需剥离 `window.tools`/`trans()` 依赖，形态从独立 `QDialog` 改为内嵌 `QWidget`） |
| theia-zen | ❌ 未实现媒体播放 | — |
| Multi_Cli_Studio | ❌ 视频在其 `kind` 分类中归为 `binary-unsupported`（不预览） | 反面佐证：IDE 类项目普遍不做媒体播放 |

**关键观察**：三个参考项目中**仅 VS_Code_Python 实现了媒体播放**（且是 PySide6 原生、可移植），另两个 IDE 类项目都不做。这印证了"音视频在 IDE 场景价值偏弱"的判断——但正因有现成同栈可移植代码，实施成本可控。

> ⚠️ **协议合规边界**：本篇唯一可移植来源为 VS_Code_Python/PyGPT（MIT 协议），移植其 `media_player` 代码片段时须在对应文件头部保留其 MIT 版权声明（© Marcin Szczygliński，见审计报告 `2026-0729-1028_theia实质代码审计与协议补全建议.md` §4.3 预防性条款）。theia-zen 未实现媒体播放，本篇对其无任何借鉴，无 EPL-2.0 合规负担。

## 4. 候选方案

| | 方案 A：QtMultimedia（`QMediaPlayer`+`QVideoWidget`/`QAudioOutput`） | 方案 B：`QWebEngineView` + `<video>`/`<audio>` | 方案 C：外部播放器 |
|:---|:---|:---|:---|
| 描述 | Qt 原生多媒体栈 | 浏览器内核 HTML5 媒体 | `QDesktopServices` 调系统播放器 |
| 视频显示 | `QVideoWidget` | `<video>` | — |
| 音频输出 | `QAudioOutput` | `<audio>` | — |
| 播放控制 | `QMediaPlayer`（play/pause/seek/volume） | 浏览器原生控件 | — |
| 新增依赖 | 无（PySide6 自带） | 无，但 🔴 违背路线 | 无 |
| 就地播放 | ✅ | ✅ | ❌ |
| 可抄代码 | 🟢 VS_Code_Python 现成 | ❌ | — |

### 方案 B 否决
WebEngine 已三度否决（同 PDF/Markdown 选型）。🔴 **否决**。

### 方案 C 定位
不满足"就地播放"，但作为**降级兜底**（不支持的格式 → 外部打开）。✅ 保留为辅助。

## 5. 推荐方案：A（QtMultimedia）

| 能力 | 说明 |
|:---|:---|
| 播放器 | `QMediaPlayer`（统一音频/视频，自动按源类型分发） |
| 视频输出 | `QMediaPlayer.setVideoOutput(QVideoWidget)` |
| 音频输出 | `QMediaPlayer.setAudioOutput(QAudioOutput)` |
| 控制 | play/pause/stop、`setPosition` 进度、`setVolume`/`setMuted`、`duration`/`positionChanged` 信号驱动进度条 |
| 格式 | 受运行时媒体后端解码能力决定（见 §6 风险） |
| 移植 | VS_Code_Python `tools/media_player/ui/widgets.py` 的播放状态机/事件处理可直接移植 |

## 6. 风险与实施要点（⚠️ 重点）

1. **媒体后端与打包（首要风险）**：Qt 6 多媒体在 Linux 默认走 **FFmpeg 后端**（Qt 6.5+），理论上降低了对 GStreamer 的强依赖；但运行时仍需 Qt 多媒体插件与 FFmpeg 库随包。**开发态 import 通过 ≠ 打包态解码可用**，必须 onedir/AppImage 实机验证（能否实际播放 mp4/mp3，而非仅 import 成功）。这是本方案最大不确定性。
2. **格式覆盖**：解码能力依赖后端，常见 mp4(h264)/mp3/ogg/wav/webm 通常可播；特殊编码（hevc、avi 旧编码）可能失败 → 需错误兜底（标题行提示"无法播放，请用外部程序打开"）。
3. **新增控件**：`gui/panels/viewer/media_viewer.py`，含 `QVideoWidget` + 控制条（播放按钮、`QSlider` 进度、时间标签、音量）。
4. **ViewerPanel 改造**：`QStackedLayout` 增加媒体页；扩展名判定用 VS_Code_Python 的 `get_video_ext`/`get_audio_ext` 表（mp4/avi/mkv/webm/mov/...；mp3/wav/flac/ogg/...）。
5. **音频可视化**：纯音频无画面，`QVideoWidget` 区为空，建议显示文件名 + 波形占位（可选，非必须）。
6. **生命周期**：切换文件/关闭标签时必须 `stop()` 释放 `QMediaPlayer`，防后台继续播放。
7. **降级兜底**：右键/标题栏"在外部程序打开"（`QDesktopServices.openUrl`）。
8. **验证**：mp4/mp3/webm/ogg 目检播放 + 进度拖动 + 音量 + 切换文件停止 + **打包态实机解码**（关键）。

## 7. 待决策项

1. **是否本期实施**：鉴于场景价值偏低 + 打包态媒体后端不确定性，可考虑**暂缓**（先做高价值的 PDF/Markdown/图片），音视频作为后续可选。本选型倾向：待 PDF/Markdown/图片落地后再评估是否真有需求。
2. 若实施，格式范围是否限定"主流可解码子集"（mp4/mp3/webm/ogg/wav），而非追求全覆盖。
