# Git 树切换页变更目录树渲染方案选型

## 一、背景与问题确认

### 1.1 当前界面确实复用了“已变更”列表

当前文件树头部的 `⇄` 按钮只是在 `FileExplorer` 内切换 `QStackedWidget` 页面：

- 文件树页：原有 `QTreeView + QFileSystemModel`。
- Git 页：`src/gui/panels/file_explorer/explorer.py` 中创建的 `ChangesList`。
- 右栏下“已变更”面板：`src/gui/panels/changes/panel.py` 中组合的另一个 `ChangesList`。

两个 Git 界面因此共享 `src/gui/panels/changes/list.py` 的三列扁平渲染，并由 `src/gui/controllers.py` 喂入同一份变更快照。状态色、删除线、`+N` / `-N` 和双击分派也完全一致。

这不是意外串页，而是 `work plans/2026-1105-2229_文件树与Git树切换按钮落地计划.md` 明确选择的第一期 MVP：先打通切换链路，目录层级留作后续增强。现在需要决定第二阶段采用什么渲染形态。

### 1.2 本次选型对象

本文所称“Git 树”特指**工作区变更文件的目录树/源码管理列表**，目标是让切换后的页面具备独立价值：按目录组织变更、展示文件图标与统计、保留展开状态，并可切回扁平列表。

以下功能不属于本次替换对象：

- 现有 `GitGraphDialog` 提交历史图及其 DAG 渲染。
- 分支拓扑、提交泳道、合并曲线。
- 暂存、取消暂存、提交、推送、丢弃变更等 Git 写操作。

## 二、目标与现有约束

### 2.1 目标

1. 上方 Git 页默认呈现真正的变更目录树，与下方扁平“已变更”面板形成清晰分工。
2. 保留现有 M/U/D 等状态色、增删行数、完整路径 tooltip 和双击打开差异/删除提示。
3. 支持目录展开/折叠；刷新后尽量保留展开、选中和滚动位置。
4. 继续复用 `GitStatusService.collect_changes()` 与 `GitStatusController.refresh()`，不增加第二套 Git 查询、watcher 或定时刷新。
5. 使用项目现有 Python 3.12 + PySide6 QWidget 技术栈，不引入 WebEngine 或 React 运行时。
6. 右栏下 `ChangesPanel` 保持现有外观与行为，避免一次改动同时影响两个面板。

### 2.2 数据与空间约束

- `ChangeEntry` 当前只有 `path/status/added/deleted`，足以构建目录树和现有统计列。
- `src/core/git/status.py` 已把 Git XY 双列状态归并成单一状态，**无法据此拆分“已暂存/未暂存”两组**。
- `added/deleted is None` 目前混合表示二进制、超限未跟踪文件、读取失败或无统计，不能直接照搬参考项目的“二进制/过大”精确文案。
- `ChangesList._render()` 当前先 `clear()` 再全部重建；升级为树后若不额外处理，每次 Git 刷新都会丢失展开与选中状态。
- 文件树面板最小宽度为 240px。参考项目中“状态图标 + 文件图标 + 双行路径 + 增减统计 + 多个悬浮按钮”的完整行不能不加取舍地塞入本面板。
- 删除文件已不在磁盘上，文件图标应按路径/扩展名解析并提供通用回退，不能只依赖现存文件的系统图标查询。

## 三、参考代码调研与可移植内容

### 3.1 Multi_Cli_Studio：最贴近目标的完整面板

**核心证据**

| 文件/组件 | 已有能力 | 本项目可借鉴内容 |
|:---|:---|:---|
| `参考代码/Multi_Cli_Studio/src/components/chat/GitPanel.tsx` 的 `buildDiffTree()` | 把文件路径逐段插入 `folders/files` 节点，构建目录树 | 最适合翻译成无 Qt 依赖的 Python 纯函数 |
| 同文件 `WorktreeFileRow` | 状态标记、文件图标、文件名、目录、增删统计、选中态、悬浮操作 | 文件行的信息层级与紧凑排列 |
| 同文件 `WorktreeTreeSection` | 文件夹递归渲染、展开/折叠、目录图标、树缩进 | 目录行和文件行的交互分工 |
| 同文件 `GitPanel` | Flat/Tree 双模式、Staged/Unstaged 分组、变更计数、diff 联动 | 双模式入口与空态组织；写操作不随渲染一起引入 |
| `参考代码/Multi_Cli_Studio/src/components/FileIcon.tsx` | 按文件名/扩展名取图标，目录区分开合态 | 删除文件也能按路径取图标的思路 |
| `参考代码/Multi_Cli_Studio/src/styles/settings-desktop.css`、`workspace-right-panel.css` | 行高、缩进、树辅助线、选中/hover、统计徽章 | 视觉密度参考，不直接复制色值 |

**优点**

- 功能形态与目标最接近，既有扁平列表也有目录树，且带增删统计。
- `buildDiffTree()` 输入只要求条目含 `path`，与现有 `ChangeEntry` 几乎天然匹配。
- 目录节点以稳定路径为 key，适合进一步做刷新后的状态恢复。
- 文件行同时覆盖状态、图标、路径、统计，信息完整。

**缺点**

- React + CSS，不能在 PySide6 中直接运行；只能理解后重写。
- `GitPanel.tsx` 单文件约千行，混合了取数、提交、暂存、丢弃、推送、diff 弹窗与渲染，不能整体移植。
- 树采用递归创建 DOM，未体现虚拟化；大变更集仍需本项目自行控制重建成本。
- 完整行信息偏多，直接复刻会在 240px 窄面板中挤压文件名。
- Staged/Unstaged 依赖更细的数据模型，本项目当前状态归并层不提供。

**定位：主参考。优先移植目录构建思路和紧凑行布局，不移植整个面板。**

**核心证据**

| 同文件 `buildFileChangeTree()` | 基于已排序路径分段构树，并压缩共有目录链 | 减少只有单条子链时的无效缩进 |
| 同文件 `toFileChangeFolderNode()` / `toFileChangeNode()` | 以旧节点 ID 回读 expanded/selected | Git 刷新重建时保留用户体验 |

| 同文件 `ScmResourceGroupElement` / `ScmResourceFolderElement` | 分组计数、目录行、右键与悬浮动作挂点 | 后续分组/动作扩展的边界 |
| `参考代码/theia-zen/packages/scm/src/browser/style/index.css` | 弱化路径、状态区、行选中与紧凑行高 | 视觉语义参考 |

**优点**

- 模型、节点身份、展开/选中状态和渲染职责分得很清楚。
- 同时支持 list/tree，切换后还能按旧节点 ID 恢复选择。
- 文件夹优先、目录链压缩、分组计数都已是完整实现。
- 比“每次 clear 后全部展开”的做法更适合频繁 Git 刷新。

**缺点**

- 算法建立在资源已排序、分组和 URI 语义之上，翻译成本高于 Multi_Cli_Studio 的简单插入法。
- 原生行没有本项目的 `+N/-N` 统计，需要组合两套参考。
- 键盘左右键还承担 diff hunk 导航，超出本次目录树范围，不应一并带入。

**定位：辅助参考。重点吸收稳定节点、状态保留和可选目录链压缩，不照搬框架结构。**

### 3.3 DeepSeek Harness：适合摘要卡，不适合作为目录树底座

**核心证据**

- `参考代码/deepseek-harness/packages/client/ui-deliverables/src/client/ChangedFiles.tsx`：单文件/多文件标题、默认四行折叠、增删统计、二进制/过大标记、500ms 悬停后懒加载 diff 预览。
- `参考代码/deepseek-harness/packages/client/ui-deliverables/src/client/ChangedFiles.module.css`：摘要卡、行省略、统计色和折叠按钮。
- `参考代码/deepseek-harness/packages/client/ui-deliverables/src/client/ReviewTab.tsx`：文件选择器、统一/分栏 diff、换行开关与打开文件。

**优点**

- 变更数量多时的折叠摘要和懒加载预览很成熟。
- 对二进制、过大文件的展示语义比当前空白统计更明确。
- 文件选择与 diff 评审联动设计完整。

**缺点**

- 数据口径是“某一回合的交付摘要”，不是实时工作区 Git 状态。
- 只有扁平摘要，没有目录树、状态色或目录展开状态。
- 悬停 diff 预览依赖 React HoverCard、资源 store 与异步数据通道，移植成本高。
- 二进制/过大标记需要额外元数据，当前 `ChangeEntry` 无法区分这些原因。

**定位：局部参考。本次不把摘要卡或悬停预览带入 Git 树；二进制/过大标记留待数据模型扩展后再议。**

## 四、候选落地路线与优缺点

### 方案 A：QTreeWidget 原生增量改造（推荐）

新增上方 Git 页专用的变更树控件；保留下方 `ChangesList` 不动。用纯 Python 把 `ChangeEntry.path` 组装成目录节点，再由 QTreeWidget 渲染目录和文件。

建议组合：

- Multi_Cli_Studio `buildDiffTree()` 的路径分段建树思路。
- Multi_Cli_Studio 的文件/目录行、Flat/Tree 双模式和增删统计布局。
- Theia 的稳定路径 ID、目录优先排序、展开/选中恢复。
- VS_Code_Python `BaseList` 的滚动位置保存思路作为补充。

**优点**

- 与当前 `ChangesList(QTreeWidget)` 最接近，改造和回归风险最低。
- 无需新增依赖；现有信号、主题色、双击 diff 管线可直接复用。
- 上方默认目录树、下方保持扁平完整路径，立即解决两个界面完全同质的问题。
- 对常见变更集规模足够，且可先交付再按实测优化。

**缺点**

- 每次全量重建仍需自行保存/恢复展开、选择和滚动状态。
- QTreeWidget 的逐项构建与三列布局不适合极端规模变更集。
- 若以后增加大量悬浮按钮和复杂富文本行，最终仍可能转向委托自绘。

### 方案 B：QTreeView + 自定义模型/委托重构

为变更树建立独立 `QAbstractItemModel`，使用 `QStyledItemDelegate` 自绘图标、路径、状态和统计。

**优点**

- model/view 分离最彻底，增量更新、虚拟滚动和大仓库性能上限更高。
- 行布局自由，后续可承载状态徽章、悬浮动作和更精细的省略策略。
- 更容易做不重建整棵树的增量刷新。

**缺点**

- 模型索引、持久索引、选择恢复和委托绘制都需新写，工作量与测试面显著大于方案 A。
- 当前只有工作区变更列表，尚无性能证据证明需要提前承担这套复杂度。
- 与现有 QTreeWidget 代码差异大，回归风险更高。

### 方案 C：QWebEngine 内嵌并改写 React 参考组件

以 WebView 承载 Multi_Cli_Studio 或 DeepSeek Harness 的前端组件，通过桥接获取 Git 数据。

**优点**

- 表面上能保留最多 JSX/CSS 视觉代码。
- 后续可直接复用其他 Web 前端组件。

**缺点**

- 引入大型 WebEngine 运行时、打包体积、进程与桥接复杂度。
- 仍需重写数据通道、主题、信号、权限和桌面交互，并非直接复制即用。
- 与整个项目的 QWidget/QSS 体系割裂，维护和视觉一致性成本最高。
- 为一个目录树承担上述成本，投入产出不合理。

## 五、综合对比

| 维度 | 方案 A：QTreeWidget 增量 | 方案 B：模型/委托重构 | 方案 C：WebEngine |
|:---|:---|:---|:---|
| 解决当前同质化 | 是 | 是 | 是 |
| 技术栈一致性 | 高 | 高 | 低 |
| 新增依赖 | 无 | 无 | WebEngine 及桥接体系 |
| 首期实现成本 | 低—中 | 中—高 | 高 |
| 刷新状态保留 | 需显式实现 | 可系统实现 | 依赖前端重写 |
| 大变更集扩展性 | 中 | 高 | 中，取决于 Web 实现 |
| 现有交互复用 | 最高 | 中 | 低 |
| 本次推荐度 | 推荐 | 暂缓，留作性能升级路线 | 否决 |

## 六、推荐组合与界面边界

### 6.1 推荐结论

选择**方案 A**，以 Multi_Cli_Studio 为主、Theia 为辅做 PySide6 原生重写：

1. 上方 Git 页新增独立 `ChangesTree`，不再直接实例化下方同款 `ChangesList`。
2. 默认显示目录树，提供小型“列表/树”切换；列表模式保留“文件名 + 弱化父目录 + 增删统计”，不再只显示一条长路径。
3. 目录模式显示目录图标、文件图标、展开箭头与增删统计；目录优先、同层按名称排序。
4. 文件行采用紧凑单行：文件图标 + 文件名 + 弹性空间 + `+N/-N`。状态继续由颜色、删除线和 tooltip 表达，首期不额外塞入状态字母与悬浮操作列。
5. 以仓库相对路径作为目录和文件的稳定身份；刷新前后保存并恢复展开目录、选中文件和滚动位置，已消失节点自然丢弃。
6. 空变更与非 Git 降级沿用现有语义；M/U 双击 diff、D 双击提示、其他可打开条目进查看器的行为不变。
7. 下方 `ChangesPanel` 保留扁平完整路径清单，作为上方结构化导航的补充，不在本期删除或改造。

### 6.2 建议保留为后续项的功能

| 功能 | 来源 | 暂缓原因 |
|:---|:---|:---|
| 单链目录压缩，如 `src/gui/panels` 合并为一层 | Theia | 有价值但会增加节点身份和测试复杂度；可在基础树稳定后单独加入 |
| Staged/Unstaged 分组、组计数 | Multi_Cli_Studio / Theia | 当前 XY 状态已归并，需先扩展 Git 数据层 |
| 暂存、取消暂存、丢弃、提交、推送 | Multi_Cli_Studio / Theia | 属写操作与独立 SCM 需求，不应随渲染改造夹带 |
| 悬浮 diff 预览 | DeepSeek Harness | 需要懒加载缓存与弹层体系，窄面板中也不是首要能力 |
| 二进制/过大精确标签 | DeepSeek Harness / kilocode-main | 当前 `None` 统计无法区分原因，需先补元数据 |
| 行内悬浮操作按钮 | Multi_Cli_Studio / Theia | 会挤占 240px 面板宽度，并引入危险操作入口 |

### 6.3 不直接复制的代码

- 不复制 React 组件、CSS 或图标 SVG 集合进生产代码。
- 不 import `参考代码/`，不建立运行时依赖，不把参考目录加入打包。
- 以算法和交互语义重写为主；若最终复制实质片段，按来源许可证与 `参考代码/README.md` 的来源标注、NOTICE 约定处理。
