# Token 用量汇总数字缩写方案选型

## 一、背景

Token 用量热力图弹窗底部常驻三项汇总（今日 / 最近七天 / 最近三十天），当前直接用千分位全数字显示（`src/ide/gui/token_usage_dialog.py` 的 `reload()`，格式 `{value:,} tokens`）。随着用量积累，数字位数不断增长，例如截图中的 `368,598,460 tokens`，三项合计宽度持续挤压弹窗布局，且长数字可读性差。本次目标是选定一种缩写显示方案，使底部汇总在任意用量规模下保持简短、可读、布局稳定。

约束：

- 只改显示层，数据口径（`src/ide/core/token_stats.py` 的 `summarize()`）不动。
- 格子 tooltip（`_tooltip_text()`）已显示精确千分位数字，属于补充信息通道，不受本次改动影响。
- 中文界面环境，用户读数习惯以「万 / 亿」为自然量级锚点。

## 二、结论先行

**最终决策：方案一（K / M / B 国际缩写），用户拍板。** 本文原推荐方案二（中文界面读数最直观、无跨文化换算歧义），但用户明确偏好方案一，故落地计划按方案一编写。方案一的 `1B = 10亿` 换算歧义由 tooltip 精确数字兜底。

## 三、候选方案

### 方案一：自适应国际缩写（K / M / B）

按数量级分段：

| 区间 | 显示 | 示例 |
|:---|:---|:---|
| < 1,000 | 原样（千分位） | `3,113` |
| < 100,000 | 千位缩写，1 位小数 | `86.5K` |
| < 100,000,000 | 百万缩写，1 位小数 | `368.6M` |
| ≥ 100,000,000 | 十亿缩写，2 位有效数字 | `1.25B` |

tooltip 保留精确数字。

**优点**

- 国际通用，GitHub 等产品的用户无障碍。
- 阈值规则简单，位数上限恒定（约 6 字符）。

**缺点**

- `1B = 10亿` 与中文「亿」相差一个数量级，中文用户极易误读（`368.6M` 实际是 `3.69亿`，口算换算负担在用户侧）。
- 与本项目全中文 UI 的风格不完全一致。

### 方案二：中文单位缩写（万 / 亿）（推荐）

按数量级分段：

| 区间 | 显示 | 示例 |
|:---|:---|:---|
| < 10,000 | 原样（千分位） | `3,113` |
| < 100,000,000 | 万，1 位小数（去尾零） | `8,660.5万` → 简化为 `8660.5万`，或 `8,660万` 取整 |
| ≥ 100,000,000 | 亿，2 位有效数字 | `3.69亿` |

具体规则在落地计划中细化（小数位与是否千分位需定）。

**优点**

- 中文界面下读数零换算成本，`311万`、`3.69亿` 一眼可懂。
- 无跨文化歧义。
- 实现与方案一同级，一个纯函数即可。

**缺点**

- 「万/亿」带口语色彩，与偏技术化的热力图风格略有反差（可接受）。
- 非中文用户不友好（本项目无此诉求）。

### 方案三：保持千分位全数字 + 布局兜底

不改数字格式，仅靠弹窗加宽或字号缩小容纳长数字。

**优点**

- 零逻辑改动，精确数字常驻可见。

**缺点**

- 治标不治本：位数随用量无限增长，布局终将再次挤压。
- 长数字串本身可读性差，千分位分隔在超过 9 位后帮助有限。

**结论：否决。**

## 四、综合对比

| 维度 | 方案一：K/M/B | 方案二：万/亿 | 方案三：原样+布局 |
|:---|:---|:---|:---|
| 中文读数直观性 | 低（需换算） | 高 | 中（位数长） |
| 位数上限恒定 | ✅ | ✅ | ❌ |
| 中文 UI 风格一致 | 中 | 高 | 高 |
| 实现成本 | 低 | 低 | 最低 |
| 长期可维护性 | 高 | 高 | 低 |
| 推荐结论 | 备选 | **推荐** | 否决 |

## 五、共通补充约定（任一方案均适用）

1. tooltip 与格子悬停信息继续显示精确千分位数字，缩写只用于底部汇总标签。
2. 缩写逻辑抽为公共纯函数（建议放 `src/ide/core/token_stats.py`，零 Qt 依赖，便于测试与复用），命名如 `format_token_amount()`。
3. 数据层（`UsageSummary`、落盘 schema）一律不变。
