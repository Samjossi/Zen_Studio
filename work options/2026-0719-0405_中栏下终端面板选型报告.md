## 1. 背景与需求

中栏下目前为占位面板（`make_panel("中栏下")`），定位为**内嵌终端**。AI-first 语境下的职责：

1. **用户自己的命令通道**：`git`、`uv run`、测试脚本等即席命令（AI 不代办时的手边工具）
2. **CLI 运维入口**：`kimi login`（device-code 流程）、`kimi doctor` 等需真实终端交互的操作
3. **程序输出观察**：长驻进程日志、带颜色的测试报告

明确边界：agent 的 shell 执行在 kimi 本地（ACP terminal 反向 RPC 官方未实现，见 1555 计划 C1 纪要），**本面板不承接 agent 命令展示**——它是用户终端，不是 agent 终端的镜像。本期单实例起步；多 tab、分栏列入备案。

## 2. 参考实现调研结论

| 项目 | 终端相关资产 | 结论与教训 |
|:---|:---|:---|
| Multi_Cli_Studio | **PTY 会话管理**（`main.rs` ensure/write/resize/close 四命令，≈160 行核心，portable-pty）★★★★★；**终端 Dock 交互**（`TerminalDock.tsx` 458 行，xterm.js）★★★★ | 全仓对该需求价值最高：**"每 tab 一会话表 + reader 线程 + 事件推送"架构可直接照搬为 Python `pyte` + `QThread` + `pyqtSignal`**；Dock 交互（`QTabWidget` + `QSplitter` + `QSettings`）为多 tab 期规格 |
| theia-zen | `packages/terminal/`（xterm.js 5.3 前端）+ `packages/process/`（node-pty 后端）前后端分离 ★★★★ | 前后端分离思想对 PySide6 的启发已给出明确路线：**`pyte` 屏幕模拟 + `ptyprocess` + 自绘 QWidget**，或 QWebEngineView 嵌 xterm（后者与 viewer 选型一致否决） |
| VS_Code_Python（PyGPT） | 调试控制台 `console.py`（190 行，QLineEdit）★★★★★；代码解释器 ~2600 行 ★★★ | ⚠️ 控制台**非真终端**（无 PTY、无转义序列处理），仅"命令行+输出回显"；彩色/交互式程序会输出乱码——本期需求超出其能力，仅命令历史 ↑↓ 交互可借鉴 |

**关键启示**：

- 真终端的技术栈三家一致收敛：**PTY 后端 + 终端模拟器（屏幕模型）+ 渲染前端**三层；PySide6 对应 `ptyprocess` + `pyte` + 自绘 QWidget。
- **依赖底牌实测**（2026-07-19）：`pyte`/`ptyprocess` 未装（均为**纯 Python** 小库，`uv add` 零风险）；stdlib `pty` 可用（后端备选）。
- Multi_Cli 的 160 行会话管理核心证明：PTY 层可以很薄，复杂度集中在渲染前端——选型重点在渲染路线。

## 3. 候选方案对比（四个维度）

### 3.1 维度一：终端形态

| | A. 真 PTY 终端 | B. 简化命令控制台（无 PTY） |
|:---|:---|:---|
| 做法 | 子进程挂伪终端，全量处理 ANSI 转义序列 | `QLineEdit` 输入 + `QProcess` 执行 + 纯文本回显（PyGPT console 路线） |
| ✅ 优点 | 颜色/光标/交互式程序（vim、top、less、`kimi login` device 流程）全部可用；cwd 状态天然保持 | 实现约 200 行零依赖 |
| ❌ 缺点 | 需终端模拟器层（pyte）与渲染层，复杂度集中在 3.2 | **不是终端**：彩色输出变乱码、交互程序全灭、每条命令独立无会话状态；对 IDE 而言是信用短板 |

### 3.2 维度二：渲染引擎路线（终端模拟器 + 前端）

| | A. `pyte` + 自绘 QWidget | B. QWebEngineView 嵌 xterm.js | C. QTermWidget（C++ 绑定） |
|:---|:---|:---|:---|
| 做法 | pyte 做 VT100 屏幕模型（`Stream` 喂字节流 → `Screen` 字符网格），自绘控件 paintEvent 画网格 + 光标，`keyPressEvent` 映射按键 → 控制序列 | Web 视图加载 xterm.js，Python↔JS 桥接 I/O | Qt 原生 C++ 终端控件（QTerminal/lxqt 同款） |
| ✅ 优点 | **纯 Python 双小库**（pyte/ptyprocess）；原生 Qt 外观、qss 主题同体系；无 Web 重量；屏幕模型可读（未来"把终端内容喂给 AI"白送的特性）；Multi_Cli 架构官方建议路线 | xterm.js 久经考验（VS Code 同款），渲染/选区/回滚全免写 | 渲染/输入全免写，功能最全 |
| ❌ 缺点 | 自绘层需自研（~400-600 行：网格绘制、ANSI 16 色调色板、按键映射表、滚动条）；pyte 更新不活跃（但 VT100 功能成熟稳定） | WebEngine 百 MB 级重量（viewer 选型已两次否决同构方案）；JS 桥 I/O 与键位事件繁琐；主题不一致 | **PySide6 绑定可得性差**（官方绑定以 PyQt 为主）；新增二进制依赖；与 qss 双主题打通成本高 |

### 3.3 维度三：PTY 后端

| | A. `ptyprocess` | B. stdlib `pty` + `os` |
|:---|:---|:---|
| ✅ 优点 | API 干净（`spawn`/`read`/`write`/`setwinsize`/`isalive`），与 pyte 同生态；读超时控制方便 | 零依赖 |
| ❌ 缺点 | 多一个小依赖（纯 Python） | `fork`/`exec`/`setwinsize` 需手工编排（`fcntl`+`termios`），易错且基本是在重写 ptyprocess |

### 3.4 维度四：会话与布局

| | A. 单实例固定面板 | B. 多 tab + 分栏 Dock |
|:---|:---|:---|
| 做法 | 中栏下整区一个终端会话 | `QTabWidget` 多会话 + 可拖放分栏（Multi_Cli Dock 规格） |
| ✅ 优点 | 装配最简（替换占位面板即完成）；覆盖本期全部需求 | 多任务并行（日志 + 即席命令） |
| ❌ 缺点 | 单会话 | tab 管理/会话表/布局持久化一整层，本期过度；备案（Multi_Cli `TerminalDock.tsx` 规格留档） |

## 4. 综合对比与推荐结论

🟢 **推荐组合：A + A + A + A**——真 PTY 终端，`ptyprocess` 后端 + `pyte` 屏幕模拟 + 自绘 QWidget 前端，单实例固定面板起步：

| 维度 | 决策 | 理由 |
|:---|:---|:---|
| 终端形态 | **A. 真 PTY** | 颜色/交互程序/`kimi login` 全可用；控制台路线对 IDE 是信用短板 |
| 渲染引擎 | **A. pyte + 自绘 QWidget** | 纯 Python 双小库零重型依赖；原生主题一致；与 viewer 选型同一哲学（原生 Qt 优先，WebEngine 否决）；屏幕模型顺带产出"终端内容可喂 AI"的协议资产 |
| PTY 后端 | **A. ptyprocess** | 与 pyte 同生态的干净 API；stdlib 路线等于重写它 |
| 会话布局 | **A. 单实例起步** | 本期需求全覆盖；多 tab Dock 按 Multi_Cli 规格备案 |

**B/C 否决记录**：xterm.js 路线 WebEngine 重量与桥接成本，否决（同 viewer 选型结论）；QTermWidget 的 PySide6 绑定可得性与主题成本不可控，否决。

## 5. 实施要点（供后续计划引用）

1. **依赖**：`uv add pyte ptyprocess`（均纯 Python）。
2. **新增子包** `gui/panels/terminal/`：
   - `session.py` — `PtySession`：`ptyprocess.spawn($SHELL)`（cwd=项目根），reader 线程读字节流 → 回调推送（照搬 Multi_Cli ★★★★★ 会话架构的 Python 版）；`write(data)`/`resize(rows, cols)`/`terminate()`；进程退出检测
   - `screen.py` — `TerminalScreen`：pyte `Screen`（+ `History` 回滚）+ `Stream` 喂流；ANSI 16 色 × 明暗双调色板
   - `widget.py` — `TerminalWidget(QWidget)`：paintEvent 画字符网格（等宽字体、按格背景色/前景色/反转/粗体）+ 光标；`keyPressEvent` → VT100 序列映射（方向键/Home/End/PgUp/PgDn/Delete/Ctrl 组合）；resizeEvent → `setwinsize` + `Screen.resize`；滚动条映回滚区
   - `panel.py` — `TerminalPanel`：标题行（shell 名 + 状态）+ `TerminalWidget`；装配会话生命周期（进程退出提示 + 重开）
3. **接线**：`main_window.py` 以 `TerminalPanel` 替换 `make_panel("中栏下")`；应用退出时终止会话（防子进程残留，同 ACP 后端的 atexit 纪律）。
4. **主题**：16 色 ANSI 调色板按明暗双主题各一份（`config/themes/` 同源色板），`apply_theme` 联动。
5. **剔除**（本期）：多 tab/分栏、文本选区复制、超链接识别、输入法（fcitx）精细支持、`tmux` 控制模式。
6. **验证要点**：颜色输出（`ls --color`）、交互程序（`vim` 打开退出、`top` 刷新）、`kimi login` device 流程、CJK 宽字符对齐（pyte wcwidth）、resize 后重排、shell 退出后面板状态。
