# PDF 文件预览功能选型

> 本篇与 `2026-0725-1849_图片文件预览功能选型.md` 同属"中栏可预览文件类型扩展"系列，共享同一接入架构（`ViewerPanel.open_file` 按 kind 分流 + `QStackedLayout`），仅在控件层与该类型特有逻辑上独立成篇。

## 1. 背景与目标

Zen Studio 中栏查看器当前对 `.pdf` 文件的处理：读字节 → UTF-8 解码失败 → 标题行提示"（二进制文件，共 N 字节，不支持预览）"。工作区内的 PDF 文档（规格说明、研究报告、打包产物说明等）无法就地浏览，只能外部程序打开。

**目标**：在中栏就地预览 PDF，支持翻页、连续滚动、缩放，复用现有查看面板基建（标题行、外部修改自动重载），不引入重型依赖。

## 2. Zen Studio 现状与接入点

接入架构与图片选型一致：`ViewerPanel.open_file` 头部按文件类型分流——文本→`CodeViewer`，图片→image_viewer，**PDF→PdfView**，二进制→占位。三者用 `QStackedLayout` 在同一面板切换。详见图片选型文档 §2.3 / §4.3。

**技术底牌（已实测）**：`PySide6.QtPdf` 与 `PySide6.QtPdfWidgets` 随项目 `pyside6>=6.11.1` 就绪（import 探针通过），**零新增第三方依赖**。

## 3. 参考项目调研

| 项目 | PDF 预览实现 | 可借鉴点 |
|:---|:---|:---|
| theia-zen | 后端 `PdfHandler`（`packages/mini-browser/src/node/mini-browser-endpoint.ts`）回传 `application/pdf` 字节，前端 iframe 调用 **Chromium 原生 PDF 查看器** | 仅思路：浏览器内核原生渲染；控件层不可移植 |
| Multi_Cli_Studio | 前端 `<object data={src} type="application/pdf">`，同样靠 **Webview 浏览器原生 PDF 渲染**；>4MB 截断 | kind 分流架构（已在图片选型采纳）；控件层不可移植 |
| VS_Code_Python | ❌ 未实现 PDF 预览 | — |

**关键观察**：两个实现 PDF 预览的参考项目**都依赖浏览器内核**（Chromium/Webview）。Zen Studio 走原生 Qt 路线（WebEngine 已否决），需用 Qt 自带的 PDF 能力重写——而这恰好是 Qt 6 提供的现成模块。

## 4. 候选方案

| | 方案 A：QtPdf（`QPdfDocument` + `QPdfView`） | 方案 B：`QWebEngineView` 加载 PDF | 方案 C：第三方库渲染为图 | 方案 D：外部查看器 |
|:---|:---|:---|:---|:---|
| 描述 | Qt 原生 PDF 模块，`QPdfView` 直接承载 `QPdfDocument` | Chromium 原生 PDF 渲染 | `PyMuPDF`(fitz)/`pypdf` 把每页渲染成 `QPixmap` 自行显示 | `QDesktopServices.openUrl` 调系统 PDF 阅读器 |
| 渲染 | 矢量（Qt PDF 引擎） | 矢量（Chromium） | 栅格化 | — |
| 缩放/滚动 | ✅ `QPdfView` 内建（连续/单页模式、`setZoomFactor`） | ✅ 浏览器原生 | 需自绘 | — |
| 文本选择 | ✅ 支持 | ✅ | ❌（已成像素） | — |
| 新增依赖 | 无（PySide6 自带） | 无，但 🔴 违背路线 | ⚠️ 新增二进制依赖（fitz 含 C 扩展） | 无 |
| 就地预览 | ✅ | ✅ | ✅ | ❌（弹外部窗口） |

### 方案 B 否决
项目在 viewer / 终端 / 聊天面板选型中**一致否决 WebEngine**（见 `文档/选型记录/2026-0719-0205_中栏代码显示与语法高亮选型报告.md`、`2026-0719-0405_中栏下终端面板选型报告.md`："原生 Qt 优先，WebEngine 否决"）。🔴 **否决**。

### 方案 C 否决
栅格化丢失矢量优势（缩放模糊）、丧失文本选择、且引入 `PyMuPDF` 等重型 C 扩展依赖（与项目零重型依赖哲学冲突）。仅在 QtPdf 不可用的假设下才考虑，但已实测 QtPdf 可用。🔴 **否决**。

### 方案 D 定位
不满足"就地预览"目标，但可作为**降级兜底**（加密/损坏/QtPdf 渲染失败的 PDF → 菜单"在外部程序打开"）。✅ 保留为辅助。

## 5. 推荐方案：A（QtPdf）

`QPdfView`（`PySide6.QtPdfWidgets`）+ `QPdfDocument`（`PySide6.QtPdf`）：

| 能力 | 说明 |
|:---|:---|
| 加载 | `QPdfDocument.load(path)` / `setFileName`，异步加载状态机（Loading/Ready/Error） |
| 显示 | `QPdfView.setDocument(doc)`，`ViewMode.MultiPage` 连续滚动 / `SinglePage` 单页 |
| 缩放 | `setZoomFactor(1.0)`，可接滚轮/按钮 |
| 文本选择 | 内建支持（可复制） |
| 页面导航 | `QPdfDocument.pageCount`、`QPdfView.currentPage` |
| 错误处理 | `QPdfDocument.Error` 状态 → 标题行提示 + 兜底外部打开 |

## 6. 风险与实施要点

1. **打包态插件收编（首要风险）**：`QPdfView` 运行时依赖 Qt 的 PDF 插件（`plugins/imageformats`、PDF 渲染后端）。PyInstaller spec 需确认 QtPdf 相关 binary/plugin 已收编；**必须在 onedir/AppImage 实机验证**（开发态 import 通过 ≠ 打包态可用，此为 Qt 扩展模块的常见坑）。
2. **新增控件**：`gui/panels/viewer/pdf_viewer.py`，`QPdfView` 派生或组合，封装加载/缩放/错误兜底。
3. **ViewerPanel 改造**：`QStackedLayout` 增加 PdfView 页，`open_file` 对 `.pdf` 分流。扩展名判定 `path.lower().endswith(".pdf")`。
4. **主题适配**：`QPdfView` 背景/配色接入 `gui/theme.py` 体系（与 CodeViewer/image_viewer 同模式）。
5. **外部修改重载**：复用现有 `QFileSystemWatcher`，PDF 文件被外部修改时重新 `load`。
6. **大文件**：`QPdfDocument` 流式加载，无需像图片那样设字节守卫；但可对超大 PDF 提示页数。
7. **降级兜底**：右键/标题栏菜单"在外部程序打开"（`QDesktopServices.openUrl`），覆盖加密/损坏场景。
8. **验证**：多页/单页/含图/含表/加密 PDF 目检 + 缩放/滚动/文本选择 + 双主题 + 外部修改重载 + **打包态实机**。

## 7. 待决策项

1. 默认视图模式：连续滚动（`MultiPage`，推荐，贴合现代 PDF 阅读习惯）vs 单页。
2. 是否本期做"在外部程序打开"兜底菜单（推荐做，成本低、覆盖异常 PDF）。
