## 0. 语义族铁律（本计划最高约束 ⭐ 重点标注）

Git 状态是**语义信息，不是装饰色**。五键按下表约束色相族，主题只允许在族内微调明暗/饱和度，**禁止跨族**：

| 键 | 语义族 | 现状 |
|:---|:---:|:---|
| modified | 🔵 蓝族 | 当前四主题共享 `#1e88e5`（天然在族）；1643 若按 §5.3 初值执行则 wheat 琥珀/mint 绿出族，本计划回改 |
| untracked | 🟢 绿族 | ✅ 四主题已统一 `#1f8a3d`，不动 |
| deleted / conflict | 🔴 红族 | ✅ 已统一 `#c0392b` / `#d40000`，不动 |
| ignored | ⚪ 灰族（允许冷暖适配微调） | ✅ 0253 已做冷暖灰适配，保留不动 |

**拍板口径（姊妹项目用户走查讨论定稿，本项目沿用）**：

1. 走「语义族约束」路线，不走「四主题逐像素同值」路线——族内色相一致即满足稳定认知，且与业界主流（VS Code / JetBrains 状态色跨主题近统一、仅对比度微调）一致。
2. 暖色调主题（wheat）取**偏灰的低饱和蓝**，降低冷暖冲突，但不要蓝到跳出灰感。
3. 族约束的现实收益：mint 若按 1643 §5.3 初值取绿 `#0f6e3f`，与 untracked 绿 `#1f8a3d` 几乎无法区分，是 bug 级观感缺陷，入蓝族即修复。

## 1. 背景与需求

用户走查右栏下方**变更面板**（`src/ide/gui/panels/changes/list.py`）发现：文件路径列字色随主题变化且色相族漂移——wheat 的琥珀、mint 的绿都不读作"已修改"。色值来自调色板 `git_status` 包的 `git_status_color(theme, status)`。五键现状：

| 键 | 现状 | 来源 |
|:---|:---|:---|
| untracked / deleted / conflict | 四主题已统一 | 语义色，不动 |
| modified | 当前共享 `#1e88e5`；1643 归位后逐主题不同 | 1643 蓝键归位：非蓝主题取 accent 同族深色档，导致琥珀/绿混入 |
| ignored | 逐主题冷暖灰适配 | 0253 口径，灰族内微调，符合铁律 |

## 2. 现状机制

- 消费方两处，均按键取值、零消费方代码改动预期：
  - 变更面板 `changes/list.py`：路径列按 `file_status` 着色（:93）、占位提示用 `IGNORED`（:78）、`+`/`-` 统计列用 `UNTRACKED`/`DELETED`（:103）；
  - 文件树 `file_explorer/model.py` 的 `GitStatusProxyModel`：`ForegroundRole` 按文件/目录聚合状态着色，与变更面板同数据源。
- 测试守护（`tests/test_theme.py`，经 1643/0253 重写后的结构）：`_THEME_BLUES` 有各主题 `git_modified` 槽、`_THEME_ADAPTED` 有各主题 `ignored` 槽、`_SHARED_LEGACY["git_status"]` 仅 untracked/deleted/conflict——「维持 ∪ 适配 = 全键」等式断言自动覆盖变动。

## 3. 目标

## 8. 已定决策（姊妹项目走查讨论拍板，本项目沿用）

- **D1 路线**：语义族约束 + 族内微调（§0 铁律）。否决项：a) 四主题逐像素同值（过度统一，抹掉 sky 的合法微调）；b) 维持 1643 accent 归位现状（琥珀/绿不读作"已修改"）。
- **D2 暖主题取值**：偏灰的低饱和蓝。理由：压冷暖冲突；色饱和度让位于色温和谐——但姊妹项目二轮终裁把"看得出蓝"排在灰感之前（§5.1 wheat B=160）。
- **D3 ignored**：保留 0253 冷暖灰适配，不统一。理由：灰族内微调合法，且"忽略=弱化"是层级语义，冷暖灰的观感收益真实。
- **D4（本项目适配）mint 取值**：姊妹项目 mint 终值取 cloud 基准蓝 `#0765d4`；若你希望 mint 保持一点个性，可在蓝族内（200°–222°）另选，对比度 ≥4.5 前提下走查定夺。🟡 建议：直接用 `#0765d4`，与 cloud 同源零风险。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
