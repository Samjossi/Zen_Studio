# ACP 工具调用 kind 兜底推导落地计划

> **状态**：已实施（修改记录：`文档/修改记录/2026-1018-2002_ACP工具调用kind兜底推导修改记录.md`）
> **范围**：ACP 公共映射层（`src/llm/providers/acp.py`）、DSH 后端（`src/llm/providers/dsh_acp.py`）、聊天面板卡片分派（`src/gui/panels/chat/cards.py`）
> **时间**：2026-10-18 19:47（设计，UTC+8）/ 2026-10-18 20:02（实施）
> **优先级**：中

## 需求

1. DSH 后端执行任务时，聊天面板工具卡片不再清一色通用卡：bash 命令出 BashCard、write/edit 出 DiffCard、read/search 出 TextOutputCard、todo_write 出 TodoListCard、subagent 出 SubagentCard。
2. 修复做成**通用兜底机制**：任何 ACP 后端在 kind 缺失或敷衍上报时都能受益，未来新增后端零成本接入。
3. Kimi 后端现有行为**零变化**：Kimi 如实上报语义化 kind，兜底推导不得覆盖、不得干扰。

## 关键探查结论（已核实）

- **卡片分派两级制**（`src/gui/panels/chat/cards.py` `make_tool_card`）：先按工具名（title 归一化后）查 `_TOOL_NAME_CARDS`（仅 askuserquestion/ask/agent/task/readmediafile/todolist/todowrite 七项），未命中再按 `tool_kind` 分派（execute→BashCard、edit→DiffCard、read/search/fetch→TextOutputCard、think→SubagentCard），兜底 McpCard 通用卡。
- **Kimi 帧带真实 kind**：`文档/帧存档/` 实抓帧证实 title=`Bash`/kind=`execute`、title=`Edit`/kind=`edit`；Agent/TodoList/AskUserQuestion 的 kind 是 `other`，靠一级工具名分派命中专属卡。
- **DSH 侧根因在 DSH 自己**：`参考代码/deepseek-harness/packages/acp/acp/src/updates.ts` 的 `toolCallUpdate` 把 `kind` 硬编码为字面量 `'other'`，是其刻意设计（README 明说不向自动化端暴露呈现层数据），无任何配置开关。DSH 模型侧工具实际很丰富（bash/pwsh/read/write/edit/read_image/fs-search/todo_write/web/skill/subagent 等，见 `参考代码/deepseek-harness/packages/bundle/base/cordis.patch.yml`）。
- **zen_studio 适配层原样透传无改写**：`src/llm/providers/acp.py` `_map_tool_call` 取帧 `title` 与 `kind`，kind 缺失归 `other`。Kimi（`src/llm/providers/kimi_acp.py`）与 DSH（`src/llm/providers/dsh_acp.py`）共用同一 `map_session_update`。
- **update 帧通常不带 kind**：tool_call_update 帧缺 kind 字段，首帧登记、后续帧回填的账本机制已有同构先例（`_input_detail_seen`）；子代理 wire 旁路的 `_WIRE_TOOL_KINDS`（`src/llm/providers/kimi_acp.py`）也是「工具名→kind」映射的先例，但属 Kimi 私有，不在本计划复用范围。
- **图标与默认开合只认 kind**：`_KIND_ICONS`、`_DEFAULT_OPEN`（`src/gui/panels/chat/cards.py`）按 kind 键控，kind 推导正确后这些表现自动跟随生效。

## 根因归纳

| 症状 | 根因 | 确定性 |
|---|---|---|
| DSH 全部工具落通用卡 | DSH ACP 投影层 kind 恒为 `other`，zen_studio kind 分派全部落空 | ✅ 源码确证 |
| 观感像「全归到 Bash 卡」 | 所有工具共用同一张 McpCard，且 DSH 最高频工具恰叫 bash，标题清一色 "bash" | ✅ 源码确证 |
| Kimi 卡片丰富 | Kimi 如实上报语义化 kind + 工具名一级分派 | ✅ 帧存档实证 |

## 设计决策

- **修复点放公共映射层**（`src/llm/providers/acp.py`），不放 `src/llm/providers/dsh_acp.py`：让兜底对一切 ACP 后端生效，DSH 只是第一个受益者。
- **只兜底、不覆盖**：仅在 kind 缺失或为 `other` 时按工具名推导；后端明确上报的 kind 一律原样透传。Kimi 路径行为逐字节不变。
- **推导不认识的工具名保持 `other`**，落 McpCard——与现状一致的保守兜底，绝不猜测。
- **不改 DSH 源码**：`参考代码/` 为只读参照，且 DSH 侧无开关可开。
- **不改卡片分派主逻辑**：`make_tool_card` 两级分派结构不动，仅工具名归一化规则可能需兼容下划线命名（见实施步骤 3）。

## 实施步骤

### 1. kind 兜底推导表（`src/llm/providers/acp.py`）

- 新增模块级常量 `_FALLBACK_TOOL_KINDS`（工具名归一化后小写 → kind）：

```python
# src/llm/providers/acp.py
_FALLBACK_TOOL_KINDS = {
    "bash": "execute", "pwsh": "execute", "shell": "execute", "terminal": "execute",
    "write": "edit", "edit": "edit", "patch": "edit",
    "read": "read", "read_image": "read",
    "grep": "search", "glob": "search", "fs-search": "search", "fs_search": "search",
    "web": "fetch", "web_search": "fetch", "web_fetch": "fetch", "fetch": "fetch",
    "todo_write": "other",   # 显式登记：交给卡片侧工具名分派，不借 kind 通道
    "subagent": "think", "task": "think",
}
```

- `_map_tool_call` 中：kind 缺失或为 `other` 时，用归一化 title 查表，命中则填推导 kind；查不到保持 `other`。
- 推导命中后按 toolCallId 记入账本（仿 `_input_detail_seen` 同构），tool_call_update 帧缺 kind 时回填首帧推导结果，保证运行中/完成态帧 kind 稳定不漂移。

### 2. 归一化兼容下划线命名（`src/llm/providers/acp.py`）

- 工具名归一化在现有「剥 `mcp__` 前缀 + 小写」基础上，确认对 `fs-search`/`todo_write` 这类连字符/下划线命名的处理：表内同时收录两种写法（如上），或在归一化处统一 `-`→`_`——实施时取改动面更小者，注释只写 why（DSH 工具命名与 Kimi 风格不一致）。

### 3. todo_write 卡片通道（`src/gui/panels/chat/cards.py`）

- 现状 `_TOOL_NAME_CARDS` 有 `todowrite` 但 DSH 工具名是 `todo_write`（含下划线）。检查 `_normalize_tool_name` 是否剥下划线；若不能命中，最小改动让 `todo_write` 落到 TodoListCard。
- 其余卡片（BashCard/DiffCard/TextOutputCard/SubagentCard）经 kind 推导自动生效，无需改卡片代码。

### 4. 测试

- 新增用例（归入现有 ACP/DSH 测试文件，如 `tests/test_dsh_backend.py` 或按 `tests/README.md` 惯例选址）：
  - DSH 风格帧（title=`bash`、kind 缺失或 `other`）→ 映射结果 kind=`execute`。
  - title=`write`/`edit` → `edit`；title=`read` → `read`；title=`todo_write` → 卡片落到 TodoListCard；title=`subagent` → SubagentCard。

  - **Kimi 回归**：kind 明确上报为 `execute`/`edit` 的帧，推导不生效，结果逐字段不变。
  - update 帧回填：首帧推导后，同 toolCallId 的 update 帧 kind 一致。

## 风险与边界

| 项 | 说明 |
|---|---|
| ⚠️ 工具名撞名 | 未来某后端工具名与表内条目撞名但语义不同（如别家 `run` 非 shell）。因推导只在 kind 缺失时兜底、永不覆盖显式上报，风险可控；真撞上时按后端细分表，另行立项 |
| ⚠️ `think`→SubagentCard 复用 | `subagent`/`task` 借 `think` kind 通道出子代理卡，是现有 kind 语义的就势复用；若未来 ACP 引入真正语义化的子代理 kind，届时切换 |
| 🟢 表可扩展 | `_FALLBACK_TOOL_KINDS` 是开放表，新后端接入时按需补条目即可 |
