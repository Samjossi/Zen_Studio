# Token 用量热力图跨 IDE 账本共享落地计划

> **状态**：已实施
> **范围**：`src/ide/core/paths.py`（用户级路径根）、`src/ide/core/token_stats.py`（账本路径与落盘）、`tests/test_token_stats.py`（路径与共享回归）、`scripts/merge_token_usage.py`（可选迁移工具）、`config/README.md` / `src/ide/core/README.md`（文档）；两个同源 IDE 项目的账本路径契约
> **时间**：2026-11-17 06:27（UTC+8，设计）
> **优先级**：高

> 本文同时作为两个同源 IDE 项目的**共同契约**。项目 B 可直接按本文实施，也可在其 `work plans/` 下复制一份并替换头部时间；但第 4 节的路径规则、第 5 节的 schema、第 6 节的合并规则不得分叉，否则两边仍然无法同账。

---

## 1. 背景与问题定性

### 1.1 现象

同一份源码被复制到另一个路径，形成项目 A / 项目 B，各自启动 IDE。两边都能正常对话、都产生真实 token 消耗，但热力图各看各的：在 A 里看不到 B 的消耗，在 B 里看不到 A 的消耗。看起来像“一个 IDE 用了，另一个就不记录”。

### 1.2 代码事实

- `src/ide/core/token_stats.py` 的 `USAGE_FILE = USER_CONFIG_DIR / "token_usage.jsonl"`。
- `src/ide/core/paths.py` 的 `USER_CONFIG_DIR` 在开发态等于 `PROJECT_ROOT / "config"`，打包态才分流到 `${XDG_CONFIG_HOME:-~/.config}/zen-studio/`。
- 因此项目 A 写 `A/config/token_usage.jsonl`，项目 B 写 `B/config/token_usage.jsonl`，是两个文件。
- `turn_id` 的构成为“CLI 会话 UUID + 轮次计数”（kimi 在 `kimi_acp.py`，DSH 在 `dsh_acp.py`）；去重只在当前写入的那个文件内生效。
- 两个 IDE 各自创建自己的 CLI 会话，会话 UUID 不同，**不存在跨副本互相压制**；真实情况是“分账”，不是“漏记”。
- 如果复制源码时连同 `config/` 一起复制，历史记录也会被复制成两份；合并时必须按 `turn_id` 去重，不能直接相加。
- 如果只有一份副本改了代码、另一份仍跑旧代码，旧副本会继续写自己的 `config/`，共享仍然不成立。

### 1.3 结论

采集链路、`TurnConsumption`、热力图渲染都没有问题。问题只在**账本路径跟着源码副本走**。要共享，只需让同一用户下的所有副本读写同一个绝对路径的账本文件；其余代码不动。

## 2. 目标与非目标

### 2.1 目标

1. 同一 OS 用户下，所有源码副本、所有 IDE 实例、开发态与打包态，共用一本 Token 用量账本。
2. 账本路径不再受 `PROJECT_ROOT` 影响；复制源码不会再复制出一本新账。
3. 历史数据可迁移：按 `turn_id` 去重，幂等，可重复执行，不丢记录、不重复计数。
4. 改动最小：不改 kimi / DSH 的采集实现，不改 `Chunk.consumption`，不改热力图弹窗与聚合算法。
5. 两个同源项目按同一契约落地，账本文件可以互换、可以合并。

### 2.2 非目标

- 不做中央服务、数据库、网络同步或账号体系。
- 不共享 `settings.json`、`window_state/`、`sessions/`、`recent_projects.json`；这些仍按各副本/各工作区独立。
- 不新增“来源 IDE”字段（`source`）；本期只关心总花费。若后续要拆分来源，另立计划，两个项目同步加字段。
- 不支持不同 OS 用户、跨机器共享；跨机器需要额外的文件同步，且 `flock` 在 NFS 上不可靠。
- 不改变计量口径（输入含缓存读写 + 输出）、日期归属（轮次收尾本地日期）、今日/最近七天/最近三十天窗口、0~4 分档算法。

## 3. 方案选择

| 方案 | 做法 | 评价 |
|:---|:---|:---|
| **A. 用户级固定路径** | 账本固定到 `${XDG_CONFIG_HOME:-~/.config}/zen-studio/token_usage.jsonl` | ✅ **推荐**：所有副本自动同账，无需每副本维护 |
| B. 每副本软链 | 把各副本的 `config/token_usage.jsonl` 与 `token_usage.lock` 都软链到同一个真实文件 | 🟡 零改码的过渡方案；每复制一份源码都要重做，且只链数据不链锁会破坏互斥 |
| C. 整个 `config/` 共享 | 软链或共用整个配置目录 | ❌ 拒绝：`settings`、窗口状态、会话存档会互相污染 |
| D. 仅加环境变量 | 启动时设置 `ZEN_TOKEN_USAGE_FILE` | 🟡 作为 A 的覆盖手段，不作为默认；桌面启动容易漏设 |

**选 A。** 理由：Token 用量是“用户花了多少钱”的账，不是某个源码副本的项目状态。它本来就应该跨工作区、跨副本、跨开发/打包态；放在项目 `config/` 是路径归属错误。A 方案只改路径解析，采集与展示零改动，且一劳永逸。

## 4. 账本路径契约（两个项目必须逐字一致）

### 4.1 默认路径

```text
${XDG_CONFIG_HOME:-$HOME/.config}/zen-studio/token_usage.jsonl
```

锁文件固定为同目录的 `token_usage.lock`。

选 `~/.config` 而不是 `~/.local/state`，是为了与打包态现有 `USER_CONFIG_DIR` 对齐，避免已安装用户再迁一次；用量历史虽然更接近 XDG state 语义，但本期以“少改动、单一目录”优先。

### 4.2 解析优先级

1. `ZEN_TOKEN_USAGE_FILE` 环境变量（最高优先级）。
   - 必须是绝对路径，或以 `~` 开头（经 `expanduser()` 后为绝对路径）。
   - 相对路径视为配置错误：记 warning，回退默认路径，避免写盘落点随进程 CWD 漂移。
2. 默认路径：`USER_GLOBAL_CONFIG_DIR / "token_usage.jsonl"`。
   - `USER_GLOBAL_CONFIG_DIR` 固定为 `${XDG_CONFIG_HOME:-$HOME/.config}/zen-studio`。
   - `XDG_CONFIG_HOME` 必须是绝对路径；相对路径按 XDG 规范忽略，回退 `$HOME/.config`（与 `paths.py` 现有纪律一致）。

### 4.3 关键约束

- **开发态与打包态同指**：账本不再按 `IS_FROZEN` 分流。开发态也写用户目录，这样 `python main.py` 与 AppImage/打包版能同账。
- **应用目录名必须一致**：两个项目都必须使用 `zen-studio` 作为用户级目录名。若项目 B 的应用名不同，必须把它的 `USER_GLOBAL_CONFIG_DIR` 改为 `zen-studio`，或启动时显式设置 `ZEN_TOKEN_USAGE_FILE`；否则默认路径不同，仍然分账。
- **锁必须同源**：`record_turn` 当前用 `target.with_suffix(".lock")` 推导锁路径。只要 `USAGE_FILE` 相同，锁就相同；不要另写别的锁名，也不要把数据和锁分别指向不同目录。
- **路径在进程启动时定型**：`USAGE_FILE` 是模块级常量，运行中改环境变量不生效；必须重启 IDE。
- **只共享账本，不共享配置目录**：`USER_CONFIG_DIR` 保持原语义（开发态项目 `config/`、打包态 XDG），不要顺手把 `settings.json` 等也搬走。

## 5. 代码改动

### 5.1 `src/ide/core/paths.py`：增加用户级全局根

保留现有 `USER_CONFIG_DIR` 语义不变，只把 XDG 解析抽成可复用函数，并新增 `USER_GLOBAL_CONFIG_DIR`：

```python
# src/ide/core/paths.py

def _xdg_config_dir() -> Path:
    """用户级配置根：开发态与打包态同指，供跨副本共享数据使用。"""
    xdg = Path(os.environ.get("XDG_CONFIG_HOME") or "")
    base = xdg if xdg.is_absolute() else Path.home() / ".config"
    return base / "zen-studio"


def _user_config_dir() -> Path:
    if not _MEIPASS:
        return PROJECT_ROOT / "config"
    return _xdg_config_dir()


USER_CONFIG_DIR = _user_config_dir()

#: 用户级全局数据根：不受源码副本位置影响；Token 用量账本等跨副本共享数据
USER_GLOBAL_CONFIG_DIR = _xdg_config_dir()
```

要点：

- `USER_CONFIG_DIR` 的行为完全不变：开发态仍是项目 `config/`，打包态仍是 XDG。
- 新增的 `USER_GLOBAL_CONFIG_DIR` 在两种形态下都指向用户目录，是“跨副本共享数据”的唯一入口。
- 若项目 B 的 `paths.py` 没有 `_MEIPASS` / `PROJECT_ROOT` 这套逻辑，按等价方式实现即可；关键是最终导出的 `USER_GLOBAL_CONFIG_DIR` 与项目 A 完全相同。

### 5.2 `src/ide/core/token_stats.py`：账本改用用户级路径

```python
# src/ide/core/token_stats.py

import logging
import os
from pathlib import Path

from ide.core.paths import USER_GLOBAL_CONFIG_DIR

logger = logging.getLogger(__name__)


def _usage_file() -> Path:
    """账本路径：所有源码副本/实例共用一本，必须是用户级绝对路径。"""
    override = os.environ.get("ZEN_TOKEN_USAGE_FILE")
    if override:
        candidate = Path(override).expanduser()
        if candidate.is_absolute():
            return candidate
        logger.warning(
            "ZEN_TOKEN_USAGE_FILE 必须是绝对路径，已回退默认路径: %s", override)
    return USER_GLOBAL_CONFIG_DIR / "token_usage.jsonl"


USAGE_FILE = _usage_file()
USAGE_LOCK_FILE = USAGE_FILE.with_suffix(".lock")
```

同时更新模块 docstring 中的存储说明，把“`config/token_usage.jsonl`（打包态经 USER_CONFIG_DIR 分流至 XDG）”改为“用户级 `${XDG_CONFIG_HOME:-~/.config}/zen-studio/token_usage.jsonl`（所有源码副本/实例共用）”。

### 5.3 兼容性说明

- `record_turn(path=...)` 与 `load_daily(path=...)` 的显式路径参数保持不变；现有 `tests/test_token_stats.py` 用 `tmp_path` 的用例无需改。
- `USAGE_LOCK_FILE` 是观测/测试用常量；真正写盘时 `record_turn` 仍用 `target.with_suffix(".lock")`，两者必须保持同一目录、同一文件名。
- 记录 schema 不变：`ts / backend / model / turn_id / input_other / input_cache_read / input_cache_creation / output`。
- 采集侧不改：`kimi_acp.py`、`dsh_acp.py`、`base.py`、`panel.py`、`token_usage_dialog.py` 均无改动。
- 旧 `config/token_usage.jsonl` 不再被新代码读取；它是迁移来源，不是运行路径。

## 6. 历史数据迁移

### 6.1 前置条件

- 先关闭两个 IDE，避免迁移期间还有进程追加写。
- 先备份各副本的 `config/token_usage.jsonl`；不要直接删除旧文件。
- 若目标路径此前已被软链到别处，先移除软链再迁移；迁移脚本会用普通文件替换目标路径，不会保留软链。
- 迁移脚本对目标文件做“全量读取 → 按 `turn_id` 去重 → 原子替换”，因此目标文件里已有的重复行也会被清掉。
- 同一 `turn_id` 视为同一笔消费；若不同来源的数值字段冲突，保留首条并打印 warning，人工核查，不做相加。

### 6.2 一次性脚本

建议入库为 `scripts/merge_token_usage.py`，两个项目共用同一份逻辑；若不想增加维护面，也可按此代码一次性执行后删除。

```python
# scripts/merge_token_usage.py
"""按 turn_id 合并多份 token_usage.jsonl；先关闭所有 IDE 再执行。"""
import argparse
import json
import os
import shutil
from datetime import datetime
from pathlib import Path

_FIELDS = ("input_other", "input_cache_read", "input_cache_creation", "output")


def _records(path: Path):
    if not path.exists():
        return
    for line in path.read_text(encoding="utf-8").splitlines():
        try:
            record = json.loads(line)
            turn_id = record["turn_id"]
        except (ValueError, KeyError, TypeError):
            continue
        if isinstance(turn_id, str) and turn_id:
            yield turn_id, record


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("--dest", required=True, type=Path)
    parser.add_argument("sources", nargs="+", type=Path)
    args = parser.parse_args()

    dest = args.dest.expanduser()
    dest.parent.mkdir(parents=True, exist_ok=True)
    merged: dict[str, dict] = {}
    conflicts = 0
    paths = [dest, *(p.expanduser() for p in args.sources)]
    for path in paths:
        for turn_id, record in _records(path):
            if turn_id not in merged:
                merged[turn_id] = record
                continue
            if any(merged[turn_id].get(k) != record.get(k) for k in _FIELDS):
                conflicts += 1
                print(f"conflict: {turn_id} (keep first)")

    if dest.exists():
        backup = dest.with_name(
            f"{dest.name}.bak-{datetime.now():%Y%m%d-%H%M%S}")
        shutil.copy2(dest, backup)
        print(f"backup: {backup}")

    tmp = dest.with_name(dest.name + ".tmp")
    with tmp.open("w", encoding="utf-8") as out:
        for record in merged.values():
            out.write(json.dumps(record, ensure_ascii=False) + "\n")
    os.replace(tmp, dest)
    print(f"records={len(merged)} conflicts={conflicts} dest={dest}")


if __name__ == "__main__":
    main()
```

### 6.3 执行命令

```bash

.venv/bin/python scripts/merge_token_usage.py \

  /path/to/copyB/config/token_usage.jsonl
```

注意：如果 `XDG_CONFIG_HOME` 不是绝对路径，上面的 shell 展开会与程序逻辑不一致；此时把 `--dest` 直接写成 `$HOME/.config/zen-studio/token_usage.jsonl`。


### 6.5 旧文件处理

迁移并验证后，旧副本的 `config/token_usage.jsonl` 可以：

- 保留为冷备（推荐，至少保留到热力图数值核对完成）；
- 或改名为 `config/token_usage.legacy.jsonl`；
- 确认共享账本无误后再删除。

不要在新代码运行期间继续往旧文件写；旧代码副本必须先升级，否则会继续分账。

## 7. 测试计划

### 7.1 路径解析单元测试

写入 `tests/test_token_stats.py`，直接测 `token_stats._usage_file()`，不要依赖模块导入时的 `USAGE_FILE` 常量，避免测试顺序污染：

- 默认：`monkeypatch.delenv("ZEN_TOKEN_USAGE_FILE")` 后，返回 `USER_GLOBAL_CONFIG_DIR / "token_usage.jsonl"`。
- 覆盖：`monkeypatch.setenv("ZEN_TOKEN_USAGE_FILE", str(tmp_path / "shared.jsonl"))` 后返回该绝对路径。
- 相对路径：设置 `"relative.jsonl"` 时回退默认路径，并产生一条 warning（可用 `caplog` 断言）。
- 用户级根：在开发态断言 `USER_GLOBAL_CONFIG_DIR != USER_CONFIG_DIR`，且 `USER_GLOBAL_CONFIG_DIR` 不在 `PROJECT_ROOT/config` 下。
- XDG：`XDG_CONFIG_HOME` 为绝对路径时生效；为相对路径时回退 `Path.home() / ".config"`。若测试需要重算模块常量，必须用 `importlib.reload` 并在用例结束后恢复，不要让其他用例继承被改写的模块状态。

### 7.2 落盘与锁

- 同一个 `tmp_path / "usage.jsonl"` 连续写入两个不同 `turn_id`，断言两行都在；这是“共享账本”的最小回归。
- 同一 `turn_id` 第二次写入返回 `False` 且不新增行（现有用例保持）。
- `record_turn(path=...)` 后断言 `tmp_path / "usage.lock"` 存在，防止锁路径被改到别处。
- 坏行、缺字段、全零消耗的既有容错用例保持通过。

### 7.3 迁移脚本

若 `scripts/merge_token_usage.py` 入库，增加 `tests/test_merge_token_usage.py`：

- 两个来源各含一条相同 `turn_id` + 各自一条不同 `turn_id`，合并后目标恰好 3 条（1 条共享 + 2 条各自独有）。
- 来源含坏行、缺 `turn_id` 行，迁移不中断。
- 同 `turn_id` 但 token 字段不同，保留首条并报告 conflict。
- 重复执行迁移，目标行数不再增加（幂等）。

### 7.4 并发验收

至少做一次手工双进程验收（也可写成 Linux 下的 `multiprocessing` 用例）：

1. 两个进程同时向同一个共享账本各写 20 条不同 `turn_id`；
2. 全部结束后断言 40 行、`turn_id` 无重复；
3. 不应出现 `token 用量落盘失败`。

若 CI 环境不稳定，可保留为手工验收项，并在实施回写中注明。

### 7.5 回归与门禁

- `tests/test_token_stats.py`、`tests/test_token_usage_dialog.py`、`tests/test_kimi_usage.py`、`tests/test_dsh_usage.py` 全过。
- `bash scripts/check.sh` 全绿（隐私扫描 + lint + 测试）。
- 热力图弹窗仍能打开；底部今日/最近七天/最近三十天数值与共享账本一致。

## 9. 实施顺序

1. 关闭两个 IDE，确认没有进程还在写旧账本。
2. 在项目 A、项目 B 同步修改 `src/ide/core/paths.py`，导出同一个 `USER_GLOBAL_CONFIG_DIR`。
3. 在两边同步修改 `src/ide/core/token_stats.py`，接入 `_usage_file()` 与环境变量覆盖。
4. 在两边补 `tests/test_token_stats.py` 用例；若入库迁移脚本，补对应测试。
5. 两边分别跑聚焦测试，再跑 `bash scripts/check.sh`。
6. 关闭 IDE 状态下执行第 6 节迁移脚本，合并所有旧账本到共享路径。
7. 启动两个 IDE，各跑一轮 kimi / DSH 对话，核对共享账本行数与热力图数值。

## 11. 风险与边界

- 🔴 **`fcntl` 仅 Unix**：`token_stats.py` 顶部 `import fcntl` 在 Windows 会直接失败。若项目 B 要支持 Windows，必须先把锁换成 `msvcrt` / `portalocker` 等跨平台实现；本文不展开。
- 🔴 **应用目录名不一致**：项目 B 若使用别的应用名，默认路径不同，仍然分账。必须统一 `zen-studio`，或显式设置 `ZEN_TOKEN_USAGE_FILE`。
- 🟡 **旧代码仍在跑**：只升级一个副本，另一个副本继续写旧 `config/`；共享账本不会自动收到旧副本的新记录。
- 🟡 **相对路径覆盖**：`ZEN_TOKEN_USAGE_FILE` 配成相对路径会回退默认并告警；不要用相对路径做共享。
- 🟡 **跨机器/跨时区**：账本是本地文件。跨机器需要额外同步，且 `flock` 在 NFS 上不可靠；`load_daily()` 按读取方本地时区归日，不同时区的机器可能把同一条记录归到不同日期。跨机器共享不在本计划范围。
- 🟡 **无来源字段**：记录只有 `backend` / `model`，合并后无法拆分“这是 A 还是 B 用的”。若需要来源维度，另立计划加 `source`，两个项目同步改 schema；不要在一边单独加。
- 🟡 **读取不加锁**：`load_daily()` 是 lock-free 全量读，极端情况下可能读到另一进程正在写的半行并跳过该行；本次少显示一条，重新打开弹窗即可恢复，不会写坏数据。
- 🟡 **写盘失败静默**：`record_turn()` 捕获 `OSError` 只记日志并返回 `False`，不会打断对话。共享后若权限/锁异常，表现是“不记”，需查各副本的日志（开发态 `config/logs/zen-studio.log`，打包态 `~/.config/zen-studio/logs/zen-studio.log`）中的 `token 用量落盘失败`。
- 🟢 **数据量**：一轮一行，个人使用量级下全量读/全量去重可接受。若未来达到数十万行、热力图打开明显变慢，再评估 SQLite 或索引；本期不引入。
- 🟡 **隐私**：账本只含时间、后端、模型与 token 数，不含对话正文；仍属用户数据，建议文件权限 `0600`，不要提交到仓库或外发。

## 13. 项目 B 落地注意事项

1. **按符号定位，不按行号**：两个项目代码相近但不保证完全一致；以 `USAGE_FILE`、`USER_CONFIG_DIR`、`USER_GLOBAL_CONFIG_DIR`、`record_turn`、`load_daily` 这些符号为准。
2. **不要跨项目 import**：项目 B 复制本文的路径解析逻辑，不要从项目 A 的源码路径 import；两边各自维护，但常量值必须一致。
3. **先改代码再迁移**：先把两个项目都升级到共享路径，再合并旧账本；否则迁移期间旧进程还会往旧文件写。
4. **schema 与 `turn_id` 不得分叉**：字段名、字段含义、`turn_id` 的“会话 UUID + 轮次计数”规则必须一致；任一边改了字段名或含义，合并后可能读不出或算错，新增可选字段必须两边同时兼容。
5. **各自跑门禁**：项目 B 用自己的 `.venv` 与 `scripts/check.sh` 验证；不要把项目 A 的测试结果当作项目 B 的结果。
6. **计划文档复制**：项目 B 若需要独立计划，复制本文并改头部时间/状态；第 4~6 节保持原文，作为两项目的共同契约。

**经验沉淀**：

1. **测函数不测常量**：`USAGE_FILE` 是模块导入时定型的常量，路径解析测试直接调 `_usage_file()` 并用 `monkeypatch` 控环境变量，避免了计划 §7.1 预警的“测试顺序污染”，全程不需要 `importlib.reload`。
2. **锁与账本同源只需一个常量**：`USAGE_LOCK_FILE = USAGE_FILE.with_suffix(".lock")` 让锁自动跟随账本（含环境变量覆盖），无需第二处路径推导；测试里断言锁出现在 `tmp_path` 根下即守住“锁不被改到别处”。
3. **`USER_GLOBAL_CONFIG_DIR` 与 `USER_CONFIG_DIR` 分离是关键设计**：共享数据（账本）与副本私有数据（settings/window_state/sessions）分两个根，既达共享又避免整目录共用的污染（方案 C 的坑）；后续若有新的跨副本共享数据，一律落 `USER_GLOBAL_CONFIG_DIR`。
4. **迁移脚本幂等靠“目标也作为来源参与合并”**：把 `--dest` 自身放进合并序列首位的写法，使重复执行行数不再增长，天然幂等，比“先清后写”更不容易出事故。
