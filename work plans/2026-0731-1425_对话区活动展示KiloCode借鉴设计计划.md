## 2. 关键协议事实（对 1405 初步计划的修正）

### F1 🔴 kilocode 的 ACP **不发送 `plan` sessionUpdate**

全仓无 `sessionUpdate: "plan"`。todo list 走 **todowrite 普通工具调用**
（kind=`other`），载荷路径为 `tool_call.rawInput.todos`，schema 经
`packages/opencode/src/tool/todo.ts` 实证：

```jsonc
// tool_call.rawInput（todowrite）
{ "todos": [
  { "content": "任务描述",
    "status": "pending | in_progress | completed | cancelled",
    "priority": "high | medium | low" } ] }
```

附加事实：title 为 `"N todos"`（未完成计数）；`rawOutput.metadata.view`
带 compact 变化窗口（前后各有 `N earlier/later to-dos hidden`，供
长清单截断展示——kilocode_change 私有增强，映射层可选消费）。

**对 1405 计划的影响**：todo 上屏必须**双通道**——①标准 ACP `plan`
更新（kimi 等后端可能发送，保留映射）；②解析 todowrite tool_call 的
rawInput（kilocode/opencode 系后端的唯一通道）。kilo-ui 自身的
`HIDDEN_TOOLS` 机制（把 todowrite 从通用工具渲染摘除、单独渲染
TodoToolCard）正是同一设计——印证「todo 块与工具块分流」是合理范式。

### F2 🔴 子代理内部活动**协议层不可得**

task 工具 = 普通 tool_call，`kind="think"`；子代理使用独立子 sessionID，
其事件在 `event.ts` 被静默丢弃，**任何 ACP client 都拿不到子代理内部
步骤**（要拿需另接 `kilo serve` SSE，非 ACP 通道）。1405 计划的 D5
（子代理展示粒度）被协议事实强制为「仅开始/完成 + 最终输出」，不再是
开放选项。最终成果从 `tool_call_update(completed)` 的
`rawOutput.output`（kilocode 为 `<task_result>` 包裹文本）提取。

### F3 tool_call / tool_call_update 载荷全字段（实证）

| 字段 | 内容 |
|---|---|
| `toolCallId` | 工具实例唯一键（**状态更新的锚点键**） |
| `kind` | `execute`(bash/shell) / `edit`(edit/write/apply_patch) / `read` / `search`(grep/glob) / `fetch`(webfetch) / `think`(task 子代理) / `other`(todowrite/MCP 等) |
| `status` | 状态机：`tool_call(pending)` → `tool_call_update(in_progress)`（可多次，bash 输出快照流式刷新）→ `(completed|failed)`（终态一次） |
| `title` | **shell 工具 title 即命令本身**；其余为模型给的标题 |
| `locations` | `[{path}]`：bash 给工作目录、read/edit/write 给文件路径 |
| `rawInput` / `rawOutput` | 原始入参 / 完成时输出（failed 时含 error） |
| `content` | `text` / `image` / **`diff`（{path, oldText, newText}，kind=edit 时携带）** |

字段容错：tool_call_update 除 toolCallId 外均可能缺省，须按部分更新
合并，不得假设全量。

### F4 usage_update 载荷

`{used, size, cost:{amount, currency}}`。⚠️ 与本仓
`2026-0731-1412_上下文Token用量百分比显示移植计划.md` 主题重叠，
**本文档不覆盖**，仅在映射层预留不过滤（两计划落地时注意同改
`_map_update` 的合并冲突）。

### F5 kilocode ACP 无私有 sessionUpdate 扩展

仅 7 种标准更新（agent_message_chunk / agent_thought_chunk /
user_message_chunk(仅回放) / tool_call / tool_call_update /
usage_update / available_commands_update），无 `_meta` 私有通道。
映射层「未知类型返回 None」的既有纪律完全适用。

## 3. kilo-ui 渲染设计模式（借鉴摘要）

1. **标题行骨架**（BasicTool）：`[语义图标][动词标题 加粗][参数摘要 灰，省略号截断]`；
   pending 时标题 shimmer 动画 + 隐藏参数，完成后参数淡入。
2. **状态三态**：进行中（动画/参数隐藏）→ 完成（参数显现，edit 附
   `+N -M` DiffChanges，绿 `#3a8437` / 红 `#ed4831`）→ 失败（整块
   红色错误卡）。
3. **todo 双轨**：流内 TodoToolCard（完成项**灰色删除线**、副标题
   `已完成/总数`、compact 窗口截断）+ 顶部 TaskHeader 进度摘要。
4. **bash 三态**：运行中尾部 5 行滚动窗 → 完成折叠 → 展开限高 10 行
   内滚；预处理 `stripAnsi` + `\r` 进度条帧折叠；超 2000 行/50KB
   **后端落盘整档**（`truncate.ts`）前端给「打开全文」。
5. **reasoning 一句话标题**：`reasoning-heading.ts` 按优先级正则提取
   （md 标题 → setext → 粗体首行），正则规则可直接移植 Python re。
6. **排序保证**：流式中 reasoning 强制排在 text 之前。
7. **配色语义**：四档灰（`#171717/#6f6f6f/#8f8f8f/#c7c7c7`）+ 功能色
   （成功绿/错误红/链接蓝），亮暗双主题各一套（`packages/ui/src/styles/theme.css`）。
8. **工程机制**（与渲染技术无关，可完整移植）：callID 块级锚点、
   开合状态 LRU 记忆、流式节流、ANSI/`\r` 预处理、超限落盘。

## 5. 降级规格（QTextBrowser 落地格式）

### 5.1 工具行文本规格

```
进行中：◐ ▸ Edit — gui/panels/chat/panel.py
完成：  ✔ ▸ Edit — gui/panels/chat/panel.py  (+12 -3)
失败：  ✖ ▸ Bash — pytest tests/  （错误首行，灰）
todo：  ☑ ▸ 更新任务清单 — 3/5 项完成
子代理：⧉ ▸ 子代理 Explore — 搜索代码库（完成后追加成果摘要块）
```

图标字符映射（kind → 字符）：execute=`❯`、edit=`✎`、read=`📄`、
search=`🔍`、fetch=`🌐`、think/task=`⧉`、other=`▸`；状态字符：
pending/in_progress=`◐`（可轮转）、completed=`✔`、failed=`✖`。

### 5.2 锚点机制（新增基础设施，1405 计划无此项）

`ChatOutput` 维护 `{toolCallId: (起始 block number, 结束 block number)}`
簿记；状态更新 = QTextCursor 选中旧行范围替换；todo 块同理单锚点。
轮次收尾全部作废。此机制是 K3/K5/K6 共同依赖，独立成任务先行。
（降级预案：锚点替换失稳则退回「状态变化追加新行」，与 1405 之
T5 降级预案一致。）

### 5.3 预处理与截断（协议层单点）

- ANSI 转义正则剥离；`\r` 帧折叠（按行 split 取最后非空帧）——
  移植 `shell-rolling-results.tsx` 思路，Python 实现约 20 行。
- bash 输出截断：头部保留命令行 + 尾部 15 行；超限全文写
  `.temp/tool_output_<toolCallId>.log`，上屏给相对路径提示。
- diff 只渲 hunk：`@@` 头灰字、`+` 绿字、`-` 红字、上下文行默认色；
  单 diff 超 200 行截断。
