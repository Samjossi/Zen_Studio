# Git 提交历史图弹窗显示计划

> 在「视图」菜单新增一个动作，点击弹出非模态对话框，以只读文本图（`git log --graph` 的 ASCII 拓扑）展示当前仓库的提交历史（分支/合并/标签装饰）。不占用主布局，不提供图内交互，第一版只做纯展示。

## 1. 目标行为

| 场景 | 现状 | 目标 |
|:---|:---|:---|
| 查看提交历史拓扑 | ❌ 无入口，须切外部终端敲 `git log --graph` | 视图菜单 ▸ 「提交历史图(&L)」弹窗展示 |
| 分支/合并/HEAD/标签装饰 | — | 随 `--graph --decorate --all` 原样呈现 |
| 仓库有新提交后查看 | — | 弹窗内「刷新」按钮手动重拉；弹窗每次打开亦自动重拉 |
| 无 git / 非仓库工作区 | — | 弹窗显示降级占位文本（不报错、不弹错误框），对齐全局静默降级语义 |
| 主窗口布局 | 三栏 splitter 定式 | 零改动（对话框为独立顶级窗口） |

## 3. 设计要点

### 3.1 数据源：一行命令，原样透传

```python
# core/git/log.py
run_git(repo_root, "log", "--graph", "--oneline", "--decorate", "--all",
        "--color=never", "-n", str(MAX_COUNT))
```

- **原样透传 stdout，不做结构化解析**：`--graph` 的 ASCII 线条（`*` `|` `\` `/`）在等宽字体下自对齐，解析反而引入错排风险。本项目第一期为纯展示，无交互需求，无解析必要。
- **`--all` 覆盖全部分支/标签/stash 引用**，对齐 Git Graph 类工具的默认视野。
- **`-n MAX_COUNT`（取 500）条数上限**：大仓库一次拉全量可能撞 runner 的 2s 超时上限并返回大文本；500 条对纯浏览足够。命中上限时在文本尾部追加一行提示（如 `……仅显示最近 500 条`），让用户知晓截断而非误以为仓库只有这些提交。
- **`--color=never` 显式去色**：防御用户全局 gitconfig 设了 `color.ui=always` 导致 ANSI 转义序列混入文本（runner 管道捕获时 git 默认已去色，此行是显式保险）。
- **失败返回 None**：沿用 runner 静默降级语义，由 UI 层决定占位呈现。

### 3.2 对话框：非模态单例 + 等宽只读文本

- **载体**：`QDialog` + 只读 `QPlainTextEdit`（等宽字体）。`QPlainTextEdit` 对大块纯文本的渲染开销低于 `QTextBrowser` 富文本路径，且天然无链接/选中富格式干扰；等宽字体是 `--graph` 线条对齐的前提。
- **非模态（`show()`）+ 单例惰性创建**：照搬 `_settings_dialog` 模式——MainWindow 持 `self._git_graph_dialog: GitGraphDialog | None = None`，菜单触发时惰性创建并 `show()`/`raise_()`/`activateWindow()`。用户可一边看图一边回主窗口操作。
- **对话框结构**：顶部信息行（仓库根 + 当前分支名）+ 中部文本区 + 底部「刷新」按钮。当前分支名用 `run_git(repo_root, "branch", "--show-current")` 获取（detached HEAD 时为空串，显示 `(detached)`）。
- **刷新时机两处**：每次 `show()` 时自动重拉一次；对话框内「刷新」按钮手动重拉。**不做事件驱动常驻刷新**（提交图是低频查看，不值得挂进 GitStatusController 的去抖汇流）。
- **降级占位**：`is_enabled` 为 False 或 `fetch` 返回 None 时，文本区置占位文案（「当前工作区不在 git 仓库内」/「提交历史获取失败」），信息行与刷新按钮照常可用（重试语义），不弹任何错误框。

### 3.3 菜单入口

- 视图菜单在「刷新 Git 状态(&G)」之后插入「提交历史图(&L)」非勾选动作，`triggered` 直连 MainWindow 的 `show_git_graph()`，`actions.register("view.git_graph", action)`。
- **菜单项不做 enable 联动**：非仓库时点击照样弹窗（窗内降级占位），避免给 GitStatusController.refresh 扇出链再加一个菜单状态同步点。低频次动作，窗内占位已足够告知。

### 3.4 字体与主题

- 等宽字体取自应用统一字体设置（沿用终端面板/查看器的等宽字体来源，实施时确认单一来源键，不新造字体配置）。
- 文本区颜色走主题 qss 全局规则（`QPlainTextEdit` 已被四主题覆盖），不新增主题键。

## 4. 决策表

| 编号 | 决策点 | 初步倾向 | 依据 |
|:---|:---|:---|:---|
| D1 | 渲染方式 | 文本图原样透传（非 QGraphicsView 泳道绘制） | 纯展示需求；矢量泳道绘制工作量与解析风险不在本期 |
| D2 | 模态性 | 非模态单例（照搬设置中心模式） | 看图时可回主窗口对照代码；项目已有同款先例 |
| D3 | 数据拉取时机 | 打开时 + 手动刷新，两处；不挂事件驱动 | 低频查看；避免污染 GitStatusController 去抖汇流 |
| D4 | 条数上限 | `-n 500` + 截断提示行 | runner 2s 超时是兜底不是体验保障；大仓库防护 |
| D5 | 菜单项 enable 联动 | 不做；窗内降级占位 | 避免 refresh 扇出链新增同步点；低频动作占位即可 |
| D6 | 非仓库/失败呈现 | 文本区占位文案，不弹错误框 | 对齐 runner「无 git 属正常场景而非故障」语义 |
| D7 | 控件选型 | `QPlainTextEdit`（非 QTextBrowser） | 大文本渲染开销低；无富文本干扰；等宽对齐 |

## 6. 验证方案

1. **数据层单测**（`.temp/` 下脚本，项目 `.venv` 运行）：
   - 在 `.temp/` 内构造 fixture 仓库：主分支 3 提交 + 特性分支 2 提交 + 一次合并 + 一个标签，断言 `fetch_commit_graph` 输出含 `*`/`\` 图线、分支名装饰、标签装饰。
   - 空仓库（无提交）、非仓库目录、不存在路径三例，断言返回 None 不抛异常。
   - `-n` 截断：造 600 条提交的仓库（脚本批量空提交），断言输出尾部含截断提示行。
2. **offscreen GUI 冒烟 + 截图对照**（依 `视觉验证闭环开发指南.md`）：
   - `QT_QPA_PLATFORM=offscreen` 起对话框指向 fixture 仓库，grab 截图，断言图线字符渲染、等宽对齐无错排。
   - 降级分支截图：非仓库工作区下弹窗显示占位文案。
   - 四主题逐一截图目验文本区配色可读性。
3. **真机回归**：
   - 视图菜单点击 → 弹窗 → 主窗口照常可操作（非模态验证）。
   - 终端 `git commit` 后点弹窗「刷新」→ 新提交出现。
   - 再次点击菜单项 → 已有窗口置顶而非新开（单例验证）。

## 7. 不做的事

- ❌ 图内任何交互：点击提交看 diff、右键 cherry-pick/revert、双击切换分支（后续如需另行立项）。
- ❌ QGraphicsView 矢量泳道绘制（D1）。
- ❌ 结构化提交数据解析（无消费方；为解析而解析）。
- ❌ 事件驱动常驻刷新 / 纳入 GitStatusController 去抖汇流（D3）。
- ❌ 菜单项 enable 状态随仓库可用性联动（D5）。
- ❌ 分页/虚拟滚动加载更多（500 条上限内一次性呈现）。
- ❌ 提交搜索/过滤框（第一版纯浏览）。
