## 1. 背景与目标

本项对已经完成的厂商隔离做集中自动化、视觉和冻结态验证。重点不是新增功能，而是证明源码测试通过之外，独立卡片实现没有改变既有观感，目录迁移后打包入口也没有漏模块。

真实 Kimi/DSH 端到端验收属于 T7，本项不得用 offscreen、内存假 agent 或冻结态冒烟冒充真实后台结果。

## 2. 启动条件与边界

- 自动化测试继续遵守「不起真实 CLI」纪律，不读取或改写 CLI 凭据。

## 3. 实施步骤

### T6.1 自动化与生命周期回归

1. 定向运行 Kimi、DSH、Local、权限、卡片、中断、恢复、用量和架构守卫测试。
2. 运行标准门禁 `bash scripts/check.sh`，确认隐私扫描、ruff、pytest 全绿。
3. 使用现有内存假 agent 分别跑三家「建立会话 → 正文/工具帧 → 停止 → 关闭」。
4. 确认无孤儿进程、无跨实例账本，同 provider/session 所需的连续状态仍正常。

### T6.2 分厂商视觉回归

1. 将 `scripts/shot_tool_cards.py` 等视觉脚本改为显式选择对应厂商工厂，不恢复公共卡片工厂。
2. 分别重出 Kimi、DSH 代表卡片，至少覆盖 Agent/AskUserQuestion/ReadMediaFile/TodoList 与 read_image/todo_write/subagent 的现行可用路径。
3. 按项目视觉验证流程逐张读回，对照 T0 基线确认内容、入参/出参、折叠复制和观感未变。
4. Local 使用可控假数据验证独立工厂和卡片，不借用 Kimi 截图代替。

### T6.3 冻结态构建与启动冒烟

1. 通过项目现有 PyInstaller/AppImage 构建入口验证目录迁移后的冻结态 import。
2. 对构建产物执行启动冒烟，确认三家后台注册、卡片组合根和关键模块可加载。
3. 不替换用户当前应用，不手工修补旧构建目录；记录实际命令、产物位置与结果。
4. 将自动化、视觉和冻结态结果回写本文档，未执行项明确标注，不以推断代替执行。
