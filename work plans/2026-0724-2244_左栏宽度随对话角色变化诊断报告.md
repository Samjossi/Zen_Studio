# 左栏宽度随对话角色变化诊断报告

## 1. 现象（用户报告）

主窗口左栏（AI 聊天区）的宽度会随对话发生变化：**用户发言时左栏变得更宽，AI 对话时相对正常**。本报告仅依据当前代码与运行时取证诊断，未翻查历史修改记录。

## 2. 诊断方法

1. 走查当前布局与聊天面板代码（`gui/main_window.py`、`gui/panels/chat/tabs.py`、`gui/panels/chat/model_bar.py`、`gui/panels/chat/panel.py`、`gui/panels/chat/output.py`）；
2. 编写运行时探针 `.tmp/probe_left_pane.py`（offscreen 平台），完整模拟「用户发言 → busy 置位 → AI 流式上屏 → 回合结束」链路，逐阶段记录 `_splitter_main.sizes()` 与相关控件的 `minimumSizeHint()`；
3. 探针每阶段抓取主窗口截图（`.tmp/probe_01_基线.png` ～ `.tmp/probe_06_仅busy复位.png`），多模态读图核实。

## 3. 结论：根因链路

**直接根因：busy 期间 ModelBar 弹出的「■ 停止」按钮抬高了整个左栏的最小宽度，QSplitter 为满足子控件最小宽度约束，自动把左栏撑宽。**

完整链路：

1. 用户按 Enter 发送 → `ChatPanel._on_send` → `ChatPanel._set_busy(True)` → `ChatTabs._recompute_busy` → `ModelBar.set_busy(True)` → `stop_button.setVisible(True)`（`gui/panels/chat/model_bar.py`）。
2. ModelBar 是单行 `QHBoxLayout`：`模型` 标签 + 后端下拉 + `版本` 标签 + 版本下拉（stretch=1）+ 停止按钮。**QComboBox 的 `minimumSizeHint()` 按「最长条目文本宽度」计算**（Qt 内建行为），两个下拉框使 ModelBar 空闲时最小宽度已达 **528px**；停止按钮显示后再增约 **85px → 613px**。
3. ModelBar 最小宽度经 `ChatTabs`（左右各 6px 外边距）上传：左栏整体最小宽度 **540px → 625px**。
4. `ChatTabs` 是外层水平分隔栏 `_splitter_main` 的直接子控件（`gui/main_window.py` 的 `_build_layout`）。**QSplitter 布局时强制执行子控件的 minimumSizeHint**：当前左栏宽 540px < 新下限 625px，于是自动将左栏撑宽至 625px，差额 **85px 从中栏（查看器/终端）抢夺**，右栏不变。
5. AI 回合结束 → busy 复位 → 停止按钮隐藏 → 最小宽度回落 540px，**但 QSplitter 不会自动缩回**（棘轮效应：只撑不缩），加宽后的宽度粘滞保持；窗口关闭时 `closeEvent` 把加宽后的分隔栏状态持久化（`gui/window_state.py`），下次启动原样恢复。

## 4. 取证数据（探针实测）

```text
# .tmp/probe_left_pane.py 运行输出（QT_QPA_PLATFORM=offscreen）
[基线]       sizes = [540, 388, 240]  ModelBar最小宽=528  ChatTabs最小宽=540  停止按钮=隐藏
[用户发言后] sizes = [625, 321, 240]  ModelBar最小宽=613  ChatTabs最小宽=625  停止按钮=可见
[AI流式中]   sizes = [625, 321, 240]  （不变）
[回合结束后] sizes = [625, 321, 240]  ModelBar最小宽=528（回落） 但左栏宽度保持625不缩回
[仅busy置位] sizes = [625, 321, 240]  ModelBar最小宽=613（复现：与消息文本无关）
[仅busy复位] sizes = [625, 321, 240]
```

要点：

- 「仅 busy 置位」对照组证明：**宽度变化与消息文本内容完全无关**，唯一变量是停止按钮的显隐；
- 「AI流式中」阶段宽度不变证明：AI 回复的文字上屏本身不影响左栏宽度；
- 截图 `.tmp/probe_02_用户发言后.png` 可见「■ 停止」按钮出现在模型行，左栏明显宽于基线（`.tmp/probe_01_基线.png`）；`.tmp/probe_04_回合结束后.png` 可见按钮已消失但左栏仍保持加宽。

## 5. 为什么观感是「我说话时变宽、AI 对话时正常」

这是**时机巧合 + 棘轮效应**叠加出的错觉：

- busy 恰在用户按 Enter 发送的同一帧置位（用户消息上屏与「■ 停止」按钮出现同时发生），AI 回复结束的瞬间才复位——于是「变宽」总是与「我说话」同框出现；
- 由于只撑不缩，用户（或「恢复默认布局」）把左栏拖回静态下限约 540px 后，静止与 AI 输出期间宽度稳定不变（观感「正常」）；下一次用户发送又瞬间弹宽——形成「我一说话它就变宽」的循环。

## 6. 附带发现

- ⚠️ 默认布局 `DEFAULT_SIZES_MAIN = [320, 630, 250]`（`gui/main_window.py`）中左栏 320px **永远不可达**：ModelBar 静态最小宽度 528px（两个 QComboBox 按最长条目撑出）已将左栏下限锁死在约 540px，且模型别名越长地板越高（如版本别名变化会改变该下限）。
- ⚠️ 棘轮不缩回 + 关闭持久化意味着：一旦加宽，重启后依旧宽，宽度只增不减，直到用户手动拖回或恢复默认布局。

## 7. 修复方向（建议，本报告不实施）

| 方案 | 说明 |
|:---|:---|
| A. 压缩下拉框最小宽度 | 对两个 QComboBox 调 `setMinimumContentsLength` + `setSizeAdjustPolicy(AdjustToMinimumContentsLengthWithIcon)`（或设最大宽度/省略号截断），消除「最长条目决定左栏下限」 |
| B. 停止按钮退出布局流 | 停止按钮改为覆盖式浮动（或移入标签栏角落「+」旁），不参与 ModelBar 水平布局的最小宽度计算；显隐不再改变任何 sizeHint |
| C. 左栏最小宽度封顶 | `ChatTabs.setMinimumWidth(...)` 显式给定合理下限，屏蔽内部控件 sizeHint 波动 |

A+B 组合最彻底：A 解决静态下限过高（顺带修复 320px 默认不可达），B 解决 busy 显隐引起的动态撑宽。
