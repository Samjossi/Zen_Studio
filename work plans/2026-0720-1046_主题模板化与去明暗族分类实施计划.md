# 主题模板化（C2）与去明暗族分类实施计划

## 1. 目标

1. **C2 全量模板化**：五套 qss 副本合并为唯一模板 `config/themes/base.qss`，每主题一包色值令牌集中在 `gui/theme.py`，耦合色（如菜单/下拉同底色）物理同源、不可能漂移；新增主题 = 加一行字典。
2. **去明暗族分类（资源包下沉，用户选定）**：彻底废除 family 概念——不做亮度推导、不留分类接口。语法高亮/终端 ANSI/查看器行号/Git 状态色四套明暗资源包**下沉进 `THEME_PALETTES`**，每主题字典自带全套（亮色四主题共享资源用模块级常量引用，不复制）；`get_family()` 接口删除，架构中不再存在任何明暗判断代码。介于明暗之间的主题天然支持：逐值手写或基于共享包覆盖单项。

## 2. 现状分析（五副本全量 diff 实测）

- 规则键总数 116，五主题结构基本同构；**唯一结构差异**：dark 多一条 `QComboBox:hover { background-color: #454548 }`（亮色四主题无此行）。
- **差异点 46 处**，去重收敛后约 25 个令牌——高频复用者：主题色 accent（选中背景/菜单选中/焦点描边/tab 选中下划线共 6 处）、正文色（窗口/菜单/下拉/tab 共 5 处）、描边色（卡片/输入/按钮/列表/下拉共 5 处）、浮层底色（菜单/下拉 2 处，即本次色差事故的耦合点）。

## 3. 目标架构设计

### 3.1 模板与调色板

```
config/themes/base.qss     ← 唯一模板，差异点写 $token 占位符（string.Template）
gui/theme.py
  THEME_PALETTES = {
      "cloud": {"label": "云白", "window_bg": "#ffffff", "accent": "#0765d4", ...},
      "wheat": {...}, "sky": {...}, "mint": {...}, "dark": {...},
  }
```

- `render_theme(name) -> str`：`string.Template(base_qss).substitute(THEME_PALETTES[name])`——**缺键即抛 KeyError**（fail-fast，不静默产出残缺样式）。
- `apply_theme()` 改走渲染路径；`is_valid()`/`available_themes()` 改查 `THEME_PALETTES` 键（替代文件存在性检查）；`THEMES_DIR` 仅指向模板。
- 令牌命名按语义分组：`window_*`（窗口/正文）、`side_*`（侧栏/卡片）、`input_*`/`btn_*`（输入与按钮）、`popup_*`（浮层）、`list_*`（树/列表）、`scrollbar_*`、`tooltip_*`、`accent`（主题色）、`muted_text`（弱化文字）。

### 3.2 dark 特有行的模板化处理

模板统一包含 `QComboBox:hover { background-color: $combo_hover_bg; border-color: $combo_hover_border; }`：dark 令牌 `#454548`，亮色四主题令牌 `transparent`（1259 计划 §3.5 已验证 `:hover` 伪态背景不触发选中背景接管，透明等价于未设置；实施时以 hover 态截图回归终验）。

### 3.3 去明暗族分类：资源包下沉调色板

**设计动机**：`get_family()` 消费的不是字体颜色，而是四套手工调色的资源包（语法高亮 16 值 / 终端 ANSI 18 值 / 查看器行号 5 值 / Git 状态色 5 值）——这些值是设计决策，无法从背景色公式推导，亮度推导方案（已否决）本质仍是明暗二分。彻底方案：**每主题自带全套资源，代码零明暗判断**。

```python
# gui/theme.py：全部主题数据的唯一汇聚点（THEME_META 废除）
SYNTAX_PACK_A = {Token.Keyword: {"color": "#0000AF", "bold": True}, ...}   # 原 highlighter "light" 包
SYNTAX_PACK_B = {...}                                                       # 原 "dark" 包
TERMINAL_PACK_A / TERMINAL_PACK_B   # 原 terminal/palette.py 双包
CHROME_A / CHROME_B                 # 原 code_viewer.CHROME 双套
GIT_STATUS_A / GIT_STATUS_B         # 原 GIT_STATUS_COLORS 双族

THEME_PALETTES = {
    "cloud": {"label": "云白", "window_bg": "#ffffff", ..., 
              "syntax": SYNTAX_PACK_A, "terminal": TERMINAL_PACK_A,
              "chrome": CHROME_A, "git_status": GIT_STATUS_A},
    "dark":  {..., "syntax": SYNTAX_PACK_B, ...},
}
```

- **共享即引用**：亮色四主题引用同一常量（一行，不复制）——是"直接选用这包资源"而非"被分类"；中间态主题可 `{**CHROME_A, "find_bg": "#xxx"}` 单项覆盖或全手写。
- **包定义迁入 theme.py**（全部主题数据单点汇聚，避免 theme ← 面板的反向依赖环）；各面板模块内的双包常量删除。
- **接口调整（4 处调用点改签名）**：

| 现状 | 改后 |
|:---|:---|
| `get_family(theme)` → 族名 | **删除** |
| `git_status_color(family, status)` | `git_status_color(theme, status)`（内部查 `THEME_PALETTES[theme]["git_status"]`） |
| `AnsiPalette(family)` | `AnsiPalette(colors_dict)`（构造收包数据，不再查表） |
| `highlighter.set_theme(family)` | `set_theme(pack_dict)`（收包数据） |
| `CodeViewer(theme=family)` + 模块内 `CHROME` | 构造收 `chrome` 包数据（`CHROME` 常量迁出） |

- 调用点清单（迁移时逐一改）：`terminal/panel.py:51`、`viewer/panel.py:70`、`main_window.py:155,247`、`file_explorer/explorer.py:153`、`changes/panel.py`、`file_explorer/model.py`。

### 3.4 历史教训的显式防线（1259 事件根因约束）

1259 事件（[`2026-0719-1259_下拉框选中项实心方块修复计划.md`](文档/修改记录/2026-0719-1259_下拉框选中项实心方块修复计划.md)）根因：**`QComboBox` 普通态设 `background-color` → QSS 背景接管 → 弹出列表选中背景失效（白底白字）**。该约束当前只存在于五 qss 的警示注释中，模板化时若被当作普通注释丢弃即为隐患。本计划设三道显式防线：

1. **警示注释保留清单**（步骤 2 复核项）：现行 qss 中的教训性注释原样迁入 `base.qss`，逐条核对——① `QComboBox` 段"本体普通态不可设 background-color（背景接管致选中背景失效）"防回加警示；② 文件头部"background 语义沿控件树传播"特性说明；③ 浮层段"顶级浮层，不继承 QMainWindow 颜色"注释。
2. **反模式断言**（步骤 8 校验脚本）：渲染结果中 `QComboBox` 普通态规则**不得含 `background-color`**——1259 教训固化为机器防线，任何人（含 AI）日后误加 `combo_bg` 类令牌即被拦截。
3. **风险登记**（§6）：模板化后误加 combo 本体背景令牌的风险行与应对。
