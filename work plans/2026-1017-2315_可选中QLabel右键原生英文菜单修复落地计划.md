## 1. 需求背景

客户反馈（2026-10-17，版本关于页截图确认 **1.7.0.449 最新构建**）：**收起状态的卡片对标题右键**，弹出 Qt 原生英文菜单（`Copy`/`Select All`、带主题图标、带 `Ctrl+C`/`Ctrl+A` 快捷键显示后缀），与 2026-1016-1122 计划统一后的「复制」「全选」中文精简两项形态不一致。

关键操作路径：**卡片收起 → 对标题右键**。卡片展开后对正文右键是已修复的正常形态（正文块走 `BodyText`/`BodyHtml` 的 `contextMenuEvent` 覆写），收起态唯一可点文本是标题 QLabel，问题由此暴露。

## 2. 现状诊断

**根因：Qt 对可选中 QLabel 自带原生标准右键菜单，菜单统一漏了整个 QLabel 家族。**

- `57aa5b1` 给卡片 QLabel 统一开了 `TextSelectableByMouse`（`_selectable()`，`src/gui/panels/chat/cards.py`），满足标题/问答/todo 等整段复制诉求；
- 但 Qt 对开了该旗标的 QLabel 内建一个标准右键菜单——offscreen 探针（`.temp/probe_label_menu.py`）实锤：投喂 `QContextMenuEvent` 后弹出 `&Copy\tCtrl+C`（objectName `edit-copy`，无选区时禁用）、分隔条、`Select All\tCtrl+A`（objectName `select-all`）；英文、带快捷键后缀，真机再叠加主题图标即客户截图形态；
- 2026-1016-1122 菜单统一（`b93e7c0`）只覆写了带 `createStandardContextMenu()` 的文本编辑控件（`BodyText`/`BodyHtml`/`QLineEdit` 等）。**QLabel 没有 `createStandardContextMenu()`**，`exec_standard_context_menu()` 无从复用，QLabel 家族整体漏网。

**影响面（逐一清点）**：

| # | 位置 | 场景 |
|:---:|:---|:---|
| ① | `src/gui/panels/chat/cards.py` `_ElidedLabel`（构造即 `_selectable(self)`） | **各卡标题/副标题——收起态唯一入口（客户截图即此）** |
| ② | `cards.py` 各 `_selectable(QLabel(...))` | 「入参」「出参」节标签、尾注、行数徽标、「子代理活动」、Ask 卡问答行/提示、todo 条目等约 16 处 |
| ③ | `src/gui/settings_dialog.py` 路径标签 | 设置中心裸调 `setTextInteractionFlags`，未走 `_selectable` 的散兵 |

**未受影响面**：卡片正文 `BodyText`/`BodyHtml`、流式块 `TextStreamBlock`、气泡、终端面板、查看器——均有各自 `contextMenuEvent` 覆写，形态已统一。

**语义备注**：QLabel 原生并不处理 Ctrl+C 按键（菜单里的快捷键后缀本就只是显示文本），精简菜单去掉后缀不改变任何按键行为，与全局「菜单项与快捷键正交」规约不冲突。

## 3. 方案设计

**D1（popups.py 新增 QLabel 专用入口，单一 choke point）**：新增 `make_label_selectable(label) -> QLabel`——开 `TextSelectableByMouse` + 装控件级事件过滤器 `_SelectableLabelMenuFilter`（以 label 为父，随控件同生命周期，天然防 GC 与重复叠装），拦截 `QEvent.Type.ContextMenu` 并消费（return True），改弹自制精简菜单：

```python
# src/gui/popups.py
menu = QMenu(label)
make_translucent_popup(menu)
copy_action = menu.addAction("复制")      # enabled = label.hasSelectedText()
select_all = menu.addAction("全选")       # 文本非空时可用
# 复制 → QGuiApplication.clipboard().setText(label.selectedText())
# 全选 → label.setSelection(0, len(label.text()))
menu.exec(event.globalPos())
menu.deleteLater()
```

形态与 2026-1016-1122 规约完全对齐：恰两项、无图标、无 `\t` 快捷键后缀、复制随选区启停。菜单透明化走 `make_translucent_popup()`（popups.py 既有规约函数）。菜单挂 label 为父，天然处于卡片 ID 选择器样式表作用域之外，无 0811 级联透明旧坑。

**D2（cards.py `_selectable` 改委托）**：`_selectable()` 本体改为直接调用 `make_label_selectable()`——①②全部 17 处调用点零改动自动覆盖（`_ElidedLabel` 构造内 `_selectable(self)` 同样走新路径）。

**D3（settings_dialog.py 散兵归队）**：路径标签的裸 `setTextInteractionFlags` 改走 `make_label_selectable()`，消除第二处开口。

**D4（回归测试，QLabel 路径首次入测）**：`tests/test_context_menu.py` 增补——

- 单元级：helper 处理后的 QLabel，经 `QApplication.sendEvent(label, ev)` 投喂右键（**必须走 sendEvent**——事件过滤器只在事件派发路径生效，现有用例的直调 `widget.contextMenuEvent(ev)` 会绕过过滤器），断言菜单恰为 `["复制", "全选"]`、无图标、无 `\t` 后缀；无选区复制禁用，`setSelection` 模拟选区后复制启用；
- 行为级：触发「全选」→ `hasSelectedText()` 且 `selectedText()` 为全文；触发「复制」→ 剪贴板内容与 `selectedText()` 一致；
- 集成级：`_ElidedLabel`（卡片标题实型）右键同形态断言。菜单捕获复用现有 `_MenuGrabber`（Show 即关，offscreen 不卡死）。

**D5（零改动红线）**：`BodyText`/`BodyHtml` 右键路径、`simplify_standard_menu`、终端/查看器/对话框菜单一律不动；不新增主题色键、不动 qss。

**D6（静态守卫，可选——待拍板）**：仿 `scripts/check_qss_selector_guard.py` 手法加规则——扫描 `src/gui/` 下 `TextSelectableByMouse` 字面量，命中点不在 `popups.py` 白名单内即违规非零退出，防未来再生散兵。规则极简（字面量扫描即够），成本一行配置级；不拍板则落为开放项。

## 5. 风险与开放项

- ⚠️ **`_ElidedLabel` 省略态语义**：标题截断上屏时，QLabel 选区与复制只及上屏文本（与鼠标拖选可得范围一致），全文仍经 tooltip 提供——维持 Qt 原生语义，不额外扩复制范围。
- ⚠️ **键盘触发的菜单键**（`Reason.Keyboard`）：`globalPos()` 对键盘理由可能为 `(-1,-1)`，菜单落点偏移；QLabel 默认不可聚焦、实际不可达，接受现状不特判。
- 开放项：D6 静态守卫是否并入（待拍板）；QLabel 是否补 Ctrl+C 按键复制（原生亦无，超本计划范围，不立项）。
