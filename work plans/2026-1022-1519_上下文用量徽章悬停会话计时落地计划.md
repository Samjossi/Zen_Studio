# 上下文用量徽章悬停会话计时落地计划

> **状态**：已实施（修改记录：`文档/修改记录/2026-1022-1531_上下文用量徽章悬停会话计时修改记录.md`）
> **范围**：AI 聊天面板状态行（`src/gui/panels/chat/panel.py`）
> **时间**：2026-10-22 15:19（设计，UTC+8）/ 2026-10-22 15:31（实施）
> **优先级**：中

## 需求

上下文用量徽章（`chatUsageLabel`，状态行右侧百分比）悬停 tooltip 目前只有用量两行（已用/上限 tokens + 数据来源）。用户希望悬停时再看到三类计时信息：

1. **本次对话开始时间**（本标签首轮发送时刻）。
2. **本次对话已持续多久**（会话开始 → 当前，悬停瞬间的实时值）。
3. **上次任务用时**（每轮 AI 任务收尾时记录本轮耗时， tooltip 显示最近一轮）。

徽章是状态行唯一的信息汇聚位，计时信息归到它的悬停 tooltip 是合理落点，不新增常驻 UI。

## 关键探查结论（已核实）

- **tooltip 是静态文本**：`QLabel.setToolTip` 设的是固定字符串，悬停期间不会自动刷新。「已持续 X 小时 Y 分」若只在 `_refresh_usage_label` 时写入，悬停时看到的是上次用量刷新时刻的旧值。必须在 `QEvent.Type.ToolTip` 到达时按当前时刻重算 tooltip，才能保证读数是悬停瞬间的真值。
- **轮次边界清晰**：一轮 = `_send_turn` 启动 → `_on_finished`（正常/失败）或 `_on_stopped`（手动中断）收尾，三个落点都在 `src/gui/panels/chat/panel.py` 单文件内，计时埋点不需跨模块。
- **排队待发接续轮**：`_fire_pending_send` 复走 `_send_turn`，每轮天然独立计时（接续轮是新一轮任务），「上次任务用时」语义 = 最近一轮的耗时，含失败与中断轮（附收尾状态标注）。
- **徽章与簿记同寿命**：`_usage` 本身就是内存态（切后端/重启归零，见 `_usage` 注释），计时簿记对齐同一纪律——内存态不持久化，语义一致无歧义。重放存档会话不考古历史时间（存档未存首条消息墙钟时间，不臆造）。
- **无用量数据时**：当前 `_refresh_usage_label` 空文本 + 空 tooltip。落地后 tooltip 组成改为「用量段（有数据才有）+ 计时段（有数据才有）」，任一段非空即挂 tooltip——首轮发送后轮次计时即可见，不必等用量帧。

## 默认行为决策

- **会话开始 = 本标签首轮 `_send_turn` 的墙钟时刻**；标签创建即置 None，未发送过不显示会话行（不拿标签创建时间冒充对话开始）。
- **上轮任务记录三要素**：开始时刻、收尾时刻、收尾态（完成 / 失败 / 手动停止）；tooltip 显示「用时 + 收尾时刻 + 收尾态」。
- **本轮进行中加赠一行**：`_turn_started_at` 既有簿记顺手利用——busy 期间悬停显示「本轮进行中：已用 N 分 N 秒」（同样是悬停瞬间实时值）。成本仅一个分支，不另设簿记。
- **tooltip 实时重算**：`ChatPanel` 对 `_usage_label` 挂 `installEventFilter`，捕获 `QEvent.Type.ToolTip` 时调用组文案函数重写 tooltip，再走默认显示流程。
- **文案组装与时长格式化抽成模块级纯函数**（不碰 Qt）：`_format_duration(seconds)`、`_compose_usage_tooltip(usage, session_start, last_turn, turn_started_at, now)`——可脱离 GUI 直接单测。
- **时长格式**：<60s 显「N 秒」；<1h 显「N 分 N 秒」；≥1h 显「N 小时 N 分」。时刻显「HH:MM」（跨天会话开始行带「MM-DD HH:MM」，以 now 是否同日判定）。

## tooltip 目标形态（示例）

```
上下文已用 20,806 / 上限 262,144 tokens（8%）
数据来源：kimi 会话记录（agent 落盘的接口真值）
会话开始：15:12（已持续 2 小时 7 分）
上轮任务：用时 1 分 23 秒（15:18 完成）
```

busy 期间：

```
……（用量段同上）
会话开始：15:12（已持续 2 小时 9 分）
本轮进行中：已用 45 秒
上轮任务：用时 1 分 23 秒（15:18 完成）
```

## 实施步骤

### 1. 纯函数（`src/gui/panels/chat/panel.py` 模块级）

- `_format_duration(seconds: float) -> str`：按决策的分档格式输出。
- `_compose_usage_tooltip(...) -> str`：用量段（沿用现有 `source_note` 三态映射，原地提取复用）+ 会话行 + 本轮进行中行（busy 才有）+ 上轮任务行，按有数据的段拼装，全空返回空串。

### 2. 计时簿记（`ChatPanel`）

- 新增字段：`_session_started_at: datetime | None`、`_turn_started_at: datetime | None`、`_last_turn: dict | None`（开始/收尾时刻 + 收尾态）。
- `_send_turn`：`_turn_started_at = now`；`_session_started_at` 为 None 时同刻置位。
- `_on_finished`：正常/失败分支统一在收尾处记 `_last_turn`（收尾态区分完成/失败），`_turn_started_at` 清 None。
- `_on_stopped`：同记（收尾态=手动停止）。
- 三处收尾后调 `_refresh_usage_label()`，让 tooltip 即时含新计时数据（不等下一次用量帧）。

### 3. 悬停实时重算（`ChatPanel`）

- `_build_input_box` 内 `_usage_label.installEventFilter(self)`。
- `eventFilter`：对象为 `_usage_label` 且事件为 `QEvent.Type.ToolTip` 时，调 `_compose_usage_tooltip` 按当前时刻重写 tooltip 后放行（返回 False 走默认显示）。

### 4. `_refresh_usage_label` 改造

- 徽章文本逻辑（百分比 / `~` 前缀 / hot 属性）不动。
- tooltip 赋值改调 `_compose_usage_tooltip`（用量段数据来自 `self._usage`），替代现有内联两行拼装；`source_note` 映射移入纯函数。

### 5. 测试（新增 `tests/test_usage_badge_timing.py`）

- 纯函数用例（不实例化 ChatPanel，无 Qt 依赖）：
  - `_format_duration` 三档边界（59s / 60s / 3599s / 3600s）。
  - `_compose_usage_tooltip`：全 None → 空串；仅用量 → 与现行两行同形；仅计时 → 无用量段；会话开始跨天 → 时刻带日期；busy（`turn_started_at` 非 None）→ 含「本轮进行中」行；上轮三态收尾态文案各一。
- 探针式 GUI 验证（offscreen，参照 `scripts/probe_subagent_frames.py` 惯例放 `.temp/`）：发一轮 mock 轮次后读徽章 tooltip，确认含三段。
