# 终端面板单行头部栏重构计划（阶段一）

## 1. 目标

把现有"标题行"重构为**正式的单行头部栏**：左侧标识区（shell 名 + 状态）、右侧操作组（清屏 / 重开 / 隐藏面板），高度锁定、样式接入主题 qss；同步移除排版诊断用的三条 DEBUG 边框。单 PTY 会话保持不变（多会话属阶段二）。

目标形态：

```
┌────────────────────────────────────────────┐
│ bash           [状态]  [清屏] [重开] [−]   │ ← 单行头部栏（固定高度）
├────────────────────────────────────────────┤
│ $ █                                        │ ← 终端视口占满剩余
└────────────────────────────────────────────┘
```

## 2. 现状问题（本计划要消除的）

| 问题 | 出处 |
|:---|:---|
| 标题行无高度约束，曾膨胀抢占终端区（已用 stretch=1 临时收敛，需固化为正式设计） | 2026-07-19 排版走查 |
| 代码残留三条 DEBUG 边框（panel 红框 / title_row 蓝框 / widget 绿框硬编码） | 同上 |
| 「重开」独占按钮位，清屏/隐藏等新操作无安放位置 | 选型文档 §3 方案 A |
| 无"隐藏面板"入口（`setCollapsible(1, False)` 禁止折叠后只能拖 splitter） | 同上 |

## 3. 设计

### 3.1 头部栏结构（panel.py）

```
头部栏 QWidget（objectName="TerminalHeader"，固定高度）
└── QHBoxLayout
    ├── _title  QLabel（objectName="PanelTitle"）  shell 名，stretch=1
    ├── _status QLabel（objectName="PanelHint"）   状态文本（进程退出提示等）
    ├── btn_clear   QPushButton("清屏")
    ├── btn_restart QPushButton("重开")            （现有 _restart 沿用）
    └── btn_hide    QPushButton("−")               隐藏面板
```

- **高度锁定**：`setFixedHeight(...)`（取按钮 `sizeHint` 高 + 边距，约 28px），从根上杜绝"标题行膨胀"复发；外层 `QVBoxLayout` 维持 `addWidget(terminal, 1)` 的 stretch 约束双保险。
- **样式**：全部走主题 qss——标题/状态沿用现有 `#PanelTitle`/`#PanelHint` 选择器；按钮沿用主题 `QPushButton` 实体化描边体系；头部栏容器给 `objectName="TerminalHeader"` 预留定制钩子，本期 qss 无需新增规则。
- **图标化**：项目尚无图标字体体系，本期用文字按钮（「清屏」「重开」「−」），图标化列入备案。

### 3.2 三个操作的语义

| 按钮 | 行为 | 实现 |
|:---|:---|:---|
| 清屏 | 向 PTY 写入 `Ctrl+L`（`\x0c`），由 shell/readline 执行清屏并把提示符重绘到顶行（与真实终端 Ctrl+L 语义一致）；进程已退出时禁用 | `TerminalPanel._on_clear()` → `session.write(b"\x0c")` |
| 重开 | 现有行为不变：重建 `TerminalScreen` + spawn 新进程 | 现有 `_start_session()` |
| 隐藏 | 隐藏整个终端面板，中栏查看器占满；恢复入口在「视图」菜单 | 见 §3.3 |

清屏选型说明：**不**采用"本地重置 pyte 屏幕"——那会与 shell 的行编辑状态脱节（shell 不知道屏幕被清了，提示符位置错乱）；写 `Ctrl+L` 让 shell 自己清，语义与真实终端一致。

### 3.3 隐藏/恢复接线（main_window.py）

- `TerminalPanel` 新增信号 `hide_requested`；`btn_hide` 点击 → 发射。
- `MainWindow` 接线：`terminal_panel.setVisible(False)`（`QSplitter` 自动把空间让给查看器）。
- **恢复入口**：视图菜单新增勾选动作「终端面板(&T)」（勾选态跟随 `isVisible()`，取消勾选 = 隐藏，勾选 = 恢复）。与既有「过滤噪音目录」动作同区。
- 与 `setCollapsible(1, False)` 的协调：防折叠约束针对的是 splitter 把手拖动（防误拖归零），按钮/菜单控制的显隐走 `setVisible`，二者不冲突。
- 窗口状态持久化（`splitter_middle` sizes）不受影响；可见性是否持久化本期不做（启动始终显示，备案）。

## 5. 验证标准

| 项 | 标准 |
|:---|:---|
| 高度锁定 | 拖动 splitter、缩放窗口、restoreState 恢复后，头部栏始终为固定高度（offscreen 截图核对像素） |
| 内容贴顶 | 启动后提示符从终端区顶行起排（既有修复不回退） |
| 清屏 | `seq 1 50` 输出一屏后点「清屏」→ 屏幕清空、提示符在顶行；回滚区同步清空（Ctrl+L 语义） |
| 重开 | `exit` 后状态行显示退出码、清屏按钮禁用、点「重开」新会话正常 |
| 隐藏/恢复 | 点「−」面板消失、查看器占满；视图菜单「终端面板」勾选恢复且会话仍存活（未 terminate） |
| 主题 | 五个主题逐一切换：头部栏与按钮样式跟随主题、无硬编码残色 |
| 回归 | 终端既有功能（交互程序、回滚、resize）不受影响 |

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| `Ctrl+L` 在某些交互程序（vim 等）中语义不同（重绘而非清屏） | 🟢 | 可接受：语义本就与真实终端一致，清屏按钮面向 shell 提示符场景 |
| 固定高度在不同字体/字号下截断按钮文本 | 🟡 | 高度取按钮 `sizeHint().height()` 动态计算而非写死像素；主题切换字号后重算 |
| 视图菜单动作勾选态与实际可见性失同步 | 🟢 | 单一事实源：动作 `setChecked(terminal_panel.isVisible())`，隐藏信号与菜单动作都汇入同一槽函数 |
