# 「最近打开的文件」→「最近打开的项目」改造计划

> **状态**：已实施（2026-07-24 同日闭环，P1/P2/P3 全量落地，验证见 §7）
> **范围**：`gui/menus/file_menu.py`（文案 + 子菜单语义）
>   + `gui/main_window.py`（记录接线 + 回放槽）
>   + `gui/window_state.py`（键空间回收 `recent_files`）
>   + `gui/panels/viewer/panel.py`（删除 `file_opened` 信号）
>   + 新增 `gui/recent_projects.py`（最近项目存取，全局共享）
>   + 删除 `gui/recent_files.py`（最近文件存取，整体退役）
> **时间**：2026-07-24 10:03（立项，UTC+8）
> **起因**：需求方评审文件菜单「最近打开的文件」，指出记录语义不符合 IDE
>   惯例——IDE 记住的是**最近打开的项目（文件夹）**，而非单独的文件。
>   决定将该项改造为「最近打开的项目」

## 目标布局（仅子菜单语义与文案变化，菜单位置/助记符不变）

```
文件(&F)
├─ 打开文件(&O)…            （现有，不动）
├─ 新建窗口(&N)             （现有，不动）
├─ 在新窗口打开文件夹(&W)…  （现有，不动）
├─ 打开配置目录(&C)         （现有，不动）
├─ 最近打开的项目(&R) ▸     （改造：记录项目文件夹，点击在新窗口打开）
├─ ────────────
└─ 退出(&Q)                 （现有，不动）
```

## 1. 现状与差距

现有「最近打开的文件」（work plans/2026-0722-1901 落地）记录的是
**单文件绝对路径**（`ViewerPanel.file_opened` 信号收口），回放为在查看器
重新打开该文件。与 IDE 惯例的差距：

1. **记录对象错误**：IDE 的 Recent 列表回答的问题是"我最近在做哪几个
   项目"，用于快速回到项目现场；单文件列表回答的是"我最近看过哪几个
   文件"，回访价值低（文件树一点即达，无需历史）。
2. **回放层级错误**：项目级回放应恢复整个工作区现场（新窗口绑定该
   工作区根），而非只在中栏查看器里摆一个文件。

### 1.1 关键既有事实（方案约束来源）

| 事实 | 位置 | 对本计划的约束 |
|:--|:--|:--|
| 多开模型：一进程绑定一工作区根，「打开文件夹」= `subprocess.Popen` 起新进程 | `main_window.py:343-359` | 项目回放天然复用 `_spawn_window(folder)`，零新增进程逻辑 |

| 记录点候选：`open_folder_in_new_window` 只覆盖菜单入口 | `main_window.py:343` | 命令行 `main.py <folder>` 启动不入列——收口点上移至**窗口启动**（见 §2.2） |

## 2. 方案

### P1 全局存取层（新增 `gui/recent_projects.py`）

**存储位置：`config/recent_projects.json`（全局单文件，不按工作区哈希分文件）。**

- 不放 `settings.json`：`reset_settings` 全量重写偏好文件，最近项目列表
  是历史数据而非偏好，不应随"恢复默认设置"被清
- 不放 `window_state` 体系：该体系按工作区根哈希分文件，无"全局"位置；
  且键空间由 `WindowState` 定型为布局 + 本工作区查看历史，混入全局
  数据破坏其"按工作区隔离"的单一职责

**文件格式**（dict 包一层，留扩展位；键名常量引用，AFCP 3.1）：

```json
{"recent_projects": ["/abs/path/to/project", "..."]}
```

**存取层**：

```python
MAX_RECENT_PROJECTS = 10

class RecentProjectsStore:
    """最近打开的项目（工作区根）列表，全局共享，存 config/recent_projects.json。

    add(path)：规范化（resolve）+ 去重 + 置顶 + 截断 10 条，即时原子写；
    list()：读回（缺失/损坏回退空表，拷出隔离）；
    remove(path)：回放发现目录已消失时剔除；
    clear()：清空（子菜单「清除列表」项）。
    """
```

- 构造显式接 `state_file: Path`（AFCP 2.3 依赖显式；调用方传
  `CONFIG_DIR / "recent_projects.json"`）
- 读写走「读全量 → 合并 → `write_json_atomic` 写回」链；损坏防御：
  非 dict / 键值非 `list[str]` 一律回退 `[]`（路径允许多字节 UTF-8，
  与 `recent_files` 判据同理）
- 多开并发：各窗口启动写同一文件，读-合并-写后写胜；列表非关键数据，
  收敛即正确，不加锁（沿用 2026-0722-1901 §5 论证）

### P2 记录链与回放改造

**记录点：窗口启动即记录自身工作区根（收口于 `MainWindow.__init__`）。**

- 覆盖全部打开路径：菜单「在新窗口打开文件夹」、命令行
  `main.py <folder>`、「新建窗口」（同根）——三路径最终都汇聚为
  "一个窗口进程带着一个 workspace_root 启动"
- 去重置顶语义下，「新建窗口」/重复打开同根只是把该项固定在首位，
  不产生噪音条目
- 默认根（PROJECT_ROOT）照常记录：它也是合法项目，且是最高频现场
- 时机取 `_build_layout` 之后即可（无 UI 依赖，纯数据写盘）

**回放槽 `MainWindow.open_recent_project(path)`**：

- `Path.is_dir()` 探活——存在则 `_spawn_window(path)` 起新进程绑定该
  工作区根（新窗口启动时会自动把该项置顶，无需手工再记）
- 目录已消失：`store.remove(path)` + 状态栏提示
  「文件夹已不存在，已从列表移除」（沿用原最近文件的提示风格）
- 点击项恰为当前工作区根：等价于「新建窗口」，**接受、不开特例**
