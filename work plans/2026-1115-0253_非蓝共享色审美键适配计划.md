## 1. 背景与需求

去共享化把六包物理拆进四主题，但非蓝键仍全部保持旧共享基线（四主题逐值相同）。违和重灾区是**语法包审美键**——暖米主题的代码字符串仍是鲜绿 `#007a1c`、命名空间仍是紫 `#7a3db8`，与米黄窗口同框刺眼；其次是**中性灰的冷暖**——wheat 的注释灰、气泡底色是冷灰，与暖族底色不同温。

用户拍板适配口径为**选项 3 仅审美键**：语法包审美键全量按主题色相适配；中性灰冷暖跟随主题；终端 ANSI 16 色、git 状态色、聊天 diff 红绿、git_graph 徽标等语义/功能色**一律不动**（四主题继续同值）。

本计划只做颜色适配，不增删主题、不改 qss 令牌、不动六包结构。

## 2. 现状机制

主题体系与六包结构见 1643 计划 §2，此处不再重复。与本次直接相关的事实：

- `tests/test_theme.py` 经 1643 重写后断言**全部非蓝键**四主题等于旧共享基线——本次适配后该断言必须按口径拆分（§6）。
- 蓝键已由逐主题锁定表守护（1643 §5.3 及 D6 终值）；本次新增的适配值用同构的 `_THEME_ADAPTED` 表锁定。
- 消费方全部按键取值、零消费方改动预期（grep 复查兜底）：语法包 → 查看器高亮（`panels/viewer/highlighter.py`，经 panel 装配传入）；chrome 行号 → `panels/viewer/code_viewer.py:144`；chrome 借用方 → `panels/viewer/markdown_view.py:230`（见 D6）；聊天灰键 → 聊天卡片渲染；ignored → `panels/changes/list.py:78`；hash_fg → git 提交图 hash 弱化。

## 3. 目标

1. 语法包七枚审美键（Keyword.Namespace / Name.Builtin / Name.Function / Name.Decorator / String / Number / Comment / Operator，Error 红为语义色不动）按 §5.1 表逐主题适配。
2. 六包内八枚中性灰键（chrome line_number_fg/bg、chat reasoning_fg / tool_fg / user_bubble_bg / tool_output_bg、git_status ignored、git_graph hash_fg）按 §5.2 表冷暖跟随。
3. 语义/功能色维持四主题同值不变（测试断言守护，§6）。
4. `bash scripts/check.sh` 全量门禁通过；offscreen 四主题截图走查通过（重点：同族近亲 token 可辨、灰阶冷暖观感、对比度）。

## 4. 非目标与硬边界

- 🔴 终端 ANSI 16 色（含 find_bg/find_cur）、git_status 状态色四键中 untracked/deleted/conflict（ignored 是灰键属本次范围）、git_graph 徽标四色（head/branch/tag/remote）、chat diff 四键（diff_add_fg/diff_del_fg/diff_add_bg/diff_del_bg）与 timeline_tool_fg、chat usage_hot_fg / tool_error_fg（引用 WARNING_COLOR 的语义警示色）——四主题同值不动。
- 🔴 Token.Error `#cc0000` 不动（语法错误语义色）。
- 🔴 chrome/terminal 的 find_bg/find_cur 黄系查找色不动（功能色）。
- 🔴 不动 qss 令牌、不动蓝键、不增删主题、不改消费方代码（D6 若拍板同步做掉，仅动 markdown_view.py 一个取键）。
- 🔴 所有改动值小写（Qt HTML 导出色值归一小写的姊妹项目经验，大写会使「包值 in html」型断言假阴性）。

### 5.3 对比度底线（机器断言）

- 正文级文字键（Namespace/Function/Decorator/String/Number/Operator、tool_fg）在 `#ffffff` 底上对比度 ≥ 4.5。
- 弱层级键（Comment、reasoning_fg、line_number_fg、hash_fg、ignored）在各自底色上对比度 ≥ 3.0（与旧基线 `#888888` 在白色上 3.54 同档，不弱于现状）。
- 测试内用 QColor 相对亮度公式逐主题机器计算，不依赖目检。

## 8. 决策点（请审阅时拍板）

- **D1 cloud 锚定政策**：cloud 作为默认/参考主题，审美键与灰键全部保持基线不动（本计划表即按此写）。🟡 建议：不动——基线值本来就是为 cloud 调的，且默认主题稳定性优先（姊妹项目同口径执行）。
- **D2（本项目自动消解）**：姊妹项目有 mono 锚定政策（仅 Comment/Operator 中性化）；本项目无 mono 主题，无需拍板。
- **D3 灰键覆盖清单**：Operator（近黑文字）计入灰键跟随冷暖；git_graph hash_fg、git_status ignored 计入。🟡 建议：计入（它们的冷暖违和同属本次要解决的问题）；若有键你认为必须保持跨主题一致（如 ignored），指出后从表剔除。
- **D4 徽标与终端的后续**：git_graph 徽标（head 品红/branch 绿/tag 棕橙）与终端 16 色本次不动——它们在非蓝主题仍是共享血统。🟡 建议：本次不动，走查后若观感碍眼再立小计划（避免本次范围蔓延）。
- **D5 气泡/输出卡底色的冷暖幅度**：user_bubble_bg/tool_output_bg 从 `#ededf0`（蓝紫灰）转到暖族/绿族后，与 qss 令牌 `popup_bg`/`sidebar_bg` 同屏时的层级感需走查确认。🟡 建议：按表初值走查，必要时在同族内回调。
- **D6（新增，本项目适配）`line_number_bg` 借用的连带染色**：`markdown_view.py:230` 的 `code_bg` 借用行号栏底色令牌——本计划把 `line_number_bg` 按主题染色后，Markdown 行内代码/代码块/表头底色会被一并带成主题色。姊妹项目漏掉此点，用户走查不满后被迫单立 1255 回改计划（chrome 新增 `code_bg` 专用键、四主题回填 `#f5f5f5`）。🟡 建议**本计划同步做掉**：chrome 包新增 `code_bg` 键（四主题统一 `#f5f5f5`，即适配前基线观感）+ `markdown_view.py` 改取新键，范围仅 +1 文件，消掉整个回改循环。备选：不做，后续单立 1255 移植版。
