## 1. 背景与目标

`acp/connection.py` 同时承担 JSON-RPC 收发、进程生命周期、反向请求分发、terminal/* 处理、stderr 脱敏与诊断日志。连接主路径与两类外设设施混在一个文件里，terminal 与脱敏无法独立测试。

本子计划目标：

1. 新建 `acp/diagnostics.py`，承接脱敏、有界 stderr ring 与诊断日志。
2. 新建 `acp/terminal.py`，承接 terminal/* 反向请求、env 解析与终端输出处理。
3. `connection.py` 只保留收发、请求配对、连接代次、进程失效与轮次原语，行为不变。

- terminal 处理仍只由连接层分发；provider 与 GUI 的现有接口不变。

### S6.2 新建 `acp/diagnostics.py`

1. 迁入脱敏函数：凭证、JWT、Cookie、长 token 等规则原样保留。
2. 迁入有界 stderr ring：容量、按字节/行截断、tail 行为不变。
3. 迁入诊断日志 helper：事件名、方法名、脱敏后的 stderr 摘要格式不变。

### S6.3 新建 `acp/terminal.py`

## 5. 风险与注意点

- **超时与取消**：terminal 与轮次取消共享等待机制；搬家不能改变超时归属与错误码。
- **反向请求 ID**：terminal 回复必须沿用原请求 ID；错配会让 agent 挂起。
- **安全边界**：env 过滤、cwd 校验与命令处理不得因拆分放宽；不新增 shell 执行路径。
- **循环依赖**：terminal 模块不要反向 import connection；用参数传入发送/回复原语。
- **可选性**：本子计划不阻塞主链；若余量不足，明确记录未做，不降低前五项完成标准。
