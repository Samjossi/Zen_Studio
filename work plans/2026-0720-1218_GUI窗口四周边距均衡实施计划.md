# GUI 窗口四周边距均衡实施计划

## 1. 问题陈述

用户实机发现：**窗口底部面板距离边缘较远，而左、右、上三边距离窗口边界太近**，四边呼吸感失衡，视觉上卡片"贴边"。

### 1.1 多模态取证（2026-07-20 12:14 实测）

离屏自动截图（`uv run main.py --auto-screenshot`，1200×800，晴空主题）经像素扫描脚本（`.tmp/measure_margins.py`，Qt 像素色值比对）量化：

| 方位 | 实测间距 | 构成 |
|:---|:---|:---|
| 左 | **6px** | 面板外边距 6px（`chat/panel.py:91`） |
| 右 | **6px** | 面板外边距 6px（`changes/panel.py:100`） |
| 上（菜单栏底→卡片顶） | **≈5px** | 面板外边距 6px（`viewer/panel.py:89`） |
| 下（卡片底→窗口底） | **31px** | 面板外边距 6px + 状态栏高约 25px |

用户实机截图（1600 宽）与离屏截图边距**像素值一致**（均 ≈6px），感知的"截图边缘更宽"系窗口尺寸差异（同等像素边距在小窗口中相对占比更大），非代码路径分叉。

### 1.2 根因定位

1. **无窗口级外边距**：`main_window.py:99` 将 `QSplitter` 直接 `setCentralWidget()`，窗口四边的唯一间距来源是各面板内部布局的 6px 外边距。
2. **底部天然多一层状态栏**：`QStatusBar`（`base.qss:314` 透明融合）自身高约 25px，叠加面板 6px 外边距后底部视觉间距 ≈31px，约为其余三边（6px）的 5 倍。
3. 面板外边距的既有设计意图是"卡片不贴窗口边缘与 splitter 把手"（`chat/panel.py:90` 注释），其同时承担**卡片间间距**职能，不可简单删改。

## 2. 目标设计

### 2.1 方案：中央容器外边距（选定）

在 `MainWindow` 中将主 splitter 包入一层容器 `QWidget`，由容器布局提供窗口级外边距：

```python
central = QWidget(self)
outer = QVBoxLayout(central)
outer.setContentsMargins(6, 6, 6, 0)  # 左/上/右补 6px；底部 0（状态栏已提供呼吸区）
outer.setSpacing(0)
outer.addWidget(self._splitter_main)
self.setCentralWidget(central)
```

叠加后四边有效间距：

| 方位 | 改前 | 改后 |
|:---|:---|:---|
| 左/右 | 6px | **12px** |
| 上（菜单栏底起） | ≈5px | **≈11px** |
| 下（卡片底起，含状态栏） | 31px | **31px（不变）** |

- **底部不再加大**：底部间距由状态栏结构性提供，容器下边距设 0，避免底部进一步臃肿——失衡的来源是左右上三边太小，而非底部太大。
- **面板内边距不动**：6px 外边距继续承担卡片↔splitter 把手间距，与容器外边距职责分离、可独立调参。
- **零持久化影响**：容器不改变 splitter 层级内的部件顺序与 objectName，`saveState/restoreState` 字节格式不受影响，既有窗口几何/分隔栏持久化数据全兼容。

### 2.2 否决方案

- **QSS `QSplitter { padding }`**：splitter 把手命中区随 padding 内缩，拖拽热区错位，且 qss padding 对 QSplitter 布局行为跨平台不一致。
- **削状态栏高度**：状态栏承载"就绪"消息与 Git 差异统计常驻区（`main_window.py:110-112`），压缩高度损害功能性，且底部呼吸感本身合理。
