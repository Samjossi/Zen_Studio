# 音频双击播放与播放按钮失效修复落地计划

> **状态**：已实施
> **范围**：文件查看面板媒体页（`src/gui/panels/viewer/`）
> **时间**：2026-10-13 05:46（设计，UTC+8）/ 2026-10-13 06:08（实施）
> **优先级**：高

## 需求

1. 用户在文件树**双击**音频文件（wav/mp3/ogg/flac）→ 查看面板自动播放。
2. 用户点击媒体页**播放按钮** → 播放/暂停生效。
3. 播放失败时给出**用户可见的明确反馈**，不再静默停在 `-:-- / -:--` 占位页。

## 关键探查结论（已核实）

- **功能代码已存在且链路完整，不是空实现**：
  - 文件树双击：`src/gui/panels/file_explorer/explorer.py:567` `_on_double_clicked` 对扩展名无过滤，`file_opened` 信号经 `src/gui/main_window.py:275` 接入 `ViewerPanel.open_file`（`src/gui/panels/viewer/panel.py:316`），音频扩展名分流到 `_open_media` → `MediaViewer`。
  - 双击自动播放：`src/gui/panels/viewer/media_viewer.py:152` `open_media` 置 `_autoplay=True` + `setSource`；`:248` `_on_media_status` 在 `LoadedMedia` 时自动 `play()`。
  - 播放按钮：`:91` `clicked` 已连接 `_toggle_play`（`:200`，play/pause 真实实现）；`open_media` 末尾置 enabled。
- **源码态端到端探针验证通过**（offscreen + 项目 `.venv`，打开真实 wav）：页面切换、按钮 enabled、LoadedMedia 自动播放、播完到 EndOfMedia、按钮点击切 PlayingState，全链路正常。
- **用户现场症状的关键读数**：截图中时间恒为 `-:-- / -:--` 且停留在音频占位页。这说明 `durationChanged` 从未触发（媒体未达 `LoadedMedia`），同时也没收到 `InvalidMedia`（否则会走 `failed` 信号回落文本页占位，见 `panel.py:475`）——**媒体卡在加载阶段，且无任何错误上抛**。
- **基础设施齐备**：`pyproject.toml` 仅声明 `pyside6`（QtMultimedia 随附）；`building/dist/zen-studio`（2026-10-05 构建）内 FFmpeg 后端插件与 `media_viewer` 模块均已打入。
- **日志通道**：`main.py:55` 统一日志（INFO 级，`config/logs/zen-studio.log` + stderr 双输出），各模块 `logging.getLogger(__name__)` 即可；打包态日志文件是唯一观测面。
- **可复用的兜底范式**：`src/gui/sound_player.py` 的 QSoundEffect + `aplay/paplay/play` 系统播放器降级链（提示音专用，与查看器互不复用）。

## 根因分析（候选按嫌疑排序）

代码无缺失，问题在**用户运行环境层面**：

1. **Qt Multimedia FFmpeg 后端在用户环境加载失败或卡住**：`mediaStatus` 停在 `NoMedia/LoadingMedia`，`play()` 与自动播放被静默吞掉，`_autoplay` 永不触发。AppImage 场景需排查插件加载（libva 等系统库缺失）。
2. **无音频输出设备/声卡**：Qt 音频进 Error 态（`tests/test_notification.py:236` 已记录 offscreen/无声卡下同类现象），play 看似无反应。
3. **目标 wav 编码异常**（非 PCM，如 GSM/ADPCM）：FFmpeg 解不了且错误消息为空时 `_on_error`（`media_viewer.py:259`，空串不上抛）静默吞掉。

## 默认行为决策

- **先诊断后修复**：第一步加日志埋点，在用户出问题环境复现一次拿到实锤根因，再决定修复侧重；但下述加固项无论根因是哪个都要做（失败必须可见）。
- **加载停滞超时**：`open_media` 挂源后 5 秒未到 `LoadedMedia/InvalidMedia`，判定加载停滞，上抛 `failed`（提示"音频加载超时：后端不可用或无声卡"），回落占位提示。
- **空错误消息不再静默**：`_on_error` 收到空串以外的错误照常上抛；超时守卫覆盖"完全无信号"场景，两者合起来消灭静默卡死。
- **音频降级保底出声**：超时或后端错误时，除占位提示外，音频文件（非视频）自动降级到系统播放器（aplay/paplay/play 探测链，模式取自 `sound_player.py`）保底出声；UI 控制条保持禁用态并标注"已降级系统播放"。视频不降级（无声卡环境下视频画面仍可看，仅提示无声）。
- **不新增依赖**：Qt Multimedia + 系统播放器探测链覆盖目标场景。

## 实施步骤

### 1. 诊断埋点（先落地，先复现）

- `media_viewer.py` 模块级加 `logger = logging.getLogger(__name__)`（仿 `src/gui/panels/file_explorer/explorer.py:38` 先例）。
- `_ensure_player` 记录后端初始化完成；`_on_media_status` 记录每次状态变迁（状态名）；`_on_error` 记录错误码与消息（含空串，DEBUG 级记"错误清除"）；`open_media`/`stop`/`_toggle_play` 各记一行 INFO。
- 交付后请用户在出问题环境复现一次（源码态看 stderr；AppImage 态看 `config/logs/zen-studio.log`），按日志确认根因属于 §根因分析 中哪一类。

### 2. 加载停滞超时守卫（`media_viewer.py`）

- `open_media` 挂源后启动 `QTimer.singleShot(5000, ...)` 单次定时器（持有引用防 GC）；`stop()` 与 `_on_media_status` 收到 `LoadedMedia/InvalidMedia` 时取消。
- 超时触发：记 WARNING 日志 → `self.failed.emit("音频加载超时：Qt 音频后端不可用或无输出设备")`（视频文案对应调整），走现有 `failed` 回落链。

### 3. 错误上抛完善（`media_viewer.py`）

- `_on_error`：非空消息上抛照旧；补记日志（含错误枚举值）。空串不再单独特殊化为"完全无动作"——仅不上抛（避免错误清除误报），但必须 DEBUG 落日志。
- `_on_media_status` 收到 `InvalidMedia` 的上抛文案补充建议项（"格式不受支持或缺少解码器；可尝试系统播放器"）。

### 4. 音频系统播放器降级（`media_viewer.py` + 抽出共用探测链）

- 把 `sound_player.py` 中 `_play_system` 的 `aplay/paplay/play` 探测链抽为共用函数（放 `src/gui/sound_player.py` 导出 `play_system(path)`，`sound_player` 内部改调它），`media_viewer` 复用，不复制实现。
- `MediaViewer` 新增：超时/后端错误且 `_is_audio` 时，调 `play_system(path)` 保底出声；音频占位页文案追加"（已降级系统播放）"。探测链全部不可用则静默（占位提示已说明原因）。
- `stop()`/切换文件时不强杀系统播放器子进程（提示音同款语义：短音自然播完）。

### 5. 测试（新建 `tests/test_media_viewer.py`）

- offscreen 范式参考 `tests/test_viewer_find_shortcut.py` 与 `tests/test_notification.py`。
- 双击链路：`open_media` 后 `_autoplay` 置位；模拟 `LoadedMedia` 触发自动 `play()`（mock `_player` 或打真实 wav，CI 无声卡场景用 mock）。
- 超时守卫：mock 播放器不产状态信号，定时器用短超时（注入间隔）验证 `failed` 上抛。
- 降级：`failed` 触发后音频文件调用 `play_system`（mock 掉子进程）、视频不调用。
- `_on_error` 空串不上抛、非空串上抛并落日志。

### 6. 门禁与收尾

- 跑 `bash scripts/check.sh`（隐私扫描 + lint + 测试），全绿。
- 真实环境人工验证（非 offscreen）：双击 wav 出声、播放/暂停按钮生效、进度条与时间走动、切走文件自动停播。
- AppImage 态另行验证一次（打包态 stderr 不可见，以 `config/logs/zen-studio.log` 为观测面）。
