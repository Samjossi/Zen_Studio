# Git 提交历史图美化计划

> 1507 计划交付的提交历史图是 `git log --graph` 的 ASCII 原样透传（单色、无分栏、refs 与正文混杂），真机目验确认「不是人类可读友好」。本计划在 0110 选型报告推荐的方案 A 路线上立项美化：先 ANSI 彩色化止血，再结构化列表化（图形列自绘 + 信息/作者/时间分栏 + refs 徽标化）。

## 1. 目标行为

| 场景 | 现状（1507 交付） | 目标 |
|:---|:---|:---|
| 图线辨识度 | 单色 ASCII（`*` `|` `\` `/`），分支一多即难以追踪泳道 | 图线按 git 原生 lane 配色着色（颜色随主题适配） |
| 提交信息可读性 | 短 hash + refs 括号 + 信息挤在一行，长信息横向溢出 | hash / refs 徽标 / 信息 / 作者 / 相对时间 分栏呈现 |
| refs（分支/标签/HEAD） | 与正文同色的 `(HEAD -> main, tag: v1)` 纯文本 | 徽标化着色（HEAD/分支/标签/远程分色） |
| 大仓库浏览 | 500 条纯文本一屏滚 | 列表虚拟化滚动 + 截断提示行（上限沿用 500） |
| 降级/刷新/单例/非模态 | 已具备（1507） | 全部沿用，不回归 |

## 4. 候选方案

### 方案 甲：ANSI 彩色透传（止血档）

数据命令改为 `git log --graph --color=always`（强制 git 输出 SGR 颜色：图线按 lane 着色、hash 黄、refs 彩色），自写迷你 SGR→HTML 转换（git 只用前景色 30–37/90–97、粗体、重置，约 60 行可覆盖），颜色经 TERMINAL_PACK 映射为当前主题色，载体换 `QTextBrowser`（等宽不变）。

- **优点**：改动最小（数据层 1 个参数 + 1 个转换函数 + 换控件）；图线彩色化后泳道可追踪性即获质的提升；git 布局引擎零维护
- **缺点**：仍是 ASCII 字符画；无分栏；refs 仍是文本括号；长信息依旧挤压

### 方案 乙：结构化列表 + 图形列自绘（推荐主线）

`QTreeView`（平铺无层级）+ 委托：图形列自绘（数据源为 git 自身 `--graph` 输出逐字符解析），其余列分栏（hash / refs 徽标 / 信息 / 作者 / 相对时间）。

- **优点**：真·人类可读：分栏对齐、refs 徽标化、行级选中高亮；图形列颜色与布局 100% 复用 git 布局引擎（逐字符解析 `--graph` 行前缀），**无需移植/维护 lane 算法**；`QTreeView` 天然虚拟化，500 条无性能压力
- **缺点**：工作量集中在委托自绘与 `--graph` 输出解析；`--graph` 输出非 git 官方机器接口（porcelain 才是），存在版本漂移风险——须断言兜底（解析失败整窗降级回方案甲形态）

### 方案 丙：theia-zen lane 算法移植 + 贝塞尔平滑泳道（远期）

移植 `scm-history-graph-lanes.ts`（0110 估计 300–500 行 + 800 行单测对照），泳道以三次贝塞尔曲线平滑绘制，视觉对齐 VS Code Source Control Graph。

- **优点**：视觉上限高（曲线平滑、无连接行）；布局自主可控，后续交互（点击 lane 高亮分支链）有载体
- **缺点**：算法翻译与单测移植成本高； parents 数据需自行解析维护；对本「低频查看」场景投入产出比低

### 对比小结

| 维度 | 方案 甲 | 方案 乙（推荐） | 方案 丙 |
|:---|:---|:---|:---|
| 图线彩色 | ✅ | ✅ | ✅ |
| 分栏/徽标化 | ❌ | ✅ | ✅ |
| 开发成本 | 低（半天级） | 中（2–3 天级） | 高（5 天+） |
| 新增依赖 | 无 | 无 | 无 |
| 布局引擎维护 | git 自身 | git 自身（解析其输出） | 自维护算法 |
| 视觉上限 | ASCII | 列表级（对齐 Fork/GitKraken 的表格形态） | VS Code 曲线级 |

## 5. 推荐路线与分阶段

**甲 → 乙 两阶段推进，丙留作远期预留：**

1. **阶段一（方案甲）**：ANSI 彩色透传。独立可交付、低风险，先行止血；同时成为阶段二的整窗降级形态（解析失败时回退）。
2. **阶段二（方案乙）**：结构化列表替换文本区。图形列解析 git `--graph` 输出绘制，颜色同源（TERMINAL_PACK 映射）。
3. **远期（方案丙）**：仅当阶段二落地后仍对泳道平滑度不满、或出现 lane 级交互需求时再立项；届时以 theia-zen 单测为验收基准。

0110 原推荐「移植 theia-zen lane 算法」的前提是没有现成布局可用；实证发现 `git log --graph --color=always` 本身已输出**带 lane 配色的完整布局**，逐字符解析即可复用 git 布局引擎，避免维护数百行算法——故阶段二对 0110 路线做出此点修正（渲染载体仍为方案 A 的 QTreeView 委托自绘，不变）。

## 6. 设计要点（阶段二）

### 6.1 数据层：`core/git/log.py` 追加 `fetch_commit_rows()`

单条命令同时取回图形与元数据：

```bash
git log --graph --color=always --all -n 500 \
  --pretty=format:%x1f%h%x1f%s%x1f%an%x1f%ar%x1f%D%x1e
```

- format 串沿袭 0110 调研的 Multi_Cli_Studio 方案（`%x1f` 字段分隔 / `%x1e` 记录分隔）；行首 `%x1f` 是**图形前缀与元数据的分界锚点**——`--graph` 模式下前缀（图线字符 + ANSI 色码）在前、format 文本在后，首个 `%x1f` 即切分点，无需猜测前缀宽度
- 逐记录解析为：`graph_cells: list[(字符, 颜色名)]`（前缀逐字符 + SGR 颜色）、`hash/subject/author/rel_date/refs`
- 纯图线连接行（如合并后的 `|\` 行）：无 `%x1f` 锚点，解析为仅含 `graph_cells` 的连接记录
- `%D` 拆解：`HEAD -> main`、`tag: v1`、`origin/main` 分类为 HEAD/本地分支/标签/远程四型
- 解析失败（格式漂移）：整体返回 None，UI 回退阶段一形态（D3）
- `--all` / 500 上限 / 截断提示 / 空仓库归一 None：全部沿用 1507 语义

### 6.2 图形列委托

- 每行将 `graph_cells` 逐格绘制：`*`→实心圆点、`|`→竖线、`/ `\`→斜线、`-` `_`→横线、空格→空；颜色取 cells 携带的 ANSI 颜色名 → `TERMINAL_PACK` 当前主题色值
- 格宽 = 等宽字体字符宽（`get_mono_family()` 度量），列宽 = 最大前缀格数 × 格宽（每次 reload 重算）
- 连接行渲染为半高行（忠实 git 布局，零折叠算法；D5）
- 仅绘制直线图元，不做贝塞尔平滑（方案丙预留）

### 6.3 列表与分栏

- `QTreeView` 平铺（`setRootIsDecorated(False)`），列：图 | 提交 | 作者 | 时间
- 「提交」列内自绘：`hash`（muted 色）+ refs 徽标（圆角小胶囊：HEAD/分支/标签/远程四色）+ subject（UI 字体）
- refs 徽标与 hash 色新增 **`GIT_GRAPH_PACK` 主题配色包**（head/branch/tag/remote/hash_fg 五键 × 四主题），遵循 GIT_STATUS_PACK 先例与 `check_theme_tokens.py` 机器断言；图线色不新增键（复用 TERMINAL_PACK）
- HEAD 所在行 subject 加粗
- 截断提示为列表末尾一行（沿用 1507 语义）

### 6.4 对话框骨架沿用

非模态单例、showEvent + 刷新按钮两处拉取、降级占位、`_apply_font_size` 链字号跟随，全部不动；仅中部控件由 `QPlainTextEdit` 换为列表（阶段一过渡期为 `QTextBrowser`）。

**实施中发现与设计修正**：

1. **`splitlines()` 将 `\x1e`（RS）误判为行界**（设计未预见）：Python 的 `splitlines()` 把 FS/GS/RS 控制符也当行界，记录尾 `%x1e` 处多出空行——改用 `split("\n")`。
2. **git 对单 lane 线性段图线不输出颜色**（实证）：线性段 `*` `|` 为裸字符，解析为 None 键格，UI 映射 `terminal default_fg`（主题默认前景色）；多 lane 段图线才带 31–37 色码。
3. **`%D` 短路径无法区分本地/远程同名分支**：改用 `--decorate=full` 输出全路径（`refs/heads/`、`tag: refs/tags/`、`refs/remotes/`）精确分类；未识别形态宽容兜底为 branch 徽标（不构成格式漂移）。
4. **模型 `SizeHintRole` 的 `QSize(-1, h)` 污染表头列宽**（实证钳到 40px 致作者列省略）：`-1` 宽度被 `ResizeToContents` 采纳——行高改为三委托各自覆写 `sizeHint`（高度按行型、宽度保留内容宽），模型不再提供 SizeHintRole。
5. **`QHeaderView.stretchLastSection` 默认 True**：时间列被拉伸至与提交列同宽（实证 377px），挤压提交列致 subject 意外省略——显式关闭。
6. **模型重置后 `ResizeToContents` 列不自动重算**（作者列截断"fi…"）：`set_graph` 内显式 `header().resizeSections(ResizeToContents)` 后再定图形列宽。
7. **detached HEAD 重复徽标**：`HEAD` 直指提交与 `HEAD ->` 指针两路径均会补 HEAD 徽标，去重修正。
