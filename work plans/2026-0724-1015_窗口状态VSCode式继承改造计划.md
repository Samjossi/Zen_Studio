## 0. 目标语义（对齐 VS Code）

| 场景 | 现状 | 目标 |
|:--|:--|:--|
| 存储位置 | `config/window_state_<hash8>.json` 散落 config 根目录 | **统一收进 `config/window_state/` 子目录**（`<hash8>.json` + `default.json`），对齐 VS Code `workspaceStorage/` |
| 新工作区首次打开 | 硬编码默认布局 | **继承最近关闭窗口的布局**（全局 `default.json`） |
| 已知工作区重开 | 恢复自身哈希文件 ✅ | 恢复自身哈希文件（不变）✅ |
| 多开窗口各自关闭 | 各写各的哈希文件 ✅ | 各写各的哈希文件 **+ 双写 default**（后写胜 = 最后关闭窗口生效） |
| 工作区文件夹被删除/改名 | 哈希文件成孤儿，永不清理 | 启动时惰性清理（限时可裁剪，见 P3） |

非目标（明确不做）：

- **不做纯全局统一**——老工作区强制套用全局布局会洗掉用户按项目调好的
  分栏（如 `fruit_picker_2` 常开宽聊天面板），违背 2026-0722-0756 多开
  改造按工作区分文件的初衷；
- **不做键级合并**——哈希文件存在即全量采用，不做「缺失键从 default
  补齐」（语义复杂化，VS Code 亦不按键合并）。

### 1.2 差距

1. **存储散落根目录**：3 个 `window_state_<hash8>.json` 与 `settings.json`、
   `themes/` 等混居 `config/` 根目录，随工作区增多持续摊大饼；VS Code
   同类存储统一收在 `workspaceStorage/` 目录内，边界清晰；
2. **新工作区冷启动割裂**：`WindowStateStore.restore()` 在哈希文件缺失时
   直接落硬编码默认（`controllers.py:154-162`），用户刚在 A 项目调好的
   窗口尺寸/分栏，打开 B 项目全部归零；
3. **孤儿文件无治理**：文件夹删除/改名后哈希文件永不再被访问（哈希
   单向不可逆，无法从文件名反推归属），长期积累。

## 2. 方案

### P0 目录收纳与存量迁移（对齐 VS Code `workspaceStorage/`）

**目标布局**：

```
config/
├─ settings.json            （不动）
├─ recent_projects.json     （不动）
├─ themes/                  （不动）
└─ window_state/            （新增子目录，窗口状态唯一存放点）
   ├─ default.json          （P1 新增：全局继承源，仅布局 5 键）
   └─ <hash8>.json          （每工作区一个，现根目录存量整体迁入）
```

**`gui/window_state.py` 改动**：

- 新增常量 `WINDOW_STATE_DIR = CONFIG_DIR / "window_state"`；
- `window_state_file_for(workspace_root)` 返回路径改为
  `WINDOW_STATE_DIR / f"{digest}.json"`（文件名去 `window_state_` 前缀——
  目录名已表意，前缀冗余）；
- 新增 `migrate_state_dir() -> None`：一次性迁移，幂等，失败静默——
  1. `WINDOW_STATE_DIR.mkdir(exist_ok=True)`；
  2. 扫描 `config/window_state_*.json`（根目录存量），逐个 `os.replace`
     搬入子目录并去前缀改名（`window_state_06dff9ce.json` → `06dff9ce.json`）；
  3. 目标已存在时删根目录侧（后启动的新版本文件为准，防双写期分叉）。
- 调用点：`WindowStateStore.__init__` 中 `migrate_legacy_window_state`
  之前执行（先目录搬迁，后旧版单文件迁移直接落子目录，链路有序）。

**`.gitignore`**：`config/window_state*.json` → `config/window_state/`。

### P1 default 文件读写（核心，对齐 VS Code 继承语义）

**新增固定路径 `config/window_state/default.json`**，仅承载布局 5 键。

**`gui/window_state.py` 改动**：

- 新增常量 `DEFAULT_LAYOUT_FILE = WINDOW_STATE_DIR / "default.json"`；
- 新增 `load_layout_state(state_file: Path) -> WindowState`：
  哈希文件存在 → `load_window_state(state_file)`；
  不存在 → `load_window_state(DEFAULT_LAYOUT_FILE)`（缺失/损坏由既有
  防御链回退全默认）。文件级回退一处收口，调用方无感；
- 新增 `update_default_layout(patch: WindowStatePatch) -> None`：
  过滤 `patch` 至布局 5 键后走 `update_window_state(DEFAULT_LAYOUT_FILE, …)`
  （`recent_files` 等任何非布局键一律丢弃，防跨工作区泄漏）。

**`gui/controllers.py` 改动**（`WindowStateStore`，两处接线）：

- `restore()`：`load_window_state(self._state_file)` → `load_layout_state(self._state_file)`；
- `save()`：现有哈希文件回写后，追加 `update_default_layout(patch)`
  （同一 `_is_save_enabled` 守卫下；`splitter_chat` None 跳过语义随
  patch 天然继承）。

**多开并发语义**：所有窗口关闭时都双写 default，后写胜——等价于
「最后关闭的窗口」成为下一个新工作区的继承源，与 VS Code「最后活动
窗口」语义近似，可接受，无需加锁串行化（原子写已防截断）。

### P2 重置语义裁决 + 冒烟

**`reset_window_state` 行为裁决（需需求方确认）**：

| 选项 | 语义 | 倾向 |
|:--|:--|:--|
| A. 仅删本工作区哈希文件（现状） | 下次打开该工作区改为继承 default | ✅ 推荐：与 VS Code「忘记此工作区」语义一致；default 是其他窗口的真实布局，非脏数据 |
| B. 连 default 一并删 | 彻底回硬编码默认 | 过度——重置当前工作区不应波及全局继承源 |

**冒烟用例**（`.tmp/` 新增，验收标准）：

1. 目录迁移：构造根目录存量 `window_state_<hash8>.json` ×2 + 旧版单文件
   `window_state.json` → 启动后根目录清零，子目录内 `<hash8>.json` 齐全、
   内容逐字节一致；二次启动幂等（无文件移动、无报错）；
2. 新工作区冷启动：构造 `default.json`（已知几何）+ 无哈希文件 →
   恢复的几何/分栏与 default 一致；
3. 已知工作区优先：哈希文件与 default 几何不同 → 采用哈希文件
   （default 不覆盖工作区私有状态）；
4. 双写落盘：模拟关闭 → 哈希文件与 `default.json` 均含新几何；patch 混入
   `recent_files` 时 default 文件**不含**该键；
5. 损坏防御：`default.json` JSON 损坏/值越界 → 回退全默认，启动不崩；
6. 重置守卫：`disable_save()` 后关闭 → 两文件均无回写；
7. `splitter_chat` None：关闭时两文件该键均保留旧值不被洗。

### P3 孤儿清理（已裁决不实施，备查）

**前提**：哈希单向不可逆，需先在键空间扩 `KEY_WORKSPACE_ROOT`
（`WindowState` 第 7 键，值为明文工作区根路径；`_is_valid_value`
分流 str 判据）。存量 3 个哈希文件无此键——**无键文件永不删除**
（宁留勿错杀）。

**清理时机**：每次启动（`migrate_state_dir` 同点）扫描
`config/window_state/[0-9a-f]*.json`：

- 含 `workspace_root` 且路径已不存在 **且** 文件 mtime 超过 30 天 → 删；
- 其余一律保留（含无键旧文件、路径仍存在、近期活跃的孤儿——
  文件夹可能只是暂时移走）。

**裁剪判据（裁决结论：不实施）**：单文件 <1KB，百个孤儿 ≈100KB 无实际
危害，治理收益不抵键空间扩张成本（需扩 `workspace_root` 键 + 扫描逻辑 +
无键文件保护分支）。本节设计保留备查；未来孤儿积累成实际问题时再启用。
