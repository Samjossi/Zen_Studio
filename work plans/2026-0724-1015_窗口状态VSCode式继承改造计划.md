## 0. 目标语义（对齐 VS Code）

| 场景 | 现状 | 目标 |
|:--|:--|:--|
| 新工作区首次打开 | 硬编码默认布局 | **继承最近关闭窗口的布局**（全局 default 文件） |
| 已知工作区重开 | 恢复自身哈希文件 ✅ | 恢复自身哈希文件（不变）✅ |
| 多开窗口各自关闭 | 各写各的哈希文件 ✅ | 各写各的哈希文件 **+ 双写 default**（后写胜 = 最后关闭窗口生效） |
| 工作区文件夹被删除/改名 | 哈希文件成孤儿，永不清理 | 启动时惰性清理（限时可裁剪，见 P3） |

非目标（明确不做）：

- **不做纯全局统一**——老工作区强制套用全局布局会洗掉用户按项目调好的
  分栏（如 `fruit_picker_2` 常开宽聊天面板），违背 2026-0722-0756 多开
  改造按工作区分文件的初衷；
- **不做键级合并**——哈希文件存在即全量采用，不做「缺失键从 default
  补齐」（语义复杂化，VS Code 亦不按键合并）。

### 1.2 差距

1. **新工作区冷启动割裂**：`WindowStateStore.restore()` 在哈希文件缺失时
   直接落硬编码默认（`controllers.py:154-162`），用户刚在 A 项目调好的
   窗口尺寸/分栏，打开 B 项目全部归零；
2. **孤儿文件无治理**：文件夹删除/改名后哈希文件永不再被访问（哈希
   单向不可逆，无法从文件名反推归属），长期积累。

## 2. 方案

### P1 default 文件读写（核心，对齐 VS Code 继承语义）

**新增固定路径 `config/window_state_default.json`**，仅承载布局 5 键。

**`gui/window_state.py` 改动**：

- 新增常量 `DEFAULT_LAYOUT_FILE = CONFIG_DIR / "window_state_default.json"`；
- 新增 `load_layout_state(state_file: Path) -> WindowState`：
  哈希文件存在 → `load_window_state(state_file)`；
  不存在 → `load_window_state(DEFAULT_LAYOUT_FILE)`（缺失/损坏由既有
  防御链回退全默认）。文件级回退一处收口，调用方无感；
- 新增 `update_default_layout(patch: WindowStatePatch) -> None`：
  过滤 `patch` 至布局 5 键后走 `update_window_state(DEFAULT_LAYOUT_FILE, …)`
  （`recent_files` 等任何非布局键一律丢弃，防跨工作区泄漏）。

**`gui/controllers.py` 改动**（`WindowStateStore`，两处接线）：

- `restore()`：`load_window_state(self._state_file)` → `load_layout_state(self._state_file)`；
- `save()`：现有哈希文件回写后，追加 `update_default_layout(patch)`
  （同一 `_is_save_enabled` 守卫下；`splitter_chat` None 跳过语义随
  patch 天然继承）。

**多开并发语义**：所有窗口关闭时都双写 default，后写胜——等价于
「最后关闭的窗口」成为下一个新工作区的继承源，与 VS Code「最后活动
窗口」语义近似，可接受，无需加锁串行化（原子写已防截断）。

### P2 重置语义裁决 + 冒烟

**`reset_window_state` 行为裁决（需需求方确认）**：

| 选项 | 语义 | 倾向 |
|:--|:--|:--|
| A. 仅删本工作区哈希文件（现状） | 下次打开该工作区改为继承 default | ✅ 推荐：与 VS Code「忘记此工作区」语义一致；default 是其他窗口的真实布局，非脏数据 |
| B. 连 default 一并删 | 彻底回硬编码默认 | 过度——重置当前工作区不应波及全局继承源 |

**冒烟用例**（`.tmp/` 新增，验收标准）：

1. 新工作区冷启动：构造 default 文件（已知几何）+ 无哈希文件 →
   恢复的几何/分栏与 default 一致；
2. 已知工作区优先：哈希文件与 default 几何不同 → 采用哈希文件
   （default 不覆盖工作区私有状态）；
3. 双写落盘：模拟关闭 → 哈希文件与 default 均含新几何；patch 混入
   `recent_files` 时 default 文件**不含**该键；
4. 损坏防御：default 文件 JSON 损坏/值越界 → 回退全默认，启动不崩；
5. 重置守卫：`disable_save()` 后关闭 → 两文件均无回写；
6. `splitter_chat` None：关闭时两文件该键均保留旧值不被洗。

### P3 孤儿清理（可选，独立裁剪）

**前提**：哈希单向不可逆，需先在键空间扩 `KEY_WORKSPACE_ROOT`
（`WindowState` 第 7 键，值为明文工作区根路径；`_is_valid_value`
分流 str 判据）。存量 3 个哈希文件无此键——**无键文件永不删除**
（宁留勿错杀）。

**清理时机**：每次启动（`migrate_legacy_window_state` 同点）扫描
`config/window_state_[0-9a-f]*.json`：

- 含 `workspace_root` 且路径已不存在 **且** 文件 mtime 超过 30 天 → 删；
- 其余一律保留（含无键旧文件、路径仍存在、近期活跃的孤儿——
  文件夹可能只是暂时移走）。

**裁剪判据**：单文件 <1KB，百个孤儿 ≈100KB 无实际危害；若需求方
认为治理收益不抵键空间扩张成本，P3 整体不做，P1+P2 独立成立。
