## 1. 背景与目标

### 1.1 现状问题

| 问题 | 现状 |
|:---|:---|
| 三处重复 | AI 模型（菜单子菜单 / ModelBar / 设置中心模型页）、字体大小（菜单三动作 / 设置中心 SpinBox）、终端反转（菜单复选框 / 设置中心复选框）——同一设置多个入口，维护每处都要同步 |
| 菜单表达力枯竭 | 菜单勾选项只有"是/否"二态；权限四态已因塞不下菜单而迁出，未来更多枚举型/数值型/文本型设置同样无处安放 |
| 设置中心不可扩展 | 当前五页在 `__init__` 硬编码元组，新增设置页要改骨架代码；reload 逻辑五页混写一处，页数增多后必然臃肿 |

### 1.2 目标架构

```text
设置中心（唯一偏好配置面）◄── 菜单「设置中心…」（无快捷键）─┐
  ├─ 全部用户偏好（枚举/数值/文本/布尔统一承载）               │
原位控件（高频快捷通道，保留）── ModelBar、视图菜单面板显隐     │
菜单「设置」= 入口菜单（三项）────────────────────────────────┘
  ├─ 设置中心…（无快捷键，附加裁决）
  ├─ 打开配置文件（AI-first 落盘通道）
  └─ 恢复默认设置…（破坏性操作，带确认框）
```

| 项 | 现状 | 目标 |
|:---|:---|:---|
| 设置菜单 | 6 项（含 2 子菜单） | **3 项** |
| 偏好配置面 | 菜单 + ModelBar + 设置中心三通道 | 设置中心单通道（ModelBar 为原位快捷控件，非配置面） |
| 新增设置页成本 | 改 `__init__` 硬编码 + 改 `reload()` | 注册表加一行 + 写 build/reload 两个函数 |

## 2. 菜单简化设计（P0）

### 2.1 保留与移除

| 菜单项 | 处置 | 理由 |
|:---|:---|:---|
| 设置中心(&P)… | **保留**（**撤下 `Ctrl+,` 快捷键**，附加裁决） | 唯一配置面入口；快捷键位留给未来更高频操作 |
| 打开配置文件(&J) | **保留** | AI-first 落盘通道，快捷键可达不依赖对话框 |
| 恢复默认设置(&D)… | **保留** | 破坏性操作通行做法（带确认框），菜单直达 |
| AI 模型(&M) 子菜单 | **移除** | 三处重复中最弱通道（ModelBar 就在眼前，设置中心更完整） |
| 字体大小(&F) 子菜单 | **移除** | 设置中心 SpinBox 更直观；原项无快捷键，移除无快捷操作损失 |
| 终端：Ctrl+C/V 复选框 | **移除** | 设置中心终端页同一开关 |

### 2.2 连带清理（不做干净就是死代码）

| 位置 | 清理内容 |
|:---|:---|
| [`gui/menus/settings_menu.py`](../../gui/menus/settings_menu.py) | `ModelMenu` 类整体删除（约 85 行）；`build()` 返回值简化为 None；`BACKEND_ITEMS` 常量、相关 import 精简 |

### 2.3 不受影响的链路（明确不动）

- **ModelBar 原位控件保留**：聊天面板顶部双下拉是高频快捷通道，不是"菜单下拉框"，不在简化范围；`ChatTabs._on_selection_changed` 广播链路、`model_bar.set_busy` 均在 tabs.py 内部闭环，零影响
- **模型切换能力不丢**：`MainWindow.apply_model_selection` 收敛点保留（设置中心模型页走它）；`_on_modelbar_changed` 删除菜单 sync 分支后保留 `_sync_settings_dialog()`
- **视图菜单不动**：面板显隐 ×4、噪音过滤、恢复布局、Git 刷新、外观（主题）均为视图操作或高频原位项；主题双通道（视图菜单/设置中心）去留列备案评估，本轮不扩面

## 3. 设置中心扩展性重构（P1）：页面注册表

### 3.1 设计

```python
# gui/settings_dialog.py
#: 页面注册表：(导航名, 构建方法名, 重载方法名)；元组顺序即导航顺序。
#: 新增设置页 = 写 _build_xxx_page / _reload_xxx 两函数 + 此处加一行，
#: 骨架与 reload 分发零改动（AFCP 3.4 常量化；同 menus/assembler.MODULES 先例）
_PAGE_REGISTRY: tuple[tuple[str, str, str | None], ...] = (
    ("AI 工具权限", "_build_permission_page", "_reload_permission"),
    ("AI 模型", "_build_model_page", "_reload_model"),
    ("外观", "_build_appearance_page", "_reload_appearance"),
    ("终端", "_build_terminal_page", "_reload_terminal"),
    ("高级", "_build_advanced_page", None),
)
```

- `__init__` 遍历注册表装配导航 + 堆叠页（替换硬编码五页元组）
- `reload()` 遍历注册表调用各页 reload 方法（替换内联五页逻辑）；`_reloading` 标志与 try/finally 纪律不变
- 各页 reload 从 `reload()` 拆出为独立方法（`_reload_permission` / `_reload_appearance` / `_reload_terminal`，当前内联段平移，签名统一 `(settings) -> None`）
- **不预建分组**：页数 >8 再引入导航分组（注册表扩 category 字段即可，演进路径写明但不提前实现，防过度设计）

### 3.2 新增设置项的标准流程（写入 docstring，未来 AI/人遵循）

1. `settings.py` 加 `KEY_*` 常量 + `AppSettings` 键 + 默认值（7 键 → N 键，机制不变）
2. 选归宿页（或新页）：写 `_build_xxx_page`（控件 + change 接 MainWindow 应用槽或 `update_settings`）
3. 写 `_reload_xxx(settings)`（控件态回读，`_reloading` 抑制）
4. 注册表加一行——完

## 4. 候选迁移盘点（"尽可能多转移"的事实依据）

| 设置项 | 现状机制 | 处置 | 理由 |
|:---|:---|:---|:---|
| 噪音过滤 | 视图菜单勾选，**会话态不持久化**，`reset_settings` 重置为 True | **P2：持久化 + 入设置中心**（外观页增"文件树"小节，单键不立新页） | reset 都管它说明本质是用户偏好；当前重启丢失恰是缺陷；作为注册表机制的首个迁移验证项 |
| 面板显隐 ×4 | 视图菜单勾选，会话态 | 不进 | 布局操作非偏好（1240 计划 §2 已裁决，维持） |
| 窗口几何/分隔栏 | `window_state.py` 自动持久化 | 不进 | 无用户决策面（维持） |
| 字体族 | 固定自带思源黑体 | 不展示 | 登记键无 UI 意义（维持）；未来开放自选字体时直接进外观页（注册表机制收益点） |
| 主题 | 视图菜单 ▸ 外观 + 设置中心 双通道 | 本轮保留双通道 | 高频原位操作；去留列备案评估，不扩面 |
| 编辑/文件/终端/帮助菜单 | 操作类动作 | 不动 | 非用户偏好 |

## 9. 备案

1. 视图菜单 ▸ 外观（主题）通道去留评估：高频原位操作 vs 双通道维护成本，积累使用反馈后裁决
2. 页数 >8 时引入导航分组（注册表扩 category 字段）；页数 >10 重评设置搜索
3. 字号调整快捷键（如 Ctrl+=/Ctrl+-）：经全局 action + 设置中心外观页，非菜单
4. 字体族开放自选后进外观页（注册表机制首个自然收益点）
5. P2 模式验证后，后续新设置项一律走 §3.2 四步流程，禁止再向菜单直挂偏好项（写入 settings_menu.py docstring 作为纪律）
