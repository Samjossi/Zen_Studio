## 1. 背景与目标

Kimi provider 目前把 session_index 反查、wire 全量/增量读取、字节游标、轮次统计与速度计算、轮内用量轮询、轮末宽限和请求配对全部内联在一个文件里。任何一处格式变化都要在千行文件中定位，用量逻辑也无法独立测试。

本子计划目标：

1. 新建 `kimi/wire.py`，承接纯文件读取与统计计算。
2. 新建 `kimi/usage.py`，承接轮内/轮末用量状态与请求配对。
3. provider 只负责组合与生命周期；行为、数值口径、缺失处理与线程语义保持不变。

## 2. 启动条件与边界

- S0–S2 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S4。
- 只搬 wire 与 usage；**sidecar 仍留在 `provider.py`**，留给 S4。
- 纯搬家，不改帧解析、不改用量口径、不改日志文案、不改宽限值。
- 不 import provider、不 import Qt、不 import 其他厂商；不新增第三方依赖。
- 模块级状态改为实例状态；不得引入跨 provider/跨会话共享缓存。

## 3. 实施步骤

### S3.1 现状映射

1. 盘点 `provider.py` 中 wire 相关：`_session_dir_of`、`_read_wire_records`、`_is_turn_request`、`_usage_values`、`_context_size`、`_usage_stats`、`_read_wire_turn_stats`、`_read_wire_turn_metrics`。
2. 盘点用量相关：`_WireUsageState`、`_read_wire_usage_incremental`、`_reset_usage_poll_state`、`_drain_usage_updates`、`poll_usage`、`_collect_turn_end_usage`、`_ensure_context_sizes`、`_poll_session_dir`。
3. 标注每个函数的输入/输出、是否触碰连接对象、是否有模块级状态；区分「纯文件计算」与「需要 ACP 连接」的部分。
4. 记录迁移前基线：定向测试通过数、provider 行数、真实 wire 测试帧。

### S3.2 新建 `kimi/wire.py`

1. 迁入 session_index 反查、wire 全量读取、轮次请求统计、上下文用量与速度计算。
2. 提供清晰公开入口，例如：`session_dir_of(session_id)`、`read_records(session_dir)`、`read_turn_stats(session_dir, ...)`、`read_turn_metrics(session_dir, ...)`、`read_usage_incremental(cursor, ...)`。
3. 把模块级可变状态改为显式游标对象（记录路径、偏移、最后上下文水位），由 provider/usage 持有；模块函数不缓存跨调用数据。
4. 文件缺失、损坏、截断、空行、非法 JSON 的容错与现状一致；失败只记日志并返回空/None，不抛出。
5. 不 import provider；不 import Qt；不解析 ACP 帧。

### S3.3 新建 `kimi/usage.py`

1. 迁入轮内用量轮询状态、增量读取、轮末宽限内的用量收集、请求与响应配对、轮次消耗汇总。
2. 设计为按 provider 会话持有的 tracker 实例：构造时接收会话目录解析器与上下文窗口来源，方法接收当前连接对象，不反向 import provider。
3. `poll()` 保持廉价、幂等、线程安全：GUI 线程调用，与 chat 所在 worker 并发；不得抢正文/工具帧，不得在持锁时执行子进程或等待 ACP。
4. `collect_turn_end(...)` 保持现有请求配对、迟到帧宽限与去重语义；返回的 `UsageStats`/`TurnSpeed`/`TurnConsumption` 数值口径不变。
5. 会话重置/关闭时清空游标与请求配对状态；不保留跨会话数据。

### S3.4 provider 组合

1. `KimiAcpLLM.__init__` 创建 wire 游标与 usage tracker；`reset_session`/新建会话/`close` 时重置或清理。
2. `poll_usage()` 委托 tracker；轮末收集委托 tracker；provider 保留能力快照与恢复态判断。
3. 删除已搬走的实现；不保留同名包装 shim；必要时只保留一行转发。
4. 保持 `session/new`、`session/resume`、取消与断管路径的调用顺序不变。

## 5. 风险与注意点

- **并发**：`poll_usage` 从 GUI 线程调用，chat 在 worker 线程；游标与请求配对状态必须只由轻量锁保护，不能在持锁时做 I/O 子进程或等待 ACP。
- **文件截断**：wire 可能在轮内被重写/截断；游标越过文件尾时要安全回退，不能重复计数。
- **迟到写盘**：轮末 usage.record 可能晚于响应到达；宽限与重读逻辑必须原样保留，不能因为搬家缩短等待。
- **状态归属**：tracker 必须随会话重置；把状态放到模块级会重新引入跨实例污染。
- **范围**：sidecar 仍在 provider，本子计划不要顺手搬；DSH 会话日志留 S4。
