## 1. 背景与目标

Kimi provider 目前把 session_index 反查、wire 全量/增量读取、字节游标、轮次统计与速度计算、轮内用量轮询、轮末宽限和请求配对全部内联在一个文件里。任何一处格式变化都要在千行文件中定位，用量逻辑也无法独立测试。

本子计划目标：

1. 新建 `kimi/wire.py`，承接纯文件读取与统计计算。
2. 新建 `kimi/usage.py`，承接轮内/轮末用量状态与请求配对。
3. provider 只负责组合与生命周期；行为、数值口径、缺失处理与线程语义保持不变。

## 2. 启动条件与边界

- S0–S2 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S4。
- 只搬 wire 与 usage；**sidecar 仍留在 `provider.py`**，留给 S4。
- 纯搬家，不改帧解析、不改用量口径、不改日志文案、不改宽限值。
- 不 import provider、不 import Qt、不 import 其他厂商；不新增第三方依赖。
- 模块级状态改为实例状态；不得引入跨 provider/跨会话共享缓存。

### S3.3 新建 `kimi/usage.py`

## 5. 风险与注意点

- **并发**：`poll_usage` 从 GUI 线程调用，chat 在 worker 线程；游标与请求配对状态必须只由轻量锁保护，不能在持锁时做 I/O 子进程或等待 ACP。
- **文件截断**：wire 可能在轮内被重写/截断；游标越过文件尾时要安全回退，不能重复计数。
- **迟到写盘**：轮末 usage.record 可能晚于响应到达；宽限与重读逻辑必须原样保留，不能因为搬家缩短等待。
- **状态归属**：tracker 必须随会话重置；把状态放到模块级会重新引入跨实例污染。
- **范围**：sidecar 仍在 provider，本子计划不要顺手搬；DSH 会话日志留 S4。

## 6. 实施结果回写（2026-11-21 01:24 UTC+8）

S3 全部完成。以下为实施过程中相对原计划的偏差、验证结果与可复用经验。

### 6.1 与计划的偏差

1. **`usage.py` 的依赖边界按「不反向 import provider」落地，而非字面只依赖 wire/base**：tracker 还 import 公共 ACP 的 `TurnAborted`，用于空闲排空时清位上一轮 abort；连接对象以 `object` 接收，帧解释由 provider 传入 `map_update` 回调，因此不 import provider、KimiUpdateMapper、Qt 或其他厂商。上下文窗口来源按 §3.3.2 由 provider 构造时注入 `context_sizes_from_catalog(load_kimi_provider_catalog())`，`usage.py` 自身不依赖 catalog。
2. **轮末收集是「状态搬家 + IO 编排留在组合根」**：`_collect_turn_end_usage` 里驱动 ACP 帧与 sidecar 的生成器循环仍在 provider（sidecar 属 S4 范围），`TurnUsage` 承接基线、wire 完成度、push 优先级、宽限截止与轮末汇总；截止时间由 `start_collection()` 在 response 到达后开启，保持「最多再等 3s」的原口径。没有把整段生成器原样搬进 `usage.py`。
3. **`poll_usage` 只剩早退 + 一行委托**：`_poll_session_dir`、`_drain_usage_updates`、`_ensure_context_sizes` 与全部游标/退避/迟到 push 状态进入 `UsageTracker`；provider 不再保留同名包装或兼容 shim。
4. **测试桩目标被迫更新（计划未列出的隐藏改动点）**：`test_kimi_acp_turns.py`、`test_vendor_provider_lifecycle.py`、`test_provider_launch_contract.py` 原来补丁 `KimiAcpLLM._ensure_context_sizes`、`provider._session_dir_of`、`provider._read_wire_turn_stats`、`provider._WIRE_USAGE_WAIT_S`；现改为 `UsageTracker.ensure_context_sizes`、`wire.session_dir_of`、`wire.read_turn_stats`、`usage.WIRE_USAGE_WAIT_S`。语义不变，仅补丁落点随模块迁移。

### 6.3 经验沉淀

1. **纯搬家也要先跑「旧实现对照」**：测试全绿只能证明接口没断，不能证明数值没漂；从 git HEAD 载入旧函数做同 fixture 对比，能抓到 baseline、坏字段、游标回退这类测试不敏感的差异。
2. **状态与 IO 分开搬，比整段生成器搬家更稳**：轮末循环同时涉及 ACP 帧、sidecar、chunk 产出与截止时间，整段搬会迫使 usage 依赖 mapper/sidecar。把「基线、完成度、优先级、汇总」抽成 `TurnUsage`，循环留在组合根，边界更干净且保持逐帧顺序不变。
3. **测试补丁目标是拆分的隐性契约**：计划只写「保留既有测试」，实际必须改 monkeypatch 落点；拆分前先 grep 测试对私有名的引用，把它列进偏差，避免评审误以为改了行为。
4. **构造注入要绑定到「来源」而不是「模块」**：上下文窗口来源由 provider 注入后，usage 不再认识 catalog；`session_dir_of` 保持动态默认值，测试补丁模块函数即可生效，不会被构造期绑定冻结。
5. **日志 logger 名会随模块变，文案要逐字保留**：搬家时最容易顺手改文案；只让 logger 名变化、消息和参数顺序不动，才能用旧日志检索经验继续定位。
6. **并发 smoke 要模拟「锁已被 worker 持有」**：只开两个线程读写文件不足以覆盖 GUI 抢帧；让 worker 真正停在 `next_update`、再断言 response 仍在队列里，才能锁住 `turn_lock` 的保护语义。
