## 1. 背景与症状

用户从文件树拖动图片给 AI 看时，AI **能收到图片内容，但不知道图片的路径**。用户观点：图片本身和图片的路径同等重要——AI 若不知道路径，就无法用工具再次读取、比对或在回复中准确引用该图。

用户实证（真机截图）：AI 收到图片占位符后反问"请把图片保存到项目目录里，然后把路径发给我"——即图片到了、路径没到。

---

## 2. 参考项目调研结论（`参考代码/kilocode-main`）

### 2.1 附件数据结构

权威定义在 `参考代码/kilocode-main/packages/core/src/v1/session.ts`（FilePart / FilePartInput）：

```ts
# 参考代码/kilocode-main/packages/core/src/v1/session.ts
{
  type: "file",
  mime: string,
  filename?: string,
  url: string,                 // data:base64 URL 或 file:// 绝对路径 URL
  source?: {
    type: "file",
    path: string,              // ← 路径信息单独携带
    text: { value, start, end } // 文本中占位符的位置
  }
}
```

### 2.2 相对路径还是绝对路径

参考项目**两者都用，按场景区分**：

| 场景 | source.path | prompt 文本中 |
|:---|:---|:---|
| webview 拖入文件路径 → @mention | **相对路径**（工作区内） | 文本中插入 `@相对路径` |
| TUI 粘贴/拖入图片 | **绝对路径** | 文本中只有 `[Image N]` 虚拟占位符 |
| webview 直接拖图片二进制/粘贴截图 | 无路径 | 无 |

路径换算逻辑：绝对→相对在 `参考代码/kilocode-main/packages/kilo-vscode/webview-ui/src/utils/path-mentions.ts`（convertToMentionPath，工作区内转相对、区外保留绝对）；相对→绝对在 `file-mention-utils.ts`（拼工作区目录构造 file:// URL，含 isInsideWorkspace 安全校验）。

### 2.3 路径如何到达 LLM

**路径不随 file part 传给 LLM**。发给 LLM 的图片 part 只有 `{ type:"file", url:data URL, mediaType, filename }`。模型能看到路径只有两个途径：

1. prompt 文本中残留的 `@相对路径` mention 文本（webview 场景）；
2. 服务端读取 file:// 附件时合成的文本：`Called the Read tool with the following input: {"filePath":"<绝对路径>"}`（`参考代码/kilocode-main/packages/opencode/src/session/prompt.ts`）。

**结论**：参考项目的答案是——**图片内容走 base64，路径以文本形式拼进 prompt**；路径形式按"工作区内相对、工作区外绝对"换算，且在合成给模型看的文本里用的是**绝对路径**（确保模型工具可直接读取）。

## 3. 本项目现状与根因

### 3.1 现状链路

拖入图片：`gui/panels/chat/input.py` `_insert_file_reference` → 后端支持图片时走附件化（`image_attached(path, mime, False)`，**path 为源文件绝对路径，不复制**）→ `AttachmentStrip` → `gui/panels/chat/panel.py` 装配 `message["images"]` → `llm/providers/acp.py` `build_prompt_blocks` 转 base64 image 块发给 agent。

路径载体 `llm/base.py` ImageAttachment 中存的是**绝对路径**（拖入=源文件绝对路径；粘贴=项目内 `.tmp/pasted/` 落盘绝对路径）。

### 3.2 根因（唯一缺失环节）

`llm/providers/acp.py` `build_prompt_blocks` 构造 text 块时：

```python
# llm/providers/acp.py
text = message["content"] or ("请查看附图。" if images else "")
blocks = [{"type": "text", "text": text}]
```

**text 块只取用户原文，`images[*].path` 从未被拼入任何发往 agent 的字段**。`img["path"]` 仅用于 provider 层本地 `read_bytes()` 读盘，读完即弃。上游 `panel.py` 装配 message 时同样未附带路径。AI 收到的只有：用户原文 + 若干 `{type:"image", data:<base64>, mimeType}` 块。

---

## 4. 修复方案

### 4.1 路径形式决策

采用参考项目验证过的约定，并与本项目 AGENTS.md（项目内优先相对路径）一致：

| 图片位置 | 拼入 prompt 的路径形式 |
|:---|:---|
| 项目工作区内（含 `.tmp/pasted/` 粘贴图） | **相对路径**（posix 风格，如 `.tmp/pasted/pasted-20260806-190000.png`） |
| 项目工作区外（用户从外部目录拖入） | **绝对路径** |

理由：
- 项目内相对路径可读性好、commit/日志可移植，agent CLI 通常以项目根为 cwd，相对路径可直接解析；
- 项目外文件无相对意义，必须给绝对路径，否则 AI 无法定位；
- 换算逻辑复用 `gui/panels/chat/input.py` `_mention_text` 已有的"工作区内相对、区外绝对"规则，但协议层（acp.py）不能反向依赖 GUI——需将换算逻辑下沉为可共用的纯函数（见 T1 改动点 2）。

### 4.2 任务分解

#### T1：`build_prompt_blocks` 附带图片路径（核心修复）

**改动点 1 — 文本块附带路径**（`llm/providers/acp.py`）：构造 text 块时，把每张图的路径说明追加到文本尾部，仿参考项目的合成文本风格：

```python
# llm/providers/acp.py
lines = [text]
for i, img in enumerate(images, 1):
    lines.append(f"[附图 {i}] 图片路径：{display_path(img['path'])}")
blocks = [{"type": "text", "text": "\n".join(lines)}]
```

**改动点 2 — 路径换算函数下沉**：新增纯函数（建议放 `llm/base.py` 或 `core/paths.py` 附近），输入绝对路径，输出"工作区内相对 / 区外绝对"的显示路径。`gui/panels/chat/input.py` `_mention_text` 同步改为调用该函数（单一来源，防两处漂移）。

**改动点 3 — 文案防歧义**：路径行用明确中文标记（如"附图 N 路径"），避免与正文中的 `@路径` mention 混淆；不改变 image 块本身的 base64 内容。

#### T2：五 provider 冒烟验证

- mock/单元层：对 `build_prompt_blocks` 构造含 images 的 message，断言 text 块包含换算后的路径（项目内相对、项目外绝对两例）。
- 真机冒烟：用 kimi / kilocode 后端各拖入一张项目内图片 + 一张项目外图片，抓 session/prompt 出站帧存档 `.temp/`，确认 text 块含路径、image 块正常；再观察 AI 回复是否能正确引用路径。

### 4.3 不做的事

- 不改 GUI 附件 chip 的显示（附件条已有缩略图与文件名，路径透传是协议层职责）；
- 不把图片复制进项目目录（拖入场景保持"引用原路径不复制"现状）；
- 不改 @mention 退化链路（后端 supports_images=False 时路径本就以文本形式传给 AI，无此问题）。

## 5. 风险与验收

| 风险 | 缓解 |
|:---|:---|
| 路径文本被 AI 误认为需要读文件而多一次工具调用 | 可接受——这正是用户期望的行为（AI 知道路径后可按需使用） |
| `_mention_text` 下沉重构引入 GUI 回归 | 改动点 2 落地后跑输入框既有测试，@mention 行为保持逐字一致 |
| 各 provider chat() 均取末条 user 消息，历史轮次图片路径不带入 | 与现状一致，本期不扩大范围 |

**验收标准**：
1. 拖入项目内图片发送后，抓帧可见 text 块含相对路径（如 `.tmp/pasted/xxx.png`）；
2. 拖入项目外图片，text 块含绝对路径；
3. AI 回复中不再出现"请把路径发给我"式反问，能直接引用图片路径；
4. `input.py` @mention 退化行为无回归。
