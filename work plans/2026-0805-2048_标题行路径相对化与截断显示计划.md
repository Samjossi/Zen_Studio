# 标题行路径相对化与截断显示计划

## 1. 背景

打包版客户实机反馈：中栏（上）ViewerPanel 的**标题行信息太繁杂**。用户提供的
反馈截图实证：打开 `work plans/2026-0805-2003_移除摘要生成功能计划.md` 时，
标题行整行被完整绝对路径
`~/zen/工具脚本/AI_Video_Transcriber/work plans/...`
占满。

用户决策（2026-08-05 20:4x 对话确认，经两轮复述校准）：

1. **标题行所有显示路径的地方一律改为相对路径**（相对当前工作区根）；
2. **路径过长时做截断收敛**，不得占满整行（用户原话「不要那么夸张」）；
3. 覆盖范围：① 路径标签 `_path_label`；② B 类常驻提示（sticky hint）中
   内嵌的路径；
4. **标题行字号相对派生为「用户全局字号 − 4pt」**（2026-08-05 20:58 追加：
   用户确认标题行字体跟随全局字号可调后，要求标题行在当前调整字体上
   减 4 号，弱化其视觉权重）。

> 校准记录：用户第一轮口述为「绝对路径」，与现状（已是绝对路径）矛盾，
> 经复述确认为口误，真实需求为**相对路径**。本计划以相对路径为唯一准绳。

### 2.3 两个结构性事实（影响设计）

- **入参路径不保证绝对**：`open_file` 有三个信号源——文件树
  （`main_window.py` 193，绝对）、对话区文件引用链接（195，可能为相对
  工作区路径，0438 计划产物）、打开文件对话框（408）与设置文件（639，
  绝对）。相对化前必须先 `resolve()` 归一为绝对路径，否则 `relative_to`
  对相对入参会静默出错。
- **workspace_root 已在主窗口持有**：`MainWindow._workspace_root`
  （`main_window.py` 126，一进程绑定一工作区根），但 **未注入
  ViewerPanel**（175 行 `ViewerPanel()` 无参构造）——需新增注入通路。

### 2.4 标题行字体机制（2026-08-05 20:58 实证核对）

- **qss 未指定字号**：`assets/themes/base.qss` 45–53 行 `#PanelTitle` /
  `#PanelHint` 只定义字重（500）/颜色（muted_text）/padding，无
  `font-size`——标题行三个 QLabel（`_path_label`/`_git_badge`/`_hint_label`）
  字号**继承 app 全局字体**（`gui/theme.py` 538 行
  `app.setFont(QFont(BUNDLED_FAMILY, settings[KEY_FONT_SIZE]))`）；
- **全局字号用户可调**：`KEY_FONT_SIZE` 默认 10pt，范围 8–24pt
  （`main_window.py` 585–586 `FONT_SIZE_MIN/MAX`），设置对话框「外观」页
  经 `MainWindow.set_font_size → _apply_font_size`（588–605）收敛重刷；
  即**现状标题行字号 = 全局字号，等大**；
- **相对派生先例**：`settings_dialog.py` 103–106 行
  `_TITLE_FONT_DELTA_PT = 4`——设置中心页标题按「app 字号 + 4pt」
  相对派生，注释明确绝对值不可用的原因（全局 16pt 时 14pt 绝对标题
  反而比正文小）。本计划的「−4pt」是其镜像；
- **重刷链路两处缺口**：① `ViewerPanel.refresh_font()`（panel.py
  393–396）只刷查看器等宽字体与 Markdown 渲染页，**不刷标题行标签**；
  ② 启动时不走 `_apply_font_size`（全库仅 591 设置调整、671 恢复默认
  两个调用点），启动字号全靠 app 字体继承——故减 4 派生须在
  `__init__` 自初始化一次，不能只挂 refresh_font。

## 3. 设计决策

- **D1 相对基准**：`MainWindow._workspace_root`。构造参数注入
  `ViewerPanel(workspace_root=...)`（仅 main_window 一处实例化，改动最小）；
  缺省 `None` 时退化为现状（绝对路径），保证探针/测试直接实例化不受累。
- **D2 归一顺序**：入参 → `Path(path).resolve()` 绝对化（兼解 symlink、
  兼容相对入参，见 §2.3）→ `relative_to(workspace_root)` 相对化 →
  `ValueError`（工作区外文件）回退绝对路径。
- **D3 截断策略（字符级中间省略，保尾）**：显示文本超过约 60 字符时，
  保留尾部（文件名优先级高于目录链），头部目录链中间省略为
  `…/`，如 `工具脚本/…/2026-0805-2003_移除摘要生成功能计划.md`。
  取舍：放弃像素级 `QFontMetrics.elidedText` + resizeEvent 重算方案——
  相对化后路径已大幅缩短，截断仅为兜底；字符级确定性高、无布局依赖、
  探针可纯函数断言。
- **D4 悬停 tooltip 兜底全路径**：路径标签与 sticky 提示标签均挂
  `setToolTip(完整绝对路径)`，截断不丢信息，用户可悬停对照。
- **D5 单点格式化**：新增 `ViewerPanel._display_path(path) -> str`
  私有方法，收口「归一 → 相对化 → 截断」全部逻辑；§2.1/§2.2 所有上屏点
  一律调用，禁止散落重写（对齐 `core/paths.py` 收口纪律）。
- **D6 既有后缀不受影响**：`（已截断：超过 1 MB）` 在 `_display_path`
  输出之后追加，逻辑不变。
- **D7 标题行字号「全局字号 − 4pt」相对派生**（2026-08-05 20:58 追加）：
  新增模块级常量 `_TITLE_ROW_FONT_DELTA_PT = -4`（镜像
  `settings_dialog.py` 106 行 `_TITLE_FONT_DELTA_PT = 4` 先例，相对派生
  而非绝对值，随用户全局字号缩放）；三个标题行标签
  （`_path_label`/`_git_badge`/`_hint_label`）统一按
  `全局字号 + delta`（即严格 −4）显式 `setFont`；
  - **无地板严格 −4pt**（2026-08-05 21:04 用户定夺）：不设最小字号钳制，
    严格 `全局字号 − 4`。用户理由：默认 10pt 本身很小，客户拿到程序
    自然会调大全局字号，地板没有意义；
  - **重刷两点**：`refresh_font()`（挂 `_apply_font_size` 链，用户调字号
    时跟随）+ `__init__` 末尾自初始化一次（启动不走 `_apply_font_size`，
    见 §2.4）；字号来源 `load_settings()[KEY_FONT_SIZE]`（panel.py 已
    import `load_settings`，仅需增 `KEY_FONT_SIZE` 导入）；
  - **按钮组不缩小**：图片/PDF 按钮（QToolButton）维持 app 字号——按钮
    是点击目标，随标签缩小会同时缩小热区，可用性受损；仅三个文字标签
    派生缩小（用户「标题行」诉求落在信息文字上）。

## 5. 风险与取舍

- **R1 相对入参**：对话区链接可能发来相对路径，`resolve()` 归一解决
  （§2.3），即使入参恒绝对亦无副作用；
- **R2 frozen 打包态**：workspace_root 由启动参数注入、与 PROJECT_ROOT
  解耦，本计划不碰 `core/paths.py`，打包态行为与开发态一致——且打包客户
  的工作区根是用户自己的项目目录，相对化收益最大的正是该场景；
- **R3 symlink 出根**：工作区内 symlink 指向根外时 `resolve()` 后
  `relative_to` 失败回退绝对路径——可接受（提示真实性优先）；
- **R4 同名文件歧义**：保尾截断保证文件名始终可见，目录链省略后不同
  目录同名文件的标题行可能同形——tooltip 全路径兜底（D4）；
- **R5 设置文件页**：`main_window.py` 639 行打开 `config/settings.json`
  在多开场景下可能位于工作区根外 → 显示绝对路径，属 D2 既定回退行为，
  不特殊处理；
- **R6 字符级截断精度**：等宽字体下 60 字符宽度稳定，渲染页
  （QTextBrowser）字体不同但标题行标签用的是面板字体，60 字符上限
  对所有主题均显著短于截图中的失控整行，满足「不要那么夸张」目标；
- **R7 减 4pt 低字号端可读性（用户已定夺：无地板严格 −4）**：默认
  10pt → 6pt、最小 8pt → 4pt，低字号端标题行会很小——用户判断可接受：
  默认 10pt 本身很小，客户实机必然调大全局字号（如 14pt → 标题行
  10pt），地板钳制反而破坏「始终小 4pt」的恒定视觉层级。若日后反馈
  低字号端不可读，改 `_TITLE_ROW_FONT_DELTA_PT` 常量单点调整即可。

## 6. 验收标准

- 根内文件：标题行显示相对路径（如 `work plans/xxx.md`），不再出现
  `/home/...` 前缀；
- 根外文件：显示绝对路径但受 60 字符截断约束；
- 超长路径：中间省略、文件名始终可见、整行不占满；
- 三条 sticky 提示（文件不存在/已被删除/读取失败）内嵌路径同样相对化；
- 路径标签与提示标签悬停 tooltip 可见完整绝对路径/提示全文；
- 标题行三标签字号严格 = 全局字号 − 4pt（无地板）：默认 10pt 全局下
  显示 6pt，用户调全局字号后标题行随动且始终小 4pt；按钮组字号不变；
- 修前/修后截图成对存档 `.temp/shots/`，多模态核验通过；
- 冒烟断言新增用例全过、既有用例零回归、合规检查零新增违规。
