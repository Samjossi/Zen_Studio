# Git 树切换页提交拓扑图落地计划

> **状态**：草稿（待审阅）
> **范围**：右栏上 `FileExplorer` 的 Git 页、现有提交历史图视图与弹窗复用、紧凑泳道和合并曲线、刷新与字号接线、测试和 GUI 文档
> **时间**：2026-11-06 04:48（设计，UTC+8）
> **优先级**：中

## 1. 目标纠偏

本计划所称“Git 树”是**提交历史有向无环图（DAG）**，用于展示分支拓扑、提交泳道、分叉与合并关系，不是工作区变更文件目录树。

此前 `2026-1105-2317_Git树切换页变更目录树渲染方案选型.md` 与 `2026-1106-0421_Git树切换页变更目录树渲染落地计划.md` 将目标误定为变更文件目录树。该路线与右栏下“已变更”列表高度重合，本计划取代其实施方向；历史文档保留，不在本次删改。

目标分工：

- 右栏上 Git 页：以图形化提交历史回答“各分支从哪里来、在哪里分叉、在哪里合并”。
- 右栏下 `ChangesPanel`：继续以扁平完整路径列表回答“当前工作区有哪些文件变更”。
- 不再为上方 Git 页提供变更目录树或“目录树 / 列表”切换。

## 2. 需求

1. 点击文件树头部 `⇄` 后，原槽位切换为当前仓库提交拓扑图，再次点击返回文件树。
2. 图中显示提交节点、彩色分支泳道、分叉边、合并曲线、HEAD/本地分支/远程分支/标签徽标和提交主题。
3. 240px 窄面板下优先保证拓扑与提交主题可读；作者、时间和短 hash 收进 tooltip，不让完整弹窗的四列布局直接挤压图线。
4. 进入 Git 页时加载提交历史，页内提供手动刷新；页面隐藏时不增加常驻轮询或重复 Git 查询。
5. 保留现有空仓库、非仓库、解析失败降级、500 条上限、主题配色和字号跟随语义。
6. 右栏下 `ChangesPanel` 及 `ChangesList` 外观、数据与三路双击行为保持不变。
7. 本期只读浏览，不夹带 checkout、cherry-pick、revert、提交详情或工作区变更操作。

## 3. 现状与复用结论

### 3.1 已有完整提交图基础

- `src/core/git/log.py` 已通过 `git log --graph --color=always --all --decorate=full` 一次取回图线前缀、短 hash、主题、作者、相对/绝对时间和 refs；`CommitGraph` / `CommitRow` 已区分提交行与纯图线连接行。
- 泳道布局直接复用 Git 自身 `--graph` 引擎，无需移植 Theia lane 算法；`MAX_COUNT = 500`、截断提示和空仓库归一也已存在。
- `src/gui/git_graph_view.py` 已有 `QTreeView + QAbstractTableModel + QStyledItemDelegate`：图形列绘制节点与直线/斜线，提交列绘制 hash、refs 胶囊和主题，连接行半高，作者/时间独立成列。
- `src/gui/git_graph_dialog.py` 已有占位页、彩色富文本降级页和结构化视图页的三页栈，以及失败静默降级和缓存重渲染。
- `src/gui/main_window.py` 已有视图菜单打开非模态提交图弹窗及字号跟随链。

### 3.2 不能直接嵌入的部分

- 现有 `GitGraphView` 面向 860px 弹窗，作者和时间列会挤占 240px Git 页的拓扑与提交主题。
- `GraphColumnDelegate` 当前把 `/`、`\` 画成直线，需要升级为平滑曲线才能满足合并曲线的视觉目标。
- `GitGraphDialog` 把取数、三页降级和弹窗外壳组合在一起，若直接复制到面板会形成两套刷新与降级逻辑，应抽取共享内容控件。
- 当前 `FileExplorer` 第二页消费 `ChangeEntry` 工作区快照；改为提交图后不再接收该快照，也不应继续转发 M/U/D 文件信号。

## 4. 方案决策

### D1 复用 Git 布局与现有模型，不新写 DAG 算法

- 继续使用 `fetch_commit_rows()` 和 `CommitGraphModel`，以 Git 输出的图线格作为节点与边的位置来源。
- 不引入 WebEngine、Graphviz、QGraphicsView 全景画布或第三方 DAG 库。
- 不自行计算 parents/lane，不改变 `--all` 视野和 500 条上限。
- `src/core/git/log.py` 数据命令与解析规则原则上不改；只有新紧凑展示确实缺字段时才单独补充，不预先扩模型。

### D2 抽取共享提交图内容，弹窗与内嵌页共用

- 新增 `src/gui/git_graph_content.py`，将三页栈、结构化/富文本/占位切换、提交图加载、缓存、主题和字号重渲染从 `GitGraphDialog` 抽成 `GitGraphContent`。
- 内容控件接收 `GitStatusService` 的只读结论，支持 `set_service()`、`reload()`、`apply_theme()`、`refresh_font()` 和紧凑模式设置。
- `GitGraphDialog` 保留仓库/分支信息行、刷新按钮、非模态单例和菜单入口，内部组合共享内容；弹窗继续使用完整四列视图。
- 新增 `src/gui/panels/git_graph_panel.py`：无重复标题，仅保留紧凑刷新按钮和共享内容，内部视图启用紧凑模式。

### D3 紧凑模式：图线 + refs + 提交主题优先

为 `GitGraphView` 和提交列委托增加紧凑模式：

- 隐藏作者列、时间列和表头，仅保留图形列与提交列。
- 紧凑提交列不直接绘制短 hash；空间依次分配给必要 refs 徽标和提交主题，过长徽标与主题省略，HEAD 行继续加粗。
- 每行 tooltip 提供完整短 hash、主题、作者、相对/绝对时间和 refs，窄屏信息不丢失。
- 图形列按实际最大泳道格数定宽，提交列吃剩余空间；图线超宽时允许横向滚动，不压缩到无法辨认。
- 完整弹窗保持现有 hash + refs + 主题 + 作者 + 时间布局，不受紧凑模式影响。

### D4 分叉与合并曲线：只升级图元绘制

- `GraphColumnDelegate` 继续消费 `CommitRow.graph`，节点仍画实心圆，`|` 仍为竖线，`-` / `_` 仍为横线。
- 使用 `QPainterPath` 三次贝塞尔曲线替换 `/`、`\` 的直线段：端点严格落在原有格边界与行中心坐标，控制点沿纵向平滑过渡，跨提交行和半高连接行保持连续。
- 曲线颜色继续取每格携带的 ANSI lane 色，经 `TERMINAL_PACK` 映射；不新增主题色键。
- 保留半高连接行、行选中和现有格宽计算；未知图线字符仍安全忽略，不因新增绘制影响富文本降级。
- 通过真实“特性分支分叉后合回主干”的 fixture 截图验收，不以线性历史截图冒充合并曲线验证。

### D5 页面接线与刷新边界

- `FileExplorer` 第二页由 `ChangesList` 改为 `GitGraphPanel`；头部项目名、分支名和 `⇄` 按钮保持现有位置与行为。
- `FileExplorer.apply_git_status()` 将共享 `GitStatusService` 注入提交图面板；非 Git 环境继续隐藏切换按钮并强制回文件树。
- 提交图在每次由文件树切入 Git 页时加载一次，页内刷新按钮可重拉；`showEvent` 与显式刷新统一汇入 `reload()`，避免双路径漂移。
- 页面隐藏时，`GitStatusController.refresh()` 只更新服务可用性，不拉取提交历史；不为提交图加入文件系统 watcher、定时器或 300ms 去抖刷新链。
- 删除 `FileExplorer.apply_git_changes()` 及控制器向上方页面扇出 `ChangeEntry` 的调用；下方 `ChangesPanel` 仍消费同一次 `collect_changes()`。
- 移除 `FileExplorer` 不再使用的 `diff_opened` / `deleted_activated` 及控制器连接；`file_opened` 和原文件树查看器接线不变。
- 视图菜单“提交历史图”继续打开完整弹窗，作为内嵌窄视图的大图补充，不在本期删除。

### D6 状态、主题与字号

- 提交图刷新前记录选中提交 hash 与垂直滚动值，模型重置后在仍存在提交中恢复；已消失提交自然取消选中，滚动值由范围钳制。
- 切换文件树/Git 页不重建 `QFileSystemModel`，原文件树展开、选中、搜索和悬浮按钮行为不变。
- 主题重渲染只使用缓存 `CommitGraph` / 富文本，不额外执行 Git；热主题切换仍遵循主窗口现有“重启生效”策略，不恢复已移除的全局热链。
- `MainWindow._apply_font_size()` 追加内嵌提交图 `refresh_font()`，完整弹窗既有调用保留；等宽格宽随字号重新计算。

- 下方“已变更”仍只显示工作区文件，双击 M/U/D 行为不变。
