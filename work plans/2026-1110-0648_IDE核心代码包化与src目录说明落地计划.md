# IDE 核心代码包化与 src 目录说明落地计划

> **状态**：已实施
> **范围**：`src/core/`、`src/gui/`、`src/llm/` 迁入 `src/ide/`，相关导入与路径锚点适配，新增 `src/README.md`，同步现行文档、测试与打包验证
> **时间**：2026-11-10 06:48（设计，UTC+8）/ 2026-11-10 07:08（实施）
> **优先级**：中

## 1. 背景与目标

当前 IDE 自有代码以 `core/`、`gui/`、`llm/` 三个顶层包直接放在 `src/` 下，与内置第三方包 `markdown_it/`、`mdurl/` 平级。该结构可以运行，但“IDE 产品本体”的目录边界不够直观；后续把项目交给他人做增量开发时，新模块容易继续散入现有包中。

本次借鉴“IDE 核心包与增量业务模块平级”的组织方式，只整理代码归属，不引入对方的量化功能。目标如下：

1. 将 IDE 自有代码统一收纳到 `src/ide/`，形成明确的产品本体边界。
2. 保留 `core`、`gui`、`llm` 的既有内部划分和依赖方向，不借目录迁移做功能重构。
3. 新增 `src/README.md`，说明源码根、各包职责、第三方包边界和未来模块扩展位置。
4. 保持项目为纯 IDE；不创建 `quant/` 或其他空占位模块。
5. 开发态、测试、辅助脚本和 PyInstaller 打包在迁移后均保持原有行为。

## 2. 现状与牵连面

### 2.1 当前结构与导入方式

当前结构为：

```text
# src/
src/
├── core/
├── gui/
├── llm/
├── markdown_it/
└── mdurl/
```

`main.py`、`tests/conftest.py` 和辅助脚本已经把项目根下的 `src/` 加入模块搜索路径。现有 IDE 代码主要使用 `core.*`、`gui.*`、`llm.*` 绝对导入；迁移后须统一改为 `ide.core.*`、`ide.gui.*`、`ide.llm.*`，不能只移动目录而保留旧导入。

当前全库导入检索覆盖运行时代码、测试和脚本，属于批量机械适配，而非三个目录自身的小改动。实施前仍须重新生成完整触点清单，避免以本次快照替代落地时审计。

### 2.2 已确认的关键锚点

- `main.py`：六根 IDE 导入改为 `ide.core` / `ide.gui`；现有 `src/` 引导保留，根入口位置不变。
- `src/core/paths.py`：开发态项目根当前依赖文件位于 `src/core/` 的层级；迁入 `src/ide/core/` 后，`PROJECT_ROOT` 的 `parents[N]` 必须增加一级，并同步注释。冻结态 `sys._MEIPASS` 分支不变。
- `tests/conftest.py`：仍向模块搜索路径加入 `src/`，路径本身不变；各测试中的 IDE 导入改为新包名。
- `building/zen-studio.spec`：`pathex` 继续指向 `src/`，入口与资源 `datas` 不变；其中 `core/version.py`、`gui/theme.py` 等现行路径说明改为 `ide/core/...`、`ide/gui/...`。
- `pyproject.toml`：`src/markdown_it`、`src/mdurl` 的 ruff 排除项不变，不为 `ide/` 增加豁免。
- `scripts/check_label_selectable_guard.py`、`scripts/check_qss_selector_guard.py`：检查目标仍是被迁移的 GUI 代码，扫描路径和导入须改为 `src/ide/gui/...` 或新包名。
- `scripts/` 下截图与探针脚本：现有 `src/` 搜索路径引导保留，IDE 导入改为新包名；展示用 mock 数据中的 `gui/...`、`llm/...` 路径也须同步，避免继续给出旧位置。
- 子进程或 fixture 若通过 `PYTHONPATH=src` 导入 IDE 包，仅更新导入名，不改变其项目根、临时目录或配置目录锚点。

### 2.3 文档牵连

- 新增 `src/README.md` 作为源码布局与扩展边界的首要说明。
- `src/core/README.md`、`src/gui/README.md`、`src/llm/README.md` 随目录移动保留，更新包名、跨包引用和使用示例；文件表内仍正确的包内相对路径不机械加前缀。
- 根 `README.md`、`术语表.md`、`building/README.md`、`维护手册/`、`dream-acp/` 等现行文档若引用旧源码路径，须按实际消费关系更新。
- 历史计划、修改记录和选型文档记录当时事实，不做批量追改。

## 3. 目标结构与方案决策

### 3.1 目标结构

```text
# src/
src/
├── README.md
├── ide/
│   ├── __init__.py
│   ├── core/
│   ├── gui/
│   └── llm/
├── markdown_it/
└── mdurl/
```

`quant/` 仅是外部增量示例，不属于本项目目标结构。未来确有新业务模块实施时，再在 `src/` 下建立与 `ide/` 平级的真实包。

### D1 建立唯一的 `ide` 包，不保留旧顶层包兼容壳

- 将 `src/core/`、`src/gui/`、`src/llm/` 原样移动到 `src/ide/` 下，再统一修正导入。
- 新增轻量 `src/ide/__init__.py` 作为包标记；不急切导入 GUI 或 LLM，不借迁移新增公共门面和循环依赖。
- 不保留 `src/core/`、`src/gui/`、`src/llm/` 的转发模块，也不在 `sys.modules` 注册旧名别名。项目内消费方一次性切到新名，避免形成两套长期入口。
- `markdown_it`、`mdurl` 继续作为 `src/` 下的独立第三方包，导入名与内容均不变。

### D2 只做命名空间和目录边界调整

- 不改 `core` 的零 Qt 约束，不改 `gui → llm`、`gui/llm → core` 的既有依赖方向。
- 不调整类、函数、配置格式、资源内容、后端协议或界面行为；除导入、路径锚点和说明文字外，不做顺手优化。
- 本次形成的是源码组织边界，不宣称已经提供稳定的插件 API 或第三方扩展 SDK。外部增量如何调用 IDE 能力，仍须在具体模块实施时明确设计。

### D3 `src/README.md` 同时服务维护者与外部增量开发者

README 至少包含：

1. `src/` 是源码模块搜索根，不是需要导入的业务包；项目代码经 `ide.*` 导入。
2. 目标目录树及 `ide/core`、`ide/gui`、`ide/llm` 的职责与依赖方向。
3. `markdown_it`、`mdurl` 是内置第三方包，保持原样，不属于 IDE 自有代码。
4. 当前项目仍是纯 IDE，不存在量化模块，也不预留空 `quant/` 目录。
5. 新独立业务模块优先放在 `src/<模块名>/`，与 `ide/` 平级；只有确属 IDE 本体的代码才进入 `src/ide/`。
6. 简短的开发态导入示例，以及修改布局后须检查导入、路径锚点、测试和打包的提醒。

### D4 只同步现行事实文档

- 现行 README、模块说明、维护手册和协议真值引用使用新路径。
- 历史文档中的 `src/core/...`、`src/gui/...`、`src/llm/...` 保留，不为追求全库零命中而改写历史。
- 旧导入清零的自动检查范围限定为运行时代码、测试、脚本和现行配置；文档残留按 D4 人工区分。

## 4. 实施步骤

### T1 迁移前盘点与基线

1. 运行一次完整 `bash scripts/check.sh`，记录迁移前基线；若已有失败，先确认与本次无关，不把红门禁当作迁移后结果接受。
2. 全量检索 `core`、`gui`、`llm` 的导入、字符串模块名、文件路径、`parents[N]`、`PYTHONPATH` 和子进程调用，形成实际触点清单。
3. 将新发现且本次必须处理的触点补入本计划，再开始移动；重点排查仅靠 import 检索无法发现的守卫路径、mock 路径和动态导入。
4. 临时盘点或验证产物只放 `.temp/`。

### T2 建立 `ide` 包并移动 IDE 自有代码

1. 新建 `src/ide/__init__.py`，保持轻量。
2. 移动 `src/core/`、`src/gui/`、`src/llm/` 至 `src/ide/`，保留各包内部文件和 `__init__.py`。
3. 不移动或修改 `src/markdown_it/`、`src/mdurl/`，不创建任何新业务占位目录。
4. 检查移动结果，确认 `src/` 下不再存在旧的三个 IDE 顶层目录。

### T3 批量适配导入与运行锚点

1. 将运行时代码、`main.py`、测试和脚本中的 IDE 绝对导入统一改为 `ide.core.*`、`ide.gui.*`、`ide.llm.*`。
2. 保持 `main.py`、`tests/conftest.py` 和辅助脚本的 `src/` 模块搜索路径引导不变。
3. 将 `src/ide/core/paths.py` 的开发态项目根推导增加一级，并验证 `PROJECT_ROOT`、`ASSETS_DIR`、`USER_CONFIG_DIR` 等常量仍指向原位置。
4. 更新守卫脚本扫描目录、截图 mock 路径和其他现行字符串路径；冻结态分支、资源目录和打包入口不做无依据改动。

### T4 编写源码说明并同步现行文档

1. 按 D3 新建 `src/README.md`。
2. 更新迁移后的三个模块 README，尤其是 `ide.llm` 使用示例、跨包路径和依赖方向表述。
3. 更新根 README、术语表、构建说明、维护手册和活协议文档中的实际旧路径引用。
4. 检查本次触及文件的注释与 docstring，确保不再声称 IDE 包直接位于 `src/` 根下，也不把目录整理描述成插件机制。

### T5 分层验证与完整交付检查

1. 先执行纯 Python 导入和路径冒烟，再运行 GUI 测试，尽早区分包名错误与路径层级错误。
2. 运行全部现有测试，不新增仅用于断言目录存在的测试；既有用例只做必要导入和路径适配，原功能断言不得削弱。
3. 使用现有 offscreen 启动/截图方式实际启动主窗口，确认识别配置、主题、主面板与资源加载正常，而非只验证模块可导入。
4. 运行完整 `bash scripts/check.sh`，隐私扫描、守卫、ruff 和测试必须全部通过。
5. 执行标准 AppImage 构建并启动打包产物做冒烟验证，确认真 frozen 导入链、版本文件、字体、主题和提示音路径无回归。
