# 开源前 Git 历史净化与双轨发布实施计划

## 1. 目标

1. **历史净化**：全历史 356 个提交的 author/committer 邮箱 `<原个人邮箱>` 替换为公开身份邮箱；全部文件内容中的内网 IP `<NAS内网地址>` 替换为占位符。提交信息正文、提交时间、树结构一律不动。
2. **原始历史存档**：净化前的原始历史推 Forgejo `archive/pre-oss` 分支永久保留（内网私有），本机另留 bundle 备份。

**非目标**：不改写提交信息正文（审查已实证正文零邮箱零密钥，见 §2）；不 squash 历史；不动 `参考代码/` 第三方快照内容（其许可证原文中的第三方邮箱属合规保留）；不做 GitHub 仓库设置类操作（协作者/Pages/Action 等）；不处理 GitHub 账户级邮箱关联（账户注册邮箱与本计划无关）。

## 6. 风险与回滚

| 风险 | 应对 |
|:---|:---|
| 净化不可逆 | 双备份（bundle + Forgejo archive 分支）先行；任何一步失败可整体回退 |
| 净化中误伤文件内容 | `--replace-text` 仅一条精确 IP 规则；CP2 抽查 diff 逐字节核对兜底 |
| 邮箱回调拼错 | CP2 扫描断言旧邮箱零命中 + 新邮箱恰 712 处（356×2） |
| 操作窗口混入新提交 | T0 起暂停日常提交，CP0/CP3 各查一次 `git status` |
| GitHub 删库误操作 | D3-a 的删库动作由用户在网页端亲手执行，AI 不代办 |

**回滚预案**：任意检查点失败——工作仓库 `git reset --hard <原始main哈希>`（哈希自 bundle 取回），Forgejo main 从 `archive/pre-oss` force push 还原，GitHub 侧未动则无需处理。
