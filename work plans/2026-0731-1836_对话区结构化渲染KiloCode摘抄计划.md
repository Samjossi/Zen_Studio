# 对话区结构化渲染 KiloCode 摘抄计划

## 1. 渲染归属结论（先答后摘）

**对话栏全部由 Kilo Code 自己渲染，VS Code 只提供容器。** 证据链：

1. 扩展架构（`packages/kilo-vscode/AGENTS.md` 自述）：侧边栏聊天是
   `KiloProvider` 创建的 **webview**（iframe 壳），VS Code 原生侧仅有
   `src/KiloProvider.ts` 负责消息桥接与 HTML 骨架注入；
2. webview 内部是完整 SolidJS 应用（`webview-ui/src/index.tsx` 入口，
   esbuild IIFE 打包），组件树为 `ChatView → MessageList →
   AssistantMessage / VscodeUserMessage → kilo-ui Part 组件`；
3. 全部视觉元素（气泡、折叠、工具卡、代码块、按钮）来自共享组件库
   `packages/kilo-ui/`（118 个组件文件）+ `webview-ui/src/styles/`
   24 个 CSS 文件，VS Code 主题变量仅作配色桥接。

**推论**：截图里的一切结构化渲染效果都能在 `参考代码/kilocode-main`
内找到完整实现，**不需要 VS Code 源码**。本计划按「摘抄什么、怎么摘」
展开。

## 3. 可摘性分级（核心判断：载体约束）

本仓对话区载体是 **QTextBrowser**（Qt 富文本子集：支持 CSS 部分属性、
表格、背景色、超链接锚点；不支持交互折叠/嵌套 widget/JS）。摘抄按
「载体可达性」分三级：

### L1 纯逻辑直译（与载体无关，代码可直接翻 Python）✅ 最优先

| # | 摘抄项 | 出处 | 移植形态 |
|---|---|---|---|
| L1-1 | **reasoning 一句话标题提取** | `reasoning-heading.ts`（49 行） | 正则规则直译 Python `re`，约 40 行；用于推理块标题行（现状纯灰斜体无标题） |
| L1-2 | **bash 输出预处理**（ANSI 剥离 + `\r` 帧折叠） | `shell-rolling-results.tsx` 思路（1425 封存款 §5.3 已预判约 20 行 Python） | 协议层单点预处理，进 tool_update payload 前净化 |
| L1-3 | **流式节流重渲** | `createThrottledValue` | ChatOutput 流式 append 已逐 chunk 上屏，加 30~50ms 合帧节流（QTimer）防高频小帧刷屏 |
| L1-4 | **开合状态记忆键规则**（tool/callID/partID 组键 + LRU） | `tool-open-state.ts` | 若 L3 折叠落地时配套；L1 阶段仅记录设计 |
| L1-5 | **时间线条块几何/配色/命中** | `utils/timeline/` 四模块 | **已由 1824 计划覆盖**，本文档不重复 |

### L2 QTextBrowser HTML 子集可达的样式规格（摘设计不摘代码）🟡 次优先

| # | 摘抄项 | QTextBrowser 落地形态 |
|---|---|---|
| L2-1 | **用户消息气泡**（灰底圆角卡） | `<table>` 单格 + bgcolor + 边距模拟气泡（Qt 富文本经典技法）；圆角不可达，直角卡观感可接受 |
| L2-2 | **工具行标题骨架**（图标+动词+参数摘要+状态色） | 1602 已落地纯文本版（`◐ ▸ title — summary`）；可升级为 L1-1 同款「动词加粗 + 摘要灰」双格式混排（QTextCharFormat 分段着色，无需 HTML） |
| L2-3 | **bash 工具卡**（`$ 命令` 头 + 输出体等宽字体块） | 完成态工具行下追加等宽字体缩进块（QTextCharFormat 设 fontFamily + 背景画刷），头部 `$ ` 前缀；行数上限 + 「…共 N 行」尾注（1425 K6 降级规格） |
| L2-4 | **复制按钮** | QTextBrowser 不支持块内按钮；降级为**轮次级**——输出区右键菜单/工具条「复制本轮回复」（clipboard 直给）；块级复制需换载体（归 L3 不做） |
| L2-5 | **文件路径可点击** | 渲染 text 时用正则把 `` `path:line` `` 片段转 `<a href="file://path#Lxx">`，QTextBrowser `anchorClicked` 信号拦截跳编辑器查看器（本仓已有文件打开管线，接线即可） |
| L2-6 | **推理块标题行 + 分隔空行** | L1-1 提取的标题加粗一行 + 正文维持灰斜体；视觉层级即刻提升，零交互依赖 |

### L3 需换载体才可达（本期不做，记录备查）❌

> ⚠️ **重要提醒：L3 不是增量路径的「下一步」。** L1→L2 是按载体可达性
> 排序的增量序列，每步独立可验证、不回退前步；但 L3 是被架构决策
> （D2 坚守 QTextBrowser）**排除的另一条路线**，不是难度递增的第三级。
> L1、L2 全部完成后若要 L3，必须单独做载体迁移（QTextBrowser →
> QScrollArea+widget 或 QWebEngine）的立项评估，**严禁顺着增量惯性
> 滑入载体重构**。

| # | 项 | 障碍 |
|---|---|---|
| L3-1 | 推理/工具卡**交互折叠**（三态状态机 + 自动收起） | QTextBrowser 无块级显隐交互；需迁移 QScrollArea + 每消息独立 QWidget——对话区载体整体重构，工作量与风险远超收益，单独立项再议 |
| L3-2 | 块级 hover 操作按钮（复制/删除/分叉/回退） | 同上，需 widget 载体 |
| L3-3 | diff 着色卡（Pierre 级） | 1425 封存款已判不可迁移，降级逐行着色亦属 L2 范围外，维持封存 |
| L3-4 | Markdown 完整渲染（表格/任务列表/嵌套引用） | QTextBrowser HTML 子集有限；现状纯文本流 + 轻量格式已够用，全量 Markdown 需换 QWebEngine 或自绘，不换 |
