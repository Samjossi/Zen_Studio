# Kimi K3-256k 新模型接入计划

## 1. 背景与目标

Kimi Code 官方于 2026-07-24/25 发布新模型 **`k3-256k`**（Kimi K3 的 256K 上下文版本）。官方规格（https://www.kimi.com/code/docs/kimi-code/models）：

| 项 | `k3-256k` | 对比 `k3`（1M） |
|:---|:---|:---|
| 模型版本 | Kimi K3 | Kimi K3 |
| 上下文窗口 | 固定 256K | 最高 1M（Allegretto 以上） |
| 额度消耗 | **基准**（同模式约为 k3 的一半） | 约为 k3-256k 两倍 |
| 思考程度 | `low`/`high`/`max`（默认 `high`） | 同左 |
| 多模态 | **仅图片**（不支持视频） | 图片、视频 |
| 调用门槛 | Moderato 及以上 | Moderato 可调，Allegretto 以上才有 1M |

官方定位：**日常问答、代码补全、常规功能开发、单文件或少量文件修改用 `k3-256k`**（约 90% 线上请求上下文未超 256K）；大型代码库分析、多文件重构、超长文档才用 `k3`（1M）。

本期目标：

- IDE 模型版本列表出现 `kimi-code/k3-256k` 并可正常对话；
- 按用户拍板决定是否将其设为日常默认（省一半额度）；
- 同步官方「切换模型」注意事项到 IDE 行为或文档。

## 2. 可行性取证

### 2.1 IDE 侧：模型列表全动态，代码零改动

- `llm/providers/kimi_cli.py::list_kimi_models()` 经子进程 `kimi provider list --json` 解析，返回 `sorted(models.keys())`——**无任何硬编码模型名**（全仓 grep `kimi-code/k3` / `kimi-for-coding` 于 `*.py` 零命中）。
- 消费方均为动态渲染：底行 `ModelBar._refresh_versions`（`gui/panels/chat/model_bar.py:167`）与设置中心模型页（`gui/settings_dialog.py:463`）直接遍历该列表。
- 默认版本持久化值为 `None`（`gui/settings.py:100`）= 跟随 CLI `default_model`；用户当前持久化选择 `config/settings.json` 为 `kimi-code/k3`。
- **结论：CLI 一旦列出新模型，IDE 双入口（底行版本菜单 / 设置中心版本下拉）自动出现第四项，无需改代码。**

### 2.2 环境侧：当前 CLI 尚未列出 k3-256k

- 本机 kimi CLI **0.27.0**（`~/.kimi-code/bin/kimi`），`provider list --json` 仅 3 项（`kimi-for-coding` / `-highspeed` / `k3`）；模型目录落盘于 `~/.kimi-code/config.toml` 的 `[models.*]` 段。
- 更新通道已有 **0.28.1**（2026-07-20 发布，30% 灰度，`~/.kimi-code/updates/latest.json`），CLI 自带 `kimi upgrade` 命令。
- 官方文档明示：「列表里暂未出现最新模型时，`/logout` 后重新 `/login` 即可」——模型目录为**服务端下发、登录时刷新**。
- 兜底路径：手动向 `~/.kimi-code/config.toml` 追加 `[models."kimi-code/k3-256k"]` 段（字段仿照 k3：`model = "k3-256k"`、`max_context_size = 262144`、capabilities 去 `video_in`、`support_efforts = ["low","high","max"]`、`default_effort = "high"`）。⚠️ 该文件在 CLI 重登录/升级时可能被服务端目录覆盖重写，手动补丁属临时手段。

### 2.3 官方切换注意事项（影响 IDE 语义设计）

1. **切模型缓存失效**：切换 model id 后已建立的上下文 cache 不命中，需重新 prefill，刚切换时消耗偏高——官方建议**开新会话再切**。
2. **k3（1M）→ k3-256k**：会话上下文超 256K 时，CLI 侧会直接 compact；含**视频**的历史切换将报错，须先 compact。
3. **k3-256k → k3（1M）**：可直接切，不影响缓存。
4. IDE 现状：`KimiCliLLM.set_model()` 仅改别名，**保留 `_session_id` 续接**——即切换版本后下一条请求仍带 `-S session_id` 续旧会话，与官方「开新会话再切」建议相悖。
5. IDE 目前**无图片/视频附件能力**（gui 下 grep `video|attach|image_in` 零命中），故「k3-256k 不支持视频」对 IDE 无实际影响，仅需文档注明。

## 3. 架构关键决策（D2/D3 待用户拍板）

| 编号 | 决策 | 理由 |
|:---|:---|:---|
| D1 | 环境前置走「升级 + 重登录」组合：`kimi upgrade` 至 0.28.1+ → 重登录刷新服务端模型目录 → 验证 `provider list --json` 出现 `kimi-code/k3-256k`；不采用手动补丁 config.toml（会被覆盖） | 官方推荐路径，结果持久 |
| D2 | **默认模型是否切到 `kimi-code/k3-256k`**：a) 改——`config/settings.json` 持久化值与 CLI `default_model` 均切 k3-256k（日常省一半额度，官方推荐）；b) 不改——保持 k3，用户按需手动切 | 省额度 vs 保留 1M/视频能力的取舍，用户拍板 |
| D3 | **切换版本时的会话语义**：a) 维持现状（保留 session 续接，CLI 侧自行 compact）；b) 切换版本时 `reset_session()` 开新会话（契合官方建议，避免缓存失效浪费，但丢失会话连续性）；c) 现状 + 文档提示 | 官方建议与 IDE 续接语义冲突，用户拍板 |
| D4 | k3-256k 不支持视频仅作文档注明，不做 capabilities 过滤逻辑 | IDE 无附件能力，无实际影响面 |

## 4. 任务分解

### T1　环境前置：CLI 升级与模型目录刷新

- `~/.kimi-code/bin/kimi upgrade` 升级至最新（≥0.28.1）；随后交互模式 `/logout` → `/login`（或 `kimi login`）刷新服务端模型目录。
- 验证：`kimi provider list --json` 返回 4 项，含 `kimi-code/k3-256k`（`maxContextSize=262144`、capabilities 无 `video_in`、含 `supportEfforts`）。
- 若重登录后仍无新模型（服务端目录未推送），回退手动补丁 config.toml（§2.2 兜底）并在验收中注明临时性。

### T2　IDE 零改动验证（探针 + 实测）

- `list_kimi_models()` 返回 4 项且排序含 `kimi-code/k3-256k`。
- 底行版本菜单与设置中心版本下拉均出现新项；选择持久化写盘、重开恢复、无效回退路径不受影响（复用既有机制）。
- 实测对话：切到 `kimi-code/k3-256k` 发一条消息，流式响应正常、session 续接正常。

### T3　默认模型调整（按 D2 拍板执行，可选）

- 选 a：更新 `config/settings.json` 的 `model_version` 为 `kimi-code/k3-256k`；CLI `~/.kimi-code/config.toml` 的 `default_model` 同步切换（影响 CLI 裸跑默认）。
- 选 b：本任务跳过，仅 T2 验证可用性。

### T4　切换会话语义（按 D3 拍板执行，可选）

- 选 b：`KimiCliLLM.set_model()` 内增 `self.reset_session()`（一行 + 注释引官方建议）；影响面为切换版本即丢会话续接，需在验收中明确。
- 选 a/c：零代码改动；选 c 时在 `llm/README.md` 注明「切换模型建议新开会话（缓存失效）」。

### T5　文档同步

- `llm/README.md`：可用模型别名段补 `kimi-code/k3-256k`（标注 256K/省额度/不支持视频）。
- 本计划实施记录区补落地结果；按需更新 `文档/修改记录/` 索引。

## 5. 风险与缓解

| 风险 | 缓解 |
|:---|:---|
| 重登录后服务端目录仍未含 k3-256k（新模型发布初期） | T1 兜底手动补丁 config.toml；待 CLI 后续版本覆盖后自动转正 |
| 会员档位不足（低于 Moderato）调 k3-256k 返回 401 | 本机已在用 k3，档位已满足；报错文案由 CLI stderr 尾部透传，IDE 无需特判 |
| 旧会话上下文超 256K 切 k3-256k 触发 CLI 侧 compact，体感「丢上下文」 | D3 拍板项；选 b（切即新会话）可根治，选 a/c 靠文档提示 |
| 手动补丁 config.toml 被 CLI 升级/重登录覆盖 | 补丁仅临时；覆盖后重跑 T1 验证 |
