> **状态**：草稿（待审阅）

> **时间**：2026-09-09 22:44 (UTC+8)（设计）
> **优先级**：高
> **依据**：`协议和指南/无测试门禁整改方案.md`（拆分自 `2026-0909-0943_工程化短板整改方案.md` 第 1 节）

## 1. 目标

把"提交前跑一下"从纪律变成一条命令：`scripts/check.sh`（ruff + pytest），写进 `AGENTS.md`，人与 AI 提交前必跑。原则：**先做到比现状好，不追求完美**——不追覆盖率、不上 CI、不上 typecheck。

## 2. 现状盘点（2026-09-09 实测）

- 无 `tests/` 目录；`.venv` 未装 pytest、ruff；dev 依赖仅 pyinstaller、python-xlib。
- `scripts/` 已有 5 个断言式手工测试脚本（失败即 `SystemExit`），是现成的第一批用例：

| 脚本 | 行数 | 性质 | 收编要点 |
|:---|:---:|:---|:---|
| `scripts/test_child_env.py` | 81 | 纯逻辑（`core/child_env.py`） | 直接转断言 |
| `scripts/test_git_dir_status.py` | 138 | 纯逻辑（`core/git/service.py`，虚构仓库根不落盘） | 直接转断言 |
| `scripts/test_question_permission.py` | 144 | 纯逻辑（`llm/permission_policy.py`） | 直接转断言 |
| `scripts/test_follow_lock.py` | 106 | 需 `QT_QPA_PLATFORM=offscreen` 的 QApplication | 保留 offscreen 要求，由 check 脚本统一注入环境变量 |
| `scripts/test_subagent_nested.py` | 214 | 纯逻辑，但**依赖 `.temp/` 下帧蓝本**（`.temp/subagent_acp_test/reasonix_frames.jsonl`、`.temp/subagent_wire_sample.jsonl`） | ⚠️ `.temp/` 不入库，蓝本须迁入 `tests/fixtures/`，否则清缓存/换机器即挂 |

- ruff 实测（`E,F,W`，排除 vendored `markdown_it/`、`mdurl/`）：共 278 条 = **270 条 E501 行宽**（中文长注释，风格噪音）+ 6 条 F401 未用导入（可 `--fix`）+ 2 条 E402 导入位置。存量代码质量本身良好。

## 3. 实施步骤

### T1 依赖与 ruff 配置

- `uv add --dev pytest ruff`（写入 `pyproject.toml` 的 `[dependency-groups] dev`）。
- `pyproject.toml` 增 `[tool.ruff]`：
  - `exclude`：`参考代码/`、`markdown_it/`、`mdurl/`、`building/`、`.temp/`、`.tmp/`；
  - `lint.select = ["E", "F", "W"]`，`lint.ignore = ["E501"]`——270 条行宽报警全是中文长注释/文档串，属项目既有风格，关闭而非批量改行（**审阅点**：若想保留行宽约束，可改 `line-length = 120` 并放行存量，二选一）。

### T2 存量 lint 清零

- `ruff check --fix` 修 6 条 F401；手动处理 2 条 E402（移动导入或加 `noqa` 并注明原因）。
- 验收：`ruff check` 全绿。

### T3 建 `tests/`，收编 5 个脚本

- 目录形态：`tests/test_child_env.py` 等 5 个用例文件 + `tests/fixtures/`（收编 `test_subagent_nested.py` 依赖的 2 份帧蓝本，从 `.temp/` 复制入库）+ `tests/conftest.py`（如需统一 `sys.path`/offscreen 环境）。
- 改写要点：去 `sys.path.insert` hack、去 print 目检、`check()` 辅助函数改为裸 `assert`；测试体逻辑**一行不改**。
- 原 `scripts/test_*.py` 收编后删除（避免双份漂移），`scripts/README.md` 同步更新。
- offscreen：`test_follow_lock.py` 所需 `QT_QPA_PLATFORM=offscreen` 由 check 脚本或 conftest 统一注入，用例内不重复设置。

### T4 门禁入口 `scripts/check.sh`

```bash
# scripts/check.sh
#!/usr/bin/env bash
set -euo pipefail
uv run ruff check
QT_QPA_PLATFORM=offscreen uv run pytest tests/ -q
```

- 唯一入口，退出码即门禁结果；`chmod +x`。

### T5 规则入库

- `AGENTS.md` 增一条：**提交前必跑 `scripts/check.sh`，全绿才可提交**。
- 更新 `scripts/README.md`（测试脚本已迁 `tests/`）、本计划状态改为"已实施"。

## 4. 验证清单

1. `scripts/check.sh` 退出码 0（ruff 0 错误、pytest 5 个用例文件全过）。
2. 删除 `.temp/` 后重跑 check 仍全绿（证明 fixtures 已入库，无临时目录依赖）。
3. 人为制造一个 F401（加一行未用导入），check 变红——验证门禁有效，随后还原。
4. `git status` 确认改动面仅限： `pyproject.toml`、`uv.lock`、`tests/`（新增）、`scripts/`（删 5 迁 1 增 check.sh 改 README）、`AGENTS.md`。

## 5. 风险与代价

- 首次投入约半天到一天；此后改动被测逻辑需同步更新用例（这是门禁的意义，非额外负担）。
- ⚠️ T3 帧蓝本迁移是唯一可能翻车的点：蓝本若与现状代码已脱节，收编时可能暴露既有失败——遇到则如实记录，不在本计划内修行为。
- E501 关闭后行宽无约束，依赖审查自觉；如后续想收紧，改配置即可，存量不动。

## 6. 明确不做（本计划边界外）

- ❌ CI（typecheck、GitHub Actions 等）——单人项目本地门禁已够，协作者出现或发版频率上升再加。
- ❌ mypy/ty 类型检查。
- ❌ 全程序 GUI 冒烟测试——应用配置写在项目内 `config/`，冒烟会污染真实窗口状态/会话数据，需单独设计隔离方案，另立计划。
- ❌ 覆盖率指标、存量代码 E501 批量换行、`markdown_it/`/`mdurl/` vendored 代码的任何 lint 改动。
