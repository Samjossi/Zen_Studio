## 1. 背景与目标

Kimi 的 sidecar 线程、wire 合成与迟到帧观察，以及 DSH 的会话日志定位、zstd 读取与 usage 事件提取，仍内联在各自 provider 中。它们都有独立故障模式（线程泄漏、迟到帧、日志 generation 漂移、zstd 缺失），却无法独立测试。

本子计划目标：

1. 新建 `kimi/subagent.py`，承接 sidecar 生命周期、wire 事件合成与父调用发现。
2. 新建 `dsh/session_log.py`，承接会话日志定位、zstd 解压、usage 事件与轮次消耗差量。
3. provider 只负责组合；线程收尾、日志缺失处理与用量数值保持不变。

## 2. 启动条件与边界

- S0–S3 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S5。
- 纯搬家，不改子代理展示规则、不改迟到帧时机、不改 DSH 用量口径。
- `kimi/subagent.py` 可复用 S3 的 `kimi/wire.py` 公开入口，但不得 import provider。
- `dsh/session_log.py` 不得 import provider、其他厂商或 GUI。
- 不新增依赖；zstd 仍按现有可选依赖处理，缺失时跳过采集并告警。
- 线程只能由 provider 显式启动/停止；模块 import 不得产生线程或 I/O 副作用。

3. 标注线程生命周期：何时启动、何时停止、会话重建时是否重启、close 时是否 join；标注迟到帧与父调用的状态归属。

### S4.2 新建 `kimi/subagent.py`

1. 迁入 sidecar 线程：目录发现、文件轮询、增量读取、事件入队；提供显式 `start()`/`stop()`/`join()` 或等价生命周期。

### S4.3 新建 `dsh/session_log.py`

1. 迁入 DSH home 解析、session 目录定位、generation 文件选择（`session.jsonl`/`session.vN.jsonl`/`.zstd`）。

## 5. 风险与注意点

- **线程泄漏**：sidecar 线程最容易在异常/重建路径漏停；start/stop 必须幂等，close 必须 join 或有界等待。
- **迟到帧**：sidecar 与 ACP 双源汇合有节拍假设；搬家不能改变入队/消费顺序，否则子卡片会闪烁或丢帧。
- **zstd 可选**：不要在模块 import 时强制依赖 zstd；保持现有 try/except 与告警文本。
- **generation 漂移**：DSH 可能同时存在多个 `session.vN.jsonl`；选择规则与现状一致，并用真实夹具覆盖。
- **状态归属**：sidecar 观察账本与 DSH 基线必须随会话重置；不能放模块级。
