## 1. 需求背景

用户真机反馈（2026-10-16，三张截图对比确认）：**应用内右键菜单形态不统一**——

- 截图 1：AI 聊天面板对 **AI 回复**右键 → 「复制」「全选」两项，纯文字、无图标、无快捷键提示（✅ 用户拍板此为统一标准）；
- 截图 2：AI 聊天面板对**用户自己的话（气泡）**右键 → Qt 原生英文菜单「Copy / Copy Link Location / Select All」，带图标与 Ctrl+C/Ctrl+A 快捷键提示（❌）；
- 截图 3：文件查看面板右键 → 仅单项「全选」，无「复制」（❌）。

**统一目标（用户三条拍板）**：

1. 只读文本展示区域的右键菜单统一为截图 1 形态——**仅「复制」「全选」两项，无图标、菜单文本不显示快捷键提示、中文**；
2. 菜单项与键盘快捷键**正交并存**——菜单有「复制」可点，Ctrl+C / Ctrl+A 等快捷键同时照常可用，非二选一；
3. **「无图标」是全局要求**——所有右键菜单一律不出现旧版每项带图标的样式（不简洁），不限于只读文本区。

**根因**：`cards.py` 的 `BodyText`/`BodyHtml` 是卡片轨全部只读正文的基类，始终未覆写 `contextMenuEvent`——当年 simplify 只接到了 `TextStreamBlock`、`ChatOutput`、`ChatInput` 三个点上，卡片基类漏接，用户气泡与各类卡片正文全部回落 Qt 默认菜单。查看器两处则是 0806 计划主动拍板「只留全选」的历史决策，与本次新标准冲突。其余对话框与零散输入框则是历次功能开发各自 new 裸控件，从未纳入右键菜单规约。

**图标的来源**：应用自建菜单（文件树、终端、查看器）本来就是纯文字 `addAction("…")`，无图标；**所有图标均来自 Qt 内建标准编辑菜单**（`createStandardContextMenu()` 按当前主题取图标）。因此全局无图标 = 把一切仍走 Qt 原生标准菜单的控件全部纳入 `simplify_standard_menu()` 覆盖。

## 3. 方案设计

**D1（统一标准定义）**：只读文本展示控件右键菜单 = 「复制」「全选」两项，顺序复制在前；无图标、菜单文本不显示快捷键提示、中文；「复制」仅在有选区时可用（Qt 标准菜单自带该启停语义），「全选」恒可用。

**D1a（快捷键正交保留，拍板 2）**：菜单补「复制」项的同时，Ctrl+C / Ctrl+A 等快捷键**必须照常可用**。现状即如此（`simplify_standard_menu()` 只截断菜单文本的 `\tCtrl+C` 显示后缀，控件自身按键处理不动；查看器 Qt 内建复制/全选快捷键也未禁用），本计划任何改动不得削弱快捷键路径，测试须一并断言 Ctrl+C 复制生效。

**D1b（全局无图标，拍板 3）**：任何右键菜单项一律不挂图标。自建功能菜单（文件树/终端/查看器）现状已合规，仅需核对防回归；其余全部经 `simplify_standard_menu()` 去图标。

**D2（卡片基类接入，主修复面）**：`cards.py` `BodyText` 与 `BodyHtml` 各覆写 `contextMenuEvent` → `exec_standard_context_menu(self, event, simplify=True)`。只读控件经 Qt `createStandardContextMenu()` 仅产出 Copy / Select All（QTextBrowser 多出的 Copy Link Location 由 `simplify_standard_menu()` 既有逻辑删除），精简后即恰好「复制」「全选」两项。一处接入，`UserBubbleBlock` 气泡体、`SystemBlock`、`ThinkingCard`、全部工具卡正文自动继承，与 AI 回复流式块同一形态。

**D3（查看器补「复制」）**：`code_viewer.py` 与 `markdown_view.py` 的自绘菜单在「全选」前补「复制」项——

- `menu.addAction("复制", self.copy)`，`setEnabled(self.textCursor().hasSelection())`，构建时按当下选区状态定启停；
- 「全选」项不变；菜单仍走 `make_translucent_popup()` 透明化规约，无图标；
- `markdown_view.py` 保持 `_build_context_menu()` 构建/弹出分离结构（探针可断言），仅改构建内部。

本项推翻 0806 计划「菜单只留全选」的拍板（当时语义是菜单项与快捷键二选一，本次用户明确二者正交并存），以本次拍板为准；两处控件的 `contextMenuEvent` docstring 与 `popups.py` 模块 docstring 中相关描述同步更新。

**D4（只读对话框文本纳入 D1 标准）**：`git_graph_dialog.py` 降级 `QTextBrowser`、`diff_view_dialog.py` `QTextBrowser`、`settings_dialog.py` 黑名单 `QTextEdit` 三处均为只读文本展示，属 D1 适用范围。参照 `popups.py` 既有 `TranslucentMenu*` 封装模式，新增只读简化版封装（`contextMenuEvent` → `exec_standard_context_menu(self, event, simplify=True)`），三处对话框换用。

**D5（可编辑输入框去图标，保编辑项）**：`find_bar.py` 查找框、`permission_dialog.py` 详情框、`explorer.py` 文件树搜索框为可编辑控件，保留撤销/剪切/粘贴等完整编辑项，但按拍板 3 去图标、顺带中文化——

- `TranslucentMenuLineEdit` / `TranslucentMenuPlainTextEdit` 两处调用改 `simplify=True`（一行量级）；
- `explorer.py` 裸 `QLineEdit` 换用 `TranslucentMenuLineEdit`，同时补上缺失的菜单透明化。

**D6（边界不动）**：以下保持现状，仅核对不改动——

- 聊天输入框 `ChatInput`、终端面板功能菜单、文件树功能菜单：已中文化无图标，功能项按各自语义保留；
- 菜单栏下拉：非右键菜单，不在范围；
- 若审阅时希望连可编辑输入框也砍到两项，需知会丢失粘贴入口，默认不做。

## 5. 风险与开放项

- ⚠️ **QTextBrowser 链接项变体**：`BodyHtml` 右键落在锚点上时 Qt 标准菜单可能多出 Copy Link Location 之外的链接项；T6 探针需覆盖「点在文件引用链接上」场景，若多出项则在 `simplify_standard_menu()` 中一并剔除，保持两项红线。
- ⚠️ **主题图标依赖环境**：Qt 标准菜单图标取自当前桌面主题，CI/offscreen 环境可能本就没图标——T6 的「无图标」断言以 `simplify_standard_menu()` 处理后的菜单为准，不依赖环境主题。
- ⚠️ **注释规约**：T8 更新注释时遵守 `AGENTS.md`——注释只答 why，新写注释不带日期/计划编号。
- 开放项：无（原 `TranslucentMenu*` 去图标开放项已经拍板 3 转正为 T5）。
