# 左栏最小宽度与横向滚动根治计划

## 1. 背景

用户实机截图反馈：左栏对话区某一行内容过长时，对话区底部出现**横向滚动条**，
用户不希望它能左右滚动。经两轮复述校准，用户决策三条：

1. **左栏设定最小缩小宽度**：给一个合适的最小宽度，用户拖动 splitter 缩到
   该宽度即触底，不能再小；
2. **任何宽度下禁止横向滚动条**：普通文本一行太长时**自动换行**到下一行，
   而不是撑出横向滚动；
3. **卡片内容超长则截断显示**：卡片内的字（标题/副标题/条目等单行文本）
   过长时在卡片内**截断显示**（省略号收尾），不换行撑开。

## 2. 现状诊断（2026-08-06 04:0x 离屏探针实证）

### 2.1 根因定位

`QT_QPA_PLATFORM=offscreen` 探针实测三类控件的最小宽度提示：

| 控件 | minimumSizeHint 宽 | 换行行为 |
|---|---|---|
| `QPlainTextEdit`（BodyText） | 70px | `WidgetWidth` 自动换行（默认） |
| `QTextBrowser`（BodyHtml） | 70px | 自动换行（默认） |
| `QLabel`（200 字长文本） | **2400px（全文像素宽）** | 不换行、不可收缩 |

结论：**body 文本块（正文流/卡片 body）不是撑宽源头**——它们 70px 下限
且天然换行。真正的元凶是 **`QLabel` 单行标签**：卡片 header 的
`_title_label` / `_subtitle_label`、`TodoCard` 条目标签等，长文本时
`minimumSizeHint` 等于全文宽度，沿布局链一路上推：

```
长 QLabel → 卡片 header 最小宽 → CollapsibleCard 最小宽
→ ChatTranscriptView._container 最小宽
→ QScrollArea 内容超视口 → 横向滚动条
```

一张带长标题的卡（如 bash 长命令标题、Thinking — 长首行、长路径副标题、
长 todo 条目）会把**整个容器**撑宽，容器内所有换行文本随之按超宽单行
平铺显示（截图中「出参」英文长段单行平铺即此表征），横向滚动条出现。

### 2.2 左栏宽度现状

- `gui/main_window.py` 注释实证链：左栏默认 320 ≥ ChatTabs 实测静态下限
  315（2026-0724-2354 计划 T6 回摆，底行双下拉 + 附件/发送按钮决定）；
- 但 `_splitter_main` 对 index 0（左栏）**未调 setCollapsible**——
  collapsible 默认 `True`，用户可拖过最小尺寸提示直接**塌缩到 0**，
  不存在「最小缩小宽度」的硬性下限。

## 3. 设计决策

### D1 省略标签 `_ElidedLabel`（cards.py 内部组件）

`QLabel` 子类，治「单行长文本撑宽」：

- 全文簿记 `_full_text`，`setText`/`resizeEvent` 两入口重算
  `fontMetrics().elidedText(text, ElideRight, width)` 上屏；
- `minimumSizeHint()` 覆写为 `(0, 行高)`——布局链最小宽贡献归零，
  可随卡片任意收缩；
- 水平 sizePolicy 置 `Ignored`——允许收缩到 sizeHint 之下；
- tooltip 落全文，截断不丢信息（hover 可读完整内容）。

取舍：选像素级 `elidedText` + resizeEvent 重算（随宽度拖动实时重省略），
放弃 2048 计划 D3 的字符级定长方案——彼处标题行一次性收敛求确定性，
此处卡片宽度随 splitter 连续变化，像素级才能「始终刚好占满可用宽」。

### D2 省略标签挂载点（卡片内容截断，用户决策 3）

| 挂载点 | 现状 | 改后 |
|---|---|---|
| `CollapsibleCard._title_label` | QLabel | `_ElidedLabel` |
| `CollapsibleCard._subtitle_label` | QLabel | `_ElidedLabel` |
| `ThinkingCard` 标题（`set_title` 同源） | 经基类标签 | 随基类自动生效 |
| `TodoCard` 条目标签 | QLabel | `_ElidedLabel` |

状态图标（◐/✔/✖）、diff 徽标（+N −M）、「共 N 行」尾注均为定长短文本，
不改。`TodoCard._title`/`_subtitle`（「任务清单」「— N/M 项完成」）为定长
短文本，不改。

### D3 横向滚动条硬关闭（transcript.py，用户决策 2 的兜底）

`ChatTranscriptView.__init__` 增加
`setHorizontalScrollBarPolicy(ScrollBarAlwaysOff)`。

语义：这是**硬保证**而非治本——D1/D2 落地后内容在任何宽度自适应，
横向滚动条本不会出现；AlwaysOff 保证未来新增块类型即使异常撑宽，
也只会被裁边而**永不出现横向滚动条**（视觉纪律高于个别极端裁边）。

普通文本换行（用户决策 2 的前半）由既有机制承接：BodyText/BodyHtml
默认 `WidgetWidth` 换行 + `_HugHeightMixin._fit_height` 跟随视口宽
`setTextWidth`，本计划不改。

### D4 左栏最小宽度 320px + 防塌缩（用户决策 1）

- `gui/panels/chat/tabs.py` 新增类常量 `ChatTabs.MIN_WIDTH = 320`：
  取现有实证链数值（默认 320 ≥ 静态下限 315，2026-0724-2354 计划 T6），
  单一来源一处可调；
- `gui/main_window.py`：构造接线处 `chat_tabs.setMinimumWidth(ChatTabs.MIN_WIDTH)`
  + `self._splitter_main.setCollapsible(0, False)`——前者给出显式下限，
  后者堵 collapsible 默认 True 允许拖塌到 0 的缺口，双闸合一用户缩到
  320 即触底；
- 右栏（index 2）已有 `setCollapsible(2, False)` 先例（FileExplorer.MIN_WIDTH
  约束），本决策与其同构，无新范式；
- 窗口最小宽 900 不变：320（左）+ 240（右）+ 中栏余量 ≥ 300，不冲突。

### D5 经典旧轨不改

旧轨 `ChatOutput`（QTextBrowser）天然换行，无双栏卡片 QLabel 撑宽链，
不在本次范围（冻结轨纪律：非缺陷不动）。

## 5. 验证方案（T6，`.temp/smoke_chat_width.py`，offscreen）

构造真实 `ChatTranscriptView`，压入极端内容后在**超窄宽度（240px，
小于左栏下限 320）**下断言：

1. **硬关闭**：`horizontalScrollBarPolicy() == ScrollBarAlwaysOff`；
2. **容器不撑宽**：压入长标题工具卡（200 字 title + 长路径 summary）、
   长 todo 条目（200 字）、长英文段落 Mcp 出参后，
   `_container.width() <= viewport.width()`（无横向溢出）；
3. **截断生效**：各 `_ElidedLabel` 上屏文本以 `…` 收尾且 ≠ 全文，
   tooltip == 全文；
4. **换行生效**：长英文段落 BodyText 在窄宽下 doc 块行数 > 1
   （`document().size().height()` 大于单行高）；
5. **回归**：短文本标签不省略（上屏 == 全文）、卡片开合/状态流转
   （◐→✔）不受影响；
6. **左栏下限**：实例化 `ChatTabs` 断言 `MIN_WIDTH == 320`；
   静态断言 `gui/main_window.py` 含 `setCollapsible(0, False)` 与
   `setMinimumWidth` 接线（MainWindow 整树实例化重，源码级断言接线
   存在即可，实机手感归用户收尾对照）。

## 6. 风险与取舍

- ⚠️ **标题截断丢上下文**：长 bash 命令标题在窄栏下省略，hover tooltip
  兜底全文；复制按钮（T11 既有）复制的是 body 全文，不受省略影响。
- ⚠️ **AlwaysOff 裁边**：极端情况（未来新增不收缩块类型）内容右侧被裁
  而非滚动可见——按 D3 语义这是有意的视觉纪律取舍。
- **像素级省略的重算成本**：resizeEvent 每帧 `elidedText` 一次，
  单行文本 O(n)，对话区卡片量级（数十张）下可忽略。
- **旧轨不动**（D5）：切回 classic 轨的用户在极窄栏理论上仍可见
  QTextBrowser 原生行为，与现状一致，非回归。

## 7. 非目标

- 不改输出/输入区垂直 splitter 行为与持久化；
- 不改 ModelBar 底行任何组件宽度（315 静态下限来源保持现状）；
- 不调整窗口最小尺寸（900×500 维持）；
- 不做卡片内容的双行省略/多行截断（用户决策为单行截断）。

   标签保持默认 Preferred 策略（`minimumSizeHint` 归零覆写不变）+
   header 中标题/副标题挂拉伸因子 3:2、移除弹性间隔项——可用宽按
   3:2 确定性分割，短文本时标签左对齐延展，视觉与原方案一致。
2. **富文本判定替换**：`Qt.mightBeRichText` 在 PySide6 未暴露
   （AttributeError），改用 `_TAG_RE.search(full)` 正则判定，语义等价
   （DiffCard 双色副标题仅此处产富文本）。
