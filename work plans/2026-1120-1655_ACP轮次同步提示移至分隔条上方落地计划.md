## 1. 背景与目标

当前 `_turn_sync_label` 位于输入区状态行内，排列在活动时间线与上下文用量徽章之间。由于输入区整体位于垂直 `QSplitter` 把手下方，提示实际也处于分隔条下方，不符合最新确认的视觉层级。

本期只调整该临时提示的承载位置与外观，目标如下：

- 提示显示时，从上到下严格排列为：**输出区 → 轮次同步提示 `QLabel` → 现有可拖动分隔条 → 原状态横条**。
- 原状态横条继续保持**左活动时间线色块条、右上下文用量徽章**，提示不再插入二者之间。
- 提示与状态横条是上下独立的两条横条，不相互覆盖，也不放在分隔条与状态横条之间。
- 提示高度与状态横条一致，左右边缘与状态横条对齐，同宽显示。
- 提示显示时使用 AI 聊天面板 `PanelCard` 的卡片底色；默认隐藏及原有轮末清理行为保持不变。

## 2. 结构映射与目标布局

当前布局为：

```text
PanelCard
└─ QSplitter（垂直）
   ├─ 输出区
   ├─ 可拖动分隔把手
   └─ 输入区
      ├─ 状态行：时间线 + turn_sync QLabel + 用量徽章
      ├─ 附件行
      ├─ 输入框
      └─ 底行按钮
```

目标布局为：

```text
PanelCard
└─ QSplitter（仍只有两个窗格、一个原把手）
   ├─ 输出侧容器
   │  ├─ 输出区
   │  └─ turn_sync QLabel（默认隐藏，显示时独占一整行）
   ├─ 可拖动分隔把手（位置与拖动功能保留）
   └─ 输入区
      ├─ 状态行：左时间线 + 右用量徽章
      ├─ 附件行
      ├─ 输入框
      └─ 底行按钮
```

提示显示时的局部视觉顺序固定为：

```text
┌──────────────────────────────┐
│ turn_sync 临时提示            │  ← 与状态横条同高同宽，card_bg 底色
├──────────────────────────────┤
│ 现有 QSplitter 可拖动分隔条    │  ← 不新增第二个把手
├──────────────────────────────┤
│ 时间线色块条        用量徽章   │  ← 原“左条右徽”布局不变
└──────────────────────────────┘
```

## 3. 现状锚点

- `src/ide/gui/panels/chat/panel.py` 的 `_build_input_box()` 创建 `_turn_sync_label`，并将其加入 `status_row`，位于 `self.timeline` 与 `self._usage_label` 之间。
- `src/ide/gui/panels/chat/panel.py` 的 `_build_layout()` 以 `self.output` 和 `_build_input_box()` 作为垂直 `QSplitter` 的两个窗格；二者之间已有可拖动把手，不能把提示作为第三个 splitter 子件直接插入，否则会多出把手并改变状态持久化语义。
- `src/ide/gui/panels/chat/timeline.py` 的 `ActivityTimeline` 固定高度为 `MAX_H + 4`，当前即 **30px**；状态行高度由该控件决定。
- `assets/themes/base.qss` 的 `#PanelCard` 使用 `$card_bg` 作为背景。因此“AI 聊天面板卡片底色”的唯一来源是主题调色板顶层 `card_bg`，不是 `chat.tool_output_bg`、`chat.user_bubble_bg` 或新造颜色。
- `ChatPanel.apply_theme()` 已统一刷新时间线、附件和用量徽章，提示底色应接入同一入口，避免主题切换后残留旧色。
- `tests/test_turn_abort.py` 已覆盖提示显示、连续更新、正常完成、失配失败和停止清理；这些生命周期断言应原样保留，只补充布局与配色回归。

## 4. 设计决策

### D1 输出侧容器承载提示，保留单一分隔把手

将输出区与 `_turn_sync_label` 装进同一个无额外边框的输出侧容器，再作为 `QSplitter` 的第一个窗格；输入区仍为第二个窗格。提示位于输出区底部，因此自然紧贴原把手上方，并随把手拖动保持正确相对位置。

禁止采用以下方式：

- 把提示留在输入区首行：那仍然位于把手下方。
- 把提示作为第三个 splitter 子件：会引入额外把手，并破坏现有两窗格尺寸保存/恢复。
- 用绝对坐标悬浮覆盖：拖动、缩放和主题字体变化后容易错位。

### D2 原状态行恢复为“左条右徽”

从 `status_row` 移除 `_turn_sync_label`，仅保留 `self.timeline` 横向延展和 `self._usage_label` 右侧恒宽布局。时间线、徽章、附件行、输入框及底行按钮的顺序和交互均不改。

### D3 同高同宽以现有控件为基准

- 提示固定高度直接复用 `self.timeline` 的当前固定高度作为基准，当前为 30px，不另写一份独立的高度常量。
- 输出侧容器与输入区均保持零内容边距；提示在输出侧容器中横向铺满，使其左缘与时间线左缘对齐、右缘与用量徽章右缘对齐。
- 保持提示最小宽度不撑宽左栏，长文案仍以完整 tooltip 兜底；不因本次移动引入固定面板宽度或横向滚动条。
- 默认隐藏时不保留提示行的空白高度；显示时新增一条独立横条，隐藏后恢复原布局。

### D4 底色复用 `card_bg` 并随主题刷新

为提示设置控件级背景样式，颜色读取 `get_theme_palette(theme)["card_bg"]`。初始构建与 `apply_theme()` 使用同一设置入口，确保首次显示和运行中切换主题都正确。

不新增主题令牌，不写死十六进制颜色，不把提示底色误设为工具卡或用户气泡颜色；除背景及必要的内边距外，不新增边框、圆角、阴影等未要求装饰。

### D5 生命周期与业务语义零改动

继续复用现有 `_set_turn_sync()` 统一显隐入口及 `_on_chunk()`、新轮、完成、失败、停止路径。提示仍是 `ChatPanel` 自持的临时状态：

- 连续 `turn_sync` 原位更新，不追加对话消息。
- 新轮及所有轮末隐藏并清空文案。
- busy、停止、待发、历史回滚和真实失配错误语义不变。
- 卡片轨与经典轨共用同一面板布局，不分别实现两套提示。

## 6. 风险与注意点

- **布局位置误判**：把提示放到输入区顶部仍是在把手下方，必须以真实 splitter 结构验证，不能只把控件移到状态行上方就视为完成。
- **额外把手**：提示不能直接成为第三个 splitter 窗格；输出侧容器方案用于保持两窗格和一个把手。
- **splitter 尺寸恢复**：新增容器不能改变 `save_state()` / `restore_state()` 的两段尺寸语义，也不能造成输出区被错误均分。
- **长文本撑宽**：提示独占整行后仍需服从左栏宽度，不得因 `QLabel.minimumSizeHint()` 把面板撑宽；完整文案继续由 tooltip 保留。
- **隐藏占位**：默认隐藏及轮末隐藏后不能留下一条空白横条；显示时高度变化只属于临时提示，不改变按钮使能或待发逻辑。
- **主题色来源**：`card_bg` 是 AI 聊天面板 `PanelCard` 底色；不得误用 `chat.tool_output_bg`。主题切换需刷新已存在的提示。
- **视觉验收边界**：逻辑几何断言和 offscreen 截图可以证明实现结构，但真机自然操作仍需用户终裁。
- **交付边界**：本期不重新设计状态横条、不修改 ACP 同步判定，也不将旧 AppImage 自动视为已热加载新布局。

## 7. 已确认决策

1. 提示 `QLabel` 放在**现有可拖动分隔条上方**，不是分隔条与状态横条之间，也不是与任何现有控件叠放。
2. 提示显示时形成独立横条；其下依次为原分隔条和原“左活动时间线色块条 + 右上下文用量徽章”状态横条。
3. 提示与原状态横条**一样高、一样宽**，左右边缘对齐。
4. 提示显示时使用 **AI 聊天面板卡片底色**，已映射到现有主题令牌 `card_bg`。
5. 提示继续默认隐藏，原有连续更新和全终态清理机制不变。
6. 初版布局实施后，用户将该提示正式命名为**临时提示面板**，并要求补入 `术语表.md`。
7. 设置中心外观页新增临时提示面板开关，默认开启以保持原行为；切换即时持久化并下发全部存量会话标签，新建标签读取同一设置，恢复默认设置时同步复位。
8. 外观页提供「预览样式」按钮，在当前活动会话标签的原位置显示 3 秒；预览不受启用开关限制，不改变开关、不入历史、不回传。
9. 真实提示到达、清理或轮次收尾时接管预览；预览计时器不得误清真实提示，真实提示已经可见时不再覆盖。

**经验沉淀**：

1. 要贴在原 splitter 把手上方又不改变两段尺寸持久化语义，应把临时行与输出区装进同一个零边距容器，而不是新增 splitter 子件；隐藏子件后该容器自然不保留临时行高。
2. 临时横条同高应直接读取既有控件固定高度，同宽应依靠两侧容器零内容边距和布局约束，避免复制高度常量或用绝对坐标补齐。
3. 像素采样坐标也属于布局状态：拖动或 `restoreState()` 后必须重新从控件映射，不能复用旧 `QPoint`；样式字符串已更新而旧坐标像素不变时，应先排查采样位置。
4. 当生产主题恰好共享同一色值时，样式更新测试必须显式制造可区分的调色板输入，否则“切换主题后值不变”无法证明刷新链路有效；测试覆盖不应反向修改生产配色。

**经验沉淀**：

1. “允许关闭真实状态”与“允许预览外观”是两个独立需求：预览不应被业务开关禁用，但必须与真实状态区分，避免用户把预览误认为新轮次消息。
2. 预览与真实提示共用控件时，单靠 `QTimer.singleShot` 清理存在竞态；需要预览活动标志，并让所有真实设置/清理入口取消计时器，超时回调再次校验活动状态。
3. 新外观偏好不能只加对话框控件：默认值、TypedDict、持久化、回读防回环、主窗口应用槽、存量/新建标签、零标签降级和恢复默认设置必须形成完整链路。
