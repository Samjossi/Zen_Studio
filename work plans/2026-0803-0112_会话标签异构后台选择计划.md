# 会话标签异构后台选择计划

> 目标：废除「全部标签共享同一（后台, 接口, 模型）选择」的全局语义（2026-0724-2354 计划 D5），改为**每会话标签独立选择后台/接口/模型**——用户新增会话时可选用不同后台，多后台会话并行（如标签 1 跑 Kimi、标签 2 跑 Reasonix）。
>
> **架构前提（实证）**：底层隔离早已完成——每标签独立 ChatPanel + 独立 provider 实例 + 独立 ACP 子进程连接（2026-0722-0756 计划 D6 方案 A）、注册表工厂懒实例化、切换异步 close。本计划**不碰 llm/ 与 provider 层任何代码**，只是状态归属从「容器全局单值 + 广播」下移为「每标签自持」。

## 1. 目标行为

| 场景 | 现状 | 目标 |
|:---|:---|:---|
| 标签 A 底行切换后台 | 广播强制同步全部标签（D5） | 只作用于标签 A；其余标签不受影响 |
| 新建标签 | 注入全局选择 | 注入「最近使用」选择（沿用现状持久化值语义） |
| 菜单/设置中心切换模型 | 广播全部标签 | 只作用于**当前活动标签** |
| 任一标签响应中 | 全部标签三按钮禁用 | **仅本标签**三按钮禁用；其余标签可正常切换 |
| 标签页标题 | 「会话 N」 | 「会话 N · 后台显示名」，随切换即时更新 |
| 图片附件能力 | 每标签随后端刷新（已实现） | 不变——异构后天然生效（识图会话与纯文本会话并存） |

## 3. 设计要点

### 3.1 状态归属下移（核心）

- **每标签自持**：(backend, version) 的有效值唯一来源是各标签的 ModelBar（现状已是「回退后的有效值以 ModelBar 为准」）。`ChatPanel._llm_name` 已是每标签字段，无需新增状态。
- **容器只留「新建注入值」**：`ChatTabs._backend/_version` 语义收缩为「下一个新建标签的初始选择 + 重启默认」，来源 = 最近一次用户显式切换（任一入口）。零标签时菜单切换只更新该注入值（等价现状语义）。
- **废除广播**：`_on_selection_changed` 不再调 `_broadcast_selection()`；持久化（`KEY_MODEL_BACKEND` + 记忆表）保留——写的是「最近使用值」，一期不作每标签区分（D2）。

### 3.2 菜单/设置中心作用域

- `MainWindow.apply_model_selection(backend, version)` → `ChatTabs.apply_model_selection` 改为：**当前活动标签** `panel.set_model_selection(...)`（无标签时只更新注入值）。
- 设置中心模型页展示值 = 当前活动标签的选择；标签切换（`currentChanged`）时经 `selection_changed` 链路重刷设置中心（reload 防回环机制现状已有）。
- 「恢复默认设置」批量路径：注入值重置 + 应用到当前活动标签（其余标签不动——它们已是用户显式选择的独立会话）。

### 3.3 busy 粒度收窄

- `ChatTabs._recompute_busy`：任一忙禁全部 → **各禁各的**（`panel.model_bar.set_busy(panel in _busy_panels)`）。
- `busy_changed` 对外语义改报「当前活动标签忙」（主窗口据此禁用设置中心模型页）；标签切换时重算重发。
- 发送/停止双态按钮本来就是标签本地，不涉及。

### 3.4 标签标题

- 格式 `会话 N · {vendor_label}`（后台显示名取 `VENDOR_LABELS`，不取接口 label——标题寸土寸金，后台级已足够辨识；同一后台多接口为一期不考虑的边缘形态）。
- 更新时机：新建时 + 该标签 `set_model_selection` 后（经 ChatTabs 槽统一改标题）。
