# 面板最小尺寸与苹果风界面改造计划

## 1. 背景与目标

主界面当前存在两类问题：

1. **布局约束缺失**：右栏文件树可被 QSplitter 拖至极窄并出现横向滚动条；中下终端栏可被拖至过矮。全项目无任何 `setMinimumWidth/Height` 调用。左栏之所以缩不小，是因为其内部 QComboBox 等控件自带 `minimumSizeHint`，属"碰巧正确"，并非显式设计。
2. **视觉噪音过重**：输入框/树/列表/按钮均有 1px 边框、`QMainWindow::separator` 2px 分割线、全部直角、菜单栏与状态栏灰底割裂、各面板标题行样式不统一。整体观感与"简约 / 苹果风"目标不符。

目标：

- 第一部分（已确认，直接实施）：右栏设最小宽度（不出现横向滚动条、不可缩得过小，效果对齐左栏现状）；中下终端栏设最小高度。
- 第二部分（待评审后实施）：去边框、去分割线、圆角化、背景色块分区，明暗双主题同步改造为苹果风。

## 2. 第一部分：面板最小尺寸约束（已确认）

### 2.1 现状分析

| 面板 | 现状 | 后果 |
|:---|:---|:---|
| 左栏 [chat/panel.py](gui/panels/chat/panel.py) | 内部 ModelBar 双 QComboBox 的 `minimumSizeHint` 较大 | 天然缩不小（用户认可此效果） |
| 右栏 [file_explorer/explorer.py](gui/panels/file_explorer/explorer.py) | QTreeView 最小尺寸约束极小 | 可拖至极窄、长文件名触发横向滚动条 |
| 中下 [terminal/panel.py](gui/panels/terminal/panel.py) | TerminalWidget 自绘，最小高度约等于 0 | 可拖至仅剩标题行 |

关键机制：QSplitter 的 `collapsible` 属性**默认为 true**，允许拖动把手将子控件压到小于 `minimumSize` 直至折叠为 0。因此仅设 `setMinimumWidth/Height` 不够，必须同时对对应 splitter 索引调用 `setCollapsible(index, False)`。

### 2.2 实施方案

改动集中于 [gui/main_window.py](gui/main_window.py) 与各面板构造函数：

| # | 改动 | 位置 | 说明 |
|:--|:---|:---|:---|
| 1 | `FileExplorer` 设 `setMinimumWidth(W_MIN)` | [explorer.py](gui/panels/file_explorer/explorer.py) 构造函数 | `W_MIN` 初定 **240**，实施时按 2.3 节调优 |
| 2 | 主水平 splitter `setCollapsible(2, False)` | [main_window.py](gui/main_window.py) | 索引 2 = 右栏，双保险防折叠 |
| 3 | `TerminalPanel` 设 `setMinimumHeight(H_MIN)` | [terminal/panel.py](gui/panels/terminal/panel.py) 构造函数 | `H_MIN` 初定 **140**（标题行约 26px + 约 6 行终端文本） |
| 4 | `middle_splitter.setCollapsible(1, False)` | [main_window.py](gui/main_window.py) | 索引 1 = 中下终端栏 |

数值以常量形式定义于各面板模块顶部并注释依据，便于后续调参。

### 2.3 调优与验收方法

1. 以 `uv run main.py --auto-screenshot --screenshot-on-start` 截图走查；
2. 右栏宽度从 240 起按 10px 递减，找到"根级最长文件名（当前为 `记忆银行_轻量版指导文档.md`）省略号截断前 / 横向滚动条出现前"的阈值，向上取整到 10 的倍数定为最终 `W_MIN`；
3. 拖动验证：把手拖至极限，右栏不得小于 `W_MIN`、不得出现横向滚动条；终端栏不得小于 `H_MIN`；
4. 窗口整体缩小至最小后，三栏仍保持各自最小尺寸（此时窗口最小尺寸由布局自动推导）。

### 2.4 验收标准

- [ ] 拖动把手，右栏宽度 ≥ `W_MIN`，无横向滚动条；
- [ ] 中下终端栏高度 ≥ `H_MIN`；
- [ ] 左栏行为与现状一致（不回退）；
- [ ] 窗口缩小后布局不破、无控件重叠。

### 3.2 设计原则（苹果风）

1. **去边框化**：控件不用描边区分边界，改用**背景色块**分区——侧栏与输入区用浅灰（亮 `#f5f5f7` / 暗 `#2c2c2e`），内容区用底色（亮 `#ffffff` / 暗 `#1e1e1e`）。
2. **极细分隔**：分隔只保留 splitter 把手 1px 半透明线，常态近乎隐形、hover 时显现；`QMainWindow::separator` 2px → 1px 浅灰。
3. **圆角**：输入框、按钮、菜单、下拉框统一 6px 圆角（菜单 8px）。
4. **扁平按钮**：去边框去底色，hover 才浮现 `rgba` 浅灰圆角底。
5. **融合式菜单栏/状态栏**：与窗口同色，去灰底；状态栏仅保留文字。
6. **统一标题行**：三栏面板标题行统一为 13px 半粗 + 次级灰文字（苹果 secondary label 风格），去除各自硬编码 bold 黑。
7. **隐形滚动条**：10px 宽、无箭头按钮、半透明圆角滑块，底色透明。
8. **配色克制**：选中/强调色沿用现有 `#0765d4`（双主题已统一），文字色柔化（亮 `#1d1d1f` 替纯黑；暗 `#f5f5f7` 替纯白）。

### 3.3 改造方案

#### 3.3.1 qss 重写（两份主题文件同步）

亮暗两份 qss 按同一结构重写，仅色值不同：

| 选择器 | 改造点 |
|:---|:---|
| `QWidget` | 文字色 `#000000` → `#1d1d1f`（亮）/ `#f5f5f7`（暗）；`selection-*` 保持 `#0765d4` |
| `QLineEdit, QTextEdit, QPlainTextEdit` | 去边框；背景 `#f5f5f7`（亮）/ `#2c2c2e`（暗）；`border-radius: 6px; padding: 4px 8px` |
| `QTreeView, QListView` | 去边框；背景透明（继承面板底色，见 3.3.2 侧栏灰分区）；`outline: none` 去焦点虚线 |
| `QPushButton` | 去边框去底色；`border-radius: 6px; padding: 4px 12px`；hover `rgba(0,0,0,0.06)`（亮）/ `rgba(255,255,255,0.08)`（暗） |
| `QComboBox` | 新增定制：去边框、灰底圆角 6px、padding；下拉箭头区去边框 |
| `QMenuBar, QMenu` | 菜单栏背景透明融入窗口；菜单 `border-radius: 8px; padding: 4px`，item 圆角 4px |
| `QMainWindow::separator` | 2px `#ebebeb` → 1px `#e5e5e5`（亮）/ 1px `#38383a`（暗） |
| `QSplitter::handle` | 新增：常态透明；hover 显示 1px 分隔色 |
| `QScrollBar:vertical/horizontal` | 新增：宽高 10px、背景透明、`::handle` 半透明灰圆角 5px、`::add-line/sub-line` 尺寸归零 |
| `QStatusBar` | 去灰底，背景透明 |
| `QToolTip` | 新增：圆角 6px、灰底，与整体协调 |

#### 3.3.2 面板背景分区（侧栏灰 / 内容白）

苹果风侧栏与内容区的灰白分块需控件级背景区分，方案：

1. 给左栏 `ChatPanel`、右栏 `FileExplorer` 设 `objectName`（如 `SidePanel`），qss 中以 `#SidePanel { background-color: #f5f5f7; }`（亮）/ `#2c2c2e`（暗）统一着色；
2. 中栏查看器/终端保持窗口底色；
3. 侧栏内控件（树、输出区、输入框）背景设为透明或同色，避免出现"灰底上的白色色块"。

|:--|:---|:---|

#### 3.3.4 字体（2026-07-19 06:27 修订：采用 assets 自带思源黑体）

**结论**：改用项目自带字体 `assets/fonts/思源黑体/`（Source Han Sans CN，7 档字重 OTF，已入库）。

**评估依据**（修订过程记录）：

- 思源黑体（Source Han Sans）与当前配置的系统字体 `Noto Sans CJK SC` 是 Adobe / Google 联合开发的**同一套字体的双品牌发行**，字形完全一致，更换不会带来视觉差异；
- 采纳价值在工程层面：① **分发一致性**——不再依赖目标机器是否安装 Noto（缺失时会静默回退到不可控字体）；② **字重保障**——苹果风标题行层级依赖 Medium 等真字重（Qt 对 CJK 的合成加粗效果差），本机系统 Noto 虽恰好装全 7 档，其他机器未必；自带后字重层级有硬保障。

**实施方案**：

| # | 改动 | 位置 | 说明 |
|:--|:---|:---|:---|
| 1 | 启动时经 `QFontDatabase.addApplicationFont()` 注册字体 | [theme.py](gui/theme.py) `apply_theme()` | 注册 **Regular / Medium / Bold** 三档（约 25 MB），其余四档（ExtraLight/Light/Normal/Heavy）保留于目录备用，后续如需 Light 次级文字可直接启用 |
| 2 | 默认 `font_family` 改为 `Source Han Sans CN` | [theme.py](gui/theme.py) `DEFAULT_SETTINGS` | 注册失败（文件缺失/损坏）时回退系统 `Noto Sans CJK SC`，再退化 Qt 默认 |
| 3 | 标题行层级用真 Medium 字重 | qss `PanelTitle` 选择器（见 3.3.3 任务 3） | 以 `font-weight: 500`（Medium）替代合成 bold |
| 4 | 许可证声明 | [assets/fonts/思源黑体/](assets/fonts/思源黑体/) 目录 | 思源黑体为 SIL OFL 1.1，允许随应用分发，须附带 OFL 许可证文本（实施时从官方源获取 `LICENSE.txt` 放入） |
| 5 | 字体现状入库 | git | assets 此前未追踪未忽略；本次 `assets/fonts/思源黑体/` 全量 7 档入库（约 57 MB，单文件均 < 10 MB） |

字号维持 10pt 不变；等宽字体（查看器/终端）仍走系统 `FixedFont`，不在本期范围。

### 3.4 验收标准

- [ ] 亮/暗双主题下：无任何 1px 控件边框；分隔线 ≤ 1px 且常态低存在感；
- [ ] 输入框/按钮/菜单/下拉统一圆角；
- [ ] 左/右栏浅灰底、中栏内容底色，分区清晰无描边；
- [ ] 三处面板标题行样式一致（字重、字号、灰度）；
- [ ] 滚动条无箭头、半透明滑块；
- [ ] 双主题截图走查（`--auto-screenshot`）对比改造前后，无配色回退（选中色保持 `#0765d4`）。
