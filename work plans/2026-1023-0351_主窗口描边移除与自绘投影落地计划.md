# 主窗口描边移除与自绘投影落地计划

> **状态**：待验证（代码已落地，待真机视觉走查）
> **范围**：`src/gui/main_window.py`（窗口壳改造）、`src/gui/window_resize.py`（热区适配）、`src/core/`（新增平台探测）、`assets/themes/base.qss`（撤描边 + 背景绘制迁移）、`src/gui/theme.py`（撤 `window_border` 令牌）
> **时间**：2026-10-23 03:51（设计，UTC+8）/ 2026-10-23 04:06（实施）
> **优先级**：中

## 背景

`2026-1023-0333_主窗口主题描边落地计划.md` 以 1px 描边解决了 Wayland 下窗口边界不可辨问题，**已提交固定为回退锚点 `4e8a76e`**——本计划实施不理想时整体回退到该版本。

本计划换成更贴近原生观感的路径：**撤掉描边，改客户端自绘投影**（Wayland 装饰/阴影本为客户端责任，GNOME 原生应用即自绘阴影）。X11 下 Mutter 服务端阴影仍在，自绘投影须门控只对 Wayland 生效，防双重阴影。

## 需求

1. 撤除 `base.qss` 的 `QMainWindow` 描边规则与 `theme.py` 的 `window_border` 令牌（令牌随描边退场，不留孤儿键）。
2. Wayland 会话下主窗口四围自绘投影，白底桌面边界可辨，观感对标 GNOME 原生窗口。
3. X11 会话下**无自绘投影**（Mutter 阴影独占），观感与描边方案落地前一致。
4. 最大化/全屏态投影收起（ margins 归零），还原后恢复；八向缩放热区、标题栏拖拽、窗口几何保存恢复不劣化。

## 任务量评估

**中等偏大（M+），约 0.5–1 个工作日当量**——对比描边方案（一行 QSS）大一个数量级。工作量构成：

| 构成 | 量级 | 说明 |
|---|---|---|
| 平台探测收口 | 小 | 新增 `src/core/platform_info.py`（`is_wayland()`，读 `QGuiApplication.platformName()`）+ 纯函数单测；全部平台分支只许引此一处 |
| 窗口壳改造 | **中（主战场）** | `MainWindow` 顶层开 `WA_TranslucentBackground`；状态栏显式创建并挂入中央容器底部（沿用菜单栏 reparent 先例，`src/gui/main_window.py` T7/T8 路径）；中央容器外包投影宿主层（四边等宽阴影边距）；`base.qss` 窗口底色从 `QMainWindow` 迁到宿主内层（透明顶层上 QSS 底色会填满阴影环，必须迁） |
| 投影绘制 | 中 | 首选九宫格缓存位图自绘（见方案决策）；备选 `QGraphicsDropShadowEffect` |
| 最大化态切换 | 小 | `changeEvent` 监听 windowState，最大化/全屏时阴影边距归零、恢复时还原 |
| 热区适配 | 小 | `_edges_at`（`src/gui/window_resize.py`）判定基准从窗口物理边改为视觉边（内移一个阴影边距），阴影环整圈并入缩放热区（对标 macOS 手感） |
| 视觉验证 | 中 | Wayland 真机走查（白底辨识度、缩放流畅度、最大化切换、六主题）+ X11 回归（无双重阴影）；双会话都要过 |

风险集中点：透明顶层窗口的绘制回归（`base.qss` 头部注释对背景接管有连串教训，迁移需小心）与热区偏移手感。

## 方案决策

- **投影绘制首选九宫格缓存位图自绘**：启动时离屏渲一次阴影图元（四角 + 四边），宿主 `paintEvent` 九次 `drawPixmap` 拼贴；resize 仅重拼贴不重新模糊，性能确定性高。备选 `QGraphicsDropShadowEffect`（实现约五行，但每次几何变化重算全窗模糊，拖拽缩放流畅度存疑）——仅作快速原型对照，不作交付路径。
- **阴影参数初值**：边距 16px、模糊半径约 24px、色 `rgba(0,0,0,~0.25)`，六主题共用（阴影是环境光模拟，不随主题换色）；真机走查后微调。
- **平台门控单点**：`is_wayland()` 为 True 才挂投影壳；X11 / offscreen 一律走原路（不透明顶层、无边距、无宿主）——offscreen 天然豁免，既有 264 项测试不受影响。
- **窗口圆角本期不做**：圆角需对整棵子控件树做裁剪（setMask 失抗锯齿 / 自绘裁剪复杂度高），投影按矩形走；想要圆角另立计划。

### 不做项（已知取舍，留档）

- 不为投影引入第三方库（九宫格位图程序生成，不落二进制资源文件）。
- 不处理 GNOME 边缘平铺（tiling）态的投影收起——Qt 无可靠 API 感知平铺，接受平铺时四围留阴影缝，留档为已知限制。
- 不动 `QDialog`：对话框依旧无阴影无描边，观察后续。

## 实施步骤

### 1. 撤除描边体系

- `assets/themes/base.qss`：删除 `QMainWindow { border: 1px solid $window_border; }` 规则及注释。
- `src/gui/theme.py`：六主题调色板删 `window_border` 键、`QSS_TOKEN_KEYS` 删同名项。

### 2. 平台探测（`src/core/platform_info.py`）

- 新增 `is_wayland()` / `is_x11()`，内部读 `QGuiApplication.platformName()`；docstring 注明「平台差异判断唯一入口」。附纯函数单测（mock `platformName` 双向断言）。

### 3. 窗口壳改造（`src/gui/main_window.py`）

- Wayland 分支：`MainWindow` 设 `WA_TranslucentBackground`；状态栏显式创建、挂入中央容器底部（退出 `statusBar()` 槽位，沿用菜单栏 reparent 先例）；中央容器外套投影宿主（四边 16px 边距）。
- `base.qss`：`QMainWindow` 的 `background-color` 迁至宿主内层（新 objectName，如 `#WindowShell`），`QMainWindow` 自身仅保留 `color`/`selection` 继承声明；`QDialog` 联合规则不受影响。
- X11 / offscreen 分支：维持现状零改动。

### 4. 投影绘制与状态切换

- 宿主 `paintEvent`：九宫格拼贴缓存阴影位图；首次使用离屏生成。
- `changeEvent`：最大化/全屏 ↔ 边距归零 + 投影停绘；还原逆向恢复。

### 5. 热区适配（`src/gui/window_resize.py`）

- `_edges_at` 增加阴影边距偏移参数（默认 0，X11 路径零行为变化）：判定基准内移至视觉边，阴影环整圈计入热区。

### 6. 门禁与视觉验证

- `bash scripts/check.sh` 全绿。
- Wayland 真机：白底桌面边界辨识度、拖拽缩放流畅度（重点盯 resize 时阴影是否掉帧）、最大化/还原、六主题走查、中文输入回归。
- X11 会话回归：无双重阴影、无描边、热区与拖拽与描边方案落地前一致。

### 7. 文档同步（随代码同提交）

- 本计划回写「实施回写」段并改状态；`2026-1023-0333_主窗口主题描边落地计划.md` 状态改「已归档」，注明被本计划取代、代码锚点为 `4e8a76e`。
