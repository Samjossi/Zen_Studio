# DSH 模型目录条目同步落地计划

> **状态**：草稿（官方目录核对与维护手册更新已完成，代码尚未实施）
> **范围**：DSH CLI 升级核对、Zen Studio 的 dsh-acp 静态模型表、显示名、测试与真实 ACP 验证
> **时间**：2026-11-05 21:52（设计，UTC+8）
> **优先级**：中

## 1. 背景与核对结论

用户提出 DSH 新增模型，需要同步 Zen Studio 的模型条目。经 DSH 官方仓库、npm 发布信息、DeepSeek API 文档及本机 ACP `session/new` 交叉核对，结论如下：

- npm `latest` 已为 **0.2.2-rc.1**，本机为 **0.2.1-rc.2**；0.2.2 系列要求 Node.js ≥24.9。
- DSH 0.2.2-rc.1 与 `master` 的 DeepSeek 内置目录均为两条现行模型：`deepseek-flash`、`deepseek-v4-pro`，上下文窗口均为 1,048,576 tokens。
- 2026-10-17 的 **DeepSeek-V4.1-Flash-1017** 是 `deepseek-flash` 背后的模型版本升级，API 模型 ID 不变，不应新增 `deepseek-v4.1-flash-1017` 条目。
- `deepseek-v4-flash` 是仍被 API 兼容接受的旧名，请求转由 V4.1-Flash-1017 服务；最新 DSH 内置目录已不再列出，新配置应使用 `deepseek-flash`。
- 本机 0.2.1-rc.2 的 ACP 实测仍返回旧别名，共三项；Zen Studio 的静态表与该项一致，因此当前没有可新增的第四个模型 ID。
- Zen Studio 另有一处确定错误：`src/llm/providers/dsh_acp.py` 将 `deepseek-flash` 显示名写成 `DeepSeek-V41-Flash`，应为官方目录的 `DeepSeek-V4.1-Flash`。

官方依据：

- DSH 内置模型目录：https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/src/models.ts
- DSH 模型配置指南：https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.zh.md
- DSH 0.2.2-rc.1 发布说明：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1
- DeepSeek API 更新日志：https://api-docs.deepseek.com/zh-cn/updates/
- DeepSeek 模型与价格：https://api-docs.deepseek.com/zh-cn/quick_start/pricing

上述核对结果已登记到 `维护手册/后端CLI工具维护说明手册.md` §7。

## 2. 目标模型条目

Zen Studio 的 dsh-acp 菜单目标为仅展示两个现行模型，旧别名不再作为新会话候选项：

| 处理 | 不透明模型选项值 | 显示名 | 说明 |
| --- | --- | --- | --- |
| 保留并修正显示名 | `["deepseek-official","deepseek-flash"]` | `DeepSeek-V4.1-Flash` | 当前实际后端为 V4.1-Flash-1017；不另建 checkpoint 条目 |
| 保留 | `["deepseek-official","deepseek-v4-pro"]` | `DeepSeek-V4-Pro` | 现行 Pro 模型 |
| 移除候选 | `["deepseek-official","deepseek-v4-flash"]` | — | 旧别名，上游路由至 V4.1-Flash-1017 |

模型选项值继续作为不透明 JSON 对串原样透传，不解析、不重组。本次不增加动态目录重构，不改变推理强度轴、图片能力位、默认模型记忆或会话切换语义。

## 3. 实施步骤

### 3.1 升级并冻结实测基线

1. 确认 Node.js ≥24.9，通过本机现有安装渠道将 DSH 升至 0.2.2-rc.1；`dsh --version` 验证结果。
2. 用项目 `.venv` 驱动真实 `dsh acp`，仅执行 `initialize` 与 `session/new`，不发送模型 prompt；提取 `agentInfo`、`model` 配置项和 `reasoning_effort` 配置项，脱敏保存到 `.temp/dsh_model_catalog_20261105.json`。
3. 核对最新 ACP 返回的模型值、顺序、显示名与默认强度。官方动态目录若仍返回旧别名，在实测摘要中注明；Zen 菜单仍按 §2 只保留两个现行 ID。
4. 若新版 ACP 的 `configId`、选项值结构或连接行为发生漂移，暂停本计划并另立协议适配任务，不把协议变化混入静态表更新。

### 3.2 更新静态目录与相邻说明

1. 修改 `src/llm/providers/dsh_acp.py`：
   - `_DSH_MODELS` 按最新实测顺序保留 `deepseek-flash`、`deepseek-v4-pro` 两项，移除 `deepseek-v4-flash`；
   - `_DSH_DISPLAY_NAMES` 同步删除旧别名，并将 `DeepSeek-V41-Flash` 修正为 `DeepSeek-V4.1-Flash`；
   - 更新静态表注释中的实测日期与证据位置，保留“模型值原样透传”的约束说明。
2. 修改 `src/llm/registry.py` 的 dsh-acp `dev_note`，将接入验证版本从 0.2.0-rc.2 更新为实际验证通过的 0.2.2-rc.1；其余注册行为不变。
3. 检查 `src/llm/README.md` 的 DSH 静态表说明，补充现行两条目及旧别名处理口径；历史帧存档保持原样，不改写旧实测证据。

### 3.3 更新回归测试

1. 修改 `tests/test_dsh_backend.py` 的模型基线为 §2 的两个选项值，并移除旧别名预期。
2. 显示名测试除覆盖全部模型外，精确断言 `deepseek-flash` 对应 `DeepSeek-V4.1-Flash`，防止点号再次丢失。
3. 断言旧别名不再出现在 `list_dsh_models()`，现有注册、探测链、强度回退测试保持不变。
4. 增加或更新一个持久化兼容用例：设置中若仍保存旧别名，模型菜单与后端不得崩溃；发送时沿用现有“切换失败则保持 agent 默认/新会话重试”降级，不做静默字符串改写。

### 3.4 验证与交付

1. 运行聚焦测试：`.venv/bin/python -m pytest tests/test_dsh_backend.py`。
2. 运行完整门禁：`bash scripts/check.sh`，隐私扫描、lint 与全部测试通过后才可交付。
3. 在真实 DSH 0.2.2-rc.1 + ACP 环境验证：
   - ModelBar 的 DSH 菜单仅显示两个现行模型，名称与 §2 完全一致；
   - 两个模型均可切换，`off/low/high/max` 档位行为不回归；
   - 分别以两个模型完成一轮真实对话，流式正文、思维链、工具帧与 `usage_update` 正常；
   - 曾保存旧别名的配置可正常打开并重新选择现行模型，无崩溃或伪造模型名。
4. 实施后在 `文档/修改记录/` 补修改记录，回链本计划与实测摘要，并将本计划状态更新为已实施；真实对话未执行时不得标记全部验证完成。
