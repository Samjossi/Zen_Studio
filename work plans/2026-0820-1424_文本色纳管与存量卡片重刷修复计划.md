# 文本色纳管与存量卡片重刷修复计划

## 1. 目标

1. **文本色令牌化收口**：全部文本编辑类控件（QTextBrowser/QTextEdit/QPlainTextEdit/QLineEdit 及其子类实例）文字色纳入 `text` 令牌管理，深浅主题下均正确着色。
2. **存量块重刷**：聊天卡片轨已存在的块（气泡/工具卡/思维链/diff 卡等）在主题切换时同步换色，消灭「切换后白底黑字」。
3. **零散漏网清零**：模块级 `CHAT_PACK` 捕获、跨主题固定 `WARNING_COLOR`、开关轨道硬编码色、输入框选区带无刷新、图委托默认色残留，逐项纳管。
4. **亮色四主题视觉零回归**：渲染 diff 仅允许白名单内差异（新增 color 声明行），offscreen 截图对比确认。

## 2. 根因（已实证，非推测）

`base.qss:18` 注释论断「qss 的 color/selection 沿控件树继承」**对文本编辑类控件不成立**。offscreen 逐像素探针实测：

- `QMainWindow { color: #eeeeee }` 下 `QLabel` 文字渲染为浅灰 ✅ 继承
- 同条件 `QTextBrowser`/`QTextEdit`/`QPlainTextEdit`/`QLineEdit` 文字像素恒为 `(0,0,0)` ❌ 不继承——落到 widget 调色板 Text 角色，而主题切换只设样式表不碰 palette（`gui/settings_dialog.py:15` 注释自证）
- 仅当 QSS 规则**显式命中该类**并写 `color` 才生效（`markdown_view.py:214` 的 document 默认样式表是既有正确范式）

亮色四主题正文色 ≈ 黑，缺陷潜伏；深色主题使其系统性暴露。次要根因：聊天卡片族颜色在构造期冻结进内联 QSS/HTML，`transcript.py:193` 注释自认「主题切换仅影响此后新建的块」。

### 4.2 B 类：存量块重刷机制

原则：**CardColors 袋共享引用语义不变**，每块类保留袋引用 + 原始数据，新增 `refresh_colors()`；`ChatTranscriptView.apply_theme` 更新袋后遍历已建块逐个调用。

```python
# gui/panels/chat/transcript.py（示意）
def apply_theme(self, user_bubble_bg, tool_output_bg, link_fg):
    self._colors.user_bubble_bg = user_bubble_bg   # 既有 setter 逻辑保留
    ...
    for block in self._iter_blocks():              # 新增：存量块重刷
        block.refresh_colors()

# UserBubbleBlock：构造时留存 content/images，refresh_colors 重建内联 QSS
# 与链接化 HTML（颜色全部从袋重取）
# ToolCard：refresh_colors 重建外壳 QSS + 标题/状态 label 样式
# 思维链/diff 卡：构造时留存原始文本/hunk 数据，refresh_colors 重生成 HTML
```

- 逐块实施时如某卡类原始数据未留存，先补簿记再重渲染，**不做近似刷新**（防色值与数据不一致的中间态）。
- 决策点 D2：**旧轨 ChatOutput 存量块不追溯**。旧轨已是冻结回退通道（0645 计划 D2-A），其正文色经 A 类 `QTextEdit` 规则自动修复，存量 HTML 内联色（气泡底/思维链灰等）维持「仅影响此后追加的块」语义。新轨卡片为默认轨，重刷投入集中在该处。
