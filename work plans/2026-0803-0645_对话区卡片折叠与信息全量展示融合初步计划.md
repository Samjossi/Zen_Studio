## 1. 背景与定位

### 1.1 两份前序计划的关系（已厘清）

0619 与 0640 **信息层正交、渲染层冲突**：0619 的信息补全（diff/成果
摘要/尾窗/统计）与载体无关；但其渲染层（QTextBrowser 锚点泛化 +
就地改写）与 0640 的载体迁移互斥。0640-D3 原拟「信息层并入、渲染层
取代」，本文在此之上更进一步——**不只是并入，而是全面升级**。

### 1.2 为什么截断规格可以放宽

0619 的每条信息截断都是「防刷屏」的产物，其前提（行文本追加流、
信息一上屏就永久占版面）在折叠载体下不复存在：

| 0619/现状规格（防刷屏产物） | 折叠载体下的新前提 |
|---|---|
| bash 输出截尾末 20 行（`_OUTPUT_KEEP_LINES = 20`） | body 折叠不占版面；展开后限高**内滚动**，行数多也只是块内滚动 |
| 非 execute 工具输出正文**整键丢弃**（panel.py:706-710） | read/search/fetch 的正文放进各自折叠卡 body，默认折 |
| 子代理成果摘要截 10 行 | 同上，软上限内全量 |
| diff 只渲 hunk、超 200 行截断 | hunk 全量渲，软上限放宽（D4） |
| read/search/fetch 仅尾注「—— N 行」（0619-D5-A 淘汰输出卡） | 「N 行」保留为标题行尾注，body 同时给正文（0619-D5-B 在折叠载体下重新激活） |

**结论**：折叠把「信息多」从版面负债变成可选资产——信息规格的
上限不再由「不刷屏」决定，只由**单卡性能软上限**决定（§2.4）。

### 1.3 不变的边界

- 协议事实 F1–F5（1425）全部有效：子代理内部步骤仍不可得（F2
  永久边界）；edit diff 项非必填，缺省降级不臆造。
- kilocode 对标模式 P1–P8（0640 §1.3）与默认开合约定全部继承。
- QWebEngine 不复议（项目四次否决立场）。
- 只上屏不入历史（红线）、不动 ACP 连接层/审批链路。

## 2. 信息全量规格（本文核心变化）

### 2.1 各类工具卡信息规格总表

「标题行」折叠态常驻可见；「body」展开可见，均为限高内滚动只读块。

| 卡类型 | 标题行（常驻） | body（展开） | 默认开合 |
|---|---|---|---|
| **BashCard** | `▾ $ <命令首行>` + 状态图标 | 完整命令 + **输出全量**（软上限截尾，见 2.4）+「共 N 行」尾注；运行中尾滚 5 行实时帧，完成定格 | **开**（P2） |
| **DiffCard**（edit/write） | `▸ ✎ <path>` + `+N −M` 红绿徽标 | **hunk 全量**三色卡（@@ 灰 / + 绿 / − 红），软上限放宽（D4）；无 diff 项时退化为纯标题行 | **折**（P2） |
| **ReadCard** | `▸ ☐ Read — <path> —— N 行` | **文件内容正文**（软上限**截首保头**，区别于 bash 保尾，见 2.4） | 折 |
| **SearchCard** | `▸ ☐ Search — <pattern> —— N 行` | **命中结果正文**（同截首保头） | 折 |
| **FetchCard** | `▸ ☐ Fetch — <url> —— N 行` | **抓取正文**（同截首保头） | 折 |
| **SubagentCard**（think/task） | `▾ ⧉ Agent — <description>` + 子状态 | **成果摘要全量**（`<task_result>` 提取，无标记取全文；软上限截首保头；D5） | 运行中开、完成折（P2） |
| **MCP/未知工具卡** | `▸ ☐ <name> — <首个参数摘要>` | 入参 JSON + 输出 JSON 两节（对标 kilocode McpTool） | 折 |
| **TodoCard** | `▾ ☑ 任务清单 — N/M 项完成` | checkbox 列表（完成项灰+删除线，进行中 ▶） | **常开**（P7，不可折） |
| 任意工具 **failed** | `✖ <标题>`（红） | **错误详情全量**（现仅错误首行截 80——放宽为完整错误文本，软上限内） | **自动展开**（异常必见） |

### 2.2 通用「入参区」（D3）

每张工具卡 body 末尾附弱化灰的**入参小块**：格式化展示 rawInput
关键字段（command/path/pattern/url/todos…，按 kind 取已知键 +
JSON pretty 兜底）。这是「尽可能全」的兜底保证——即使专门渲染
未覆盖的字段也不丢信息。MCP 卡 body 本身即入参+出参，不重复附。

### 2.3 协议层/路由层配套改造

1. `acp._extract_tool_output`：截尾行数参数化——`_OUTPUT_KEEP_LINES`
   20 行规格拆为两档：**完成态卡 body 软上限**（D2，建议 1000 行）与
   **运行中尾窗**（5 行，不变）；新增**截断方向**参数（execute 保尾、
   read/search/fetch/think 保头），截断时 `output_total_lines` 仍为
   原始行数供尾注。
2. `panel._on_activity_chunk`：**取消非 execute 工具的 output 剥除**
   （panel.py:706-710 现状整键丢弃）——所有工具的 output 随载荷进
   渲染层，由对应卡 body 承接。
3. `result_summary`：取消 10 行硬截断，全量交付渲染层（软上限内
   截首保头由协议层统一执行，同 2.3-1）。
4. `diff_hunks`：截断上限放宽（D4，建议 1000 行），截断标记保留。
5. failed 错误提取：首行截 80 → 完整错误文本（软上限内）。
6. 兜底文本同步纪律不变（改一处须同步）。

### 2.4 单卡性能软上限（唯一保留的截断）

折叠化解版面压力，但不化解**单块渲染成本**。统一纪律：

- 每个卡 body 正文软上限 **N_max 行**（D2，建议 1000 行），超限
  截断 + 灰字尾注「共 N 行，仅显示前/末 M 行」；
- 截断方向按 kind：execute **保尾**（排障看尾），其余**保头**
  （读/搜/抓取看头）；
- body 一律**限高内滚动**（固定最大高度 + 块内滚动条），卡片自身
  高度有界，不撑爆 QScrollArea 布局；
- 「打开全文」落盘链接仍不做（1000 行已覆盖排障主场景，真实需求
  出现再单独立项——继承 0619 §5 判定）。
