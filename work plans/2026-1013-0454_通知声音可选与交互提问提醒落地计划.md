# 通知声音可选 + 交互提问（AskUserQuestion）声音与横幅提醒落地计划

> 前置：`work plans/2026-1013-0430_任务完成声音与通知横幅落地计划.md` 已落地（声音+横幅骨架、两个总开关、备选池/正在使用目录）。本计划在其上扩展。

## 需求

1. `assets/sounds/备选池/` 写 README：说明此处为**备用声音资产库存**，运行时不消费，仅作存档供挑选。
2. `assets/sounds/正在使用/` 写 README：说明此处资产均**从备选池复制而来**，是运行时实际消费与用户在设置中心挑选的范围。
3. 设置中心「通知」页：用户经**下拉框**从 `正在使用/` 目录的 wav 文件中挑选各事件的提示音（任务成功 / 任务失败）。
4. 新增「交互提问」事件：AI 弹出 AskUserQuestion 类交互卡时，与任务成功/失败一样**播放提示音（可选文件）+ 弹出顶部横幅**。

## 关键探查结论（已核实）

- **通知页现状**：`src/gui/settings_dialog.py:502-535` `_build_notify_page`（两个复选框 + 一个试听按钮），回读 `:594-596` `_reload_notify`；新设置项标准流程见文件头 docstring。
- **播放模块现状**：`src/gui/sound_player.py:31` `play_completion_sound(success)` 硬编码 `done.wav`/`error.wav`（`:17-18`），QSoundEffect 主路径 + aplay/paplay/play 兜底已定型，重构时保留。
- **完成提醒接线现状**：`panel.py` `turn_completed` 信号 → `tabs.py` 转发 → `main_window.py:831-839` `_on_turn_completed` 读两个总开关分别触发声音/横幅。交互提问照此同构接线。
- **交互提问钩子点**：`src/gui/panels/chat/panel.py:845-847` `_ask_permission` 的 question 特判分支（`is_question_request` 命中 → `QUESTION_BRIDGE.ask`）。注意 `_ask_permission` 在 **agent reader 线程**执行，提醒须走 Qt 信号跨线程到 GUI 线程（`turn_completed` 同此模式，Qt 信号跨线程 emit 天然安全）。横幅/声音在「提问请求到达」即触发，不等用户作答。
- **横幅现状**：`src/gui/notification_banner.py:79` `show_completion(success, detail="")` 单入口，标题/配色按 success 二态写死；需泛化出第三态（提问）。
- **设置持久化**：`src/gui/settings.py:70-72` 现有两个 bool KEY；新增 str 型 KEY 走同一套 `AppSettings`/`AppSettingsPatch`/`DEFAULT_SETTINGS` + flock 原子写。
- **资产目录纪律**（`assets/README.md:17-18`）：`正在使用/` 打包、`备选池/` 不打包已登记；`building/zen-studio.spec` 的 datas 按整目录收编——两个 README.md 放进目录后，`正在使用/README.md` 会随目录被打包（无害，说明书随产物走），`备选池/README.md` 不打包（正常）。

## 默认行为决策

- **交互提问默认音**：从备选池复制 `alert-01.wav` → `正在使用/question.wav` 作为默认值（alert 族语义=需要用户注意）。
- **提醒开关**：交互提问**复用现有两个总开关**（声音开关管三类事件的声音、横幅开关管三类事件的横幅），不新增第三套开关——保持设置面简单。
- **下拉框持久化**：存**文件名**（str，如 `"done.wav"`），不存绝对路径（便携 + AppImage 兼容）。
- **缺失文件兜底**：设置的文件名在 `正在使用/` 中不存在时，播放侧静默跳过（与现状文件缺失语义一致）；下拉框回读时若持久化值不在扫描结果内，临时插入该项并标注「（缺失）」，不静默篡改用户选择。
- **试听**：每个事件行各一个「试听」按钮，试听播当前下拉框选中文件，不受总开关影响（沿用现状语义）。

## 追加实施：横幅「试看」按钮（2026-10-13 05:47）

> ⚠️ 本节所述「软件内横幅 + 试看发 `show_notification`」已被下一节

- 决策：与试听同例——试看**不受总开关门控**、不改动开关持久化值；三事件态（success / error / question）各一按钮，便于分别核对三种标题与强调色（成功主题色 / 失败警示红 / 提问琥珀色）。
- 落地：
  - `src/gui/main_window.py` 新增公开入口 `preview_notify_banner(kind)`：不经开关门控，直发横幅懒创建单例 `show_notification(kind)`。

- 测试：`tests/test_notification.py` 新增 `test_banner_preview_buttons`（逐行触发对应事件态、开关关闭亦可试看且不改动开关值）与 `test_main_window_preview_banner`（不经门控直发指定事件态）。

## 追加实施：横幅改系统级桌面通知（notify-send）（2026-10-13 05:56）

- 起因：用户澄清「顶部通知横幅」要的是**操作系统级**桌面通知（`notify-send` 经 D-Bus 交桌面守护进程弹出），而非软件内自绘横幅——窗口最小化/被遮挡/切走桌面时软件内横幅根本看不到，提醒失去意义。拍板：**替换**（不并存），设置键与开关名不动（`KEY_NOTIFY_BANNER_ENABLED` 语义直接改指系统通知）。
- 决策：
  - 实现走外部命令 `notify-send`（freedesktop 通知规范通用 CLI，桌面发行版自带），同 `sound_player` 的 aplay/paplay/play 先例：命令缺失静默跳过，不引新依赖；AppImage 调宿主机命令不受打包影响。
  - 命令形态：`notify-send -a "Zen Studio" -t 4000 [-i logo_64.png] 标题 正文`；三态标题/默认正文沿用原软件内横幅文案（任务完成 / 任务失败 / 需要你的回答），用户认知不变；强调色、4 秒淡出等自绘语义随之废弃（样式与消退由桌面环境管理）。
  - 三个「试看」按钮保留，触发目标同步改为 `notify_event(kind)`（仍不经开关门控）。
- 落地：
  - 新建 `src/gui/desktop_notifier.py`：`notify_event(event, detail)` + `notify_completion(success)` 薄封装（对偶 `sound_player` 的 play_event_sound/play_completion_sound）；`shutil.which` 探测 + Popen 子进程持有防僵尸。
  - `src/gui/notification_banner.py`（软件内横幅组件）**整体删除**；`src/gui/main_window.py` 去 `_notify_banner` 字段与 `_get_notify_banner` 懒创建，`_on_turn_completed` / `_on_question_asked` / `preview_notify_banner` 改调 desktop_notifier。
  - `src/gui/settings.py` 键注释、`src/gui/settings_dialog.py` 常量注释与 hint（补「窗口最小化或被遮挡时也能送达，样式与消退由桌面环境管理」）、`src/gui/panels/chat/panel.py` 与 `tabs.py` 信号注释同步改述。
- 测试：`tests/test_notification.py` 删三个横幅控件测试，新增四项 notifier 测试（事件态映射与 detail 覆盖、未知事件静默、notify-send 缺失静默、命令形态断言）；门控与试看测试改为 mock `notify_completion`/`notify_event`。
- 验证：真机端到端发送两条系统通知（成功 + 提问）肉眼确认弹出；`bash scripts/check.sh` 全绿（隐私扫描 ✔、lint ✔、154 项测试全过）。
