# 四后台移除与 Local 解封落地计划

> **状态**：已实施（真实 Local CLI 模型对话未验证）
> **范围**：AI 后台注册表、四个待移除后台的 provider、Local 解封、相关测试与现行文档
> **时间**：2026-11-20 14:52（设计）(UTC+8)
> **优先级**：中
> **依据**：用户指示：移除 Reasonix、OpenCode、Kilo Code、Dream，最终仅保留 Kimi、DSH、Local

---

## 1. 背景与目标

当前 `src/ide/llm/registry.py` 注册七个后台：Kimi、DSH、Reasonix、OpenCode、Kilo Code、Dream、Local。其中 Reasonix、OpenCode、Kilo Code、Local 已封存；Dream 仍为开发中接口。

本次将 IDE 的后台集合收敛为三个：

| 顺序 | 后台 | 接口实现名 | 目标状态 |
|:---:|:---|:---|:---|
| 1 | Kimi | `kimi-acp` | 保持现行行为 |
| 2 | DSH | `dsh-acp` | 保持现行行为与 developer preview 提示 |
| 3 | Local | `local-acp` | **解除封存，恢复正常发送路径** |

移除 Reasonix、OpenCode、Kilo Code、Dream 的 IDE 运行接入及对应菜单项，不再以“已封存”形式保留入口。保留三家仍依赖的公共 ACP 连接、协议解析、GUI 卡片与审批能力，不做无关重构。

## 2. 移除与保留边界

- 删除四个 provider：

  - `src/ide/llm/providers/dream_acp.py`

- 删除 `src/ide/llm/registry.py` 与 `src/ide/llm/__init__.py` 中四个后台的导入、注册项和 re-export。
- 删除只用于已移除后台、且不再具有回归价值的专用脚本或测试；优先明确处理：
  - `scripts/capture_reasonix_ask_frames.py`
  - `tests/test_kilocode_archived.py`

### 2.2 保留项

- 保留 `src/ide/llm/providers/acp.py`、`src/ide/llm/base.py`、注册表缓存、模型与推理强度公共机制。
- 保留 `BackendSpec.archived`、`dev_note` 与 `ChatPanel` 的通用封存/提示机制。本次只是不再注册封存后台，不借精简之名拆除通用能力；DSH 仍使用 `dev_note`。
- 保留提问、TODO、子代理嵌套、图片、terminal 等公共协议兼容逻辑。代码或测试最初源自 Reasonix/Kilo Code 帧，不等于该代码只服务已移除后台；Kimi 的子代理 wire 旁路仍复用层级 ID 机制。
- 保留 `dream-acp/` 独立协议与示例目录。`src/ide/llm/providers/local_acp.py` 仍以其中的协议文档为参考，不能随 Dream 菜单一并删除；现行文档须明确它不再是 Zen Studio 的 Dream 后台注册入口。
- 保留 `参考代码/`、`文档/帧存档/`、历史计划、修改记录、审计报告及致谢。历史资料不改写成“从未接入”；仅更新声称当前仍有七后台或当前仍注册 Dream 的文档。
- 不卸载本机任何 CLI，不修改用户目录下的配置、凭证或会话数据。

## 3. 现状锚点与隐藏影响面

1. **菜单与设置中心无需各自删项**：ModelBar 和设置中心均从注册表派生后台列表，删除注册项后两处会同步收敛。
2. **Local 需要反转三处封存数据**：`vendor_label` 恢复为 `Local`，`archived=False`，移除封存用 `dev_note`；provider 本体、GGUF 枚举和 `auto` 单档强度不变。
3. **注册表顺序断言会失效**：`tests/test_local_backend.py` 目前锁定旧七后台顺序，需改为锁定目标三后台的完整顺序，而非只检查 Local 仍存在。
4. **封存测试以被删后台为样本**：`tests/test_kilocode_archived.py` 不能原样保留；Local 解封断言并入 `tests/test_local_backend.py`。
5. **旧配置不能手工抹除**：`config/settings.json` 及用户运行配置中的已删除接口名、模型记忆不主动清理。须验证持久化值指向已删除接口时，现有未知接口回退链能落到首个可用后台，不崩溃、不启动已删除 provider。
6. **公共兼容测试仍有价值**：`tests/test_question_permission.py`、`tests/test_subagent_nested.py` 及相应 fixtures 可继续作为协议回归样本，但测试名或 docstring 不应暗示相应后台仍是现行可选项。
7. **专用探针需收缩**：`scripts/probe_subagent_frames.py` 删除 Reasonix、Kilo Code 目标，保留 Kimi 探针；通用 terminal 探针等不因注释中的历史名称而删除。

## 4. 设计决策

- **D1：最终注册表精确等于三项**：顺序为 `kimi-acp → dsh-acp → local-acp`，不保留空壳、别名或隐藏注册项。
- **D2：Local 是真正解封，不只是改显示名**：切换与发送均不得再被 `_blocked_by_archive` 拦截；未安装 Local CLI 时仍按普通“未检测到”逻辑禁用，不伪造可用状态。
- **D3：最小删除而非公共能力大清仓**：只删后台专属实现及确定失效的专用代码，公共协议兼容与通用封存机制保持原行为。
- **D4：运行接入与资料库分开处理**：`dream-acp/`、历史文档和帧存档属于资料；四个 provider 和注册项属于运行接入。本次删除后者，不销毁前者。
- **D5：用户配置只兼容，不清洗**：已删除后台的持久化值自然失效并回退；不批量改写用户配置，不删除旧模型记忆。
- **D6：现行文档同步收口**：根 README、术语表、LLM 包说明、维护手册统一改为三后台；历史文档保持原貌。

## 6. 风险与注意点

- **Local 当前未检测到**：解封可被代码和 GUI 状态验证，但真实本地模型对话依赖外部 CLI 与 GGUF 配置；缺环境时须如实保留未验证项。
- **旧会话/配置指向已删除后台**：必须走现有回退链，不得因为 import 删除或空模型列表导致启动失败。
- **公共协议代码误删**：层级 ID、提问字段兼容、TODO 与审批逻辑可能被多个后台共享，不能按名称机械删除。
- **Local 的协议参考仍指向 `dream-acp/`**：保留该目录是本次边界的一部分；若未来要彻底移除，需先另行迁移 Local 的协议文档，不在本次扩展。
- **手册信息真实性**：Local 的安装与更新命令须以可核实的现行资料为准，不能从 Dream 或旧文档猜测。
- **外部安装不动**：本次只改项目内代码与文档，不删除 Reasonix、OpenCode、Kilo Code、Dream 的本机安装和用户数据。

**验证结果**：

- 注册表命令断言三后台精确顺序、三家 `archived=False` 和 Kimi/DSH/Local 显示名均通过；本机可用性为 `Kimi=True`、`DSH=True`、`Local=False`。

**经验沉淀**：

1. 后台菜单由注册表派生时，删除注册项即可同步收敛 ModelBar 与设置中心，不应在多个 GUI 入口复制删项逻辑；通用 `archived` / `dev_note` 能力与具体封存注册项必须分开处理。
2. 已删除接口的持久化值应利用 `spec_of() → None` 与 ModelBar 逐级回退自然失效，验证重点是“回退、不改写、不起旧进程”，而不是清洗用户配置。
3. provider 删除不能以名称匹配扩大为协议能力清仓。历史帧 fixtures、层级 ID、提问字段兼容、TODO 与审批逻辑仍可服务现行后台，应把测试描述改为历史兼容输入并保留行为断言。
4. “未安装”与“已封存”是两条独立状态轴：Local 解封后仍可由 `available()` 禁用并标注“未检测到”，不能用可用性状态伪造真实模型验收结果。
5. 现行文档与历史资料应分开扫描；旧构建产物和历史实测归属也不需要为了形式上零命中而篡改。
