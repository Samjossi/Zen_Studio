# work plans

本目录用于存放项目的 **Work Plans（工作计划）**。

计划文档用于将章程拆分为可执行、可追踪的任务清单，通常包含：
- 阶段划分
- 任务列表与优先级
- 预计起止时间
- 负责人
- 检查点与依赖关系

文件命名遵循 `文档编写规范.md`：
- 根目录文件：`YYYY-MM-DD-HH_计划标题.md`
- 中文优先，英文名后置

## 实施回写规范

计划实施完成后，**必须将实施过程回写到原计划文档**，而不是只写修改记录或口头汇报。回写是计划文档的必备收尾，包含三部分：

1. **与计划的偏差**：实际改动与计划不一致之处及原因，包括计划遗漏的隐藏改动点（如测试桩签名、报错消息、输出文件的描述性字段），不得只写"按计划完成"。
2. **验证结果**：实际执行的验证命令与结果（测试通过数、check 脚本、真实端到端验收的关键数据），以及验证成果保留位置；未做的验证须明确说明。
3. **经验沉淀**：可复用的教训与设计判断，供后续计划直接引用，避免重复踩坑。

回写时将文档状态从"草稿"更新为"已实施"，并在 `文档/修改记录/` 保留对应修改记录；计划文档写"过程与经验"，修改记录写"改动清单与验证"，两者互相引用、不互相替代。
