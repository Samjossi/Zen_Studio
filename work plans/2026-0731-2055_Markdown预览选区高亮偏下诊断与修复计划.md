# Markdown 预览选区高亮纵向偏下诊断与修复计划

## 1. 问题现象

Markdown 预览页（`gui/panels/viewer/markdown_view.py`，QTextBrowser +
`setMarkdown` GitHub 方言）中鼠标滑选文本，选区高亮带**纵向偏下**：
带上缘几乎贴字形顶，下缘悬出一条空白，高亮视觉重心落在字的中下段。
对照参考截图（KiloCode 侧编辑器选区），高亮带上下对称包裹文字，
呈"气泡"观感；本侧呈"下垂荧光笔"观感。

## 2. 结论先行（根因）

🔴 **这不是 CSS 盒子问题，"给高亮加 padding" 的机制不存在。**
Qt 原生选区绘制的高亮带几何 = `QTextLine` 整行高（含 leading），
由字体度量直接决定，Qt 富文本的选区不是盒子模型元素，
CSS `padding` 对其无效。

实证根因链：

1. 预览页文档默认字体 = 库内自带**思源黑体 Source Han Sans CN**
   （`gui/theme.py` `BUNDLED_FAMILY`，注册于 `register_bundled_fonts()`）；
2. 该字体把额外行距打包为 **lineGap（leading）**：10pt 下
   ascent 11.44 + descent 1.55 + **leading 6.50** = lineSpacing 19.48；
3. Qt（PySide6 6.11.1）排版把 **leading 全部垫在行框底部**
   （ascent 顶对齐行框顶，leading 落在 descent 之下）；
4. 选区带按整行高 20px 绘制，字形墨盒仅 13px 且贴行框顶 →
   **带上缘留白 2px、下缘留白 7px，带中心较墨盒中心偏下 +2.5px**；
5. 对照字体更纱黑体 Sarasa Term SC leading=0，上下留白 2/3px，
   偏差仅 +0.5px —— 故代码查看器/聊天输出路径无此观感。

## 3. 诊断方法与实证记录

探针 `.temp/probe_selection_metrics.py`（临时产物不入库）：
offscreen QPA 复现生产链路（QTextBrowser + `setMarkdown` +
思源黑体 10pt + `测试文档_003.md` 原文），几何/像素双层度量。

### 3.1 几何层（QFontMetricsF / QTextLine / glyphRuns 墨盒）

| 字体 @10pt | ascent | descent | leading | lineSpacing | 行框高 | 墨盒高 | 行框顶-墨顶 | 行框底-墨底 |
|---|---|---|---|---|---|---|---|---|
| Source Han Sans CN | 11.44 | 1.55 | **6.50** | 19.48 | 20px | 12.98px | 0.00px | **7.02px** |
| Sarasa Term SC | 12.53 | 3.70 | 0.00 | 16.23 | 17px | 16.23px | 0.00px | 0.77px |

glyph runs 引擎字体解析均为字体本身（无回退混入），嫌疑锁定度量本身。

### 3.2 像素层（有/无选区两帧 grab 逐行差分）

| 字体 | 选区带纵向 | 字形墨纵向 | 带上缘留白 | 带下缘留白 | 带中心偏差 |

| Sarasa Term SC | (45,61) 高17px | (47,58) 高12px | +2px | +3px | +0.5px |

| 字体 @10pt | leading | lineSpacing | 备注 |
|---|---|---|---|
| Noto Sans CJK SC | 0.00 | 18.81 | 额外行距内嵌 ascent/descent，天然上下分摊 |

### 3.4 探针坑位记录（复用探针者必读）

- ⚠️ QTextBrowser 未 `show()` 时块布局 `lineCount()=0`，此时
  `lineForTextPosition()` 取行对象**直接段错误核心转储**——
  offscreen 探针必须先 `show()` + `processEvents()` 触发排版；
- ⚠️ `QTextLine.position()` 是**块内坐标**，与视口坐标差块偏移，
  像素层定位须走全图差分或 `cursorRect()`，不可混用；
- ⚠️ 墨迹行检测须裁剪到选区带纵向跨度内，否则被相邻行字形污染。

## 4. 对「加 padding」提议的机制纠正

提议的效果目标（文字与高亮边缘留白对称、呈图 2 气泡感）✅ 正确，
采纳为验收标准；但实现机制 ❌ 不成立——原生选区带无 CSS 盒子，
无 padding 可加。留白只能经下列三条真实机制之一达成：
换度量（§5 方案 B/C）、换绘制（§5 方案 A）。

## 8. 实施记录（方案 A，2026-07-31 21:20）

### 8.1 改动清单（仅 `gui/panels/viewer/markdown_view.py` 一文件）

1. **抑原生带**：构造器设控件级 qss
   `selection-background-color: rgba(0,0,0,0); selection-color: palette(text)`
   ——qss 的 accent 选中色规则沿控件树继承自 `assets/themes/base.qss`
   的 `QMainWindow, QDialog` 选择器，控件级声明优先；选中文字保持
   正文色（原生反白在透明带上会不可读）；
2. **自绘带**：`paintEvent` 基类绘制后叠绘——`_selection_rects()`
   逐行一段算视口矩形（块内行坐标→视口锚点取块首 `cursorRect`，
   横向端点 `QTextLine.cursorToX`，选及换行符行尾补 4px 小尾巴对齐
   原生观感），纵向 = 行 `ascent+descent` 墨盒上下各加
   `SELECTION_PAD_Y=3px`，`SELECTION_RADIUS=3px` 圆角、
   `SELECTION_ALPHA=110` 半透明叠绘（保文字可读）；
3. **色源**：`apply_theme` 注入调色板 `accent`（守单一来源纪律，
   未新增主题令牌），缺省回退 QPalette Highlight；
4. 模块 docstring 增补方案 A 机理说明。

### 8.3 如实记录的偏差与取舍

- **横向未加留白**：原生选区横向贴齐字形边界是编辑器通例（图 2
  参考侧同样贴齐），"左右留白 6px"诉求系气泡卡片语义误植于文本
  选区，故自绘带横向保持贴齐，仅圆角软化；
- 多行选区相邻带各自圆角，行界处有 3px 微凹（VS Code 为直角），
  观感影响微小，如需直角将 `SELECTION_RADIUS` 置 0 即可；
