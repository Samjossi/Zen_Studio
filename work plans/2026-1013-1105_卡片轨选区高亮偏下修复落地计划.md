## 1. 需求背景

用户真机反馈（2026-10-13，双截图对比确认）：**AI 聊天面板的文本选区高亮相对文字上下不居中（偏下），终端面板的高亮正常**。

该问题与 2026-07-31 修过的「选区高亮偏下」同根因，当年已诊断并修复：

- `2026-0731-2055_Markdown预览选区高亮偏下诊断与修复计划.md` — 诊断 + 方案 A（自绘选区带）落地 Markdown 预览；
- `2026-0731-2208_聊天区选区高亮偏下修复与视觉验证闭环经验.md` — 方案 A 通用化：新建公共辅助 `src/gui/selection_band.py`，接入旧轨聊天输出与输入框。

本计划 = 把同一套修复机制接到当前默认渲染轨（卡片轨）的正文组件上。

## 2. 现状诊断

**根因（沿用 2055 计划结论）**：库内自带思源黑体把额外行距打包为 leading（10pt 下 6.5px），Qt 排版把 leading 全部垫在行框底部；Qt 原生选区高亮带 = QTextLine 整行高（含 leading），带上缘留白 2px、下缘 7px，视觉偏下约 2.5~3px。终端面板走自绘字符网格 + 更纱黑体（leading=0），从未走 Qt 富文本选区路径，所以一直正常。

**修复本体完好**：`src/gui/selection_band.py` 的 `SUPPRESSION_QSS`（抑原生带）+ `selection_rects()` + `paint_selection_band()`（行墨盒上下各 3px 对称留白自绘半透明圆角带）仍挂在三处——旧轨 `src/gui/panels/chat/output.py`、`src/gui/panels/chat/input.py`、`src/gui/panels/viewer/markdown_view.py`，实测修复后中心偏差 0.0px。

**为什么复发**：8 月卡片化改造后默认渲染轨切到卡片轨（`src/gui/settings.py` `DEFAULT_CHAT_RENDERER = "cards"`，`src/gui/panels/chat/panel.py` 默认实例化 `ChatTranscriptView`），带修复的旧轨 ChatOutput 已成冻结保留的回退通道，用户实际看不到。新轨正文全部落在：

- `BodyHtml`（QTextBrowser 子类，`src/gui/panels/chat/cards.py`）——`TextStreamBlock`（AI 正文）、`SystemBlock`、`UserBubbleBlock` 气泡体（`src/gui/panels/chat/transcript.py`）、各工具卡正文均继承/持有它；
- `BodyText`（QPlainTextEdit 子类，`src/gui/panels/chat/cards.py`）——bash 输出等等宽正文块。

这两类**均未挂抑制 qss、无 paintEvent 自绘带**，原生偏下高亮带在默认卡片轨全面回归。

## 3. 方案设计

**D1（BodyHtml 接入，主修复面）**：`cards.py` `BodyHtml.__init__`——

- 现有 ID 选择器样式表并入抑制声明：`#CardBodyHtml { background: transparent; border: none; selection-background-color: rgba(0,0,0,0); selection-color: palette(text); }`（沿用 0811 规约：禁无选择器写法，防级联进右键菜单）；
- 覆写 `paintEvent`：基类绘制后调 `paint_selection_band(self, color)`。

一处接入，`TextStreamBlock` / `SystemBlock` / `UserBubbleBlock` 气泡体 / 全部工具卡 BodyHtml 实例自动继承。

**D2（BodyText 接入）**：同 D1 机制接入 `#CardBodyText` 样式表与 `paintEvent`。`selection_rects()` 基于 QTextBlock layout + cursorRect，QPlainTextEdit 路径当年已在 `input.py` ChatInput 验证可行，无需改造公共辅助。

**D3（带色口径）**：沿用 `input.py` 先例——构造可选注入 `band_color`，None 时退化为 `QApplication.palette().color(QPalette.ColorRole.Highlight)`。卡片轨正文块无逐块主题色注入通道，本计划默认走 palette 兜底（主题 `_apply_palette` 统一填 Highlight 色），不新增构造参数；若实测某主题下带色与全局选区色不一致，再立项补注入通道。

**D4（零改动红线）**：旧轨三处挂载点（`output.py` / `input.py` / `markdown_view.py`）、`selection_band.py` 算法与常量、终端面板一律不动；改动仅限 `cards.py` 两类正文组件与文档。

**D5（QLabel 开放项）**：卡片标题 / 副标题 / 问答对走 `_selectable(QLabel)`，其原生选区无 viewport 绘制钩子，本机制不适用。QLabel 均为短单行文本、整行高即墨盒高，偏下观感远弱于正文块——本计划不处理，若用户真机仍觉碍眼另立项。

## 5. 风险与开放项

- ⚠️ **ID 选择器内 selection 声明生效性**：当年 `SUPPRESSION_QSS` 是无选择器控件级写法，实证优先于 base.qss 继承规则；并入 `#CardBodyHtml { }` 块内后需重新验证抑制生效（T3/T4 双通道核对）。若不生效，回退为无选择器追加段并实测右键菜单选区观感。
- ⚠️ **流式冲刷期绘制频率**：`TextStreamBlock` 30ms 合帧冲刷期间拖选会高频触发 `paintEvent`；`selection_rects()` 逐行遍历代价随文档增长，实测若有卡顿再议缓存。
- ⚠️ **气泡内 documentMargin=2**：`UserBubbleBlock` 气泡体收紧过 margin，锚点取块首 cursorRect 的算法不依赖 margin，预期无影响，T4 实测气泡内选区核对。
- 开放项：`_selectable(QLabel)` 字段的原生选区偏下（D5）；`band_color` 主题注入通道（D3）。
