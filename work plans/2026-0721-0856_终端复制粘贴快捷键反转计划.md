# 终端复制/粘贴快捷键反转计划

## 1. 背景与目标

当前终端的复制/粘贴快捷键为 `Ctrl+Shift+C` / `Ctrl+Shift+V`，而 `Ctrl+C` 按 VT100 规则发送 `\x03`（SIGINT）、`Ctrl+V` 发送 `\x16`（readline quoted-insert）。

目标：在「设置」菜单中增加一个**可勾选项**，勾选后**立即反转**两组快捷键的功能：

| 快捷键 | 未勾选（现状，类 Linux 终端） | 勾选后（类普通编辑器） |
|:---|:---|:---|
| `Ctrl+C` | 发送 SIGINT（中断进程） | 复制选区 |
| `Ctrl+V` | 发送 `\x16`（quoted-insert） | 粘贴剪贴板 |
| `Ctrl+Shift+C` | 复制选区 | 发送 SIGINT |
| `Ctrl+Shift+V` | 粘贴剪贴板 | 发送 `\x16` |

要求：**即时生效、无需重启**；状态持久化到 [`config/settings.json`](config/settings.json)。

---

## 2. 命名讨论（决策点 D1）

### 2.1 菜单显示名候选

| 候选 | 优点 | 缺点 |
|:---|:---|:---|
| A. `终端：Ctrl+C/V 复制粘贴` | 描述开启后的**效果**，用户一眼能懂 | 未提"反转" |
| B. `反转终端复制/粘贴快捷键` | 描述动作，与本文档术语一致 | "反转"需用户自行脑补具体行为 |
| C. `交换 Ctrl+C/V 与 Ctrl+Shift+C/V` | 最精确 | 冗长，菜单过宽 |

**推荐 A**——勾选状态本身已暗示"开/关两种模式"，效果描述对非终端熟手更友好。类似产品惯例（Windows Terminal、Tabby）也均采用"效果描述"式命名。

### 2.2 配置键名候选（写入 settings.json）

| 候选 | 说明 |
|:---|:---|
| `terminal_swap_copy_paste` | 语义"交换"，与 DEFAULT 默认 `False` 契合 |
| `terminal_ctrl_cv_copy_paste` | 描述开启后效果，与菜单名 A 对应 |

**推荐** `terminal_swap_copy_paste`，对应常量 `KEY_TERMINAL_SWAP_COPY_PASTE`（遵循 [`gui/settings.py`](gui/settings.py) 现有 `KEY_*` 常量 + TypedDict 规范）。

## 3. 语义设计（决策点 D2：✅ 已确认 = 方案一）

反转模式下 `Ctrl+C` 的行为曾有一个关键分支，**审阅后确认为方案一**：

### ✅ 方案一：严格交换（已采纳）
`Ctrl+C` 无条件执行复制。若用户想中断进程，改用 `Ctrl+Shift+C`。
- 行为简单确定，实现最小。
- 已知预期行为：无选区时按 `Ctrl+C` 无任何效果（既不复制也不中断）——用户可自行换用 `Ctrl+Shift+C`，不构成问题。
- 采纳理由（审阅意见）：要切换就彻底切换，误复制不是大事；引入"有状态快捷键"反而会让用户对按键行为产生混淆。

### ❌ 方案二：智能回退（已否决）
`Ctrl+C` 按选区状态在复制与 SIGINT 之间切换。否决理由：按键行为依赖选区状态，用户无法稳定预期按键结果，导致混淆。

### 3.1 其他语义细节

- **`Ctrl+Shift+V` 反转后的落点**：当前 [`gui/panels/terminal/widget.py`](gui/panels/terminal/widget.py) 的 `key_to_bytes` 只检查 Ctrl 修饰键、不排斥 Shift，因此 `Ctrl+Shift+C/V` 只要不被拦截，会自然落入 VT100 转换分别发送 `\x03` / `\x16`。**反转实现的本质就是"交换拦截条件"**，无需在 `key_to_bytes` 中补分支。
- **`Ctrl+F` 查找浮层**：拦截在复制/粘贴判断之前，不受本功能影响。
- **右键菜单「复制 / 粘贴」**（[`gui/panels/terminal/panel.py`](gui/panels/terminal/panel.py) `_on_context_menu`）与编辑菜单「复制」（`copy_focused` 按焦点分发）：行为与快捷键无关，**无需改动**。
- **修饰键精确匹配**：现有拦截用 `event.modifiers() ==` 精确相等，反转后保持同风格，避免 CapsLock/Alt 等杂散修饰键造成歧义。

## 4. 实现方案

### 4.1 生效机制选择

快捷键由 `TerminalWidget.keyPressEvent` 手写判断（全项目无 QShortcut/QAction shortcut），每次按键都执行判定。采用项目惯用的**注入标志位**模式（与 `apply_palette` / `refresh_font` 一致）：

```
设置菜单勾选
  → update_settings({KEY_TERMINAL_SWAP_COPY_PASTE: checked})   # 持久化
  → MainWindow.set_terminal_swap_copy_paste(checked)            # 即时应用
  → TerminalPanel.set_swap_copy_paste(checked)
  → TerminalWidget.set_swap_copy_paste(enabled)                 # 更新标志位
```

启动时 `TerminalPanel.__init__` 从 `load_settings()` 读初值注入 widget（参照现有主题初值读法）。**全程无需重启。**

## 7. 风险与边界

- 🟢 严格交换为"无状态快捷键"：按键行为与选区无关，用户预期稳定（D2 审阅结论）。
- 🟢 已知预期行为：反转模式下无选区按 `Ctrl+C` 无任何效果，需在 `keyPressEvent` 相关注释中写明，避免后续维护者误判为 bug。
- ⚠️ 多 PTY 会话栈：`set_swap_copy_paste` 需对所有已存在的 TerminalWidget 实例生效（由 TerminalPanel 统一下发），新建会话也要带上当前值。
- 🟢 无 QShortcut 冲突风险（全项目快捷键均为 `keyPressEvent` 手写判断）。
- 🟢 旧配置文件兼容（缺字段回退默认 `False`，行为与现状一致）。
