# T3 厂商专属卡片、工厂与 Presenter 拆分子计划

> **状态**：草稿（等待用户批准执行）
> **范围**：`src/ide/gui/panels/chat/` 的 UI 基础件、卡片组合根、Kimi/DSH/Local 具体卡片与更新逻辑，通用面板字段读取和轮后用量能力；不重新设计卡片外观，不改后台 update 规则
> **时间**：2026-11-20 21:15（设计，UTC+8）
> **优先级**：高
> **依据**：`2026-1120-1818_Kimi与DSH后台厂商隔离及公共层收口落地计划.md` 的 T3、§5.2–§5.5；T0 面板职责清单与 T2 厂商载荷

## 1. 背景与目标

本项把具体卡片格式、工具名分派、迟到帧和更新逻辑按厂商隔离。公共 GUI 只保留无厂商语义的 Qt 技术基础件、卡片生命周期和事件转发；通用面板不得继续认识 `command`、`summary`、`diff_hunks`、`questions` 等厂商载荷字段。

迁移初期允许复制现有具体卡片以保证等价，之后由各厂商独立演化。禁止保留公共 `BashCard`、`DiffCard`、`QuestionCard` 等具体实现，也禁止以统一 `card_kind` 或中性类型表变相恢复公共卡片体系。

## 2. 启动条件与边界

- 主计划 T2 已勾选，且用户明确批准 T3 后才能开始；本项批准不包含 T4。
- 必须使用 T0 的「通用生命周期保留 / 移入厂商 presenter」清单和帧到卡片基线。
- 不改变卡片观感、持久化键、默认后台、模型别名或用户配置。
- 厂商 GUI 包只 import 本厂商 models 的纯数据类型，不得 import provider 运行时、连接对象或其他厂商卡片。
- 权限中性分类属于 T4；本项只保证现有提问卡内容与交互不因卡片迁移改变。

## 3. 实施步骤

### T3.1 建立 UI 基础件与卡片组合根

1. 建立 `src/ide/gui/panels/chat/card_base.py`，等价承接 `ToolCard` 生命周期、折叠/展开、复制、颜色、基础 body、图片显示等稳定技术能力。
2. 建立 `src/ide/gui/panels/chat/vendors/registry.py`，按后台 registry 的 `vendor` 选择本厂商卡片工厂。
3. 后台组合根不 import GUI；通用面板只接触卡片组合根，不 import 具体厂商卡片包。

### T3.2 等价复制三家具体卡片与工厂

1. 为 Kimi、DSH、Local 分别建立 `factory.py`、`cards.py`、`presenter.py`。
2. Kimi 工厂承接 `AskUserQuestion`、`Agent/Task`、`ReadMediaFile`、`TodoList` 等工具名；DSH 工厂承接 `read_image`、`todo_write`、`subagent` 等工具名。
3. Local 建立自有工厂、卡片和更新逻辑，不从 Kimi 导入相似实现。
4. 未知工具分别进入本厂商通用卡，不设置公共兜底格式。
5. 删除 `_TOOL_NAME_CARDS`、`_normalize_tool_name` 和公共 `make_tool_card()`，不引入统一 `card_kind` 替代。

### T3.3 将格式与更新职责移出通用面板

1. 按 T0 清单将标题/命令账本、迟到字段判断、diff/summary/questions 等载荷读取和卡片更新分支移入各厂商 presenter。
2. 通用面板只保留调用 ID 定位、卡片插入/结束、展开状态、信号封送和不透明事件转发。
3. 每家 presenter 自行决定迟到帧补卡、字段覆盖、账本清理和子代理嵌套。
4. 审计会话持久化与历史回放是否直接保存旧工具载荷；确需兼容时由对应厂商 presenter 读取自己的旧载荷，不恢复公共兼容工厂。

### T3.4 中性化轮后用量能力并补回归

1. 用 `post_turn_usage_grace_s()` 替代 `_llm_name == "kimi-acp"`，保持 Kimi 恢复中和正常态的现行宽限值，DSH/Local 默认返回 0。
2. 将面板中「Kimi 轮后宽限」等实现注释改为中性能力描述；Kimi 专属设置键仅为持久化兼容保留。
3. 将卡片测试按厂商拆开，贯通「本厂商帧 → 本厂商载荷 → 本厂商工厂 → 本厂商卡片 → 本厂商更新」。
4. 补另一家同名工具不会误入的边界测试，并运行定向测试与 `bash scripts/check.sh`。
