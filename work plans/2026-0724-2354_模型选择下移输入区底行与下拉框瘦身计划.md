# 模型选择下移输入区底行与下拉框瘦身计划

## 1. 背景与目标

`2026-0724-2305_左栏宽度根治_下拉框压缩与发送停止双态按钮计划.md` 已实施：动态撑宽根除、ModelBar 静态下限 528→402px、左栏下限 414px。用户拍板下一步（2026-07-24 深夜讨论）：

1. **模型/版本双下拉从顶部模型行下移到输入区底行**（与发送/停止双态按钮同行），顶部模型行整行消失；
2. **下拉框进一步缩短**：框体只显示截断文本，点击弹出时列表显示全部条目（用户原话「不需要显示全部，当用户点击的时候再显示全部」）；
3. 形态按建议定为 **B：去掉「模型」「版本」文本标签，双 combo 裸放底行左侧**（tooltip 注明语义），N 取 4~6。

本期目标（量化验收见 §7）：

- 左栏静态最小宽度从 414px 压到 **≤ 320px**，`DEFAULT_SIZES_MAIN` 左栏 320 从「不可达」变「可达且正确」（默认值回摆 [320, 630, 250]）；
- 弹窗列表按最长条目自适应加宽显示全文（框体截断不受影响）；
- 全局模型选择语义（D5：全部标签共享同一选择）在多实例架构下保持等价。

## 2. 可行性取证

### 2.1 「框体短、弹窗全」是 Qt 内建行为

QComboBox 弹出列表宽度独立于框体宽度：弹出时按视图内容（最长条目 + 图标 + 边距）自动加宽。本期 T1 已铺好 `AdjustToMinimumContentsLengthWithIcon`（框体宽度与条目脱钩）+ tooltip 兜底全名，缩短 N 值即可直接生效。

⚠️ 唯一验证点：本项目弹窗经自定义修复（`gui/popups.py` 的 `make_translucent_combo_popup`，StyledPanel 容器 + 透明去框），容器是否保留「按内容加宽」需探针截图确认；若被破坏，修复为弹出前按 `view.sizeHintForColumn` 设弹窗最小宽（一行量级，见 T5）。

### 2.2 参考实现同构

Multi_Cli_Studio 模型选择器即在输入区底行（流式时锁定，与 busy 禁用双下拉同构）；theia 的代理/模式选择在输入框下方 options 行。方向与两家主流一致。

### 2.3 收益测算（实测外推：N=10 单 combo ≈145px，每字符 ≈8px，按钮 81px）

| 项 | 估算 |
|:---|:---|
| 底行 = combo×2（N=6，各 ≈113px）+ 间距 + 按钮 81px | ≈ 315px |
| 卡片边距 + ChatTabs 边距 | + 28px |
| **左栏新下限** | **≈ 300~320px** |

⚠️ 不缩短直接平移是负收益（底行 ≈455px，比如今 414 还高）——「移动」与「缩短」必须捆绑，本期一体实施。

## 3. 架构关键决策

| 编号 | 决策 | 理由 |
|:---|:---|:---|
| D1 | ModelBar 从 ChatTabs 全局单例改为**每 ChatPanel 底行一个实例**（纯视图组件） | 底行属每标签布局（随标签销毁），全局控件无法放入；与参考实现同构 |
| D2 | **选择状态单一来源上移 ChatTabs**：持有当前 backend/version；写盘收敛到 `ChatTabs._on_selection_changed`；ModelBar 不再自管持久化 | 多实例下防止「各实例各自写盘」的状态分裂；零标签时状态不丢（原「ModelBar 全局常驻」语义由状态层承接） |
| D3 | UI 同步走阻断广播：用户在某标签切换 → ChatTabs 写盘 + 广播其余实例 `set_selection`（QSignalBlocker 全程阻断，不发信号不写盘）+ 广播 provider（现有 `set_model_selection` 路径） | 防多实例回环；`set_selection` 阻断机制已存在，直接复用 |
| D4 | 首标签/新建标签的选择来源 = ChatTabs 当前状态（启动时 ChatTabs 从 settings 读取一次） | 单一初始来源，杜绝「各实例各自 load_settings」的时序漂移 |
| D5 | busy 禁用语义不变：任一标签 busy → ChatTabs 遍历全部实例 `set_busy` 禁用双下拉 | 现「防切换中途打断正在响应的标签」语义完整保留（设置中心模型页联动不变） |
| D6 | 去「模型」「版本」文本标签；tooltip 注明「模型后端」/「模型版本」+ 当前项全名 | 形态 B 拍板；省 ≈70px 是 320 可达的关键 |
| D7 | N 初值 6，验收阶段按实测调优（下限 ≤320 与别名可读性平衡） | 上期 N=12→10 调优先例 |
| D8 | 弹窗宽度自适应验证不通过才修 `gui/popups.py`（最小侵入） | 自定义容器可能已保留 Qt 行为，先证后修 |

## 4. 任务分解

### T1　ModelBar 重构为纯视图组件（`gui/panels/chat/model_bar.py`）

- 移除「模型」「版本」QLabel 与布局中的 stretch；布局只余双 combo 横排（小间距）。
- `_MIN_CONTENTS_LENGTH` 10 → 6（D7，验收调优）。
- 移除写盘职责（`_emit` 中 `update_settings` 删除，settings import 清理）；tooltip 改为「模型后端：{全名}」/「模型版本：{全名}」格式（`_refresh_tooltips` 同步更新）。
- 保留：`selection_changed` 信号、`set_selection`（阻断）、`set_busy`、`current_backend`/`current_version`、`setMinimumContentsLength` 机制、弹窗修复调用。
- 构造不再 `load_settings` 自恢复（初始选择由外部 `set_selection` 注入，D4）。

### T2　选择状态上移 ChatTabs（`gui/panels/chat/tabs.py`）

- ChatTabs 构造时 `load_settings` 读取 `KEY_MODEL_BACKEND`/`KEY_MODEL_VERSION` 为当前选择（D4 单一来源）；新增 `current_backend()`/`current_version()` 查询接口（替代现 `model_bar.current_*` 消费方）。
- `add_tab`：用 ChatTabs 当前选择实例化 ChatPanel 与其 ModelBar；连接各实例 `selection_changed` → `_on_selection_changed`。
- `_on_selection_changed`：更新 ChatTabs 状态 + **写盘**（update_settings 收敛至此，D2）+ 广播其余实例 UI（`set_selection` 阻断，D3）+ 广播 provider（现有逻辑）+ 发射新信号 `selection_changed`（供 main_window 设置中心联动，替代现直连 `model_bar.selection_changed`）。
- `apply_model_selection`：更新状态 + 写盘 + 广播全部实例 UI 与 provider（零标签时只更新状态与写盘，新建标签生效——等价现「广播空列表 no-op」语义）。
- `_recompute_busy`：改为遍历全部标签的 ModelBar 实例 `set_busy`（D5）。
- 顶部模型行移除：`layout` 只留 `_stack`，边距/间距按截图验收调整（模型行消失后呼吸感重排）。

### T3　ChatPanel 底行装配（`gui/panels/chat/panel.py`）

- 底行布局改为 [`model_bar`（左）, `stretch`, `_send_button`（右）]；ModelBar 实例化于 ChatPanel（初始选择用构造已传入的 backend/version）。
- `set_model_selection` 扩展：广播时同步自身 ModelBar UI（`set_selection` 阻断）——UI 同步与 provider 写入单一入口。
- `_set_busy` 不变（ModelBar 禁用由 ChatTabs 遍历处理，不经面板 busy 本地逻辑——与现全局语义对齐）。

### T4　main_window 接线适配（`gui/main_window.py`）

- `chat_tabs.model_bar.selection_changed.connect(...)` → `chat_tabs.selection_changed.connect(...)`（T2 新信号）；`_on_modelbar_changed`（设置中心同步）与 busy 联动（`is_busy()`）逻辑不变。

### T5　弹窗宽度自适应验证与修复（`gui/popups.py`，先证后修）

- 探针弹出双下拉截图：弹窗宽度 ≥ 最长条目全文宽度即保留 Qt 行为，本任务关闭；
- 不达标则在弹窗容器弹出前按 `view.sizeHintForColumn(0)` + 图标/边距设最小宽（一行量级），不得影响既有透明去框修复（圆角双框治理语义不变）。

### T6　默认值回摆（`gui/main_window.py`，依赖实测）

### 10.1 背景与拍板

迭代 1 落地后，N=3 框体截断显示（"Kim"/"kim"）用户观感难看。拍板（2026-07-25 凌晨讨论）：

- **路线 C**：双 QComboBox 换 **QToolButton（InstantPopup）+ QMenu**（QActionGroup 互斥、当前项 ✓ 勾选）——Qt 标准「带标题下拉按钮」形态，与 Multi_Cli_Studio 底行模型选择器、theia 输入区 options 同构（两家都不用 combo，正是为了显示文本自由定制）；否决路线 A（QComboBox + 只读 QLineEdit hack，与全局 qss 的 QLineEdit 样式易冲突）与路线 B（子类 paintEvent 自绘，hover/focus/裁剪维护成本高）；

### 10.2 设计

- **对外接口零变化**：`selection_changed` / `set_selection`（阻断）/ `set_busy` / `current_backend` / `current_version` 签名与语义保持——ChatTabs 状态层、阻断广播、main_window 接线、设置中心联动**零改动**，只换控件内核；
- 按钮恒显标签：`setText("模型"/"版本")` 不随选择变化；tooltip 动态携带当前项全名（机制沿用）；
- QMenu：QActionGroup 互斥、当前项 `setChecked`；菜单创建经 `make_translucent_popup()`（`gui/popups.py` 规约：任何新建 QMenu 一律透明化）；菜单项 data 携带 registry 后端名/模型别名；菜单天然按内容加宽显示全文（迭代 1 §2.1 同款 Qt 内建行为）；
- 阻断语义天然成立：`QAction.setChecked` 不发射 `triggered`（只有用户点击才发），`set_selection` 广播同步天然无回环，无需 QSignalBlocker；
- 宽度收益：按钮 ≈50px/个（2 中文字 + 箭头），左栏下限预计 **≈230px**（验收记录实测；`DEFAULT_SIZES_MAIN` 320 不动，余量更充裕）；
