# Wayland 平台适配落地计划

> **状态**：草稿（待审阅）
> **范围**：全应用 GUI 运行链路（`src/gui/`）、输入法子系统（`building/build-fcitx5-qt6-plugin.sh`）、打包产物（`building/build_appimage.sh`、`building/zen-studio.spec`）、维护文档
> **时间**：2026-10-23 00:29（设计，UTC+8）
> **优先级**：中

## 需求

1. 应用在同一套代码、同一份产物下，在 Wayland 会话与 X11 会话中均行为正确（已决策：**单代码库运行时自适应，不分叉双版本**）。
2. 适配工作在 Git 新开 `dev_wayland` 分支上进行，验证通过后合回主线。
3. Wayland 下确认不可控的差异（合成器策略类）要有明确回退路径与文档说明，不允许静默劣化。
4. **目标合成器已定为 GNOME / Mutter**（开发机 Ubuntu 24.04.5 LTS + GNOME 46 + AMD GPU，现跑 X11 会话，切换方式为登录界面齿轮选 Wayland 会话）。验收以该环境为准；KDE Plasma / Hyprland 不在本次范围，留待日后可选补测。

## 探查结论（审计已完成）

代码审计结论：**源码无 X11 专有 API 依赖，主干链路已具备 Wayland 兼容性**，本计划以「实测 + 定点补强」为主，而非大规模改造。审计事实清单：

| 区域 | 现状 | 判据 |
|---|---|---|
| 窗口拖拽 / 缩放 | ✅ 已兼容 | 走 `QWindow.startSystemMove` / `startSystemResize`，Wayland xdg-toplevel 与 X11 均由 WM 接管（`src/gui/title_bar.py`、`src/gui/window_resize.py`） |
| X11 专有调用 | ✅ 无 | 全项目无 `QX11Info` / `Xlib` / `pynput` / `xdotool` / `wmctrl` / `xclip` 依赖 |
| 平台插件强制 | ✅ 无 | 无任何代码强制 `QT_QPA_PLATFORM=xcb`，Qt 可按会话自动选 wayland/xcb |
| 打包产物 | ✅ 已内置 | AppImage 同时收编 `libqwayland.so` 与 `libqxcb.so`；`.desktop` 已处理 Wayland 任务栏图标关联（`building/build_appimage.sh`、`building/zen-studio.desktop`） |
| 窗口唤活 | ⚠️ 已知受限 | `activateWindow` 置前受 Wayland 合成器策略限制，代码注释已自知（`src/gui/main_window.py` `_on_external_activate`） |
| 标题栏手动 move 兜底 | ⚠️ 待核 | 降级路径用 `window.move()` 手动拖拽（`src/gui/title_bar.py`），Wayland 禁止应用自设顶层窗口位置，此兜底在 Wayland 下无效——需确认主路径可用性并补 why 注释 |
| 窗口几何恢复 | ⚠️ 待核 | `restoreGeometry`（`src/gui/controllers.py`）在 Wayland 下位置恢复被合成器忽略、尺寸恢复有效——需确认无报错且体验可接受 |
| 终端自绘渲染 | ⚠️ 待复查 | 注释记载「实机 xcb 独有的后画 run 盖前字残片」现象（`src/gui/panels/terminal/widget.py`），Wayland 下是否消失需实机复查 |
| 中文输入法 | 🔴 最大不确定项 | 自编译 fcitx5 Qt6 插件构建时关闭 Wayland workaround（`building/build-fcitx5-qt6-plugin.sh`）；原生 Wayland 下 Qt6 输入法走 text-input-v3 协议，依赖合成器支持，全输入点需实测 |

## 方案决策

- **运行时探测集中收口**：新增一处平台探测小工具，集中封装 `QGuiApplication.platformName()` 判断（`"wayland"` / `"xcb"`），后续所有零星差异点只许引用该工具，禁止各处散落环境变量/字符串判断。注释只写 why（差异来自合成器策略而非代码缺陷）。
- **回退路径**：任何 Wayland 下不可修复的问题，统一回退为设 `QT_QPA_PLATFORM=xcb` 走 XWayland（行为与现状完全一致），并写入维护文档。回退是环境变量级，不涉及代码分支。
- **测试体系不动**：既有 pytest 全部 offscreen 平台，天然与显示服务器解耦，门禁 `bash scripts/check.sh` 照旧。

### 不做项（已知取舍，留档）

- 不为 Wayland 单独分叉代码或单独出包（决策已定为单代码库单产物）。
- 不尝试用代码绕过合成器的焦点/置前策略（Wayland 设计上禁止，无合法 API）。
- 不引入全局快捷键、屏幕取色等 Wayland 下需 XDG portal 的新能力（当前无此需求，引入即适配负债）。

## 实施步骤

### 1. 分支与基线

- 从主线新开 `dev_wayland` 分支；提交信息用中文；每次提交前门禁 `bash scripts/check.sh` 全绿。
- 在 X11 会话下先跑一次基线：门禁绿 + 应用启动冒烟，作为后续对照。

### 2. 开发期调试工作流（嵌套合成器）

**问题**：开发机当前是 X11 会话，不能每次调试都注销切换会话。
**方案**：在 X11 会话内开**嵌套 Wayland 合成器**（一个窗口里的完整 Wayland 环境），应用以真实 `libqwayland` 路径运行，行为与真实会话一致。

- 首选 weston（开发机已装，轻量）：

  ```bash
  # X11 会话内开一个嵌套 Wayland 窗口，socket 钉死便于引用
  weston --socket=wayland-9 &
  # 应用以真实 wayland 平台插件运行（libqwayland、xdg-toplevel 全真路径）
  WAYLAND_DISPLAY=wayland-9 QT_QPA_PLATFORM=wayland .venv/bin/python main.py
  ```

- 输入法联调时优先 **Mutter 嵌套**（与验收环境同族，text-input-v3 行为最贴近真机；weston 对该协议支持视版本而定），命令以目标发行版文档为准。
- 可沉淀为 `scripts/` 下的启动脚本，一键起 weston + 应用。
- **能力边界**（留档）：嵌套环境可验证平台插件加载、窗口装饰/拖拽/缩放、剪贴板、拖拽、渲染；**焦点置前策略与输入法候选框定位等合成器深度耦合项，最终仍以一次真实 Wayland 会话验收为准**（嵌套仅作迭代期手段，验收见「验证」节）。
- **与在用冻结态并行不冲突**（留档）：开发态用户数据写项目内 `config/`，冻结态（AppImage）写 XDG 配置目录，settings 锁、一窗一根套接字、会话/窗口状态分文件全部按目录天然隔离（`src/core/paths.py`、`src/gui/root_ownership.py`）；嵌套 weston 用独立 socket，与 X11 会话里运行的冻结态互不影响。唯一注意点：两态套接字互不知晓，勿用两态同时打开同一文件夹（会同根双开，非崩溃级但避免 git 操作互相干扰）。

### 3. 平台探测工具（`src/core/`）

- 新增集中探测模块（如 `src/core/platform_info.py`）：提供 `is_wayland()` / `is_x11()`，内部读 `QGuiApplication.platformName()`，docstring 注明「差异判断的唯一入口」职责。
- 附纯函数级单测（mock `platformName` 返回值断言两方向）。

### 4. 输入法链路（重点）

- 复核 `building/build-fcitx5-qt6-plugin.sh` 中 `ENABLE_QT6_WAYLAND_WORKAROUND=OFF` 的语义与当前 Qt 版本下的正确性，结论写入脚本注释（why）。
- Wayland 会话实测全部输入点的中文输入与候选框定位：聊天输入框（`src/gui/panels/chat/input.py`）、终端（`src/gui/panels/terminal/widget.py`）、各搜索/查找框（`src/gui/panels/find_bar.py`、文件树搜索）。
- 若合成器 text-input-v3 不可用导致输入失效：确认 `QT_IM_MODULE=fcitx` + xcb 回退路径可用，并记录适用条件。

### 5. 窗口行为核对与补强

- `restoreGeometry` 在 Wayland 下实测：确认仅位置恢复被忽略、无异常告警；如体验落差明显，评估以「尺寸恢复 + 居中」为 Wayland 分支行为（经步骤 3 的探测工具判断）。
- 标题栏手动 `move()` 兜底路径：确认主路径 `startSystemMove` 在目标合成器上可用；为兜底路径补 why 注释（Wayland 禁止应用自设顶层窗口位置，兜底仅对 X11 生效）。
- `_on_external_activate` 唤活链在 Wayland 下实测，实测结论回写代码注释（现状注释为推断语气，实测后改定论）。

### 6. 交互链路实测

- 剪贴板：终端复制/粘贴（`src/gui/panels/terminal/widget.py`）、聊天图片粘贴、文件树复制路径。
- 拖拽：文件拖入聊天输入框（`src/gui/panels/chat/input.py` 的 `dragEnterEvent` 链路）。
- 终端自绘渲染：复查 xcb 残片现象在 Wayland 下是否消失，结论回写 `src/gui/panels/terminal/widget.py` 注释。
- HiDPI：若目标环境有分数缩放，验证界面缩放比例与字体清晰度。

### 7. 打包产物 Wayland 冒烟

- Wayland 会话下启动 AppImage 冻结产物冒烟（主窗口、对话框、终端、PDF 预览走查），确认 `libqwayland.so` 收编完整、无缺插件告警。

### 8. 文档同步（随代码同提交）

- `维护手册/` 增补或更新 Wayland 适配说明：支持矩阵（哪些合成器实测通过）、已知受限项（唤活置前、位置恢复）、xcb 回退操作方法。
- 涉及行为变化的模块头注释 / docstring 同步订正。
- 本计划实施完成后回写「实施回写」段并改状态。
