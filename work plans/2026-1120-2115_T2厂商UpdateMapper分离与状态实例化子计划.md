## 1. 背景与目标

T1 只完成目录迁移，公共 update 实现仍汇集三家字段、工具名和模块级账本。本项将完整映射流程和具体载荷类型分别交给三家，消除跨 provider/session 状态串联，同时保持现有帧语义不变。

公共层最终只保留稳定流式事件信封、路由元数据和无厂商语义的 ACP 纯函数；不得用新的公共 schema、hook 基类或统一 `card_kind` 把厂商差异重新合并。

## 2. 启动条件与边界

- 主计划 T1 已勾选，且用户明确批准 T2 后才能开始；本项批准不包含 T3。
- 先复制现有行为再删除公共厂商语义，以 T0 的逐帧基线判定等价。
- 不实现 DSH edit 合成 diff、ask_user_question 回环或其他未落地能力。
- 标准 text/reasoning/usage、ACP content、ANSI 清理、通用截断和标准 oldText/newText diff 可共享纯函数；具体工具名和字段词表不得共享。
- 本项不拆卡片工厂/presenter，不改权限分类和轮后宽限。

## 3. 实施步骤

### T2.1 建立独立 mapper 与 models

1. 新建 `KimiUpdateMapper`、`DshUpdateMapper`、`LocalUpdateMapper`，分别持有完整 `map_session_update` 流程；每个 provider 实例创建自己的 mapper。
2. 将 `ToolCallPayload`、`ToolUpdatePayload`、todo、提问等具体载荷类型分别迁入各厂商 `models.py`，三家不得横向导入。
3. 将 `src/ide/llm/base.py` 收敛为稳定信封、不透明载荷和路由必需元数据，不保留公共具体卡片 schema。
4. 不新建通用厂商流程基类或包含大量厂商 hook 的 mapper 基类。

### T2.2 迁移各厂商规则

1. Kimi 承接显式 kind 信任、Kimi 工具名和 camelCase、write diff、回执模板、`<image path>`、task 成果摘要、todo `title/done`、sidecar 合成帧和层级父指针。
2. DSH 承接 kind 缺失/other 的工具名兜底、snake_case、`read_image`、todo_write、DSH 图片输入和现有输出形态。
3. Local 依据自身可控假 agent 和协议资料形成独立 mapper 与 models；即使当前输出与 Kimi 相似，也不得 import Kimi mapper 或载荷类型。
4. 三家仅可调用无厂商语义的 `acp/content.py` 等纯函数，公共 ACP 包不得反向依赖厂商包。

### T2.3 实例化账本并删除公共厂商语义

1. 将 `_input_detail_seen`、`_derived_tool_kinds`、`_last_todo_snapshots` 移入 mapper 实例。
2. 保证同 toolCallId 在不同 provider 或不同会话不互相命中；reset/close 清理本实例状态，终态帧继续清理单调用账本。
3. 保留同一 provider/session 内连续轮次所需的 todo 快照，不以「清状态」为由破坏连续高亮。
4. 删除公共 `map_session_update`、公共具体工具载荷类型及厂商词表；脚本按实际目标显式使用 Kimi 或 DSH mapper。
5. 将现有测试按厂商归属改写，不为旧公共测试保留兼容 shim。

### T2.4 回归验证

## 6. 实施结果回写（2026-11-20 23:12 UTC+8）

T2 全部完成，修改记录见 `文档/修改记录/2026-1120-2312_T2厂商UpdateMapper分离与状态实例化实施记录.md`。

### 6.1 与计划的偏差

1. **Kimi 实际字段是蛇形而非计划写的 camelCase**：帧存档中 Kimi 使用 `path`/`old_string`/`new_string`。Kimi mapper 以实证蛇形为主，同时保留历史驼峰字段，避免按计划措辞删掉既有行为；DSH 只收 snake_case，Local 用自身标准词表。
2. **`_input_detail_seen` 与 `_derived_tool_kinds` 的键由 `toolCallId` 改为 `(sessionId, toolCallId)`**：仅靠每 provider 一个 mapper 不能防同 provider 内不同会话复用同一调用 ID；加会话维度后才满足「不同会话不互相命中」。
3. **除 `reset`/`close` 外，新建会话也清空 mapper 账本**：新建会话没有旧调用可承接，清空可避免账本无界增长，并让相同 `toolCallId` 在新会话重新开始；同一会话的 todo 快照仍跨轮保留。
4. **Local 有意不继承 DSH 工具名兜底与 Kimi 私有标记**：Local mapper 仅按自身 ACP 协议处理显式 kind、标准 content 和自身 rawInput 词表；因此旧公共 mapper 中「Local 也吃 DSH fallback / Kimi `<image path>` / `done`」的偶然能力不再存在。现有 Local 基线与协议内帧逐帧等价，未启用新能力。
5. **回执模板按厂商拆开**：Kimi 保留 `Current todo list` 块；DSH 只保留 todo 回执两式；Local 按 `dream-acp` 协议文档保留三式。三家各自维护，不互相 import。
6. **测试文件整体改写而非保留旧基线文件**：删除 `tests/test_vendor_behavior_baseline.py`，按厂商拆为三个 mapper 测试、一个 provider 生命周期测试、一个隔离/边界测试；没有为旧公共入口保留 shim。
7. **`scripts/shot_tool_cards.py` 每个 mock 场景使用独立 Kimi mapper**：旧脚本依赖模块级全局映射器并以 sessionId 隔离场景；实例化后改为场景内新建，避免场景间账本串联。
8. **公共 `acp/content.py` 移除 `<image path>` 解析**：该标记是 Kimi 私有出参形态，已迁入 `kimi/updates.py`；标准图片块、ANSI 净化、截断与 diff 仍共享。

### 6.3 经验沉淀

1. **实例化只解决「跨 provider」，键控才解决「跨会话」**：每个 provider 一个 mapper 是必要不充分条件；账本键必须带 `sessionId`，否则会话重建后相同 `toolCallId` 仍会误命中。
2. **「字段词表」应按实证而非计划措辞迁移**：计划中的 camelCase 与 Kimi 存档不一致；先跑存档再拆，才能避免把可观察行为当脏数据删掉。
3. **等价验证要拿旧实现做对照，而不是只跑新测试**：T0 基线只锁语义，旧/新双跑同一批帧才能发现 partial 帧、回执过滤、截断方向这类测试没覆盖的细节；导出一份 `git archive` 到 `.temp/` 即可，无需长期维护旧实现。
4. **厂商解耦会主动丢掉「偶然共享」**：Local 不再支持 DSH 工具名兜底、Kimi `<image path>`/`done`，这类差异必须在回写中明说，不能以「测试仍绿」冒充完全等价。
5. **受控重复的代价要提前接受**：三家 mapper 的兜底文本、输出提取与词表有意重复；用统一基类消重会把变化轴重新合并，后续修一家又要证明另一家不受影响。
