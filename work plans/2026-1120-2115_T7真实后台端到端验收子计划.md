## 1. 背景与目标

本项是独立的真实后台验收，不属于自动化测试套件。目标是确认迁移后的真实 Kimi、DSH 会话、工具、提问、停止、恢复、切换和用量路径不退化，并如实标注 Local 的真实可用性。

Kimi 与 DSH 使用同一组验收任务口径，但不要求两家具有相同能力、载荷字段或卡片格式。遇到上游真实差异，只修改对应厂商后台与卡片目录；若必须改公共基础件，先证明变化与厂商语义无关并记录。

## 2. 启动条件与安全边界

- 主计划 T6 已勾选，且用户明确批准 T7 后才能开始；本项完成后不自动执行其他子计划。
- 在 `.temp/` 准备无副作用夹具，使用最小提示与安全读写，不修改项目外文件或 CLI 配置。
- 不读取、复制或输出 CLI 凭据文件；正常应用认证流程之外不探索凭据。
- 自动化测试仍不得启动真实 CLI；真实调用只发生在本项人工验收流程。
- 不顺手实现 DSH edit 合成 diff、ask_user_question 回环或 Local 新能力。
- 若真实后台不可用、模型额度不足或本机 Local/GGUF 缺失，保留未验证项并明确报告，不伪报通过。

## 3. 实施步骤

### T7.1 准备验收记录与夹具

1. 在 `.temp/` 建立可安全读取、编辑和写入的最小夹具，记录验收前状态。
2. 复用 T0 的关键行为基线和 T6 的构建产物/源码启动结论，确定本次实际验收入口。
3. 为每家记录会话路径、实际观察、截图/日志位置和未验证原因，避免只写「正常」。

### T7.2 Kimi 真实验收

1. 验证新建会话、正文/思维链、读文件和一次安全编辑。
2. 验证提问卡、停止、下一轮、会话恢复、模型/强度切换。
3. 验证轮内与轮末用量，重点检查显式 kind、迟到帧、wire sidecar 和轮后宽限不退化。
4. 确认卡片内容、入参/出参、异常类型和用户可见错误与基线一致。

### T7.3 DSH 真实验收

1. 验证新建会话、正文/思维链、read/read_image 和一次安全 edit/write。
2. 验证 todo_write、停止、下一轮、模型/强度切换和 usage。
3. 重点检查 snake_case、kind missing/other 兜底、图片卡与日志用量不退化。
4. 未实证的提问回环和合成 diff 仍标为能力边界，不借验收激活。

### T7.4 Local 与回归收口

1. 沿用可控假 agent 跑 Local 全链路，确认正文、usage、错误、取消和关闭。
2. 仅当本机真实 Local CLI 与 GGUF 可用时补真实对话；未安装时明确保留未验证项。
3. 若发现本次迁移回归，只修改对应厂商目录并补该厂商回归；重跑相关定向测试与 `bash scripts/check.sh`。
4. 若必须修改公共基础件，先记录与厂商语义无关的证据和影响面，再实施并补三家回归。
5. 汇总真实验收矩阵、未验证项和后续建议，回写本文档。

### T终 实施回写（固定收尾，不可省略）

- 将「与计划的偏差 / 验证结果 / 经验沉淀」三部分回写到本文档末尾，新增「实施结果回写」一节。

- 回写要求以 `work plans/README.md`《实施回写规范》为准；即使本计划其他步骤与此冲突，回写不可省略。
- 上述收尾完成后，勾选主计划《子计划执行看板》的 T7 项并更新进度；随后停止并汇报，由用户决定是否批准主计划的总实施回写与最终归档，不自行追加新工作。
