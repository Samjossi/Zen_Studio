## 0. 背景与目标

### 0.1 背景

`work plans/2026-0905-2025_启动模式设置与最后关闭项目恢复计划.md`（已实施）引入了「无参启动恢复最后关闭的项目」特性及设置中心「常规」页启动模式二态（restore / blank）。实施后用户反馈该功能仍未达到预期效果，且恢复语义涉及的边界场景（多窗关闭顺序、换根关旧窗、历史失效回退链）复杂难缠。

用户决策：**不再修复，整体撤销该特性**——程序在任何情况下启动都不自动打开/恢复之前的项目，无参启动恒为空白窗口。

### 0.2 目标

1. **无参启动恒空白窗口**：删除启动恢复逻辑与启动模式设置项，启动行为不再有分支。
2. **代码减负**：连带删除 `last_closed_root` 存取、设置中心「常规」页、`startup_mode` 设置键等仅为该特性服务的代码。
3. **保留不受影响的功能**：菜单「最近打开的项目」列表（仅菜单回访消费）、`--blank`、显式 `folder` 参数、「新建窗口」、一窗一根唤活逻辑全部维持现状。

### 0.3 撤销后的启动行为

| 启动方式 | 行为 |
|:---|:---|
| 无参启动（双击图标 / `uv run main.py`） | 空白窗口（恒，不再读任何历史） |
| `main.py <folder>`（有效目录） | 打开该项目（不变） |
| `main.py <folder>`（无效目录） | 空白窗口 + stderr 提示（原「回退恢复历史」改为不回退） |
| `--blank` | 空白窗口（不变） |
| 菜单「新建窗口」 | 空白窗口（spawn `--blank`，不变） |

## 1. 关键决策

### D1 恢复逻辑整段删除，不留开关

不留「默认 blank 的隐藏设置」之类的残留开关——特性撤销即代码删除，启动路径零分支。`main.py` 的 `_default_workspace()` 整函数删除，`resolve_workspace_root()` 简化为：显式 `folder` 有效则返回根，否则返回 `None`（空白窗口）。

### D2 `_is_unpack_dir()` 一并删除

该防护仅服务于恢复落点校验（防把 PyInstaller 解包目录当工作区恢复）。恢复路径删除后无消费方，一并删除。显式 `folder` 参数是用户意图，无需此防护。

### D3 `last_closed_root` 存取整段删除，列表功能保留

`gui/recent_projects.py` 删 `KEY_LAST_CLOSED_ROOT`、`get_last_closed()`、`set_last_closed()`；`clear()` 与 `_write()` 恢复原语义（只写/只覆盖列表键）。`recent_projects` 列表本身保留——菜单「最近打开的项目」仍在消费。

存量 `config/recent_projects.json` 中的 `last_closed_root` 键**不做迁移清除**：读取侧不再读它，下次 `add()`/`remove()` 整表写回时经 `_write()`（只覆盖列表键）……不，`_write()` 读全量合并会保留旧键。沿用 `KEY_WORKSPACE_ROOT` 先例（`gui/settings.py` docstring：「存量旧键读取即丢弃自然失效」）——旧键无害残留，不接受则不读；若在意可在 `clear()` 时自然清掉（`clear()` 整表重写只写列表键，本就会丢弃它）。结论：零迁移代码。

### D4 `startup_mode` 设置键整层拆除

`gui/settings.py` 删 `KEY_STARTUP_MODE` 常量、`STARTUP_MODE_*` 值域常量、`AppSettings` / `AppSettingsPatch` 键、`DEFAULT_SETTINGS` 默认值、`load_settings()` 值域防御段；模块 docstring 键数 12 改回 11。存量 settings.json 中的 `startup_mode` 键同 D3——读取即丢弃，自然失效，零迁移。

### D5 设置中心「常规」页整页删除

该页仅含启动模式一项（`_build_general_page` 只构建两枚单选），删除 `_PAGE_REGISTRY` 首行 + `_build_general_page` / `_on_startup_mode` / `_reload_general` + `_STARTUP_MODE_LABELS` + 相关 import。导航首项变为「AI 工具权限」。`_make_hint`、`_STYLE_RADIO`、`_DESC_INDENT` 等其他页仍使用的公共件不动。

### D6 旧计划文档标记撤销，不删除

`work plans/2026-0905-2025_....md` 状态由「已实施」改为「已撤销（2026-0905-2347 计划整体回滚）」，保留全文作历史档案。`2026-0903-0305` 计划（清空历史回退空白窗口）不被撤销——其「无项目可恢复 → 空白窗口」结论在简化后成为**唯一**启动形态，代码中相关注释引用保留有效。

## 3. 验证方案

1. **静态检查**：`grep -rn "startup_mode\|last_closed\|_default_workspace\|_is_unpack_dir\|STARTUP_MODE" main.py gui/` 应只剩历史注释中的计划文件名引用（如有）；`.venv` 下 `python -m compileall main.py gui/` 通过。
2. **端到端（开发态 `uv run main.py`）**：
   - 无参启动（历史非空）→ 空白窗口（欢迎占位、面板置灰）；
   - `uv run main.py 测试文件夹` → 打开该项目；
   - `uv run main.py /不存在的目录` → 空白窗口 + stderr 提示；
   - `--blank`、菜单「新建窗口」→ 空白窗口；
   - 打开项目 A 后关闭 → 再无参启动 → 仍空白窗口（核心目标：任何情况都不恢复）；
   - 设置中心打开 → 无「常规」页，首项为「AI 工具权限」，各页 reload 正常（`_PAGE_REGISTRY` 分发无残留引用）。
3. **回归**：
   - 菜单「最近打开的项目」列表正常展示/回访/清除；
   - 一窗一根：活窗口占用 A 时 `main.py A` → 唤活已有窗口、退出码 3；
   - 「打开文件夹」换根关旧窗流程正常。

## 4. 风险与影响面

- ⚠️ 行为变化：无参启动不再恢复任何项目——**本计划目标行为**，用户显式要求。
- 存量配置残留键（`startup_mode`、`last_closed_root`）无害：读取侧已删，不回读、不写回（`add()`/`remove()` 的 `_write()` 读全量合并会原样保留旧键；`clear()` 整表重写会顺带清掉）——与 `KEY_WORKSPACE_ROOT` 旧键处理先例一致。
- 设置中心导航顺序变化（「常规」消失）——无持久化索引引用（按行分发），安全。
- 简化收益：删除 1 个设置键、1 个设置页、2 个存取方法、2 个 main.py 函数，启动路径从「模式分流 + 二级回退链」收敛为「显式参数或空白」单一路径。
