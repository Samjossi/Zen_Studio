## 3. 协议面盘点：Dream agent 必须满足的 ACP 最小集

以 `acp.py` 客户端实现与四后台实测教训为准（**协议真值来源是代码与实测，不是猜想**）。本节内容即 `dream-acp/protocol/` 文档的章节骨架，二者逐条对应、同步维护。

### 3.1 传输与生命周期

- argv 恒为 `[bin_path, "acp"]`；stdio ndjson JSON-RPC；请求 id 配对；agent 可向 client 发反向请求（审批）
- stdout 只写协议帧，**日志一律 stderr**（防污染协议流；对齐 reasonix `_log_agent_info` 诊断惯例）
- `initialize`：收 `protocolVersion: 1` + `clientCapabilities`（`fs.readTextFile/writeTextFile: false`、`terminal: false`——**client 不代办文件与终端，工具必须 agent 自行执行**）+ `clientInfo`；回 `agentInfo`（name/version）
  - 教训（0730 实测修正 #1）：`authMethods` 是静态能力声明，不能当未配置信号；未配置信号归 `session/new` 错误
- `session/new {cwd, mcpServers: []}`（timeout 60s）→ `{sessionId}`；**cwd 硬校验绝对路径**（reasonix -32602 实测）
- `session/set_config_option {sessionId, configId: "model", value}`（timeout 10s）：模型别名**不透明字符串**，原样接受，不解析不拼接（D6 红线 2）
- `session/cancel`：轮次即停；cancel 后连接与会话须可复用

### 3.2 轮次与流式

- `session/prompt {sessionId, prompt: [ContentBlock]}`：恒 text 块打头（空文本时为占位文案「请查看附图。」——client 已兜底，agent 亦应容忍空 text），随后 image 块（base64 + mimeType）
- 流式通知 `session/update`：`agent_message_chunk`（正文）/ `agent_thought_chunk`（思维链灰字）/ `tool_call` / `tool_call_update` / `usage_update`（`{used, size, cost?}`——size 缺失或为 0 不上屏，无真实数据就不发）
- 收尾响应 `result.stopReason`：正常 `end_turn`；**轮次失败必须显式 `stopReason="error"`**（reasonix 实测修正 #5：失败走正常响应 + 零 update 时用户看到空回复零提示；error 帧亦可，二选一并保持一致）
- 历史由 agent 会话自管理：client 每轮只发末条 user 消息（工具结果回灌在 agent 内部闭环）

### 3.3 审批回环

- 执行类工具前 agent 发反向请求 `session/request_permission {sessionId, toolCall, options}`，options 含 `allow_once/allow_always/reject_once`（kind + optionId + name）
- client 回 `optionId`（None 视为拒绝）；拒绝后 agent 应放弃执行并向用户追问（0730 验收双向验证语义）

### 3.4 本地部署侧

- `_find_bin()` 三级范式：PATH → `$DREAM_HOME/bin` → `~/.dream/bin`（桌面会话 PATH 可能缺 `~/.local/bin`）
- 模型目录来源自持（config 文件自解析或静态表）：缺文件/解析失败全 try 兜底空列表（空列表 = 用 agent 默认模型，不崩 UI）
- 默认模型提首：用户选定的默认 = 菜单回退落点（红线 4 的静默回退首项依赖枚举序）

## 4. `dream-acp/` 协议文件夹设计

自包含、零 import 项目代码、零相对路径依赖——**搬走即完整**。

```
dream-acp/
├── README.md                  # 文件夹导览 + 迁出说明（如何作为 Dream 项目底本使用）
├── protocol/
│   └── dream-acp-v1.md        # 《Dream ACP 接入协议 v1.0》：§3 全条目的正式文档化
│                              #   （帧格式/方法表/错误码表/时序图/实测教训附录），
│                              #   文头带 版本号 v1.0 + 生效日期 + 变更纪律
├── example/
│   └── dream                  # 最小示例 agent（Python 单文件可执行，见 §4.1）
└── tools/
    └── spike_handshake.py     # 握手/轮次/cancel/审批的管道级 spike 断言脚本
```

### 4.1 示例 agent 的协议覆盖度

示例 agent 是「协议的可执行形态」——不接任何模型，但要**覆盖 §3 每一条**，使 Dream 开发者可以逐条对照实现：

- `initialize`/`session/new`（含相对 cwd 拒收 -32602）/`session/cancel` 全实现
- `session/prompt`：固定演示文本逐 chunk 发 `agent_message_chunk` + 一段 `agent_thought_chunk` 演示思维链通道 + 末尾 `usage_update`（演示真实格式）
- 关键词触发演示工具调用（如 prompt 含「建文件」）：`tool_call` → `session/request_permission`（三态 options）→ 按回执执行/放弃 → `tool_call_update` → `end_turn`
- 演示错误路径：特定关键词触发 `stopReason="error"` 收尾
- 两个演示模型别名（如 `dream/demo-fast`、`dream/demo-smart`），验证 `set_config_option` 切换与 `list_models` 枚举联动

### 4.2 版本纪律

- 协议文档版本号独立演进（v1.0 起），与 ACP `protocolVersion: 1` 是两个层面：后者是线协议协商值，前者是 Dream 接入规约的文档版本
- 任何协议面变更（新增方法/字段语义变化）必须升文档版本并在文尾追加变更记录——对齐本项目「修改记录」文档纪律
- Zen Studio 侧 `acp.py` 若发生协议面演进，`dream-acp/protocol/` 同步修订（本计划 §10 明确反向依赖：协议文档跟随客户端实测，不臆造）

## 9. 验证方案

1. **spike 断言**（`dream-acp/tools/spike_handshake.py`，项目 `.venv` 跑）：
   - initialize 响应含 agentInfo；session/new 接受绝对 cwd、拒相对路径（-32602 语义）
   - prompt 收到逐 chunk 流 + thought 段 + usage_update + end_turn；cancel 后同会话可续用
   - 演示工具触发审批反向请求（options 三态齐全）；allow → 演示文件实建；reject → agent 放弃并追问
   - 错误关键词触发 `stopReason="error"` 而非静默空回复
2. **offscreen GUI 冒烟**（依《视觉验证闭环开发指南》既有模式）：
   - 后台菜单出现 Dream 项（第五位）；屏蔽 PATH/DREAM_HOME 后禁用+「（未检测到）」且不作回退落点

   - 响应中三按钮禁用；停止即停；关闭响应中标签 `pgrep` 无孤儿进程
3. **真机回归**：四旧后台全功能零回归（各真实对话一轮：流式/思维链/工具/审批/cancel）；重启后（后台, 接口, 模型）三元组正确还原
4. **验收走查清单**（对齐 0730 实施记录 §4）：流式/思维链演示/工具调用演示/审批 allow+reject 双向/cancel 即停与停后续接/set_model 会话内即时切换（两个演示别名互切）/close 无孤儿/重启还原/未安装标注——逐项打勾后补实施记录
