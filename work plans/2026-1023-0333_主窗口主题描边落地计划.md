# 主窗口主题描边落地计划

> **状态**：已归档（被 `2026-1023-0351_主窗口描边移除与自绘投影落地计划.md` 取代；描边版代码锚点 `4e8a76e`，自绘投影不理想时回退该提交）
> **范围**：`assets/themes/base.qss`（主窗口描边规则）
> **时间**：2026-10-23 03:33（设计，UTC+8）/ 2026-10-23 03:37（实施）
> **优先级**：中

## 背景

开发机已从 X11 切换到 GNOME Wayland 会话。主链路实测正常（窗口行为、中文输入），但发现一处合成器策略类差异：**主窗口外缘阴影消失**。

根因：主窗口为 `FramelessWindowHint` 无边框 + 自绘 TitleBar（`src/gui/main_window.py`），自身不设任何边缘线段；X11 下的阴影由 Mutter 在**服务端**绘制，Wayland 下装饰与阴影均为**客户端责任**，合成器不再代画。后果：窗口浮于白色桌面背景时与背景融合，无法辨认边界。

## 需求

1. 主窗口四周加 **1px 描边**，颜色取**极淡的主题色**——初定与文件查看面板（`#PanelCard`）边线同令牌 `$border`；实施期用户拍板改为**新增独立令牌 `$window_border`，初值直接提取各自主题的标题栏底色**（比 `$border` 更淡一档），取值是静态复制而非运行时引用 title_bar 资源包，与标题栏、卡片边线双向解耦。
2. 描边颜色**随主题切换自动跟随**，六套主题（云白/暖米/晴空/薄荷/石墨/深夜）各自取用本主题的 `$window_border` 值。
3. 单代码库双平台一致生效（X11 / Wayland 不分叉）。

## 探查结论（审计已完成）

| 区域 | 现状 | 判据 |
|---|---|---|
| 主题渲染机制 | ✅ 天然支持随主题切换 | 唯一模板 `assets/themes/base.qss` + 每主题令牌包 `THEME_PALETTES`（`src/gui/theme.py`），`apply_theme` 用 `string.Template` 按主题重渲整表；`$border` 为既有令牌，六主题各自有值，**无需新增令牌、无需新增联动代码** |
| 参照边线 | ✅ 已存在 | `base.qss` 的 `#PanelCard` 规则即 `border: 1px solid $border;`，正是用户所指「文件查看面板四周的边线」 |
| 边缘缩放热区 | ✅ 无冲突 | `EdgeResizeController`（`src/gui/window_resize.py`）八向热区宽度数 px，1px 内描边不侵占有效判定区 |
| 门禁兼容 | ✅ 无冲突 | `scripts/check_qss_selector_guard.py` 只扫 `src/gui/panels/chat/` 下控件级 `setStyleSheet`，不管应用级模板 `base.qss` |
| 现有联合规则 | ⚠️ 需拆开 | `base.qss` 现有 `QMainWindow, QDialog { ... }` 联合规则（背景/文字/选中色）；描边不能直接并入，否则所有对话框一并加边——超出本需求范围 |

## 方案决策

- **在 `base.qss` 新增独立 `QMainWindow` 规则**：`border: 1px solid $window_border;`，置于现有 `QMainWindow, QDialog` 联合规则之后，注释只写 why（Wayland 合成器不代画阴影，描边承担窗口边界辨识度；差异来自合成器策略而非代码缺陷）。
- **新增令牌 `$window_border`**：`QSS_TOKEN_KEYS` 与六主题调色板各加一项，初值静态提取自该主题标题栏底色（云白 `#e8e8ec`、暖米 `#f0e9dc`、晴空 `#dfeaf3`、薄荷 `#dfeddf`、石墨 `#242426`、深夜 `#1d2534`）。用户拍板：描边取标题栏色的淡度，但不要运行时耦合——故为值复制，标题栏日后改色不波及描边，描边微调也不波及卡片边线。
- **双平台无条件生效**，不引入平台探测分支：X11 下 1px 细边与 Mutter 服务端阴影并存，视觉不冲突；符合单代码库、禁散落平台判断的既定决策。
- 主题跟随零新增联动代码：令牌重渲机制既有，切换主题后整表重挂，描边自动换色。

### 不做项（已知取舍，留档）

- **不自绘客户端阴影**：需窗口透明化 + 外扩边距 + 渐变绘制，阴影区计入窗口几何，会连锁影响八向缩放热区、窗口几何恢复与吸附，成本高收益小。
- **不给 `QDialog` 加边**：本次需求仅限主窗口；对话框在 Wayland 下同样无阴影，先观察实际观感，需要时另立计划。

## 实施步骤

### 1. 代码改点

- `src/gui/theme.py`：`QSS_TOKEN_KEYS` 增 `window_border`；六主题调色板各增 `"window_border"` 项（初值见方案决策）。
- `assets/themes/base.qss`：现有 `QMainWindow, QDialog` 联合规则之后，新增：

  ```css
  # assets/themes/base.qss
  /* Wayland 下合成器不为客户端装饰窗口绘制阴影，主窗口外缘失去
   * 边界辨识度；1px $window_border 描边代之（初值提取自标题栏底色，
   * 与卡片边线解耦；X11 下与 WM 阴影并存无冲突） */
  QMainWindow {
      border: 1px solid $window_border;
  }
  ```
