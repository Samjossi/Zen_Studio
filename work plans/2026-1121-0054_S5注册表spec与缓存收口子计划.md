## 1. 背景与目标

`registry.py` 目前同时承担组合根、`BackendSpec` 类型定义、三家厂商的静态元数据、Kimi 目录缓存与三路派生闭包。新增或修改一家厂商仍要编辑集中式大注册表，厂商目录也不是完整入口。

本子计划目标：

1. 把 `BackendSpec` 与 `resolve_efforts` 迁到中性 `llm/spec.py`。
2. 把模型/强度/原始载荷缓存迁到 `llm/cache.py`，`refresh_models()` 仍是唯一失效口。
3. 三家各自新增 `providers/<vendor>/spec.py`，注册表只做组合与查询。
4. 保持公共导出、注册顺序、默认后台、模型目录与缓存行为不变。

## 2. 启动条件与边界

- S0–S4 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S6。
- 只做类型/元数据/缓存的搬迁与组合收口；不改 provider 会话流程、不改模型目录内容、不改默认后台。
- `ide.llm.BackendSpec`、`REGISTRY`、`spec_of`、`vendor_of`、`vendor_groups`、`BACKEND_LABELS`、`VENDOR_LABELS`、`refresh_models`、`resolve_efforts` 的公共行为保持兼容。
- 厂商 `spec.py` 只允许 import 中性 `llm.spec`/`llm.cache`、本厂商模块与 `llm.base`；禁止 import registry 或 GUI。

## 5. 风险与注意点

- **循环 import**：`ide.llm.__init__` 会 import registry，registry import 厂商 spec，厂商 spec 只能 import 中性模块；先把 spec/cache 独立出来，再迁厂商。
- **公共导出破坏**：测试、脚本、GUI 可能从 `ide.llm` 或 `ide.llm.registry` 取类型/函数；迁移前先全库搜索，保留兼容再导出。
- **缓存键漂移**：缓存以接口实现名为键，不要改成厂商名或模块名；`refresh_models` 必须同时清三路缓存。
- **惰性破坏**：厂商 spec 模块级不得执行 CLI 探测或目录子进程；`available`/`list_models` 必须保持可调用对象。
- **注册顺序**：UI 菜单序依赖 dict 插入序；组合顺序必须与现状一致。
- **范围**：不改 provider 会话流程、不改模型目录内容、不改默认后台；发现目录数据差异只记录。

5. **导入无副作用 smoke 的边界**：既有 `ide.core.version` 在 import 期会跑 `git` 子进程取构建号，不能把「import 无副作用」测成「零 subprocess」。子进程 smoke 改为只拦截 `kimi`/`dsh`/`local-cli` 厂商 CLI 探测，允许既有版本加载。
6. **缓存 helper 命名去私有化**：`cached_list_models`/`cached_list_efforts`/`cached_raw`/`clear`；内部字典仍为模块私有。`registry.refresh_models` 通过 `clear_caches` 别名委托 `cache.clear`，测试以 monkeypatch 该别名验证委托，不直接触碰缓存字典。
7. **未新增 `BackendSpec` 字段**：盘点后现有字段已覆盖三家声明，保持字段名、顺序与默认值不变；对照脚本逐项确认。

### 6.3 经验沉淀

1. **中性模块先落地，厂商 spec 后落地**：先建 `llm/spec.py`/`llm/cache.py`，再让厂商 spec 只依赖它们和本厂商模块，最后注册表只 import 三个 `SPEC`；顺序反了会先出现 registry→spec→provider→registry 的环。
2. **工厂保持类对象而非惰性包装**：`factory is KimiAcpLLM` 是隐藏契约；若为绕环改成函数内 import，会破坏身份断言与调用签名，正确做法是让 provider 不反向 import spec。
3. **守卫规则要按 AST targets 的「模块 + 导入名」双形态匹配**：`from m import X` 会生成 `m` 与 `m.X` 两个候选，规则必须用前缀匹配，否则正常导入被误报或违规导入漏报。
4. **缓存失效口只留一个**：`cache.clear` 内一次持锁清三路缓存，注册表只做委托；测试同时验证「同接口三路同点失效」与「按接口名不串其他接口」，防未来只清模型列表。
5. **导入无副作用要区分既有基础设施**：版本加载的 git 调用不是厂商探测；隔离 smoke 应只禁目标厂商 CLI，否则测试会把历史行为误判为回归。
6. **注册表也要纳入公共层守卫**：只扫描 `spec.py`/`cache.py` 挡不住厂商元数据回流注册表；把注册表加入公共词表扫描，并同步移除它的设置键例外，才算真正收口。
7. **文档债务会跨子计划累积**：S3/S4 新增模块没有同步 README，S5 才暴露 `_WireSidecar` 与 `_kimi_catalog` 旧名；后续拆分阶段应把「目录表/现行说明」纳入本阶段收尾，而不是留到下一个计划。
