## 1. 背景与目标

`registry.py` 目前同时承担组合根、`BackendSpec` 类型定义、三家厂商的静态元数据、Kimi 目录缓存与三路派生闭包。新增或修改一家厂商仍要编辑集中式大注册表，厂商目录也不是完整入口。

本子计划目标：

1. 把 `BackendSpec` 与 `resolve_efforts` 迁到中性 `llm/spec.py`。
2. 把模型/强度/原始载荷缓存迁到 `llm/cache.py`，`refresh_models()` 仍是唯一失效口。
3. 三家各自新增 `providers/<vendor>/spec.py`，注册表只做组合与查询。
4. 保持公共导出、注册顺序、默认后台、模型目录与缓存行为不变。

## 2. 启动条件与边界

- S0–S4 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S6。
- 只做类型/元数据/缓存的搬迁与组合收口；不改 provider 会话流程、不改模型目录内容、不改默认后台。
- `ide.llm.BackendSpec`、`REGISTRY`、`spec_of`、`vendor_of`、`vendor_groups`、`BACKEND_LABELS`、`VENDOR_LABELS`、`refresh_models`、`resolve_efforts` 的公共行为保持兼容。
- 厂商 `spec.py` 只允许 import 中性 `llm.spec`/`llm.cache`、本厂商模块与 `llm.base`；禁止 import registry 或 GUI。
- 不新增依赖；不改变 `model_backend` 持久化键与默认值。

## 5. 风险与注意点

- **循环 import**：`ide.llm.__init__` 会 import registry，registry import 厂商 spec，厂商 spec 只能 import 中性模块；先把 spec/cache 独立出来，再迁厂商。
- **公共导出破坏**：测试、脚本、GUI 可能从 `ide.llm` 或 `ide.llm.registry` 取类型/函数；迁移前先全库搜索，保留兼容再导出。
- **缓存键漂移**：缓存以接口实现名为键，不要改成厂商名或模块名；`refresh_models` 必须同时清三路缓存。
- **惰性破坏**：厂商 spec 模块级不得执行 CLI 探测或目录子进程；`available`/`list_models` 必须保持可调用对象。
- **注册顺序**：UI 菜单序依赖 dict 插入序；组合顺序必须与现状一致。
- **范围**：不改 provider 会话流程、不改模型目录内容、不改默认后台；发现目录数据差异只记录。
