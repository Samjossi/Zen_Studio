# 对话区流式跟随智能锁定计划

## 1. 背景与用户诉求

用户原话整理（2026-08-16）：

1. **问题**：AI 流式输出内容与卡片时，对话区视角被持续拉到底部
   （流式跟随本身正常）；但当用户滚轮上翻查看历史对话时，自动跟随
   与用户滚动**互相争抢视角**，用户无法停留在历史位置阅读。
2. **诉求**：用户向上滚动时，系统不得再把视角往下拉；视角锁定机制
   要参考业界成熟做法，而非简单的"鼠标悬停"判定。

## 2. 调研结论（业界做法选型）

桌面 AI 聊天产品（ChatGPT、Claude 桌面端）与终端/日志跟随组件
（xterm.js、stackblitz-labs/use-stick-to-bottom、GitHub Actions 日志）
的事实标准行为：

- **解锁由用户手势触发**：向上滚轮、拖动滚动条、键盘翻页——不是
  鼠标悬停位置。悬停位置与用户意图无可靠关系，且触摸板/键盘翻页
  完全绕过"鼠标位置"信号，故弃用悬停判定。
- **恢复由位置阈值触发**：用户滚回距底部 ≤ 阈值时重新锁定跟随。
- **配套悬浮「回到底部」按钮**：解锁期间浮现，点击一键回底并锁定。

候选方案对比后拍板 **方案 C**：手势解锁 + 底部阈值恢复 + 悬浮
「回到底部」按钮。桌面系统（鼠标滚轮 + 拖动滚动条 + 键盘翻页）
信号干净，触摸分支全部不涉及。

## 4. 设计决策

### D1 核心机制：`_pinned` 跟随锁

两轨各加一个布尔状态 `self._pinned`（初始 `True`），语义：

| 状态 | 行为 |
|:---|:---|
| `_pinned = True` | 流式输出/卡片追加时自动滚底（现状行为） |
| `_pinned = False` | 一切自动滚底被拦截，视角原地不动；悬浮「回到底部」按钮浮现 |

**解锁条件（仅用户手势，程序滚动永不触发解锁）**：

- `wheelEvent` 向上滚动（`angleDelta().y() > 0`，Ctrl 缩放吞并分支
  在旧轨先行判定，不受影响）；
- 拖动滚动条滑块离开底部（监听 `QScrollBar.sliderMoved`，该信号仅
  用户拖拽触发，程序 `setValue` 不触发）；
- 键盘翻页（PageUp / Home；QTextBrowser 与 QScrollArea 均内建支持，
  滚后位置判定自然生效，见恢复条件——键盘上翻后位置离开底部，
  经由 valueChanged 非程序分支统一判定解锁）。

**恢复锁定条件**：

- 滚动停止后视口距底部 ≤ 阈值（初定 48px，拍板点 P1）；
- 或点击悬浮「回到底部」按钮：立即 `setValue(maximum)` +
  `_pinned = True` + 隐藏按钮。

### D2 程序滚动与用户滚动的区分（关键防误判）

`bar.setValue()` 与「内容增长推高 maximum」都会触发 `valueChanged`，
必须区分来源，否则流式输出本身会被误判为"用户在滚"：

- `_do_scroll` 执行期间置 `_in_programmatic_scroll = True` 标志
  （try/finally 包裹 `setValue`），`valueChanged` 回调中遇标志直接
  跳过位置判定；
- 内容增长导致用户**被动**离开底部（用户没滚，新内容把他推离）时
  不得解锁——因此解锁只由 D1 的手势路径触发，`valueChanged` 非程序
  分支只做"距底 ≤ 阈值则恢复锁定"的**单向**判定，绝不在该分支里
  反向解锁。

### D3 悬浮「回到底部」按钮

- 形态：`QToolButton`，文案「↓ 回到底部」（拍板点 P2），objectName
  `BackToBottomButton`，parent 到滚动区 viewport，右下角绝对定位
  （留 16px 边距），`resizeEvent` 中重定位；
- 显隐：`not _pinned` 且不在底部时显示，其余隐藏；
- 样式：`assets/themes/base.qss` 新增 `#BackToBottomButton` 选择器
  规则（半透明底 + 圆角，色板复用既有键，守不新增颜色键纪律），
  注意项目禁无选择器裸属性写法（0811 修复教训），写后跑
  `scripts/check_qss_selector_guard.py` 验证。

### D4 窗口/容器尺寸变化

`resizeEvent` 中若 `_pinned = True`，重新滚底贴尾（否则窗口拉高后
底部留白、跟随失效假象）；`_pinned = False` 时不动视角。

### D5 双轨同步

新轨（transcript.py）与旧轨（output.py）同构实现，逻辑、常量、
注释口径一致；旧轨是双轨开关的回退通道，不可偏废。常量
`_FOLLOW_THRESHOLD_PX = 48` 两轨各自定义（两文件本就各自独立
定义常量，不为此新增共享模块）。

无现成自动化滚动测试，以实机验证为主：

1. 流式输出期间上翻 → 视角停住，「回到底部」按钮浮现；

### 9.1 箭头符号候选池（备查，再改时免重翻）

字形覆盖均已用思源黑体 `QFontMetrics.inFontUcs4` 实测通过：

| 符号 | 码位 | 特点 | 备注 |
|:---:|:---|:---|:---|
| `⏷` | U+23F7 | 中等向下三角，实心扁三角、轻重适中 | **现行**（26px 常规） |
| `⤓` | U+2913 | 向下至横线，"跳到底部"语义最准 | 细线字形，观感太小太轻（需 20px+粗体仍偏弱），弃用 |
| `▼` | U+25BC | 实心倒三角，纯几何形、重心最稳 | 观感太厚重，弃用 |
| `↓` | U+2193 | 简单下箭头，最保守零风险 | 与"向下滚一点"语义分不清 |
| `⇓` | U+21D3 | 双线向下，有"快速下降"感 | 小尺寸易糊 |
| `⬇` | U+2B07 | **禁用**：带 emoji 变体（⬇️），项目装有 Noto 彩色 Emoji，Qt 会渲染成彩色 emoji 破坏素色风格 | — |
