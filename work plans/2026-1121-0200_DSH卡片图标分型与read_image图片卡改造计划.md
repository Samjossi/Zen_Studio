## 1. 背景与目标

DSH 卡片目前的标题行类型图标由 ACP `tool_kind` 决定，而不是由卡片类型决定。盘点结果是：11 个当前可见卡型只落 9 种图案，`read_image` 与普通 read 共用 📄，`todo_write` 与未知工具共用 🧩。用户明确不满意 `read_image` 卡片及其图标，并希望尽可能让不同卡片类型对应不同图案。

本计划目标：

1. 在 DSH 厂商包内建立「卡片类型 → 标题图标」的局部覆盖机制，不动公共 `_KIND_ICONS`，不影响 Kimi/Local。
2. 落地已确认图标分型：`read_image` 用 👁️（U+1F441 U+FE0F）、`todo_write` 用 🎯、`TodoCard` 保持 📋、MCP 服务器用 🔌；未知工具与 AskUserQuestion 保持 🧩。
3. 把 `read_image` 从「MCP 入参/出参调试卡」改造成图片优先的查看卡（可选阶段，独立验收）。
4. 用单测锁定每个卡型的图标，用分厂商截图锁定视觉效果，用全量门禁锁定无回归。

本轮只写计划，不实施；审阅通过后再按 §5 执行。

### 2.3 原图标族与可选范围

项目没有卡片专用的 SVG/图标字体。标题行类型图标来自公共 `card_base.py` 的 `_KIND_ICONS`，全部是 Unicode emoji；运行时由 `assets/fonts/Noto彩色Emoji/NotoColorEmoji.ttf` 统一兜底渲染（`theme.py` 注册该族，`assets/fonts/Noto彩色Emoji/README.md` 明确「只作回退链兜底」）。

完整候选目录见 `维护手册/Noto彩色Emoji图标目录.md`：字体 charset 1,499 个码点，筛出 1,395 个单码点字形，按 16 个分区列出码点、Unicode 名称与「现行/建议/备选」标记；本文档只保留与卡片分型相关的候选，不复制全量。

用户 2026-11-21 已确认最终组合：`read_image` 👁️（U+1F441 U+FE0F）、`todo_write` 🎯（U+1F3AF）、`TodoCard` 保持 📋（U+1F4CB）、MCP 服务器 🔌（U+1F50C）、`QuestionCard` ❓（U+2753，预留）；其余卡型保持现行。

| 用途 | 图标 | 码点 | 来源 |
|:---|:---:|:---:|:---|
| execute | 💻 | U+1F4BB | `_KIND_ICONS` |
| edit | 📝 | U+1F4DD | `_KIND_ICONS` |
| read | 📄 | U+1F4C4 | `_KIND_ICONS` |
| search | 🔍 | U+1F50D | `_KIND_ICONS` |
| fetch | 🌐 | U+1F310 | `_KIND_ICONS` |
| think | 🤖 | U+1F916 | `_KIND_ICONS` |
| other | 🧩 | U+1F9E9 | `_KIND_ICONS` |
| 思维链 | 🧠 | U+1F9E0 | `ThinkingCard` |
| 计划清单 | 📋 | U+1F4CB | `TodoCard` |
| 问答/清单正文 | ❓ ✅ ☑ ▶ ☐ ⏭ | U+2753 / U+2705 / U+2611 / U+25B6 / U+2610 / U+23ED | DSH `cards.py` 正文标记 |

另一组是**文本符号**，不是 emoji 族：状态 `◐`（U+25D0）/ `✔`（U+2714）/ `✖`（U+2716），折叠 `▸`（U+25B8）/ `▾`（U+25BE），复制 `⧉`（U+29C9）/ `✓`（U+2713）。它们走主题色，不在「换卡片类型图标」的范围内。

因此本轮的可选范围就是 **Noto Color Emoji 字体覆盖的 Unicode emoji**：

- 默认用单码点；唯一例外是 `U+1F441`，必须附加 `U+FE0F` 才呈彩色（10pt 下不加会退成灰黑文本眼）；
- 不引入新的 SVG、图标字体或第三方依赖；
- 先用 app 实际 10pt 字号在 20px 图标列内离屏对比，再决定；
- 计划文档表格里的 emoji 可能由阅读器的系统 emoji 字体渲染，**不能代表 app 内观感**；对照图以 `.temp/dsh_icon_candidates_10pt.png`（临时探查产物）为准。

10pt 实测结论：`👁️` 是彩色眼睛，`👁` 不加 VS16 会退成灰黑文本眼；`🎯` 红白靶心最醒目；`TodoCard` 保持现行 📋，与 `📄` 的纸片簇组合是既有状态，不再新增 `📑`；`🔌` 偏深色，但项目现有 4 个主题都是浅色卡头，对比度足够；`❓` 红色醒目。

## 3. 目标方案

### 3.1 图标矩阵（按卡片类型，不按工具别名）

| 卡片类型 | 最终图标 | 相对现状 | 性质 |
|:---|:---:|:---:|:---|
| `BashCard` | 💻 | 保留 | 必做 |
| `DiffCard` | 📝 | 保留 | 必做 |
| `TextOutputCard`（read） | 📄 | 保留 | 必做 |
| `TextOutputCard`（search） | 🔍 | 保留 | 必做 |
| `TextOutputCard`（fetch） | 🌐 | 保留 | 必做 |
| `MediaReadCard` | 👁️ | **📄 → 👁️** | 必做（VS16） |
| `SubagentCard` | 🤖 | 保留 | 必做 |
| `TodoListCard` | 🎯 | **🧩 → 🎯** | 必做 |
| `McpCard`（MCP 服务器） | 🔌 | **🧩 → 🔌** | 必做（工厂拆分） |
| `McpCard`（未知） | 🧩 | 保留 | 必做 |
| `QuestionCard` | ❓ | 预留，不接分派 | 只加类属性 |
| `TodoCard`（计划） | 📋 | 保留 | 核对（不改） |
| `ThinkingCard` | 🧠 | 保留 | 公共卡，不动 |

- **类型级而不是工具名级**：bash/pwsh/shell/terminal 共享 💻；write/edit/patch 共享 📝；grep/glob/fs_search 共享 🔍；web/web_search/web_fetch/fetch 共享 🌐。不为每个别名造一个图标，避免图标表膨胀。
- **`👁️` 是唯一 VS16 例外**：`U+1F441` 默认文本呈现，不加 `U+FE0F` 在 10pt 浅色卡头会退成灰黑文本眼；加 VS16 后为彩色眼睛。两者宽度一致（advance 13px、sizeHint 20px），不会裁切。代码里必须写 `"\U0001F441\uFE0F"`，不要依赖肉眼复制。
- **`🎯` / `📋` 是确认选择**：`todo_write` 用 🎯，10pt 最醒目，语义偏「目标」；`TodoCard` 保持现行 📋，语义最准且与 Kimi/Local 一致。备选为 `📑`/`📌`（TodoCard）、`🗒`（todo_write）、`🖼`/`👀`（read_image）。
- **MCP 必须拆分**：只对 `mcp__` 前缀的工具用 🔌；未知工具与 `AskUserQuestion` 继续 🧩。不能把 `McpCard` 全局设为 🔌，否则所有未知工具都会变成插头。

### 3.2 DSH 局部图标覆盖机制

不修改公共 `CollapsibleCard` / 公共 `ToolCard` 的构造签名，也不改 `_KIND_ICONS`。只在 DSH 的 `ToolCard` 外壳增加一个厂商私有的图标覆盖点：

1. `vendors/dsh/cards.py` 的 `ToolCard` 增加类属性 `_header_icon: str = ""`，以及仅关键字的 `header_icon: str | None = None` 构造参数。
2. `super().__init__()` 完成后，取 `header_icon or self._header_icon`；非空则 `self._icon_label.setText(icon)`。
3. 各卡类声明最终类属性：
   - `MediaReadCard._header_icon = "\U0001F441\uFE0F"`（显示 👁️；必须带 VS16）
   - `TodoListCard._header_icon = "🎯"`
   - `McpCard._header_icon = "🧩"`（未知工具与 AskUserQuestion 的兜底）
   - `QuestionCard._header_icon = "❓"`（仅预留，不接分派）
   - `BashCard` / `DiffCard` / `SubagentCard` / `TextOutputCard` 不声明，继续回退 ACP kind 图标。
4. `TodoCard` 不是 `CollapsibleCard`：保持硬编码的 `QLabel("📋")` 不改；📑/📌 只作备选。标题、完成数、条目绘制不变。
5. `factory.py` 必做 MCP 覆盖：识别 `mcp__` 前缀后，给 `McpCard` 传 `header_icon="🔌"`；未知工具/AskUserQuestion 仍走 🧩。不新增卡片类，不改 `_TOOL_NAME_CARDS`。

为什么在类属性上而不是工厂统一表：

- 图标是卡片自身的视觉属性，跟类放在一起，新增卡类时不容易漏；
- 工厂只需要在「MCP 与未知工具同用 `McpCard`」的场景做一次覆盖，其余不参与；
- 不把 DSH 的 emoji 表写进公共层，符合厂商隔离守卫；
- 不用改三家工厂的统一签名，Kimi/Local 零影响。

### 3.3 `read_image` 图片卡重构（可选 T5）

现状：`MediaReadCard(McpCard)` 的标题行是 `📄 read_image` + 绝对路径副标题；body 先「入参」路径原文 + 320px 缩略图，再「出参」结果图。截图实测整卡接近 800px 高，观感像 MCP 调试卡，不像看图卡。

目标形态（只改展示，不改协议）：

- 标题：保持工具名 `read_image`（可追溯），副标题改为「文件名 · 目录」两段式；完整路径进 tooltip 或折叠明细。
- body：图片优先，不再出现「入参 / 出参」两个调试标签。
  - 运行中只有入参路径：显示入参缩略图，caption 用「待读取」或「输入」。
  - completed 有结果图：显示结果图为主图；入参图与结果图不同时，入参图降为小图或次级行；同一文件只显示一次。
  - 无图片或读取失败：保留路径文本与错误/降级说明，不出现破图占位。
- 路径：底部一行可省略文本 + 复制路径按钮；长绝对路径不再占满标题行。
- 降级不变：文件不存在不渲染、>10MB 留占位说明、无 `media_path` 时回退文本。
- 高度：主图宽度沿用 `MCP_IMAGE_WIDTH`（480），整卡不超过 `BODY_MAX_HEIGHT`（320）的图片区上限。

实现上倾向让 `MediaReadCard` 直接继承 DSH `ToolCard`，不再继承 `McpCard`；类名与工厂映射保持不变，现有 `isinstance(card, MediaReadCard)` 断言不受影响。若审阅只想先解决图标，T5 可后置，`MediaReadCard` 继续继承 `McpCard`，仅加 👁️。

| 纸片图标簇（📄/📋）10pt 区分度 | 这是现行既有组合；`todo_write` 用 🎯，不再新增纸片图标。若以后仍要区分 TodoCard 与 Read，备选 📑/📌。 |
