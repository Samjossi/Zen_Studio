## 1. 背景与目标

前序子计划完成代码迁移后，本项将公共再导出入口收敛，并用可持续运行的架构测试固定依赖方向，防止厂商规则以后重新侵入公共层或跨厂商复用。

后台组合根仍为 `src/ide/llm/registry.py`，卡片组合根仍为 `src/ide/gui/panels/chat/vendors/registry.py`。只有这两个组合根可以按职责装配具体实现，且 LLM registry 不得反向 import GUI。

## 6. 实施结果回写（2026-11-20 23:55 UTC+8）

T5 全部完成，修改记录见 `文档/修改记录/2026-1120-2355_T5公共出口收敛与架构守卫实施记录.md`。以下为实施过程中相对原计划的偏差与经验。

**与计划的偏差**：

1. **删除 `BACKEND_KIMI_ACP`，默认后台常量迁入 `registry.DEFAULT_BACKEND`**：计划只要求公共出口收敛为稳定契约与 registry API，没有点名这个厂商命名常量。实际全库仅 `settings.py` 消费它，保留别名会形成第二个公共入口，故改由注册表持有；值仍为 `"kimi-acp"`，持久化键与默认后台行为不变。
2. **公共注释中性化范围略大于「旧行为描述」**：除删除旧模块路径外，还把 `base.py`、`acp/connection.py`、`acp/content.py`、`acp/prompt.py` 中的厂商名、私有 wire 字段和具体错误码清单改为中性技术描述，并把 `card_base.py`、`permission_dialog.py`、`question_bridge.py` 注释中的 `DiffCard`/`BashCard`/`McpCard`/`SubagentCard`/`QuestionCard` 等具体卡片类名改为能力/形态描述。只改注释/docstring，不改字段、常量、异常类型或调用链。
3. **守卫扫描 `src/ide/**/*.py` 与 `main.py`，未扫 `src/markdown_it`、`src/mdurl`**：二者是 vendored 第三方库，不属于本次 IDE 依赖边界；计划要求只扫生产源码，未要求扫 vendored 库。扫描集共 136 个模块，测试中有覆盖断言防止空扫。
4. **import 目标采用保守展开**：`from package import name` 同时记录 `package` 与 `package.name` 候选，以抓住 `from ide.llm.providers import kimi` 这类子模块导入；规则可能多报，但当前生产源码无误报，换取不漏报。
5. **新增「provider 不得导入公共出口」规则**：计划只列 registry/GUI，实际 `ide.llm` 顶层会 import registry，provider 反向导入它同样形成环，故一并禁止；已加受控反例。
6. **未改 `PermissionDialog` 的用户可见文案「Kimi ACP 请求执行工具」**：这是 T4 记录在案的已知残留，T5 范围是公共出口、依赖与现行维护说明，不含用户文案改版；如需中性化应单独立项并覆盖 DSH/Local 验收。
7. **`KEY_KIMI_WIRE_SIDECAR` 保留在 `settings.py`/`panel.py`**：它是 Kimi 子代理旁路的用户配置开关，经 duck typing 注入，未形成厂商 ID 分支，不属于 T5 的公共出口再导出或公共层词表范围。
8. **没有删除既有局部边界断言**：`test_update_mapper_isolation.py` 与 `test_permission_boundaries.py` 中的厂商横向 import 断言继续保留，作为统一守卫之外的附加护栏；未用新测试替代或删除旧测试。

**验证结果**：

- 架构守卫定向：`QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests/test_provider_boundaries.py -q` → **49 passed**（`.temp/t5_boundary_evidence.log`）。
- 全量门禁：`UV_CACHE_DIR=$PWD/.temp/uv-cache bash scripts/check.sh` → 隐私扫描通过、可选中 QLabel 裸用守卫通过、ruff 通过、**128 passed**（`.temp/t5_check.log`）。
- 守卫覆盖：`src/ide/**/*.py` 135 个模块 + `main.py`，共 136 个；只排除 `tests/`、`scripts/`、历史文档和帧存档，测试断言扫描集包含两个组合根、ACP 公共包、通用面板与三家厂商包。
- 依赖方向：具体 provider 导入只剩 `registry.py` 的 kimi/dsh/local 三处组合根；生产代码无旧平铺模块路径；公共 LLM 层与通用聊天 GUI 无厂商工具名/私有载荷字段/私有 configId/落盘路径；`ide.llm` 运行时可导出符号中无 `KimiAcpLLM`/`DshAcpLLM`/`LocalAcpLLM`（`.temp/t5_boundary_evidence.log`）。
- 受控反例：覆盖跨厂商后台/GUI 导入、通用模块导入具体 provider、通用 GUI 导入厂商卡片、provider 导入 registry/公共出口、LLM 导入 GUI、GUI 厂商包导入 provider 运行时、旧模块路径、33 个公共层私有词表；聚合入口 `_all_violations` 也有失败用例，证明全绿不是没扫到目标。
- 行为：公共出口收敛只改导出面与注释；`DEFAULT_SETTINGS[KEY_MODEL_BACKEND]` 仍为 `"kimi-acp"`，`REGISTRY` 仍含三后台；既有 79 个行为测试全部保留并通过。
- 未做真实 CLI 端到端；未读写凭据；真实 Kimi/DSH/Local 验收留 T7，冻结态构建留 T6。验证日志只落 `.temp/`。未执行 `git commit`/`git push`。

**经验沉淀**：

1. **公共出口收敛必须给「默认值」找中性归属**：只删具体 provider 类还不够，厂商命名的默认常量仍是公共入口的厂商语义。把它放回注册表组合根、公共出口只转发注册表 API，才能既保行为不变又不留第二入口。
2. **守卫要测聚合入口，而不只是子规则**：子规则各自有反例仍可能因 `_all_violations` 漏接而全绿；本次给聚合入口单独加失败用例，避免「规则对了但没接上」。
3. **`from package import name` 必须按候选子模块展开**：只记录 `node.module` 会漏掉 `from ide.llm.providers import kimi` 这种绕过；保守展开的代价是多报，但可用组合根/厂商自身包例外收敛。
4. **公共层词表规则要明确排除组合根**：注册表必须持有厂商 ID 与私有配置键，若不排除会把合法装配点判违规；公共层与组合根分文件、分规则，守卫才不会逼着把厂商语义藏到别的公共模块。
5. **注释也是架构的一部分**：公共 ACP/base 的厂商示例和私有路径会诱导后来者按旧方向加代码；本次把注释中性化并纳入词表守卫，比只在评审口头约束更可持续。
6. **静态 AST 守卫有边界**：它能抓常见 import 与字符串回潮，抓不住 `getattr`/动态 `import_module` 绕过；仍需代码评审红线和后续按需扩展，不能把全绿当成绝对安全证明。
