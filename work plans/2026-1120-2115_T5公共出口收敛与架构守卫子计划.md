## 1. 背景与目标

前序子计划完成代码迁移后，本项将公共再导出入口收敛，并用可持续运行的架构测试固定依赖方向，防止厂商规则以后重新侵入公共层或跨厂商复用。

后台组合根仍为 `src/ide/llm/registry.py`，卡片组合根仍为 `src/ide/gui/panels/chat/vendors/registry.py`。只有这两个组合根可以按职责装配具体实现，且 LLM registry 不得反向 import GUI。

## 2. 启动条件与边界

- 主计划 T4 已勾选，且用户明确批准 T5 后才能开始；本项批准不包含 T6。
- 守卫只扫描生产源码，不扫描历史文档、帧存档或测试夹具。
- 不引入新依赖，不用宽泛字符串规则误伤正常日志与中性命名。
- 历史选型与历史计划保留原样；只更新现行注释、README、脚本说明和维护手册。
- 不通过删除测试、放松既有安全断言或保留双入口 shim 规避违规依赖。

## 3. 实施步骤

### T5.1 收敛公共出口

1. 将 `src/ide/llm/__init__.py` 收敛为稳定契约、ACP 公共类型和 registry API。
2. 生产代码需要具体 provider 类时，仅允许后台 registry 从厂商包导入；具体类由本厂商包导出。
3. 更新 `src/ide/llm/providers/__init__.py`，避免再导出所有具体 provider 形成误用入口。
4. 全库搜索并清理现行代码中的旧模块路径、公共 mapper、公共具体卡片、公共工具载荷、工具名分派表和厂商 ID 特判。

### T5.2 增加 AST 架构守卫

1. 新增 `tests/test_provider_boundaries.py`，使用 Python 标准库 AST 检查主计划 §5.3 的 import 方向。
2. 覆盖 Kimi/DSH/Local 后台与 GUI 厂商包的双向隔离、两个组合根例外，以及 provider/公共 ACP 不得依赖 registry/GUI。
3. 检查通用面板、公共 ACP 和公共 UI 基础件不得依赖具体 provider、私有 mapper、具体厂商卡片或厂商 models。
4. 检查公共层不含已知厂商工具分派表、具体卡片 schema、私有 configId 和 wire 路径；厂商卡片包不得互借 cards/presenter。
5. 先用受控反例证明守卫会失败，再验证现行源码通过；反例只存在于测试构造或 `.temp/`，不污染生产树。

### T5.3 更新现行维护说明

1. 更新 `src/ide/llm/README.md`、相关脚本说明和维护手册中的目录、新增后台与新增厂商卡片流程。
2. 说明 `2026-1119-0952_DSH卡片完备度审计选型.md` 的公共别名层后续路线已被主计划替代，但不修改历史选型文档。
3. 清理仍描述旧行为的模块 docstring 和实现注释，确保说明与实际依赖方向一致。
4. 运行架构守卫、相关定向测试和 `bash scripts/check.sh`。
