## 1. 背景与问题

### 1.1 现象（用户截图实证，2026-08-03）

一级落地后，多步任务的对话区活动流仍过于稀疏——截图实证形态：

```
◐ ▸ Agent
◐ ▸ Agent
✔ ▸ Agent
✔ ▸ Agent
```

每个工具两行（调用行 + 状态行），子代理全程只见「Agent」一词：
**改了什么文件、diff 内容、子代理产出、bash 运行中进度、读取/搜索的
结果规模，全部不可见**。信息密度与可追踪性仍不满足「看清 AI 在做什么」。

### 1.2 剩余盲区定位（对照协议事实 F3，已实证数据均在协议侧）

1602 计划 §7 明示的二级候选即本计划范围；逐项对照现状代码：

| 盲区 | 协议数据来源（F3 已实证） | 现状处置 | 现状代码位置 |
|---|---|---|---|
| 工具行状态就地改写（一工具两行 → 一行） | toolCallId 状态锚点键 | ◐ 行 + ✔/✖ 行**追加**，无就地改写（一级 D1 明示不做） | `output.append_tool_update` 追加式 |
| edit 改了什么（diff 不可见） | `tool_call.content[]` 的 diff 项 `{path, oldText, newText}` | 完全不消费，只显示「Edit — path」 | `acp._map_tool_call` 丢弃 content |
| 子代理产出（成果不可见） | completed 帧 `rawOutput.output` 的 `<task_result>` 包裹文本（1425 之 K2） | `_extract_tool_output` 提取后**路由层丢弃**（非 execute 不上屏） | `panel._on_activity_chunk` execute 过滤 |
| bash 运行中进度（长命令「卡住」观感） | `tool_call_update(in_progress)` 输出快照帧（可多次，F3） | **整帧滤除**（一级 D1：上屏即刷屏） | `output.append_tool_update` status 过滤 |
| read/search/fetch 结果规模（读了多少、命中多少） | 同上输出正文行数统计 | `output_total_lines` 已提取但随正文一并丢弃 | 同上 |
| todo 进度概览 | entries 状态计数 | 无副标题，逐行扫读才知进度 | `output._insert_todo_entries` |

结论：**协议侧数据早已到达 IDE 并被提取，盲区全在「路由层丢弃 +
渲染层无形态」**，与 1602 一级同性质——仍是纯 IDE 侧改造，不动 ACP
连接层、不需要 agent 侧配合。

## 2. 改造总思路

一条主线：**锚点机制泛化**（1425 §5.2，本计划唯一基础设施）+ 四个
信息块摘用（diff / 子代理成果 / bash 尾窗 / 结果摘要），自下而上三层：

1. **协议层**（`llm/providers/acp.py`）：tool_call / tool_call_update
   载荷扩字段——diff 预格式化（+N -M 计数 + hunk 列表）、子代理成果
   摘要（`<task_result>` 正则提取截断）、in_progress 快照帧放行
   （携带截尾输出）；GUI 依旧不碰 rawInput/rawOutput 各家差异。
2. **渲染层**（`gui/panels/chat/output.py`）：锚点簿记由 todo 单锚点
   泛化为「工具行锚点表 + todo 锚点」统一偏移维护；新增工具行就地
   状态改写、diff 着色卡、成果摘要块、bash 运行中尾窗四种渲染形态。
3. **路由层**（`gui/panels/chat/panel.py`）：`_on_activity_chunk`
   按 toolCallId 分流——in_progress 带输出帧进尾窗（节流）、completed
   就地改写工具行并摘挂信息块；全部只上屏不入历史（红线不变）。

## 4. 实施任务分解（T1–T8）

### T1：`gui/panels/chat/output.py` —— 锚点簿记泛化（D1/D4 共同基础设施，先行）

**现状**：`_todo_anchor: tuple[int, int] | None` 单锚点（upsert_todo_block），
位置不变性论证基于「唯一改写者即簿记者自身」。

**改动**：

1. 新增工具行锚点表 `_tool_line_anchors: dict[str, tuple[int, int]]`
   （toolCallId → 行区间 document position，区间含行首 `\n` 与行尾
   `\n`，与 todo 锚点同构保证替换后结构不变）。
2. **偏移维护纪律**（多锚点共存的核心不变量）：任何锚点区间的改写
   （removeSelectedText + 重插）产生长度差 `delta` 时，对**所有**
   start > 被改写区间旧 end 的簿记（工具行锚点表与 `_todo_anchor`
   统一遍历）执行 `start += delta; end += delta`。封装为内部方法
   `_shift_anchors(after: int, delta: int)`，三个改写点
   （工具行改写 / todo 替换 / 尾窗重写）统一调用。
3. `reset_activity_anchors()` 扩展：工具行锚点表与尾窗锚点一并清空
   （轮次收尾语义不变）。
4. 降级预案沿用 1602-T5 范式：就地改写实测失稳则退回追加式（D1-B /
   D4-B），仅改渲染方法内部，路由与映射层不动。

### T2：`output.py` —— 工具行就地状态改写（D1-A）

1. `append_tool_call(payload)` 改造：上屏后记录
   `_tool_line_anchors[tool_call_id] = (start, end)`（无 id 不簿记，
   该工具状态更新降级为追加行——容错路径）。
2. 新增 `update_tool_line(payload)`：completed/failed 到达时按锚点
   选中旧行区间 → 重插 `✔ ▸ title — summary` / `✖ ▸ title（error）`
   （格式与 append_tool_update 现状一致，L2-2 双格式分段保留），
   delta 偏移维护（T1-2）；锚点缺失回退追加。
3. `append_tool_update` 重构为薄壳：有锚点走 `update_tool_line`，
   再按 D2/D3/D4 摘挂信息块（见 T4/T5/T6）。
4. 文本内容与 acp 兜底文本零漂移纪律不变（改一处须同步）。

### T3：`llm/providers/acp.py` —— diff 与成果摘要载荷扩展（D2/D3 数据侧）

1. `ToolCallPayload`（base.py）新增可选键：
   - `diff_stat: str`——`+N -M` 预格式化计数（edit 类）；
   - `diff_hunks: list[dict]`——预解析 hunk 列表
     （`[{head: str, lines: list[tuple[str, str]]}]`，lines 为
     (前缀 `+`/`-`/空格, 文本)；协议层从 `content[]` diff 项的
     oldText/newText 以 difflib 生成 unified hunk，**只保留 hunk
     不保留全文**，超 200 行截断并置截断标记）；
   - `result_summary: str`——think（task 子代理）completed 帧的
     `<task_result>...</task_result>` 正则提取，净化 + 截 10 行
     （1425 之 K2；无包裹标记时取 output 全文截 10 行兜底）。
2. `_map_tool_call`：kind == "edit" 且 content 含 diff 项时提取
   （F3：edit 时 content 携带 `{path, oldText, newText}`）。
3. `_map_tool_call_update`：
   - status == "completed" 且 kind == "think"（经路由层簿记反查不可
     得——**协议层按 update 帧自身 kind 判定，缺省则不产摘要**，路由层
     不再补充）时填充 `result_summary`；
   - **in_progress 帧放行改造**：status == "in_progress" 且
     `_extract_tool_output` 有产出时**返回 Chunk**（现状返回正常
     Chunk 但渲染层滤除；本计划改为路由层分流，见 T6），payload
     output 截尾改末 5 行（尾窗规格，区别于完成卡末 20 行）。
4. 兜底文本同步：diff_stat 附于 tool_call 兜底行尾、result_summary
   追加于 update 兜底文本（多行）。

### T4：`output.py` + `gui/theme.py` —— diff 着色卡（D2-B）

1. ChatPack 新增两键（直抄 1425 之 K7 色值，守四主题共享引用纪律）：
   - `diff_add_fg`：`#3a8437`（成功绿）；
   - `diff_del_fg`：`#ed4831`（错误红）；
   hunk 头（@@）复用 reasoning_fg 灰弱化，不新增键。
2. 渲染：`update_tool_line` 完成后若 payload 带 `diff_hunks`，于
   工具行下追加等宽字体卡（与 L2-3 bash 输出卡同载体：table+bgcolor
   复用 `tool_output_bg`）——`@@` 头灰、`+` 行绿、`-` 行红、
   上下文行默认色逐行 `insertHtml` 内联 `<font color>`；截断标记时
   末行灰字尾注「…… diff 过长，仅显示前 200 行」。
3. `+N -M` 计数（`diff_stat`）附于工具行摘要尾（就地改写后的行
   内容的一部分）。

### T5：`output.py` —— 子代理成果摘要块（D3-A）

1. `update_tool_line` 完成后若 payload 带 `result_summary`：于 ⧉
   工具行下追加弱化灰块（reasoning_fg，非斜体——与思维链区分，
   成果是「事实记录」非「自言自语」），每行前导四空格缩进，
   末行后一空行间距。
2. 无 `result_summary`（agent 未给/提取失败）静默略过，不影响状态行。

### T6：`panel.py` + `output.py` —— bash 运行中尾窗（D4-A）

1. 路由层 `_on_activity_chunk` 的 tool_call_update 分支新增：
   status == "in_progress" 且 payload 带 output 且 tid 在
   `_tool_commands` 簿记（execute）→ `output.upsert_tool_tail(tid,
   output)`；非 execute 或无输出静默丢弃。
2. **节流**：panel 簿记 `{tid: 末次上屏时间}`，同 tid 200ms 内到达
   的快照帧只更新待发数据不上屏（QTimer 单发冲刷或时间戳判定，
   实现取简）；completed/failed 帧强制冲刷（终态不丢）。
3. 渲染层 `upsert_tool_tail(tid, tail_text)`：锚点表新增
   `_tail_anchors: dict[str, tuple[int, int]]`——首帧于对应工具行
   之后插入尾窗块（等宽字体、tool_output_bg 底卡、尾部 5 行），
   后续帧锚点重写（T1-2 偏移维护）；completed 时 `update_tool_line`
   摘挂完整输出卡（末 20 行规格不变）后**尾窗块移除**（锚点选中删除，
   避免与完成卡重复）。
4. 尾窗不挂 `$ 命令` 头（工具行本身即命令标题，防重复）。

### T7：`panel.py` —— read/search/fetch 结果摘要尾注（D5-A）

1. `_on_activity_chunk` 的 output 过滤逻辑调整：非 execute 工具
   completed 帧**保留 `output_total_lines`、丢弃 `output` 正文**
   （现状是整键丢弃）。
2. `update_tool_line` 行尾追加 ` —— N 行`（tool_fg 灰；N=0 或
   缺省不追加）。search 类语义为命中行数、read 为读取行数，统一
   「N 行」表述不细分（agent 输出口径差异，不臆造语义）。

### T8：`output.py` + `acp.py` —— todo 副标题（D6-A）

1. `_insert_todo_entries` 块首行插入副标题：
   `☑ ▸ 任务清单 — {completed}/{total} 项完成`（tool_fg 加粗标题 +
   灰计数，与工具行层级同语言）。
2. 锚点区间含副标题行（替换时整块含头，结构不变性维持）。
3. acp `_todo_fallback_text` 兜底文本同步加首行。

## 7. 边界与遗留
