# 空白窗口设置中心模型页崩溃修复计划

> **状态**：已实施（2026-09-05）
> **范围**：`gui/settings_dialog.py`（唯一改动文件）
> **时间**：2026-09-05 20:44（UTC+8）（设计）/ 2026-09-05 20:50（实施）
> **优先级**：中

---

## 0. 背景与目标

### 0.1 Bug 现象

空白窗口（不绑定工作区根：`--blank` / 新建窗口 / startup_mode = blank 无参启动）中打开设置中心，对话框构建或显示即崩溃：

```
AttributeError: 'NoneType' object has no attribute 'current_backend'
```

（2026-0905-2025 启动模式计划实施验证时发现；startup_mode = blank 落地后空白窗口成为一等启动形态，本 bug 的触达率随之上升。）

### 0.2 期望行为

空白窗口可正常打开设置中心。模型页语义为「作用于当前活动会话标签」（2026-0803-0112 计划 T5），空白窗口无会话标签——模型页三下拉降级为禁用态并提示原因；其余各页（常规 / 权限 / 外观 / 终端 / 高级）不依赖聊天面板，正常工作。

---

## 1. 根因

空白窗口 `MainWindow.chat_tabs` 为 `None`（`gui/main_window.py` 空窗分支置 None，类 docstring 已声明「消费点显式守卫」纪律），而 `gui/settings_dialog.py` 有三处**未守卫**的消费点：

1. `_reload_model()`：首行 `self._ctx.chat_tabs.current_backend()`，其后 `current_version()`——`reload()` 分发即炸；
2. `showEvent()`：`self._ctx.chat_tabs.is_busy()`——对话框每次显示即炸；
3. `set_model_enabled()`：本身不碰 chat_tabs，但其调用方（`showEvent`）会炸。

模型页变更槽（`_on_model_activated` 等）经 `MainWindow.apply_model_selection` 已有 None 守卫（`gui/main_window.py`），不在爆炸链上；`_on_chat_busy_changed` → `set_model_enabled` 链路由 ChatTabs 信号驱动，空白窗口无 ChatTabs 不会触发。

关键前提（决定修复可静态化）：**窗口实例生命周期内 `chat_tabs` 恒 None 或恒非 None**。空窗「打开文件夹」就地填充走的是换根关旧窗路径——起新进程、探活后 `self.close()` 旧窗（`gui/main_window.py` `open_folder_here` / `_close_after_spawn`），旧窗实例永远不会后天获得聊天面板。故降级态在建页时一次定型即可，无需动态切换。

---

## 2. 修复方案

### D1 模型页降级禁用 + 守卫早退（核心），不禁导航项

备选方案「空白窗口禁用模型页导航项」否决：导航骨架由 `_PAGE_REGISTRY` 静态驱动、不感知 ctx 状态，禁用项需改骨架与导航点击行为，为单页状态引入全局机制，得不偿失。页内降级（控件禁用 + 说明）与该页既有「当前会话响应中暂不可切换。」提示同款形态，用户可预期。

`gui/settings_dialog.py` 单文件三处改动：

1. **`_build_model_page()`**：三下拉建好后，若 `self._ctx.chat_tabs is None`——三下拉 `setEnabled(False)`，追加 hint「空白窗口无会话标签，模型选择不可用；打开文件夹后生效。」；
2. **`_reload_model()`**：首行守卫 `if self._ctx.chat_tabs is None: return`（三下拉保持建页初态：空 + 禁用，无填充需求）；
3. **`showEvent()`**：`set_model_enabled(...)` 实参加 `chat_tabs is not None` 合取；`set_model_enabled()` 的 `on` 表达式同步补 `self._ctx.chat_tabs is not None`——双保险，任一新调用方未来直接调它也不会把空窗三下拉重新使能。

### 为什么不做「空窗自动跳过模型页 reload」的全局机制

reload 分发循环（`_PAGE_REGISTRY` 驱动）保持零改动：守卫落在唯一需要它的页内，与「消费点显式守卫」纪律一致；全局跳过机制目前只有一个消费点，属提前抽象。

## 4. 验证方案

1. **离屏冒烟（项目 `.venv`，`QT_QPA_PLATFORM=offscreen`，临时脚本落 `./.tmp/` 验完即删）**：
   - 空白窗口（`MainWindow(workspace_root=None)`）构造并 `show()` `SettingsDialog`：不崩溃；模型页三下拉禁用、hint 在场；逐页切换导航无异常；
   - 带根窗口回归：模型页三下拉可用，`reload()` 正常回显当前标签选择。
2. **实机回归**：
   - 空白窗口（`uv run main.py --blank`）打开设置中心 → 各页可用，模型页禁用带提示；
   - 空白窗口内「打开文件夹…」就地填充后 → 新窗设置中心模型页正常（换根关旧窗路径回归）；
   - 带根窗口 AI 响应中打开设置中心 → 模型页禁用（busy 联动既有行为回归）。

---

## 5. 风险与影响面

- 无行为变化风险：带根窗口路径仅在 `set_model_enabled` 多了一个恒真合取项（chat_tabs 非 None），语义不变。
- 空白窗口模型页从「崩溃」变为「禁用 + 提示」——纯修复，无既有用户习惯被打破。
- 设置中心其余页面本就与聊天面板无关，不在改动面内。
