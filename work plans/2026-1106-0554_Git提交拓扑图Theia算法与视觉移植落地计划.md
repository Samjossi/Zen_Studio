## 1. 目标与决策来源

用户已在 `2026-1106-0550_Git提交拓扑图现成实现复用方案选型.md` 中选择方案 A：移植 Theia SCM History Graph 的泳道算法与 SVG 视觉几何，由现有 PySide6 控件体系原生承接。

本计划取代 `2026-1106-0529_Git树内嵌页泳道图主视觉重构落地计划.md` 中“继续复用 `git log --graph` 字符格、不新增 parents/lane 算法”的技术路线；历史文档保留，不回写。目标不是再补字符图元，而是让提交图直接消费真实 commit id 与有序 parent ids：

- 每个提交固定占一行，节点、活跃泳道、分叉与合并边由同一结构化图模型描述。
- 主路径不再解析 Git 字符画，不再生成纯连接行，不再维护 `*`、`|`、`/`、`\`、`-`、`_`、`.` 等字符到图元的翻译。
- 保留已经完成的 graph-only 内嵌页、完整四列弹窗、共享三页栈、加载边界、彩色富文本降级、主题与滚动语义。

## 2. 当前代码基线

### 2.1 已完成且应保留

- `src/core/git/log.py` 已有 `--all` 引用视野、500 条上限、提交总数统计、空仓库归一、refs 分类和双时间解析。
- `src/gui/git_graph_content.py` 已统一结构化视图、彩色富文本降级与占位页；主题和字号重绘使用缓存，不重复查询 Git。
- `src/gui/panels/git_graph_panel.py` 已实现进入页面和页内按钮两类加载入口，隐藏时不主动查询提交历史。
- `src/gui/git_graph_view.py` 已实现 graph-only 单列、完整四列模式、整行 tooltip、HEAD/悬停/选中、超宽横向滚动，以及刷新后的选中与横纵滚动恢复。
- `src/gui/git_graph_dialog.py` 已复用共享内容并保留详细文本阅读；下方 `ChangesPanel` 与提交图数据路径相互独立。

### 2.2 必须替换的旧内核

- `fetch_commit_rows()` 当前只取短 hash，缺少完整 commit id 和 parents，并通过 `--graph --color=always` 取回字符前缀与 ANSI lane 色。
- `CommitRow.graph` 当前是字符格序列，`is_connector=True` 表示无提交元数据的额外连接行；模型行数因此不等于提交数。
- `GraphColumnDelegate` 当前逐字符绘制，graph-only 与完整模式还维护不同格宽、节点尺寸和连接行高。
- `is_supported_graph()` 与未知字符降级只服务于旧字符内核；移植后应删除，不再把字符覆盖完整性当作结构化图可用性的判据。
- `fetch_commit_graph()` 是独立的彩色富文本失败降级，不属于被替换主内核，继续原样保留。

## 3. 需求与验收目标

1. 结构化主取数同时取得完整 commit id、完整且有序的 parent ids、短 hash、主题、作者、双时间和 refs，并使用 `--topo-order`。
2. 新增无 Qt 依赖的 Python 纯函数，等价移植 Theia `computeGraphRows()`，输出 lane、color、edges、hasTopLine 和 hasContinuation。
3. 图模型只表达 `pass-through`、`branch-out`、`merge-in` 三类边；第一父同泳道连接由节点上/下线段表达，不伪造额外边或提交行。
4. 内嵌页和完整弹窗共享同一拓扑模型与图列几何；内嵌页继续只显示图，完整弹窗继续显示 hash + refs + 主题 + 作者 + 时间四列。
5. 默认视觉对齐参考实现：22px 泳道宽、22px 提交行高、普通节点半径 5px、HEAD 外圆半径 7px 和主题背景色内点；节点最后绘制并覆盖线端。
6. HEAD 只由真实 refs 判定，不采用 Theia“第一行且 lane 0 即 HEAD”的推断。
7. 保留主题 `TERMINAL_PACK`、字号跟随、整行 tooltip、键盘单选、横纵滚动及刷新状态恢复；选中身份改用完整 commit id。
8. 保留 `--all`、500 条上限、空仓库/非仓库/失败占位和彩色富文本降级。截断时未加载父节点只形成图边界，不生成虚假提交记录。
9. 实质翻译的算法、几何与测试按 EPL-2.0 路径保留版权和许可信息；根项目 MIT 许可不变，`NOTICE` 不再把本次移植描述成“未复制实质代码”。
10. 下方 `ChangesPanel`、M/U/D 双击、文件树切换和 Git 状态服务刷新边界保持不变。

## 4. 技术设计

### D1 数据契约：完整身份与 parents 进入主模型

在 `src/core/git/log.py` 调整结构化命令与解析：

- 主命令移除 `--graph` 和 `--color=always`，加入 `--topo-order`，继续使用 `--all --decorate=full -n 500`。
- pretty format 依次包含 `%H`、`%P`、`%h`、`%s`、`%an`、`%ar`、`%aI`、`%D`，沿用 `%x1f` 字段分隔和 `%x1e` 记录尾。
- `%H` 写入 `commit_id`，作为图节点与刷新恢复的唯一身份；`%P` 按空格拆为 `parent_ids`，顺序即 Git 父提交顺序；`%h` 继续写入现有 `commit`，供表格和 tooltip 展示。
- 每行必须有固定字段数，完整 id 非空；格式漂移整体返回 `None`，继续走现有富文本降级。主题、作者、双时间和 refs 继续复用现有解析函数。
- 主取数不再产生 `is_connector` 行；`CommitGraph.rows` 与有序提交一一对应，末尾截断提示仍是模型附加行而不是提交。

### D2 纯算法模块：等价翻译而非重新设计

新增 `src/core/git/graph.py`，只依赖 Python 标准库：

- 定义不可变 `GraphEdge` 与 `GraphRow`，字段对应 `from_lane`、`to_lane`、`color`、`kind`、`lane`、`edges`、`has_top_line`、`has_continuation`。
- `compute_graph_rows(commits)` 接收拓扑有序、由新到旧的 `(id, parent_ids)` 数据，完整翻译第一父继承、额外父分支、已有父汇入、重复泳道收敛、根节点、泳道释放与首个空位复用。
- 颜色保持参考算法的 `lane % 8` 索引，不在核心层读取 Qt、主题或 ANSI 文本。
- `CommitRow` 以 `graph_row` 保存对应结果，删除旧字符 `graph` 与 `is_connector` 契约；`fetch_commit_rows()` 在元数据解析完成后一次计算并按原顺序配对。
- 不为 500 条之外的父提交补节点。算法可保留指向未加载父提交的活跃泳道，使最后一行连线自然到达图底边界。

### D3 Qt 绘制：三类边与节点线共享同一几何

将参考 SVG 几何的实质翻译隔离到新增 `src/gui/git_graph_renderer.py`，由 `GraphColumnDelegate` 调用，避免与字符绘制并存：

- 统一以 `lane_x(lane) = 左安全边距 + lane × lane_width + lane_width / 2` 和行中 `cy` 计算端点；内嵌与完整模式不再维护两套连接行几何。
- `pass-through`：从行顶到行底的竖线。
- `merge-in`：从来源泳道行顶到当前节点中心的三次贝塞尔曲线，控制点与参考 SVG 一致。
- `branch-out`：从当前节点中心到目标泳道行底的三次贝塞尔曲线，控制点与参考 SVG 一致。
- `has_top_line` 与 `has_continuation` 分别控制当前节点泳道的行顶→节点中心、节点中心→行底线段；第一父同 lane 不再额外画边。
- 绘制顺序固定为 pass-through → merge-in → 节点上/下线段 → branch-out → 节点，保证节点覆盖所有线端。
- 普通节点半径 5px；HEAD 使用半径 7px 的 lane 色外圆和主题背景色内点，不再用“首行”推断，也不沿用当前 accent 外环替代参考 HEAD 形态。
- 以 22px lane/row 为默认基线，随全局等宽字体度量有界放大；超宽时保持 lane 宽并启用横向滚动，宽 viewport 只扩展整行背景，不拉伸曲线。
- 颜色索引通过固定八项顺序映射到现有 `TERMINAL_PACK` 色键，不新增主题令牌，不继续消费 Git ANSI lane 色。

### D4 模型与交互只做必要适配

- `CommitGraphModel.max_graph_cells` 改为由所有节点 lane 和边的 from/to lane 计算最大可见泳道数，不再统计字符格长度。
- 删除连接行半高分支、字符支持集合和未知字符判断；所有提交行使用统一行高，截断提示行不参与拓扑绘制或提交 tooltip。
- `CommitColumnDelegate`、作者/时间列、refs 徽标和完整弹窗四列职责保持不变，仅消费新的行模型。
- graph-only 整行 tooltip 继续显示短 hash、主题、作者、双时间和 refs；截断提示无提交 tooltip。
- 刷新前记录完整 `commit_id` 与横纵滚动值，模型重置后按完整 id 恢复；提交消失时清空选择，滚动值由新范围钳制。
- `GitGraphContent.reload()` 只保留“结构化结果是否为 `None`”的主路径判断；失败仍调用 `fetch_commit_graph()` 获取独立彩色文本，主题/字号重绘不取数。
