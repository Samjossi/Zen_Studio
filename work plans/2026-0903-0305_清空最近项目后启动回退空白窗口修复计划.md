# 清空最近项目后启动回退空白窗口修复计划

> **状态**：已实施（2026-09-03）
> **范围**：`main.py`（唯一改动文件）
> **时间**：2026-09-03 03:05（UTC+8）（设计）/ 2026-09-03 03:11（实施）
> **优先级**：中

---

## 0. 背景与目标

### 0.1 Bug 现象

用户通过文件菜单「最近打开的项目 ▸ 清除列表(&L)」清空历史后（`config/recent_projects.json` 被写为 `{"recent_projects": []}`），下次启动打包版程序，窗口根目录落到了**用户主目录**，把整个 home 当工作区打开了。

首次安装（无历史文件）同理：`RecentProjectsStore.list()` 对缺失/损坏文件一律回退空表，与「被清空」在消费侧等价，所以两类场景命中同一缺陷。

### 0.2 期望行为

「无项目可恢复」——包括首次启动、历史为空、历史被清空——与「新建窗口(&N)」是同一类场景。启动流程发现没有可恢复的项目时，应**复用空白窗口逻辑**（`2026-0831-2350_一窗一根与空白新窗口实施计划.md` 定义的形态：不绑定目录、文件树欢迎占位、聊天/终端面板禁用、不做一窗一根登记），而不是回退打开某个默认目录。

---

## 1. 根因

`main.py` 的 `_frozen_default_workspace()`：打包态默认工作区取「最近项目首项（目录仍存在且非解包目录者）」，遍历无果时**二级回退 `Path.home()`**——主目录就是这样被打开的。

调用链：

- `main()` → `resolve_workspace_root(args.folder)`（folder 缺省时）
- → `IS_FROZEN` 为真 → `_frozen_default_workspace()` → 列表空 → `str(Path.home())`
- → `acquire_root_ownership(主目录)` + `MainWindow(workspace_root=主目录)`

补充事实：

- 开发态（非 frozen）缺省回退 `PROJECT_ROOT`，不经过 home 回退，**主目录 bug 仅存在于打包态**；但开发态/打包态两套回退本身就是一种分裂（见 D2）。
- 空白窗口的窗口侧行为已全部由 `MainWindow(workspace_root=None)` 驱动（`gui/main_window.py` 各空窗分支、不记最近项目、不登记占用），无需新增任何窗口侧代码。
- `gui/window_state.py` 只管窗口几何/布局持久化，不参与「打开哪个项目」的决策，不在改动面内。

---

## 2. 修复方案

### D1 空历史返回 `None`，汇入 `--blank` 既有分支（核心）

`main.py` 单文件改动：

1. **`_frozen_default_workspace()` 更名 `_default_workspace()`**：返回类型改 `str | None`；遍历无果时 `return None`（删除 `Path.home()` 回退）。
2. **`resolve_workspace_root()`**：返回类型改 `str | None`；**删除 `IS_FROZEN` 分流与 `PROJECT_ROOT` 开发态回退**，缺省/无效一律走 `_default_workspace()`（见 D2）。
3. **`main()`**：`resolve_workspace_root()` 返回 `None` 时走与 `args.blank` 相同的分支——`root_server = None`，跳过 `acquire_root_ownership`，以 `MainWindow(workspace_root=None)` 起空白窗口。

改后启动分流（`main.py`，开发态/打包态一致）：

| 条件 | 行为 |
|:---|:---|
| `--blank` | 空白窗口（不变） |
| `folder` 有效 | 绑定该根 + 占用登记（不变） |
| `folder` 缺省/无效，最近列表有有效项 | 恢复首项（不变） |
| `folder` 缺省/无效，列表空/全无效 | **空白窗口**（本次修复） |

文案同步：

- `main.py` 顶部模块 docstring 增补「无项目可恢复启动」用法说明；
- `parse_args()` 中 `folder` 的 help（原写「缺省回退项目根」，与实际行为早已不符，一并修正为「缺省从最近项目恢复，无历史则空白窗口」）。

### D2 开发态与打包态强行拉齐（用户决策）

原开发态缺省回退 `PROJECT_ROOT` 的所谓开发便利，相比两套回退逻辑带来的行为分裂得不偿失。修复后**开发态与打包态完全一致**：folder 缺省/无效时一律从最近项目恢复，无历史则空白窗口。`uv run main.py` 不再有隐式进项目根的特殊待遇，需要项目根时显式传参 `uv run main.py .`。

### 为什么不复用 `_spawn_window` / 再起进程

`MainWindow._spawn_window(None)` 是「从已有窗口拼 `--blank` 起新进程」的路径；启动流程本身就在进程入口，直接以 `workspace_root=None` 构造窗口即为同一终态，无需多绕一次进程。两条路径在 `MainWindow(workspace_root=None)` 处天然合流，复用的是**空白窗口语义**，不是 spawn 代码本身。

## 4. 验证方案

1. **函数级验证（开发态可跑）**：用项目 `.venv` Python 起临时脚本调用 `_default_workspace()`：
   - 最近列表为空 → 返回 `None`（修复前打包态为 `Path.home()`）；
   - 最近列表首项有效 → 返回该路径（回归）。
   临时脚本落 `./.tmp/`，验完即删。
2. **空白窗口形态确认**：开发态 `uv run main.py --blank` 起空窗，确认欢迎占位/面板置灰正常（既有行为回归，确认 `main()` 分流改动未误伤 `--blank` 路径）；`uv run main.py`（无参、最近列表清空后）应同样起空窗。
3. **打包态端到端**：由用户自行构建 AppImage（`building/build_appimage.sh`）并测试：
   - 清空最近列表 → 启动 → 应为空白窗口，标题「未打开文件夹」；
   - 打开一个项目后关闭 → 再启动 → 应恢复该项目（回归）；
   - 空窗内走「打开文件夹」就地填充 → 正常换根（回归 `2026-0831-2350` 计划的空窗填充路径）。

## 5. 风险与影响面

- ⚠️ 行为变化：「无历史启动」从打开主目录（打包态）/ 项目根（开发态）统一变为空白窗口——这正是本修复的目标行为，对齐 VS Code 首次启动形态。
- ⚠️ 开发态 `uv run main.py` 无参不再自动打开项目根，开发脚本/肌肉记忆若依赖此行为需显式传 `uv run main.py .`（用户已确认接受）。
- 主目录回退删除后，无任何代码路径再把 home 当工作区打开；`_is_unpack_dir()` 防护（解包目录绝不作回退落点）不受影响。
- 空白窗口不做一窗一根登记，多空窗可共存（既有语义，不变）。
- 改动仅限 `main.py` 入口分流，不触碰窗口侧、最近项目存储、窗口状态持久化。
