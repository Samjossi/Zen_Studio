## 1. 背景与目标

T0–T7 已完成厂商目录、update mapper、卡片、权限与守卫的主体迁移，但收尾核对发现三类残留：

1. **V05 只有能力值，没有读取契约**：GUI 仍以鸭子类型读取各 provider 的私有能力属性，并在公共层写出厂商文案与设置键。
2. **V07/V09/V11 只完成归属，没完成模块拆分**：Kimi 的 wire、用量轮询、sidecar 与 DSH 的会话日志仍堆在各自 `provider.py`；上一轮主计划 §5.1 承诺的 `kimi/wire.py` 从未创建。
3. **V19 守卫只到 import 与固定词表**：抓不住字段级载荷读取、中文厂商文案、设置键与能力鸭子接口。

本计划目标：

- 建立中性的能力快照与厂商设置声明机制，让通用 GUI 只消费契约（V21，含 V13）。
- 下线 classic 旧文本轨，消除公共 GUI 对厂商载荷的最后解释（V20）。
- 把上述边界固化为语义/字段级守卫（V24）。
- 拆分 Kimi/DSH 私有数据与子代理模块（V22）。
- 把注册表收口为纯组合根，厂商元数据归各厂商 `spec.py`（V12）。
- 可选拆分 ACP 诊断与 terminal 设施（V23）。

非目标与范围边界见 §9。

## 3. 目标结构与依赖契约

### 3.1 能力快照

在 `src/ide/llm/base.py` 增加中性不可变类型与默认实现：

| 字段 | 类型 | 默认 | 语义 |
|:---|:---|:---:|:---|
| `image_input` | `Optional[bool]` | `None` | 图片输入能力；`None` = 尚未实测，GUI 回退 `BackendSpec.supports_images` 静态值 |
| `post_turn_usage_grace_s` | `float` | `0.0` | 轮次收尾后继续接收迟到用量帧的宽限秒数 |
| `stall_watchdog` | `bool` | `True` | 本后台是否适用轮次停滞看门狗 |
| `recovery_pending` | `bool` | `False` | 当前是否处于待恢复态，仅供 GUI 决定是否取消自动待发等 |

- `LanguageModel.capabilities()` 返回当前快照；默认实现返回上述默认值。
- `capabilities_of(model)` 作为中立读取 helper：对象没有 `capabilities()` 时返回默认快照，兼容不继承 Protocol 的测试桩。
- GUI 只在以下时点刷新：provider 创建后、initialize 完成后、轮次收尾后、切换后台后。快照本身不承担事件通知。
- 能力快照只读状态，不替代 `set_model`/`set_effort`/`set_permission_handler`/`set_terminal_handler` 等动作接口。

### 3.2 厂商设置声明

- `BackendSpec` 增加 `vendor_settings: tuple[str, ...] = ()`，声明本后台读取哪些设置键；只声明键名，不解释值。
- `LanguageModel.apply_vendor_settings(settings: Mapping[str, object])` 默认 no-op；需要厂商设置的 provider 自行覆写并从映射取值。
- 面板通过中立 helper 调用 `apply_vendor_settings`，对象未实现时视为 no-op；厂商设置不参与能力快照，也不改变动作接口。
- 面板按当前 spec 的 `vendor_settings` 过滤 `load_settings()` 后整体交给 provider，面板不出现任何厂商键名或厂商分支。
- Kimi 的 `kimi_wire_sidecar` 键名与默认值保持现状，不重命名持久化键；注册表组合根声明该键，测试断言该键确实存在于公共设置默认值中，避免两处字符串漂移。
- DSH/Local 不声明厂商设置，保持零行为变化。

### 3.3 classic 旧文本轨下线

- `chat_renderer` 键保留在设置 schema 中，兼容旧存档；值域只保留 `cards`。加载时任何非 `cards` 值（含历史 `classic`）归一为 `cards`，不弹窗、不迁移文件。
- 删除 `ChatOutput` 与面板双轨分支；面板恒定使用 `ChatTranscriptView`。
- 三家 presenter 的 `prepare_update(payload, cards_track)` 改为 `prepare_update(payload)`；删除旧轨裁剪常量与分支。
- 设置对话框移除「对话区渲染」选项及其信号处理；保留设置键只为读取兼容。
- 不保留隐藏回退：删除后不存在可通过配置恢复的旧轨。

### 3.4 私有数据模块

| 新模块 | 承接内容 | 依赖约束 |
|:---|:---|:---|
| `src/ide/llm/providers/kimi/wire.py` | session_index 反查、wire 读取、字节游标、轮次统计与速度计算 | 不 import provider、不 import Qt、不 import 其他厂商 |
| `src/ide/llm/providers/kimi/usage.py` | 轮内用量轮询、轮末宽限、请求配对、轮次消耗汇总 | 只依赖 wire 与 `llm.base` 载荷；状态按实例持有 |
| `src/ide/llm/providers/kimi/subagent.py` | sidecar 线程、wire 事件合成、父调用发现与迟到帧观察 | 不 import provider；线程启停由 provider 显式调用 |
| `src/ide/llm/providers/dsh/session_log.py` | generation 定位、zstd 解压、usage 事件提取、轮次消耗差量 | 不 import provider、不 import 其他厂商 |

- `provider.py` 只负责组合与生命周期，不再持有文件格式、游标或线程实现。
- 模块级状态一律改为实例状态；模块内不缓存跨 provider/跨会话数据。
- 拆分是纯搬家：帧解析结果、用量口径、日志缺失处理、zstd 缺失告警文本与线程收尾顺序保持不变。

### 3.5 注册表 spec 收口

- `BackendSpec` 迁至中性模块 `src/ide/llm/spec.py`；`ide.llm.BackendSpec` 继续再导出，公共签名不变。
- 模型缓存 helper 迁至 `src/ide/llm/cache.py`；`refresh_models()` 仍是唯一失效口，内部委托缓存模块清理。
- 新增 `src/ide/llm/providers/<vendor>/spec.py`：持有显示名、厂商标签、可用性探测、模型目录/强度/显示名工厂、静态能力、默认强度、`dev_note`、`vendor_settings` 与实例工厂。
- `registry.py` 只保留：`REGISTRY` 组合、`DEFAULT_BACKEND`、`spec_of`/`vendor_of`/`vendor_groups`、派生显示映射与 `refresh_models`。
- 厂商 `spec.py` 不得 import registry 或 GUI；组合根不得反向 import GUI。

### 3.6 语义/字段级守卫

在现有 import 方向与固定词表规则上增加：

1. **AST 字符串常量扫描**：只检查代码中的字符串常量与属性名，排除注释与 docstring；用于厂商显示名、设置键、工具名与私有路径。
2. **通用 GUI 载荷字段白名单**：通用聊天模块只允许读取 `tool_call_id`/`parent_tool_call_id`/`tool_kind`/`title` 等路由与生命周期字段；`command`/`output`/`summary`/`status`/`error`/`is_subagent`/`diff_hunks` 等载荷字段只允许出现在厂商包。
3. **能力探针禁止清单**：通用 GUI 不得 `getattr` 到 `supports_images_override`、`post_turn_usage_grace_s`、`stall_watchdog_enabled`、`recovery_pending`、`set_subagent_sidecar` 等私有接口；只能走 `capabilities()`/`apply_vendor_settings()`。
4. **厂商设置键归属**：键名只允许出现在对应厂商包与注册表组合根；通用 GUI 不得出现 `KEY_KIMI_*` 或 `kimi_wire_sidecar`。
5. **新增厂商模块 import 归属**：`kimi/wire.py`、`kimi/usage.py`、`kimi/subagent.py`、`dsh/session_log.py` 只允许本厂商包导入。
6. 每条规则必须有受控反例，并保留聚合入口的失败用例，防「规则没接上」。
