# src 目录布局迁移落地计划

> **状态**：已实施（2026-09-19，T1-T11 全部完成并验证）
> **范围**：`core/`、`gui/`、`llm/`、`markdown_it/`、`mdurl/`、`main.py`、`tests/conftest.py`、`pyproject.toml`、`building/zen-studio.spec`、`scripts/`、活文档
> **时间**：2026-09-19 01:41（设计）(UTC+8)
> **优先级**：低

---

## 1. 背景与动机

运行时代码（`core/`、`gui/`、`llm/`）与 vendored 依赖（`markdown_it/`、`mdurl/`）散落在仓库根目录，与文档、构建、配置等 ~30 个根条目混杂。经讨论（2026-09-19 会话）拍板迁移至统一 `src/` 布局：

**收益定位（务实版）**：

- ✅ 根目录瘦身，代码/文档/构建/配置一眼分层，对人和 AI 都更友好；
- ✅ 符合 Python 社区惯例，未来若要发 wheel/pip 可装零额外成本；
- ✅ 根目录退出 `sys.path`，vendored `markdown_it/` 与 PyPI 同名包撞名的理论误导入风险消除。
- ❌ **不为打包省事**：现 spec 靠 `pathex=[项目根]` 顺 import 链收编，散装布局对 PyInstaller 本就不构成麻烦（`building/zen-studio.spec` datas 五条显式枚举，与代码布局无关）；src 经典收益「防测试误导入源码而非已安装包」对本项目（源码直跑 + onedir 应用，非 pip 库）不适用。

## 2. 现状盘点（迁移触点事实清单）

### 2.1 好消息：import 零改动

全库 import 均为**绝对导入**（`from gui.panels...`、`from core.git...`、`from markdown_it...`），五个目录原样挪进 `src/` 后 import 语句一行不改，只要 `src/` 进 `sys.path`。

### 2.2 搬运对象（五个目录）

| 目录 | 性质 |
|:---|:---|
| `core/` | 运行时（paths/git/child_env 等） |
| `gui/` | 运行时（全部界面代码） |
| `llm/` | 运行时（provider 注册表等） |
| `markdown_it/` | vendored 运行时依赖（渲染内核，ruff 已排除） |
| `mdurl/` | vendored 运行时依赖（markdown_it 依赖，ruff 已排除） |

**不搬**：`dream-acp/`（协议文档 + 示例 + spike 工具，非 Python 包；运行时代码是 `llm/providers/dream_acp.py`，随 `llm/` 走）、`tests/`、`scripts/`、`assets/`、`config/`、`building/`、各文档目录。

### 2.3 须同步修改的锚点（迁移前已核实的全部触点）

### 2.4 已审计无地雷

`parents[N]` 全库 grep 结果：`core/paths.py` 为唯一运行时推导点（其 docstring 亦声明全库唯一），其余仅 `scripts/render_logo.py`、`scripts/shot_tool_cards.py`（探针，锚定 assets 用，parents[1] 不变仍正确）与 `tests/`（不搬）。frozen 态走 `sys._MEIPASS` 分支，与源布局无关。

## 3. 方案

### 3.1 目标布局

```
Zen_Studio/
├── src/
│   ├── core/
│   ├── gui/
│   ├── llm/
│   ├── markdown_it/   # vendored
│   └── mdurl/         # vendored
├── main.py            # 留在根，加 src 引导段
├── tests/ scripts/ assets/ config/ building/ ...   # 不动
```

### 3.2 `main.py` 引导段

```python
# main.py（顶部，from core... 之前）
# 开发态 src 引导：源码包已迁入 src/，脚本目录自动入 sys.path 的只有根，
# 须显式补 src；frozen 态 import 由 PyInstaller pathex 与 PYZ 解决，
# 本行 insert 一个不存在的路径无害（_MEIPASS 下无 src/，import 不走这里）
sys.path.insert(0, str(Path(__file__).resolve().parent / "src"))
```

选「根留 `main.py` + 引导段」而非「逻辑移 `src/`、根留瘦启动器」：改动最小，spec 入口与 `uv run main.py` 习惯全不变；瘦启动器方案列为未来可选项，本期不做。

### 3.3 执行方式

- 五个目录用 `git mv` 逐个搬运，保留重命名检测能力；
- 全部改动收**一个提交**：机械搬迁 + §2.3 锚点修改，便于 `git revert` 整体回退；
- 历史文档（`文档/修改记录/`、旧计划）中的旧路径引用**不改**（历史记录保持当时真值）；只更新活文档：`AGENTS.md`、`README.md`、`维护手册/`、`常用命令.md` 中受影响的相对路径表述。

## 5. 影响面评估

- ✅ import 语句零改动；运行时资源锚定（`core/paths.py`）单点收口，frozen/开发双态均有验证任务覆盖。
- ✅ 门禁链（隐私扫描 → ruff → pytest）与 pre-commit 钩子路径无关，T9 兜底。
- ⚠️ git blame 跨搬迁有摩擦（`--follow` 可查）；有在途分支时需先合并或 rebase，搬迁窗口内避免并行改这五目录。
- ⚠️ 存量计划/修改记录文档中的旧路径引用变「旧称」——有意保留（历史真值），仅活文档同步。
- ⚠️ T3 引导段是本项目首次出现「入口 sys.path 手工干预」，注释已写明 why；未来若改 pip 可装（`pip install -e .`）可删除。

## 6. 回退

全部改动集中在一个提交（`git mv` + 机械锚点修改），`git revert` 单提交即整体回退；无数据迁移、无配置格式变化。
