# Token 用量贡献热力图落地计划（kimi / DSH 双后端）

> **状态**：已实施
> **范围**：`src/ide/llm/`（轮次消耗采集）、`src/ide/core/`（统计与落盘）、`src/ide/gui/`（视图菜单 + 热力图弹窗）、`config/`（用量记录文件）
> **时间**：2026-11-14 14:52（UTC+8，设计）/ 2026-11-14 15:11（实施）
> **优先级**：中

## 需求

1. 统计本 IDE 内 AI 对话消耗的 token 数量，**按日归档**，并提供今日 / 最近七天 / 最近三十天滚动汇总。
2. 仅支持 **kimi 后端**与 **DSH 后端**；其余后端不采集、不估算、不显示。
3. 菜单栏「视图」新增入口，点击弹出 **GitHub 式贡献热力图**（绿色格子图）：
   - 每格代表一天，格子越绿代表当天 token 消耗越多；
   - 鼠标悬停格子显示当日用量明细；
   - 格子图底部常驻显示 **今日用量 / 最近七天用量 / 最近三十天用量**（滚动窗口，含今日）。

## 关键探查结论（已核实）

- **kimi 数据源（真实值，现成）**：`~/.kimi-code/sessions/<工作区键>/<sessionId>/agents/main/wire.jsonl` 中 `type=="usage.record"` 且 `usageScope=="turn"` 的记录携带逐次 API 调用的 `inputOther` / `inputCacheRead` / `inputCacheCreation` / `output` 四项实测值与 `time` 时间戳。读取实现已存在于 `src/ide/llm/providers/kimi_acp.py`（`_read_wire_records` / `_read_wire_turn_stats` / `_read_wire_turn_speed`），轮末收尾本就会读一次 wire，可同次读取顺带求和，零额外 I/O。
- **DSH 数据源（真实值，需读盘新实现）**：ACP `usage_update` 只有 `used`/`size`（上下文占用，输入输出混算，见 `参考代码/deepseek-harness/packages/acp/acp/src/updates.ts`），**不能用作消耗计量**。但 DSH 会话落盘文件 `session.vN.jsonl` 的 `assistant/message` 事件携带逐次调用 `usage`：`inputTokens` / `outputTokens` / `cacheReadTokens` / `reasoningTokens`（格式证据见 `参考代码/deepseek-harness/snapshots/sdk/` 多份快照）。DSH home 为 `~/.dsh`（或 `DSH_HOME`），会话具体路径与写盘时机需 spike 实测（步骤 1）。
- **轮次收尾钩子（现成）**：`src/ide/gui/panels/chat/panel.py` `turn_completed = Signal(bool)`（True=成功 / False=失败），经 `tabs.py` 转发至主窗口；流式 `Chunk`（`src/ide/llm/base.py`）是 provider → GUI 的既定数据通道。
- **视图菜单（现成模式）**：`src/ide/gui/menus/view_menu.py` 每动作三行（addAction / connect / register）；非模态单例弹窗先例为「提交历史图」（`ctx.show_git_graph`，`src/ide/gui/main_window.py`），热力图弹窗照此同构。
- **落盘纪律**：`config/` 为开发态运行时数据目录（全目录 gitignored），打包态分流至 XDG 配置目录，路径收口于 `src/ide/core/paths.py`；多开实例共享文件须 flock 串行化（`config/settings.lock` 先例）。用量记录是**跨工作区全局**数据，单文件 `config/token_usage.jsonl` 即可。
- **测试与门禁**：`tests/test_kimi_usage.py` 为 kimi wire 解析的既有回归测试；统一门禁 `bash scripts/check.sh`（隐私扫描 + lint + 测试）。

## 计量口径决策

- **计什么**：每次 API 调用的真实 token 消耗，按轮次求和后落一条记录。kimi 记 `inputOther` / `inputCacheRead` / `inputCacheCreation` / `output` 四项；DSH 记 `inputTokens` / `cacheReadTokens` / `outputTokens`（`reasoningTokens` 属输出的子集，不重复计入）。总量 = 输入（含缓存读写）+ 输出，与上下文占用徽章（used/size）是**两套语义**，互不复用数值。
- **日期归属**：以轮次收尾时刻的本地日期（UTC+8）归档；一轮跨零点不拆分，记在最后完成的那天。记录内存 UTC 时间戳，聚合时转本地日期。
- **汇总窗口**：今日 / 最近七天（today-6 起）/ 最近三十天（today-29 起）滚动窗口，均含今日；不采用 ISO 周 / 自然月口径。
- **失败 / 中断轮**：已完成的 API 调用消耗真实存在，wire / 会话文件里有多少记多少；整轮无任何用量记录则不落条。
- **子代理消耗**：首版仅统计主代理（kimi `agents/main/`；DSH 主会话文件），子代理消耗不计入，在弹窗说明文案中如实标注（后续可扩展）。
- **其他后端**：reasonix 只有 chars/4 估算、kilocode/opencode/local 无逐次真值通道，一律不采集——本功能不做估算值与实测值混算。
- **只进不出**：只统计 Zen Studio 内发起的对话；用户在 IDE 之外直接用 CLI 产生的消耗不在本计数器范围（弹窗说明文案注明）。

## 存储设计

`config/token_usage.jsonl`（append-only，一行一轮）：

```json
{"ts": "2026-11-14T14:52:03+08:00", "backend": "kimi-acp", "model": "kimi-code/k3-256k", "turn_id": "<sessionId>:<轮内usage.record条数>", "input_other": 123, "input_cache_read": 4560, "input_cache_creation": 0, "output": 789}
```

- `turn_id` 用于**去重**（同轮重试收尾、双源重复到达不重复计数）；写入前读现有 id 集合判重（文件量级小，全量读可接受）。
- 写盘走 flock 文件锁（`config/token_usage.lock`）+ 追加写；读聚合失败（坏行）跳过该行不阻断。
- DSH 记录字段对齐同一 schema（`input_other=inputTokens`、`input_cache_read=cacheReadTokens`、`input_cache_creation=0`）。

## 实施步骤

### 1. DSH 数据源 spike（先行，阻塞步骤 4）

- 实跑一次 `dsh acp` 对话，定位 `~/.dsh` 下当前会话的 `session.vN.jsonl` 路径规律与 `assistant/message` 事件的 `usage` 字段实测值、写盘时机（流式中即写还是轮末结算）。
- 脱敏帧存档至 `文档/帧存档/`，格式假设登记 `维护手册/后端CLI工具维护说明手册.md` §7。
- 若实测与快照格式不符，回本计划修订 DSH 采集方案，不得臆造字段。

### 2. 统计核心模块（新建 `src/ide/core/token_stats.py`，零 Qt 依赖）

- `record_turn(record)`：flock + 去重 + 追加写。
- `load_daily() -> dict[date, DayUsage]`：全量读 → 按本地日期聚合（DayUsage 含输入/输出/总量与分后端小计）。
- `summarize(daily, today) -> UsageSummary`：今日 / 最近七天 / 最近三十天滚动聚合（均含今日）。
- `level_of(day_total, all_days) -> 0~4`：绿色分档——0 消耗为 0 档，非零日按总量分位数切 4 档（GitHub 同款相对分档，避免个别超大日压平其余格子）。

### 3. kimi 轮次消耗采集（`src/ide/llm/providers/kimi_acp.py`）

- `src/ide/llm/base.py` 新增 `TurnConsumption` dataclass（input_other / input_cache_read / input_cache_creation / output / turn_id）；`Chunk` 增加可选字段 `consumption`，随轮末 `kind="usage"` chunk 同帧携带（与 `speed` 同模式）。
- kimi 轮末读 wire 的既有路径上，对本轮新增 `usage.record` 求四项之和生成 `TurnConsumption`；`usage_baseline` 计数机制复用，禁止差分单条记录（单条即单次调用值）。

### 4. DSH 轮次消耗采集（`src/ide/llm/providers/dsh_acp.py`）

- 轮末（response 收尾）读当前会话 `session.vN.jsonl`，对本轮 `assistant/message` 事件的 usage 求和，产出同样的 `TurnConsumption`。
- 读盘失败 / 无 usage 事件：静默不产出（不臆造数值），徽章现有行为不受影响。

### 5. GUI 接线落盘

- `src/ide/gui/panels/chat/panel.py`：轮内收到 `consumption` 缓存为 `_turn_consumption`；`turn_completed` 发射前若存在有效消耗则调 `token_stats.record_turn()`（写盘放 worker/短操作，避免阻塞 GUI；失败仅记日志不打断对话）。发送新一轮时清空缓存。
- 记录只依赖轮次事件，不新增设置项、不加开关。

### 6. 热力图弹窗（新建 `src/ide/gui/token_usage_dialog.py`）

- 非模态单例 `TokenUsageDialog`，仿 `GitGraphDialog` 先例；每次打开/置前时重新 `load_daily()` 刷新。
- 主体为自绘 QWidget（QPainter）：近 52 周 × 7 行格子，周日对齐周一开头，未来日期不画；空格用主题底色，1~4 档用绿色梯度（四主题共用同一组绿，与 GitHub 视觉一致）。
- 悬停 tooltip（`QToolTip`）：`YYYY-MM-DD 周X` + 输入 / 输出 / 合计 tokens（千分位）；无消耗日显示「无用量」。
- 底部一行三标签：**今日用量 / 最近七天用量 / 最近三十天用量**（合计 tokens，千分位）。
- 弹窗附简短说明：统计范围 = 本 IDE 内 kimi / DSH 对话，主代理口径。
- 主题切换与全局字号变更时重绘（沿用主窗口统一重绘链）。

### 7. 视图菜单入口

- `src/ide/gui/menus/view_menu.py` 新增「Token 用量热力图(&U)」→ `ctx.show_token_usage`；`src/ide/gui/main_window.py` 增加非模态单例的懒创建与置前（空窗无工作区也可打开，数据是全局的，不做空窗守卫）。

## 风险与限制

- ⚠️ kimi wire 与 DSH 会话文件均为**私有落盘格式**，无稳定性契约；解析一律容错（坏行跳过、缺字段不产出），格式漂移时静默停采而非显示错数。
- ⚠️ DSH 会话文件写盘时机未经实测，若仅在会话结束才落盘，DSH 采集需改为轮次内其他真值通道或顺延确认——步骤 1 spike 定案。
- 首版不计子代理消耗、不折算费用（单价口径另属 `维护手册/模型Token单价对比手册.md`，后续可作为独立增强）。
