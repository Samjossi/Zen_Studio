# ModelBar 三级下拉当前值直显与文本精简计划

## 1. 目标

1. **当前值直显**：三个下拉按钮（后台 / 接口 / 模型）的按钮文本直接显示当前选中
   值，用户无需悬停 tooltip 即可知道「选了哪个后台、哪个接口、哪个模型」。
2. **文本精简**：直显文本必须短——模型别名普遍带 provider 前缀（如
   `kimi-code/k3-256k`、`deepseek/deepseek-v4-flash`），按钮上只摘取 `/` 后段
   （`k3-256k`）；接口显示名与后台名有重复（`Kimi CLI` 中的 `Kimi`）可剥离。
3. **宽度红线不破**：直显不得复活 2026-0724-2305 计划根治的「左栏宽度随选择
   变化被 QSplitter 撑宽」旧病——按钮宽度必须与「当前选中项的文本长度」脱钩。
4. **零链路改动**：`selection_changed` 信号签名、持久化键、菜单勾选语义、
   busy 禁用、ChatTabs/ChatPanel 接线全部不动，仅改按钮呈现层。

## 2. 背景与现状摸底（已核实）

### 2.1 恒显标签的由来（本次要「恢复回来」的东西）

- 2026-0724-2244 诊断：QComboBox 的 `minimumSizeHint()` 按「最长条目文本宽度」
  计算，两个下拉框使 ModelBar 静态最小宽度 528px，左栏下限被锁死约 540px。
- 2026-0724-2305 计划 T1/T4 根治：双 QComboBox 换 `QToolButton(InstantPopup)+QMenu`，
  框体恒显「模型」「版本」标签、当前值归 tooltip 全名 + 菜单 ✓ 勾选，
  宽度与条目文本彻底脱钩（实测 402px）。
- 2026-0724-2354 计划沿用该范式；2026-0730-0150 计划扩为三按钮时继续沿用。
- **副作用（本次客户反馈）**：按钮上只有「后台 ▾」「接口 ▾」「模型 ▾」三个
  固定词，当前选中了什么必须悬停看 tooltip，不直观。

### 2.2 现状代码事实（`gui/panels/chat/model_bar.py`）

| 事实 | 影响 |
|:---|:---|
| `_make_button(title)` 文本恒为 `f"{title} ▾"`，`setMinimumWidth(文本宽 + 24)` | 直显改造点：文本改为「当前值短文本 ▾」；宽度策略需重设计（见 D2） |
| `_refresh_tooltips()` 已把三级当前值**全名**三行写入三按钮 tooltip | 保留：tooltip 作全名兜底，直显精简后信息无损 |
| 菜单 action 的 `data` 携带全名（vendor 名 / 接口实现名 / 模型别名全名），显示文本与 data 本就分离 | 显示层截取后段**不碰 data**，D6 红线 2（别名不透明透传）在数据链路不破——截取仅发生在 UI 呈现 |
| 菜单按内容加宽显示全文（`make_translucent_popup` 规约），无宽度压力 | 菜单项文本可保持全文，防同名歧义（见 D3） |
| `set_selection` / `_refresh_interfaces` / `_refresh_models` 是勾选变化的所有汇聚点 | 按钮文本刷新挂这三处出口（或收敛为一个 `_refresh_button_texts()`），与 `_refresh_tooltips` 同节律 |
| 底行装配：`ChatPanel` 中 `model_bar + stretch(1) + 发送按钮` | ModelBar 变宽不会挤压发送按钮（stretch 吸收），但会抬高左栏最小宽度——宽度红线针对此 |

### 2.3 三级显示文本现状与精简空间

| 层级 | 当前 data / 菜单文本 | 直显短文本（本计划） | 说明 |
|:--|:--|:--|:--|
| 后台 | `vendor_label`：Kimi / Reasonix | 原文（已短） | 无精简需求 |
| 接口 | `spec.label`：Kimi CLI / Kimi ACP / Reasonix ACP | 剥 vendor 前缀 → CLI / ACP | 与一级按钮文本天然重复；剥离规则见 D1 |
| 模型 | 别名全名：`kimi-code/k3-256k`、`deepseek/deepseek-v4-flash` | `/` 后段 → k3-256k / deepseek-v4-flash | 无 `/` 时回退全文；见 D1 |

精简后底行典型呈现：`Kimi ▾  ACP ▾  k3-256k ▾`（对比全名直显
`Kimi ▾  Kimi ACP ▾  kimi-code/k3-256k ▾`，省约 20 个字符宽度）。

## 3. 方案选型与关键决策

### D1：短文本截取规则（显示层纯函数，不改数据）

新增模块级纯函数（model_bar.py 内，单测可直达）：

```python
def short_interface_label(spec_label: str, vendor_label: str) -> str:
    """接口显示名剥后台前缀："Kimi CLI" - "Kimi" → "CLI"；
    不匹配前缀时回退原文（注册项 label 无强制命名公约，兜底防误判）。"""

def short_model_alias(alias: str) -> str:
    """模型别名取 '/' 末段："kimi-code/k3-256k" → "k3-256k"；
    无 '/' 回退全文。多层 '/' 取最末段（rsplit）。"""
```

- **红线 2 合规性声明**：截取只用于按钮文本与（可选的）菜单并列短文本；
  action 的 `data`、信号载荷、持久化值全程仍是别名全名，不解析、不校验、
  不拼接回数据链路。
- **后台级不做截取**：`vendor_label` 本就短。

### D2：按钮宽度与「当前选中文本长度」脱钩（宽度红线，核心决策）

历史旧病的本质是 sizeHint 随内容变。直显恢复后必须重新脱钩，候选：

| 方案 | 做法 | 评价 |
|:--|:---|:---|
| **A（推荐）菜单最大短文本恒宽** | 每次菜单重建时，用该菜单**全部可用项的短文本**计算最大宽度，一次设定按钮 `setFixedWidth`；选择切换文本变但宽度不变 | 无省略号、无截断损失；宽度只随「菜单内容」变（切后台/接口时），不随「勾选哪一项」变——勾选是高频动作，菜单重建是低频动作，棘轮风险降至与现状同级 |
| B 固定像素上限 + elide | 按钮写死上限宽度，超长文本 `…` 省略，tooltip 全名兜底 | 宽度绝对恒定，但短模型名也可能被省略（如长别名后段仍长），观感有损 |
| C 宽度随选中文本自适应 | 直接 `adjustSize` | **否决**：勾选即变宽，QSplitter 棘轮旧病复发 |

采用 **A**。落点：

- 三处菜单重建/勾选汇聚（`__init__`、`set_selection`、`_on_*_picked` 链）
  末尾统一调 `_refresh_button_texts()`：更新三按钮文本 + 按各自菜单最大短文本
  重设 `setFixedWidth`（替代现 `_make_button` 里的 `setMinimumWidth` 一次性逻辑）。
- 宽度计算沿用现有范式：`fontMetrics().horizontalAdvance(最长短文本 + " ▾") + 24`。
- **回归验证**：沿用 2305 计划的探针范式（`.tmp/probe_*.py`），断言「连续切换
  不同长度选项，ModelBar 最小宽度与左栏 sizes 零变化」（仅切后台/接口时允许
  一次性重排——低频且由用户显式动作触发，可接受）。

### D3：菜单项文本保持全文

- 菜单天然按内容加宽，无宽度压力；全名可消解「不同 provider 同后段名」
  （如两个 provider 都有 `…/k3-256k`）的歧义。
- 勾选 ✓ 与「（未检测到）」禁用标注范式不变。
- 备选（不做）：菜单项也改短文本——省宽度无收益、引入歧义风险。

### D4：按钮是否保留层级标签

| 方案 | 呈现 | 评价 |
|:--|:---|:---|
| **A（推荐）纯值直显** | `Kimi ▾  ACP ▾  k3-256k ▾` | 最短、最直观；三级语义由左→右顺序与 tooltip 三行全名链承载 |
| B 标签+值 | `后台·Kimi ▾  接口·ACP ▾  模型·k3-256k ▾` | 语义自解释但文本翻倍，违背精简目标 |

采用 **A**。tooltip 保持现有三行全名链不变（悬停仍可见完整信息，
信息渠道是「增强」而非「替换」）。

### D5：设置中心不同步精简

`gui/settings_dialog.py` 的 AI 模型页三下拉是配置面，无宽度约束，
继续显示全名（精确无歧义）。本计划只动 ModelBar 原位控件。
（两侧显示文本差异可接受：原位控件求快、配置面求准，已有职责分工先例。）

## 7. 实施记录（2026-07-30）

### 7.1 用户拍板：D2 宽度口径变更（对本计划 D2-A 的显式覆盖）

实施中先按 D2-A 落地「菜单最大短文本恒宽」（另加 190px 上限安全阀防长
别名撑宽），实测按钮过宽（模型按钮恒定 190px，而 `k3-256k ▾` 实际只需
110px）。用户拍板：**按钮宽度直接贴合当前选中短文本**（文本宽 + 样式余量
setFixedWidth），不做菜单最大项恒宽、不设上限——别名精简后各选项长度
差异小，宽度随选择小幅变化是可接受的即时反馈。落地后：

- 默认态（`Kimi ▾  ACP ▾  k3-256k ▾`）ModelBar 最小宽 **248px**
  （D2-A 恒宽稿为 402px、旧恒显标签稿约 282px），底行显著更紧凑；
- 已知取舍（模块 docstring 同步明示）：切换长选项（如
  `kimi-for-coding-highspeed`，249px）会顶宽左栏，QSplitter 不自动回缩，
  切回短选项后需手动拖回；最窄窗口（900px 下限）下长文本选项可能被
  左栏边界裁切尾部几字（tooltip 三行全名链 + 菜单全文兜底）。
- 验收第 2 条口径随之由「切换零变化」改为「切换即时贴合、无省略、
  切回短项宽度复原无漂移」（探针断言同步改写）。
