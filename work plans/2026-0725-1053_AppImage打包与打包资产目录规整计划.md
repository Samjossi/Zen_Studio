# AppImage 打包与打包资产目录规整计划

> **平台约束**：Zen Studio 仅在 **Linux** 上使用。AppImage 面向 x86_64 桌面发行版，不考虑 Windows / macOS，不产出 .deb / .rpm / Snap / Flatpak。

## 1. 背景与目标

上一计划（`2026-0725-0859_应用Logo接入与打包图标计划.md`）落地了 PyInstaller onedir 打包的最小闭环，但留下三处结构性欠账：

1. **打包资产散落**：构建配置 `zen-studio.spec` 裸放项目根、`packaging/` 目录只装一个 `zen-studio.desktop`（单文件目录，不合理）、产物目录 `dist/` / `build/` 也裸放根下——打包相关的一切没有统一归属。
2. **无打包脚本**：构建靠手敲 `uv run pyinstaller zen-studio.spec`，无编排脚本，更无 AppImage 产出能力。
3. **打包内容无清单**：spec 的 `datas` 整目录收编 `assets/`，连 `assets/logo候选池/`（设计草稿，28K）都进了产物；PySide6 的未用 Qt 模块（Qml/Quick/Pdf/VirtualKeyboard/EglFS 等）原样收编——「哪些该打包、哪些不该打包」从未被定义。

本计划目标：

- 新建 **`building/`** 目录作为打包专区：构建配置、打包脚本、桌面入口、工具链、产物全部收口，`packaging/` 目录裁撤。
- 编写 **AppImage 打包脚本**，一条命令从源码产出 `Zen_Studio-x86_64.AppImage`。
- 定义 **打包内容清单**（该打包 / 不该打包），落到 spec 的 `datas` / `excludes` 与 AppDir 组装规则中。

## 2. 现状盘点

| 项 | 现状 |
|:---|:---|
| 构建配置 | `zen-studio.spec`（项目根，onedir，入口 `main.py`，`datas=[("assets", "assets")]` 整目录收编） |
| 桌面入口 | `packaging/zen-studio.desktop`——`packaging/` 目录内**唯一**文件 |
| 打包脚本 | ❌ 无（手动执行 pyinstaller 命令） |
| 产物目录 | `dist/zen-studio/`（364M）、`build/`（14M 中间产物），均裸放项目根，已被 `.gitignore` 忽略 |
| 产物体积构成 | 字体 **191M**（更纱黑体 49M + 思源黑体 56M + 思源宋体 87M）+ PySide6 **119M** + 其余依赖 |
| 混入的不该打包项 | `dist/zen-studio/_internal/assets/logo候选池/`（设计草稿） |
| 未用的 Qt 模块（被收编） | `libQt6Qml*`、`libQt6Quick`、`libQt6Pdf`、`libQt6VirtualKeyboard*`、`libQt6EglFS*` 等（项目仅用 Core/Gui/Widgets/Svg/Network/DBus/Wayland/Xcb） |
| 用户数据写盘 | 打包态 `config/` 写入解包目录（实证：`dist/zen-studio/_internal/config/` 内有运行生成的 `recent_projects.json`、`window_state/`）——`core/paths.py` 已声明「另立打包配置专题处理」 |
| `.gitignore` | 已忽略 `build/` `dist/`；无 `building/` 相关条目 |

### 2.1 关键风险实证：AppImage 与用户数据写盘冲突 🔴

AppImage 是**只读** squashfs 镜像，运行时挂载后内部任何写入都会失败。当前打包态把 `config/`（设置、最近项目、窗口状态）写进解包目录——onedir 下只是「不优雅」，AppImage 下是**直接故障**（设置无法持久化，甚至启动报错）。因此**用户数据目录迁移（XDG）是 AppImage 的前置任务**，不能再挂账，本计划收编为阶段三。

## 3. 目录规整方案

### 3.1 `building/` 目录结构（新建）

```
# building/（打包专区，全部打包资产收口于此）
building/
├── zen-studio.spec          # PyInstaller 构建配置（自项目根迁入并改造，见 §4）
├── zen-studio.desktop       # 桌面入口模板（自 packaging/ 迁入，内容同步修订）
├── build_appimage.sh        # AppImage 编排脚本（新增，唯一构建入口）
├── tools/                   # 构建工具链（appimagetool，脚本自动下载，不入库）
├── build/                   # PyInstaller 中间产物（--workpath，不入库）
└── dist/                    # 构建产物（--distpath，onedir 与 AppImage 均落于此，不入库）
    ├── zen-studio/          # onedir 中间产物（AppImage 的原料）
    └── Zen_Studio-x86_64.AppImage
```

### 3.2 迁移与裁撤规则

| 源 | 去向 | 处置 |
|:---|:---|:---|
| `zen-studio.spec`（根） | `building/zen-studio.spec` | 迁移 + 改造（§4），spec 内用 `SPECPATH` 推项目根，消除对 CWD 的依赖 |
| `packaging/zen-studio.desktop` | `building/zen-studio.desktop` | 迁移；`Exec=` 占位说明改为同时支持 onedir 直启与 AppImage 两种安装形态 |
| `packaging/` 目录 | — | **裁撤删除**（迁移后为空目录） |
| `dist/` `build/`（根） | `building/dist/` `building/build/` | 旧产物目录删除；新构建经 `--distpath` / `--workpath` 参数落位 |
| `.gitignore` | — | 忽略条目由 `build/` `dist/` 改为 `building/build/` `building/dist/` `building/tools/` |

### 3.3 构建入口纪律

- 唯一构建入口：`building/build_appimage.sh`（内部依次驱动 pyinstaller → AppDir 组装 → appimagetool）。
- 脚本与 spec 均**不假设 CWD**：脚本首行切到项目根再执行；spec 用 `SPECPATH` 推导 `PROJECT_ROOT`，从任何目录调用行为一致。
- 脚本产生的临时文件一律落 `building/build/` 内（`mktemp -d` 指定目录），遵守 `AGENTS.md` 禁止使用系统临时目录的约束。

## 4. 打包内容清单（该打包 / 不该打包）

### 4.1 该打包 ✅

| 类别 | 内容 | 收编方式 |
|:---|:---|:---|
| 应用代码 | `main.py`、`core/`、`gui/`、`llm/` | PyInstaller 依 import 链自动收编（无需 datas） |
| 运行时资源 | `assets/fonts/`（双字体族全套字重）、`assets/logo/`（母版 SVG + 八件 PNG） | spec `datas` **按子目录分别收编**，替代整目录收编 |
| Qt 实际使用模块 | Core / Gui / Widgets / Svg / Network / DBus / Wayland / Xcb | PyInstaller 自动收编，不在 excludes 之列 |

### 4.2 不该打包 ❌

| 类别 | 内容 | 排除手段 |
|:---|:---|:---|
| 设计草稿 | `assets/logo候选池/`（当前已混入产物） | spec `datas` 不再整目录收编 `assets/`，自然排除 |
| 用户数据 | `config/`（settings、recent_projects、window_state） | 不收编（现状即未收编，保持）；打包态写盘迁 XDG（阶段三） |
| 项目文档与研发资料 | `文档/`、`参考代码/`、`work plans/`、`测试文档_*.md`、`.kilo/` 等 | 本就不在 import 链与 datas 中，列入清单只为**明示禁止**——任何人不得为其新增 datas |
| 未用 Qt 模块 | `PySide6.QtQml`、`PySide6.QtQuick`、`PySide6.QtPdf`、`PySide6.QtVirtualKeyboard`、`PySide6.QtEglFSDeviceIntegration`（及对应库族） | spec `excludes` 显式列出；**每一项排除后必须回归验证**（字体/终端/渲染链路），排除失败即回退该项 |
| Python 缓存 | `__pycache__/`、`.pyc` | PyInstaller 默认不收，无需动作 |
| API 密钥 | `api_key/` | 🔴 严禁以任何形式收编，脚本构建前自查并告警 |

### 4.3 spec 改造要点

- `datas` 由 `[("assets", "assets")]` 改为按子目录收编：`assets/fonts`、`assets/logo` 两条。
- `excludes` 新增 §4.2 未用 Qt 模块清单（逐项验证，先试探性排除再回归）。
- spec 头部注释同步更新：构建入口改为 `building/build_appimage.sh`，产物位置改为 `building/dist/`。
- **体积预期**：排除未用 Qt 模块后 onedir 应明显小于当前 364M；字体 191M 为最大构成项，本期**不裁剪**（字体加载是最高风险回归点，字重裁剪另立评估，见 §8）。

## 5. AppImage 技术方案

### 5.1 工具链

- **appimagetool**（官方 release，x86_64 固定版本）：`build_appimage.sh` 首次运行时下载至 `building/tools/`，校验存在性与可执行位；不入库。
- 不引入 linuxdeploy / linuxdeploy-plugin-qt——PyInstaller onedir 已自含全部 Qt 依赖与 Python 运行时，AppDir 只需原样搬运，无二次依赖解析需求。

### 5.2 AppDir 结构

```
# building/build/Zen_Studio.AppDir/（组装区，构建中间产物）
Zen_Studio.AppDir/
├── AppRun                   # 启动脚本：exec "$APPDIR/usr/bin/zen-studio" "$@"
├── zen-studio.desktop       # AppDir 版（Exec=zen-studio，Icon=zen-studio）
├── zen-studio.png           # 取 assets/logo/logo_256.png
└── usr/bin/
    ├── zen-studio           # onedir 可执行文件
    └── _internal/           # onedir 资源目录（原样搬运）
```

- AppDir 版 `.desktop` 与 `building/zen-studio.desktop`（用户手动安装模板）是**两个用途**：前者喂 appimagetool，后者服务 onedir 直启场景，分别维护，脚本内生成 AppDir 版（不从模板改）。
- `StartupWMClass=zen-studio` 两版保持一致，与 `main.py` 的 `setDesktopFileName("zen-studio")` 对齐（Wayland 任务栏图标关联约束，沿用上一计划结论）。

### 5.3 `build_appimage.sh` 流程

1. 前置自查：项目根定位、`api_key/` 不会被收编的断言、appimagetool 就位（缺则下载）。
2. `uv run pyinstaller building/zen-studio.spec --distpath building/dist --workpath building/build --noconfirm`。
3. 组装 AppDir：按 §5.2 搬运 onedir 产物、生成 `AppRun` 与 AppDir 版 `.desktop`、拷贝 `logo_256.png` 为 `zen-studio.png`。
4. `appimagetool Zen_Studio.AppDir building/dist/Zen_Studio-x86_64.AppImage`。
5. 冒烟验证：`--appimage-extract` 解包核对关键文件存在（可执行件、字体、`logo_256.png`、无 `logo候选池`、无 `config/`）；实机直接执行 AppImage 验证启动。
