## 1. 背景与症状

用户真机报告：鼠标在**左栏（AI 会话栏）**右键时，弹出的右键菜单**无底色**——菜单背景全透明，只剩一圈线框和菜单文字悬浮在界面上，文字后方直接透出下层内容；中栏（查看器/终端）、右栏（文件树/变更）右键菜单正常。且左栏该菜单的样式设计看起来与中栏、右栏不是同一套。

修前取证（五拍闭环 T1/T2，已完成）：真机探针 `.temp/diag_leftmenu_transparency.py` 以生产控件逐一弹出五组菜单并抓屏：

| 组 | 菜单来源 | 结果 |
|:---:|:---|:---|
| A | `ChatInput`（左栏输入框）标准菜单 | 🟢 底色正常 |
| B | `ChatOutput`（旧轨输出区）标准菜单 | 🟢 底色正常 |
| C | 对照组：无控件级 qss 的 `QTextEdit` 标准菜单 | 🟢 底色正常 |
| D | `FileExplorer`（右栏）手工 QMenu | 🟢 底色正常 |
| E | `TextStreamBlock`（新轨会话正文块）标准菜单 | 🔴 **复现缺陷**：菜单透明，仅图标/文字悬浮，下层「探针文本」透过菜单体可见 |

证据截图：`.tmp/leftmenu_diag/E_streamblock_standard_screen.png`（缺陷实况）与同目录 A–D 四张正常对照。像素定量：E 组菜单抓帧「上缘内/左缘内/项区」alpha 均为 0，A–D 组同点位 alpha 全为 255。

用户观察与复现吻合：左栏大块可右键区域是会话正文（`TextStreamBlock`），其标准编辑菜单（Copy / Select All 等 Qt 内建项）与中栏、右栏的定制单项菜单设计不同，且底色丢失。

## 2. 根因分析

### 2.1 机制链（R1，唯一根因）

1. `gui/panels/chat/cards.py` 的 `BodyHtml.__init__` 对控件调用**无选择器**控件级 qss：`setStyleSheet("background: transparent; border: none;")`（意图是让正文块透明融入卡片底色）；
2. 右键时 `TextStreamBlock.contextMenuEvent`（`gui/panels/chat/transcript.py`）走 `exec_standard_context_menu`（`gui/popups.py`），菜单由 Qt 内部 `createStandardContextMenu()` **以正文块为父**即时创建；
3. Qt 的控件级样式表会**沿父子链级联**，无选择器声明等价于通配——祖先的 `background: transparent` 落到子代 QMenu 上；控件级 qss 优先级高于应用级 qss，将 `assets/themes/base.qss` 的 `QMenu { background-color: $popup_bg }` 覆盖为透明；
4. 叠加 `make_translucent_popup` 的 `WA_TranslucentBackground`，菜单窗口底色彻底消失，只剩描边与文字——即用户所见。

### 2.2 同类泄漏点全量清单（修复面定界）

排查左栏全部控件级 `setStyleSheet`，以下**无选择器 `background: transparent`** 声明均会级联进右键菜单（第 1 条已探针实证，其余同机制推断）：

| # | 位置 | 声明对象 | 说明 |
|:---:|:---|:---|:---|
| L1 | `gui/panels/chat/cards.py` `BodyHtml.__init__` | QTextBrowser 正文块（`TextStreamBlock`/`SystemBlock`/气泡正文） | **已实证根因** |
| L2 | `gui/panels/chat/cards.py` `BodyText.__init__` | QPlainTextEdit 等宽/正文块（工具卡 body 等） | 默认右键菜单同机制透明 |
| L3 | `gui/panels/chat/cards.py` `ToolCard._set_error_body` | 错误全文 BodyText（覆写含 color） | 同 L2，覆写时重建该声明 |
| L4 | `gui/panels/chat/cards.py` bash 卡 `_on_failed` | 输出区 BodyText 覆写（红字） | 同 L2 |
| L5 | `gui/panels/chat/cards.py` 思维链卡构造 | 思维链 BodyText 覆写（灰斜体） | 同 L2 |
| L6 | `gui/panels/chat/transcript.py` `ChatTranscriptView.__init__` 的 `_container.setStyleSheet("background: transparent;")` | 会话容器（全部块的祖先） | 祖先级级联：仅修 L1–L5 不够，此条会沿容器→块→菜单链再次把透明灌进所有块的右键菜单 |

**不属于本缺陷、明确不动**：

- `ChatInput`/`ChatOutput` 挂的 `SUPPRESSION_QSS`（`gui/selection_band.py`）只含 `selection-background-color`/`selection-color` 两个选区属性，无 `background`——探针 A/B 组证实其菜单渲染正常；
- 中栏、右栏定制 QMenu 的宿主均无控件级透明背景声明（探针 D 组正常）；
- 既有正确先例：`transcript.py` 的 `#ChatUserBubble`、`#ChatTranscript` 均为 **ID 选择器**作用域，不级联——即本计划的修复范式。

## 3. 修复方案

### 决策点 D1：修源头还是修菜单出口

| 方案 | 内容 | 裁定 |
|:---|:---|:---|
| A | 源头治理：把 L1–L6 的无选择器声明改为 **ID 选择器**作用域（沿用 `#ChatUserBubble` 先例），级联链对 QMenu 不再命中 | ✅ 采用：治本、改动收敛、范式在库内已有先例 |
| B | 出口拦截：在 `exec_standard_context_menu` 给菜单补一条背景色覆写 qss | ❌ 不采用：盖不住 `BodyText` 的 Qt 默认右键菜单（不经该出口）；色值硬编码违「设计令牌零新增/单一来源」纪律；治标 |

### T1/T2：修前复现截图与视觉确认（已完成）

探针 `.temp/diag_leftmenu_transparency.py`，产物 `.tmp/leftmenu_diag/`（A–E 五组抓屏 + alpha 数据日志），见 §1。修复后复验使用**同一脚本**，保证前后对照。

### T3：qss 作用域化改造（L1–L6）

统一范式：控件 `setObjectName` + `#对象名 { ... }` 声明；覆写点同样带 ID 前缀重写整条规则。

| 改动点 | 改造内容 |
|:---|:---|
| `cards.py` `BodyText.__init__` | `setObjectName("CardBodyText")`；声明改 `#CardBodyText { background: transparent; border: none; }` |
| `cards.py` `BodyHtml.__init__` | `setObjectName("CardBodyHtml")`；声明改 `#CardBodyHtml { background: transparent; border: none; }` |
| `cards.py` `ToolCard._set_error_body` | 覆写串加 `#CardBodyText` 前缀（color 等其余属性原样保留） |
| `cards.py` bash 卡 `_on_failed` | 同上 |
| `cards.py` 思维链卡构造 | 同上（italic/gray 属性原样保留） |
| `transcript.py` `ChatTranscriptView.__init__` | `_container.setObjectName("ChatTranscriptContainer")`；声明改 `#ChatTranscriptContainer { background: transparent; }` |

约束：

- 视觉语义零变化：选择器仍精确命中原控件自身，块体透明融入卡片的观感不变；
- 不新增设计令牌、不动 `base.qss`、不动 `gui/popups.py`；
- `gui/popups.py` 模块 docstring 补一条规约：文本类控件挂控件级 qss 必须带选择器（禁无选择器 `background` 声明），防右键菜单级联染色再犯。

### T4：同脚本复验（修后）

- 重跑 `.temp/diag_leftmenu_transparency.py`，E 组菜单应与 A–D 一致：底色不透明、圆角描边与 base.qss 一致；
- 像素断言：E 组抓帧「上缘内/左缘内/项区」alpha 由 0 → 255；
- 多变体补帧：思维链卡（L5）、bash 失败红字块（L4）各弹一次右键菜单抓帧确认（探针增补两组步骤，仍同一脚本）；
- 眼睛终裁：修前/修后成对截图逐张多模态核对。

### T5：回归补强

- 探针 `alpha_report` 升级为硬断言（修后 alpha < 255 即非零退出），脚本常驻 `.temp/` 供复跑；
- 新增静态守卫脚本（随探针同目录或 `scripts/`）：扫描 `gui/panels/chat/` 的 `setStyleSheet` 调用，拦截**无选择器且含 `background`** 的声明模式，防止同类级联再犯（对齐 `check_theme_tokens.py` 反模式断言的既有思路）；
- 全量跑 `scripts/` 既有测试防回归。

## 4. 风险与取舍

- ⚠️ ID 选择器依赖 `setObjectName` 先行：覆写点（L3–L5）改的是 `BodyText` 实例，对象名在构造时已设，覆写串引用同一 ID 即可，顺序安全；
- ⚠️ L6 容器改名不影响既有 qss：全库无对 `_container` 的既有选择器引用（容器原声明即无选择器）；
- 取舍：`ChatInput`/`ChatOutput` 的 `SUPPRESSION_QSS` 虽同为无选择器控件级 qss 但实证无害（仅选区属性，菜单正常），本计划不动，保持最小改动面；
- 探针只进 `.temp/`、截图只落 `.tmp/`，不入版本库，生产代码零引用。
