## 0. 背景与目标

### 0.1 现状语义（改造前）

文件菜单三组多开入口语义对照（文档/修改记录/2026-0722-0756、2026-0722-1901、2026-0724-1806）：

| 菜单项 | 语义 |
|:---|:---|
| 新建窗口(&N) | **同根**起新进程，两窗并存 |
| 打开文件夹(&D)… | 换根起新进程，探活后**关旧窗**（替换当前工作区） |
| 在新窗口打开文件夹(&W)… | 换根起新进程，**留旧窗** |
| 最近打开的项目(&R) ▸ | 起新进程绑定该根，留旧窗（同根也只是多开） |

### 0.2 用户诉求（2026-08-31 会话确认）

1. **「一窗一根」**：同一工作区根同时只允许一个窗口。任何入口命中已占用的根时**激活已有窗口**（对齐 VS Code），不再起重复窗口。
2. **「新建窗口」改为空白窗口**：不绑定任何目录（对齐 VS Code `New Window`），空窗内走「打开文件夹」就地填充（复用换根关旧窗路径，空窗无旧根可留恋，正好不浪费窗口）。
3. **空窗形态**：文件树区欢迎占位（「未打开文件夹」+「打开文件夹…」按钮），聊天/终端面板禁用。

### 0.3 动机（同根多开的实际代价）

多开共享状态审计结论（2026-08-31 会话）：

- `settings.json` 与模型记忆表：flock + 原子写已治理（gui/settings.py D7），**无冲突**；
- `recent_projects.json`：去重置顶天然幂等，无实际影响；
- `window_state/<hash8>.json`：同根多开后写胜，5 键全布局，仅"最后关闭窗口生效"，无损坏风险；
- 🔴 `sessions/<hash8>.json`：同根两窗各聊各的，关闭时全量快照落盘**互相覆盖**，先关窗口的会话记录丢失——同根多开唯一有实际数据语义的冲突点。

「一窗一根」结构性地消除该冲突点；「新建窗口 = 空窗」则杜绝了同根多开的最大来源（误触/习惯新建）。

## 1. 关键设计决策

### D1 占用登记：QLocalServer 按根监听（零新依赖）

全项目无任何 IPC 机制（QLocalServer/dbus/QLockFile 零命中），PySide6 内置 `QtNetwork.QLocalServer/QLocalSocket`，不增依赖即够用，不引入 D-Bus。

- 套接字路径：`CONFIG_DIR / "sockets" / f"{workspace_digest(root)}.sock"`（绝对路径 listen，QLocalServer 支持）。放配置目录内遵守 AGENTS.md「禁用系统临时目录」纪律（QLocalServer 默认会落 /tmp 或 XDG_RUNTIME_DIR）。
- `workspace_digest(root)` = sha256(root) 前 8 位，抽成 `core/paths.py` 公共函数；`window_state.py` 与 `session_store.py` 两处内联同段哈希改复用（单一来源，防漂移）。
- 空窗不登记（无根可占；多空窗共存本无状态文件冲突）。
- 开发态与打包态 `CONFIG_DIR` 不同 → sockets 目录天然分离，互不感知（与现有配置隔离语义一致，可接受）。

### D2 占用判定与唤活协议（main.py 单一收口）

所有起窗路径（菜单 spawn / 命令行 / 双击图标）最终汇聚 `main()`，在此统一判定：

```
acquire_root_ownership(root) -> QLocalServer | None
  1. listen(sock 路径) 成功 → 返回 server（本进程拥有该根）
  2. 失败 → QLocalSocket.connectToServer + waitForConnected(300ms)：
     - 连上     → 发送唤活消息 → 返回 None（已被活窗口占用）
     - 连不上   → 陈旧套接字（崩溃残留）→ removeServer + 重试 listen
```

- 占用时 `sys.exit(EXIT_ROOT_OCCUPIED)`（常量 3；避开正常 0 与 argparse 的 2）。
- 已有窗口侧：`server.newConnection` → `showNormal() + raise_() + activateWindow()`（唤活先例：设置中心/提交历史图对话框同款链，main_window.py:571-572）。
- 崩溃残留套接字由「connect 探测失败 → removeServer → 重试 listen」自愈，无需心跳/pid 文件。

### D3 退出码协议接入既有探活链

- `open_folder_here` 的 `_close_after_spawn` 增加分支：`returncode == EXIT_ROOT_OCCUPIED` → **不关旧窗**，状态栏提示「该文件夹已在其他窗口打开，已激活该窗口」。空窗打开已占用根 = 空窗保留，语义正好合理。
- `open_folder_in_new_window` / `open_recent_project` 增加轻量探活 `_report_spawn_outcome`：退出码 3 时把状态栏「已在新窗口打开」纠正为「已激活已有窗口」。
- 「最近项目」点击当前根（旧注释"等价于新建窗口"）：现为激活本窗口自身（连自己 socket 发唤活，无害自激），同步更新过时注释。

### D4 空窗模式：占位部件 + None 守卫，不造假根

拒绝「哨兵目录伪装根」方案（污染 sessions/布局哈希、违反 AFCP 显式纪律）。改为：

- `MainWindow(workspace_root=None)` = 空窗；`self._workspace_root: str | None`。
- 文件树槽位、聊天槽位换占位部件；`self.file_explorer` / `self.chat_tabs` 置 `None`，全部消费点显式守卫（清单见 §2 步骤 5）。
- `WindowStateStore` 增加 `state_file` 显式入参：空窗传 `DEFAULT_LAYOUT_FILE`（布局继承/回写都走全局 default，天然合理）；`chat_panel` 放宽为 `ChatTabs | None`。
- 空窗不写 `recent_projects`、不建 GitStatusController、不做会话存取、标题 `Zen Studio — 未打开文件夹`。

## 2. 实施步骤

### 1. `core/paths.py`：新增 `workspace_digest`

```python
def workspace_digest(workspace_root: str) -> str:
    """工作区根 → 8 位摘要（sha256 前缀）。"""
    return hashlib.sha256(workspace_root.encode("utf-8")).hexdigest()[:8]
```

### 2. 哈希复用重构（纯改名不换逻辑）

- `gui/window_state.py` `window_state_file_for` 改调 `workspace_digest`；

## 4. 风险与边界

- ⚠️ QLocalServer 绝对路径 listen 依赖 Unix domain socket（Linux 桌面目标平台，符合"Linux 桌面优先"定位）；sun_path 长度上限约 108 字节，配置目录路径加深套接字名（8 hex + .sock）远在限内。
- ⚠️ 两进程同时 probe-fail 后竞争 listen：败方 listen 返回 False，再走一次 connect 探测唤活胜方，不会双开；该竞态窗口极小且后果可接受。
- ⚠️ Wayland 下 activateWindow 受合成器限制可能不置前（当前用户环境 X11，实测为准）。
- 🔴 `EXIT_ROOT_OCCUPIED` 退出码协议是 spawn 探活链的新契约，`_close_after_spawn` / `_report_spawn_outcome` 必须与 main.py 同步消费，漏一处即"唤活被误判为启动失败"。
- 空窗 reset_settings 不删 default.json（它不属于"当前工作区状态"）。

## 5. 不做的事（防范围蔓延）

- 不做窗口内就地换根（2026-0722-1901 已否决，维持进程级替换）；
- 空窗不做「最近项目」快捷列表、不做 New File 欢迎项（后续需要再迭代）；
- 不引入 D-Bus；TitleBar 固定文本不改（任务栏区分靠 windowTitle 已够）。
