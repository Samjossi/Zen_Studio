## 1. 背景与目标

`ChatOutput` 是公共文本轨的最后一个厂商载荷解释器：它按 `command`/`output`/`summary`/`status`/`error`/`is_subagent`/`output_total_lines` 理解三家数据，与「通用 GUI 只路由、不解释厂商载荷」的边界直接冲突。`classic` 仍是设置项，双轨维护成本会长期存在。

本子计划目标：

1. 删除 classic 旧文本轨，只保留卡片轨。
2. 删除三家 presenter 的旧轨裁剪分支与 `cards_track` 参数。
3. 兼容旧持久化值但保留隐藏回退；不改变卡片轨行为。

## 2. 启动条件与边界

- S0 已完成并获批准后，本子计划再单独取得用户同意；批准不包含 S2。
- 只删除旧轨与相关分支；**不改卡片格式、不改卡片外观、不改三家 mapper 与权限**。
- `chat_renderer` 设置键保留在 schema 中用于旧存档兼容，但值域只允许 `cards`；不重命名、不迁移配置文件。
- 不保留隐藏开关或环境变量来恢复 classic。
- 不删除 `card_base.py`、`ChatTranscriptView` 或卡片组合根。

### 6.3 经验沉淀

1. **删 UI 模块要连同「死路径注释」一起扫**：只 grep 类名/import 会漏掉「与旧轨 output.py 同构」这类注释；删除后应以 `旧轨|双轨|ChatOutput|output.py|cards_track` 组合再扫一遍，否则后续读者会以为回退通道仍在。
2. **兼容键的正确收口方式是「键留、值域缩、读取归一、不写回」**：`chat_renderer` 保留在 schema 与 `DEFAULT_SETTINGS`，但 `CHAT_RENDERERS` 只含 `cards`；测试同时断言内存值归一与磁盘文件未被改写，才能防止「静默迁移」违背兼容承诺。
3. **presenter 参数迁移要用符号级 grep 收口**：`cards_track` 分布在面板、三家 presenter、两个截图脚本与测试；漏一处就是运行时 `TypeError`。本次先全库列清单再逐个改，最后以 0 匹配复查。
4. **截图脚本的确定性足以做严格像素回归**：同一份 mock 帧、offscreen 渲染下 PNG 哈希逐张一致；删除旧轨分支后仍 37/14 全等，说明 presenter 简化没有触碰卡片轨输出。后续视觉回归可直接用哈希 diff，无需逐张读图。
5. **设置对话框是跨页耦合的**：`apply_font_size` 会访问权限页控件，单独测外观页时必须隔离页面注册表或 stub 该方法；否则测试会被无关页面拖垮，掩盖真正要验证的控件缺失。
6. **截图脚本可能有文档目录副作用**：`shot_tool_cards.py` 会把嵌套场景归档到 `文档/帧存档/`；执行前应预期未跟踪文件，并在回写中如实记录，避免误以为工作区被污染。
