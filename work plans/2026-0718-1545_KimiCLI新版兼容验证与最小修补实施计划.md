## 1. 目标

Kimi Code CLI 已由 Python 旧版（kimi-cli）重写为 TypeScript 新版（kimi-code，本机 0.27.0）。本计划确认现有 [`llm/providers/kimi_cli.py`](llm/providers/kimi_cli.py)（1445 计划产出，针对 0.19.0 设计）对新版的兼容性，并完成实测发现的**最小修补**——解析层与命令构造经实测**无需改动**，仅修补环境检测与错误诊断两处。

官方文档（新版）：[moonshotai.github.io/kimi-code](https://moonshotai.github.io/kimi-code/en/)（旧 kimi.com/code/docs 已 403，逐步迁移中）。

## 2. 本机环境实测结论（2026-07-18，新版 0.27.0）

### 2.1 现状

| 项 | 实测值 |
|:---|:---|
| 路径/版本 | `~/.kimi-code/bin/kimi`，**0.27.0**（1445 计划时为 0.19.0） |
| 认证 | OAuth 已登录（`managed:kimi-code`），`kimi login` 支持 device-code 免 TUI |
| 可用模型别名 | `kimi-code/kimi-for-coding`、`kimi-code/kimi-for-coding-highspeed`、`kimi-code/k3`（1M context，effort 可调）——**由 2 个增至 3 个**，`list_kimi_models()` 动态解析无需改代码 |
| ⚠️ PATH | `~/.kimi-code/bin` **不在非登录 shell 的 PATH**（桌面启动/裸 `env` 下 `shutil.which("kimi")` 返回 None） |

### 2.2 接口兼容逐条核对（官方 Command Reference + Changelog + 本机实测）

| 代码依赖 | 新版状态 | 结论 |
|:---|:---|:---:|
| `kimi -p <prompt>` | 保留；auto 权限 + 静态 deny 语义不变 | ✅ 实测 |
| `--output-format stream-json` | 保留，官方明确推荐程序化解析用 | ✅ 实测 |
| assistant 消息 `content`（纯字符串） | 实测输出 `{"role":"assistant","content":"收到"}` | ✅ 实测 |
| meta 行 `session.resume_hint` 抓 `session_id` | Changelog 0.2.0 明确"Emit session resume hint as a structured meta message"；实测末行携带 | ✅ 实测 |
| `-S <id>` 续接 + `-p` 组合 | 冲突规则不禁止；实测第二轮答出上一轮内容，续接生效 | ✅ 实测 |
| `tool_calls[].function.name` | 文档确认 schema（assistant 带 tool_calls → tool 消息 → assistant）；thinking 不进 JSONL | ✅ 文档 |
| `kimi provider list --json` → `models` 表 keys | 实测结构不变（新增 providers 表来源标注） | ✅ 实测 |

**结论：解析逻辑、命令构造、session 续接三处核心代码零改动。**

### 2.3 新版行为变化（0.19.0 → 0.27.0 间与本后端相关项）

| 变化 | 版本 | 影响 |
|:---|:---|:---|
| `-p` 默认等后台任务/subagent 完成才退出（`print_background_mode`） | 0.24.x | 子进程存活时间可能显著变长，**非卡死**；UI placeholder 文案已覆盖"响应中"，无需改代码 |
| 429/overload 重试事件 surface 到 stream-json | 0.23.5 | 解析器对未知 `role`/`type` 跳过，向前兼容；后续可选展示"重试中" |
| `-p` 失败退出码由 0 修正为非零 | 0.23.2 | 现有 `proc.wait() != 0` 兜底在新版才真正可靠 ✅ |
| thinking/工具进度/resume 通知写 stderr | — | 当前 `stderr=DEVNULL` 全吞，**失败时无诊断信息**（修补点 P2） |

## 3. 修补清单

| # | 位置 | 修补 | 动机 |
|:---:|:---|:---|:---|
| P1 | `kimi_cli.py` `kimi_available()` / spawn | **二进制解析增加 fallback**：`shutil.which("kimi")` → 候选 `~/.kimi-code/bin/kimi`（尊重 `KIMI_CODE_HOME` 环境变量）；解析结果供 spawn 与 `provider list` 统一使用 | 桌面启动 Zen_Studio 时 PATH 无 `~/.kimi-code/bin`，当前会被误判为"未安装"而禁用后端（本机实测复现） |
| P2 | `kimi_cli.py` `chat()` | **stderr 由 DEVNULL 改为捕获**：进程退出非零时把 stderr 尾部（限长，如末 500 字符）附进 `RuntimeError` 消息 | 新版把错误诊断全写 stderr；当前失败只有退出码，排查抓瞎 |
| P3 | `llm/README.md` | 行为说明同步：`-p` 后台任务保活（长进程属预期）、重试事件跳过策略、PATH fallback 说明 | 文档与 0.27.0 行为一致 |

**明确不改**：JSONL 解析循环、命令构造（`-p`/`-m`/`-S`）、`reset_session()` 语义、Chunk 双通道映射——实测全部兼容。

## 6. 验证标准

| 项 | 标准 |
|:---|:---|
| 冒烟 | `uv run python -c` 直调 `KimiCliLLM.chat`：首轮返回正文且捕获 `session_id`；第二轮带 `-S` 感知上下文（复现 2.2 实测） |
| 别名 | `list_kimi_models()` 返回 3 个别名（含 `kimi-code/k3`）；面板版本下拉联动正确 |
| PATH fallback | `env -i PATH=/usr/bin:/bin uv run main.py` 启动：Kimi CLI 后端**仍可用**（走 `~/.kimi-code/bin` fallback），不发问时模型下拉该项不禁用 |
| 失败诊断 | 构造失败场景（如临时 `-m` 传不存在别名）：异常消息含 stderr 原文而非裸退出码 |
| 回归 | 正常 PATH 下对话、多轮、工具调用灰字摘要与现行为一致 |
| 走查 | `uv run main.py` 无报错；截图确认面板渲染正常 |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|:---|:---:|:---|
| fallback 路径在用户自定义安装位置失效 | 🟢 | 候选链末端回退 `"kimi"` 字面量（保持现行为）；README 注明 `KIMI_CODE_HOME` 覆盖方式 |
| stderr 管道与 stdout 同时产生大量输出致死锁 | 🟡 | 先迭代完 stdout 再一次性 `proc.stderr.read()`（stderr 体量小，诊断文本远小于 64K 管道缓冲的极端情形可接受；或线程读取，实施时从简） |
| CLI 后续版本再改 JSONL schema | 🟢 | 解析按字段名容错（现状）；本计划验证标准沉淀为冒烟脚本，升级后重跑即可 |
| 0.24.x 保活行为致单轮耗时过长被误判卡死 | 🟢 | 属 CLI 预期行为；P3 文档说明；后续 ACP 方案可 `session/cancel` 主动中断 |
